- **1.15.0** Provider `--use_antigravity`: translate on the Google AI Pro or Ultra subscription quota via the official `agy` CLI; and, for all providers, Ctrl-C no longer abandons an in-flight agent, a whitespace segment no longer fails the file, and a project `.env` no longer chooses the executed binary (2026-09-26):

  - **Tenth provider path: Google subscription, without pay-as-you-go billing.** Anyone paying for Google AI Pro or Ultra can now draw their translations from it instead of paying per token on the Gemini API. `agy`, the official Antigravity CLI, is the only path to this quota: Gemini CLI no longer serves Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK only authenticates via an API key or Google Cloud. `--use_antigravity` drives it in headless mode, like Codex and Grok CLI, on the same foundation — dedicated process group, `SIGTERM` then `SIGKILL` on timeout, sanitized environment. Verified end-to-end on agy 1.2.11: a Markdown guide — front matter, bold, parenthesized link, inline code, indented code block within a list, table, blockquote — translated into English in 14 seconds, preflight included, structure identical to source, translator note added; then, after review fixes, into German in 19 seconds, identical structure, nothing written to `~/.gemini`.

  - **No paid path remains open, and each launch verifies it.** agy supports paths other than the subscription — API key, Google Cloud project, gateway, paid AI credits — and several environment variables silently switch it over. Measured: `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, `CLOUD_CODE_URL` reroutes the authenticated endpoint to any address. The subprocess environment is therefore an allowlist, not a denylist: `PATH`, language and timezone, terminal, identity, machine proxies and certificates, and the session bus — what an `env -i` proved agy requires —, without any keys. A denylist by prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), attempted first, missed some: a review found endpoint overrides in the binary's strings that no prefix covered, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings escape the environment and can only be read via `agy -p /config`: paid AI credits that take over when a quota is exhausted, and connecting via a Google Cloud project. A preflight that consumes zero quota — zero usage, measured — refuses to translate if either is active or if an API key is configured, and a setting absent from `/config` counts as a refusal for each of the three: an agy version that renames one must not pass a check that verified nothing. Finally, each call's log must confirm subscription authentication (`authMethod=consumer`), and any other authentication method appearing in it, under either of the two spellings used by the binary, causes the response to be rejected: the call itself is the source of truth, not the configuration that was prepared.

  - **The translation agent has zero tools, and its loading is proven on every call.** Each call writes, to a disposable directory, an agent in agy's project agent format: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Around 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone still allowed a workspace hook to execute its commands and inject its text. The real trap lies elsewhere: a missing agent does not make agy fail. Exit code 0, status `SUCCESS`, and the coding agent, with 57 active tools, responds — to "The cat is sleeping.", it answered "Shh, let's not wake it! 🐱💤 How can I help you today?". Nothing on stdout or stderr: only the call log shows it. The response is therefore rejected if the log reports this fallback, and also if it lacks the positive marker of agent loading — an evolution of the log format causes the translation to be rejected instead of silently dropping the guard. Each marker must occupy an entire log line, matching the measured format — severity, date, time, thread, file, and line: the binary also contains a line that echoes the user's message into the log — never observed at the default log level across 78 real logs —, and a document quoting these messages must not be able to satisfy the guard in place of agy.

  - **User agy settings and history are untouched.** Each call runs with a private HOME, temporary directory, and working directory, deleted afterward. agy still authenticates via the system keyring, which aipmt never reads. Nothing is inherited: neither user permissions — which allowed the default agent to run `ls` and `git` without prompting —, nor global rules, plugins, MCP servers, hooks, and skills. And nothing is appended to their history, where each call left a conversation of about 200 KB, including translated text: the probe campaign had left about 95 conversations and evicted 17 entries from a cache capped at 100. Verified: no files written to `~/.gemini/antigravity-cli`.

  - **Fail-closed where isolation cannot hold.** On Linux without a D-Bus session bus — SSH session, container, server —, agy stores its token in a file under `~/.gemini` instead of the keyring, as stated in its own changelog (1.1.3), and per-call isolation masks this file. The refusal now happens before any launch, stating its true cause, instead of a one-minute wait for a login code followed by a reconnection hint that would resolve nothing. On Windows, agy reads `USERPROFILE`, `APPDATA`, and `TEMP`, not `HOME` or `TMPDIR` — according to Go documentation and binary strings —: nothing would isolate the call from user settings or history there, and `--use_antigravity` is rejected there until measured. macOS passes without having been measured; the billing guard, which reads the effective configuration, holds there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero exit code, a JSON object with status `SUCCESS`, a conforming log, no rejected actions, no commands, no errors in the JSON, no truncation warnings on stderr, and non-empty text. `--print-timeout` is never used: upon expiry, agy returns partial output as `SUCCESS`, code 0; the timeout is external and kills the process group. A segment starting with `/commande`, `!commande`, or `@fichier` is translated, never executed or resolved — without `--disable-slash-commands`, "/help" was executed instead of being translated. A whitespace segment no longer reaches agy, as the pipeline returns it as-is (see below), and remains rejected before the call as a final safety net: on empty input, agy opens its interactive interface with code 0. Retries follow the `retryable` field of the `AGY_ERROR` line that agy has written to stderr since 1.2.6: it already retries transient errors itself — 502, 503, 504, per-minute limits —, and it knows whether the remaining failure is still transient. In the absence of this field, no retry occurs when the message mentions exhaustion — at Google, `RESOURCE_EXHAUSTED` carries the same 429 code as a per-minute limit, but an exhausted 5-hour window does not reset in 90 seconds —, and otherwise retries only on rate limiting. The response retains the segment's line endings: agy always terminates its output with a newline, which, at boundaries, split in two a paragraph broken mid-sentence. A disconnected session produces a message prompting to run `agy` to reconnect. Finally, `AGY_CLI_DISABLE_AUTO_UPDATE=true` prevents a fresh HOME from spawning an update checker in its own session on every call, beyond the timeout's reach — the value `1`, however, has no effect.

  - **Models: reasoning effort is part of the name.** Identifiers match those of `agy models` — `gemini-3.7-flash-medium`, `gemini-3.8-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… A bare base name, which agy would reject, is rejected before the call, listing existing suffixes: `-medium` or `-low` for Flash, `-high` or `-low` for Pro. Defaults are `gemini-3.7-flash-medium`, and `gemini-3.7-flash-low` for `--eco`, established by the campaign described below. `gemini-3.8-flash-medium` is excluded: the slowest in the pilot, 103 to 128 seconds per README, it spent 79% of its output on reasoning on one probe, deducted from quota. `--reasoning_effort` has no effect and reports so. Claude and GPT-OSS draw from a separate, much smaller quota — about 1% of the 5-hour window per measured call, compared to 0.05% for Flash — and a warning reminds users. Remaining quota can be checked for free via `agy -p /usage`. Rejected in CI, like Codex and Grok CLI: login lives in a personal keyring, and the message suggests `--use_gemini` with a Google key.

  - **September 26 campaign: defaults are measured, not guessed.** Using `aipmt --use_antigravity` itself, four parallel translations, each compared to its source with `scripts/compare_structure.py`. Pilot on this README in Japanese, Arabic, and Hindi: all four Flash variants — 3.7 and 3.8, low or medium effort — produce identical structure, taking 42 to 58 seconds per language at low effort, 72 to 84 in `gemini-3.7-flash-medium`, 103 to 128 in `gemini-3.8-flash-medium`. With no structural difference to separate them, the quality default remains in the family with the most evidence — Gemini 3.7 Flash, 14 out of 14 languages with zero discrepancies on the dense article via API —, at medium effort, with eco being low effort, the fastest. Full campaign in `gemini-3.7-flash-medium`, fourteen languages: the dense monitoring article from the README benchmarks, in `--news`, 14 translations written out of 14, all with zero discrepancies, median 3 min 14 s per language; in English, the model stripped the three French translation lines itself without inventing a flag — the failure mode that disqualified Gemma 4 and Qwen 3.5 —, and English quotes remained intact. This README, in its 1.14.0 revision: 14 written out of 14, 13 with zero discrepancies — one less bold word in Korean —, median 1 min 22 s. In `--eco`, the article in English, Japanese, Arabic, and Hindi: four out of four with zero discrepancies, median 1 min 52 s. Quota, checked via `agy -p /usage` before and after: the full campaign, 32 translations and 2.2 million source characters, consumed 26.3 points of the 5-hour window and 4.4 of the weekly window, i.e. on the order of half a point for a 40,000-character README — on the measured account tier, the weekly limit depending on the tier.

  - **Terms of service and data handling, plainly stated.** Antigravity terms (Section 6) and FAQ prohibit accessing the service through third-party software using an Antigravity login — Claude Code, OpenClaw, and OpenCode are explicitly mentioned —, under penalty of account suspension. aipmt never reads or reuses the token: it launches the official binary in headless mode as documented by Google for scripts and CI, and a Google staff member deemed it "standard" on the official forum to run `agy -p` from a local script for personal work — an answer, not a binding commitment. No text addresses the case of a distributed tool: the README notes that the user commits their own account. Section 5 of the same terms permits Google to use interactions — prompts, responses, metadata — to improve products and machine learning, and to have them reviewed by humans, without distinguishing the free tier from Pro and Ultra: the README reserves this path for public documents, and its final warning mentions this.

  - **Repository translations can use this path, with no exemption.** `REGEN_PROVIDER=antigravity` is a subscription, not a billed API: it passes without `REGEN_ALLOW_PAID_API`, using four jobs — the entire campaign ran at four in parallel without a single error — and Codex's 1,800-second per-job cap, justified by measurement: the entire CHANGELOG in Hindi, the file where Codex drops placeholders, was translated with zero discrepancies in 4 min 33 s, six and a half times under the cap. A full regeneration is estimated, based on the campaign, at one quarter of the 5-hour window. A single check, the module preflight, precedes the 28 jobs: a disconnected agy or one configured for billing launches none. The default remains Codex with `gpt-5.6-sol`.

  - **Ctrl-C and terminal closure now stop the agent, across all four CLIs.** Codex, Grok CLI, OpenCode, and Antigravity run in their own session, outside the foreground group: a Ctrl-C `SIGINT` does not reach them, and, upon Ctrl-C, `Popen` only waits a quarter of a second before returning control. Verified by review using a mock binary: the agent survived aipmt and finished its turn on quota, for a discarded result — four at a time during regen. A `KeyboardInterrupt` or `SystemExit` during the call now kills the agent's group before bubbling up. Terminal closure or SSH session drop (`SIGHUP`) killed Python without any cleanup: the agent continued running, and Antigravity's private directory remained on disk along with its log, which contains the account address. `SIGHUP` now follows the `SIGTERM` path: agent group killed, then exit with 129. An ignored `SIGHUP`, when launched under `nohup`, remains ignored: that is the user's choice. Antigravity's preflight — `agy --version`, then `agy -p /config` — uses the same handler: a signal received during this check stops agy and also cleans up the private directory, instead of leaving it on disk with its log.

  - **The subprocess driver can no longer target the entire session.** On Linux, `killpg(1, sig)` is equivalent to `kill(-1, sig)`: the signal is sent to all user processes. This occurred while writing this version during a mutation testing run: a mutant called a `Popen` doubled by a bare `MagicMock`, the resulting error traversed the new interrupt path, and the mock process pid, which Python converts to 1, caused the entire graphical session to be killed. `_codex_kill_group`, shared across all four CLIs, now targets a group only if pid is a valid integer greater than 1, `getpgid` returns that same pid — an agent started in its own session is group leader —, and it is not the current process group; otherwise, only the direct child is targeted. In production, this guard changes nothing: it closes the loophole where a bug might bubble up something else. Test doubles for `Popen` not intended for use now fail fast, mock processes carry an impossible pid, and mutation runs execute inside a PID namespace.

  - **A whitespace segment no longer causes the file to fail, regardless of the provider.** `segment_text` can isolate the whitespace end of a document: 16,001 characters ending with three line breaks yield a second segment made of two line breaks. Antigravity rejected it before the call — reproduced during review — and, with an API provider, an empty response fell under the empty content guard: in both cases, the entire file failed after the quota of preceding segments had already been consumed. A whitespace segment is now returned as-is, without making a call.

  - **Security: a project `.env` can no longer choose the executed binary.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`, and `AGY_BIN` designate the program launched by translation, with the user's permissions: set by the `.env` of a newly cloned repository, they caused a file from that repository to be executed upon the very first translation. The suffix `_BIN` therefore joins `_BASE_URL`, `_API_BASE`, and `_ENDPOINT` in the project-layer filter, along with `GROK_HOME`, under which the Grok binary is searched (`$GROK_HOME/bin/grok`). These variables remain accepted from the environment and from `~/.config/aipmt/.env`, and each rejection is reported on stderr along with where to set them.

  - **Tests**: new file `tests/test_antigravity_provider.py` (103 tests), covering 100% of statements and branches in the module — exact argv and never `-p`, segment via stdin, agent written without tools or inheritance, environment reduced to the allowlist, private directory deleted after success, failure, timeout, or signal, complete output contract, agent fallback and billing tier parsed from log lines in the real format, `AGY_ERROR` and `retryable`, strict billing preflight, rejection on Windows and without session bus, effort suffixes, line endings inherited from the segment, dispatch wiring, and regen branch. No test runs agy: a fake binary placed at the head of `PATH` was not called by any run, including under CI conditions, with a hidden session bus and `CI=true`. `tests/test_provider_base.py` interrupts a real subprocess via Ctrl-C and via `SIGHUP`, including under `nohup`, and locks down the safeguard of `killpg` — pid `MagicMock`, boolean, 1 or less, current group or another's group: never a process group signal; `tests/test_key_resolution.py` spawns a fresh process for each `_BIN` variable; `tests/test_orchestration.py` translates a document whose whitespace end forms a separate segment. Full suite at **650 tests**.

- **1.14.1** Mistral: rate limit exceedances no longer fail the file, and default models are confirmed by measurement (2026-09-17):

  - **An HTTP 429 caused the entire file to be lost.** The `mistralai` SDK does not retry anything by default, unlike those from OpenAI and Anthropic, and Mistral's limits are low and specific to each model: 15 requests per minute for Large 3, 100,000 tokens per minute for Small 4, measured on the repository's account. A benchmark run with four concurrent translations on Small lost five out of eighty-four. The client now retries on 429, 5xx, and connection errors, with an increasing backoff from 2 to 60 seconds for at most five minutes: Mistral's 429 does not specify how long to wait, and its limits are per-minute. Cross-check against the API: twenty consecutive calls on Large 3, twenty succeeded, the sixteenth after a 33-second wait.
  - **A response with reasoning blocks no longer breaks translation.** Small 4 and Medium 3.5 reason when asked to, and the response then becomes a list of `thinking` followed by `text` blocks instead of a string. Neither reasons by default (measured), but a default changing on the provider's side would have ended in `AttributeError`: reasoning blocks are stripped out, as with Claude.
  - **Default models confirmed: `mistral-large-latest` and `mistral-small-latest`.** The only newer model, Mistral Medium 3.5, was benchmarked against them in all fourteen languages on the dense tech-watch article from the compatibility table and on the README. On the article, it drops or changes the level of subheadings in 9 out of 14 languages — only a single discrepancy-free translation, compared to 6 for Large 3 and 8 for Small 4 — and it costs 3 times more than Large 3 for input, 5 times for output. The aliases point to Large 3 (`mistral-large-2512`) and Small 4 (`mistral-small-2603`).
  - **`MODEL_TOKEN_LIMITS` aligned with the API**: 262,144 tokens for the Mistral lineup instead of 256,000, 131,072 for `ministral-3b`, and dated identifiers, including `mistral-medium-2604`, no longer trigger the "unlisted" warning. Chunking, capped at 16,000 characters, remains unchanged.

- **1.14.0** A compatibility table at the top of the README, and the benchmark campaign backing it (2026-09-09):

  - **The verdict per model, at the top of the README, in French.** Over three hundred translations were sitting in the middle of the document, spread across three tables that had to be read and cross-referenced. The new table settles it in one line per model, specifically highlighting what differs: "one forgotten bold word, in Arabic and Japanese" rather than a ratio. Three models show zero discrepancies detected by the comparator across the two dense documents — `gemini-3.7-flash`, `gpt-5.6-sol` via the ChatGPT subscription, `z-ai/glm-5.2` via OpenRouter.
  - **A re-measurement campaign of 176 translations.** The original measurements dated from September 4 and were based on a README that has changed significantly since. Eight models were re-benchmarked on this README, two on a blog tech-watch article in `--news` mode, one on four public READMEs — FastAPI, Ollama, tldr-pages, and Vue.js. Three findings were worth noting: Mistral drops an **entire section heading** in Arabic, Hindi, and Korean without any pipeline guard detecting it — a heading cannot be replaced by a token, and nothing currently checks it during translation, even though the comparator catches it after the fact; Grok fails on five languages of a tech-watch article, dropping four inline codes and three URLs in the very first segment, despite holding up on a README; and Gemini delivers 55 discrepancy-free translations out of 56 across the four public READMEs.
  - **The structural comparator enters the repository.** The README described this protocol as the right way to evaluate a model — "compare the number of sections, links, distinct URLs, code blocks" — without providing the tool. `scripts/compare_structure.py` is what generated these tables, with eleven tests proving that it detects a lost URL, code block, section, inline code, table row, and blockquote. It includes the two non-Latin script fixes that made it reliable: a URL followed by a full-width parenthesis is no longer counted as different, and a shorter blockquote in Chinese is no longer counted as a lost blockquote.
  - **Package checks, before and after publication.** The test suite runs against source files and remains green even when the distributed package is broken — a module forgotten in the setuptools configuration, an entry point that fails to resolve. `scripts/check-package-smoke.sh --wheel` builds the wheel, installs it in a disposable venv outside the repository, verifies that it contains only the package, that both invocation methods work, that all modules import successfully, then translates a real document and compares its structure. `--pypi` does the same from the package index: it is the only verification proving that those exact bytes were shipped, and PyPI never allows republishing a version. The `--full` gate runs the offline portion, without model calls or cost.
  - **Seven claims in the README corrected, all reproduced before being rewritten.** "Nothing incorrect lands on your disk" was false: a model that removes a section or modifies a front matter date yields a file that the pipeline writes with `success` status, reproduced with a mocked response. The README now states what tokens protect — code blocks, inline code, URLs, anchors, blockquotes — and what pipeline guards do not currently check. "Discrepancy-free" does not mean "identical": the comparator counts elements without reading their content, and flags neither the deletion of a level-4 heading, nor replacing the text of an inline code, nor a swapped flag — three observed cases, and the mention "same flags" was removed since the comparator has no flag counter. Installing for development did not produce a usable tool: `pip install -r requirements.txt` only installs dependencies, `python -m aipmt` returned `No module named aipmt`, and `pip install -e .` was missing — as was the install line for `pre-commit`, which was absent from both dependency files. The OpenRouter promise regarding small contexts stated the opposite of the code: a model with a context window under **16,400 tokens** is rejected before any call, measured at 4,095, 8,192, and 16,384. The filter preventing a project `.env` from redirecting API calls was documented nowhere; it is now, along with the list of affected variables. Finally, two numbers: a Grok cell in the top table came from a September 9 benchmark whereas its column stated September 4, and "one broken link" attributed to Gemini was the opposite of what was measured — it converts three bare URLs into links, dropping none.

  - **A write failure no longer leaves a truncated translation on disk.** `open(cible, "w")` truncates the file before writing to it: an error during writing — full disk — left a partial target. Reproduced: eight bytes written, status `failure` returned, then the next run found this file, responded with `skipped`, and kept it. A failure turned into a truncated translation that was no longer flagged, and the exit code was 0. Content is now written to a temporary file in the same directory — `os.replace` is only atomic on the same filesystem — then renamed, with the temporary file being deleted if writing fails, including on interruption. This temporary file comes from `mkstemp`, and a review showed that a predictable name would only have moved the problem: a symlink placed at `cible.md.aipmt-tmp` caused the translation to be written into the target file outside the output directory while returning `success`; and two concurrent runs on the same target shared that name, the second renaming while the first was still writing to the same inode — target reported as successful, mixed content (`BBBAAAAA` instead of `BBBBBBBB`, measured). `mkstemp` creates with `O_CREAT | O_EXCL` under a unique name, which closes both issues. Permissions of the existing target are explicitly preserved before replacement: `mkstemp` creates with 0600, and a target intentionally set to 0600 would otherwise become 0664, while a target at 0644 served by a web server would have become unreadable. Eight tests lock this down, and two code mutations trigger test failures.

  - **The purity manifest can declare a rewritten suppression marker.** The check required that every line bearing a reference `# nosec`, `# nosemgrep`, or `NOSONAR` survive verbatim. However, moving a write to a temporary file renames the opened variable: the Sonar suppression is the same, but its line changes. The `markers` category of the manifest declares this `old` → `new` pair along with its rationale. Two conditions, and the second comes from a review: the replacement must exist, **and bear the same suppressions as the original line**. Without it, declaring `value = 1  # NOSONAR` → `value = 1` passed, meaning a declaration was enough to drop a marker — precisely what this check exists to prevent. An undeclared disappearance remains rejected.

  - **Two benchmark runs removed from the tables because they were interrupted by something other than the model.** Grok lost its CLI session after twelve languages of this README — two languages rejected in four seconds, without calling the model — and `qwen3.8-flash` was throttled by an upstream HTTP 429 after two. An interrupted run cannot be evaluated: they will be rerun in full or not at all. At the same time, the durations in the "README of this project" table were realigned with the September 9 benchmark — they dated back to a 508-line revision compared to 785 measured lines, and reported 2 min 04 s for `gpt-5.6-sol` where the measurement showed 6 min 46 s.

  - **The README is overhauled: 600 lines instead of 1,007, structured for the reader.** What the tool does, installation, configuration, getting started, followed by the compatibility table — placed after installation, once users know what they are running —, options, a chapter per provider, detailed benchmarks, and finally how to contribute. Benchmark narratives, measurement anecdotes, and redundancy across sections were removed; every retained number matches the tables, and every behavioral claim corresponds to the code in this version. The overhaul changelog remains in the git history.

  - **The summary table now states HOW MANY languages each discrepancy affects.** It previously stated "✅ 14 languages" and then, in the adjacent column, "one bold word" — without specifying whether that applied to one language or all fourteen. A reader could not tell, creating a bad impression despite good measurements: on this README, Gemini had only one language out of fourteen with an extra bold word, Sol two, GLM three. Each cell now shows the number of affected languages and which ones, the figure in the verdict columns is defined in one sentence — the number of languages, out of fourteen, where the translation is written and nothing differs —, and a legend explains the three symbols. The breakdown follows the owner's criteria: ✅ nothing differs; ⚠️ everything is translated and only markup shifts, nothing is missing; ❌ at least one language was rejected, or content is missing in a written file.

  - **The entire article benchmark was recalculated with the current comparator.** Two figures had been published before the comparator was fixed for non-Latin scripts, and it counted discrepancies that did not exist: `qwen3.8-flash` goes from thirteen to fourteen discrepancy-free languages, `qwen3.7-flash` from seven to eight. The section on `gpt-oss` is corrected at the same time: its passages left in French never reached an output file, as the untranslated excerpt guard rejected the four affected languages — this is the difference between a model being caught and a model slipping by unnoticed, and the README explicitly states it.

  - **A disclaimer at the end of the README.** Sections 15 and 16 of the GPL v3 already disclaim any warranty, but nobody reads a license before installing a tool. Four points are therefore clearly stated: machine translation must be reviewed before publication, as guards do not cover headings, tables, front matter, or meaning; the translated document is sent to the chosen provider under their terms, and some free models may reuse inputs — a local model remaining the only path without data egress; API calls are billed and the program does not cap spending; and published benchmarks are point-in-time observations, not guarantees.

  - **The entire `gpt-5.6-*` family is reachable via the ChatGPT subscription**, measured: `--model gpt-5.6-terra` yields via Codex the model served by default by the API. The default remains `gpt-5.6-sol`, the only model measured at fourteen languages without loss on a dense document, and it is the one translating this repository.

- **1.13.1** Dependency freshness: falling behind is no longer a warning that can be overlooked (2026-09-09):

- **A warning that is not counted is a warning that is missed.** `check-deps-fresh.sh` had been reporting for several days that `openai` and `anthropic` were falling behind, but the gate's summary line only counted failures: it announced "READY: N checks passed" while a delay was written a few lines above. Anyone reading the last line—and that is what everyone does—could not know. The verdict now includes the number of warnings, and a dedicated counter tracks them instead of printing them on the fly.
  - **The delay comes with release notes.** A version number does not say what changes, and finding the right file yourself is precisely the friction that causes the step to be skipped. The check displays the CHANGELOG URL for each lagging package, across both major and minor versions, along with the reason: a minor SDK update has already changed things that this project relies on.
  - **`openai` 3.8.0 → 3.10.0 and `anthropic` 1.3.0 → 1.4.0, release notes reviewed before locking.** On the OpenAI side, only a single behavioral change over the interval—a numeric `Retry-After` header overflowing a float no longer triggers a fallback to a short backoff, but returns the original error without retrying—and nothing affecting what this project depends on: model tolerance for extra fields is unchanged, verified in code across both tags, so the `native_finish_reason` and `error` that OpenRouter adds to a choice continue to pass. On the Anthropic side, a new guard explicitly rejects with a `TypeError` an object from the `httpx` package where the SDK expects `httpx2`; this project passes only floats, verified. The rule rejecting a non-streamed call lasting over ten minutes is byte-for-byte identical between the two versions: it is indeed the explicit `timeout` that waives it, its 32,768 tokens exceeding the 21,333 threshold.
  - **Verified**: test suites at 502 + 31 tests on the bumped versions, closure of `requirements.txt` consistent with what is installed (41 pins), and one real call per SDK—OpenAI and Claude—on a document in `--news` mode, structure identical to the source.

Since the endpoint is OpenAI-compatible, the client is identical to the one for xAI; **everything that distinguishes this provider lives in a preflight**, and every single one of its rules comes from API measurements.

  - **A single model is served by dozens of hosts with different caps, and routing is blind to this.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash`—including one capped at **2,048 output tokens**. One out of 23 long translations thus ended up truncated at random, without the slightest warning. The preflight reads `/api/v1/models/{modèle}/endpoints`, filters out hosts below 8,000 output tokens, those with degraded status, and those declaring no cap at all, then pins the rest. `provider.only` **without** `allow_fallbacks: false` is merely a preference: the router falls back to a discarded host, making the pinning useless. If no host meets the cap, the command aborts: translating anyway would amount to accepting the silent truncation that this preflight exists to prevent.

  - **Reasoning is billed at the output rate, and enabled by default on many models.** Same request on `z-ai/glm-5.2`, "OK" response: **107 completion tokens at model default, 2 with reasoning disabled**. On a translation, where reasoning adds no value, that is an 18x multiplier across every chunk of every file. It is therefore turned off by default. The **288 out of 431 models** that require it (`reasoning.mandatory`) return `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for these, the preflight inspects the accepted efforts and requests the lowest one (see next bullet)—the effort allocates a **percentage of `max_tokens`** that reasoning consumes first, so choosing an arbitrary value merely displaces the blank page risk instead of reducing it.

  - **A model that enforces reasoning receives the lowest effort it accepts, and this was decided by measurement.** The initial choice was to send nothing, avoiding second-guessing the model. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced output **truncated at 32,768 tokens** before the translation finished—losing two languages out of fourteen. Increasing the budget would have changed nothing: the effort allocates a percentage of it, and reasoning grows alongside it. The provider therefore reads `supported_efforts` during preflight and requests the lowest available, falling back to "nothing" when the catalog lists none that are usable. Cross-check on the failing language: previously failing on an exhausted budget, it now completes in 9 minutes with a structure identical to the source.

  - **An upstream host outage now displays its name.** The router normalizes this scenario into a `finish_reason=error` with a null `native_finish_reason`—measured twice, across two languages, at exactly 750 seconds. The generic message used to prompt checking for an issue in the document or chunking; it now states that the failure is upstream on the provider side and that retrying is often sufficient.

  - **`finish_reason=length` with empty output is not a truncation.** It is the budget consumed by reasoning before the first usable character—measured at 15,850 reasoning tokens for 148 usable ones. The two scenarios require opposite actions: reducing chunk size is useless in the first case. The message distinguishes between them explicitly. Two other guards originate from measurements: the router returns **200 with a body containing only an error** when the upstream host fails (`choices[0]` used to raise an opaque `TypeError` that masked the message), and the context window is read from the catalog and written into `MODEL_TOKEN_LIMITS`—`DEFAULT_TOKEN_LIMIT` is inaccurate for 44 catalog models, including two capped at 4,095 tokens.

  - **`--model fournisseur/modèle` is mandatory, and its format is validated before any network call.** OpenRouter is not a provider: the selection implies price, licensing, and data handling choices, and cannot be made on behalf of the user. Because the slug is interpolated into the preflight URL, validation is not mere ergonomic courtesy but the guard preventing path injection: the namespaced regex shared by both routers accepts `a/b/..`, hence the explicit rejection of the parent segment. `--eco` has no effect and states so.

OpenCode responds with its contract error, and not a `AttributeError`, on a `part: null` event, and rejects a JSONL stream where an event line is unreadable rather than accepting partial text. The three agentic CLIs kill the agent's process group when that process receives `SIGTERM` during the call — the `timeout` of the regen allowed the agent to survive and consume its quota — and the `SIGKILL` of the group always follows the grace period, a shim dying cleanly leaving its grandchild alive. The agentic CLI foundation falls back to `terminate` then `kill` where POSIX process groups do not exist, instead of letting a `AttributeError` cross the timeout guard and the wait prolong. The `429` marker in OpenCode is searched as a number and no longer as a substring, where an error identifier like `err_84290b` triggered 90 seconds of back-off before failing anyway. Finally, a non-canonical OpenRouter endpoint is displayed during preflight: a project `.env` is enough to set one, and the real key would then be sent out.
  - **Security: a project `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file starting from the current directory and its parents: an untrusted directory tree — a repository that was just cloned — could place `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` (the latter read by the SDK itself) without knowing any key, and the real key, coming from the environment or user configuration, would then go out in the authorization header of a third-party server. The filter operates on a PATTERN and not on a list: surveyed across installed SDKs, twelve routing variables are read, including six by the Anthropic client alone — a hand-written enumeration would have missed half of them. Therefore, any variable in `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, proxies, and certificate stores (pointing to a controlled authority makes an interceptor indistinguishable from a real server), as well as `XDG_CONFIG_HOME` and `APPDATA`, are rejected from the project layer: setting them was tantamount to deciding which file constitutes the user layer, thus bypassing the filter through the back door. These variables are only accepted from the two layers that the user controls, the exported environment and `~/.config/aipmt/.env`. The project layer is furthermore read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` copied the real key under a name that subprocess pattern filtering does not recognize — it then entered the environment of `codex exec`, contrary to the stated invariant. Finally, rejection displays only the variable name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into the logs, even as it was being rejected. A rejection is reported on stderr with the steps to follow — an enterprise proxy is declared in the user configuration.
  - **Fix: the OpenRouter output envelope is calculated for each call.** `context_length` covers input AND completion, and a fixed reserve calibrated for Latin text does not bound anything: measured with the `o200k_base` tokenizer, 16,000 characters equal 3,200 tokens in French but 12,300 in Japanese and 17,500 in emoji. The budget therefore comes from the text actually sent, bounded upward by its number of UTF-8 bytes: for any byte-pair encoding tokenizer — byte-level BPE, SentencePiece with byte fallback, the families used by the catalog — one token is worth at least one byte, and this is the only upper bound available here, where OpenRouter routes to dozens of tokenizers that are not known in advance. No average ratio was suitable — a supplementary plane ideograph drops to 1.33 bytes per token, a combining character to 1.00 —, and input plus output now fit within the window by construction. A segment that is too dense for the chosen model is rejected before the call rather than after billing.
