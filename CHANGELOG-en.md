- **1.16.2** Code protection: code quoted inside a blockquote `--news` and an indented block within a list no longer cause translation to be rejected across all languages (2026-10-03):
  - **Code quoted within a blockquote no longer blocks translation.** In `--news` mode, aipmt protects inline code before setting aside English blockquotes, which are restored as-is. Code placed inside a blockquote therefore went with it: the model never saw its token, and validation declared it lost for all languages. The author's daily news watch came to a halt on October 2 because of this: a `/plugin enable …` command quoted in a tweet, the probe language rejected twice, the thirteen others never started. Tokens carried away by a blockquote are now resolved in the set-aside text. For the English target, the French translation line of a quote is no longer sent to the model: the instructions told it to remove it, and the code it carried was then counted as lost even though the model had complied. The published output does not change. Finally, restoring a blockquote no longer reinterprets its backslashes: a quoted `\n` remains `\n`. Verified end-to-end on the article that had failed: English and German translated on the first try by `gpt-6.1-sol`, structure identical to the published versions.

  - **An indented code block within a list is protected.** CommonMark allows an indented block fence, and this is the normal case for a block documenting a numbered list step: it belongs to the list item, so it is indented. Anchored at column 0, the protection pattern missed them all: measured on a real README, 8 blocks spotted out of 14. The six others were sent to the model as prose and returned identical, since they are commands, and the guard that rejects a translation copied as-is rejected the file for all languages, with a message stating the symptom and never the cause. The pattern now accepts an indented fence, and the round-trip between protection and restoration returns the document identically, indentation included.

- **1.16.1** Internal links: the anchor token leaves its parentheses to the link, and a translated link is no longer silently duplicated (2026-09-27):
  - **An internal link no longer breaks without anything noticing.** To protect a link to a section, `[texte](#ancre)`, aipmt replaced its parenthesized part, parentheses included, with a token: the model received square brackets followed by a bare token, a link looking broken, and it occasionally "repaired" it. Restoration then yielded `[texte]((#ancre))`, a link leading nowhere, without any guard reporting it. The bug recurred with every regeneration of this repository's translations — in Spanish, Korean, then Italian for 1.15.0, in German for 1.16.0 — with every Gemini Flash tested, and even with Claude Sonnet and Haiku. A Markdown link's token now keeps its parentheses: the model receives a valid link that it no longer has any reason to fix, and restoration also accepts a token from which it might have stripped the parentheses. HTML anchors retain a bare token. Verified end-to-end with the most fragile model, `gemini-3.8-flash-low`, on a README where a link was in parentheses: without the fix, README rejected, three duplicated links, and one segment re-run; with it, three intact links out of three, no re-runs. Then on this README, in German, Japanese, and Hindi by `gemini-3.8-flash-medium`, and in German by Claude Code with `sonnet`: structure identical to the source, all three internal links intact everywhere.

  - **Tests can no longer modify the repository running them.** When pushed from a linked worktree, git passes the variable pointing to the repository to its hooks, and the pre-push hook runs the tests: a test's `git init`, intended for a temporary directory, reset the real repository, suddenly declared to have no working tree. Tests running git now strip any `GIT_*` variable from their environment, and a regression test pointing this variable to a decoy repository verifies this.

  - **The quota is shared with Claude Code sessions, and the provider conserves it.** Each call reports usage for the 5-hour and weekly windows; beyond 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), no additional segments are launched. On the day of writing, the author's account week was already at 98%.

A leading newline before the segment sends it to the model; the output contract rejects anyway any response returned with zero turns, in more than one turn, truncated, or by a model other than the one announced.

  - **Models: aliases, never a pinned identifier.** `sonnet` by default, at `low` effort, and in `--eco` as well — `--eco` therefore changes nothing on this pathway —, `opus` and `haiku` via `--model`; `fable` and `[1m]` variants are rejected, because in `-p` they switch to paid credits without asking.

The `sonnet` run, 1.8 million source characters, consumed 9 points of the 5-hour window and 2 points of the weekly window on the author's Max subscription — an upper bound: the session orchestrating the measurements drew from the same quota.

  - **An Anthropic guardrail refusal is identified as such.** Opus 5.5 has stricter guardrails than Sonnet, and Anthropic's error message warns that they sometimes flag work close to biological research. A news brief on 279 molecules generated for a binding site was enough. Claude Code then aborts the response, retries once, and the model returns "I can't continue this translation" with a success status, without error, over two turns: only the single-turn contract stopped this response, with a message silent on its cause. Sent alone, the brief is rejected by the API under the "bio" category. aipmt now recognizes these signs, identifies the guardrails and their category, does not retry — the same text would trigger the same refusal again —, and recommends `--model sonnet`, which translated the brief in all fourteen languages.

- **1.15.0** Provider `--use_antigravity`: translate on Google AI Pro or Ultra subscription quota, via the official CLI `agy`; and, for all providers, Ctrl-C no longer leaves orphaned agents running, a blank segment no longer fails the file, a project `.env` no longer selects the executed binary (2026-09-26):
  - **Tenth provider pathway: the Google subscription, without pay-as-you-go billing.** Anyone paying for Google AI Pro or Ultra can now charge their translations against it instead of paying per token on the Gemini API. `agy`, Antigravity's official CLI, is the only pathway to this quota: Gemini CLI no longer serves Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK authenticates only via an API key or Google Cloud. `--use_antigravity` runs it in headless mode, like Codex and Grok CLI, on the same foundation — dedicated process group, `SIGTERM` then `SIGKILL` on timeout, sanitized environment. Verified end-to-end on agy 1.2.11: a Markdown guide — front matter, bold, parenthesized link, inline code, indented code block in a list, table, blockquote — translated into English in 14 seconds, preflight included, structure identical to the source, translation note added; then, after review fixes, into German in 19 seconds, identical structure, nothing written to `~/.gemini`.

  - **No paid pathway remains open, and each launch verifies it.** agy supports pathways other than the subscription — API key, Google Cloud project, gateway, paid AI credits — and several environment variables silently switch it over. Measured: `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, `CLOUD_CODE_URL` redirects the authenticated endpoint to any address. The subprocess environment is therefore an allowlist and not a denylist: `PATH`, language and timezone, terminal, identity, machine proxies and certificates, and the session bus — what an `env -i` proved agy needs —, without any keys. A denylist by prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), tried first, missed some: a review of the binary's strings uncovered endpoint overrides not covered by any prefix, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings escape the environment and are readable only via `agy -p /config`: paid AI credits taking over when quota is exhausted, and login via a Google Cloud project. A preflight that consumes zero quota — usage at zero, verified — refuses to translate if either is active or if an API key is configured, and a missing setting in `/config` counts as a rejection for each of the three: an agy version that renames one must not pass a check that verified nothing. Finally, the log of each call must confirm subscription authentication (`authMethod=consumer`), and any other authentication method appearing in it, under either of the two spellings the binary uses, causes the response to be rejected: the call itself is authoritative, not the prepared configuration.

  - **The translation agent has no tools, and its loading is verified on every call.** Each call writes, to a disposable directory, an agent in the format of agy project agents: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Roughly 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone allowed a workspace hook to execute its commands and inject its text. The real pitfall lies elsewhere: a missing agent does not make agy fail. Return code 0, status `SUCCESS`, and the coding agent, with 57 active tools, responds instead — to "The cat is sleeping.", it replied "Shh, let's not wake it up! 🐱💤 How can I help you today?". Nothing on stdout or stderr: only the call log says so. The response is therefore rejected if the log reports this fallback, and also if it does not carry the positive marker of the agent loading — any change in the log format causes the translation to be rejected rather than silently dropping the guard. Each marker must occupy an entire log line, in the measured format — severity, date, time, thread, file, and line: the binary also contains a line that echoes the user's message into the log — never seen at the default log level across 78 real logs —, and a document quoting these messages must not be able to satisfy the guard in place of agy.

  - **The user's agy settings and history are untouched.** Each call runs with a private HOME, temporary directory, and working directory, deleted afterward. agy still authenticates via the system keychain, which aipmt never reads. Nothing is inherited: neither the user's permissions — which allowed the default agent to run `ls` and `git` without prompting —, nor their global rules, plugins, MCP servers, hooks, and skills. And nothing is added to their history, where each call left a conversation of about 200 KB, including translated text: the probe campaign had left about 95 conversations there and evicted 17 entries from a cache capped at 100. Verified: no files written to `~/.gemini/antigravity-cli`.

  - **Fail-closed refusal where isolation would not hold.** On Linux without a D-Bus session bus — SSH session, container, server —, agy stores its token in a file under `~/.gemini` instead of the keychain, as stated in its own changelog (1.1.3), and isolating each call masks this file. The refusal now occurs before any launch, with its real cause, instead of a one-minute wait for a login code followed by reconnection advice that would solve nothing. On Windows, agy reads `USERPROFILE`, `APPDATA`, and `TEMP`, not `HOME` or `TMPDIR` — based on Go documentation and strings in the binary —: nothing would isolate the call from the user's settings or history there, and `--use_antigravity` is refused there until measured. macOS passes, without having been measured; the billing guard, which reads the effective configuration, holds there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero return code, a JSON object with status `SUCCESS`, a conforming log, no refused action, no command, no error in the JSON, no truncation warning on stderr, and non-empty text. `--print-timeout` is never used: upon expiring, agy returns partial output in `SUCCESS`, exit code 0; the timeout is external and kills the process group. A segment starting with `/commande`, `!commande`, or `@fichier` is translated, never executed or resolved — without `--disable-slash-commands`, "/help" was executed instead of being translated. A whitespace-only segment no longer reaches agy, as the pipeline returns it as is (see below), and remains rejected before the call as a safety net: on empty input, agy opens its interactive interface with exit code 0. Retries follow the `retryable` field of the `AGY_ERROR` line that agy writes to stderr since 1.2.6: it already retries transient errors itself — 502, 503, 504, per-minute limit —, and it knows whether the remaining failure is still transient. In the absence of this field, no retry when the message mentions exhaustion — at Google, `RESOURCE_EXHAUSTED` carries the same 429 code as a per-minute limit, but an exhausted 5-hour window does not reset in 90 seconds —, and otherwise on rate limiting only. The response preserves the segment's line ending: agy always terminates its own with a newline, which, at the junction, split a mid-sentence paragraph in two. A disconnected session yields a message advising to run `agy` to reconnect. Finally, `AGY_CLI_DISABLE_AUTO_UPDATE=true` prevents a fresh HOME from launching an update checker in its own session on every call, out of reach of the timeout — the value `1`, for its part, has no effect.

  - **Models: reasoning effort is part of the name.** Identifiers are those of `agy models` — `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`... A base name alone, which agy would reject, is rejected before the call, showing the available suffixes: `-medium` or `-low` for a Flash, `-high` or `-low` for a Pro. By default `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`, set by the campaigns described below. `--reasoning_effort` has no effect and reports this. Claude and GPT-OSS draw from a separate and much smaller quota — about 1% of the 5-hour window per measured call, compared to 0.05% with Flash — and a warning reminds the user. The remaining quota can be checked for free via `agy -p /usage`. Rejected in CI, like Codex and Grok CLI: the login lives in a personal keychain, and the message suggests `--use_gemini` with a Google key.

In the afternoon, at the author's request, Gemini 3.8 Flash vs. 3.7 on the same batch, this README and this CHANGELOG in their 1.15.0 version: at medium effort, same structure for both; 3.8 reasons as much as 3.7 — 63% of output tokens versus 60%, read from agy's JSON — and costs one-seventh more quota, for a quarter more time. Then the morning campaign, rerun in `gemini-3.8-flash-medium`: fourteen languages out of fourteen without discrepancy on the article, 3 min 59 s median, as on the README, 1 min 43 s; internal links intact across all fourteen READMEs, where 3.7 broke some in Italian; and in English, the French translation lines removed by the model, without invented flags, English quotes intact.   - **Terms of service and data handling, plainly stated.** Antigravity's terms (Section 6) and FAQ prohibit accessing the service through third-party software using the Antigravity login — Claude Code, OpenClaw, and OpenCode are cited —, under penalty of account suspension. aipmt never reads or reuses the token: it runs the official binary in headless mode as documented by Google for scripts and CI, and a Google staff member deemed it "standard", on the official forum, to run `agy -p` from a local script for one's own work — an answer, not a commitment. No text settles the case of a distributed tool: the README states that the user commits their own account. Section 5 of the same terms allows Google to use interactions — prompts, responses, metadata — to improve its products and machine learning, and to have them reviewed by humans, without distinguishing the free tier from Pro and Ultra: the README reserves this path for public documents, and its final warning notes this.

  - **Translations for this repository can use this path, without exception.** `REGEN_PROVIDER=antigravity` is a subscription, not a metered API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs — the entire campaign ran with four in parallel without a single error — and Codex's 1,800-second per-job cap, which measurements justify: the entire CHANGELOG in Hindi, the file where Codex drops placeholders, was translated without discrepancy in 4 min 33 s by 3.7 Flash in its 1.14.1 version, and in 5 min 50 s by 3.8 Flash in its 1.15.0 version, one-fifth longer: at least five times below the cap. A full regeneration, 2.2 million characters, amounts to 30 to 36 points of the 5-hour window in `gemini-3.8-flash-medium`. A single check, the module preflight, precedes the 28 jobs: a disconnected agy or one configured to bill launches none of them. The default remains Codex with `gpt-5.6-sol`.

  - **An internal link was breaking silently.** The token protecting an anchor swallows its parentheses: the model receives an apparently broken link, brackets followed by the bare token, and sometimes "fixes" it. Restoration then produces `[texte]((#ancre))`, which leads nowhere, without any guard or `compare_structure.py` flagging it. This occurred in two READMEs during this version's first regeneration, and with all tested models, more frequently when the link itself is parenthesized — as was the case for a link this version had just added to this README. The release check now counts intact internal links in each translation, and this README no longer places any inside parentheses; the fix for the token itself remains to be done.

  - **Ctrl-C and terminal closure now terminate the agent, for all four CLIs.** Codex, Grok CLI, OpenCode, and Antigravity run in their own session, outside the foreground process group: the `SIGINT` of a Ctrl-C does not reach them, and, on Ctrl-C, `Popen` only waits a quarter of a second for them before returning control. Verified during review using a mock binary: the agent survived aipmt and finished its turn on the quota, with the result discarded — four at a time during regen. A `KeyboardInterrupt` or `SystemExit` during the call now kills the agent's process group before bubbling up. Terminal closure or SSH session disconnect (`SIGHUP`) killed Python without any cleanup: the agent kept running, and Antigravity's private directory remained on disk along with its log, which contains the account address. `SIGHUP` now follows the `SIGTERM` path: agent process group killed, then exit with code 129. An ignored `SIGHUP`, via launch under `nohup`, remains ignored: that is the user's choice. Antigravity preflight — `agy --version`, then `agy -p /config` — goes through the same handler: a signal received during this check stops agy and also deletes the private directory, instead of leaving it on disk with its log.

  - **The subprocess driver can no longer target the entire session.** On Linux, `killpg(1, sig)` equals `kill(-1, sig)`: the signal is sent to all of the user's processes. This happened during the development of this version during a mutation testing run: a mutant called a `Popen` stubbed by a bare `MagicMock`, the resulting error traversed the new interruption path, and the mock process pid, which Python converts to 1, caused the entire graphical session to be killed. `_codex_kill_group`, shared across all four CLIs, now targets a group only if the pid is a real integer greater than 1, `getpgid` returns that same pid — an agent launched in its own session is its process group leader —, and it is not the current process's group; otherwise, only the direct child is targeted. In production, this guardrail changes nothing: it eliminates the case where a bug might pass something else up. Stubs of `Popen` that should not be used now fail immediately, mock processes carry an impossible pid, and mutation testing runs inside a PID namespace.

  - **A whitespace-only segment no longer causes the file to fail, regardless of the provider.** `segment_text` can isolate trailing whitespace at the end of a document: 16,001 characters ending with three newlines result in a second segment consisting of two newlines. Antigravity rejected it before the call — reproduced during review — and, with an API provider, an empty response triggered the empty-content guard: in both cases, the entire file failed, after the quota for previous segments had already been consumed. A whitespace-only segment is now returned as is, without making a call.

  - **Security: a project `.env` can no longer select the executed binary.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`, and `AGY_BIN` designate the program launched by the translation, with user privileges: set by the `.env` of a freshly cloned repository, they caused a file from that repository to be executed on the very first translation. The `_BIN` suffix therefore joins `_BASE_URL`, `_API_BASE`, and `_ENDPOINT` in the project-layer filter, along with `GROK_HOME`, under which the Grok binary is located (`$GROK_HOME/bin/grok`). These variables remain accepted from the environment and from `~/.config/aipmt/.env`, and each rejection is reported on stderr along with where to set them.

  - **Tests**: new file `tests/test_antigravity_provider.py` (103 tests), covering 100% of the module's statements and branches — exact argv and never `-p`, segment via stdin, agent written with no tools or inheritance, environment reduced to the allowlist, private directory deleted after success, failure, timeout, or signal, complete output contract, agent fallback and billing route parsed from log lines in the real format, `AGY_ERROR` and `retryable`, strict billing preflight, rejection on Windows and without session bus, effort suffixes, segment line ending preserved, dispatch wiring, and regen branch. No test runs agy: a mock binary placed at the head of `PATH` was not called during any run, including under CI conditions, masked session bus, and `CI=true`. `tests/test_provider_base.py` interrupts a real subprocess via Ctrl-C and via `SIGHUP`, including under `nohup`, and locks in the guardrail for `killpg` — pid `MagicMock`, boolean, 1 or less, current process group or someone else's process group: never a group signal; `tests/test_key_resolution.py` spawns a fresh process for each `_BIN` variable; `tests/test_orchestration.py` translates a document whose trailing whitespace forms a separate segment. Full suite at **650 tests**.

- **1.14.1** Mistral: rate limit overruns no longer cause the file to fail, and default models are confirmed by measurement (2026-09-17):
  - **An HTTP 429 caused the loss of the entire file.** The `mistralai` SDK does not retry anything by default, unlike those of OpenAI and Anthropic, and Mistral's rate limits are low and specific to each model: 15 requests per minute for Large 3, 100,000 tokens per minute for Small 4, measured on the repository's account. A campaign with four concurrent translations on Small lost five out of eighty-four. The client now retries on 429, 5xx, and connection errors, with an increasing backoff from 2 to 60 seconds for up to five minutes: Mistral's 429 does not specify how long to wait, and its limits are tracked per minute. Counter-test on the API: twenty calls in a row on Large 3, twenty successful, the sixteenth after a 33-second wait.
  - **A response in reasoning blocks no longer breaks translation.** Small 4 and Medium 3.5 reason when requested, and the response then becomes a list of `thinking` then `text` blocks instead of a string. Neither reasons by default (measured), but a default that changed provider-side would have ended up in `AttributeError`: reasoning blocks are discarded, as with Claude.
  - **Default models confirmed: `mistral-large-latest` and `mistral-small-latest`.** The only newer model, Mistral Medium 3.5, was benchmarked against them across all fourteen languages, on the dense monitoring article from the compatibility table and on the README. On the article, it drops or changes the level of subheadings in 9 out of 14 languages — only a single translation without discrepancies, compared to 6 for Large 3 and 8 for Small 4 — and it costs 3 times more than Large 3 on input, 5 times on output. The aliases point to Large 3 (`mistral-large-2512`) and Small 4 (`mistral-small-2603`).
  - **`MODEL_TOKEN_LIMITS` aligned with the API**: 262,144 tokens for the Mistral lineup instead of 256,000, 131,072 for `ministral-3b`, and dated identifiers, including `mistral-medium-2604`, no longer trigger the "unlisted" warning. Segmentation, capped at 16,000 characters, remains unchanged.

- **1.13.0** Provider `--use_openrouter`: a paid router to ~430 models, including open Chinese models (2026-09-05):
  - **Ninth provider path, shipped alongside the eighth.** 1.12.0 was not published on PyPI: both routers, OpenCode and OpenRouter, are released together. [OpenRouter](https://openrouter.ai) provides single-key access to models that no other provider exposes here — Kimi, Qwen, DeepSeek, Z.ai — on a single pay-as-you-go credit. Since the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything that distinguishes this provider lies in a preflight**, and each of its rules comes from measurements against the API.

  - **The same model is served by dozens of hosts with different caps, and routing is blind to this.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash` — including one capped at **2,048 output tokens**. A long translation out of 23 therefore ended up truncated, at random, without the slightest warning. The preflight reads `/api/v1/models/{modèle}/endpoints`, filters out hosts under 8,000 output tokens, those with degraded status, and those reporting no cap, then pins the rest. `provider.only` **without** `allow_fallbacks: false` is merely a preference: the router falls back to a discarded host, rendering pinning useless. If no host meets the cap, the command stops: translating anyway would mean accepting the silent truncation that this preflight exists to prevent.

  - **Reasoning is billed at the output rate, and active by default on many models.** Same query to `z-ai/glm-5.2`, response "OK": **107 completion tokens with the model default, 2 with reasoning turned off**. On a translation, to which reasoning brings nothing, this is an 18x factor on every segment of every file. It is therefore turned off by default. The **288 models out of 431** that require it (`reasoning.mandatory`) return `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for them, the preflight checks the supported efforts and requests the lowest one (next bullet) — effort allocates a **percentage of `max_tokens`** that reasoning consumes first, meaning a randomly chosen value shifts the blank page risk instead of reducing it.

  - **A model that enforces reasoning receives the lowest effort it accepts, and a benchmark decided this.** The initial choice was to send nothing, so as not to second-guess the model. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced output **truncated at 32,768 tokens** before the translation finished — two languages out of fourteen lost. Increasing the envelope would have changed nothing: effort allocates a percentage of it, so reasoning grows alongside it. The provider therefore reads `supported_efforts` during preflight and requests the lowest, falling back to "nothing" when the catalog advertises none usable. Cross-check on the failing language: it used to fail on an exhausted budget, it now succeeds in 9 minutes with structure identical to the source.

  - **An upstream host outage now carries its name.** The router normalizes this case into `finish_reason=error` with a null `native_finish_reason` — measured twice, across two languages, at exactly 750 seconds. The generic message used to send users hunting for a defect in the document or the chunking; it now states that the failure is upstream and that retrying is often sufficient.

  - **`finish_reason=length` with empty output is not truncation.** It is the budget consumed by reasoning before the first useful character — measured at 15,850 reasoning tokens for 148 useful ones. The two cases call for opposite actions: reducing segment size is useless in the former. The message distinguishes between them explicitly. Two other guards stem from measurements: the router responds **200 with a body carrying only an error** when the upstream host fails (`choices[0]` raised an opaque `TypeError` that masked the message), and the context window is read from the catalog then recorded in `MODEL_TOKEN_LIMITS` — `DEFAULT_TOKEN_LIMIT` is false for 44 models in the catalog, including two capped at 4,095 tokens.

  - **`--model fournisseur/modèle` is required, and its format is validated before any network request.** OpenRouter is not a vendor: the choice commits price, licensing, and data handling, so it is not made on the user's behalf. Because the slug is interpolated into the preflight URL, validation is not a matter of ergonomic courtesy, but the guard preventing path injection: the namespaced regex shared by both routers accepts `a/b/..`, hence the explicit rejection of the parent segment. `--eco` has no effect and reports so.

  - **Three phrasings corrected, one of which was false.** OpenAI's warning about `codex exec` targeted injecting a personal session file on a shared runner, not whether the repository was public: it was cited backwards in the README, CLAUDE.md, and the code. The OpenCode authentication storage location changed in 1.18.27 (`credential` table in `opencode.db`, rather than `auth.json`); the invariant "never read here" remained true, but the path was outdated. Finally, the OpenCode section no longer presents untested paths as equivalent: the Zen gateway and Ollama were benchmarked end-to-end; GitHub Copilot, LM Studio, and llama.cpp were not, and the README now says so.

  - **A benchmark campaign, and a table of recommended models in the README.** Over three hundred translations run across three document sets — a dense blog post in `--news` mode, this README in standard Markdown, and four public project READMEs taken as-is from GitHub — into fourteen languages. The table distinguishes two things that were often conflated: translations that **complete** and those whose **structure is identical** to the source. Three models never lost any information across both dense documents: `gemini-3.7-flash`, `gpt-5.6-sol` via ChatGPT subscription, and `z-ai/glm-5.2` via OpenRouter — their only deviations were a pair of `**` missed in one or two languages. The central finding is that **the discriminating factor is document density, not `--news` mode**: subscription Grok fails thirteen times out of fourteen on the blog post and succeeds on fourteen out of sixteen public READMEs, the root cause being dropping out on long segments, confirmed by cross-check. The table carries its own warning: it is not exhaustive, it is point-in-time, durations do not rank quality, and the sound approach remains measuring on one's own documents.

  - **The structural comparison tool was fixed before publishing its figures, because it produced two false positives on non-Latin scripts.** A URL followed by a full-width closing parenthesis `）` was not split by a regex stopping at `)`, and the extracted string differed even though the URL was identical; a five-line quote in French fitting on three lines in Chinese caused line-based counts to drop. Both fixes were validated by cross-checking: removing a URL, section, or inline code is still detected. Without them, Gemini and Codex would have been published at eleven out of fourteen languages instead of thirteen and twelve.

  - **Tests**: new file `tests/test_openrouter_provider.py` (76 tests) — model validation and parent segment rejection, host pinning (cap, status, undeclared cap, common minimum), `allow_fallbacks` always false, reasoning disabled or kept according to `mandatory`, complete output contract (error in a 200, no choices, blank page distinguished from truncation, abnormal `finish_reason`, null content), fail-closed preflight on unreachable catalog, missing slug, and absence of healthy host, flag exclusivity, and filename labelling. Full test suite at **502 tests**.

  - **Refactor: the single 4,253-line module is split into modules, without altering a single line of behavior.** `src/aipmt/translate.py` is divided into `config`, `markdown`, `segmentation`, `guards`, `placeholders`, `news`, `prompts`, `notes`, `naming`, `pipeline`, `cli`, and a `providers/` subpackage (one module per provider, `base` as base, `registry` for resolution and dispatch). Every move is a commit verified mechanically: a checker compares the AST of all top-level nodes in the package against a reference snapshot, verifies each symbol's location, verbatim survival of security markers, and absence of untracked files — temporary tooling, removed in the following version. Visible changes: `aipmt.translate` becomes a facade re-exposing, by object identity, the 64 names the module exposed without prefix `_` (`__all__` holds nine, the supported API; the others are compatibility aliases), and ceases re-exporting the 29 standard-library and dependency names picked up by a `import *`; direct file execution (`python src/aipmt/translate.py`) no longer exists — `aipmt` and `python -m aipmt` remain the two supported forms; the `__module__` of public functions is that of their defining module; SDKs are imported after loading `.env` instead of before, with no known impact. All 427 tests are preserved down to their identifiers and migrated to the modules they exercise: 91 patches that used to go through the facade now target the module looking up the name (two of which remained green without their patch, as measured), seven contract tests lock down the facade, and gate tooling was rewritten BEFORE the first move so that none could pass falsely by skipping checks — Lizard directory scopes with minimum thresholds, flags parsed from the generated parser, package-level coverage floor, `release.sh` enumerating tracked modules.
  - **Fix (pull request review)**: OpenRouter rejects a catalog entry missing `context_length` instead of recording the default 128,000 tokens as a measurement — which also suppressed the "unlisted model" warning — and when `finish_reason` is null (documented type `string | null`), the host's raw reason is authoritative, `max_tokens` being equal to `length`; an error carried by the choice itself rejects the accompanying partial content, with the same message as normalized upstream failures — host details, raw reason, and advice combined. OpenCode responds with its contract error, not a `AttributeError`, on an `part: null` event, and rejects a JSONL stream containing an unreadable event line rather than accepting partial text. The three agentic CLIs kill the agent's process group when this process receives `SIGTERM` during an invocation — the regen's `timeout` previously allowed the agent to survive and burn its quota — and group `SIGKILL` always follows the grace period, as a shim dying cleanly previously left its grandchild running. A `# fmt: off` / `# fmt: on` pair split during refactoring is reunited; `--reasoning_effort` help names the four providers that consume it.
  - **Fix (second review)**: the output cap requested from OpenRouter now reserves the context portion consumed by the prompt and segment — `context_length` covers BOTH input and completion, and six catalog models were seeing requests sent with no room for input; insufficient context is rejected before any billing occurs. The agentic CLI base falls back to `terminate` then `kill` where POSIX process groups do not exist, instead of letting a `AttributeError` slip past the timeout guard and extend the wait. OpenCode's `429` marker is matched as a number rather than a substring, where an error ID like `err_84290b` previously triggered 90 seconds of back-off before failing anyway. Finally, a non-canonical OpenRouter endpoint is displayed during preflight: a project `.env` is enough to configure one, and the real key would then be dispatched.
  - **Security: a project `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file starting from the current directory and its parents: an untrusted tree — such as a freshly cloned repository — could place `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` (the latter read by the SDK itself) without knowing any API key, and the real key, originating from the environment or user configuration, would subsequently be sent in the authorization header to a third-party server. The filter operates on a PATTERN rather than a fixed list: survey of installed SDKs revealed twelve routing variables read, six by the Anthropic client alone — a hand-written enumeration would have missed half of them. Therefore, any variable matching `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, proxies, and certificate stores (pointing to a controlled authority makes an interceptor indistinguishable from a genuine server), as well as `XDG_CONFIG_HOME` and `APPDATA`, are rejected from the project layer: setting them was equivalent to choosing which file constitutes the user layer, thereby bypassing the filter sideways. These variables are only accepted from the two layers controlled by the user: exported environment and `~/.config/aipmt/.env`. Furthermore, the project layer is read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` copied the real key under a name unrecognized by subprocess pattern filtering — it then entered the environment of `codex exec`, violating the stated invariant. Finally, rejection displays only the variable name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into logs, even while rejecting it. Rejections are reported on stderr along with remediation steps — corporate proxies belong in user configuration.
  - **Fix: the OpenRouter output envelope is calculated per call.** `context_length` covers BOTH input and completion, and a fixed reserve calibrated on Latin text bounds nothing: measured with tokenizer `o200k_base`, 16,000 characters amount to 3,200 tokens in French, but 12,300 in Japanese and 17,500 in emoji. The budget is therefore derived from the actual text sent, upper-bounded by its UTF-8 byte count: across all byte-merging tokenizers — byte-level BPE, SentencePiece with byte fallback, the families used across the catalog — a token is worth at least one byte, which is the only upper bound available here, where OpenRouter routes to dozens of unknown tokenizers. No average ratio was adequate — an ideograph in the supplementary plane drops to 1.33 bytes per token, a combining character to 1.00 —, and input plus output now fit within the window by design. A segment too dense for the selected model is rejected before the call rather than after billing.

- **1.12.0** Provider `--use_opencode`: OpenCode, the open-source agent, to the provider of your choice — local model, free without an account, subscription, or key (2026-09-04):
  - **Eighth provider path, of a different nature than the first seven.** [OpenCode](https://opencode.ai) (MIT) is not a model provider but a _router_ to those configured by the user within OpenCode itself: an API key, a subscription (GitHub Copilot, ChatGPT, SuperGrok), the OpenCode Zen gateway — which serves free models **without an account** —, or a **local** model (Ollama, LM Studio, llama.cpp). The script drives `opencode run` in non-interactive mode, just as it drives Codex and Grok, and reuses the same subprocess foundation (clean process group, `SIGTERM` then `SIGKILL` on timeout, stdin always closed, sanitized environment). Verified through **two real translations**: this entire README into English via `opencode/mimo-v2.5-free` — 49 s, a single pass, identical structure to the source file (32 headings, 26 code fence closings, 18 links, 37 URLs, 37 table rows, 135 inline code spans) — and a test file via `ollama/qwen2.5:7b`, locally, without any key.

  - **`--model provider/modèle` is required, and that is a deliberate choice.** Without `--model`, OpenCode falls back to its own default, which on a fresh install is `opencode/big-pickle`, a free "stealth" model whose exchanges may be used for training — measured, it was indeed this model that responded. Choosing this silently on behalf of the user would be exactly the kind of invisible shift this repository tracks; the error message therefore names the command that lists models (`opencode models`) and three examples (local, free, subscription). `--eco` has no effect and says so. `--reasoning_effort` is passed through as-is as OpenCode's `--variant`, only upon explicit request.

  - **Measured confinement, not assumed.** An inline configuration (`OPENCODE_CONFIG_CONTENT`, last in OpenCode's merge order, therefore taking precedence over the user's without replacing it) defines an agent `aipmt` with all tools denied (`permission: {"*": "deny"}`): the registry no longer even offers them to the model, which, when prompted to "list files and run `id`", replies that it has no tools. Session sharing disabled, external plugins discarded (`--pure`), never `--auto`, disposable and empty working directory. Two silent injections were measured and cut off: without `OPENCODE_DISABLE_CLAUDE_CODE`, the user's `~/.claude/CLAUDE.md` enters **every** prompt (515 input tokens instead of 186 for a simple "Hello"); without `OPENCODE_DISABLE_PROJECT_CONFIG`, the current directory's `AGENTS.md` does as well — an instruction to "end each response with BANANA" was applied to the translation. The global `~/.config/opencode/AGENTS.md`, however, remains injected: no switch disables it, and bypassing it via a diverted `XDG_CONFIG_HOME` would also hide the user's providers. Documented rather than hacked together.

  - **`exit 0` proves nothing, third CLI, same instincts — with two traps specific to this one.** An unknown `--agent` does not cause `opencode run` to fail: a warning on stderr and a **silent** fallback to the coding agent, with tools active. If the inline configuration were not taken into account, the translation would therefore proceed with an agent capable of writing; the output contract verifies the absence of this message, in addition to: return code 0, no `error` event, no `tool_use`, last `step_finish` in `stop` (a `length` is a truncated response), non-empty text. Second trap: the JSON error event is **opaque** — "Unexpected server error. Check server logs for details.", with a simple reference — and the actual cause (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) only lives in the logs. Hence `--print-logs --log-level ERROR` and reading the `error="…"` field from stderr, stripped of the Bun trace that follows it. An unknown model thus fails in one second, with its named cause. `--title` incidentally avoids an extraneous LLM call: without it, OpenCode generates a session title via an extra round on the `small_model`.

  - **Secrets: same pattern-based filtering as Codex and Grok, with one nominative exception.** `OPENCODE_API_KEY` is preserved: it is the key for OpenCode itself (Zen gateway, Go subscription), addressed to it by name — the equivalent of its `auth.json`, not a key that aipmt would manage or could bill. Providers are configured in OpenCode (`opencode auth login`, `opencode.json`), never in aipmt's `.env`, from which no key reaches the subprocess. No refusal in CI, unlike subscription CLIs: an API key or a self-hosted model on a runner are legitimate use cases.

  - **The anti-traversal guard now checks the interpolated value, not the raw value.** `provider/modèle` contains a `/` that the 1.10.0 guard rejected — rightly so, as `--model` was interpolated into the `--include_model` filename. The filename slug now replaces `/`, `\`, and `:` with `-` before any interpolation (`ollama/qwen2.5:7b` → `ollama-qwen2.5-7b`, `:` being illegal under Windows), and the upstream guard inspects this slug: `../../evil` becomes the simple name `doc-en-..-..-evil.md` under the target, `..` alone remains rejected, as does `--target_lang ../x`. The `_ensure_within_directory` boundary guard remains the second layer, unchanged.

  - **Free models and local models, what was measured.** `opencode/mimo-v2.5-free` translates a paragraph in 16 s and this README in 49 s; `opencode/big-pickle` takes 40 s for 200 words, and two concurrent requests were left unanswered for 5 minutes where each one alone succeeded; `opencode/nemotron-3.5-lightning-free` yielded no response in 3 minutes. Hence `REGEN_PROVIDER=opencode` with required `REGEN_MODEL` and **2 jobs** in parallel. On the local side, Ollama often configures 4,096 context tokens whereas segments reach up to 16,000 characters: a `Modelfile` with `PARAMETER num_ctx 32768` is essential, and quality mirrors the model — a 7B inverted a list and corrupted a code block closing on the test file, whereas the gateway model preserved everything.

  - **Translations in this repository never go through a billed API anymore.** `regen_translations.sh` picked the OpenAI API as soon as a key was lying around in `.env`, making Codex opt-in only. That is exactly what happened when preparing this release: the 28 translations ran on the OpenAI API, then the Hindi CHANGELOG on Gemini's, even though the ChatGPT subscription exists precisely to avoid paying per use. Key auto-detection is gone: **Codex is the default, with `gpt-5.6-sol`**, the quality model; `openai`, `gemini`, and `grok` require `REGEN_ALLOW_PAID_API=1` in addition to `REGEN_PROVIDER`, a named opt-in flag so that the rule bites at the moment of decision; an unknown `REGEN_PROVIDER` fails instead of falling back to the API. - **1.9.2** Fix news attribution URL extraction with nested parentheses or FR prefix (2026-05-11):
  - **Bug fixed**: attribution URL extraction in `_protect_news_quotes` used the regex `re.search(r"\((.+?)\)", attribution)` (lazy capture inside parentheses). On an attribution such as `(relayé par [@user sur X](https://x.com/.../123))` (nested parentheses: enclosing `(` + markdown link `]()`), capture stopped at the first `)` encountered → truncated string + including the FR prefix: `relayé par [@user sur X](https://x.com/.../123` (without trailing `)`). Consequence: `_validate_news_post` looked for this string in the translated output and systematically failed (two reasons: truncated `)` + "relayé par" translated to `relayed by`/`weitergeleitet von`/...). Full low → medium → high → gpt-5.5 cascade could not succeed.
  - **Fix**: the regex becomes `re.search(r"\]\(([^)]+)\)", attribution)` — specifically targets the `](url)` of the markdown link, captures **only the pure URL** (without FR prefix or truncation), an invariant preserved by `#URL{N}#` placeholders during translation. Robust against both problematic patterns:
    - `(relayé par [@account sur X](url))` — nested parentheses
    - `via [@source](url)` or `selon [@author](url)` — FR prefix without enclosing parentheses
