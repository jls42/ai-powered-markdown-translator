- **1.13.0** Provider `--use_openrouter`: a paid router to ~430 models, including open Chinese models (2026-09-05):

  - **Ninth provider path, shipped with the eighth.** 1.12.0 was not released on PyPI: both routers, OpenCode and OpenRouter, are being released together. [OpenRouter](https://openrouter.ai) provides access with a single key to models that no other provider exposes here — Kimi, Qwen, DeepSeek, Z.ai — through a single pay-as-you-go credit balance. Since the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything that distinguishes this provider lies in a preflight**, and each of its rules comes from an API measurement.

  - **The same model is served by dozens of hosts with different limits, and routing is blind to this.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash` — including one capped at **2,048 output tokens**. A long translation out of those 23 was therefore randomly truncated, without the slightest signal. The preflight reads `/api/v1/models/{modèle}/endpoints`, excludes hosts with fewer than 8,000 output tokens, those with degraded status, and those that declare no limit, then pins the others. `provider.only` **without** `allow_fallbacks: false` is only a preference: the router falls back to an excluded host, making the pinning worthless. If no host meets the limit, the command stops: translating anyway would mean accepting the silent truncation this preflight exists to prevent.

  - **Reasoning is billed at the output rate and enabled by default on many models.** Same request on `z-ai/glm-5.2`, response “OK”: **107 completion tokens with the model default, 2 with reasoning disabled**. For translation, where reasoning adds nothing, that is an 18× factor on every segment of every file. It is therefore disabled by default. The **288 models out of 431** that require it (`reasoning.mandatory`) respond with `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for them, nothing is sent rather than guessing an effort level — effort allocates a **percentage of `max_tokens`** that reasoning consumes first, so choosing an arbitrary value merely shifts the risk of blank output instead of reducing it.

  - **A model that requires reasoning receives the lowest effort it accepts, and that decision was based on measurement.** The initial choice was to send nothing, to avoid guessing on the model's behalf. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced output **truncated at 32,768 tokens** before the translation ended — two languages out of fourteen were lost. Increasing the envelope would not have changed anything: effort allocates a percentage of it, and reasoning grows along with it. The provider therefore reads `supported_efforts` during preflight and requests the lowest value, falling back to “nothing” when the catalog lists no usable value. Control test on the failing language: it previously failed because the budget was exhausted; it now succeeds in 9 minutes with a structure identical to the source.

  - **An upstream host outage now bears its name.** The router normalizes this case as `finish_reason=error` with a null `native_finish_reason` — measured twice, on two languages, at exactly 750 seconds. The generic message sent users looking for a defect in the document or segmentation; it now says that the outage is on the provider's side and that retrying is often enough.

  - **`finish_reason=length` with empty output is not truncation.** It means the budget was consumed by reasoning before the first useful character — measured at 15,850 reasoning tokens for 148 useful ones. The two cases call for opposite actions: reducing segment size is useless in the first. The message distinguishes them explicitly. Two other safeguards come from measurements: the router responds with **200 and a body containing only an error** when the upstream host fails (`choices[0]` raised an opaque `TypeError` that hid the message), and the context window is read from the catalog and then written to `MODEL_TOKEN_LIMITS` — `DEFAULT_TOKEN_LIMIT` is wrong for 44 catalog models, including two capped at 4,095 tokens.

  - **`--model fournisseur/modèle` is mandatory, and its format is validated before any network access.** OpenRouter is not a provider: the choice determines price, licensing, and data processing, and cannot be made on the user's behalf. Since the slug is interpolated into the preflight URL, validation is not merely an ergonomic courtesy but the safeguard that prevents path injection: the shared namespaced regex for both routers accepts `a/b/..`, hence the explicit rejection of the parent segment. `--eco` has no effect and says so.

  - **Three corrected wordings, including one false claim.** OpenAI's warning about `codex exec` concerned injecting a personal session file on a shared runner, not whether the repository was public: it was cited out of context in the README, CLAUDE.md, and the code. OpenCode's authentication location changed in 1.18.27 (the `credential` table in `opencode.db`, no longer `auth.json`); the “never read here” invariant remained true, but the location was outdated. Finally, the OpenCode section no longer presents untested paths as equivalent: the Zen gateway and Ollama were measured end to end, while GitHub Copilot, LM Studio, and llama.cpp were not, and the README now says so.

  - **A measurement campaign and a table of recommended models in the README.** More than three hundred translations were run across three document sets — a dense blog post in `--news` mode, this README in standard Markdown, and four READMEs from well-known projects taken as-is from GitHub — into fourteen languages. The table distinguishes two things that had been conflated: translations that **complete** and those whose **structure is identical** to the source. Three models never lost any information across the two dense documents: `gemini-3.7-flash`, `gpt-5.6-sol` through the ChatGPT subscription, and `z-ai/glm-5.2` through OpenRouter — their only deviations are a pair of `**` markers not reproduced in one or two languages. The central finding is that **the discriminating factor is document density, not `--news` mode**: subscription-based Grok fails thirteen times out of fourteen on the blog post and succeeds on fourteen public READMEs out of sixteen, with the cause traced through a control test to losing track on a long segment. The table carries its own warning: it is not exhaustive, it is dated, durations are not rankings, and the right approach remains to measure on your own documents.

  - **The structure comparator was fixed before its figures were published because it produced two false positives for non-Latin scripts.** A URL followed by a full-width closing parenthesis `）` was not split by a regex that stops at `)`, so the extracted string differed even though the URL was identical; a five-line French quotation fitting into three lines in Chinese caused a line-based count to drop. Both fixes were validated by control tests: removing a URL, section, or inline code is still detected. Without them, Gemini and Codex would have been reported at eleven languages out of fourteen instead of thirteen and twelve.

  - **Tests**: new `tests/test_openrouter_provider.py` file (39 tests) — model validation and parent-segment rejection, host pinning (limit, status, undeclared limit, shared minimum), `allow_fallbacks` always false, reasoning disabled or preserved according to `mandatory`, complete output contract (error inside a 200 response, no choices, blank output distinguished from truncation, abnormal `finish_reason`, null content), fail-closed preflight when the catalog is unreachable, missing slug and no healthy host, flag exclusivity, and filename label. Full suite at **427 tests**.

  - **Refactor: the single 4,253-line module is split into modules without changing a single line of behavior.** `src/aipmt/translate.py` is divided into `config`, `markdown`, `segmentation`, `guards`, `placeholders`, `news`, `prompts`, `notes`, `naming`, `pipeline`, `cli`, and a `providers/` subpackage (one module per provider, `base` as the foundation, `registry` for resolution and dispatch). Each move is a commit backed by mechanical proof: a verifier compares the AST of every top-level package node against a reference snapshot, checks the location of every symbol, the verbatim survival of security markers, and the absence of untracked files — temporary tooling removed by the following version. The visible changes are: `aipmt.translate` becomes a façade that re-exports, with object identity preserved, the 64 names that the module exposed without an `_` prefix (`__all__` contains nine of them, the supported API; the others are compatibility aliases), and stops re-exporting the 29 dependency and standard-library names picked up by `import *`; direct execution of the file (`python src/aipmt/translate.py`) no longer exists — `aipmt` and `python -m aipmt` remain the two supported forms; the `__module__` of public functions is that of their defining module; SDKs are imported after `.env` is loaded rather than before, with no known consequence. All 427 tests are preserved down to their identifiers and migrated to the modules they exercise: 91 patches that previously went through the façade now target the module that looks up the name (nine of them remained green without their patch, as measured), seven contract tests lock down the façade, and the gate tooling was rewritten BEFORE the first move so none could turn green by ceasing to verify — directory-scoped Lizard with a floor, flags read from the constructed parser, per-package coverage floor, and `release.sh` listing tracked modules.

- **1.12.0** Provider `--use_opencode`: OpenCode, the open-source agent, routing to the provider of your choice — local model, free without an account, subscription, or key (2026-09-04):

  - **Eighth provider path, different in nature from the first seven.** [OpenCode](https://opencode.ai) (MIT) is not a model provider but a _router_ to those configured by the user in OpenCode itself: an API key, a subscription (GitHub Copilot, ChatGPT, SuperGrok), the OpenCode Zen gateway — which serves free models **without an account** — or a **local** model (Ollama, LM Studio, llama.cpp). The script drives `opencode run` in non-interactive mode, just as it drives Codex and Grok, and reuses the same subprocess foundation (dedicated process group, `SIGTERM` followed by `SIGKILL` on timeout, stdin always closed, sanitized environment). Verified through **two real translations**: this entire README into English via `opencode/mimo-v2.5-free` — 49 seconds, a single pass, structure identical to the source file (32 headings, 26 code-block closures, 18 links, 37 URLs, 37 table rows, 135 inline code spans) — and a test file via `ollama/qwen2.5:7b`, locally, without any key.

  - **`--model provider/modèle` is mandatory, and it is a choice.** Without `--model`, OpenCode falls back to its own default, which on a fresh installation is `opencode/big-pickle`, a free “stealth” model whose exchanges may be used for training — as measured, this is the model that responded. Silently choosing that on the user's behalf would be exactly the kind of invisible switch this repository tracks; the error message therefore names the command that lists models (`opencode models`) and gives three examples (local, free, subscription). `--eco` has no effect and says so. `--reasoning_effort` is passed through unchanged as OpenCode's `--variant`, only when explicitly requested.

  - **Measured confinement, not assumed.** An inline configuration (`OPENCODE_CONFIG_CONTENT`, last in OpenCode's merge order and therefore taking precedence over the user's without replacing it) defines a `aipmt` agent for which all tools are denied (`permission: {"*": "deny"}`): the registry no longer even offers them to the model, which, when ordered to “list the files and run `id`,” responds that it has no tools. Session sharing is disabled, external plugins excluded (`--pure`), never `--auto`, and the working directory is disposable and empty. Two silent injections were measured and disabled: without `OPENCODE_DISABLE_CLAUDE_CODE`, the user's `~/.claude/CLAUDE.md` enters **every** prompt (515 input tokens instead of 186 for a simple “Hello”); without `OPENCODE_DISABLE_PROJECT_CONFIG`, so does the current directory's `AGENTS.md` — an instruction to “end every response with BANANA” was applied to the translation. The global `~/.config/opencode/AGENTS.md`, however, is still injected: no switch excludes it, and bypassing it through a repurposed `XDG_CONFIG_HOME` would also hide the user's providers. Documented rather than patched around.

  - **`exit 0` proves nothing: third CLI, same reflexes — with two traps of its own.** An unknown `--agent` does not make `opencode run` fail: it emits a warning on stderr and **silently** falls back to the coding agent, with tools enabled. If the inline configuration were ignored, the translation would therefore proceed with an agent capable of writing; the output contract checks that this message is absent, in addition to requiring: exit code 0, no `error` event, no `tool_use`, final `step_finish` in `stop` (a `length` is a truncated response), and non-empty text. Second trap: the JSON error event is **opaque** — “Unexpected server error. Check server logs for details.”, with only a reference — and the actual cause (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) exists only in the logs. Hence `--print-logs --log-level ERROR` and reading the `error="…"` field from stderr, without the Bun stack trace that follows it. An unknown model thus fails in one second with the cause named. `--title` also avoids a stray LLM call: without it, OpenCode generates a session title through an additional turn on `small_model`.

  - **Secrets: the same pattern-based filtering as Codex and Grok, with one explicitly named exception.** `OPENCODE_API_KEY` is preserved: it is OpenCode's own key (Zen gateway, Go subscription), addressed to it by name — the equivalent of its `auth.json`, not a key that aipmt manages or could bill. Providers are configured in OpenCode (`opencode auth login`, `opencode.json`), never in aipmt's `.env`, none of whose keys reach the subprocess. There is no CI rejection, unlike subscription CLIs: an API key or a self-hosted model on a runner are legitimate uses.

  - **The traversal safeguard now checks the interpolated value, not the raw value.** `provider/modèle` contains a `/` that the 1.10.0 safeguard rejected — correctly, since `--model` was interpolated into the filename `--include_model`. The filename label now replaces `/`, `\`, and `:` with `-` before any interpolation (`ollama/qwen2.5:7b` → `ollama-qwen2.5-7b`, since `:` is illegal on Windows), and the upstream safeguard examines that label: `../../evil` becomes the simple name `doc-en-..-..-evil.md` under the target, only `..` remains rejected, as does `--target_lang ../x`. The `_ensure_within_directory` scope safeguard remains the second layer, unchanged.
  - **Free and local models, what was measured.** `opencode/mimo-v2.5-free` translates one paragraph in 16 s and this README in 49 s; `opencode/big-pickle` takes 40 s for 200 words, and two simultaneous requests remained unanswered for 5 minutes even though each succeeds on its own; `opencode/nemotron-3.5-lightning-free` returned nothing in 3 minutes. Hence `REGEN_PROVIDER=opencode` with mandatory `REGEN_MODEL` and **2 jobs** in parallel. Locally, Ollama often configures 4,096 context tokens while segments contain up to 16,000 characters: `Modelfile` with `PARAMETER num_ctx 32768` is essential, and quality depends on the model—a 7B model reversed a list and damaged a code-block fence in the test file, whereas the gateway model preserved everything.

  - **Translations in this repository never use a billed API anymore.** `regen_translations.sh` used the OpenAI API whenever a key happened to be present in `.env`, making Codex merely opt-in. That is exactly what happened while preparing this release: the 28 translations went through the OpenAI API, followed by the Hindi CHANGELOG through the Gemini API, even though the ChatGPT subscription exists precisely to avoid usage-based billing. Automatic key detection is gone: **Codex is the default, with `gpt-5.6-sol`**, the quality model; `openai`, `gemini`, and `grok` require `REGEN_ALLOW_PAID_API=1` in addition to `REGEN_PROVIDER`, a named exemption so the rule takes effect at decision time; an unknown `REGEN_PROVIDER` fails instead of falling back to the API. Ten tests lock down the default, the refusal, and the exemption. The 28 translations in this release were redone through Codex.

  - **Rate-limit back-off is factored out** (`_retry_on_rate_limit`): the Codex and Grok loops were identical apart from their labels, and a third copy would have crossed the duplication threshold. All three CLI errors derive from the same `_CliCallError`; a test prevents any of the three from leaving it, otherwise the shared loop would no longer detect it.

  - **Tests**: new `tests/test_opencode_provider.py` file (51 tests)—complete output contract, agent fallback, cause read from logs, deduplicated text parts and ignored synthetic parts, timeout killing the process group, 429 back-off, mandatory and validated model, secret-free preflight, binary resolution, dispatch wiring, filename labeling, and path-traversal counter-test. `tests/test_review_hardening.py` extends flag exclusivity and the absence of secrets to the new provider. The gate now requires **22 documented** argparse flags. Full suite at **382 tests**.

- **1.11.0** Published on PyPI: `pip install ai-powered-markdown-translator`, then the `aipmt` command, without cloning the repository (2026-09-03):

  - **The single-file script becomes an installable package.** `translate.py` moves from the root to `src/aipmt/translate.py`, with a `aipmt` console entry point and the equivalent `python -m aipmt`. A cloned repository is still required for contributing—tests, 28 translations, and quality tooling live there—but no longer for using it.

    - **The import name is `aipmt` and never `translate`**, because the collision is real and silent. The `translate` PyPI package (v3.8.1, latest upload 2026-07-06) installs a DIRECTORY with the same name. Reproduced in a venv: the directory takes precedence over the module, `translate.main` disappears, and the entry point fails on `AttributeError`—while `pip check` reports “No broken requirements found” with rc=0. A simple `pip install translate` on the user's system would have been enough to break the CLI without an actionable diagnostic. Counter-test using the actual wheel: `pip install translate` on top of the package, `aipmt --help` rc=0 before and after, and both CLIs coexist.
    - **Long distribution name, short command.** `ai-powered-markdown-translator` makes the package discoverable through a PyPI search; an acronym alone would be impossible to find for anyone who does not already know the project, whereas the very purpose of publishing is to be discovered. Two plausible candidates were ruled out after verification: `ai-markdown-translator` has been TAKEN on npm since 2024 by a tool serving the same purpose, 17 months older than this repository; and `aimt` is one letter away from `aim` (v3.29.1), an active package in the SAME domain—the worst setup for lasting confusion. A methodological trap along the way: `pypi.org/project/<nom>/` returns 200 for any name (anti-bot page); only the JSON API is authoritative.
    - **`src/` layout instead of a flat package.** A flat package would have preserved the six `sys.path.insert(..., "..")` statements in the tests, and that is precisely the problem: they make the source tree get imported instead of the package, which would hide any packaging error. Actual cost: one additional substitution rule.

  - **Keys can finally be configured once and for all.** An installed CLI had no PERSISTENT configuration: only the environment variable and the `.env` in the current directory remained. `find_dotenv` does walk up to the system root and therefore found a `~/.env` **when working beneath the home directory**, but found nothing when working elsewhere—coverage that depended on where the command was launched, not a design choice. A third layer is therefore added: `~/.config/aipmt/.env`, beneath the existing two.

    - **Priority is not hard-coded**; it follows from `override=False`, the default value of `load_dotenv`: each layer fills in only what the previous one left empty. Hence the order environment variable → project `.env` → user configuration, verified by BEHAVIOR tests rather than structural tests—reversing the order of the two calls makes them fail, as does removing the third layer.
    - **`.env` format rather than TOML**, deliberately: `python-dotenv` is already a dependency, the syntax is already documented in all 15 READMEs, and the same file serves both scopes. No new dependency or syntax. The location follows `XDG_CONFIG_HOME` if it is **absolute**—the specification requires ignoring a relative value, otherwise the configuration location would once again depend on the current directory—and `APPDATA` on Windows.
    - **Two options rejected, with reasons.** The system keyring (`keyring`) is safer on a desktop machine but fails in headless environments—servers, containers, CI—which are precisely the use case for batch translation; a good opt-in candidate, a poor default. A `--api-key` flag would put the key in the shell history and expose it in `ps`.
    - **Without a key, there is no longer a stack trace.** Users received a Python stack trace pointing to `site-packages`, plus a message mentioning “the environment or .env” without saying where to create the latter. It now lists all three locations with their exact paths, and the command exits with 2. The safety net is **deliberately narrow**: `except ValueError` around the configuration phase alone. Wrapping the entire execution would turn a real bug occurring during translation into a reassuring message—the failure mode this repository is designed to catch. A test reads the source of `main()` to prohibit this.

  - **Fix—the user's `.env` was ignored once the tool was installed.** `load_dotenv()` without an argument does not walk upward from the current directory, but from the CALLING file, thus from `site-packages`. Measured with a real console entry point launched from a project containing its own `.env`: `find_dotenv()` returns `''` and the key is not loaded, whereas `find_dotenv(usecwd=True)` finds it. The bug did not exist while the tool ran only from the cloned repository; publishing would have made it systematic, with the sole symptom being a “missing” API key despite correct configuration.

  - **Three gates would have turned green after ceasing to verify anything.** They were hardened BEFORE the move, deliberately: a safeguard written after the change it is supposed to catch proves nothing. Each is green on the original repository and turns red on a migrated copy—both directions were measured.

    - **Lizard silently ignores a missing path**: rc=0, “0 file analyzed.” The complexity gate would have dropped from 158 functions / 2247 nloc to 3 functions / 34 nloc, with zero-byte output. The scope is now an array whose entries are each checked for existence.
    - **`coverage run --source=` on a missing module does not fail**: warning on stderr only, rc=0 for both unittest and `coverage xml`, with the report still published—reduced from 1453 to 141 statements. The project would have appeared healthy because almost none of it was being analyzed anymore. Two lower bounds guard the report: the total and the largest measured file.
    - **The translation freshness probe is structurally blind to the invocation form**: it anchors itself to the argparse flags, precisely what a filename change does not alter. Reproduced: module moved, all 15 READMEs still documenting a nonexistent command, verdict “no stale translations.” A 7th section therefore checks the FORM rather than the options, and the Lizard hook is checked against the script's actual scope—its `files:` key does not make pre-commit fail when it no longer matches; it makes it SKIP the hook.

  - **`requires-python = ">=3.10"` is no longer merely an assertion.** `sonar-project.properties` already advertised 3.10–3.12 even though nothing had ever exercised those versions, since the development machine only had 3.12—an internal contradiction that publishing would have made public. A test workflow now runs the suite on 3.10, 3.11, and 3.12, installing the PACKAGE and therefore testing its public bounds.

  - **Lower bounds, no upper bound.** `requirements.txt` remains the tested lock, while `[project.dependencies]` becomes the public contract: publishing the lock's exact versions would cause conflicts for every user with other packages. No `<N+1` upper bound either—it would directly contradict `check-deps-fresh.sh`, which makes the release gate fail for any major-version lag. The set of lower bounds resolves successfully, and the `openai==1.0.0` counter-test exits with `ResolutionImpossible`, proving that the check discriminates rather than accepting everything. Another guard prevents the version in `pyproject.toml` from diverging from the CHANGELOG version: PyPI does not allow version numbers to be reused.

  - **Verified end to end in a fresh venv**: a wheel of about 70 KB containing only `aipmt/*.py`, dist-info, and the license; `aipmt --help` rc=0 with 22 flags; `python -m aipmt` displaying “usage: aipmt” rather than “usage: \_\_main\_\_.py”; functional `pipx` installation; and, most importantly, **an actual fr→en translation from an arbitrary user directory**, with bold text, list, inline code, link, and URL preserved, and the code block left untranslated. The 318 tests predating the migration pass with an identifier list identical byte for byte before and after—that is what proves no test was neutralized, not the “OK”; twelve more cover the three-layer configuration, for a total of 330.

- **1.10.0** `--use_codex` provider (ChatGPT subscription quota), SDK and model updates, fix for multi-paragraph news citations (2026-08-29):

  - **Security review—two safeguards that the PR introduced without enforcing them everywhere**:

    - **The Codex preflight passed the entire `.env` to the binary.** `_codex_preflight` called `subprocess.run` **without `env=`**: the subprocess inherited the complete `os.environ`, including the entirety of `.env` loaded by `load_dotenv`. Measured with an instrumented fake binary: **seven secrets** reached the preflight—the keys for all six providers plus one `GITHUB_TOKEN`—versus **zero** for its `_grok_preflight` counterpart, which correctly passed `env=_grok_env()`. The inconsistency was internal to the PR: `_strip_secret_env` exists precisely to enforce this invariant, only a few lines away. A `_codex_env_base()` is extracted and shared by both paths; measurement after the fix: 0 secrets on both sides.
    - **The “`--deny` fail-closed” property did not cover the form being used.** The comment justified all Grok confinement on the basis that a rule with an unknown prefix makes startup fail. Measured on `grok 1.0.13`, this validation exists **only for the parenthesized form**: `--deny 'CeciNestPasUnOutil(*)'` refuses to start (“unknown tool prefix”), whereas `--deny 'CeciNestPasUnOutil'` is silently accepted. Yet `GROK_DENY_RULES` used only bare names—renaming a tool on xAI's side would therefore have removed the only measured confinement layer without any signal, on a machine where the OS sandbox already does not apply. The eight named rules switch to `Prefix(*)`, each verified as a prefix known to the CLI; the catch-all `*` remains in its literal form, the only accepted one. A test prevents regression to the unvalidated form.
    - **Otherwise verified clean**: no command injection (list form everywhere, never `shell=True`, document content through stdin or `--prompt-file`), no unsafe deserialization (`json.loads` only, with a type guard), no bypass found for the path-traversal fix across seven payloads, and `--deny '*'` actually enforced by the CLI (`DENY_ENFORCED` observed on a read outside the workdir).
    - The freshness check added above also bypassed its own principle: a package whose PyPI request failed was silently skipped, leaving the gate green. It now counts the packages actually compared and fails if coverage is incomplete.

  - **Dependencies brought up to date, with two safeguards to prevent them from falling behind again**:
    - **The lag was real and persistent**: `openai` 2.54 → **3.6.0**, `anthropic` 0.125 → **1.2.0**, `certifi` 2024.8.30 → **2026.7.22** — two years behind on the root certificate store that validates TLS for all provider calls. Root cause identified: **there was no `.github/dependabot.yml`**. Without this file, GitHub enables only _security updates_, and Dependabot proposes a PR only for a dependency affected by a CVE — which explains why it bumped `urllib3` and `idna` while letting two SDKs drift by a major version.
    - **The two major versions coexist without conflict**, contrary to what earlier reasoning suggested: `openai` 3.x and `anthropic` 1.x migrate to **`httpx2`** while `mistralai` and `google-genai` remain on `httpx<1`, but these are two distinct distributions. Verified through an actual installation, then through **all 7 provider paths tested end to end** — OpenAI, Claude, Mistral, Gemini, Grok API, Codex CLI, and Grok CLI — with inline code and links preserved in every output. “Avoid two HTTP stacks” was a preference, not a blocker: measurement settled the matter.
    - **`requirements.txt` did not describe the actual environment**: `google-auth`, `cryptography`, and the `opentelemetry` stack were installed in the working venv without ever being declared — so a fresh installation did not reproduce what was being tested. Conversely, `tokenizers`, `huggingface-hub`, and `PyYAML` were listed there without being imported or required by anything, remnants of `mistralai` 1.x. The file has been regenerated as the complete closure of a venv built solely from direct dependencies. `pip-audit` reports no known vulnerabilities in the new set.
    - **`.github/dependabot.yml`** (new) enables weekly version updates for pip and github-actions. Minor and patch updates are grouped into one PR — one patch bump per PR eventually gets ignored, and noise is the enemy of maintenance; **major updates remain separate**, each requiring validation through an actual call.
    - **`scripts/check-deps-fresh.sh`** (new, wired into the gate) makes dependency lag visible in the project verdict: Dependabot proposes updates, but does not guarantee them, and its PRs can pile up. - **1.9.2** Fix news attribution URL extraction with nested parentheses or an FR prefix (2026-05-11):
