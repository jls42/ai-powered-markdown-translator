- **1.14.0** A compatibility table at the top of the README, and the measurement campaign supporting it (2026-09-09):

  - **The verdict for each model, at the top of the README, in French.** More than three hundred translations were buried in the middle of the document, spread across three tables that had to be read and cross-referenced. The new table delivers a verdict in one line per model and, above all, states what differs: “one missing bold word, in Arabic and Japanese” rather than a ratio. Three models have no differences detected by the comparator across the two dense documents — `gemini-3.7-flash`, `gpt-5.6-sol` through the ChatGPT subscription, and `z-ai/glm-5.2` through OpenRouter.
  - **A remeasurement campaign covering 176 translations.** The original measurements dated from September 4 and concerned a README that has changed considerably since then. Eight models were remeasured on this README, two on a monitoring article from the blog in `--news` mode, and one on four public READMEs — FastAPI, Ollama, tldr-pages, and Vue.js. Three results deserved to be recorded: Mistral drops an **entire section heading** in Arabic, Hindi, and Korean without any pipeline guard noticing — a heading cannot be replaced with a token, and nothing currently checks it during translation, even though the comparator detects it afterward; Grok fails on five languages in a monitoring article, dropping four inline code spans and three URLs in the very first segment, even though it holds up on a README; and Gemini produces 55 translations with no differences out of 56 across the four public READMEs.
  - **The structure comparator enters the repository.** The README described this protocol as the right way to judge a model — “compare the number of sections, links, distinct URLs, and code blocks” — without providing the tool. `scripts/compare_structure.py` is the tool that produced these tables, with eleven tests proving that it detects a lost URL, code block, section, inline code span, table row, and blockquote. It includes the two fixes for non-Latin scripts that made it reliable: a URL followed by a full-width parenthesis is no longer counted as different, and a shorter blockquote in Chinese is no longer treated as a lost blockquote.
  - **A package check, before and after publication.** The test suite runs against the source and stays green even when the distributed package is broken — a module omitted from the setuptools configuration, an entry point that does not resolve. `scripts/check-package-smoke.sh --wheel` builds the wheel, installs it in a disposable venv outside the repository, checks that it contains only the package, that both execution forms respond, and that every module imports, then translates a real document and compares its structure. `--pypi` does the same from the index: it is the only check proving that those exact bytes were published, and PyPI never allows a version to be republished. The `--full` gate runs its offline portion, without a model call or cost.
  - **Seven README claims corrected, all reproduced before being rewritten.** “Nothing incorrect reaches your disk” was false: a model that removes a section or changes a front matter date produces a file that the pipeline writes with `success` status, reproduced with a simulated response. The README now states what the tokens protect — code blocks, inline code, URLs, anchors, blockquotes — and what the pipeline guards do not currently check. “No differences” does not mean “identical”: the comparator counts elements without reading their contents, and it reports neither the removal of a level-four heading, nor the replacement of inline code text, nor a swapped flag — three measured cases; the phrase “same flags” was removed because the comparator has no flag counter. The contribution installation did not produce a usable tool: `pip install -r requirements.txt` installs only the dependencies, `python -m aipmt` returned `No module named aipmt`, and `pip install -e .` was missing — as was the installation line for `pre-commit`, absent from both dependency files. The OpenRouter promise about small contexts stated the opposite of what the code does: a model with a context window below **16,400 tokens** is rejected before any call, measured at 4,095, 8,192, and 16,384. The filter preventing a project `.env` from redirecting API calls was not documented anywhere; it is now, along with the list of affected variables. Finally, two figures: a Grok cell in the summary table came from a September 9 campaign even though its column indicated September 4, and “one broken link” attributed to Gemini was the opposite of the measurement — it turns three bare URLs into links and loses none.

  - **A write failure no longer leaves a truncated translation on disk.** `open(cible, "w")` truncates the file before filling it: an error during writing — a full disk — left a partial target there. Reproduced: eight bytes written, `failure` status returned, then the next run found that file, returned `skipped`, and kept it. A failure became a truncated translation that nothing reported anymore, and the exit code was 0. The content is now written to a temporary file in the same directory — `os.replace` is atomic only on the same filesystem — and then renamed, with the temporary file deleted if writing fails, including on interruption. This temporary file comes from `mkstemp`, and a review showed that a predictable name would merely have moved the problem: a symlink placed at `cible.md.aipmt-tmp` caused the translation to be written to the linked file outside the output directory while returning `success`; and two simultaneous runs on the same target shared that name, with the second renaming it while the first was still writing to the same inode — target reported as successful, mixed content (`BBBAAAAA` instead of `BBBBBBBB`, measured). `mkstemp` creates it in `O_CREAT | O_EXCL` under a unique name, closing both issues. The permissions of an existing target are explicitly copied before replacement: `mkstemp` creates files with 0600 permissions, and otherwise a target deliberately set to 0600 changed to 0664, while a 0644 target served by a web server would have become unreadable. Eight tests lock down the whole behavior, and two code mutations make them fail.

  - **The purity manifest can declare a rewritten suppression marker.** The check required every line carrying a `# nosec`, `# nosemgrep`, or `NOSONAR` from the reference to survive word for word. But moving a write to a temporary file renames the open variable: the Sonar suppression is the same, while its line changes. The manifest's `markers` category declares this `old` → `new` pair and its reason. Two conditions apply, the second coming from a review: the replacement must exist **and carry the same suppressions as the original line**. Without it, declaring `value = 1  # NOSONAR` → `value = 1` passed, meaning a declaration alone was enough to remove a marker — exactly what this check exists to prevent. An undeclared disappearance remains rejected.

  - **Two campaigns removed from the tables because they were interrupted by something other than the model.** Grok lost its CLI session after twelve languages of this README — two languages rejected in four seconds, without a model call — and `qwen3.8-flash` was throttled by an HTTP 429 from its upstream host after two. An interrupted campaign cannot be scored: they will be rerun in full or not at all. At the same time, the durations in the “README for this project” table were realigned with the September 9 campaign — they came from a 508-line revision, compared with the 785 lines measured, and reported 2 min 04 s for `gpt-5.6-sol` where the measurement gives 6 min 46 s.

  - **The README has been overhauled: 600 lines instead of 1,007, in a reader's natural order.** What the tool does, installation, configuration, getting started, then the compatibility table — placed after installation, once readers know what they are running — followed by options, one chapter per provider, detailed measurements, and finally how to contribute. Campaign narratives, measurement anecdotes, and repetition across sections have been removed; every retained figure comes from the tables, and every behavioral claim matches the code in this version. The overhaul log remains in the git history.

  - **The summary table now says HOW MANY languages each difference affects.** It said “✅ 14 languages” and then, in the adjacent column, “one bold word” — without saying whether that applied to one language or all fourteen. A reader could not tell, and the impression was poor where the measurement was good: on this README, Gemini has only one language out of fourteen with one extra bold word, Sol has two, and GLM has three. Every cell now includes the number of affected languages and identifies them; the figure in the verdict columns is defined in one sentence — the number of languages, out of fourteen, for which the translation is written and nothing differs — and a legend explains the meaning of the three symbols. The classification follows the owner's definition: ✅ nothing differs; ⚠️ everything is translated and only markup changes, with nothing missing; ❌ at least one language was rejected, or content is missing from a written file.

  - **The entire article campaign was recalculated with the current comparator.** Two figures had been published before the comparator was fixed for non-Latin scripts, and it counted differences that did not exist: `qwen3.8-flash` rises from thirteen to fourteen languages with no differences, and `qwen3.7-flash` from seven to eight. The passage about `gpt-oss` was corrected at the same time: its passages left in French never reached a delivered file, because the untranslated-excerpt guard rejected the four affected languages — that is the difference between a model that is stopped and one that slips through unnoticed, and the README names it.

  - **A disclaimer at the end of the README.** Sections 15 and 16 of GPL v3 already disclaim all warranties, but nobody reads a license before installing a tool. Four points are therefore stated plainly: a machine translation must be reviewed before publication, because the guards cover neither headings, tables, front matter, nor meaning; the translated document is sent to the selected provider under that provider's terms, and some free models may reuse exchanges — a local model remains the only path that does not send data out; API calls incur charges and the program does not cap spending; and published measurements are dated observations, not guarantees.

  - **The entire `gpt-5.6-*` family is available through the ChatGPT subscription**, as measured: through Codex, `--model gpt-5.6-terra` provides the model that the API serves by default. The default remains `gpt-5.6-sol`, the only model measured across fourteen languages without loss on a dense document, and it is the model that translates this repository.

- **1.13.0** `--use_openrouter` provider: a paid router to approximately 430 models, including open Chinese models (2026-09-05):

  - **The ninth provider path, shipped with the eighth.** Version 1.12.0 was not published on PyPI: the two routers, OpenCode and OpenRouter, are being released together. [OpenRouter](https://openrouter.ai) provides access with one key to models that no other provider exposes here — Kimi, Qwen, DeepSeek, Z.ai — using a single pay-as-you-go credit balance. Because the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything distinguishing this provider is contained in a preflight**, and every one of its rules comes from an API measurement.

  - **The same model is served by dozens of hosts with different limits, and routing is blind to them.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash` — including one capped at **2,048 output tokens**. A long translation routed to one of the 23 could therefore be randomly truncated without any signal whatsoever. The preflight reads `/api/v1/models/{modèle}/endpoints`, excludes hosts with fewer than 8,000 output tokens, hosts with degraded status, and hosts that declare no limit, then pins the remaining ones. `provider.only` **without** `allow_fallbacks: false` is only a preference: the router falls back to an excluded host, making the pinning worthless. If no host meets the limit, the command stops: translating anyway would mean accepting the silent truncation that this preflight exists to prevent.

  - **Reasoning is billed at the output rate and is enabled by default on many models.** Same request on `z-ai/glm-5.2`, response “OK”: **107 completion tokens with the model default, 2 with reasoning disabled**. For a translation, where reasoning adds nothing, that is an 18-fold factor for every segment of every file. It is therefore disabled by default. The **288 models out of 431** that require it (`reasoning.mandatory`) return `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for them, the preflight reads the accepted effort levels and requests the lowest one (next bullet) — effort allocates a **percentage of `max_tokens`** that reasoning consumes first, so choosing a value at random merely shifts the risk of a blank page instead of reducing it.
  - **A model that enforces reasoning receives the lowest effort it accepts, and that decision is measurement-based.** The first choice was to send nothing, so as not to guess on the model’s behalf. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced output **truncated at 32,768 tokens** before the translation was complete—two out of fourteen languages were lost. Increasing the envelope would not have changed anything: effort allocates a percentage of it, so reasoning grows along with it. The provider therefore reads `supported_efforts` during preflight and requests the lowest setting, falling back to “nothing” when the catalog does not advertise any usable value. A counter-test on the failing language confirmed the result: it previously failed because the budget was exhausted; it now completes in 9 minutes with a structure identical to the source.

  - **An upstream host outage is now identified by name.** The router normalizes this case as `finish_reason=error` with a null `native_finish_reason`—measured twice, on two languages, at exactly 750 seconds. The generic message sent users looking for a defect in the document or its segmentation; it now says that the failure is on the provider’s side and that retrying is often enough.

  - **`finish_reason=length` with empty output is not truncation.** It means the budget was consumed by reasoning before the first useful character—measured at 15,850 reasoning tokens for 148 useful ones. The two cases require opposite responses: reducing segment size is useless in the first case. The message distinguishes them explicitly. Two other safeguards come from measurements: the router responds with **200 and a body containing only an error** when the upstream host fails (`choices[0]` raised an opaque `TypeError` that hid the message), and the context window is read from the catalog and then recorded in `MODEL_TOKEN_LIMITS`—`DEFAULT_TOKEN_LIMIT` is wrong for 44 catalog models, including two capped at 4,095 tokens.

  - **`--model fournisseur/modèle` is mandatory, and its format is validated before any network access.** OpenRouter is not a provider: the choice determines price, licensing, and data processing, so it must not be made on the user’s behalf. Because the slug is interpolated into the preflight URL, validation is not merely a usability courtesy but the safeguard that prevents path injection: the shared namespaced regex used by both routers accepts `a/b/..`, hence the explicit rejection of the parent segment. `--eco` has no effect and says so.

  - **Three corrected statements, including one that was false.** OpenAI’s warning about `codex exec` concerned injecting a personal session file on a shared runner, not the repository being public: it was cited out of context in the README, CLAUDE.md, and the code. OpenCode’s authentication location changed in 1.18.27 (the `credential` table in `opencode.db`, no longer `auth.json`); the “never read here” invariant remained true, but the location was outdated. Finally, the OpenCode section no longer presents untested routes as equivalent: the Zen gateway and Ollama were measured end to end, while GitHub Copilot, LM Studio, and llama.cpp were not, and the README now says so.

  - **A measurement campaign, and a table of recommended models in the README.** More than three hundred translations were run across three document sets—a dense blog post in `--news` mode, this README in standard Markdown, and four README files from well-known projects taken as-is from GitHub—into fourteen languages. The table distinguishes two things that had been conflated: translations that **complete** and those whose **structure is identical** to the source. Three models never lost any information across the two dense documents: `gemini-3.7-flash`, `gpt-5.6-sol` through a ChatGPT subscription, and `z-ai/glm-5.2` through OpenRouter—their only discrepancies are a pair of `**` markers omitted in one or two languages. The central finding is that **the discriminating factor is document density, not `--news` mode**: subscription-based Grok fails thirteen out of fourteen times on the blog post and succeeds on fourteen out of sixteen public README translations, with the cause traced to a loss of coherence on a long segment and verified by a counter-test. The table carries its own warning: it is not exhaustive, it is dated, durations are not rankings, and the right approach remains to measure performance on your own documents.

  - **The structure comparator was fixed before its figures were published because it produced two false positives for non-Latin scripts.** A URL followed by a full-width closing parenthesis `）` was not split by a regex that stops at `)`, so the extracted string differed even though the URL was identical; a five-line French quotation fitting into three lines in Chinese caused a line-based count to drop. Both fixes were validated by counter-tests: removing a URL, section, or inline code is still detected. Without them, Gemini and Codex would have been reported as supporting eleven out of fourteen languages instead of thirteen and twelve.

  - **Tests**: new `tests/test_openrouter_provider.py` file (76 tests)—model validation and parent-segment rejection, host pinning (cap, status, undeclared cap, shared minimum), `allow_fallbacks` always false, reasoning disabled or retained according to `mandatory`, complete output contract (error inside a 200 response, no choice, blank page distinguished from truncation, abnormal `finish_reason`, null content), fail-closed preflight when the catalog is unreachable, missing slug and no healthy host, flag exclusivity, and filename label. Full suite at **502 tests**.

  - **Refactor: the single 4,253-line module is split into modules without changing a single line of behavior.** `src/aipmt/translate.py` is divided into `config`, `markdown`, `segmentation`, `guards`, `placeholders`, `news`, `prompts`, `notes`, `naming`, `pipeline`, `cli`, and a `providers/` subpackage (one module per provider, `base` as the foundation, `registry` for resolution and dispatch). Each move is a commit with mechanical proof: a verifier compares the AST of every top-level package node against a reference snapshot, checks the location of every symbol, the verbatim survival of security markers, and the absence of untracked files—temporary tooling removed by the following release. The visible changes are: `aipmt.translate` becomes a facade that re-exports, by object identity, the 64 names the module exposed without the `_` prefix (`__all__` contains nine of them, the supported API; the others are compatibility aliases), and it no longer re-exports the 29 dependency and standard-library names collected by `import *`; direct execution of the file (`python src/aipmt/translate.py`) no longer exists—`aipmt` and `python -m aipmt` remain the two supported forms; the `__module__` of public functions is now that of their defining module; SDKs are imported after `.env` is loaded rather than before, with no known consequence. All 427 tests are preserved down to their identifiers and migrated to the modules they exercise: 91 patches that previously went through the facade now target the module that looks up the name (two of them remained green without their patch, as measured), seven contract tests lock down the facade, and the gate tooling was rewritten BEFORE the first move so none could turn green merely by ceasing to check—directory-scoped Lizard with a floor, flags read from the constructed parser, per-package coverage floor, and `release.sh` enumerating tracked modules.
  - **Fix (pull request review)**: OpenRouter rejects a catalog entry without `context_length` instead of recording the 128,000-token default as a measurement—which also suppressed the “model not listed” warning—and, when `finish_reason` is null (documented type `string | null`), the host’s raw reason takes precedence, with `max_tokens` equal to `length`; an error attached to the choice itself causes the accompanying partial content to be rejected, with the same message as a normalized upstream outage—host detail, raw reason, and advice combined. OpenCode responds with its contract error, rather than a `AttributeError`, on a `part: null` event, and rejects a JSONL stream containing an unreadable event line instead of accepting partial text. All three agentic CLIs kill the agent’s process group when that process receives `SIGTERM` during the call—the regen’s `timeout` allowed the agent to survive and consume its quota—and the group’s `SIGKILL` always follows the grace period, with a shim that exits cleanly otherwise leaving its grandchild alive. A `# fmt: off` / `# fmt: on` pair split during modularization is reunited; the help text for `--reasoning_effort` names the four providers that use it.
  - **Fix (second review)**: the output cap requested from OpenRouter now reserves the portion of the context used by the prompt and segment—`context_length` covers BOTH input and completion, and six catalog models had requests sent with no room for the input; a context window that is too short is rejected before any billing occurs. The agentic CLI foundation falls back to `terminate` and then `kill` where POSIX process groups are unavailable, instead of letting a `AttributeError` pass through the timeout guard and prolong the wait. OpenCode’s `429` marker is searched for as a number rather than as a substring, where an error identifier such as `err_84290b` triggered 90 seconds of backoff before failing anyway. Finally, a noncanonical OpenRouter endpoint is displayed during preflight: a project `.env` is enough to set one, and it is the real key that would subsequently be sent.
  - **Security: a project `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file from the current directory and its parents: an untrusted directory tree—a repository that was just cloned—could set `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` (the latter read by the SDK itself) without knowing any key, after which the real key, supplied by the environment or user configuration, was sent in the authorization header to a third-party server. The filter operates on a PATTERN rather than a list: an inventory of the installed SDKs found twelve routing variables, including six used by the Anthropic client alone—a hand-written enumeration would have missed half of them. The project layer therefore rejects every variable matching `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, as well as proxies and certificate stores (pointing to a controlled authority makes an interceptor indistinguishable from a genuine server), along with `XDG_CONFIG_HOME` and `APPDATA`: setting them amounted to choosing which file constitutes the user layer, thereby bypassing the filter indirectly. These variables are accepted only from the two layers controlled by the user: the exported environment and `~/.config/aipmt/.env`. The project layer is also read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` copied the real key under a name that the subprocess pattern filter did not recognize—it then entered the environment of `codex exec`, violating the stated invariant. Finally, rejection messages display only the variable name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into logs even as it was rejected. A rejection is reported on stderr with instructions—an enterprise relay belongs in the user configuration.
  - **Fix: the OpenRouter output envelope is calculated for each call.** `context_length` covers BOTH input and completion, and a fixed reserve calibrated on Latin text provides no bound at all: measured with the `o200k_base` tokenizer, 16,000 characters amount to 3,200 tokens in French, but 12,300 in Japanese and 17,500 in emoji. The budget therefore comes from the text actually sent, bounded above by its UTF-8 byte count: for any byte-fusion tokenizer—byte-level BPE, SentencePiece with byte fallback, the families used by the catalog—a token is worth at least one byte, and this is the only available upper bound here, where OpenRouter routes to dozens of unknown tokenizers. No average ratio was suitable—a supplementary-plane ideograph drops to 1.33 bytes per token, a combining character to 1.00—and input plus output now fit within the window by construction. A segment that is too dense for the selected model is rejected before the call rather than after billing.

- **1.12.0** `--use_opencode` provider: OpenCode, the open-source agent, connected to the provider of your choice—local model, free without an account, subscription, or key (2026-09-04):

  - **An eighth provider path, fundamentally different from the first seven.** [OpenCode](https://opencode.ai) (MIT) is not a model provider but a _router_ to those configured by the user in OpenCode itself: an API key, a subscription (GitHub Copilot, ChatGPT, SuperGrok), the OpenCode Zen gateway—which serves free models **without an account**—or a **local** model (Ollama, LM Studio, llama.cpp). The script drives `opencode run` in non-interactive mode, just as it drives Codex and Grok, and reuses the same subprocess foundation (dedicated process group, `SIGTERM` followed by `SIGKILL` on timeout, stdin always closed, sanitized environment). Verified through **two real translations**: this entire README into English via `opencode/mimo-v2.5-free`—49 seconds, a single pass, structure identical to the source file (32 headings, 26 code fences, 18 links, 37 URLs, 37 table rows, 135 inline-code spans)—and a test file via `ollama/qwen2.5:7b`, locally, without any key.

  - **`--model provider/modèle` is mandatory, and it is a choice.** Without `--model`, OpenCode falls back to its own default, which on a fresh installation is `opencode/big-pickle`, a free “stealth” model whose exchanges may be used for training—measurement confirmed that this was the model that responded. Silently choosing that on the user’s behalf would be exactly the kind of invisible switch this repository tracks; the error message therefore names the command that lists models (`opencode models`) and gives three examples (local, free, subscription). `--eco` has no effect and says so. `--reasoning_effort` is passed through unchanged as OpenCode’s `--variant`, only when explicitly requested.

  - **Measured confinement, not assumed.** An inline configuration (`OPENCODE_CONFIG_CONTENT`, last in OpenCode’s merge order and therefore taking precedence over the user’s configuration without replacing it) defines an `aipmt` agent for which all tools are denied (`permission: {"*": "deny"}`): the registry no longer even offers them to the model, which, when instructed to “list the files and run `id`,” responds that it has no tools. Session sharing is disabled, external plugins excluded (`--pure`), and `--auto` is never used; the working directory is disposable and empty. Two silent injections were measured and blocked: without `OPENCODE_DISABLE_CLAUDE_CODE`, the user’s `~/.claude/CLAUDE.md` enters **every** prompt (515 input tokens instead of 186 for a simple “Hello”); without `OPENCODE_DISABLE_PROJECT_CONFIG`, the current directory’s `AGENTS.md` does too—an instruction to “end every response with BANANA” was applied to the translation. The global `~/.config/opencode/AGENTS.md`, however, remains injected: no switch excludes it, and bypassing it through a repurposed `XDG_CONFIG_HOME` would also hide the user’s providers. Documented instead of patched around.
  - **`exit 0` proves nothing, third CLI, same instincts—with two traps specific to this one.** An unknown `--agent` does not cause `opencode run` to fail: a warning on stderr and a **silent** fallback to the coding agent, with tools enabled. If the inline configuration were not taken into account, the translation would therefore start with an agent capable of writing; the output contract checks that this message is absent, in addition to: return code 0, no `error` event, no `tool_use`, final `step_finish` in `stop` (a `length` is a truncated response), non-empty text. Second trap: the JSON error event is **opaque**—“Unexpected server error. Check server logs for details.”, with only a reference—and the real cause (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) exists only in the logs. Hence `--print-logs --log-level ERROR` and reading the `error="…"` field from stderr, without the Bun trace that follows it. An unknown model thus fails in one second, with its cause named. `--title` also avoids a stray LLM call: without it, OpenCode generates a session title through an additional turn on `small_model`.

  - **Secrets: same pattern-based filtering as Codex and Grok, with one named exception.** `OPENCODE_API_KEY` is retained: it is OpenCode’s own key (Zen gateway, Go subscription), addressed to it by name—the equivalent of its `auth.json`, not a key that aipmt would manage or be able to bill. Providers are configured in OpenCode (`opencode auth login`, `opencode.json`), never in aipmt’s `.env`, none of whose keys reach the subprocess. No rejection in CI, unlike subscription CLIs: an API key or a self-hosted model on a runner are legitimate uses.

  - **The anti-traversal guard now checks the interpolated value, not the raw value.** `provider/modèle` contains a `/` that the 1.10.0 guard rejected—rightly so, since `--model` was interpolated into the filename `--include_model`. The filename label now replaces `/`, `\`, and `:` with `-` before any interpolation (`ollama/qwen2.5:7b` → `ollama-qwen2.5-7b`, since `:` is illegal on Windows), and the upstream guard examines this label: `../../evil` becomes the simple name `doc-en-..-..-evil.md` under the target, only `..` remains rejected, as does `--target_lang ../x`. - **1.9.2** Fix news attribution URL extraction with nested parentheses or an FR prefix (2026-05-11):

  - **Fixed bug**: attribution URL extraction in `_protect_news_quotes` used the regex `re.search(r"\((.+?)\)", attribution)` (lazy capture between parentheses).
