- **1.16.1** Internal links: the anchor token leaves its parentheses to the link, and a translated link no longer silently duplicates (2026-09-27):

  - **An internal link no longer breaks unnoticed.** To protect a link to a section, `[texte](#ancre)`, aipmt used to replace its parenthesized part, parentheses included, with a token: the model received square brackets followed by a bare token, a seemingly broken link, and sometimes tried to "fix" it. Restoration would then yield `[texte]((#ancre))`, a link leading nowhere, without any guard flagging it. The flaw recurred with every regeneration of this repository's translations—in Spanish, Korean, and then Italian for 1.15.0, in German for 1.16.0—with every Gemini Flash tested, and even with Claude Sonnet and Haiku. A Markdown link's token now keeps its parentheses: the model receives a valid link that it has no reason to fix, and restoration also accepts a token from which it might have removed the parentheses. HTML anchors keep a bare token. Verified end-to-end with the most fragile model, `gemini-3.8-flash-low`, on a README where a link was in parentheses: without the fix, README rejected, three duplicated links, and one re-processed segment; with it, three out of three links intact, zero retries. Then on this README, in German, Japanese, and Hindi using `gemini-3.8-flash-medium`, and in German using Claude Code with `sonnet`: structure identical to source, all three internal links intact everywhere.

  - **Tests can no longer modify the repository running them.** When pushed from a linked worktree, git passes the variable designating the repository to its hooks, and the pre-push hook runs the tests: a test's `git init`, intended for a temporary directory, reset the real repository, suddenly declared bare of a worktree. Tests running git now strip any `GIT_*` variable from their environment, and a regression test, pointing this variable to a decoy repository, verifies it.

- **1.16.0** Provider `--use_claude_code`: translate using Claude Pro or Max subscription quota via the official `claude -p` CLI—no paid routes, and every call proves it (2026-09-26):

  - **Eleventh path: the Claude subscription, without pay-as-you-go billing.** `--use_claude_code` drives the official Claude Code binary in `-p` mode, on the same foundation as Codex, Grok CLI, and Antigravity—dedicated process group, safe shutdown on timeout, Ctrl-C, or terminal closure. Not to be confused with `--use_claude`, Anthropic's pay-as-you-go API. aipmt never reads the token.

  - **No paid route, verified at three levels.** The subprocess environment is an allowlist: no API key, token, cloud provider, or marker from the Claude Code session from which aipmt might be launched—the session that wrote this provider exported fifteen of them. Preflight, without model turns, requires subscription login without Console key from `claude auth status`, and the phrase certifying the subscription from `/usage`. Each call must then attest it in its initialization event—`apiKeySource: none`, forced environment acknowledged, model belonging to the requested family, no fast mode—and in its quota report: paid "extra usage" immediately halts translation.

  - **Quota is shared with Claude Code sessions, and the provider conserves it.** Each call reports usage for the 5-hour and weekly windows; above 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), no further segment is launched. On the day of writing, the author's weekly account usage was already at 98%.

  - **Nothing from user configuration enters, nothing from the session remains.** Tool-free, in customization-free mode, user settings ignored, MCP servers and hooks disabled, private and disposable working directory, no transcript kept. Measured via canaries: without `CLAUDE_CODE_DISABLE_ATTACHMENTS`, an `@chemin` in the document became an attachment, and the model returned a read call instead of the translation; with it, nothing slips through. The `AGENTS.md`, `CLAUDE.md`, and hook canaries loaded and executed nothing.

  - **A segment starting with `/` did not reach the model.** Under `--disable-slash-commands`, Claude Code itself responds "... isn't available in this environment.", with status `success`, without any turns. A newline before the segment sends it to the model; the output contract rejects in any case a response returned with zero turns, in more than one turn, truncated, or by a different model than the one announced.

  - **Models: aliases, never a pinned identifier.** `sonnet` by default, at `low` effort, and in `--eco` as well—`--eco` therefore changes nothing on this path—, `opus` and `haiku` via `--model`; `fable` and `[1m]` variants are rejected, because in `-p` they switch to paid credits without asking.

  - **Defects are measured, not assumed.** By `aipmt --use_claude_code` itself, four parallel translations, across the two benchmark documents from the README—the dense intelligence briefing, in `--news`, and this README at revision 1.14.0—fourteen languages each. `sonnet`, at `low` effort, writes all 28 translations, 26 without discrepancy: one extra bold word in Chinese on the article, and in Arabic, on the README, a table row merged into the previous one, concealed by rendering. Internal links intact, English quotes copied verbatim, and in English the French translation rows stripped by the model, without invented flags; 6 min 49 s median per language on the article, 2 min 20 s on the README. `opus` translates the README without any discrepancy, a quarter faster, but zero articles: its guardrails halted the response across all fourteen languages on a biology news brief. `haiku` writes everything—three section headings bumped to level 1 on the article, English README internal links duplicated—but twice as slow as `sonnet`: it reasons uncontrollably, 61% of its output tokens, and its lower price only yields 14% savings in API equivalent. Hence `sonnet` in `--eco` too. Effort is useless for translation: on a preliminary batch—this README and this CHANGELOG in English, Japanese, and Hindi—`sonnet` produced zero reasoning tokens, `opus` with medium effort 1% of its output tokens, and medium effort gained nothing over low effort, neither in structure nor in duration. The `sonnet` campaign, 1.8 million source characters, consumed 9 percentage points of the 5-hour window and 2 of the weekly window on the author's Max subscription—an upper bound: the session orchestrating the benchmarks drew from the same quota.

  - **A refusal from Anthropic's guardrails is reported as such.** Opus 5.5 has stricter guardrails than Sonnet, and Anthropic's error message warns that they sometimes flag work close to biological research. A monitoring brief covering 279 molecules generated for a binding site was enough. Claude Code then cuts the response, retries once, and the model returns "I can't continue this translation" with a success status, without errors, over two turns: only the single-turn contract halted this response, with a message silent on its cause. Sent alone, the brief is rejected by the API under the "bio" category. aipmt now recognizes these signs, names the guardrails and their category, does not retry—the same text would trigger the same refusal—and recommends `--model sonnet`, which translated the brief in all fourteen languages.

  - **Translations for this repository can go through this path, with no exemption.** `REGEN_PROVIDER=claude_code` is a subscription, not a billed API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs—the campaigns ran four concurrent translations without a single rate error or connection lock—after a single preflight that consumes no quota. The default remains Codex with `gpt-5.6-sol`.

  - **Terms of service, stated plainly.** Claude Code's legal page does not prevent a user from connecting to the unmodified binary with their own subscription; it prohibits third-party developers from routing requests through their users' Pro or Max credentials, and Anthropic prefers the API key for third-party tools, open-source projects included, reserving the right to charge their usage against paid credits. No terms explicitly settle the case of a distributed tool running the official binary: users commit their own accounts.

  - **Tests**: new file `tests/test_claude_code_provider.py` (58 tests), 100% of module statements and branches, without ever launching the real `claude`—cleared environment, non-existent binary, `PATH` without `claude`, test doubles that raise if called.

- **1.15.0** Provider `--use_antigravity`: translate using Google AI Pro or Ultra subscription quota via the official `agy` CLI; and, across all providers, Ctrl-C no longer abandons in-flight agents, a blank segment no longer fails the file, and a project `.env` no longer chooses the executed binary (2026-09-26):

  - **Tenth provider path: the Google subscription, without pay-as-you-go billing.** Anyone paying for Google AI Pro or Ultra can now charge translations against it instead of paying per token on the Gemini API. `agy`, the official Antigravity CLI, is the only path to this quota: Gemini CLI no longer serves Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK only authenticates via an API key or Google Cloud. `--use_antigravity` drives it in headless mode, like Codex and Grok CLI, on the same foundation—dedicated process group, `SIGTERM` then `SIGKILL` on timeout, sanitized environment. Verified end-to-end on agy 1.2.11: a Markdown guide—front matter, bold, parenthesized link, inline code, indented code block in a list, table, blockquote—translated into English in 14 seconds, preflight included, structure identical to source, translator's note added; then, after review fixes, into German in 19 seconds, identical structure, nothing written to `~/.gemini`.

  - **No paid route remains open, and each launch verifies it.** agy knows routes other than subscription—API key, Google Cloud project, gateway, paid AI credits—and several environment variables switch it there without displaying anything. Measured: `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, `CLOUD_CODE_URL` diverts the authenticated endpoint to any arbitrary address. The subprocess environment is therefore an allowlist, not a denylist: `PATH`, language and timezone, terminal, identity, machine proxies and certificates, and the session bus—what an `env -i` proved agy needs—without any key. A denylist by prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`...), tested first, missed some: a review found endpoint overrides in the binary's strings that no prefix covered, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings escape the environment and can only be read via `agy -p /config`: paid AI credits taking over when quota is exhausted, and logging in via a Google Cloud project. A preflight that consumes zero quota—zero usage, measured—refuses to translate if either is active or if an API key is configured, and a missing setting in `/config` counts as a rejection for each of the three: an agy version renaming one must not pass a check that verified nothing. Finally, the log for each call must attest subscription authentication (`authMethod=consumer`), and any other authentication method appearing there, under either of the two spellings the binary uses, causes the response to be rejected: the call itself is what counts, not the configuration that was prepared.

  - **The translation agent has no tools, and its loading is proven on every call.** Each call writes, to a disposable directory, an agent formatted as an agy project agent: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. About 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone allowed a workspace hook to execute its commands and inject its text. The real trap lies elsewhere: a missing agent does not make agy fail. Return code 0, status `SUCCESS`, and the coding agent, with 57 active tools, responds—to "The cat is sleeping.", it replied "Shh, let's not wake him! 🐱💤 What can I do for you today?". Nothing on stdout or stderr: only the call log shows it. The response is therefore rejected if the log reports this fallback, and also if it lacks the positive marker confirming agent loading—a change in log format causes translation to be rejected instead of silently dropping the guard. Each marker must occupy an entire log line, in the measured format—severity, date, time, thread, file, and line: the binary also contains a line that echoes the user's message into the log—never seen at default log level across 78 real logs—and a document quoting these messages must not be able to satisfy the guard in agy's place.

  - **User agy settings and history are untouched.** Each call runs with a private HOME, temporary directory, and working directory, deleted afterwards. agy still authenticates via the system keychain, which aipmt never reads. Nothing is inherited: neither user permissions—which allowed the default agent to run `ls` and `git` without prompting—nor global rules, plugins, MCP servers, hooks, and skills. And nothing is added to their history, where each call left an ~200 KB conversation, including translated text: the probe campaign had left about 95 conversations there and evicted 17 entries from a cache capped at 100. Verified: no files written to `~/.gemini/antigravity-cli`.

  - **Fail-closed refusal where isolation cannot hold.** Under Linux without a D-Bus session bus—SSH session, container, server—agy stores its token in a file under `~/.gemini` instead of the keychain, as stated in its own changelog (1.1.3), and per-call isolation hides this file. Rejection now occurs before any launch, with its genuine cause, instead of a one-minute wait for a login code followed by reconnection advice that solves nothing. Under Windows, agy reads `USERPROFILE`, `APPDATA`, and `TEMP`, not `HOME` or `TMPDIR`—according to Go documentation and binary strings—: nothing would isolate the call from user settings or history there, and `--use_antigravity` is rejected there until measured. macOS passes without being measured; the billing guard, which reads the effective configuration, holds there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero exit code, a JSON object with status `SUCCESS`, a conforming log, no rejected action, no command, no error in the JSON, no truncation warning on stderr, and non-empty text. `--print-timeout` is never used: upon expiration, agy returns partial output in `SUCCESS`, exit code 0; the timeout is external and kills the process group. A segment starting with `/commande`, `!commande`, or `@fichier` is translated, never executed or resolved—without `--disable-slash-commands`, "/help" executed instead of translating. A whitespace-only segment no longer reaches agy, as the pipeline returns it as is (see below), and remains rejected before the call as a safety net: on empty input, agy opens its interactive interface with exit code 0. Retries follow the `retryable` field of the `AGY_ERROR` line that agy writes to stderr since 1.2.6: it already retries transient errors on its own—502, 503, 504, per-minute rate limit—and it is the one that knows if the remaining failure is still transient. In the absence of this field, no retry when the message mentions exhaustion—at Google, `RESOURCE_EXHAUSTED` carries the same 429 code as a per-minute limit, but an exhausted 5-hour window does not recover in 90 seconds—and otherwise on rate limiting only. The response preserves the line ending of the segment: agy always terminates its output with a newline, which, at the junction, split in two a paragraph broken mid-sentence. A logged-out session produces a message telling to run `agy` to log back in. Finally, `AGY_CLI_DISABLE_AUTO_UPDATE=true` prevents a fresh HOME from spawning an update checker on every call in its own session, out of reach of the timeout—the `1` value itself has no effect.

  - **Models: reasoning effort is part of the name.** Identifiers are those of `agy models`—`gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`... A bare base name, which agy would reject, is rejected before the call, listing existing suffixes: `-medium` or `-low` for a Flash, `-high` or `-low` for a Pro. By default `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` as `--eco`, set by the benchmark campaigns described below. `--reasoning_effort` has no effect and says so. Claude and GPT-OSS draw from a separate and much smaller quota—around 1% of the 5-hour window per measured call, compared to 0.05% with Flash—and a warning reminds of this. The remaining quota can be checked for free via `agy -p /usage`. Rejected in CI, like Codex and Grok CLI: the login session lives in a personal keyring, and the message suggests `--use_gemini` with a Google key.

  - **Two benchmark campaigns on September 26: defaults are measured, not assumed.** Using `aipmt --use_antigravity` itself, four translations in parallel, each compared to its source via `scripts/compare_structure.py`, with the quota read by `agy -p /usage` before and after. In the morning, on the revision of this README published with 1.14.0 and on the dense tracking article of the README benchmarks, in `--news`, `gemini-3.7-flash-medium` wrote all fourteen languages for both documents: the article with zero discrepancies, 3 min 14 s per language median, and the README within one bold word in Korean, in 1 min 22 s. In the afternoon, at the author's request, Gemini 3.8 Flash versus 3.7 on the same batch, this README and this CHANGELOG in version 1.15.0: at medium effort, identical structure for both; 3.8 reasons as much as 3.7—63% of output tokens versus 60%, read from agy's JSON—and costs one-seventh more quota, for one-quarter more time. Then the morning campaign, rerun on `gemini-3.8-flash-medium`: fourteen out of fourteen languages with zero discrepancies on the article, 3 min 59 s median, as on the README, 1 min 43 s; internal links intact across all fourteen READMEs, where 3.7 broke some in Italian; and in English, French translation lines removed by the model, with no hallucinated flags, English quotes intact. Hence the defaults: `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`. At low effort, neither Flash model reasons and each costs half as much, but 3.8 low duplicated the three internal links of a README in Hindi, which 3.7 low did not do in any translation it produced. Measured cost on the author's account tier: 13 to 16 points of the 5-hour window per million source characters in `gemini-3.8-flash-medium`—the rerun campaign, 28 translations and 1.8 million characters, consumed 24.5, and 4.1 from the weekly quota.

  - **Terms of service and data processing, plainly stated.** Antigravity's terms of service (Section 6) and its FAQ prohibit accessing the service through third-party software using the Antigravity login session—Claude Code, OpenClaw, and OpenCode are cited there—under penalty of account suspension. aipmt never reads or reuses the token: it runs the official binary in the headless mode that Google documents for scripts and CI, and a Google staff member deemed it "standard," on the official forum, to run `agy -p` from a local script for one's own work—an answer, not a commitment. No policy settles the case of a distributed tool: the README states that the user assumes responsibility for their account. Section 5 of the same terms allows Google to use exchanges—prompts, responses, metadata—to improve its products and machine learning, and to have them reviewed by humans, without distinguishing the free tier from Pro and Ultra: the README reserves this path for public documents, and its closing warning mentions it.

  - **Translations for this repository can go through this path, with no exemption.** `REGEN_PROVIDER=antigravity` is a subscription, not a metered API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs—the entire campaign ran at four in parallel, without a single error—and the 1,800-second per-job cap from Codex, which the benchmark justifies: the entire CHANGELOG in Hindi, the file where Codex drops placeholders, was translated without discrepancy in 4 min 33 s by 3.7 Flash in its 1.14.1 version, and in 5 min 50 s by 3.8 Flash in its 1.15.0 version, one-fifth longer: at least five times under the ceiling. A full regeneration, 2.2 million characters, amounts to 30 to 36 points of the 5-hour window in `gemini-3.8-flash-medium`. A single check, the module preflight, precedes the 28 jobs: a logged-out or billed-configured agy launches none. The default remains Codex with `gpt-5.6-sol`.

  - **An internal link was breaking without anything noticing.** The placeholder protecting an anchor swallows its parentheses: the model receives an apparently broken link, brackets followed by the bare placeholder, and occasionally "repairs" it. Restoration then yields `[texte]((#ancre))`, which leads nowhere, without any guard or `compare_structure.py` reporting it. This happened in two READMEs during the first regeneration of this version, and with all tested models, more frequently when the link itself is enclosed in parentheses—as was the case for a link this version had just added to this README. The release verification now counts intact internal links in each translation, and this README no longer places any inside parentheses; the fix for the placeholder itself remains to be done.

  - **Ctrl-C and terminal closing now terminate the agent, across all four CLIs.** Codex, Grok CLI, OpenCode, and Antigravity run in their own session, outside the foreground group: the `SIGINT` of a Ctrl-C does not reach them, and, on Ctrl-C, `Popen` waits for them only a quarter of a second before yielding control. Verified during review on a dummy binary: the agent survived aipmt and finished its run against the quota, producing a discarded result—four at a time during regen. A `KeyboardInterrupt` or `SystemExit` during the call now kills the agent's group before bubbling up. Closing the terminal or dropping an SSH session (`SIGHUP`) killed Python without any cleanup: the agent kept running, and Antigravity's private directory remained on disk along with its log, which carries the account address. `SIGHUP` now follows the `SIGTERM` path: agent group killed, then exit 129. An ignored `SIGHUP`, via a launch under `nohup`, remains ignored: that is the user's choice. The Antigravity preflight—`agy --version`, then `agy -p /config`—goes through the same handler: a signal received during this check stops agy and also cleans up the private directory, instead of leaving it on disk with its log.

  - **The subprocess driver can no longer target the entire session.** On Linux, `killpg(1, sig)` equals `kill(-1, sig)`: the signal is sent to all of the user's processes. This happened while writing this version, through a mutation testing run: a mutant called a `Popen` mocked by a bare `MagicMock`, the resulting error went through the new interrupt path, and the dummy process PID, which Python converts to 1, caused the entire graphical session to be killed. `_codex_kill_group`, shared across all four CLIs, now targets a group only if the PID is a genuine integer greater than 1, `getpgid` returns that same PID—an agent spawned in its own session is its process group leader—and it is not the current process group; otherwise, only the direct child is targeted. In production, this guardrail changes nothing: it closes the gap where a bug might bubble up something else. Mock objects for `Popen` that are not meant to be used now fail immediately, fake processes carry an impossible PID, and mutation runs execute inside a PID namespace.

  - **A whitespace segment no longer causes the file to fail, regardless of the provider.** `segment_text` can isolate whitespace at the end of a document: 16,001 characters ending with three newlines yield a second segment consisting of two newlines. Antigravity rejected it before the call—reproduced during review—and, with an API provider, an empty response hit the empty content guard: in both cases, the entire file failed, after quota for previous segments had already been consumed. A whitespace segment is now returned as is, without an API call.

  - **Security: a project `.env` can no longer select the executed binary.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`, and `AGY_BIN` specify the program executed by translation, with the user's privileges: set by the `.env` of a freshly cloned repository, they would launch a file from that repository upon the first translation. The `_BIN` suffix therefore joins `_BASE_URL`, `_API_BASE`, and `_ENDPOINT` in the project layer filter, along with `GROK_HOME`, under which the Grok binary is searched (`$GROK_HOME/bin/grok`). These variables remain accepted from the environment and `~/.config/aipmt/.env`, and every rejection is reported on stderr along with where to place them.

  - **Tests**: new `tests/test_antigravity_provider.py` file (103 tests), covering 100% of statements and branches in the module—exact argv and never `-p`, segment via stdin, agent written with no tools or inheritance, environment restricted to the allowlist, private directory deleted after success, failure, timeout, or signal, complete output contract, agent fallback and billing tier parsed from log lines in real format, `AGY_ERROR` and `retryable`, strict billing preflight, rejection under Windows and without a session bus, effort suffixes, line ending preserved from the segment, dispatch wiring, and regen branch. No test executes agy: a mock binary prepended to `PATH` was never called during any run, including under CI conditions, with session bus masked and `CI=true`. `tests/test_provider_base.py` interrupts a real subprocess via Ctrl-C and `SIGHUP`, including under `nohup`, and locks the `killpg` guardrail—PID `MagicMock`, boolean, 1 or less, current group or another's group: never a group signal; `tests/test_key_resolution.py` spawns a fresh process for each `_BIN` variable; `tests/test_orchestration.py` translates a document whose trailing whitespace forms a standalone segment. Full test suite at **650 tests**.

- **1.14.1** Mistral: rate limit overruns no longer fail the file, and default models are confirmed by measurement (2026-09-17):

  - **An HTTP 429 caused the entire file to be lost.** The `mistralai` SDK retries nothing by default, unlike those from OpenAI and Anthropic, and Mistral's limits are low and specific to each model: 15 requests per minute for Large 3, 100,000 tokens per minute for Small 4, measured on the repository's account. A run with four concurrent translations on Small lost five out of eighty-four. The client now retries on 429, 5xx, and connection errors, with an increasing backoff from 2 to 60 seconds for at most five minutes: Mistral's 429 does not specify how long to wait, and its limits are tracked per minute. Counter-test on the API: twenty consecutive calls on Large 3, twenty succeeded, the sixteenth after a 33-second wait.
  - **A response in reasoning blocks no longer breaks translation.** Small 4 and Medium 3.5 reason when prompted to do so, and the response then becomes a list of `thinking` then `text` blocks instead of a string. Neither reasons by default (measured), but a default change on the provider side would have ended in `AttributeError`: reasoning blocks are discarded, as with Claude.
  - **Default models confirmed: `mistral-large-latest` and `mistral-small-latest`.** The only newer model, Mistral Medium 3.5, was benchmarked against them in all fourteen languages, on the dense tracking article of the compatibility table and on the README. On the article, it drops or changes the level of headings in 9 out of 14 languages—only a single discrepancy-free translation, compared to 6 for Large 3 and 8 for Small 4—and it costs 3 times more than Large 3 on input, 5 times on output. The aliases point to Large 3 (`mistral-large-2512`) and Small 4 (`mistral-small-2603`).
  - **`MODEL_TOKEN_LIMITS` aligned with the API**: 262,144 tokens for the Mistral lineup instead of 256,000, 131,072 for `ministral-3b`, and dated identifiers, including `mistral-medium-2604`, no longer trigger the "unlisted" warning. Segmentation, capped at 16,000 characters, remains unchanged.

The new table settles it in one line per model, and above all states what differs: "a forgotten bold word, in Arabic and Japanese" rather than a ratio. It carries the two non-Latin script fixes that made it reliable: a URL followed by a full-width parenthesis is no longer counted as different, and a shorter blockquote in Chinese is no longer considered a lost blockquote.

The `--full` gate runs the offline part, without model calls or costs.

- **1.13.0** Provider `--use_openrouter`: a paid router to ~430 models, including open Chinese models (2026-09-05):

  - **Ninth provider pathway, shipped alongside the eighth.** 1.12.0 was not published on PyPI: both routers, OpenCode and OpenRouter, are released together. [OpenRouter](https://openrouter.ai) provides access with a single key to models no other provider exposes here — Kimi, Qwen, DeepSeek, Z.ai — against a single pay-as-you-go balance. Since the endpoint is OpenAI-compatible, the client is identical to the one for xAI; **everything distinguishing this provider lies in a preflight check**, and each of its rules stems from API measurements.

  - **The same model is served by dozens of providers with different limits, and routing is blind to this.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash` — including one capped at **2,048 output tokens**. A long translation thus had a 1-in-23 chance of being randomly truncated without any warning. The preflight reads `/api/v1/models/{modèle}/endpoints`, discards hosts with under 8,000 output tokens, those with degraded status, and those reporting no limit, then pins the rest. `provider.only` **without** `allow_fallbacks: false` is merely a preference: the router falls back to a discarded host, and the pinning becomes worthless. If no host meets the limit, the command aborts: translating anyway would mean accepting the silent truncation this preflight exists to prevent.

  - **Reasoning is billed at the output rate, and active by default on many models.** Same query on `z-ai/glm-5.2`, "OK" response: **107 completion tokens at the model default, 2 with reasoning disabled**. For translation, where reasoning adds no value, that is an 18x factor on every segment of every file. It is therefore disabled by default. The **288 models out of 431** that enforce it (`reasoning.mandatory`) return `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for them, the preflight inspects supported efforts and requests the lowest one (next bullet) — effort allocates a **percentage of `max_tokens`** that reasoning consumes first, meaning an arbitrarily chosen value shifts the blank-page risk rather than mitigating it.

  - **A model that enforces reasoning receives the lowest effort it accepts, and a measurement decided this.** The initial choice was to send nothing, so as not to guess on the model's behalf. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced an output **truncated at 32,768 tokens** before the translation finished—two out of fourteen languages lost. Increasing the envelope would not have changed anything: the effort allocates a percentage of it, and reasoning grows along with it. The provider therefore reads `supported_efforts` at preflight and requests the lowest one, falling back to "nothing" when the catalog reports none that can be used. Counter-test on the failing language: it used to fail on an exhausted budget; it now passes in 9 minutes with a structure identical to the source.

  - **An upstream host outage now goes by its name.** The router normalizes this case to `finish_reason=error` with a null `native_finish_reason`—measured twice, across two languages, at exactly 750 seconds. The generic message used to prompt looking for a flaw in the document or the chunking; it now indicates that the outage is on the provider side and that retrying is often enough.

  - **`finish_reason=length` with an empty output is not truncation.** It is the budget consumed by reasoning before the first useful character—measured at 15,850 reasoning tokens for 148 useful ones. The two cases call for opposite actions: reducing chunk size is useless in the first. The message explicitly distinguishes between them. Two other guards stem from measurements: the router responds with **200 and a body containing only an error** when the upstream host fails (`choices[0]` raised an opaque `TypeError` that masked the message), and the context window is read from the catalog and then recorded in `MODEL_TOKEN_LIMITS`—`DEFAULT_TOKEN_LIMIT` is false for 44 models in the catalog, two of which are capped at 4,095 tokens.

  - **`--model fournisseur/modèle` is mandatory, and its format is validated before any network call.** OpenRouter is not a provider: the choice affects price, license, and data processing, and is not made on the user's behalf. Since the slug is interpolated into the preflight URL, validation is not a matter of ergonomics but the guard that prevents injecting a path into it: the namespaced regex shared by both routers accepts `a/b/..`, hence the explicit rejection of the parent segment. `--eco` has no effect and says so.

The agentic CLI base falls back to `terminate` then `kill` where POSIX process groups do not exist, instead of letting a `AttributeError` bypass the timeout guard and prolonging the wait. Finally, a non-canonical OpenRouter endpoint is displayed during preflight: a project `.env` is enough to set one, and the real key would then be sent.
  - **Security: a project `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file starting from the current directory and its parents: an untrusted directory tree—a repository just cloned—could place `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` there (the latter read by the SDK itself) without knowing any key, and the real key, coming from the environment or user configuration, was then sent in the authorization header to a third-party server. The filter operates on a PATTERN and not a list: surveyed across installed SDKs, twelve routing variables are read, six of them by the Anthropic client alone—a hand-written enumeration would have missed half of them. Therefore, any variable matching `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, proxies, and certificate stores (pointing to a controlled authority makes an interceptor indistinguishable from a genuine server), as well as `XDG_CONFIG_HOME` and `APPDATA`, are rejected from the project layer: setting them amounted to deciding which file constitutes the user layer, thus bypassing the filter through the back door. These variables are only accepted from the two layers that the user controls: the exported environment and `~/.config/aipmt/.env`. Furthermore, the project layer is read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` would copy the real key under a name that subprocess pattern filtering does not recognize—it would then enter `codex exec`'s environment, violating the stated invariant. Finally, rejection only prints the variable name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into the logs, even as it was being rejected. A rejection is reported on stderr along with next steps—an enterprise relay is configured in user configuration.
  - **Fix: the OpenRouter output envelope is calculated for each call.** `context_length` covers input AND completion, and a fixed reserve calibrated for Latin text provides no real upper bound: measured with the `o200k_base` tokenizer, 16,000 characters equal 3,200 tokens in French, but 12,300 in Japanese and 17,500 in emoji. The budget is therefore derived from the text actually sent, bounded above by its number of UTF-8 bytes: for any byte-pair merging tokenizer—byte-level BPE, SentencePiece with byte fallback, the families used by the catalog—a token is worth at least one byte, and this is the only upper bound available here, where OpenRouter routes to dozens of unknown tokenizers. No average ratio was suitable—a supplementary plane ideograph drops to 1.33 bytes per token, a combining character to 1.00—and input plus output now fit within the window by construction. A segment that is too dense for the chosen model is rejected before the call rather than after billing.

- **1.12.0** Provider `--use_opencode`: OpenCode, the open-source agent, to the provider of your choice—local model, free without an account, subscription, or key (2026-09-04):

If the inline configuration were not taken into account, translation would proceed with an agent capable of writing; the exit contract checks for the absence of this message, in addition to: return code 0, no `error` event, no `tool_use`, last `step_finish` as `stop` (a `length` is a truncated response), non-empty text. Second pitfall: the error JSON event is **opaque** — "Unexpected server error. Check server logs for details.", with a simple reference — and the real cause (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) lives only in the logs. - **1.9.2** Fix news attribution URL extraction with nested parentheses or FR prefix (2026-05-11):

  - **Fixed bug**: the extraction of attribution URLs in `_protect_news_quotes` used the regex `re.search(r"\((.+?)\)", attribution)` (lazy capture between parentheses). On an attribution such as `(relayé par [@user sur X](https://x.com/.../123))` (nested parentheses: enclosing `(` + `]()` of the markdown link), capture stopped at the first `)` encountered → truncated string + including the FR prefix: `relayé par [@user sur X](https://x.com/.../123` (without the trailing `)`). Consequence: `_validate_news_post` searched for this string in the translated output and systematically failed (two reasons: truncated `)` + "relayé par" translated into `relayed by`/`weitergeleitet von`/...). Complete cascade low → medium → high → gpt-5.5 could not succeed.
  - **Fix**: the regex becomes `re.search(r"\]\(([^)]+)\)", attribution)` — specifically targets the `](url)` of the markdown link, captures **only the pure URL** (without FR prefix or truncation), an invariant preserved by `#URL{N}#` placeholders during translation. Robust against both problematic patterns:
    - `(relayé par [@account sur X](url))` — nested parentheses
    - `via [@source](url)` or `selon [@author](url)` — FR prefix without enclosing parentheses
  - **Tests**: 2 new ones in `test_silent_failure.py` class `TestNewsCitationExtraction`:
