- **1.13.1** Dependency freshness: falling behind is no longer a warning that can go unread (2026-09-09):

  - **A warning that is not counted is a warning that gets missed.** `check-deps-fresh.sh` had been reporting for several days that `openai` and `anthropic` had fallen behind, but the gate summary line counted only failures: it announced “READY: N checks passed” even though a delay was reported a few lines above. Someone who reads the last line—and that is what everyone does—had no way of knowing. The verdict now includes the number of warnings, and a dedicated counter tallies them instead of printing them as they occur.
  - **The delay now comes with release notes.** A version number does not say what changed, and having to find the right file yourself is precisely the friction that causes the step to be skipped. The check displays the CHANGELOG address for each outdated package, for both major and minor versions, along with the reason: a minor SDK release has already changed things this project depends on.
  - **`openai` 3.8.0 → 3.10.0 and `anthropic` 1.3.0 → 1.4.0, release notes read before locking.** On the OpenAI side, there was only one behavioral change across the range—a numeric `Retry-After` header that overflows the float no longer falls back to a short backoff but returns the original error without retrying—and nothing affecting what this project depends on: model tolerance for additional fields is unchanged, as verified in the code at both tags, so the `native_finish_reason` and `error` that OpenRouter adds to a choice continue to pass. On the Anthropic side, a new guard explicitly rejects with `TypeError` an object from the `httpx` package where the SDK expects `httpx2`; this project passes only floats, as verified. The rule rejecting a non-streamed call lasting more than ten minutes is byte-for-byte identical between the two versions: it is indeed the explicit `timeout` that exempts it, since its 32,768 tokens exceed the 21,333 threshold.
  - **Verified**: suites totaling 502 + 31 tests on the bumped versions, `requirements.txt` closure matching the installed environment (41 pins), and one real call per SDK—OpenAI and Claude—on a document in `--news` mode, with a structure identical to the source.

- **1.13.0** `--use_openrouter` provider: a paid router to ~430 models, including open Chinese models (2026-09-05):

  - **The ninth provider path, shipped with the eighth.** 1.12.0 was not published on PyPI: both routers, OpenCode and OpenRouter, are being released together. [OpenRouter](https://openrouter.ai) provides access with a single key to models that no other provider exposes here—Kimi, Qwen, DeepSeek, Z.ai—using a single pay-as-you-go credit balance. Since the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything that distinguishes this provider is contained in a preflight**, and every one of its rules comes from an API measurement.

  - **The same model is served by dozens of hosts with different limits, and routing is blind to this.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash`—including one capped at **2,048 output tokens**. A long translation routed to one of the 23 could therefore be truncated at random, without any signal whatsoever. The preflight reads `/api/v1/models/{modèle}/endpoints`, excludes hosts with fewer than 8,000 output tokens, those with degraded status, and those that declare no limit, then pins the others. `provider.only` **without** `allow_fallbacks: false` is only a preference: the router falls back to an excluded host, rendering the pinning worthless. If no host meets the limit, the command stops: translating anyway would mean accepting the silent truncation this preflight exists to prevent.

  - **Reasoning is billed at the output rate and enabled by default on many models.** Same request on `z-ai/glm-5.2`, response “OK”: **107 completion tokens with the model default, 2 with reasoning disabled**. For a translation, where reasoning adds nothing, that is a factor of 18 for every segment of every file. It is therefore disabled by default. The **288 models out of 431** that require it (`reasoning.mandatory`) respond with `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for them, the preflight reads the accepted effort levels and requests the lowest one (next bullet)—the effort allocates a **percentage of `max_tokens`** that reasoning consumes first, so choosing an arbitrary value shifts the risk of a blank output instead of reducing it.

  - **A model that requires reasoning receives the lowest effort it accepts, and that decision was based on measurement.** The initial choice was to send nothing, to avoid guessing on the model's behalf. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced output **truncated at 32,768 tokens** before the translation was finished—two languages out of fourteen were lost. Increasing the allowance would not have changed anything: effort allocates a percentage of it, so reasoning grows along with it. The provider therefore reads `supported_efforts` during preflight and requests the lowest one, falling back to “nothing” when the catalog lists no usable value. Counter-test on the failing language: it previously failed because the budget was exhausted; it now completes in 9 minutes with a structure identical to the source.

  - **An upstream host outage now bears its name.** The router normalizes this case as `finish_reason=error` with a null `native_finish_reason`—measured twice, on two languages, at exactly 750 seconds. The generic message sent users looking for a defect in the document or segmentation; it now says that the outage is on the provider side and that retrying is often enough.

  - **`finish_reason=length` with empty output is not truncation.** It means the budget was consumed by reasoning before the first useful character—measured at 15,850 reasoning tokens for 148 useful ones. The two cases call for opposite actions: reducing segment size does nothing in the first case. The message explicitly distinguishes them. Two other guards come from measurements: the router responds with **200 and a body containing only an error** when the upstream host fails (`choices[0]` raised an opaque `TypeError` that hid the message), and the context window is read from the catalog and then written to `MODEL_TOKEN_LIMITS`—`DEFAULT_TOKEN_LIMIT` is wrong for 44 models in the catalog, including two capped at 4,095 tokens.

  - **`--model fournisseur/modèle` is mandatory, and its format is validated before any network access.** OpenRouter is not a provider: the choice determines price, licensing, and data processing, so it cannot be made on the user's behalf. Since the slug is interpolated into the preflight URL, validation is not merely an ergonomic courtesy but the guard that prevents path injection: the namespaced regex shared by both routers accepts `a/b/..`, hence the explicit rejection of the parent segment. `--eco` has no effect and says so.

  - **Three statements corrected, including one that was false.** OpenAI's warning about `codex exec` concerned injecting a personal session file on a shared runner, not whether the repository was public: it had been cited out of context in the README, in CLAUDE.md, and in the code. OpenCode's authentication location changed in 1.18.27 (the `credential` table in `opencode.db`, no longer `auth.json`); the invariant “never read here” remained true, but the address was outdated. Finally, the OpenCode section no longer presents untested paths as equivalent: the Zen gateway and Ollama were measured end to end, while GitHub Copilot, LM Studio, and llama.cpp were not, and the README now says so.

  - **A measurement campaign, and a table of recommended models in the README.** More than three hundred translations were run across three document sets—a dense blog post in `--news` mode, this README in standard Markdown, and four README files from well-known projects taken as-is from GitHub—into fourteen languages. The table distinguishes two things that had been conflated: translations that **complete** and those whose **structure is identical** to the source. Three models never lost any information on either dense document: `gemini-3.7-flash`, `gpt-5.6-sol` through the ChatGPT subscription, and `z-ai/glm-5.2` through OpenRouter—their only discrepancies are one pair of `**` markers not carried over in one or two languages. The central finding is that **the determining factor is document density, not `--news` mode**: subscription-based Grok fails thirteen times out of fourteen on the blog post and succeeds on fourteen public READMEs out of sixteen, with the cause identified through counter-testing as a failure on long segments. The table carries its own warning: it is not exhaustive, it is dated, durations are not a ranking, and the right approach remains to measure performance on your own documents.

  - **The structure comparator was corrected before its figures were published because it produced two false positives for non-Latin scripts.** A URL followed by a full-width closing parenthesis `）` was not cut off by a regex that stops at `)`, so the extracted string differed even though the URL was identical; a five-line quotation in French fitting into three lines in Chinese caused a line-based count to drop. Both fixes were validated through counter-testing: removing a URL, a section, or inline code is still detected. Without them, Gemini and Codex would have been reported as supporting eleven languages out of fourteen instead of thirteen and twelve.

  - **Tests**: new `tests/test_openrouter_provider.py` file (76 tests)—model validation and parent-segment rejection, host pinning (limit, status, undeclared limit, shared minimum), `allow_fallbacks` always false, reasoning disabled or retained according to `mandatory`, complete output contract (error inside a 200 response, no choice, blank output distinguished from truncation, abnormal `finish_reason`, null content), fail-closed preflight when the catalog is unreachable, missing slug, and no healthy host, flag exclusivity, and filename label. Full suite at **502 tests**.
  - **Refactor: the single 4,253-line module is split into modules, without changing a single line of behavior.** `src/aipmt/translate.py` is divided into `config`, `markdown`, `segmentation`, `guards`, `placeholders`, `news`, `prompts`, `notes`, `naming`, `pipeline`, `cli`, and a `providers/` subpackage (one module per provider, `base` as the foundation, `registry` for resolution and dispatch). Each move is a commit backed by mechanical proof: a checker compares the AST of every top-level node in the package against a reference snapshot, verifies the location of each symbol, the verbatim survival of security markers, and the absence of untracked files—temporary tooling, removed by the next release. The visible changes: `aipmt.translate` becomes a façade that re-exposes, by object identity, the 64 names that the module exposed without an `_` prefix (`__all__` contains nine of them, the supported API; the others are compatibility aliases), and stops re-exporting the 29 dependency and standard-library names collected by `import *`; direct execution of the file (`python src/aipmt/translate.py`) no longer exists—`aipmt` and `python -m aipmt` remain the two supported forms; the `__module__` of public functions is that of their defining module; SDKs are imported after `.env` is loaded rather than before, with no known consequences. All 427 tests are preserved down to their identifiers and migrated to the modules they exercise: 91 patches that went through the façade now target the module that looks up the name (two of them remained green without their patch, as measured), seven contract tests lock down the façade, and the gate tooling was rewritten BEFORE the first move so none could turn green by ceasing to check—directory-scoped Lizard with a floor, flags read from the constructed parser, per-package coverage floor, and `release.sh` enumerating tracked modules.
  - **Fix (pull request review)**: OpenRouter rejects a catalog entry without `context_length` instead of recording the 128,000-token default as a measurement—which also suppressed the “unlisted model” warning—and, when `finish_reason` is null (documented type `string | null`), the provider's raw reason is authoritative, with `max_tokens` equal to `length`; an error carried by the choice itself rejects the accompanying partial content, with the same message as the normalized upstream failure—provider detail, raw reason, and advice combined. OpenCode responds with its contract error, rather than an `AttributeError`, on an `part: null` event, and rejects a JSONL stream containing an unreadable event line instead of accepting partial text. The three agentic CLIs kill the agent's group when that process receives `SIGTERM` during the call—the regen's `timeout` let the agent survive and consume its quota—and the group's `SIGKILL` always observes the grace period, with a shim that exits cleanly leaving its grandchild alive. A `# fmt: off` / `# fmt: on` pair split by the refactor is reunited; the help for `--reasoning_effort` names the four providers that use it.
  - **Fix (second review)**: the output cap requested from OpenRouter now reserves the portion of the context used by the prompt and segment—`context_length` covers BOTH input and completion, and six catalog models had requests sent without room for the input; a context that is too short is rejected before any billing. The agentic CLI foundation falls back to `terminate` and then `kill` where POSIX process groups do not exist, instead of allowing an `AttributeError` to pass through the timeout guard and prolong the wait. OpenCode's `429` marker is searched for as a number rather than as a substring, where an error identifier such as `err_84290b` triggered 90 seconds of backoff before failing anyway. Finally, a noncanonical OpenRouter endpoint is displayed during preflight: a project `.env` is enough to set one, and the actual key would subsequently be sent to it.
  - **Security: a project `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file from the current directory and its parents: an untrusted tree—a repository that has just been cloned—could set `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` (the latter read by the SDK itself) without knowing any key, and the real key, obtained from the environment or user configuration, would then be sent in the authorization header to a third-party server. The filter is based on a PATTERN rather than a list: across the installed SDKs, twelve routing variables are read, six by the Anthropic client alone—a hand-written enumeration would have missed half of them. The project layer therefore rejects every variable ending in `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, as well as proxies and certificate stores (pointing to a controlled authority makes an interceptor indistinguishable from a real server), together with `XDG_CONFIG_HOME` and `APPDATA`: setting them amounted to deciding which file constitutes the user layer, thereby bypassing the filter indirectly. These variables are accepted only from the two layers controlled by the user: the exported environment and `~/.config/aipmt/.env`. The project layer is also read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` copied the real key under a name not recognized by the subprocess pattern filter—it then entered the environment of `codex exec`, contrary to the stated invariant. Finally, rejection displays only the variable's name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into logs even while it was being rejected. A rejection is reported on stderr with instructions—a corporate relay must be declared in the user configuration.
  - **Fix: the OpenRouter output envelope is calculated for every call.** `context_length` covers BOTH input and completion, and a fixed reserve calibrated on Latin text provides no bound: as measured with the `o200k_base` tokenizer, 16,000 characters equal 3,200 tokens in French, but 12,300 in Japanese and 17,500 in emoji. The budget is therefore derived from the text actually sent, bounded above by its UTF-8 byte count: with any byte-fusion tokenizer—byte-level BPE, SentencePiece with byte fallback, the families used by the catalog—a token represents at least one byte, and this is the only upper bound available here, where OpenRouter routes to dozens of unknown tokenizers. No average ratio was suitable—a supplementary-plane ideograph drops to 1.33 bytes per token, a combining character to 1.00—and input plus output now fit within the window by construction. A segment that is too dense for the selected model is rejected before the call rather than after billing.

- **1.12.0** Provider `--use_opencode`: OpenCode, the open-source agent, routed to the provider of its choice—local model, free without an account, subscription, or key (2026-09-04):

  - **An eighth provider path, different in nature from the first seven.** [OpenCode](https://opencode.ai) (MIT) is not a model provider but a _router_ to those configured by the user in OpenCode itself: an API key, a subscription (GitHub Copilot, ChatGPT, SuperGrok), the OpenCode Zen gateway—which serves free models **without an account**—or a **local** model (Ollama, LM Studio, llama.cpp). The script drives `opencode run` in non-interactive mode, as it does Codex and Grok, and reuses the same subprocess foundation (dedicated process group, `SIGTERM` followed by `SIGKILL` on timeout, stdin always closed, sanitized environment). Verified through **two real translations**: this entire README into English via `opencode/mimo-v2.5-free`—49 seconds, a single pass, structure identical to the source file (32 headings, 26 code-block closings, 18 links, 37 URLs, 37 table rows, 135 inline-code spans)—and a test file via `ollama/qwen2.5:7b`, locally, without any key.

  - **`--model provider/modèle` is mandatory, and deliberately so.** Without `--model`, OpenCode falls back to its own default, which on a fresh installation is `opencode/big-pickle`, a free “stealth” model whose interactions may be used for training—as measured, that is the model that responded. Silently choosing this on the user's behalf would be exactly the kind of invisible switch this repository tracks; the error message therefore names the command that lists models (`opencode models`) and gives three examples (local, free, subscription). `--eco` has no effect and says so. `--reasoning_effort` is passed through unchanged as OpenCode's `--variant`, only when explicitly requested.

  - **Measured confinement, not assumed.** An inline configuration (`OPENCODE_CONFIG_CONTENT`, last in OpenCode's merge order and therefore taking precedence over the user's without replacing it) defines an `aipmt` agent for which all tools are denied (`permission: {"*": "deny"}`): the registry no longer even offers them to the model, which, when ordered to “list the files and run `id`,” responds that it has no tools. Session sharing disabled, external plugins excluded (`--pure`), never `--auto`, disposable and empty working directory. Two silent injections were measured and disabled: without `OPENCODE_DISABLE_CLAUDE_CODE`, the user's `~/.claude/CLAUDE.md` enters **every** prompt (515 input tokens instead of 186 for a simple “Hello”); without `OPENCODE_DISABLE_PROJECT_CONFIG`, so does the current directory's `AGENTS.md`—an instruction to “end every response with BANANA” was applied to the translation. The global `~/.config/opencode/AGENTS.md`, however, remains injected: no switch excludes it, and bypassing it through a repurposed `XDG_CONFIG_HOME` would also hide the user's providers. Documented instead of worked around.

  - **`exit 0` proves nothing: third CLI, same instincts—with two traps of its own.** An unknown `--agent` does not cause `opencode run` to fail: it emits a warning on stderr and **silently** falls back to the coding agent, with tools active. If the inline configuration were not applied, the translation would therefore run with an agent capable of writing; the output contract checks for the absence of this message, in addition to: exit code 0, no `error` event, no `tool_use`, final `step_finish` in `stop` (an `length` is a truncated response), nonempty text. Second trap: the JSON error event is **opaque**—“Unexpected server error. Check server logs for details.”, with only a reference—and the actual cause (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) exists only in the logs. Hence `--print-logs --log-level ERROR` and reading the `error="…"` field from stderr, without the Bun trace that follows it. An unknown model thus fails in one second, naming its cause. Incidentally, `--title` prevents a stray LLM call: without it, OpenCode generates a session title through an additional turn on `small_model`.

  - **Secrets: the same pattern-based filtering as Codex and Grok, with one explicitly named exception.** `OPENCODE_API_KEY` is retained: it is OpenCode's own key (Zen gateway, Go subscription), addressed to it by name—the equivalent of its `auth.json`, not a key that aipmt would manage or be able to bill. Providers are configured in OpenCode (`opencode auth login`, `opencode.json`), never in aipmt's `.env`, none of whose keys reach the subprocess. No rejection in CI, unlike subscription CLIs: an API key or a self-hosted model on a runner are legitimate uses.

  - **The anti-traversal guard now checks the interpolated value, not the raw value.** `provider/modèle` contains an `/` that the 1.10.0 guard rejected—correctly, since `--model` is interpolated into the filename `--include_model`. The filename label now replaces `/`, `\`, and `:` with `-` before any interpolation (`ollama/qwen2.5:7b` → `ollama-qwen2.5-7b`, since `:` is illegal on Windows), and the upstream guard examines this label: `../../evil` becomes the simple name `doc-en-..-..-evil.md` beneath the target, only `..` remains rejected, as does `--target_lang ../x`. The `_ensure_within_directory` scope guard remains the unchanged second layer.

  - **Free models and local models: what was measured.** `opencode/mimo-v2.5-free` translates a paragraph in 16 seconds and this README in 49 seconds; `opencode/big-pickle` takes 40 seconds for 200 words, and two simultaneous requests remained unanswered for 5 minutes whereas each succeeds alone; `opencode/nemotron-3.5-lightning-free` returned nothing in 3 minutes. Hence `REGEN_PROVIDER=opencode` with mandatory `REGEN_MODEL` and **2 parallel jobs**. Locally, Ollama often configures 4,096 context tokens while segments contain up to 16,000 characters: an `Modelfile` with `PARAMETER num_ctx 32768` is necessary, and quality depends on the model—a 7B reversed a list and damaged a code-block closing in the test file, whereas the gateway model preserved everything.

  - **Translations in this repository never go through a billed API anymore.** `regen_translations.sh` used the OpenAI API whenever a key happened to be present in `.env`, making Codex merely opt-in. This is exactly what happened while preparing this release: all 28 translations went through the OpenAI API, then the Hindi CHANGELOG through Gemini's, even though the ChatGPT subscription exists precisely to avoid usage-based billing. Key auto-detection is removed: **Codex is the default, with `gpt-5.6-sol`**, the quality model; `openai`, `gemini`, and `grok` require `REGEN_ALLOW_PAID_API=1` in addition to `REGEN_PROVIDER`, an explicitly named exemption so the rule takes effect at decision time; an unknown `REGEN_PROVIDER` fails instead of falling back to the API. Ten tests lock down the default, rejection, and exemption. All 28 translations in this release were redone through Codex.

  - **Rate-limit backoff is factored out** (`_retry_on_rate_limit`): the Codex and Grok loops were identical apart from their labels, and a third copy would have crossed the duplication threshold. All three CLI errors derive from the same `_CliCallError`; a test prevents any of the three from leaving that hierarchy, because otherwise the shared loop would no longer catch it.

  - **Tests**: new `tests/test_opencode_provider.py` file (61 tests)—complete output contract, agent fallback, cause read from logs, deduplicated text parts and ignored synthetic parts, timeout killing the process group, backoff on 429, mandatory and validated model, secret-free preflight, binary resolution, dispatch wiring, filename label, and traversal counterexample. `tests/test_review_hardening.py` extends flag exclusivity and the absence of secrets to the new provider. The gate now requires **22 documented argparse flags**. Full suite at **382 tests**.

- **1.11.0** Release on PyPI: `pip install ai-powered-markdown-translator` followed by the command `aipmt`, without cloning the repository (2026-09-03):

  - **The single-file script becomes an installable package.** `translate.py` moves from the root to `src/aipmt/translate.py`, with a `aipmt` console entry point and the equivalent `python -m aipmt`. The cloned repository remains necessary for contributing—tests, 28 translations, and quality tooling live there—but no longer for using it.

    - **The import name is `aipmt` and never `translate`**, because the collision is real and silent. The PyPI package `translate` (v3.8.1, last uploaded 2026-07-06) installs a DIRECTORY with the same name. Reproduced in a venv: the directory takes precedence over the module, `translate.main` disappears, the entry point fails on `AttributeError`—and `pip check` responds “No broken requirements found” with rc=0. A simple `pip install translate` on the user's system would have been enough to break the CLI without any actionable diagnostic. Countercheck on the actual wheel: `pip install translate` on top of the package, `aipmt --help` rc=0 before and after, and both CLIs coexist.
    - **Long distribution name, short command.** `ai-powered-markdown-translator` makes the package discoverable through a PyPI search; an acronym alone would be impossible to find for anyone who does not already know the project, whereas the release is specifically intended to make it discoverable. Two plausible candidates were rejected after verification: `ai-markdown-translator` has been TAKEN on npm since 2024 by a tool serving the same purpose, predating this repository by 17 months; and `aimt` is one letter away from `aim` (v3.29.1), an active package in the SAME domain—the worst setup for lasting confusion. A methodological trap worth noting: `pypi.org/project/<nom>/` returns 200 for any name (anti-bot page); only the JSON API is authoritative.
    - **`src/` layout rather than a flat package.** A flat package would have preserved the tests' six `sys.path.insert(..., "..")`, and that is precisely the flaw: they make the source tree be imported instead of the package, which would conceal any packaging error. Actual cost: one additional substitution rule.

  - **Keys can finally be configured once and for all.** An installed CLI had no PERSISTENT configuration: only the environment variable and the current directory's `.env` remained. `find_dotenv` does admittedly search upward to the filesystem root and therefore found a `~/.env` **when working under the home directory**, but found nothing when working elsewhere—coverage that depended on where the command was launched, not on a design choice. A third layer is therefore added: `~/.config/aipmt/.env`, beneath the existing two.

    - **Priority is not hard-coded**; it follows from `override=False`, the default value of `load_dotenv`: each layer fills only what the previous one left empty. Hence the order environment variable → project `.env` → user configuration, verified through BEHAVIOR tests rather than structural tests—reversing the order of the two calls makes them fail, as does removing the third layer.
    - **`.env` format rather than TOML**, deliberately: `python-dotenv` is already a dependency, the syntax is already documented in all 15 READMEs, and the same file serves both scopes. No new dependency or syntax. The location follows `XDG_CONFIG_HOME` if it is **absolute**—the specification requires a relative value to be ignored, otherwise the configuration location would once again depend on the current directory—and `APPDATA` on Windows.
    - **Two options rejected, with reasons.** The system keyring (`keyring`) is safer on a desktop but fails in headless environments—servers, containers, CI—which is precisely the batch-translation use case; a good opt-in candidate, a poor default. A `--api-key` flag would put the key in the shell history and expose it in `ps`.
    - **Without a key, no more stack trace.** The user received a Python stack trace pointing to `site-packages`, and a message that named “the environment or .env” without saying where to create the latter. It now lists all three locations with their exact paths, and the command exits with 2. The safety net is **deliberately narrow**: `except ValueError` around the configuration phase alone. Wrapping the entire execution would turn a real bug occurring during translation into a reassuring message—the failure mode this repository tracks. A test reads the source of `main()` to prohibit it.

  - **Fix—the user's `.env` was ignored once the tool was installed.** `load_dotenv()` without an argument does not search upward from the current directory but from the CALLING file, therefore from `site-packages`. Measured with a real console entry point launched from a project containing its own `.env`: `find_dotenv()` returns `''` and the key is not loaded, whereas `find_dotenv(usecwd=True)` finds it. The bug did not exist while the tool ran only from the cloned repository; the release would have made it systematic, with an API key reported as “missing” despite correct configuration as the only symptom.

  - **Three gates would have turned green after ceasing to check anything.** They were hardened BEFORE the move, deliberately: a safeguard written after the change it is supposed to catch proves nothing. Each is green on the original repository and turns red on a migrated copy—both directions are measured.

    - **Lizard silently ignores a missing path**: rc=0, “0 file analyzed.” The complexity gate would have dropped from 158 functions / 2247 nloc to 3 functions / 34 nloc, with zero bytes of output. The scope is now an array whose entries are each checked for existence.
    - **`coverage run --source=` on a missing module does not fail**: warning on stderr only, rc=0 for both unittest and `coverage xml`, and a report is still published—cut from 1453 to 141 statements. The project would have appeared healthy because almost none of it was still being analyzed. Two floors safeguard the report: the total and the largest measured file.

- **1.9.2** Fix news attribution URL extraction with nested parentheses or an FR prefix (2026-05-11):

  - **Fixed bug**: attribution URL extraction in `_protect_news_quotes` used the regex `re.search(r"\((.+?)\)", attribution)` (lazy capture between parentheses). For an attribution such as `(relayé par [@user sur X](https://x.com/.../123))` (nested parentheses: enclosing `(` + `]()` from the Markdown link), the capture stopped at the first encountered `)` → truncated string that also included the FR prefix: `relayé par [@user sur X](https://x.com/.../123` (without the final `)`). As a result, `_validate_news_post` searched for this string in the translated output and systematically failed (for two reasons: truncated `)` + “relayé par” translated as `relayed by`/`weitergeleitet von`/...). The entire low → medium → high → gpt-5.5 cascade could not succeed.
  - **Fix**: the regex is now `re.search(r"\]\(([^)]+)\)", attribution)` — it specifically targets the `](url)` of the Markdown link and captures **only the raw URL** (without the FR prefix or truncation), an invariant preserved by `#URL{N}#` placeholders during translation. Robust against both problematic patterns:
    - `(relayé par [@account sur X](url))` — nested parentheses
    - `via [@source](url)` or `selon [@author](url)` — FR prefix without enclosing parentheses
