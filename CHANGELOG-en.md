- **1.10.0** `--use_codex` provider (ChatGPT subscription quota), SDK and model updates, multi-paragraph news citation fix (2026-08-29):

  - **Security review — two safeguards that the PR established without enforcing them everywhere**:

    - **The Codex preflight passed the entire `.env` to the binary.** `_codex_preflight` called `subprocess.run` **without `env=`**: the subprocess inherited the entire `os.environ`, including all of the `.env` loaded by `load_dotenv`. Measured with an instrumented fake binary: **seven secrets** reached the preflight—the keys for all six providers plus one `GITHUB_TOKEN`—versus **zero** for its `_grok_preflight` counterpart, which correctly passed `env=_grok_env()`. The inconsistency was internal to the PR: `_strip_secret_env` exists precisely to uphold this invariant, just a few lines away. A `_codex_env_base()` is extracted and shared by both paths; measurement after the fix: 0 secrets on both sides.
    - **The “`--deny` fail-closed” property did not cover the form being used.** The comment justified all Grok confinement on the grounds that a rule with an unknown prefix causes startup to fail. Measured on `grok 1.0.13`, this validation exists **only for the parenthesized form**: `--deny 'CeciNestPasUnOutil(*)'` refuses to start (“unknown tool prefix”), while `--deny 'CeciNestPasUnOutil'` is silently accepted. Yet `GROK_DENY_RULES` used only bare names—so an xAI-side tool rename would have removed the only measured confinement layer without any signal, on a machine where the OS sandbox already does not apply. The eight named rules now use `Prefix(*)`, each verified as a CLI-known prefix; the catch-all `*` remains in its literal form, the only accepted one. A test prevents reverting to the unvalidated form.
    - **Otherwise verified clean**: no command injection (list form everywhere, never `shell=True`, document content through stdin or `--prompt-file`), no unsafe deserialization (`json.loads` only, with a type guard), no bypass found for the path traversal fix across seven payloads, and `--deny '*'` actually enforced by the CLI (`DENY_ENFORCED` observed on a read outside the workdir).
    - The freshness check added above also bypassed its own principle: a package whose PyPI request failed was silently skipped, leaving the gate green. It now counts the packages actually compared and fails if coverage is incomplete.

  - **Dependencies brought up to date, with two safety nets to prevent this lag from recurring**:

    - **The lag was real and long-standing**: `openai` 2.54 → **3.6.0**, `anthropic` 0.125 → **1.2.0**, `certifi` 2024.8.30 → **2026.7.22**—two years behind on the root certificate store that validates TLS for all provider calls. Root cause identified: **there was no `.github/dependabot.yml`**. Without this file, GitHub enables only _security updates_, and Dependabot opens a PR only for a dependency affected by a CVE—which explains why it bumped `urllib3` and `idna` while allowing two SDKs to drift by a major version.
    - **The two major versions coexist without conflict**, contrary to what earlier reasoning had suggested: `openai` 3.x and `anthropic` 1.x migrate to **`httpx2`**, while `mistralai` and `google-genai` remain on `httpx<1`, but these are two distinct distributions. Verified through an actual installation, then through **all 7 provider paths tested end to end**—OpenAI, Claude, Mistral, Gemini, Grok API, Codex CLI, and Grok CLI—with inline code and links preserved in every output. “Avoiding two HTTP stacks” was a preference, not a blocker: measurement settled the issue.
    - **`requirements.txt` did not describe the actual environment**: `google-auth`, `cryptography`, and the `opentelemetry` stack were installed in the working venv without ever being declared—a fresh installation therefore did not reproduce what was being tested. Conversely, `tokenizers`, `huggingface-hub`, and `PyYAML` were listed there despite not being imported or required by anything, remnants of `mistralai` 1.x. The file is regenerated as the complete closure of a venv built solely from direct dependencies. `pip-audit` reports no known vulnerabilities in the new set.
    - **`.github/dependabot.yml`** (new) enables weekly version updates for pip and github-actions. Minor and patch updates are grouped into one PR—a patch bump per PR eventually gets ignored, and noise is the enemy of maintenance; **major updates are separate**, each requiring validation through a real call.
    - **`scripts/check-deps-fresh.sh`** (new, wired into the gate) makes lag visible in the project verdict: Dependabot proposes, it does not guarantee, and its PRs can pile up. Major-version lag → failure; minor-version lag → warning, because a permanently red gate eventually gets ignored; PyPI unreachable → explicit skip locally and **fail-closed in CI**, since a check that did not run is not a success. Verified in both directions: it catches the exact pre-fix state (`openai 2.54.0→3.6.0`, `certifi 2024.8.30→2026.7.22`) and issues only a warning for a minor version.

  - **Fixes resulting from this PR's review**—five review agents scrutinized the diff; every issue below was **reproduced through measurement** before being fixed, and two were regressions introduced earlier in this same version.

    - **Regression fixed—`_NEWS_CITATION_REGEX` had exponential backtracking.** The multi-paragraph fix had introduced `(?:[ \t]*$|[ \t]+.*)` inside the repetition: the allocation of spaces between `[ \t]+` and `.*` is ambiguous, and that ambiguity multiplies from one iteration to the next. Measured on `>   texte` lines—perfectly valid Markdown indentation—that do not match the pattern: **2,589 ms for 14 lines** versus 0.04 ms after the fix, with a factor of ~9 per additional line. In `--news` mode, a long nonconforming blockquote was enough to freeze translation until the job timed out, with no identifiable cause. The repetition now consumes the entire line as a single unit (`\n^>(?![ \t]*—).*`), leaving only one way to match each iteration. Verified against the real corpus of 231 articles: **zero difference** in captures, the same 423 citations, with all 14 multi-paragraph bodies still extended.
    - **Two simultaneous provider flags silently incurred usage-based charges.** `--use_codex --use_mistral` was accepted; `_select_provider_client` checks Mistral first, and `_resolve_provider` gives priority to explicit booleans—both converged on Mistral. The user was therefore requesting their subscription quota and receiving usage-based billing without any warning: exactly the failure mode `--use_codex` exists to prevent. The six provider flags now go through a `add_mutually_exclusive_group`. **Behavior change**: a command line combining two providers, previously silently accepted, now fails on `argument --use_mistral: not allowed with argument --use_codex`.
    - **The end-of-work gate turned green when its probes crashed.** Four of the thirteen `scripts/check-release-ready.sh` checks followed the pattern “capture stdout, conclude if empty” without ever checking the return code: an exception (renamed file, `FileNotFoundError`) wrote to stderr, left stdout empty, and the check concluded “nothing to report.” The “a `exit 0` proves nothing” trap reproduced inside the very script written to prevent it. A `probe()` helper now requires both a zero return code **and** an end sentinel, and the probes refuse to draw conclusions from an empty set of markers—an assertion over an empty set is always true. Demonstration: adding the exclusive group above routed the provider flags through a `*_group` object, which the old `parser\.add_argument\(` regex no longer matched; **six flags out of twenty-one** silently fell outside the scope, with the gate remaining green.
    - **The secret scan missed four of the six providers.** The `[A-Za-z0-9]` class excludes hyphens: `sk-proj-…` (the current OpenAI format) and `sk-ant-api03-…` broke at their second hyphen, and `AIza…` was not covered. The pattern has been expanded, with `.secrets.baseline` excluded from the scan. Furthermore, the `.env` guard queried `git diff --cached`, which sees only the index: an `.env` that was **already committed**—the worst case—never appeared there. It now queries `git ls-files`.
    - **The Codex “token warm-up” was not a warm-up.** Measured: `codex login status` does not touch `~/.codex/auth.json` (mtime and size unchanged), and its help text says “Show login status.” Yet the comment claimed it refreshed the token “once, sequentially,” thereby eliminating the risk of concurrent refreshes on a single-use rotating token. The stated protection did not exist; the comment now says what the code actually does, while the real mitigation remains `max_jobs=4`. The check also now honors `CODEX_BIN`, which it previously ignored—a machine without `codex` in `PATH` failed with “not authenticated,” a misleading diagnosis.
    - **`.env` was sourced in a subshell.** `detect_provider` is called through command substitution, so its exports did not propagate back: a `GROK_BIN`, `GROK_HOME`, or `REGEN_MODEL` defined in `.env` remained invisible to reads performed in `main()`, which concluded “Grok binary not found” despite a correct configuration.
    - **Concurrency exceeded the stated limit by 50%.** The guard was placed after launching the README/CHANGELOG pair: a measured peak of **3 for `max_jobs=2`**. For Grok, whose weekly quota is shared with Chat/Imagine/Voice and cannot be measured, the script therefore failed to honor its self-imposed limit. The final count, meanwhile, was displayed without ever being compared against 28—a missing file went unnoticed.
    - **Grok output contract: a missing `stopReason` is now a failure.** The code applied “`end_turn` **or absent**” where the stated contract requires `end_turn`. A payload without the field—or whose field had been renamed by a CLI update—turned the guard into a silent no-op. Furthermore, `max_turn_requests` is no longer classified as a rate limit (the turn budget has been exhausted: retrying reproduces the result at the cost of a 90-second wait), and `quota` has been removed from the rate-limit markers—for the very reason already stated by the `_codex_is_rate_limited` docstring, even though Grok did not apply it.
    - **The Gemini cascade is memoized by model.** It restarted from `minimal` for every segment even though the default model rejects it: the nominal path incurred a 400 round trip per segment and reprinted the same warning. A warning repeated hundreds of times stops being read—that is how it becomes a mask.
    - **Miscellaneous**: the CI rejection message was hard-coded for Codex and directed a `--use_grok_cli` user to `OPENAI_API_KEY` instead of `XAI_API_KEY`; `provider.capitalize()` displayed “Grok_cli” and “Openai”; the subprocess foundation comment generalized the “shim” to both CLIs even though the Grok binary is a native ELF (the correct rationale is “an agent that spawns its own subprocesses”); twelve SAST findings on `subprocess` are marked `# nosec` / `# nosemgrep` with justification, since the list form without `shell=True` makes injection impossible and document content never passes through argv.
    - **No secrets enter agentic subprocesses anymore.** Named deny lists protected only the **billing** invariant (Codex without `OPENAI_API_KEY`, Grok without `XAI_API_KEY`). Measured: **seven other secrets** still entered each subprocess—the Anthropic, Mistral, Google, and Gemini keys, the other CLI's key, and `OPENAI_BASE_URL`, which is not a secret but redirects traffic. Yet these two CLIs are **agents**, and the Grok one runs without an applicable OS sandbox on many Linux machines. Filtering is now performed **by name pattern** (`API_KEY`, `_TOKEN`, `SECRET`, `PASSWORD`, `CREDENTIALS`) rather than by named list, which also covers variables users add to their `.env` without this code knowing about them. None are required by the CLIs: authentication resides in `~/.codex` and `~/.grok`, never in the environment—verified by a **successfully completed real translation** through each of the two providers with the hardened environment.
    - **Tests**: new `tests/test_review_hardening.py` file (21 tests) locking down provider flag exclusivity, the `stopReason` contract, news regex linearity, the CI rejection message, Gemini memoization, and the absence of all secrets from the subprocess environment. The latter assertion is **generic**—it fails on a key that no list names—whereas the existing scrubbing test mirrored its constant and could detect nothing beyond a failure in its own loop. Full suite at **311 tests**.
  - **Two new Grok providers**: `--use_grok` (xAI API, `XAI_API_KEY` key, pay-as-you-go) and `--use_grok_cli` (official Grok Build CLI, deducted from the Grok subscription—same principle as `--use_codex`).
    - **API mode, ~40 lines**: since the xAI endpoint is OpenAI-compatible, the client and `_call_openai` are reused as-is; only `base_url` changes. Only one adaptation was necessary, and it benefits everyone: `finish_reason` now accepts `end_turn`, the form emitted by xAI where OpenAI emits `stop`. Models: `grok-4.6` (quality) and `grok-4.3` (economy). Note that Grok’s economy model remains the most expensive in the repository—$1.25/$2.50 per million versus $0.15/$0.60 for `mistral-small-latest`: this provider is chosen for model diversity, not price.
    - **CLI mode**: modeled after Codex, with four differences dictated by real-world constraints—the prompt is sent through a file (`--prompt-file`, the CLI does not read stdin and a segment in argv would be visible in `ps`), the output is a single JSON object on stdout (neither JSONL nor a `-o` file), the subscription only exposes `grok-4.6` and `grok-4.5`, and the sandbox cannot be applied (see below). Subprocess launching is shared with Codex in `_codex_run_process`, without touching the rest of the already-tested Codex provider.
    - **`exit 0` proves nothing, as measured**: when unauthenticated, the CLI writes `{"type":"error","message":"Not signed in."}` to **stdout** with exit code **0**. A refusal or turn-limit overrun behaves the same way. The output contract therefore requires four simultaneous conditions: exit code 0, no error payload, `stopReason == end_turn`, and non-empty text. The preflight follows the same logic: `grok models` exits with 0 even when logged out; only the presence of “not authenticated” in stdout allows that conclusion.
    - **Confinement: a deliberate and documented asymmetry.** Whereas Codex runs in `--sandbox read-only`, Grok’s sandbox is unusable on many recent Linux systems for two independent system-level reasons that cannot be worked around without `sudo`: AppArmor has blocked unprivileged user namespaces since Ubuntu 24.04 (`bwrap: setting up uid map: Permission denied`, reproduced outside Grok), and the container runtime socket deny-list fails when `/run/podman` is in `0700` (the resolver only catches `ErrorKind::NotFound`; EACCES becomes fatal). The central pitfall: a **built-in** profile that cannot be applied **silently starts without confinement**. The script therefore requests no profile by default and never falls back silently—it warns on stderr. Protection relies on the CLI’s `--deny` rules, including the catch-all `*`, the only measured _fail-closed_ layer (a rule with an unknown prefix causes startup to be refused). `GROK_TRANSLATE_SANDBOX=read-only` can be used to require it, in which case startup fails if the machine cannot honor it.
    - **Safeguards**: `XAI_API_KEY`, `GROK_API_KEY`, and `GROK_SANDBOX` are removed from the subprocess environment (a key would switch to pay-as-you-go billing; an inherited `GROK_SANDBOX` would impose an unusable profile with a misleading message), MCP/hooks/skills/agents switches are disabled, `--disable-web-search`, `--no-subagents`, `--no-plan`, disposable workdir, refusal in CI, timeout that kills the process group, and backoff on rate limits. `--max-turns` is set to 6 rather than 1: the counter is incremented after the tool turn, and 1 would truncate the output.
    - **Quota**: the Grok pool is weekly and **shared with Chat, Imagine, and Voice**, and no command exposes it—unlike Codex, whose `account/rateLimits/read` makes it possible to quantify usage. `regen_translations.sh` therefore limits concurrency to 2 and explicitly warns about it.
    - **Tests**: new `tests/test_grok_provider.py` file (24 tests). Full suite at **290 tests**.
  - **Bug fixed—multi-paragraph EN quotations were only partially protected (`--news` mode)**: `_NEWS_CITATION_REGEX` accepted as quotation content only a sequence of **consecutive** `>` lines. As soon as a quotation spanned multiple paragraphs (separated by an empty `>` line), only the last one was captured and replaced by the placeholder; the preceding ones were sent to the LLM and returned translated—the exact opposite of what `--news` exists to guarantee. The repetition now accepts internal empty `>` lines and is non-greedy, so it stops at the empty `>` preceding the italicized line rather than at the first one encountered.
    - **Measured scope** on a real corpus of 198 articles: 11 affected quotations out of 419. No regression—the new regex captures exactly the same number of quotations; only multi-paragraph bodies are extended (408 identical bodies, 11 extended), and the `> — …` attribution line still cannot be absorbed into the body (lookahead preserved).
    - **End-to-end proof** on a 69 KB article translated into ja/ar: the first paragraph of a quotation, previously rendered as `> GLM-5.3がオープンウェイト化。` in Japanese and likewise translated into Arabic, now remains `> GLM-5.3 is now open-weight.`. The number of English quotation lines returns from 9 to 10, matching the source.
    - Note: this defect was not detected by downstream validators, which check for the quotation’s presence without verifying that it is complete.
  - **Measured savings with the default provider**: `_openai_extra_kwargs` sent `reasoning_effort="medium"` whenever the model started with `gpt-5`, including in `--eco`. Measurement using `gpt-5.4-mini` to translate a ten-word sentence: `medium` → 45 reasoning tokens and 65 output tokens; `none` → 0 and 14. Reasoning adds nothing to a translation, and it was being paid for on every segment of every file. The default is now `none` in `--eco` and remains `medium` otherwise; an explicit value passed through the CLI still takes precedence. `--reasoning_effort` now accepts `none` and `xhigh` in addition to `low`/`medium`/`high` (not all are accepted by every model: `minimal`, for example, is rejected by `gpt-5.4-mini`—the existing retry without the parameter covers this case).
  - **SDK updates and Gemini migration**: `google-generativeai` (support ended on 2025-11-30, repository archived) is replaced by the unified **`google-genai`** SDK—`genai.Client(api_key=...)` followed by `client.models.generate_content(model=, contents=, config=)`, with the system prompt passed through `system_instruction` instead of being concatenated with the segment. `mistralai` moves to **2.9.4** (the import becomes `from mistralai.client import Mistral`; the old one raises an `ImportError`, verified in the wheel), `anthropic` to **0.125.0**, and `openai` to **2.54.0**—the latest versions before the switch to `httpx2`, to avoid having two HTTP stacks coexist in the venv. `httpx` 0.28.1 and `pydantic` 2.13.5 were unblocked accordingly.
  - **Two regressions caught by real tests, not by the documentation**:
    - `anthropic` ≥ 1.0 rejects client-side a non-streamed call whose `max_tokens` suggests more than 10 minutes (`ValueError: Streaming is required...`). This safeguard did not exist in 0.34.2 and broke every Claude call with `max_tokens=32768`. Fixed with an explicit `timeout` (`CLAUDE_TIMEOUT`, 900 s by default), avoiding a switch to streaming for a call where only the complete response is used.
    - `thinking_level="minimal"` is accepted by only part of the Gemini catalog: `gemini-3.1-flash-lite` supports it, while `gemini-3.7-flash` and `gemini-3.1-pro-preview` reject it with a 400. Hence `_gemini_generate_with_fallback`, a `minimal` → `low` → no thinking_config fallback chain, modeled after the existing OpenAI fallback—an optimization parameter must never cause a translation to fail.
  - **Updated default models**, each validated with a real call: OpenAI `gpt-5.5` → **`gpt-5.6-terra`** (−60% on a batch of 28) and `gpt-5.4-mini` → **`gpt-5.6-luna`** (−73%); Claude `claude-sonnet-4-6` → **`claude-sonnet-5`** (cheaper and newer) and `claude-haiku-4-5-20251001` → **`claude-haiku-4-5`** (canonical ID without a date); Gemini `gemini-3.1-pro-preview` → **`gemini-3.7-flash`** and `gemini-3.1-flash-lite-preview` → **`gemini-3.1-flash-lite`** (stable version, and cheaper than `3.5-flash-lite`). Mistral is unchanged, with `mistral-large-latest` remaining the best value for money of the four. Note: there is no Gemini Pro-tier model newer than `gemini-3.1-pro-preview`—Gemini 3.5 Pro, announced in May 2026, was never released; the 3.5/3.6/3.7 line is exclusively Flash.
  - **A/B measurement before switching Gemini**: `README.md` translated into Japanese using `gemini-3.1-pro-preview` and then `gemini-3.7-flash`. Strictly identical structure (21 lists, 18 code blocks, 13 HTML links, 13 images, all URLs preserved), in **8 s versus 48 s**. Since no public benchmark compares these two models for translation or non-Latin scripts, the switch would otherwise have rested on a mere assumption.
  - **Claude response block filtering**: `_call_claude` performed `block.text for block in response.content` without filtering by type. Models with adaptive reasoning (Sonnet 5 and later) interleave a `thinking` block, which exposes `.thinking` rather than `.text`—the translation would have failed with an opaque `AttributeError` on the first segment. `thinking`, `redacted_thinking`, `tool_use`, and `tool_result` blocks are now discarded (a deny-list, to remain tolerant of an unknown type carrying text), and a response with no text block raises an explicit error. `thinking={"type": "disabled"}` is passed with every call.

Limit corrections: Mistral 128K → **256K** (Large 3 / Small 4 generation), Gemini 1,000,000 → **1,048,576** (actual input limit), `claude-opus-4-5` 200K → **1M**, `gpt-5.6-*` family 400K → **1.05M**. Added Claude 5 (`claude-sonnet-5`, `claude-opus-5`, `claude-fable-5`), `claude-opus-4-8`, Gemini 3.5/3.6/3.7, `mistral-medium-latest`, and the `ministral-*` family. Note: these limits remain indicative, since `translate()` caps segmentation at `min(16000, limite)`.
  - **Provider `--use_codex`**: fifth provider that drives the official Codex CLI (`codex exec`) in non-interactive mode instead of calling a usage-billed API. Translation is deducted from the already-paid ChatGPT subscription quota. This is the only path documented by OpenAI for this use case: the plan availability matrix lists “Codex SDK, `codex exec`, and scriptable workflows” as available on Plus/Pro/Business/Enterprise, while `~/.codex/auth.json` tokens do not authenticate Platform API calls (and are never read by this script—the CLI continues to manage authentication and token refresh).
  - **Codex binary installable via pip, no longer only via npm**: `_resolve_codex_binary()` looks for the binary in `CODEX_BIN`, then the `PATH`, then the official Python package **`openai-codex-cli-bin`** published by OpenAI (the dependency of the `openai-codex` SDK). A Python project therefore no longer needs a global npm installation to use `--use_codex`. The package is not added to `requirements.txt`: the binary weighs ~250 MB, which would impose it on every user for an optional provider. Verified end to end: with `codex` absent from the `PATH`, resolution finds the packaged binary and completes a full translation in 6 seconds.
  - **“Subscription mode” guarantee**: `OPENAI_API_KEY` and `CODEX_API_KEY` are removed from the subprocess environment. Without this safeguard, a key present in `.env` could switch Codex to usage-based billing without any visible indication—exactly what this provider exists to prevent.
  - **CLI pitfalls locked down by tests**:
    - `codex exec` reads stdin **even** when the prompt is passed as an argument: without closing stdin, the command waits until timeout without ever calling the model (reproduced: exit 124 after 180 seconds, zero bytes). `communicate(input=...)` is therefore mandatory.
    - The `codex` installed by npm is a Node shim that `spawn` the actual Rust binary: this binary is a **grandchild** of the Python process and survives the `SIGKILL` of `subprocess.run(timeout=)`, where it would continue consuming quota. Hence `Popen(start_new_session=True)` + `os.killpg`.
    - The CLI can exit with code 0 while having emitted a `turn.failed`: the JSONL output (`--json`) is inspected in addition to the return code, and the absence of the `-o` file with a 0 exit code raises an explicit error instead of producing an empty segment.
  - **Rate-limit backoff**: the CLI implements no internal retry (`max_retries = 0`). Classification is based on the JSON payload structure (`status: 429` / `error.type`), not substrings—the word “quota” appears both in a recoverable 429 and in a permanent `insufficient_quota`.
  - **CI safeguard**: `--use_codex` is rejected if `CI` or `GITHUB_ACTIONS` is set. Subscription authentication is not intended for a shared runner, and OpenAI explicitly advises against this workflow on public repositories.
  - **Models**: `gpt-5.6-sol` (quality) and `gpt-5.6-luna` (`--eco`). The `gpt-5.6-*` family is shared by the CLI and Platform API, but a ChatGPT account is not entitled to all of it: the allowlist is enforced server-side, without local validation, and an unusual model triggers a warning. On a Plus plan, Luna offers 250–2,000 messages per 5-hour window versus 10–100 for Sol: `--eco` is the recommended mode for any batch processing.

Under `set -u`, this raised `failed_log: unbound variable` and caused the script to exit with code 1 even though all 28 translations were correct—which would have interrupted `release.sh --auto` (`set -e`) immediately after regeneration, at the most expensive stage. The variable is now global, and the trap checks whether it exists. A useful side effect: genuine translation failures, previously masked by this error, are visible again in the final summary.
  - **`REGEN_MODEL`**: new `regen_translations.sh` environment variable that forces a specific model over the provider default, for example `REGEN_PROVIDER=codex REGEN_MODEL=gpt-5.6-sol` to regenerate using the subscription quota’s premium model instead of the volume-oriented `--eco` model.

The token is refreshed once sequentially before enabling parallelism—because Codex refresh tokens rotate and are single-use, concurrent jobs would invalidate the `codex login` session—and concurrency is reduced to 4.

Explicit booleans retain priority over `args` to preserve tests that call `translate(..., use_mistral=True)` with a minimal `Namespace`.

Full suite at 290 tests.

- **1.9.2** Fix news attribution URL extraction with nested parentheses or an FR prefix (2026-05-11):

  - **Fixed bug**: attribution URL extraction in `_protect_news_quotes` used the regex `re.search(r"\((.+?)\)", attribution)` (lazy capture between parentheses). On an attribution such as `(relayé par [@user sur X](https://x.com/.../123))` (nested parentheses: enclosing `(` + `]()` from the Markdown link), the capture stopped at the first encountered `)` → truncated string that also included the FR prefix: `relayé par [@user sur X](https://x.com/.../123` (without the final `)`). As a result, `_validate_news_post` searched for this string in the translated output and systematically failed (for two reasons: truncated `)` + “relayé par” translated as `relayed by`/`weitergeleitet von`/...). The entire low → medium → high → gpt-5.5 cascade could not pass.
  - **Fix**: the regex becomes `re.search(r"\]\(([^)]+)\)", attribution)`—specifically targets the `](url)` of the Markdown link and captures **only the raw URL** (without the FR prefix or truncation), an invariant preserved by the `#URL{N}#` placeholders during translation. Robust against both problematic patterns:
    - `(relayé par [@account sur X](url))`—nested parentheses
    - `via [@source](url)` or `selon [@author](url)`—FR prefix without enclosing parentheses
  - **Tests**: 2 new tests in the `test_silent_failure.py` class `TestNewsCitationExtraction`:
    - `test_extract_attribution_url_with_nested_parens` (exact reproduction of the Genspark CEO E2B bug)

  - **Coverage gap**: `check-editorial-coverage.py` validates editorial syntax but not translatability by the translator. A possible improvement (outside the scope of v1.9.2) would be a check that simulates attribution extraction in a dry run to detect risky patterns BEFORE publication.
