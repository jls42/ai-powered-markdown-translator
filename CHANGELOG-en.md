- **1.16.0** Provider `--use_claude_code`: translate using the Claude Pro or Max subscription quota, via the official `claude -p` CLI — no paid path, and every call proves it (2026-09-26):

  - **Eleventh path: the Claude subscription, with no usage-based billing.** `--use_claude_code` drives the official Claude Code binary in `-p` mode, on the same foundation as Codex, Grok CLI, and Antigravity — its own process group, safe shutdown on timeout, Ctrl-C, or terminal closure. Not to be confused with `--use_claude`, Anthropic's pay-as-you-go API. aipmt never reads the token.

  - **No paid path, verified at three levels.** The subprocess environment is an allowlist: no API key, no token, no cloud provider, no markers from the Claude Code session from which aipmt might be launched — the one that wrote this provider exported fifteen. The preflight, without model turns, requires the subscription login without a Console key from `claude auth status`, and the phrase certifying the subscription from `/usage`. Each call must then attest to this in its initialization event — `apiKeySource: none`, forced environment properly received, model from the requested family, no fast mode — and in its quota report: paid "extra usage" halts translation immediately.

  - **Quota is shared with Claude Code sessions, and the provider conserves it.** Each call reports usage for the 5-hour and weekly windows; beyond 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), no further segments are started. On the day of writing, the author's account week was already at 98%.

  - **Nothing from the user's configuration enters, nothing from the session remains.** Tool-free, in zero-customization mode, user settings ignored, MCP servers and hooks disabled, private and disposable working directory, no transcripts kept. Measured by canaries: without `CLAUDE_CODE_DISABLE_ATTACHMENTS`, a `@chemin` in the document became an attachment, and the model returned a read call instead of the translation; with it, nothing slips through. The `AGENTS.md`, `CLAUDE.md`, and hook canaries loaded and executed nothing.

  - **A segment starting with `/` did not reach the model.** Under `--disable-slash-commands`, Claude Code responds to it itself with "… isn't available in this environment.", in `success` status, without any turns. A newline preceding the segment sends it to the model; in any case, the output contract rejects any response returned without a turn, in more than one turn, truncated, or from a model other than the one announced.

  - **Models: aliases, never a hardcoded identifier.** `sonnet` by default, at `low` effort, and in `--eco` as well — `--eco` therefore changes nothing on this path —, `opus` and `haiku` via `--model`; `fable` and the `[1m]` variants are rejected because in `-p` they switch to paid credits without asking.

  - **Defects are measured, not assumed.** Through `aipmt --use_claude_code` itself, four parallel translations, across the two benchmark documents from the README — the dense tech watch article, in `--news`, and this README at revision 1.14.0 —, fourteen languages each. `sonnet`, at `low` effort, writes all 28 translations, 26 without discrepancy: one extra bold word in Chinese in the article, and in Arabic, in the README, a table row merged into the previous one, hidden by rendering. Internal links intact, English quotes copied verbatim, and in English, the French translation lines removed by the model, with no invented flags; median of 6 min 49 s per language for the article, 2 min 20 s for the README. `opus` translates the README with zero discrepancies, a quarter faster, but no articles: its guardrails halted the response across all fourteen languages on a short biology item. `haiku` writes everything — three section headings promoted to level 1 in the article, internal links in the English README duplicated —, but twice as slowly as `sonnet`: it reasons without any way to prevent it, accounting for 61% of its output tokens, and its lower price leaves only a 14% saving in API terms. Hence `sonnet` in `--eco` as well. Effort is useless for translation: on a prior batch — this README and this CHANGELOG in English, Japanese, and Hindi —, `sonnet` produced zero reasoning tokens, `opus` at medium effort produced 1% of its output tokens, and medium effort showed no advantage over low, neither in structure nor in duration. The `sonnet` run, 1.8 million source characters, consumed 9 percentage points of the 5-hour window and 2 of the weekly window on the author's Max subscription — an upper bound, as the session running the benchmarks drew from the same quota.

  - **A refusal from Anthropic's guardrails is named as such.** Opus 5.5 has stricter guardrails than Sonnet, and Anthropic's error message warns that they sometimes flag work related to biological research. A tech watch brief about 279 molecules generated for a binding site was enough. Claude Code then cuts off the response, retries once, and the model returns "I can't continue this translation" with a success status, without errors, over two turns: only the single-turn contract halted this response, with a message silent as to its cause. Sent alone, the brief is rejected by the API under the "bio" category. aipmt now recognizes these signs, names the guardrails and their category, does not retry — the same text would trigger the same refusal again — and advises `--model sonnet`, which translated the brief in all fourteen languages.

  - **Translations for this repository can use this path without an exception.** `REGEN_PROVIDER=claude_code` is a subscription, not a billed API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs — the benchmark runs executed four concurrent translations without a single rate-limit error or connection lock —, following a single preflight that consumes no quota. The default remains Codex with `gpt-5.6-sol`.

  - **Terms of service, stated plainly.** Claude Code's legal terms do not prevent a user from connecting to the unmodified binary with their own subscription; they prohibit third-party developers from routing requests through their users' Pro or Max credentials, and Anthropic prefers API keys for third-party tools, including open-source projects, reserving the right to bill their usage against paid credits. No text settles the case of a distributed tool running the official binary: the user commits their own account.

  - **Tests**: new file `tests/test_claude_code_provider.py` (58 tests), 100% of statements and branches in the module, without ever running the real `claude` — cleared environment, nonexistent binary, `PATH` without `claude`, test doubles that raise if called.

- **1.15.0** Provider `--use_antigravity`: translate using the Google AI Pro or Ultra subscription quota, via the official `agy` CLI; and, for all providers, Ctrl-C no longer abandons in-flight agents, a blank segment no longer fails the file, a project `.env` no longer selects the executed binary (2026-09-26):

  - **Tenth provider path: the Google subscription, with no usage-based billing.** Anyone paying for Google AI Pro or Ultra can now count their translations against it instead of paying per token on the Gemini API. `agy`, the official Antigravity CLI, is the only path to this quota: Gemini CLI no longer serves Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK authenticates only via an API key or Google Cloud. `--use_antigravity` drives it in headless mode, like Codex and Grok CLI, on the same foundation — its own process group, `SIGTERM` then `SIGKILL` on timeout, sanitized environment. Verified end-to-end on agy 1.2.11: a Markdown guide — front matter, bold, bracketed link, inline code, indented code block in a list, table, blockquote — translated into English in 14 seconds, preflight included, structure identical to source, translation note added; then, after review fixes, into German in 19 seconds, identical structure, nothing written to `~/.gemini`.

  - **No paid path remains open, and every run verifies it.** agy knows other paths besides the subscription — API key, Google Cloud project, gateway, paid AI credits — and several environment variables switch it to them without displaying anything. Measured: `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, `CLOUD_CODE_URL` redirects the authenticated endpoint to any address. The subprocess environment is therefore an allowlist, not a denylist: `PATH`, language and time zone, terminal, identity, machine proxies and certificates, and the session bus — what a `env -i` proved agy requires —, without any keys. A denylist by prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), tried first, missed some: a review found endpoint overrides in the binary strings that no prefix covered, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings escape the environment and are only readable via `agy -p /config`: paid AI credits taking over when quota is exhausted, and logging in via a Google Cloud project. A preflight that consumes no quota — zero usage, measured — refuses to translate if either is active or if an API key is configured, and a setting absent from `/config` counts as a refusal for each of the three: an agy version renaming one must not pass a check that verified nothing. Finally, the log of each call must attest to subscription authentication (`authMethod=consumer`), and any other authentication method appearing there, under either of the two spellings used by the binary, causes the response to be rejected: the call itself is what counts, not the configuration that was prepared.

  - **The translation agent has no tools, and its loading is proven on every call.** Each call writes, in a disposable directory, an agent in agy's project agent format: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Around 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone let a workspace hook run its commands and inject its text. The real trap lies elsewhere: a missing agent does not make agy fail. Return code 0, status `SUCCESS`, and it is the coding agent, with 57 active tools, that responds — to "Le chat dort.", it answered "Shh, let's not wake it! 🐱💤 What can I do for you today?". Nothing on stdout or stderr: only the call log shows it. The response is therefore rejected if the log reports this fallback, and also if it lacks the positive marker confirming the agent loaded — an evolution of the log format causes the translation to be rejected rather than silently removing the guard. Each marker must occupy an entire log line, in the measured format — severity, date, time, thread, file, and line: the binary also contains a line that echoes the user message into the log — never seen at the default log level across 78 real logs —, and a document quoting these messages must not be able to satisfy the guard in place of agy.

  - **The user's agy settings and history are untouched.** Each call runs with a private HOME, temporary directory, and working directory, deleted afterward. agy still authenticates via the system keychain, which aipmt never reads. Nothing is inherited: neither user permissions — which allowed the default agent to run `ls` and `git` without asking —, nor global rules, plugins, MCP servers, hooks, and skills. And nothing is added to their history, where each call left a conversation of about 200 KB, including translated text: the probing run had left about 95 conversations there and evicted 17 entries from a cache capped at 100. Verified: no files written to `~/.gemini/antigravity-cli`.

  - **Fail-closed refusal where isolation would not hold.** Under Linux without a D-Bus session bus — SSH session, container, server —, agy stores its token in a file in `~/.gemini` instead of the keychain, as announced in its own changelog (1.1.3), and per-call isolation hides this file. Refusal now occurs before any launch, stating its real cause, instead of waiting a minute for a login code followed by reconnection advice that would solve nothing. On Windows, agy reads `USERPROFILE`, `APPDATA`, and `TEMP`, not `HOME` or `TMPDIR` — according to Go documentation and binary strings —: nothing there would isolate the call from user settings or history, and `--use_antigravity` is refused there until measured. macOS passes without having been measured; the billing guard, reading the effective configuration, holds there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero return code, a JSON object with `SUCCESS` status, a compliant log, no refused action, no command, no error in the JSON, no truncation warning on stderr, and non-empty text. `--print-timeout` is never used: upon expiration, agy returns partial output in `SUCCESS`, code 0; the timeout is external and terminates the process group. A segment starting with `/commande`, `!commande`, or `@fichier` is translated, never executed nor resolved — without `--disable-slash-commands`, "/help" was executed instead of translated. A blank segment no longer reaches agy, as the pipeline returns it as is (see below), and remains rejected before the call as a fallback safety net: on empty input, agy opens its interactive interface with code 0. Retries follow the `retryable` field of the `AGY_ERROR` line that agy writes to stderr since 1.2.6: it already retries transient errors on its own — 502, 503, 504, per-minute rate limits —, and it knows whether the remaining failure is still transient. In the absence of this field, no retry when the message mentions exhaustion — at Google, `RESOURCE_EXHAUSTED` carries the same 429 code as a per-minute limit, but an exhausted 5-hour window does not reset in 90 seconds —, and otherwise on rate limits only. The response retains the segment's line ending: agy always ends its output with a newline, which, at the join, split a paragraph in two when broken mid-sentence. A logged-out session produces a message directing to run `agy` to log back in. Finally, `AGY_CLI_DISABLE_AUTO_UPDATE=true` prevents a fresh HOME from spawning an update checker in its own session on each call, beyond the reach of the timeout — the `1` value itself has no effect.

  - **Models: reasoning effort is part of the name.** The identifiers are those of `agy models` — `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… A base name alone, which agy would reject, is rejected before the call, along with the existing suffixes: `-medium` or `-low` for a Flash, `-high` or `-low` for a Pro. By default `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`, set by the benchmark runs described below. `--reasoning_effort` has no effect and reports it. Claude and GPT-OSS draw from a separate and much smaller quota — around 1% of the 5-hour window per measured call, compared to 0.05% for Flash — and a warning reminds of this. The remaining quota can be read for free via `agy -p /usage`. Rejected in CI, like Codex and Grok CLI: the login resides in a personal keyring, and the message suggests `--use_gemini` with a Google key.

  - **Two benchmark runs on September 26: defaults are measured, not assumed.** Via `aipmt --use_antigravity` itself, four parallel translations, each compared to its source with `scripts/compare_structure.py`, quota read by `agy -p /usage` before and after. In the morning, on the revision of this README published with 1.14.0 and on the dense tracking article from the README's benchmarks, in `--news`, `gemini-3.7-flash-medium` writes all fourteen languages for both documents: the article with zero discrepancies, 3 min 14 s per language median, and the README within one bold word in Korean, in 1 min 22 s. In the afternoon, at the author's request, Gemini 3.8 Flash against 3.7 on the same batch, this README and this CHANGELOG in their 1.15.0 version: at medium effort, identical structure for both; 3.8 reasons as much as 3.7 — 63% of output tokens versus 60%, read from agy's JSON — and costs one-seventh more quota, for one-fourth more time. Then the morning benchmark run, re-run with `gemini-3.8-flash-medium`: fourteen languages out of fourteen without discrepancy on the article, 3 min 59 s median, as on the README, 1 min 43 s; internal links intact in all fourteen READMEs, where 3.7 broke some in Italian; and in English, the French translation lines removed by the model, without invented flags, English quotes intact. Hence the defaults: `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`. At low effort, neither Flash model reasons and each costs half as much, but 3.8 low doubled the three internal links of a README in Hindi, which 3.7 low did in none of the translations it produced. Measured cost on the author's account tier: 13 to 16 points of the 5-hour window per million source characters in `gemini-3.8-flash-medium` — the re-run benchmark, 28 translations and 1.8 million characters, took 24.5, and 4.1 from the weekly quota.

  - **Terms of service and data processing, stated plainly.** Antigravity's terms of service (section 6) and FAQ prohibit accessing the service via third-party software using the Antigravity login — Claude Code, OpenClaw, and OpenCode are cited there —, under penalty of account suspension. aipmt never reads or reuses the token: it launches the official binary in the headless mode that Google documents for scripts and CI, and a Google team member deemed it "standard", on the official forum, to launch `agy -p` from a local script for one's own work — an answer, not a commitment. No text settles the case of a distributed tool: the README states that users put their own accounts on the line. Section 5 of the same terms permits Google to use interactions — prompts, responses, metadata — to improve its products and machine learning, and to have them reviewed by humans, without distinguishing the free tier from Pro and Ultra: the README reserves this path for public documents, and its final warning mentions it.

  - **Translations for this repository can go through this path, with no exemption.** `REGEN_PROVIDER=antigravity` is a subscription, not a billed API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs — the entire campaign ran four in parallel, without an error — and Codex's 1,800-second per-job cap, which measurements justify: the entire CHANGELOG in Hindi, the file where Codex loses placeholders, was translated without discrepancy in 4 min 33 s by 3.7 Flash in its 1.14.1 version, and in 5 min 50 s by 3.8 Flash in its 1.15.0 version, one-fifth longer: at least five times under the cap. A full regeneration, 2.2 million characters, amounts to 30 to 36 points of the 5-hour window in `gemini-3.8-flash-medium`. A single check, the module's preflight, precedes the 28 jobs: a logged-out agy or one configured to bill launches none of them. The default remains Codex with `gpt-5.6-sol`.

  - **An internal link was breaking without anything noticing.** The token that protects an anchor swallows its parentheses: the model receives an apparently broken link, brackets followed by the bare token, and sometimes "fixes" it. Restoration then yields `[texte]((#ancre))`, which leads nowhere, without any guard or `compare_structure.py` flagging it. This happened in two READMEs during the first regeneration of this version, and with all models tested, more frequently when the link itself is inside parentheses — the case of a link this version had just added to this README. The release verification now counts intact internal links in each translation, and this README no longer puts any inside parentheses; the fix for the token itself remains to be done.

  - **Ctrl-C and closing the terminal now stop the agent, across all four CLIs.** Codex, Grok CLI, OpenCode, and Antigravity run in their own session, outside the foreground group: the `SIGINT` from a Ctrl-C does not reach them, and on Ctrl-C, `Popen` only waits a quarter of a second for them before returning control. Verified by review using a mock binary: the agent survived aipmt and finished its run on the quota, with discarded output — four at a time under regen. A `KeyboardInterrupt` or `SystemExit` during the call now kills the agent's process group before bubbling up. Closing the terminal or dropping an SSH session (`SIGHUP`) killed Python without any cleanup: the agent kept running, and Antigravity's private directory remained on disk along with its log, which contains the account address. `SIGHUP` now follows the path of `SIGTERM`: agent group killed, then exit with code 129. An ignored `SIGHUP`, launched under `nohup`, remains ignored: that is the user's choice. Antigravity's preflight — `agy --version`, then `agy -p /config` — uses the same handler: a signal received during this check stops agy and also cleans up the private directory, instead of leaving it on disk with its log.

  - **The subprocess runner can no longer target the entire session.** Under Linux, `killpg(1, sig)` equals `kill(-1, sig)`: the signal goes to all user processes. This occurred while writing this version, during a mutation testing run: a mutant called a `Popen` mocked with a bare `MagicMock`, the resulting error went through the new interrupt path, and the mock process pid, which Python converts to 1, caused the entire graphical session to be killed. `_codex_kill_group`, shared across all four CLIs, now targets a group only if the pid is a real integer greater than 1, `getpgid` returns that same pid — an agent started in its own session is leader of its group — and it is not the current process's group; otherwise, only the direct child is targeted. In production, this guard changes nothing: it closes the case where a bug might bubble up something else. Mocks of `Popen` that should not be used now fail immediately, mock processes carry an impossible pid, and mutation testing runs operate in a PID namespace.

  - **A whitespace segment no longer causes the file to fail, regardless of the provider.** `segment_text` can isolate the trailing whitespace of a document: 16,001 characters ending with three newlines yield a second segment made of two newlines. Antigravity rejected it prior to the call — reproduced during review — and, with an API provider, an empty response hit the empty-content guard: in both cases, the entire file failed, after quota for previous segments had already been consumed. A whitespace segment is now returned as-is, without a call.

  - **Security: a project-level `.env` can no longer choose the executed binary.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`, and `AGY_BIN` designate the program launched by translation, with user privileges: set by the `.env` of a newly cloned repository, they would launch a file from that repository on the very first translation. The `_BIN` suffix therefore joins `_BASE_URL`, `_API_BASE`, and `_ENDPOINT` in the project-layer filter, along with `GROK_HOME`, under which the Grok binary is searched (`$GROK_HOME/bin/grok`). These variables remain accepted from the environment and from `~/.config/aipmt/.env`, and each rejection is reported on stderr along with where to set them.

  - **Tests**: new file `tests/test_antigravity_provider.py` (103 tests), covering 100% of the module's statements and branches — exact argv and never `-p`, segment via stdin, agent written without tools or inheritance, environment restricted to the allowlist, private directory removed after success, failure, timeout, or signal, complete output contract, agent fallback and billing route parsed from real-format log lines, `AGY_ERROR` and `retryable`, strict billing preflight, rejection on Windows and without a session bus, effort suffixes, newline convention preserved from the segment, dispatch wiring, and regen branch. No test launches agy: a mock binary placed at the head of `PATH` was called by no run, including under CI conditions, with session bus hidden and `CI=true`. `tests/test_provider_base.py` interrupts a real subprocess via Ctrl-C and via `SIGHUP`, including under `nohup`, and locks down the `killpg` guard — pid `MagicMock`, boolean, 1 or less, current group or another's group: never a group signal; `tests/test_key_resolution.py` spawns a fresh process for each `_BIN` variable; `tests/test_orchestration.py` translates a document whose trailing whitespace forms a standalone segment. Full suite at **650 tests**.

- **1.14.1** Mistral: rate limit exceeded no longer causes the file to fail, and default models are confirmed by measurement (2026-09-17):

  - **HTTP 429 caused the entire file to be lost.** The `mistralai` SDK does not retry anything by default, unlike those of OpenAI and Anthropic, and Mistral's limits are low and specific to each model: 15 requests per minute for Large 3, 100,000 tokens per minute for Small 4, measured on the repo's account. A run with four concurrent translations on Small lost five out of eighty-four. The client now retries on 429, 5xx, and connection errors, with an increasing backoff from 2 to 60 seconds for at most five minutes: Mistral's 429 does not specify how long to wait, and its limits are counted per minute. Cross-check against the API: twenty consecutive calls on Large 3, twenty succeeded, the sixteenth after 33 seconds of waiting.
  - **A response in reasoning blocks no longer breaks translation.** Small 4 and Medium 3.5 reason when asked to, and the response then becomes a list of `thinking` followed by `text` blocks instead of a string. Neither reasons by default (measured), but a default changing on the provider side would have ended in `AttributeError`: reasoning blocks are discarded, as with Claude.
  - **Default models confirmed: `mistral-large-latest` and `mistral-small-latest`.** The only newer model, Mistral Medium 3.5, was measured against them across all fourteen languages, on the dense tracking article of the compatibility table and on the README. On the article, it drops or changes the level of headings in 9 out of 14 languages — a single translation without discrepancy, compared to 6 for Large 3 and 8 for Small 4 — and it costs 3 times more than Large 3 for input, 5 times for output. The aliases point to Large 3 (`mistral-large-2512`) and Small 4 (`mistral-small-2603`).
  - **`MODEL_TOKEN_LIMITS` aligned with the API**: 262,144 tokens for the Mistral range instead of 256,000, 131,072 for `ministral-3b`, and dated identifiers, including `mistral-medium-2604`, no longer trigger the "unlisted" warning. Chunking, capped at 16,000 characters, remains unchanged.

- **1.14.0** A compatibility table at the top of the README, and the benchmark run behind it (2026-09-09):

  - **The verdict by model, at the top of the README, in French.** Over three hundred translations were waiting in the middle of the document, spread across three tables that had to be read and cross-referenced. The new table settles things in one line per model, and above all states what differs: "a forgotten bold word, in Arabic and Japanese" rather than a ratio. Three models have no differences detected by the comparator on the two dense documents — `gemini-3.7-flash`, `gpt-5.6-sol` on the ChatGPT subscription, `z-ai/glm-5.2` via OpenRouter.
  - **A remeasurement campaign of 176 translations.** The original measurements dated back to September 4 and were based on a README that has changed significantly since. Eight models were remeasured on this README, two on a blog tech watch article in `--news` mode, one on four public READMEs — FastAPI, Ollama, tldr-pages, and Vue.js. Three results were worth noting: Mistral drops an **entire section title** in Arabic, Hindi, and Korean, without any pipeline guard noticing — a title cannot be replaced by a token, and nothing currently checks it during translation, even though the comparator detects it after the fact; Grok fails on five languages of a tech watch article, losing four inline code snippets and three URLs right from the first segment, whereas it holds up on a README; and Gemini delivers 55 translations with no differences out of 56 across the four public READMEs.
  - **The structure comparator joins the repository.** The README described this protocol as the proper way to judge a model — "compare the number of sections, links, distinct URLs, code blocks" — without providing the tool. `scripts/compare_structure.py` is the one that generated these tables, with eleven tests proving that it detects a lost URL, code block, section, inline code, table row, and blockquote. It includes the two non-Latin script fixes that made it reliable: a URL followed by a full-width parenthesis is no longer counted as different, and a shorter blockquote in Chinese is no longer considered a lost blockquote.
  - **A package check, before and after publication.** The test suite runs against the source files and stays green even when the distributed package is broken — a module forgotten in the setuptools configuration, an entry point that does not resolve. `scripts/check-package-smoke.sh --wheel` builds the wheel, installs it in a disposable venv outside the repository, verifies that it only contains the package, that both execution forms respond, that all modules import, then translates an actual document and compares its structure. `--pypi` does the same from the index: it is the only check proving that these exact bytes were published, and PyPI never allows republishing a version. The `--full` gate runs the offline part, without model calls or costs.
  - **Seven README claims corrected, all reproduced before being rewritten.** "Nothing false reaches your disk" was false: a model that deletes a section or modifies a front matter date produces a file that the pipeline writes with the status `success`, reproduced with a mock response. The README now states what tokens protect — code blocks, inline code, URLs, anchors, blockquotes — and what pipeline guards currently do not check. "No difference" does not mean "identical": the comparator counts elements without reading their content, and reports neither the deletion of a level-4 heading, nor the replacement of an inline code text, nor a swapped flag — three measured cases, and the mention "same flags" was removed, as the comparator has no flag counter. Installing for contribution did not produce a usable tool: `pip install -r requirements.txt` only installs dependencies, `python -m aipmt` returned `No module named aipmt`, and `pip install -e .` was missing — as was the install command for `pre-commit`, absent from both dependency files. The OpenRouter promise regarding small contexts announced the opposite of the code: a model with a window under **16,400 tokens** is rejected before any call, measured at 4,095, 8,192, and 16,384. The filter preventing a project `.env` from redirecting API calls was documented nowhere; it now is, along with the list of affected variables. Finally, two numbers: a Grok cell in the top table came from a September 9 campaign where its column claimed September 4, and "one broken link" attributed to Gemini was the opposite of the measurement — it turns three bare URLs into links, losing none.

  - **A write failure no longer leaves a truncated translation on disk.** `open(cible, "w")` truncates the file before filling it: an error while writing — disk full — left a partial target. Reproduced: eight bytes written, status `failure` returned, then the next run found this file, replied `skipped`, and kept it. A failure became a truncated translation that was no longer flagged, with an exit code of 0. Content is now written to a temporary file in the same directory — `os.replace` is only atomic within the same filesystem — and then renamed, with the temporary file being deleted if writing fails, including upon interruption. This temporary file comes from `mkstemp`, and a review showed that a predictable name would only have moved the problem: a symlink placed at `cible.md.aipmt-tmp` caused the translation to be written to the target file, outside the output directory, returning `success`; and two concurrent runs on the same target shared this name, the second renaming while the first was still writing to the same inode — target reported successful, mixed content (`BBBAAAAA` instead of `BBBBBBBB`, measured). `mkstemp` creates in `O_CREAT | O_EXCL` under a unique name, which addresses both issues. Permissions from the existing target are explicitly preserved before replacement: `mkstemp` creates with 0600, and a target deliberately set to 0600 would otherwise switch to 0664, while a target set to 0644 served by a web server would have become unreadable. Eight tests lock down the whole process, and two code mutations turn them red.

- **1.13.0** Provider `--use_openrouter`: a paid router to ~430 models, including open Chinese models (2026-09-05):

  - **Ninth provider path, shipped with the eighth.** 1.12.0 was not published on PyPI: both routers, OpenCode and OpenRouter, are released together. [OpenRouter](https://openrouter.ai) provides single-key access to models that no other provider exposes here — Kimi, Qwen, DeepSeek, Z.ai — on a single pay-as-you-go balance. Since the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything distinguishing this provider lies in a preflight**, and each of its rules comes from a measurement on the API.

  - **The same model is served by dozens of hosts with different caps, and routing is blind to this.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash` — including one capped at **2,048 output tokens**. One long translation out of 23 would therefore end up truncated, at random, without any warning. The preflight reads `/api/v1/models/{modèle}/endpoints`, filters out hosts below 8,000 output tokens, those with degraded status, and those declaring no cap, then pins the rest. `provider.only` **without** `allow_fallbacks: false` is merely a preference: the router falls back to a discarded host, and the pinning becomes worthless. If no host meets the cap, the command aborts: translating anyway would mean accepting the silent truncation that this preflight exists to prevent.

  - **Reasoning is billed at the output rate, and active by default on many models.** Same query on `z-ai/glm-5.2`, "OK" response: **107 completion tokens with the model default, 2 with reasoning turned off**. On a translation, to which reasoning brings nothing, that is an 18x factor on each segment of each file. It is therefore turned off by default. The **288 models out of 431** that enforce it (`reasoning.mandatory`) return `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for them, the preflight reads the accepted efforts and requests the lowest one (next bullet) — effort allocates a **percentage of `max_tokens`** that reasoning consumes first, so choosing a random value merely shifts the blank page risk instead of reducing it.

  - **A model that forces reasoning receives the lowest effort it accepts, and this was decided by measurement.** The initial choice was to send nothing, so as not to guess on the model's behalf. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced output **truncated at 32,768 tokens** before the translation completed — two languages out of fourteen lost. Raising the budget would have changed nothing: effort allocates a percentage of it, and reasoning grows along with it. The provider therefore reads `supported_efforts` during preflight and requests the lowest, falling back to "nothing" when the catalog announces none usable. Counter-testing on the failing language: previously failing on an exhausted budget, it now passes in 9 minutes with a structure identical to the source.

  - **An upstream provider outage now bears its real name.** The router normalizes this case into `finish_reason=error` with a null `native_finish_reason` — measured twice, across two languages, at exactly 750 seconds. The generic message used to prompt looking for a flaw in the document or segmentation; it now states that the outage is on the provider's side and that retrying is often sufficient.

  - **`finish_reason=length` with empty output is not a truncation.** It is the budget consumed by reasoning before the first usable character — measured at 15,850 reasoning tokens for 148 usable ones. The two cases call for opposite actions: reducing segment size is useless in the first. The message explicitly distinguishes between them. Two other guards stem from measurements: the router responds **200 with a body carrying only an error** when the upstream provider fails (`choices[0]` raised an opaque `TypeError` that hid the message), and the context window is read from the catalog and then recorded in `MODEL_TOKEN_LIMITS` — `DEFAULT_TOKEN_LIMIT` is false for 44 models in the catalog, including two capped at 4,095 tokens.

  - **`--model fournisseur/modèle` is mandatory, and its shape is validated prior to any network call.** OpenRouter is not a vendor: the choice involves pricing, licensing, and data processing, and is not made in place of the user. Since the slug is interpolated into the preflight URL, validation is not a courtesy of ergonomics but the guard preventing path injection: the namespaced regex common to both routers accepts `a/b/..`, hence the explicit rejection of parent directory segments. `--eco` has no effect and says so.

  - **Three phrasings corrected, one of which was false.** OpenAI's warning about `codex exec` targeted injecting a personal session file onto a shared runner, not the public status of the repository: it was cited backwards in the README, in CLAUDE.md, and in the code. The authentication location for OpenCode changed in 1.18.27 (table `credential` of `opencode.db`, no longer `auth.json`); the "never read here" invariant remained true, but the path was outdated. Finally, the OpenCode section no longer presents never-tested paths as equivalent: the Zen gateway and Ollama were measured end-to-end; GitHub Copilot, LM Studio, and llama.cpp were not, and the README now says so.

  - **A measurement campaign, and a recommended models table in the README.** Over three hundred translations executed across three sets of documents — a dense blog post in `--news` mode, this README in standard Markdown, and four well-known project READMEs taken as-is from GitHub — into fourteen languages. The table distinguishes two things that were often conflated: translations that **succeed** and those whose **structure is identical** to the source. Three models never lost any information on the two dense documents: `gemini-3.7-flash`, `gpt-5.6-sol` via ChatGPT subscription, and `z-ai/glm-5.2` via OpenRouter — their only discrepancies being a pair of `**` not carried over in one or two languages. The central finding is that **the discriminating factor is document density, not `--news` mode**: Grok via subscription fails thirteen times out of fourteen on the blog post and succeeds on fourteen public READMEs out of sixteen, the cause being a drop-off on long segments confirmed by counter-testing. The table carries its own warning: it is not exhaustive, it is dated, runtimes do not establish rankings, and the sound approach remains testing on one's own documents.

  - **The structure comparator was fixed before publishing its figures because it produced two false positives on non-Latin scripts.** A URL followed by a full-width closing parenthesis `）` was not trimmed by a regex stopping at `)`, and the extracted string differed even though the URL was identical; a five-line quote in French fitting into three lines in Chinese caused a line-count check to fail. Both fixes were validated by counter-testing: removing a URL, a section, or inline code is still detected.   - **Tests**: new file `tests/test_openrouter_provider.py` (76 tests) — model validation and parent segment rejection, provider pinning (ceiling, status, undeclared ceiling, common minimum), `allow_fallbacks` always false, reasoning disabled or kept according to `mandatory`, complete output contract (error inside a 200, zero choices, blank page distinguished from truncation, abnormal `finish_reason`, null content), preflight fail-closed on unreachable catalog, missing slug, and absence of healthy provider, flag exclusivity, and filename labelling. Full suite at **502 tests**.

  - **Refactor: the single 4,253-line module is split into modules, without changing a single line of behavior.** `src/aipmt/translate.py` is split into `config`, `markdown`, `segmentation`, `guards`, `placeholders`, `news`, `prompts`, `notes`, `naming`, `pipeline`, `cli`, and a subpackage `providers/` (one module per provider, `base` as base, `registry` for resolution and dispatch). Each move is a commit with mechanical proof: a checker compares the AST of all top-level nodes in the package against a reference snapshot, verifies the location of each symbol, the verbatim survival of security markers, and the absence of untracked files — temporary tooling, removed in the following version. What changes and is visible: `aipmt.translate` becomes a facade re-exposing, by object identity, the 64 names the module exposed without a `_` prefix (`__all__` contains nine of them, the supported API; the others are compatibility aliases), and ceases to re-export the 29 dependency and standard library names gathered by a `import *`; running the file directly (`python src/aipmt/translate.py`) no longer exists — `aipmt` and `python -m aipmt` remain the two supported forms; the `__module__` of public functions is that of their defining module; SDKs are imported after loading `.env` rather than before, with no known consequences. The 427 tests are preserved down to the identifier and migrated to the modules they exercise: 91 patches routed through the facade now target the module looking up the name (two of them remained green without their patch, as measured), seven contract tests lock down the facade, and gate tooling was rewritten BEFORE the first move so that none could turn green by ceasing to verify — Lizard scope set to directories with a floor, flags read from the built parser, package coverage floor, `release.sh` listing tracked modules.
  - **Fix (pull request review)**: OpenRouter rejects a catalog entry missing `context_length` instead of recording the default of 128,000 tokens as a measurement — which also suppressed the "unlisted model" warning — and, when `finish_reason` is null (documented type `string | null`), the host's raw reason prevails, with `max_tokens` equating to `length`; an error carried by the choice itself rejects the partial content accompanying it, using the same message as the normalized upstream outage — host details, raw reason, and guidance combined. OpenCode responds with its contract error, not a `AttributeError`, on an event `part: null`, and rejects a JSONL stream where an event line cannot be parsed rather than accepting partial text. All three agentic CLIs kill the agent's group when this process receives `SIGTERM` during the call — the regen's `timeout` allowed the agent to survive and burn its quota — and the group's `SIGKILL` always follows the grace period, as a clean shim death leaves its grandchild alive. A `# fmt: off` / `# fmt: on` pair split during refactoring is reunited; the help text for `--reasoning_effort` names the four providers consuming it.
  - **Fix (second review)**: the output ceiling requested from OpenRouter now reserves the portion of the context taken up by the prompt and segment — `context_length` covers input AND completion, and six models in the catalog had their requests sent with no room for input; an undersized context is rejected prior to any billing. The agentic CLI base falls back to `terminate` then `kill` where POSIX process groups do not exist, instead of allowing a `AttributeError` to bypass the timeout guard and stall the wait. The OpenCode `429` marker is matched as a number rather than a substring, where an error ID like `err_84290b` triggered a 90-second back-off before failing anyway. Finally, a non-canonical OpenRouter endpoint is displayed during preflight: a project `.env` suffices to define one, and the real key would then be sent out.
  - **Security: a project `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file starting from the current directory and its parents: an untrusted tree — a newly cloned repository — could place `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` (the latter read by the SDK itself) without knowing any key, and the real key, originating from the environment or user configuration, would subsequently be sent in the authorization header to a third-party server. The filter operates on a PATTERN rather than a list: audited across installed SDKs, twelve routing variables are read, six of which by the Anthropic client alone — a hand-written list would have missed half of them. Therefore, any variable matching `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, proxies, and certificate stores (pointing to a controlled CA makes an interceptor indistinguishable from a real server) are rejected from the project layer, as well as `XDG_CONFIG_HOME` and `APPDATA`: defining them amounted to deciding which file constitutes the user layer, bypassing the filter through the backdoor. These variables are accepted only from the two layers the user controls: the exported environment and `~/.config/aipmt/.env`. The project layer is furthermore read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` copied the real key under a name unrecognized by subprocess pattern filtering — it would then enter the environment of `codex exec`, contrary to the stated invariant. Finally, rejection only prints the variable name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into logs, even as it was being rejected. A rejection is printed to stderr with remediation steps — an enterprise relay is declared in user configuration.
  - **Fix: the OpenRouter output budget is calculated per call.** `context_length` covers input AND completion, and a fixed reserve calibrated for Latin text bounds nothing: measured with tokenizer `o200k_base`, 16,000 characters amount to 3,200 tokens in French, but 12,300 in Japanese and 17,500 in emoji. The budget is therefore calculated from the text actually sent, bounded above by its UTF-8 byte count: for any byte-pair encoding tokenizer — byte-level BPE, SentencePiece with byte fallback, the families used by the catalog — one token equals at least one byte, and this is the only upper bound available here, where OpenRouter routes to dozens of unknown tokenizers. No average ratio was suitable — a supplementary plane ideograph drops to 1.33 bytes per token, a combining character to 1.00 —, and input plus output now fit within the window by construction. A segment too dense for the selected model is rejected before the call rather than after billing.

- **1.12.0** Provider `--use_opencode`: OpenCode, the open-source agent, to the provider of your choice — local model, free without an account, subscription, or API key (2026-09-04):

  - **Eighth provider pathway, fundamentally different from the first seven.** [OpenCode](https://opencode.ai) (MIT) is not a model provider but a _router_ to those configured by the user inside OpenCode itself: an API key, a subscription (GitHub Copilot, ChatGPT, SuperGrok), the OpenCode Zen gateway — which serves free models **without an account** —, or a **local** model (Ollama, LM Studio, llama.cpp). The script drives `opencode run` in non-interactive mode, just as it drives Codex and Grok, and reuses the same subprocess foundation (dedicated process group, `SIGTERM` then `SIGKILL` on timeout, stdin always closed, sanitized environment). Verified by **two real-world translations**: this entire README into English via `opencode/mimo-v2.5-free` — 49 s, single pass, structure identical to the source file (32 headings, 26 code block closures, 18 links, 37 URLs, 37 table rows, 135 inline code spans) — and a test file via `ollama/qwen2.5:7b`, locally, without any key.

  - **`--model provider/modèle` is mandatory, and that is by design.** Without `--model`, OpenCode falls back to its own default, which on a fresh install is `opencode/big-pickle`, a free "stealth" model whose prompts and responses may be used for training — as measured, this was the model that answered. Silently choosing this on behalf of the user would be exactly the kind of invisible shift this repository guards against; the error message therefore mentions the command listing available models (`opencode models`) and three examples (local, free, subscription). `--eco` has no effect and says so. `--reasoning_effort` is passed through as OpenCode's `--variant` only upon explicit request.

  - **Measured confinement, not assumed.** An inline configuration (`OPENCODE_CONFIG_CONTENT`, last in OpenCode's merge order, thus taking precedence over the user's without replacing it) defines an agent `aipmt` with all tools denied (`permission: {"*": "deny"}`): the registry no longer even presents them to the model, which, when prompted to "list files and run `id`", answers that it has no tools. Session sharing disabled, external plugins discarded (`--pure`), never `--auto`, empty disposable working directory. Two silent injections were measured and blocked: without `OPENCODE_DISABLE_CLAUDE_CODE`, the user's `~/.claude/CLAUDE.md` enters **every** prompt (515 input tokens instead of 186 for a simple "Hello"); without `OPENCODE_DISABLE_PROJECT_CONFIG`, the current directory's `AGENTS.md` does as well — an instruction to "end every response with BANANA" was applied to the translation. Global `~/.config/opencode/AGENTS.md`, however, remains injected: no flag disables it, and bypassing it via a diverted `XDG_CONFIG_HOME` would also hide the user's configured providers. Documented rather than hacked around.

  - **`exit 0` proves nothing, third CLI, same reflexes — with two traps specific to this one.** An unknown `--agent` does not make `opencode run` fail: warning on stderr and **silent** fallback to the coding agent, tools active. If the inline configuration were not taken into account, translation would proceed with an agent capable of writing; the exit contract verifies the absence of this message, in addition to: return code 0, no `error` event, no `tool_use`, last `step_finish` as `stop` (a `length` is a truncated response), non-empty text. Second trap: the error JSON event is **opaque** — "Unexpected server error. Check server logs for details.", with a simple reference — and the actual cause (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`...) only lives in the logs. Hence `--print-logs --log-level ERROR` and reading the `error="…"` field of stderr, without the Bun trace that follows it. An unknown model thus fails in one second, with its named cause. `--title` also avoids a spurious LLM call: without it, OpenCode generates a session title via an extra turn on the `small_model`.

  - **Secrets: same pattern filtering as Codex and Grok, with one specific exception.** `OPENCODE_API_KEY` is retained: it is the key for OpenCode itself (Zen gateway, Go subscription), addressed to it by name — the equivalent of its `auth.json`, not a key that aipmt would manage or could bill. Providers are configured in OpenCode (`opencode auth login`, `opencode.json`), never in aipmt's `.env`, from which no key reaches the subprocess. No rejection in CI, unlike subscription CLIs: an API key or a self-hosted model on a runner are legitimate use cases.

  - **The anti-traversal guard now checks the interpolated value, not the raw value.** `provider/modèle` contains a `/` that the 1.10.0 guard rejected — rightly so, as `--model` is interpolated into the `--include_model` file name. The filename label now replaces `/`, `\`, and `:` with `-` before any interpolation (`ollama/qwen2.5:7b` → `ollama-qwen2.5-7b`, as `:` is illegal on Windows), and the upstream guard inspects this label: `../../evil` becomes the simple name `doc-en-..-..-evil.md` under the target, `..` alone remains rejected, as does `--target_lang ../x`. The `_ensure_within_directory` boundary guard remains the second layer, unchanged.

  - **Free models and local models, what was measured.** `opencode/mimo-v2.5-free` translates a paragraph in 16 s and this README in 49 s; `opencode/big-pickle` takes 40 s for 200 words, and two concurrent requests hung unanswered for 5 minutes where each on its own succeeded; `opencode/nemotron-3.5-lightning-free` returned nothing in 3 minutes. Hence `REGEN_PROVIDER=opencode` with mandatory `REGEN_MODEL` and **2 jobs** in parallel. On the local side, Ollama often configures 4,096 context tokens while segments reach up to 16,000 characters: a `Modelfile` with `PARAMETER num_ctx 32768` is necessary, and quality tracks the model — a 7B reversed a list and corrupted a code block closing fence on the test file, whereas the gateway model preserved everything.

  - **Translations for this repository never go through a billed API anymore.** `regen_translations.sh` selected the OpenAI API whenever a key was lingering in `.env`, and only made Codex an opt-in. This is exactly what happened while preparing this version: the 28 translations ran on the OpenAI API, then the Hindi CHANGELOG on Gemini's, even though the ChatGPT subscription exists precisely to avoid paying per use. Key auto-detection is removed: **Codex is the default, with `gpt-5.6-sol`**, the quality model; `openai`, `gemini`, and `grok` require `REGEN_ALLOW_PAID_API=1` in addition to `REGEN_PROVIDER`, an explicit override so that the rule takes effect at decision time; an unknown `REGEN_PROVIDER` fails instead of falling back to the API. Ten tests lock in the default, the rejection, and the override. The 28 translations for this version were redone via Codex.

  - **Rate limit back-off is refactored** (`_retry_on_rate_limit`): the Codex and Grok loops were identical except for their labels, and a third copy would have exceeded the duplication threshold. The three CLI errors derive from the same `_CliCallError`; a test prevents any of the three from deviating, otherwise the shared loop would no longer detect it.

  - **Tests**: new `tests/test_opencode_provider.py` file (61 tests) — complete exit contract, agent fallback, cause read from logs, deduplicated text parts and ignored synthetic parts, timeout killing the process group, back-off on 429, mandatory and validated model, preflight without secrets, binary resolution, dispatch wiring, filename label and traversal cross-check. `tests/test_review_hardening.py` extends flag exclusivity and secret absence to the new provider. Verified end-to-end: with `codex` absent from the `PATH`, resolution finds the packaged binary and a complete translation succeeds in 6 s.
  - **"Subscription mode" guarantee**: `OPENAI_API_KEY` and `CODEX_API_KEY` are removed from the subprocess environment. Without this safeguard, a key present in `.env` could switch Codex to pay-as-you-go billing without any visible signal — exactly what this provider exists to avoid.
  - **CLI pitfalls locked down with tests**:
    - `codex exec` reads stdin **even** when the prompt is passed as an argument: without closing stdin, the command waits until timeout without ever calling the model (reproduced: exit 124 after 180 s, zero bytes). `communicate(input=...)` is therefore mandatory.
    - The `codex` installed by npm is a Node shim that `spawn` the real Rust binary: the latter is a **grandchild** of the Python process and survives `SIGKILL` from `subprocess.run(timeout=)`, where it would continue to consume quota. Hence `Popen(start_new_session=True)` + `os.killpg`.
    - The CLI can exit with 0 while having emitted an `turn.failed`: the JSONL output (`--json`) is inspected in addition to the exit code, and the absence of the file `-o` with an exit code of 0 raises an explicit error instead of producing an empty segment.
  - **Backoff on rate limits**: the CLI implements no internal retry (`max_retries = 0`). Classification is performed on the JSON payload structure (`status: 429` / `error.type`), not on substrings — the word "quota" appearing in both a recoverable 429 and a definitive `insufficient_quota`.
  - **CI guard**: `--use_codex` is rejected if `CI` or `GITHUB_ACTIONS` is defined. Subscription authentication is not intended for a shared runner, and OpenAI explicitly advises against this workflow on public repositories.
  - **Models**: `gpt-5.6-sol` (quality) and `gpt-5.6-luna` (`--eco`). The `gpt-5.6-*` family is common to the CLI and the Platform API, but a ChatGPT account is not entitled to everything: the allowlist is enforced server-side, without local validation, and an unusual model triggers a warning. On a Plus plan, Luna offers 250–2,000 messages per 5 h window compared to 10–100 for Sol: `--eco` is the recommended mode for any batch processing.
  - **Bug fixed — `regen_translations.sh` exited with an error despite complete success**: the `trap ... EXIT` referenced `failed_log`, a `local` variable of `main()` that no longer exists at the time the trap executes. Under `set -u`, this raised `failed_log: unbound variable` and caused the script to exit with 1 even though all 28 translations were correct — which would have interrupted `release.sh --auto` (`set -e`) right after regeneration, at the most expensive stage. The variable becomes global and the trap checks for its existence. Useful side effect: real translation failures, previously masked by this error, are visible again in the final summary.
  - **`REGEN_MODEL`**: new environment variable for `regen_translations.sh` that overrides the provider default with a specific model, for example `REGEN_PROVIDER=codex REGEN_MODEL=gpt-5.6-sol` to regenerate using the high-end model of the subscription quota rather than the volume-oriented `--eco` model.

The token is refreshed once sequentially before opening parallelism — since the Codex refresh is rotating and single-use, concurrent jobs would invalidate the `codex login` session — and concurrency is reduced to 4.

- **1.9.2** Fix news attribution URL extraction with nested parentheses or FR prefix (2026-05-11):

  - **Bug fixed**: attribution URL extraction in `_protect_news_quotes` used the regex `re.search(r"\((.+?)\)", attribution)` (lazy capture between parentheses). On an attribution such as `(relayé par [@user sur X](https://x.com/.../123))` (nested parentheses: enclosing `(` + `]()` of the markdown link), the capture stopped at the first `)` encountered → truncated string + including the FR prefix: `relayé par [@user sur X](https://x.com/.../123` (without final `)`). Consequence: `_validate_news_post` searched for this string in the translated output and systematically failed (two reasons: truncated `)` + "relayé par" translated into `relayed by`/`weitergeleitet von`/...). Complete cascade low → medium → high → gpt-5.5 could not pass.
  - **Fix**: the regex becomes `re.search(r"\]\(([^)]+)\)", attribution)` — specifically targets the `](url)` of the markdown link, captures **only the pure URL** (without FR prefix or truncation), an invariant preserved by `#URL{N}#` placeholders during translation. Robust against both problematic patterns:
    - `(relayé par [@account sur X](url))` — nested parentheses
    - `via [@source](url)` or `selon [@author](url)` — FR prefix without enclosing parentheses
  - **Tests**: 2 new ones in `test_silent_failure.py` class `TestNewsCitationExtraction`:
    - `test_extract_attribution_url_with_nested_parens` (exact reproduced case of the Genspark CEO E2B bug)
