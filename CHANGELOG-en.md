- **1.13.0** Provider `--use_openrouter`: a paid router to ~430 models, including open Chinese models (2026-09-05):

  - **Ninth provider path, shipped with the eighth.** 1.12.0 was not published on PyPI: both routers, OpenCode and OpenRouter, are being released together. [OpenRouter](https://openrouter.ai) provides access with a single key to models that no other provider exposes here—Kimi, Qwen, DeepSeek, Z.ai—using a single pay-as-you-go credit balance. Since the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything that distinguishes this provider is handled in a preflight**, and every one of its rules comes from an API measurement.

  - **The same model is served by dozens of hosts with different limits, and routing is blind to this.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash`—including one capped at **2,048 output tokens**. A long translation routed to one of those 23 could therefore be randomly truncated without any signal. The preflight reads `/api/v1/models/{modèle}/endpoints`, excludes hosts with fewer than 8,000 output tokens, hosts with degraded status, and hosts that declare no limit, then pins the others. `provider.only` **without** `allow_fallbacks: false` is merely a preference: the router falls back to an excluded host, making pinning worthless. If no host meets the limit, the command stops: translating anyway would mean accepting the silent truncation this preflight exists to prevent.

  - **Reasoning is billed at the output rate and is enabled by default on many models.** Same request on `z-ai/glm-5.2`, response “OK”: **107 completion tokens with the model default, 2 with reasoning disabled**. For translation, where reasoning adds nothing, that is an 18-fold increase for every segment of every file. It is therefore disabled by default. The **288 models out of 431** that require it (`reasoning.mandatory`) respond with `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for them, the preflight reads the accepted effort levels and requests the lowest one (next bullet)—effort allocates a **percentage of `max_tokens`** that reasoning consumes first, so choosing a value at random shifts the risk of a blank output instead of reducing it.

  - **A model that requires reasoning receives the lowest effort it accepts, based on measurement.** The initial choice was to send nothing, so as not to guess on the model’s behalf. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced output **truncated at 32,768 tokens** before the translation ended—two languages out of fourteen were lost. Increasing the envelope would not have changed anything: effort allocates a percentage of it, so reasoning grows along with it. The provider therefore reads `supported_efforts` during preflight and requests the lowest value, falling back to “nothing” when the catalog lists no usable value. Counter-test on the failing language: it previously failed due to an exhausted budget; it now completes in 9 minutes with a structure identical to the source.

  - **An upstream host failure now bears its name.** The router normalizes this case as `finish_reason=error` with a null `native_finish_reason`—measured twice, in two languages, at exactly 750 seconds. The generic message sent users looking for a defect in the document or segmentation; it now says that the failure is provider-side and that retrying is often sufficient.

  - **`finish_reason=length` with empty output is not truncation.** It means the budget was consumed by reasoning before the first useful character—measured at 15,850 reasoning tokens for 148 useful ones. The two cases call for opposite actions: reducing segment size is useless in the first case. The message distinguishes them explicitly. Two other guards come from measurements: the router responds with **200 and a body containing only an error** when the upstream host fails (`choices[0]` raised an opaque `TypeError` that hid the message), and the context window is read from the catalog and then written to `MODEL_TOKEN_LIMITS`—`DEFAULT_TOKEN_LIMIT` is wrong for 44 catalog models, including two capped at 4,095 tokens.

  - **`--model fournisseur/modèle` is mandatory, and its format is validated before any network access.** OpenRouter is not a provider: the choice determines price, licensing, and data handling, and must not be made on the user’s behalf. Because the slug is interpolated into the preflight URL, validation is not merely an ergonomic nicety but the guard that prevents path injection: the namespaced regex shared by both routers accepts `a/b/..`, hence the explicit rejection of the parent segment. `--eco` has no effect and says so.

  - **Three corrected statements, including one that was false.** OpenAI’s warning about `codex exec` concerned injecting a personal session file on a shared runner, not whether the repository was public: it was cited out of context in the README, CLAUDE.md, and the code. OpenCode’s authentication location changed in 1.18.27 (`credential` table in `opencode.db`, no longer `auth.json`); the “never read here” invariant remained true, but the address was outdated. Finally, the OpenCode section no longer presents untested paths as equivalent: the Zen gateway and Ollama were measured end to end, while GitHub Copilot, LM Studio, and llama.cpp were not, and the README now says so.

  - **A measurement campaign and a table of recommended models in the README.** More than three hundred translations were run across three document sets—a dense blog post in `--news` mode, this README in standard Markdown, and four well-known project READMEs taken as-is from GitHub—into fourteen languages. The table distinguishes two things that had been conflated: translations that **complete** and those whose **structure is identical** to the source. Three models never lost any information across the two dense documents: `gemini-3.7-flash`, `gpt-5.6-sol` through the ChatGPT subscription, and `z-ai/glm-5.2` through OpenRouter—their only discrepancies are one pair of `**` markers omitted in one or two languages. The central finding is that **the discriminating factor is document density, not `--news` mode**: subscription-based Grok fails thirteen times out of fourteen on the blog post and succeeds on fourteen public READMEs out of sixteen, caused by a breakdown on long segments confirmed by counter-testing. The table carries its own warning: it is not exhaustive, it is dated, durations are not rankings, and the right approach remains to measure performance on your own documents.

  - **The structure comparator was fixed before its figures were published because it produced two false positives for non-Latin scripts.** A URL followed by a full-width closing parenthesis `）` was not split by a regex that stops at `)`, so the extracted string differed even though the URL was identical; a five-line quotation in French fitting into three lines in Chinese caused a line-based count to drop. Both fixes were validated by counter-testing: removing a URL, a section, or inline code is still detected. Without them, Gemini and Codex would have been reported as succeeding in eleven languages out of fourteen instead of thirteen and twelve.

  - **Tests**: new `tests/test_openrouter_provider.py` file (76 tests)—model validation and parent-segment rejection, host pinning (limit, status, undeclared limit, shared minimum), `allow_fallbacks` always false, reasoning disabled or retained according to `mandatory`, complete output contract (error inside a 200, no choices, blank output distinguished from truncation, abnormal `finish_reason`, null content), fail-closed preflight when the catalog is unreachable, missing slug and no healthy host, flag exclusivity, and filename label. Full suite at **502 tests**.

  - **Refactor: the single 4,253-line module is split into modules without changing a single line of behavior.** `src/aipmt/translate.py` is divided into `config`, `markdown`, `segmentation`, `guards`, `placeholders`, `news`, `prompts`, `notes`, `naming`, `pipeline`, `cli`, and a `providers/` subpackage (one module per provider, `base` as the foundation, `registry` for resolution and dispatch). Each move is a commit with mechanical proof: a verifier compares the AST of every top-level package node against a reference snapshot, checks the location of every symbol, the verbatim survival of security markers, and the absence of untracked files—temporary tooling removed by the next release. Visible changes: `aipmt.translate` becomes a façade that re-exports, by object identity, the 64 names the module previously exposed without an `_` prefix (`__all__` contains nine of them, the supported API; the others are compatibility aliases), and stops re-exporting the 29 dependency and standard-library names picked up by `import *`; direct file execution (`python src/aipmt/translate.py`) no longer exists—`aipmt` and `python -m aipmt` remain the two supported forms; the `__module__` of public functions is that of their defining module; SDKs are imported after `.env` is loaded rather than before, with no known consequence. All 427 tests are preserved down to their identifiers and migrated to the modules they exercise: 91 patches that went through the façade now target the module that looks up the name (two of them still passed without their patch, as measured), seven contract tests lock down the façade, and the gate tooling was rewritten BEFORE the first move so that none could turn green by ceasing to check—directory-scoped Lizard with a floor, flags read from the constructed parser, package-level coverage floor, and `release.sh` enumerating tracked modules.
  - **Fix (pull request review)**: OpenRouter rejects a catalog entry without `context_length` instead of recording the default of 128,000 tokens as a measurement—which also suppressed the “model not listed” warning—and, when `finish_reason` is null (documented type `string | null`), the host’s raw reason takes precedence, with `max_tokens` equal to `length`; an error attached to the choice itself rejects the accompanying partial content, using the same message as a normalized upstream failure—host detail, raw reason, and advice together. OpenCode responds with its contract error, rather than an `AttributeError`, on a `part: null` event, and rejects a JSONL stream containing an unreadable event line instead of accepting partial text. All three agentic CLIs kill the agent’s group when that process receives `SIGTERM` during the call—the regen’s `timeout` allowed the agent to survive and consume its quota—and the group’s `SIGKILL` always follows the grace period, so a shim that exits cleanly does not leave its grandchild running. A `# fmt: off` / `# fmt: on` pair split by the refactor is reunited; the help for `--reasoning_effort` names the four providers that use it.
  - **Fix (second review)**: the output limit requested from OpenRouter now reserves the share of the context occupied by the prompt and segment—`context_length` covers BOTH input and completion, and six catalog models had requests sent without room for the input; a context window that is too short is rejected before any charge. The agentic CLI foundation falls back to `terminate` and then `kill` where POSIX process groups do not exist, instead of allowing an `AttributeError` to pass through the timeout guard and prolong the wait. OpenCode’s `429` marker is searched for as a number rather than as a substring, where an error identifier such as `err_84290b` triggered 90 seconds of backoff before failing anyway. Finally, a non-canonical OpenRouter endpoint is displayed during preflight: a project-level `.env` is enough to set one, and the real key would subsequently be sent there.
  - **Security: a project-level `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file from the current directory and its parents: an untrusted directory tree—a repository that was just cloned—could define `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` (the latter read by the SDK itself) without knowing any key, after which the real key, obtained from the environment or user configuration, would be sent in the authorization header to a third-party server. The filter is based on a PATTERN rather than a list: an inventory of the installed SDKs found twelve routing variables, six of them read by the Anthropic client alone—a manually written enumeration would have missed half. The project layer therefore rejects every variable matching `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, proxies and certificate stores (pointing to a controlled authority makes an interceptor indistinguishable from a real server), as well as `XDG_CONFIG_HOME` and `APPDATA`: setting them amounted to deciding which file constitutes the user layer, thereby bypassing the filter indirectly. These variables are accepted only from the two layers controlled by the user: the exported environment and `~/.config/aipmt/.env`. The project layer is also read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` copied the real key under a name that subprocess pattern filtering did not recognize—it then entered the environment of `codex exec`, contrary to the stated invariant. Finally, rejection displays only the variable name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into logs even as it was being rejected. A rejection is reported on stderr with instructions—an enterprise relay must be declared in the user configuration.
  - **Fix: the OpenRouter output envelope is calculated for every call.** `context_length` covers BOTH input and completion, and a fixed reserve calibrated on Latin text provides no bound: measured with the `o200k_base` tokenizer, 16,000 characters amount to 3,200 tokens in French but 12,300 in Japanese and 17,500 in emoji. The budget therefore comes from the text actually sent, increased by its UTF-8 byte count: with any byte-fallback tokenizer—byte-level BPE, SentencePiece with byte fallback, the families used by the catalog—a token represents at least one byte, and this is the only available upper bound here, where OpenRouter routes to dozens of unknown tokenizers. No average ratio was suitable—a supplementary-plane ideograph falls to 1.33 bytes per token, a combining character to 1.00—and input plus output now fit within the window by construction. A segment that is too dense for the selected model is rejected before the call rather than after billing.

- **1.12.0** Provider `--use_opencode`: OpenCode, the open-source agent, connected to the provider of your choice—local model, free without an account, subscription, or API key (2026-09-04):
  - **Eighth provider path, different in nature from the first seven.** [OpenCode](https://opencode.ai) (MIT) is not a model provider but a _router_ to those the user has configured in OpenCode itself: an API key, a subscription (GitHub Copilot, ChatGPT, SuperGrok), the OpenCode Zen gateway—which serves free models **without an account**—or a **local** model (Ollama, LM Studio, llama.cpp). The script drives `opencode run` in non-interactive mode, just as it drives Codex and Grok, and reuses the same subprocess foundation (dedicated process group, `SIGTERM` then `SIGKILL` on timeout, stdin always closed, sanitized environment). Verified through **two real translations**: this entire README into English via `opencode/mimo-v2.5-free`—49 s, a single pass, structure identical to the source file (32 headings, 26 code-block closings, 18 links, 37 URLs, 37 table rows, 135 inline code spans)—and a test file via `ollama/qwen2.5:7b`, locally, without any key.

  - **`--model provider/modèle` is mandatory, and that is a deliberate choice.** Without `--model`, OpenCode falls back to its own default, which on a fresh installation is `opencode/big-pickle`, a free “stealth” model whose exchanges may be used for training—testing confirmed that this was the model that responded. Silently choosing that on the user's behalf would be exactly the kind of invisible switch this repository tracks; the error message therefore names the command that lists the models (`opencode models`) and gives three examples (local, free, subscription). `--eco` has no effect and says so. `--reasoning_effort` is passed through unchanged as OpenCode's `--variant`, only when explicitly requested.

  - **Measured confinement, not assumed.** An inline configuration (`OPENCODE_CONFIG_CONTENT`, last in OpenCode's merge order and therefore taking precedence over the user's configuration without replacing it) defines an `aipmt` agent for which all tools are denied (`permission: {"*": "deny"}`): the registry no longer even offers them to the model, which, when instructed to “list the files and run `id`,” responds that it has no tools. Session sharing disabled, external plugins excluded (`--pure`), never `--auto`, disposable and empty working directory. Two silent injections were measured and disabled: without `OPENCODE_DISABLE_CLAUDE_CODE`, the user's `~/.claude/CLAUDE.md` enters **every** prompt (515 input tokens instead of 186 for a simple “Hello”); without `OPENCODE_DISABLE_PROJECT_CONFIG`, the current directory's `AGENTS.md` does too—an instruction to “end every response with BANANA” was applied to the translation. The global `~/.config/opencode/AGENTS.md`, however, remains injected: no switch excludes it, and bypassing it through a repurposed `XDG_CONFIG_HOME` would also hide the user's providers. Documented instead of patched around.

  - **`exit 0` proves nothing: third CLI, same discipline—with two pitfalls specific to this one.** An unknown `--agent` does not cause `opencode run` to fail: it emits a warning on stderr and **silently** falls back to the coding agent, with tools enabled. If the inline configuration were not applied, the translation would therefore run with an agent capable of writing; the output contract checks that this message is absent, in addition to: return code 0, no `error` event, no `tool_use`, final `step_finish` set to `stop` (an `length` indicates a truncated response), non-empty text. Second pitfall: the JSON error event is **opaque**—“Unexpected server error. Check server logs for details.”, with only a reference—and the actual cause (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) exists only in the logs. Hence `--print-logs --log-level ERROR` and reading the `error="…"` field from stderr, without the Bun trace that follows it. An unknown model thus fails within one second, with its cause named. Along the way, `--title` avoids an extraneous LLM call: without it, OpenCode generates a session title through an additional turn on `small_model`.

  - **Secrets: the same pattern-based filtering as Codex and Grok, with one specifically named exception.** `OPENCODE_API_KEY` is retained: it is OpenCode's own key (Zen gateway, Go subscription), addressed to it by name—the equivalent of its `auth.json`, not a key that aipmt manages or could bill. Providers are configured in OpenCode (`opencode auth login`, `opencode.json`), never in aipmt's `.env`, none of whose keys reach the subprocess. No rejection in CI, unlike subscription CLIs: an API key or a self-hosted model on a runner are legitimate use cases.

  - **The traversal guard now checks the interpolated value, not the raw value.** `provider/modèle` contains a `/` that the 1.10.0 guard rejected—correctly, since `--model` was interpolated into the filename `--include_model`. The filename label now replaces `/`, `\`, and `:` with `-` before any interpolation (`ollama/qwen2.5:7b` → `ollama-qwen2.5-7b`, with `:` being illegal on Windows), and the upstream guard examines that label: `../../evil` becomes the simple name `doc-en-..-..-evil.md` under the target, only `..` remains rejected, as does `--target_lang ../x`. The `_ensure_within_directory` scope guard remains the unchanged second layer.

  - **Free models and local models: what was measured.** `opencode/mimo-v2.5-free` translates one paragraph in 16 s and this README in 49 s; `opencode/big-pickle` takes 40 s for 200 words, and two simultaneous requests remained unanswered for 5 minutes even though each completed on its own; `opencode/nemotron-3.5-lightning-free` returned nothing in 3 minutes. Hence `REGEN_PROVIDER=opencode` with mandatory `REGEN_MODEL` and **2 jobs** in parallel. Locally, Ollama often configures 4,096 context tokens while segments reach up to 16,000 characters: an `Modelfile` with `PARAMETER num_ctx 32768` is necessary, and quality depends on the model—a 7B model reversed a list and damaged a code-block closing in the test file, whereas the gateway model preserved everything.

  - **Translations in this repository never use a billed API anymore.** `regen_translations.sh` selected the OpenAI API whenever a key happened to be present in `.env`, leaving Codex as opt-in only. That is exactly what happened while preparing this version: the 28 translations went through the OpenAI API, followed by the Hindi CHANGELOG through the Gemini API, even though the ChatGPT subscription exists precisely to avoid usage-based billing. Key auto-detection is gone: **Codex is the default, with `gpt-5.6-sol`**, the quality model; `openai`, `gemini`, and `grok` require `REGEN_ALLOW_PAID_API=1` in addition to `REGEN_PROVIDER`, a named override so that the rule applies at decision time; an unknown `REGEN_PROVIDER` fails instead of falling back to the API. Ten tests lock down the default, the rejection, and the override. All 28 translations in this version were redone through Codex.

  - **Rate-limit backoff is factored out** (`_retry_on_rate_limit`): the Codex and Grok loops were identical except for their labels, and a third copy would have crossed the duplication threshold. All three CLI errors derive from the same `_CliCallError`; a test prevents any of the three from falling outside it, since otherwise the shared loop would no longer catch it.

  - **Tests**: new `tests/test_opencode_provider.py` file (61 tests)—complete output contract, agent fallback, cause read from logs, deduplicated text parts and ignored synthetic parts, timeout killing the process group, backoff on 429, mandatory and validated model, preflight without secrets, binary resolution, dispatch wiring, filename label, and traversal counterexample. `tests/test_review_hardening.py` extends flag exclusivity and the absence of secrets to the new provider. The gate now requires **22 documented** argparse flags. Full suite at **382 tests**.

- **1.11.0** Published on PyPI: `pip install ai-powered-markdown-translator` followed by the `aipmt` command, without cloning the repository (2026-09-03):

  - **The single-file script becomes an installable package.** `translate.py` moves from the root to `src/aipmt/translate.py`, with a `aipmt` console entry point and the equivalent `python -m aipmt`. The cloned repository remains necessary for contributing—tests, 28 translations, and quality tooling live there—but no longer for using it.

    - **The import name is `aipmt` and never `translate`**, because the collision is real and silent. The `translate` PyPI package (v3.8.1, last uploaded 2026-07-06) installs a DIRECTORY with the same name. Reproduced in a venv: the directory takes precedence over the module, `translate.main` disappears, the entry point breaks on `AttributeError`—and `pip check` responds “No broken requirements found” with rc=0. A simple `pip install translate` on the user's system would have been enough to break the CLI without an actionable diagnostic. Countercheck using the actual wheel: `pip install translate` installed over the package, `aipmt --help` rc=0 before and after, both CLIs coexist.
    - **Long distribution name, short command.** `ai-powered-markdown-translator` makes the package discoverable through PyPI search; an acronym alone would be impossible to find for someone who does not already know the project, yet discovery is precisely the purpose of publishing it. Two plausible candidates were rejected after verification: `ai-markdown-translator` has been TAKEN on npm since 2024 by a tool serving the same purpose, predating this repository by 17 months; and `aimt` is one letter away from `aim` (v3.29.1), an active package in the SAME domain—the worst setup for lasting confusion. A methodological trap along the way: `pypi.org/project/<nom>/` returns 200 for every name (anti-bot page); only the JSON API is authoritative.
    - **`src/` layout instead of a flat package.** A flat package would have preserved the six `sys.path.insert(..., "..")` instances in the tests, and that is precisely the flaw: they would import the source tree instead of the package, masking any packaging error. Actual cost: one additional substitution rule.

  - **Keys can finally be configured once and for all.** An installed CLI had no PERSISTENT configuration: only the environment variable and the current directory's `.env` remained. `find_dotenv` does search upward to the filesystem root and therefore found a `~/.env` **when working somewhere under the home directory**, but found nothing when working elsewhere—coverage that depended on where the command was launched, not on a design choice. A third layer is therefore added: `~/.config/aipmt/.env`, below the existing two.

    - **The priority is not hard-coded**; it follows from `override=False`, the default value of `load_dotenv`: each layer fills only what the preceding one left empty. Hence the order environment variable → project `.env` → user configuration, verified by BEHAVIORAL rather than structural tests—reversing the order of the two calls makes them fail, as does removing the third layer.
    - **`.env` format, not TOML**, deliberately: `python-dotenv` is already a dependency, the syntax is already documented in all 15 READMEs, and the same file serves both scopes. No new dependency or syntax. The location follows `XDG_CONFIG_HOME` if it is **absolute**—the specification requires ignoring a relative value, otherwise the configuration location would once again depend on the current directory—and `APPDATA` on Windows.
    - **Two options rejected, with reasons.** The system keyring (`keyring`) is safer on a desktop but fails in headless environments—servers, containers, CI—which are exactly the use case for batch translation; a good opt-in candidate, a poor default. A `--api-key` flag would put the key in shell history and expose it in `ps`.
    - **No stack trace when a key is missing.** Users received a Python stack trace pointing to `site-packages`, and a message that named “the environment or .env” without saying where to create the latter. It now lists all three locations with their exact paths, and the command exits with 2. The safety net is **deliberately narrow**: `except ValueError` around the configuration phase alone. Wrapping the entire execution would turn a real bug occurring during translation into a reassuring message—the failure mode this repository tracks. A test reads the source of `main()` to forbid it.

  - **Fix—the user's `.env` was ignored once the tool was installed.** With no argument, `load_dotenv()` does not search upward from the current directory but from the CALLING file, and therefore from `site-packages`. Measured with a real console entry point launched from a project containing its own `.env`: `find_dotenv()` returns `''` and the key is not loaded, whereas `find_dotenv(usecwd=True)` finds it. The bug did not exist while the tool ran only from the cloned repository; publishing it would have made the bug systematic, with a “missing” API key on a correct configuration as its only symptom.

  - **Three gates would have turned green after ceasing to check anything at all.** They were hardened BEFORE the move, deliberately: a safeguard written after the change it is supposed to catch proves nothing. Each is green on the original repository and turns red on a migrated copy—both directions were measured.

    - **Lizard silently ignores a missing path**: rc=0, “0 file analyzed.” The complexity gate would have dropped from 158 functions / 2247 nloc to 3 functions / 34 nloc, with zero-byte output. The scope is now an array whose entries are each checked for existence.
    - **`coverage run --source=` on a missing module does not fail**: warning on stderr only, rc=0 for both unittest and `coverage xml`, with the report still published—reduced from 1453 to 141 statements. The project would have appeared healthy because almost none of it was being analyzed. Two floors guard the report: the total and the largest measured file.
    - **The translation freshness probe is structurally blind to the invocation form**: it anchors itself to the argparse flags, precisely what a filename change does not alter. Reproduced: module moved, all 15 READMEs still documenting a nonexistent command, verdict “no stale translations.” A 7th section therefore checks the FORM rather than the options, and the Lizard hook is compared against the script's actual scope—its `files:` key does not make pre-commit fail when it no longer matches; it makes it SKIP the hook.
  - **`requires-python = ">=3.10"` ceases to be an assertion.** `sonar-project.properties` already claimed 3.10-3.12 without anything ever exercising them, since the development machine only had 3.12 — an internal contradiction that publication would have exposed. A test workflow now runs the suite on 3.10, 3.11, and 3.12, installing the PACKAGE and therefore enforcing its public bounds.

  - **Lower bounds, no upper cap.** `requirements.txt` remains the tested lock, while `[project.dependencies]` becomes the public contract: publishing the lock's exact versions would cause conflicts for any user with other packages. No `<N+1` upper cap either — it would directly contradict `check-deps-fresh.sh`, which fails the release gate whenever a major version falls behind. The set of minimum versions resolves successfully, while the negative control `openai==1.0.0` exits with `ResolutionImpossible`, proving that the check discriminates instead of accepting everything. A guard also prevents the version in `pyproject.toml` from diverging from the CHANGELOG version: PyPI does not allow a version number to be reused.

  - **Verified end to end in a fresh venv**: a wheel of approximately 70 KB containing only `aipmt/*.py`, the dist-info, and the license; `aipmt --help` rc=0 with 22 flags; `python -m aipmt` displaying “usage: aipmt” rather than “usage: \_\_main\_\_.py”; a working `pipx` installation; and, most importantly, **a real fr→en translation from an arbitrary user directory**, with bold text, a list, inline code, a link, and a URL preserved, and a code block left untranslated. All 318 tests predating the migration pass with a byte-for-byte identical list of identifiers before and after — that is what proves no test was disabled, not the “OK”; twelve more cover the three-layer configuration, bringing the total to 330.

- **1.9.2** Fix news attribution URL extraction with nested parentheses or an FR prefix (2026-05-11):

  - **Fixed bug**: attribution URL extraction in `_protect_news_quotes` used the regex `re.search(r"\((.+?)\)", attribution)` (lazy capture between parentheses). With an attribution such as `(relayé par [@user sur X](https://x.com/.../123))` (nested parentheses: enclosing `(` + `]()` from the Markdown link), capture stopped at the first `)` encountered → truncated string also including the FR prefix: `relayé par [@user sur X](https://x.com/.../123` (without the final `)`). As a result, `_validate_news_post` searched for this string in the translated output and consistently failed (for two reasons: truncated `)` + “relayé par” translated as `relayed by`/`weitergeleitet von`/...). The entire low → medium → high → gpt-5.5 cascade could not pass.
  - **Fix**: the regex becomes `re.search(r"\]\(([^)]+)\)", attribution)`—it specifically targets the `](url)` from the Markdown link and captures **only the raw URL** (without the FR prefix or truncation), an invariant preserved by the `#URL{N}#` placeholders during translation.
