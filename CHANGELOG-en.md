- **1.16.3** End of file: an API translation preserves its source's final newline, and Mistral SDK 3.0 is validated (2026-10-04):

  - **An API translation preserves its source's final newline.** The API providers — OpenAI, Anthropic, Gemini, Mistral — strip surrounding whitespace from the model's response. On the last segment, this cleanup removed the source's final newline: a translated file without a translation note ended without a newline, which git reports and formatters correct on every run. This was noticed while validating Mistral SDK 3.0 on a guide ending with a newline whose translation no longer had one. The translation note restored one, and the command-line providers — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — copy the segment ending: only an API translation without a note was affected. The translation now reproduces the source's final newline, regardless of the provider, and adds none when the source does not have one.

  - **Mistral: SDK 3.0 validated through a real call.** `mistralai` 3.0.0 replaces the `httpx` HTTP library with `httpx2`; the imports and translation call remain unchanged. A fresh aipmt installation already received it because the dependencies have no upper version bound, but no real call had yet tested it: a Markdown guide translated through the Mistral API with SDK 3.0 retains a structure identical to the source. The development lockfiles now use this SDK, and the retry tests provide it with a `httpx2` client, the one it uses in production.

- **1.16.2** Code protection: code quoted in a blockquote `--news` and an indented block in a list no longer cause translation to be rejected for every language (2026-10-03):

  - **Code quoted in a blockquote no longer blocks translation.** In `--news` mode, aipmt protects inline code before setting aside English blockquotes, which are restored unchanged. Code placed in a blockquote therefore went with it: the model never saw its token, and validation declared it missing for every language. The author's daily news monitoring stopped there on October 2: a `/plugin enable …` command quoted in a tweet, the probe language rejected twice, and the other thirteen never started. Tokens carried away by a blockquote are now resolved in the text set aside. For an English target, the French translation line in a blockquote is no longer sent to the model: the instruction asked it to remove that line, and the code it contained was then counted as missing even though the model had complied. The published result does not change. Finally, restoring a blockquote no longer reinterprets its backslashes: a quoted `\n` remains a `\n`. Verified end to end on the article that had failed: English and German translated on the first attempt by `gpt-6.1-sol`, with a structure identical to the published versions.

  - **An indented code block in a list is protected.** CommonMark permits an indented block fence, and this is the normal case for a block documenting a numbered-list step: it belongs to the list item, so it is indented. Anchored at column 0, the protection pattern missed every such block: measured on a real README, it detected 8 blocks out of 14. The other six were sent to the model as prose, returned unchanged because they were commands, and the guard that rejects a translation copied verbatim rejected the file for every language, with a message that named the symptom but never the cause. The pattern now accepts an indented closing fence, and the round trip through protection and restoration returns the document unchanged, including indentation.

- **1.16.1** Internal links: the anchor token leaves the parentheses with the link, and a translated link is no longer silently duplicated (2026-09-27):

  - **An internal link no longer breaks unnoticed.** To protect a link to a section, `[texte](#ancre)`, aipmt replaced its parenthesized portion, including the parentheses, with a token: the model received brackets followed by a bare token, which looked like a broken link, and sometimes “fixed” it. Restoration then produced `[texte]((#ancre))`, a link leading nowhere, without any guard reporting it. The defect returned every time this repository's translations were regenerated — in Spanish, Korean, then Italian for 1.15.0, and in German for 1.16.0 — with every Gemini Flash model tested, and even with Claude Sonnet and Haiku. A Markdown link token now retains its parentheses: the model receives a valid link that it has no reason to repair, and restoration also accepts a token from which the model may have removed the parentheses. HTML anchors retain a bare token. Verified end to end with the most fragile model, `gemini-3.8-flash-low`, on a README containing a parenthesized link: without the fix, the README was rejected, three links were duplicated, and one segment was retried; with it, all three links remained intact, with no retry. Then on this README, in German, Japanese, and Hindi through `gemini-3.8-flash-medium`, and in German through Claude Code with `sonnet`: structure identical to the source, with all three internal links intact everywhere.

  - **Tests can no longer modify the repository that runs them.** When pushing from a linked worktree, git passes the variable identifying the repository to its hooks, and the pre-push hook runs the tests: a test's `git init`, intended for a temporary directory, reset the real repository, which was suddenly reported as having no working tree. Tests that invoke git now remove every `GIT_*` variable from their environment, and a regression test verifies this by using that variable to point to a decoy repository.

- **1.16.0** `--use_claude_code` provider: translate using the Claude Pro or Max subscription quota through the official `claude -p` CLI — no paid route, and every call proves it (2026-09-26):

  - **Eleventh route: the Claude subscription, without usage-based billing.** `--use_claude_code` drives the official Claude Code binary in `-p` mode, on the same foundation as Codex, Grok CLI, and Antigravity — isolated process group, safely stopped on timeout, Ctrl-C, or terminal closure. It must not be confused with `--use_claude`, Anthropic's usage-billed API. aipmt never reads the token.

  - **No paid route, verified at three levels.** The subprocess environment uses an allowlist: no API key, token, cloud provider, or marker from the Claude Code session in which aipmt might be launched — the session that wrote this provider exported fifteen of them. The preflight, without a model turn, requires `claude auth status` to report a subscription connection without a Console key, and `/usage` to produce the phrase confirming the subscription. Each call must then confirm it in its initialization event — `apiKeySource: none`, enforced environment received correctly, model from the requested family, no fast mode — and in its quota report: paid “extra usage” stops the translation immediately.

  - **The quota is shared with Claude Code sessions, and the provider conserves it.** Each call reports usage for the 5-hour and weekly windows; above 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), no additional segment is started. On the day this was written, the author's account had already used 98% of its weekly quota.

  - **None of the user's configuration gets in, and none of the session remains.** No tools, no personalization, user settings ignored, MCP servers and hooks disabled, private disposable working directory, and no transcript retained. Measured with canaries: without `CLAUDE_CODE_DISABLE_ATTACHMENTS`, a `@chemin` from the document became an attachment, and the model returned a read call instead of the translation; with it, nothing gets through. The `AGENTS.md`, `CLAUDE.md`, and hook canaries loaded or executed nothing.

  - **A segment beginning with `/` did not reach the model.** Under `--disable-slash-commands`, Claude Code responds to it itself with “… isn't available in this environment.” and `success` status, without any turn. A newline before the segment sends it to the model; the output contract rejects any response returned without a turn, with more than one turn, truncated, or from a model other than the one announced.

  - **Models: aliases, never a pinned identifier.** `sonnet` by default, at `low` effort, and also in `--eco` — so `--eco` changes nothing on this route —, `opus` and `haiku` through `--model`; `fable` and the `[1m]` variants are rejected because under `-p` they switch to paid credits without asking.

  - **Defects are measured, not assumed.** Using `aipmt --use_claude_code` itself, four translations in parallel, on the two documents used for the README measurements — the dense news-monitoring article, in `--news`, and this README at revision 1.14.0 —, with fourteen languages each. `sonnet`, at `low` effort, writes all 28 translations, 26 without discrepancies: one extra bold word in Chinese in the article, and in Arabic, in the README, one table row joined to the preceding one, which rendering conceals. Internal links remain intact, English blockquotes are copied unchanged, and in English the French translation lines are removed by the model without an invented flag; median time per language was 6 min 49 s for the article and 2 min 20 s for the README. `opus` translates the README without any discrepancy, one-quarter faster, but no article: its safeguards stopped the response in all fourteen languages on a short biology news item. `haiku` writes everything — three section headings promoted to level 1 in the article, and the English README's internal links duplicated — but twice as slowly as `sonnet`: it reasons without any way to prevent it, using 61% of its output tokens, and its lower price yields only a 14% saving in API-equivalent cost. Hence `sonnet` in `--eco` as well. Effort is useless for translation: on an earlier batch — this README and this CHANGELOG in English, Japanese, and Hindi — `sonnet` produced no reasoning tokens, while `opus` at medium effort used 1% of its output tokens for reasoning, and medium effort improved nothing over low effort, either in structure or duration. The `sonnet` campaign, covering 1.8 million source characters, consumed 9 percentage points of the 5-hour window and 2 of the weekly window on the author's Max subscription — an upper bound, since the session managing the measurements drew from the same quota.

  - **A rejection by Anthropic's safeguards is identified as such.** Opus 5.5 has stricter safeguards than Sonnet, and Anthropic's error message warns that they sometimes flag work resembling biological research. A short news item about 279 molecules generated for a binding site was enough. Claude Code then cuts off the response, retries once, and the model returns “I can't continue this translation” with a success status and no error, over two turns: only the single-turn contract stopped this response, with a message that said nothing about its cause. Sent alone, the news item is rejected by the API under the “bio” category. aipmt now recognizes these signs, names the safeguards and their category, does not retry — the same text would trigger the same rejection again — and recommends `--model sonnet`, which translated the news item into all fourteen languages.

  - **This repository's translations can use this route without an exemption.** `REGEN_PROVIDER=claude_code` is a subscription, not a usage-billed API: it works without `REGEN_ALLOW_PAID_API`, with four jobs — the campaigns ran four simultaneous translations without a single rate-limit or connection-lock error — after a single preflight that consumes no quota. The default remains Codex with `gpt-5.6-sol`.

  - **The terms of use, stated plainly.** The Claude Code legal page does not prevent a user from signing in to the unmodified binary with their own subscription; it prohibits third-party developers from routing requests through their users' Pro or Max credentials, and Anthropic prefers API keys for third-party tools, including open-source projects, while reserving the right to count their usage against paid credits. No text settles the case of a distributed tool that launches the official binary: the user puts their account at stake.

  - **Tests**: new `tests/test_claude_code_provider.py` file (58 tests), covering 100% of the module's statements and branches, without ever launching the real `claude` — cleared environment, nonexistent binary, `PATH` without `claude`, and test doubles that raise if called.

- **1.15.0** `--use_antigravity` provider: translate using the Google AI Pro or Ultra subscription quota through the official `agy` CLI; and, for all providers, Ctrl-C no longer leaves an agent running, a blank segment no longer causes the file to fail, and a project `.env` no longer selects the binary to execute (2026-09-26):

  - **Tenth provider route: the Google subscription, without usage-based billing.** Anyone paying for Google AI Pro or Ultra can now count translations against that quota instead of paying per token through the Gemini API. `agy`, Antigravity's official CLI, is the only route to this quota: Gemini CLI has not served Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK authenticates only through an API key or Google Cloud. `--use_antigravity` drives it in headless mode, like Codex and Grok CLI, on the same foundation — isolated process group, `SIGTERM` followed by `SIGKILL` on timeout, sanitized environment. Verified end to end on agy 1.2.11: a Markdown guide — front matter, bold text, a link containing parentheses, inline code, an indented code block in a list, a table, a blockquote — translated into English in 14 seconds including preflight, with a structure identical to the source and a translation note added; then, after the review fixes, into German in 19 seconds, with an identical structure and nothing written to `~/.gemini`.
  - **No paid path remains open, and every run verifies this.** agy supports paths other than the subscription—API key, Google Cloud project, gateway, paid AI credits—and several environment variables make it switch to them without displaying anything. Measured: `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, and `CLOUD_CODE_URL` redirects the authenticated endpoint to any address. The subprocess environment is therefore an allowlist, not a denylist: `PATH`, the language and time zone, the terminal, identity, the machine's proxies and certificates, and the session bus—which a `env -i` proved agy needs—with no keys whatsoever. A denylist based on prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), tried first, missed some: a review found endpoint overrides in the binary's strings that no prefix covered, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings are outside the environment and can only be read through `agy -p /config`: paid AI credits that take over when a quota is exhausted, and connection through a Google Cloud project. A preflight that consumes no quota—zero usage, measured—refuses to translate if either is active or if an API key is configured, and a setting absent from `/config` means refusal for each of the three: a version of agy that renamed one must not pass a check that verified nothing. Finally, the log for every call must attest to subscription authentication (`authMethod=consumer`), and any other authentication method appearing there, in either of the two spellings used by the binary, causes the response to be rejected: the call itself is authoritative, not the configuration that was prepared.

  - **The translation agent has no tools, and its loading is proven on every call.** Each call writes, in a disposable directory, an agent in agy's project-agent format: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. About 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone still allowed a workspace hook to execute its commands and inject its text. The real trap lies elsewhere: a missing agent does not cause agy to fail. Exit code 0, status `SUCCESS`, and the coding agent, with 57 active tools, responds—to “The cat is sleeping.”, it replied, “Shh, let's not wake it! 🐱💤 What can I do for you today?”. Nothing on stdout or stderr: only the call log reveals it. The response is therefore rejected if the log reports this fallback, and also if it lacks the positive marker showing that the agent was loaded—a change to the log format causes the translation to be rejected instead of silently removing the safeguard. Each marker must occupy an entire log line, in the measured format—severity, date, time, thread, file, and line: the binary also contains a line that copies the user's message into the log—never seen at the default log level across 78 real logs—and a document quoting these messages must not be able to satisfy the safeguard in agy's place.

  - **The user's agy settings and history remain untouched.** Each call runs with a private HOME, temporary directory, and working directory, all deleted afterward. agy still authenticates through the system keyring, which aipmt never reads. Nothing is inherited: neither the user's permissions—which allowed the default agent to run `ls` and `git` without asking—nor their global rules, plugins, MCP servers, hooks, and skills. And nothing is added to their history, where every call left a conversation of about 200 KB, including the translated text: the probe campaign had left about 95 conversations there and evicted 17 entries from a cache capped at 100. Verified: no files written to `~/.gemini/antigravity-cli`.

  - **Fail closed where isolation would not hold.** On Linux without a D-Bus session bus—SSH session, container, server—agy stores its token in a file under `~/.gemini` instead of the keyring, as its own changelog (1.1.3) states, and per-call isolation hides that file. The refusal now occurs before any launch, with the actual cause, instead of waiting a minute for a login code and then suggesting reconnection, which would solve nothing. On Windows, agy reads `USERPROFILE`, `APPDATA`, and `TEMP`, not `HOME` or `TMPDIR`—according to the Go documentation and the binary's strings: nothing there would isolate the call from the user's settings or history, and `--use_antigravity` is rejected there until this has been measured. macOS passes without having been measured; the billing safeguard, which reads the effective configuration, holds there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero exit code, a JSON object with status `SUCCESS`, a compliant log, no denied action, command, or error in the JSON, no truncation warning on stderr, and non-empty text. `--print-timeout` is never used: when it expires, agy returns partial output as `SUCCESS`, with code 0; the timeout is external and kills the process group. A segment beginning with `/commande`, `!commande`, or `@fichier` is translated, never executed or resolved—without `--disable-slash-commands`, “/help” was executed instead of translated. A blank segment no longer reaches agy, as the pipeline returns it unchanged (see below), and is still rejected before the call as a final safety net: with empty input, agy opens its interactive interface with code 0. Retries follow the `retryable` field of the `AGY_ERROR` line that agy has written to stderr since version 1.2.6: it already retries transient errors itself—502, 503, 504, per-minute limit—and it knows whether the remaining failure is still transient. Without this field, there is no retry when the message mentions exhaustion—at Google, `RESOURCE_EXHAUSTED` carries the same 429 code as a per-minute limit, but an exhausted five-hour window will not recover within 90 seconds—and otherwise only on rate limiting. The response preserves the segment's line ending: agy always ends its own response with a newline, which, at the join, split a paragraph segmented in the middle of a sentence into two. A disconnected session returns a message instructing the user to run `agy` to reconnect. Finally, `AGY_CLI_DISABLE_AUTO_UPDATE=true` prevents a fresh HOME from launching an update checker in its own session on every call, beyond the timeout's reach—the value `1`, meanwhile, has no effect.

  - **Models: reasoning effort is part of the name.** The identifiers are those from `agy models`—`gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… A base name alone, which agy would reject, is rejected before the call, with the available suffixes: `-medium` or `-low` for a Flash model, `-high` or `-low` for a Pro model. The defaults are `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`, established by the campaigns described below. `--reasoning_effort` has no effect and says so. Claude and GPT-OSS draw from a separate and much smaller quota—about 1% of the five-hour window per measured call, compared with 0.05% for Flash—and a warning points this out. The remaining quota can be read for free with `agy -p /usage`. Rejected in CI, like Codex and Grok CLI: the login resides in a personal keyring, and the message suggests `--use_gemini` with a Google key.

  - **Two campaigns on September 26: the defaults are measured, not assumed.** Using `aipmt --use_antigravity` itself, four translations in parallel, each compared with its source by `scripts/compare_structure.py`, with the quota read through `agy -p /usage` before and after. In the morning, on the revision of this README published with version 1.14.0 and on the dense monitoring article about the README's measurements, in `--news`, `gemini-3.7-flash-medium` produced the fourteen languages for both documents: the article with no discrepancies, a median of 3 min 14 s per language, and the README with only one bolded word differing, in Korean, in 1 min 22 s. In the afternoon, at the author's request, Gemini 3.8 Flash versus 3.7 on the same batch, this README and this CHANGELOG in their version 1.15.0: at medium effort, the same structure for both; 3.8 reasons as much as 3.7—63% of output tokens versus 60%, read from agy's JSON—and costs one-seventh more quota while taking one-quarter more time. Then the morning campaign, rerun with `gemini-3.8-flash-medium`: fourteen languages out of fourteen with no discrepancies on the article, a median of 3 min 59 s, and likewise on the README, 1 min 43 s; internal links intact in all fourteen READMEs, whereas 3.7 broke some in Italian; and in English, the French translation lines removed by the model, with no invented flag and English quotations intact. Hence the defaults: `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`. At low effort, neither Flash model reasons and each costs half as much, but 3.8 low duplicated all three internal links in a Hindi README, something 3.7 low did in none of the translations it produced. Measured cost on the author's account tier: 13 to 16 points from the five-hour window per million source characters with `gemini-3.8-flash-medium`—the rerun campaign, 28 translations and 1.8 million characters, consumed 24.5 points from the window and 4.1 from the weekly quota.

  - **The terms of use and data processing, stated plainly.** Antigravity's terms (section 6) and its FAQ prohibit accessing the service through third-party software using the Antigravity login—Claude Code, OpenClaw, and OpenCode are named—with account suspension as a possible consequence. aipmt never reads or reuses the token: it launches the official binary in the headless mode that Google documents for scripts and CI, and a Google team member described running `agy -p` from a local script for one's own work as “standard” on the official forum—a response, not a commitment. No text settles the case of a distributed tool: the README states that the user puts their account at risk. Section 5 of the same terms allows Google to use exchanges—prompts, responses, metadata—to improve its products and machine learning, and to have humans review them, without distinguishing the free offering from Pro and Ultra: the README reserves this path for public documents, and its final warning mentions this.

  - **Translations in this repository can use this path, without an exemption.** `REGEN_PROVIDER=antigravity` is a subscription, not a billed API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs—the entire campaign ran four in parallel without a single error—and Codex's 1,800-second limit per job, which the measurements justify: the entire CHANGELOG in Hindi, the file in which Codex loses placeholders, was translated without discrepancies in 4 min 33 s by 3.7 Flash in version 1.14.1, and in 5 min 50 s by 3.8 Flash in version 1.15.0, which was one-fifth longer: at least five times under the limit. A full regeneration, 2.2 million characters, is estimated at 30 to 36 points from the five-hour window with `gemini-3.8-flash-medium`. A single check, the module's preflight, precedes the 28 jobs: if agy is disconnected or configured for billing, none are launched. The default remains Codex with `gpt-5.6-sol`.

  - **An internal link was breaking without anything detecting it.** The token protecting an anchor absorbs its parentheses: the model receives a seemingly broken link, brackets followed by the bare token, and sometimes “repairs” it. Restoration then produces `[texte]((#ancre))`, which leads nowhere, without any safeguard or `compare_structure.py` reporting it. This happened in two READMEs from the first regeneration of this version, and with every model tested, more often when the link itself was in parentheses—the case of a link that this version had just added to this README. The publication check now counts the intact internal links in each translation, and this README no longer places any inside parentheses; the token itself still needs to be fixed.

  - **Ctrl-C and closing the terminal now stop the agent for all four CLIs.** Codex, Grok CLI, OpenCode, and Antigravity run in their own session, outside the foreground group: the `SIGINT` from Ctrl-C does not reach them, and, on Ctrl-C, `Popen` waits only a quarter of a second for them before returning control. Verified by the review using a fake binary: the agent outlived aipmt and completed its turn using quota, only for the result to be discarded—four at a time during regeneration. A `KeyboardInterrupt` or `SystemExit` during the call now kills the agent's group before propagating. Closing the terminal or disconnecting an SSH session (`SIGHUP`) killed Python without any cleanup: the agent continued, and Antigravity's private directory remained on disk with its log, which contains the account address. `SIGHUP` now follows the `SIGTERM` path: the agent's group is killed, then the process exits with 129. A `SIGHUP` ignored because the process was launched under `nohup` remains ignored: that is the user's choice. Antigravity's preflight—`agy --version`, then `agy -p /config`—uses the same handler: a signal received during this check stops agy and also deletes the private directory, instead of leaving it on disk with its log.

  - **The subprocess driver can no longer target the entire session.** On Linux, `killpg(1, sig)` equals `kill(-1, sig)`: the signal is sent to all of the user's processes. This happened while writing this version, during a mutation campaign: a mutant called a `Popen` double with a bare `MagicMock`, the resulting error went through the new interruption path, and the fake process's pid, which Python converts to 1, caused the entire graphical session to be killed. `_codex_kill_group`, shared by all four CLIs, now targets a group only if the pid is a genuine integer greater than 1, `getpgid` returns that same pid—an agent launched in its own session is its group leader—and it is not the current process's group; otherwise, only the direct child is targeted. In production, this safeguard changes nothing: it covers the case where a bug would return something else. The `Popen` doubles that must not be used now fail immediately, fake processes carry an impossible pid, and mutation campaigns run inside a PID namespace.

  - **A blank segment no longer causes the file to fail, regardless of the provider.** `segment_text` can isolate the blank end of a document: 16,001 characters ending with three newlines produce a second segment consisting of two newlines. Antigravity rejected it before the call—as reproduced by the review—and, with an API provider, an empty response triggered the empty-content safeguard: in both cases, the entire file failed after the quota for the preceding segments had been consumed. A blank segment is now returned unchanged, without a call.
  - **Security: a project `.env` can no longer choose the executable being run.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`, and `AGY_BIN` specify the program that the translation runs with the user's permissions: when set by the `.env` of a freshly cloned repository, they caused a file from that repository to be run during the very first translation. The `_BIN` suffix therefore joins `_BASE_URL`, `_API_BASE`, and `_ENDPOINT` in the project-layer filter, along with `GROK_HOME`, under which the Grok binary is searched for (`$GROK_HOME/bin/grok`). These variables remain accepted from the environment and from `~/.config/aipmt/.env`, and every rejection is reported on stderr with the location where they should be set.

  - **Tests**: new `tests/test_antigravity_provider.py` file (103 tests), covering 100% of the module's statements and branches—exact argv and never `-p`, segment through stdin, agent written without tools or inheritance, environment reduced to the allowlist, private directory deleted after success, failure, timeout, or signal, complete output contract, agent fallback and billing path read from log lines in the actual format, `AGY_ERROR` and `retryable`, strict billing preflight, rejection on Windows and without a session bus, effort suffixes, segment trailing newline preserved, dispatch wiring, and the regeneration branch. No test launches agy: a fake binary placed at the front of `PATH` was not called by any run, including under CI conditions, with the session bus hidden and `CI=true`. `tests/test_provider_base.py` interrupts a real subprocess with Ctrl-C and `SIGHUP`, including under `nohup`, and locks down the `killpg` safeguard—PID `MagicMock`, boolean, 1 or less, current group or another process's group: never a group signal; `tests/test_key_resolution.py` launches a fresh process for each `_BIN` variable; `tests/test_orchestration.py` translates a document whose blank ending forms a separate segment. Full suite at **650 tests**.

- **1.14.1** Mistral: exceeding the rate limit no longer causes the file to fail, and the default models are confirmed by measurement (2026-09-17):

  - **An HTTP 429 caused the entire file to be lost.** The `mistralai` SDK does not retry anything by default, unlike OpenAI's and Anthropic's, and Mistral's limits are low and specific to each model: 15 requests per minute for Large 3, 100,000 tokens per minute for Small 4, measured on the repository account. A run with four simultaneous translations on Small lost five out of eighty-four. The client now retries on 429, 5xx, and connection errors, with an increasing delay from 2 to 60 seconds for no more than five minutes: Mistral's 429 does not say how long to wait, and its limits are measured per minute. Verification against the API: twenty consecutive calls on Large 3, all twenty successful, with the sixteenth succeeding after a 33-second wait.
  - **A response containing reasoning blocks no longer breaks the translation.** Small 4 and Medium 3.5 reason when asked to, and the response then becomes a list of `thinking` followed by `text` blocks instead of a string. Neither reasons by default (as measured), but a provider-side default change would have ended in `AttributeError`: reasoning blocks are discarded, as they are for Claude.
  - **Default models confirmed: `mistral-large-latest` and `mistral-small-latest`.** The only newer model, Mistral Medium 3.5, was measured against them in all fourteen languages, on the dense monitoring article from the compatibility table and on the README. - **1.13.0** `--use_openrouter` provider: a paid router to ~430 models, including open Chinese models (2026-09-05):

  - **Ninth provider path, shipped with the eighth.** 1.12.0 was not published on PyPI: both routers, OpenCode and OpenRouter, are being released together. Since the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything that distinguishes this provider is contained in a preflight**, and each of its rules comes from an API measurement.

  - **The same model is served by dozens of hosts with different limits, and routing is blind to this.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash`—including one capped at **2,048 output tokens**. If no host meets the limit, the command stops: translating anyway would mean accepting the silent truncation that this preflight exists to prevent.

  - **Reasoning is billed at the output rate and is enabled by default on many models.** Same request on `z-ai/glm-5.2`, response “OK”: **107 completion tokens at the model's default, 2 with reasoning disabled**. For translation, where reasoning adds nothing, that is an 18-fold factor on every segment of every file. It is therefore disabled by default. The **288 models out of 431** that require it (`reasoning.mandatory`) respond with `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for them, the preflight reads the accepted effort levels and requests the lowest one (next bullet)—effort allocates a **percentage of `max_tokens`** that reasoning consumes first, so choosing an arbitrary value shifts the risk of a blank response instead of reducing it.

  - **A model that requires reasoning receives the lowest effort it accepts, and that decision is measurement-based.** The initial choice was to send nothing, to avoid guessing on behalf of the model. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this choice produced output **truncated at 32,768 tokens** before the translation finished—two languages out of fourteen were lost. Increasing the allowance would not have changed anything: effort allocates a percentage of it, so reasoning grows along with it. The provider therefore reads `supported_efforts` during preflight and requests the lowest level, falling back to “nothing” when the catalog lists no usable value. Counter-test on the failing language: it previously failed because the budget was exhausted; it now completes in 9 minutes with a structure identical to the source.

  - **Security: a project `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file from the current directory and its parents: an untrusted directory tree—a repository that has just been cloned—could place `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` there (the latter read by the SDK itself) without knowing any key, and the real key, coming from the environment or user configuration, would then be sent in the authorization header to a third-party server. The filter is based on a PATTERN rather than a list: across the installed SDKs, twelve routing variables are read, including six by the Anthropic client alone—a hand-written enumeration would have missed half of them. The project layer therefore rejects every variable matching `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, proxies and certificate stores (pointing to a controlled authority makes an interceptor indistinguishable from a real server), as well as `XDG_CONFIG_HOME` and `APPDATA`: setting them amounted to deciding which file constitutes the user layer, thus bypassing the filter indirectly. A segment that is too dense for the selected model is rejected before the call rather than after billing.

If the inline configuration were not honored, the translation would therefore run with an agent capable of writing; the output contract checks for the absence of this message, in addition to: return code 0, no `error` event, no `tool_use`, final `step_finish` in `stop` (a `length` is a truncated response), nonempty text. Second trap: the JSON error event is **opaque**—“Unexpected server error. No rejection in CI, unlike subscription CLIs: an API key or a self-hosted model on a runner are legitimate use cases.

- **1.9.2** Fix news attribution URL extraction with nested parentheses or an FR prefix (2026-05-11):
