- **1.17.0** Claude 5.5 via the API: Sonnet 5.5, which rejected disabled thinking, becomes usable for translation and the default model, Haiku 5.5 takes over `--eco` mode; Dependabot now also runs on weekends (2026-10-19):

  - **`--use_claude` works with Claude Sonnet 5.5, Opus 5.5, and Fable 5.1.** aipmt disabled Claude's thinking via `thinking: {"type": "disabled"}`, which these three models reject: HTTP 400 from the first segment, measured with a real call. aipmt now sends the lowest setting each model accepts, as reported in the capabilities published by Anthropic's API: `between_tools` for Sonnet 5.5, which disables its preliminary thinking, and no setting for Opus 5.5 and Fable 5.x, which are then free to think as they see fit. A still-unknown model tries, after the first rejection, settings from the most economical to the most permissive, then retains the one that works for subsequent segments—the logic already used for Gemini. Any other error is propagated unchanged. All four 5.x models are added to the context-window table, at one million tokens.

  - **Claude Sonnet 5.5 becomes the default model for `--use_claude`.** Measured by aipmt itself on the two documents used for the README benchmarks—the dense news-monitoring article, in `--news`, and this README at revision 1.14.0—across fourteen languages each: 28 translations out of 28 written with no structural discrepancy, no segment retried, internal links intact, English quotations copied unchanged and, in English, French translation lines removed by the model itself. Claude Sonnet 5 achieved 11 and 12 out of 14 via the API, on a longer revision of this README, and 13 and 13 via Claude Code. The price is unchanged: $2 and $10 per million input and output tokens, respectively, or $9.21 for all 28 translations.

  - **`--eco` switches to Claude Haiku 5.5, with thinking enabled.** Measured on the same documents: with thinking disabled, Haiku 5.5 leaves entire paragraphs in French, which the untranslated-excerpt guard rejects—9 translations written out of 28. With adaptive thinking, it writes 26, including 23 with no discrepancy; two READMEs, in Arabic and Hindi, are rejected because inline-code tokens were lost in the response. Claude Haiku 4.5, the previous default, measured via the API for the first time, writes all 28 but only 21 with no discrepancy: in the article, it promotes one heading to level 1 in seven languages and leaves it in French in Japanese, which no guard detects. Haiku 5.5 costs $0.57 for all 28 translations, versus $3.67, and is twice as fast; aipmt therefore lets it think.

  - **Dependabot runs every day, including weekends.** Configured with `daily`, it ran only Monday through Friday: a version whose three-day delay ended on a Friday, after the morning run, would wait until Monday, and the daily freshness check, calibrated for one run per day, would have declared it late on Sunday. On October 18, google-genai 2.30.1 escaped this by just 1 hour and 35 minutes. Dependabot now follows a daily cron schedule, and the test that aligns the check's delay with its schedule counts three days for `daily`: reverting to it without extending the delay makes the test fail.

  - **The split-purity checker is removed**, as planned since 1.13.0. It compared the package against the snapshot taken when it was split, and every code change had to declare its discrepancies there. Its most useful check remains: `check-release-ready.sh` rejects a Python module that git does not track, invisible to both hooks and CI.

  - **Two issues reported by SonarCloud are fixed**: the function that organizes code tokens in a quotation, `--news`, was too complex and has been split into two, and an exception test now calls only one function within its block.

  - **Dependencies updated since 1.16.3.** In the pinned versions, `anthropic` 1.13.0, `openai` 3.29.0, `google-genai` 2.30.0, `mistralai` 3.2.0, and `python-dotenv` 1.2.4, automatically merged by Dependabot; the release and SonarCloud analysis actions were upgraded manually. The two questions left open by automatic merging have now been settled: it works without additional permissions, and it triggers no push workflow—the daily `main` check takes its place.

- **1.16.3** End of file: an API translation preserves its source's final newline, and Mistral SDK 3.0 is validated (2026-10-04):

  - **An API translation preserves its source's final newline.** The API providers—OpenAI, Anthropic, Gemini, Mistral—strip surrounding whitespace from the model's response. On the final segment, this cleanup removed the source's final newline: a translated file without a translation note ended without a newline, which git flags and formatters fix on every run. This was observed while validating Mistral SDK 3.0 on a guide that ended with a newline whose translation no longer had one. The translation note restored one, and command-line providers—Codex, Grok CLI, Antigravity, Claude Code, OpenCode—copy the end of the segment: only API translations without a note were affected. Translation now reproduces the source's final newline, regardless of provider, and adds none when the source does not have one.

  - **Mistral: SDK 3.0 validated with a real call.** `mistralai` 3.0.0 replaces the `httpx` HTTP library with `httpx2`; the imports and translation call remain unchanged. A fresh aipmt installation already received it because the dependencies have no upper version bound, but no real call had yet tested it: a Markdown guide translated through the Mistral API with SDK 3.0 retains a structure identical to the source. The versions pinned for development move to this SDK, and retry tests provide it with a `httpx2` client, the one it uses in production.

- **1.16.2** Code protection: code quoted inside a quotation, `--news`, and an indented block within a list no longer cause translation to be rejected for every language (2026-10-03):

  - **Code quoted inside a quotation no longer blocks translation.** In `--news` mode, aipmt protects inline code before setting aside English quotations, which are restored unchanged. Code placed inside a quotation therefore left with it: the model never saw its token, and validation declared it lost, for every language. The author's daily news monitoring stopped there on October 2: a `/plugin enable …` command quoted in a tweet, the probe language rejected twice, and the other thirteen never started. Tokens carried away by a quotation are now resolved in the text that was set aside. For an English target, the French translation line of a quotation is no longer sent to the model: the instruction asked it to remove that line, and the code it contained was then counted as lost even though the model had complied. The published result does not change. Finally, restoring a quotation no longer reinterprets its backslashes: a quoted `\n` remains a `\n`. Verified end to end on the article that had failed: English and German translated on the first attempt by `gpt-6.1-sol`, with a structure identical to the published versions.

  - **An indented code block inside a list is protected.** CommonMark allows an indented block closing fence, and this is the normal case for a block documenting a numbered-list step: it belongs to the list item and is therefore indented. Anchored at column 0, the protection pattern missed all of them: measured on a real README, it detected 8 blocks out of 14. The other six were sent to the model as prose, returned unchanged because they were commands, and the guard that rejects a translation copied unchanged rejected the file for every language, with a message that identified the symptom but never the cause. The pattern now accepts an indented closing fence, and the round trip through protection and restoration reproduces the document exactly, including indentation.

- **1.16.1** Internal links: the anchor token leaves its parentheses on the link, and a translated link is no longer silently duplicated (2026-09-27):

  - **An internal link no longer breaks without anything noticing.** To protect a link to a section, `[texte](#ancre)`, aipmt replaced its parenthesized part, including the parentheses, with a token: the model received brackets followed by a bare token, a seemingly broken link, and would sometimes “fix” it. Restoration then produced `[texte]((#ancre))`, a link leading nowhere, without any guard reporting it. The issue recurred whenever this repository's translations were regenerated—in Spanish, Korean, and then Italian for 1.15.0, and in German for 1.16.0—with every Gemini Flash model tested, and even with Claude Sonnet and Haiku. A Markdown link's token now retains its parentheses: the model receives a valid link that it no longer has any reason to repair, and restoration also accepts a token whose parentheses it has removed. HTML anchors retain a bare token. Verified end to end with the most fragile model, `gemini-3.8-flash-low`, on a README where one link was inside parentheses: without the fix, the README was rejected, three links were duplicated, and one segment retried; with it, all three links remained intact, with no retry. Then on this README, in German, Japanese, and Hindi via `gemini-3.8-flash-medium`, and in German via Claude Code with `sonnet`: structure identical to the source, with all three internal links intact everywhere.

  - **Tests can no longer modify the repository that runs them.** When pushing from a linked worktree, git passes its hooks the variable that identifies the repository, and the pre-push hook runs the tests: a test's `git init`, intended for a temporary directory, reset the real repository, which was suddenly reported as having no working tree. Tests that invoke git now remove every `GIT_*` variable from their environment, and a regression test verifies this by using that variable to point to a decoy repository.

- **1.16.0** `--use_claude_code` provider: translate using the Claude Pro or Max subscription quota through the official `claude -p` CLI—no paid route, and every call proves it (2026-09-26):

  - **Eleventh route: the Claude subscription, without usage-based billing.** `--use_claude_code` drives the official Claude Code binary in `-p` mode, on the same foundation as Codex, Grok CLI, and Antigravity—a dedicated process group, safely stopped on timeout, Ctrl-C, or terminal closure. Not to be confused with `--use_claude`, Anthropic's usage-billed API. aipmt never reads the token.

  - **No paid route, verified at three levels.** The subprocess environment is an allowlist: no API key, token, cloud provider, or marker from the Claude Code session from which aipmt might be launched—the session that wrote this provider exported fifteen of them. The preflight, without a model turn, requires `claude auth status` to report a subscription login without a Console key, and `/usage` to provide the phrase confirming the subscription. Every call must then confirm it both in its initialization event—`apiKeySource: none`, forced environment correctly received, model from the requested family, no fast mode—and in its quota report: paid “extra usage” stops translation immediately.

  - **The quota is shared with Claude Code sessions, and the provider conserves it.** Every call reports usage for the five-hour and weekly windows; above 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), no additional segment is started. On the day this was written, the author's account had already used 98% of its weekly quota.

  - **None of the user's configuration enters, and nothing from the session remains.** No tools, no customization mode, user settings ignored, MCP servers and hooks disabled, private disposable working directory, no transcript retained. Measured using canaries: without `CLAUDE_CODE_DISABLE_ATTACHMENTS`, a `@chemin` in the document became an attachment, and the model returned a read call instead of the translation; with it, nothing gets through. The `AGENTS.md`, `CLAUDE.md`, and hook canaries loaded and executed nothing.

  - **A segment beginning with `/` did not reach the model.** Under `--disable-slash-commands`, Claude Code responds to it directly with “… isn't available in this environment.”, with status `success`, without any turn. A newline before the segment sends it to the model; the output contract rejects any response returned without a turn, after more than one turn, truncated, or from a model other than the one announced.

  - **Models: aliases, never a pinned identifier.** `sonnet` by default, at `low` effort, and in `--eco` as well—`--eco` therefore changes nothing on this route—`opus` and `haiku` via `--model`; `fable` and the `[1m]` variants are rejected because in `-p` they switch to paid credits without asking.

  - **Defaults are measured, not assumed.** By `aipmt --use_claude_code` itself, with four translations in parallel, on the two documents used for the README benchmarks—the dense news-monitoring article, in `--news`, and this README at revision 1.14.0—across fourteen languages each. `sonnet`, at `low` effort, writes all 28 translations, 26 with no discrepancy: one extra bold word in Chinese in the article and, in Arabic in the README, a table row joined to the preceding one, which rendering hides. Internal links intact, English quotations copied unchanged, and in English the French translation lines removed by the model, with no invented flag; a median of 6 min 49 s per language for the article and 2 min 20 s for the README. `opus` translates the README with no discrepancy, one quarter faster, but none of the articles: its safeguards stopped the response in all fourteen languages on a short biology item. `haiku` writes everything—three section headings promoted to level 1 in the article, internal links duplicated in the English README—but twice as slowly as `sonnet`: it reasons without any way to prevent it, using 61% of its output tokens, and its lower price yields only 14% savings in API-equivalent cost. Hence `sonnet` in `--eco` as well. Effort is useless for translation: in a preliminary batch—this README and this CHANGELOG in English, Japanese, and Hindi—`sonnet` produced no reasoning tokens, while `opus` at medium effort used 1% of its output tokens for reasoning, and medium effort gained nothing over low effort, either in structure or duration. The `sonnet` campaign, covering 1.8 million source characters, used 9 percentage points of the five-hour window and 2 of the weekly window on the author's Max subscription—an upper bound, since the session driving the benchmarks drew from the same quota.
  - **An Anthropic guardrail refusal is identified as such.** Opus 5.5 has stricter guardrails than Sonnet, and Anthropic's error message warns that they sometimes flag work resembling biological research. A monitoring brief about 279 molecules generated for a binding site was enough. Claude Code then cuts off the response, retries once, and the model returns “I can't continue this translation” with a success status and no error, across two turns: only the single-turn contract stopped that response, with a message that said nothing about its cause. Sent alone, the brief is rejected by the API under the “bio” category. aipmt now recognizes these signs, identifies the guardrails and their category, does not retry—the same text would trigger the same refusal again—and recommends `--model sonnet`, which translated the brief into all fourteen languages.

  - **This repository's translations can use this route, without an exception.** `REGEN_PROVIDER=claude_code` is a subscription, not a metered API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs—the campaigns ran four translations concurrently without a single rate-limit or connection-lock error—after a single preflight that consumes no quota. Codex remains the default with `gpt-5.6-sol`.

  - **The terms of use, stated plainly.** Claude Code's legal page does not prevent a user from signing in to the unmodified binary with their own subscription; it prohibits third-party developers from routing requests through their users' Pro or Max credentials, and Anthropic prefers an API key for third-party tools, including open-source projects, while reserving the right to charge their usage against paid credits. No document settles the case of a distributed tool that launches the official binary: the user puts their account at risk.

  - **Tests**: new file `tests/test_claude_code_provider.py` (58 tests), 100% of the module's statements and branches, without ever launching the real `claude`—empty environment, nonexistent binary, `PATH` without `claude`, test doubles that raise if called.

- **1.15.0** Provider `--use_antigravity`: translate against the Google AI Pro or Ultra subscription quota through the official `agy` CLI; and, for all providers, Ctrl-C no longer leaves an agent running, a blank segment no longer causes the file to fail, and a project `.env` no longer selects the executed binary (2026-09-26):

  - **Tenth provider route: the Google subscription, with no usage-based billing.** Anyone paying for Google AI Pro or Ultra can now deduct translations from that quota instead of paying per token through the Gemini API. `agy`, Antigravity's official CLI, is the only route to this quota: Gemini CLI has not served Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK authenticates only through an API key or Google Cloud. `--use_antigravity` drives it in headless mode, like Codex and Grok CLI, on the same foundation—a dedicated process group, `SIGTERM` followed by `SIGKILL` on timeout, sanitized environment. Verified end to end on agy 1.2.11: a Markdown guide—front matter, bold text, link containing parentheses, inline code, code block indented within a list, table, blockquote—translated into English in 14 seconds including preflight, with structure identical to the source and a translation note added; then, after the review fixes, into German in 19 seconds, with identical structure and nothing written to `~/.gemini`.

  - **No paid route remains open, and every invocation verifies this.** agy supports routes other than the subscription—API key, Google Cloud project, gateway, paid AI credits—and several environment variables silently switch it to them. As measured, `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, and `CLOUD_CODE_URL` redirects the authenticated endpoint to any address. The subprocess environment is therefore an allowlist, not a denylist: `PATH`, the language and time zone, terminal, identity, machine proxies and certificates, and session bus—which a `env -i` proved agy needs—with no keys whatsoever. A denylist based on prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), tried first, missed some: a review found endpoint overrides in the binary's strings that no prefix covered, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings escape the environment and can be read only through `agy -p /config`: paid AI credits that take over when a quota is exhausted, and signing in through a Google Cloud project. A preflight that consumes no quota—zero usage, as measured—refuses to translate if either is active or if an API key is configured, and a setting missing from `/config` counts as a refusal for each of the three: an agy version that renamed one must not pass a check that verified nothing. Finally, every call's log must attest to subscription authentication (`authMethod=consumer`), and any other authentication method appearing there, in either of the two spellings used by the binary, causes the response to be rejected: the call itself is authoritative, not the configuration that was prepared.

  - **The translation agent has no tools, and its loading is proven on every call.** Each call writes, in a disposable directory, an agent in agy's project-agent format: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. About 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone still allowed a workspace hook to execute its commands and inject its text. The real trap lies elsewhere: a missing agent does not cause agy to fail. Exit code 0, status `SUCCESS`, and the coding agent, with 57 active tools, responds—to “The cat is sleeping.”, it replied, “Shh, let's not wake it! 🐱💤 What can I do for you today?”. Nothing on stdout or stderr: only the call log reports it. The response is therefore rejected if the log reports this fallback, and also if it lacks the positive marker confirming that the agent was loaded—a change to the log format rejects the translation instead of silently removing the safeguard. Each marker must occupy an entire log line in the measured format—severity, date, time, thread, file, and line: the binary also contains a line that copies the user's message into the log—never observed at the default log level across 78 real logs—and a document quoting these messages must not be able to satisfy the safeguard in agy's place.

  - **The user's agy settings and history are left untouched.** Each call runs with a private HOME, temporary directory, and working directory, all deleted afterward. agy still authenticates through the system keyring, which aipmt never reads. Nothing is inherited: neither the user's permissions—which allowed the default agent to run `ls` and `git` without asking—nor their global rules, plugins, MCP servers, hooks, or skills. And nothing is added to their history, where each call left a conversation of about 200 KB, including the translated text: the probe campaign had left about 95 conversations there and evicted 17 entries from a cache capped at 100. Verified: no file written to `~/.gemini/antigravity-cli`.

  - **Fail closed where isolation would not hold.** On Linux without a D-Bus session bus—SSH session, container, server—agy stores its token in a file under `~/.gemini` instead of the keyring, as stated in its own changelog (1.1.3), and per-call isolation hides that file. The refusal now occurs before any launch, with its real cause, instead of a one-minute wait for a connection code followed by advice to sign in again that would solve nothing. On Windows, agy reads `USERPROFILE`, `APPDATA`, and `TEMP`, not `HOME` or `TMPDIR`—according to the Go documentation and the binary's strings: nothing there would isolate the call from the user's settings or history, and `--use_antigravity` is refused there until this is measured. macOS passes without having been measured; the billing safeguard, which reads the effective configuration, holds there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero exit code, a JSON object with status `SUCCESS`, a compliant log, no refused action, command, or error in the JSON, no truncation warning on stderr, and nonempty text. `--print-timeout` is never used: when it expires, agy returns partial output as `SUCCESS`, with exit code 0; the timeout is external and kills the process group. A segment beginning with `/commande`, `!commande`, or `@fichier` is translated, never executed or resolved—without `--disable-slash-commands`, “/help” was executed instead of translated. A blank segment no longer reaches agy, as the pipeline returns it unchanged (see below), and is still rejected before the call as a final safety net: with empty input, agy opens its interactive interface with exit code 0. Retrying follows the `retryable` field of the `AGY_ERROR` line that agy has written to stderr since version 1.2.6: it already retries transient errors itself—502, 503, 504, per-minute limit—and it knows whether the remaining failure is still transient. Without this field, there is no retry when the message mentions exhaustion—at Google, `RESOURCE_EXHAUSTED` has the same 429 code as a per-minute limit, but an exhausted five-hour window does not recover within 90 seconds—and otherwise only on rate limiting. The response preserves the segment's line ending: agy always ends its own response with a newline, which, at the join, split a paragraph segmented in the middle of a sentence across two lines. A disconnected session produces a message instructing the user to run `agy` to sign in again. Finally, `AGY_CLI_DISABLE_AUTO_UPDATE=true` prevents a fresh HOME from starting an update checker in its own session on every call, beyond the timeout's reach—the value `1`, however, has no effect.

  - **Models: reasoning effort is part of the name.** The identifiers are those from `agy models`—`gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… A base name alone, which agy would reject, is rejected before the call, along with the available suffixes: `-medium` or `-low` for a Flash model, `-high` or `-low` for a Pro model. The defaults are `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`, established by the campaigns described below. `--reasoning_effort` has no effect and says so. Claude and GPT-OSS draw from a separate, much smaller quota—about 1% of the five-hour window per measured call, compared with 0.05% for Flash—and a warning points this out. The remaining quota can be read for free through `agy -p /usage`. Refused in CI, like Codex and Grok CLI: the sign-in lives in a personal keyring, and the message suggests `--use_gemini` with a Google key.

  - **Two campaigns on September 26: the defaults are measured, not assumed.** Through `aipmt --use_antigravity` itself, four translations in parallel, each compared with its source by `scripts/compare_structure.py`, with the quota read through `agy -p /usage` before and after. In the morning, using the revision of this README published with 1.14.0 and the dense monitoring article about the README measurements, in `--news`, `gemini-3.7-flash-medium` produced all fourteen languages for both documents: the article with no discrepancy, at a median of 3 min 14 s per language, and the README with only a single bold word differing, in Korean, in 1 min 22 s. In the afternoon, at the author's request, Gemini 3.8 Flash versus 3.7 on the same batch, this README and this CHANGELOG in their 1.15.0 versions: at medium effort, identical structure for both; 3.8 reasons as much as 3.7—63% of output tokens versus 60%, read from agy's JSON—and costs one-seventh more quota while taking one-quarter more time. Then the morning campaign, rerun with `gemini-3.8-flash-medium`: fourteen languages out of fourteen with no discrepancy for the article, with a median of 3 min 59 s, and likewise for the README, at 1 min 43 s; internal links intact in all fourteen READMEs, whereas 3.7 broke some in Italian; and in English, the French translation lines removed by the model, without an invented flag, with English quotations intact. Hence the defaults: `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`. At low effort, neither Flash model reasons and each costs half as much, but 3.8 low duplicated all three internal links in a Hindi README, something 3.7 low did not do in any translation it produced. Measured cost on the author's account tier: 13 to 16 points of the five-hour window per million source characters with `gemini-3.8-flash-medium`—the rerun campaign, 28 translations and 1.8 million characters, used 24.5 points from that window and 4.1 from the weekly quota.

  - **The terms of use and data processing, stated plainly.** Antigravity's terms (Section 6) and its FAQ prohibit accessing the service through third-party software using an Antigravity sign-in—Claude Code, OpenClaw, and OpenCode are cited—with the risk of account suspension. aipmt never reads or reuses the token: it launches the official binary in the headless mode that Google documents for scripts and CI, and a Google team member described launching `agy -p` from a local script for one's own work as “standard” on the official forum—a reply, not a commitment. No document settles the case of a distributed tool: the README states that the user puts their account at risk. Section 5 of the same terms allows Google to use interactions—prompts, responses, metadata—to improve its products and machine learning, and to have humans review them, without distinguishing the free offering from Pro and Ultra: the README reserves this route for public documents, and its final warning mentions this.

  - **This repository's translations can use this route, without an exception.** `REGEN_PROVIDER=antigravity` is a subscription, not a metered API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs—the entire campaign ran four in parallel without a single error—and Codex's 1,800-second limit per job, which the measurement supports: the entire CHANGELOG in Hindi, the file in which Codex loses placeholders, was translated without discrepancy in 4 min 33 s by 3.7 Flash in its 1.14.1 version, and in 5 min 50 s by 3.8 Flash in its 1.15.0 version, which was one-fifth longer: at least five times below the limit. A complete regeneration, 2.2 million characters, is estimated at 30 to 36 points of the five-hour window with `gemini-3.8-flash-medium`. A single check, the module preflight, precedes the 28 jobs: a disconnected agy or one configured for billing launches none of them. Codex remains the default with `gpt-5.6-sol`.

  - **An internal link was breaking without anything detecting it.** The token protecting an anchor absorbs its parentheses: the model receives an apparently broken link, brackets followed by the bare token, and sometimes “repairs” it. Restoration then produces `[texte]((#ancre))`, which leads nowhere, without any safeguard or `compare_structure.py` reporting it. This happened in two READMEs from the first regeneration of this version, and with every model tested, more often when the link itself was in parentheses—the case of a link this version had just added to this README. The publication check now counts the intact internal links in every translation, and this README no longer places any inside parentheses; the token fix itself remains to be done.
  - **Ctrl-C and closing the terminal now stop the agent for all four CLIs.** Codex, Grok CLI, OpenCode, and Antigravity run in their own session, outside the foreground group: the `SIGINT` from a Ctrl-C does not reach them, and, on Ctrl-C, `Popen` waits only a quarter of a second for them before returning control. Verified by reviewing with a fake binary: the agent survived aipmt and completed its turn using the quota, producing a discarded result—four at a time under regen. A `KeyboardInterrupt` or a `SystemExit` during the call now kills the agent's group before propagating. Closing the terminal or disconnecting an SSH session (`SIGHUP`) killed Python without any cleanup: the agent kept running, and Antigravity's private directory remained on disk with its log, which contains the account address. `SIGHUP` now follows the `SIGTERM` path: the agent's group is killed, then the process exits with 129. A `SIGHUP` ignored because it was launched under `nohup` remains ignored: that is the user's choice. Antigravity's preflight—`agy --version`, then `agy -p /config`—uses the same handler: a signal received during this check stops agy and also deletes the private directory, instead of leaving it on disk with its log.

  - **The subprocess driver can no longer target the entire session.** On Linux, `killpg(1, sig)` equals `kill(-1, sig)`: the signal is sent to all of the user's processes. This happened while writing this release, during a mutation campaign: one mutant called a `Popen` doubled by a bare `MagicMock`, the resulting error went through the new interruption path, and the fake process's pid, which Python converts to 1, caused the entire graphical session to be killed. `_codex_kill_group`, shared by all four CLIs, now targets a group only if the pid is a genuine integer greater than 1, `getpgid` returns that same pid—an agent launched in its own session is the leader of its group—and it is not the current process's group; otherwise, only the direct child is targeted. In production, this safeguard changes nothing: it closes the case where a bug might propagate something else. Doubles of `Popen` that must not be used now fail immediately, fake processes carry an impossible pid, and mutation campaigns run in a PID namespace.

    - **Confinement: an acknowledged and documented asymmetry.** Whereas Codex runs in `--sandbox read-only`, Grok’s sandbox is unusable on many recent Linux machines for two independent system-level reasons that cannot be worked around without `sudo`: AppArmor has blocked unprivileged user namespaces since Ubuntu 24.04 (`bwrap: setting up uid map: Permission denied`, reproduced outside Grok), and the container-runtime socket deny-list fails when `/run/podman` is in `0700` (the resolver only catches `ErrorKind::NotFound`; EACCES becomes fatal). The central trap: a **built-in** profile that cannot be applied starts **unconfined without warning**. The script therefore requests no profile by default and never falls back silently — it warns on stderr. Protection relies on the CLI’s `--deny` rules, including the catch-all `*`, the only layer measured to be _fail-closed_ (a rule with an unknown prefix prevents startup). `GROK_TRANSLATE_SANDBOX=read-only` makes it possible to require the sandbox, in which case startup fails if the machine cannot honor it.
