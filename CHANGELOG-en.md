- **1.17.1** Grok CLI switches to Grok 4.7, the only model it still accepts; a transient Antigravity outage and a Grok token refresh no longer cost a file (2026-10-21):

  - **`--use_grok_cli` translates again, with Grok 4.7.** Since version 1.0.52, the Grok CLI rejects Grok 4.6 and Grok 4.5, aipmt's models for quality and `--eco` ("unknown model id"): every translation failed on the very first segment. On October 19, Grok 4.6 was still translating. Grok 4.7 becomes the default and, for lack of a second model on the subscription, `--eco` has no effect on this path. The xAI API still serves Grok 4.6 and Grok 4.3: `--use_grok` does not change. Replayed on the 1.17.0 test suite, a guide and a `--news` news brief whose English quote contains code: three translations out of three, with the same results as the other providers.

  - **Antigravity retries a transient service outage.** On October 20, agy returned "API error (attempt 2): UNAVAILABLE (code 503)" on the fourth segment of a CHANGELOG, after retrying once on its own. Nothing indicated the failure was retryable: aipmt abandoned the file after consuming the quota for the first three segments, even though a manual retry succeeded. Codes 502, 503, and 504, which agy already retries on its side, now retry the segment after 30 and then 60 seconds. An exhausted quota window remains an immediate failure, and when agy itself reports whether the failure is retryable, it decides.

  - **The Grok CLI preflight no longer mistakes a token refresh for a logout.** Before translating, aipmt checks the session with `grok models`, which consumes nothing. But the call that refreshes an expired token itself responds "You are not authenticated.", and the next one succeeds: aipmt advised reconnecting with `grok login` when simply retrying was enough. It now asks again five seconds later before concluding. Seen on October 19, reproduced on the 21st.

  - **The retry notice explains why.** Codex, Grok CLI, Antigravity, OpenCode, and Claude Code reported every retry as a "rate limit", including a 503: leading users to look for the cause on the quota side. The notice now quotes the error returned by the CLI.

  - **Dependencies.** In the pinned versions, `openai` received its minor update, and `certifi` the patch for a critical security advisory that removes emSign roots whose intermediate keys were compromised. An installation from PyPI was already getting the patched version.

- **1.17.0** Claude 5.5 via the API, Codex on GPT-6.1-Sol: Sonnet 5.5, which rejected disabled thinking, becomes translatable and becomes the default model, Haiku 5.5 takes `--eco` mode; Codex switches to GPT-6.1-Sol and no longer discards a segment it finishes after reconnecting; Dependabot also runs on weekends (2026-10-20):

  - **`--use_claude` translates with Claude Sonnet 5.5, Opus 5.5, and Fable 5.1.** aipmt disabled Claude's thinking via `thinking: {"type": "disabled"}`, which these three models reject: HTTP 400 on the very first segment, measured with a real call. aipmt now sends the lowest setting each model accepts, determined from the capabilities published by the Anthropic API: `between_tools` for Sonnet 5.5, which disables its preliminary thinking, and no setting for Opus 5.5 and Fable 5.x, which then think at their discretion. A previously unknown model tries, upon the first rejection, settings from the most frugal to the most permissive, then keeps the one that works for subsequent segments—the logic already used for Gemini. Any other error bubbles up as-is. All four 5.x models enter the context window table at one million tokens.

  - **Claude Sonnet 5.5 becomes the default model for `--use_claude`.** Measured by aipmt itself on the two documents from the README benchmarks—the dense tech watch article, in `--news`, and this README in revision 1.14.0—fourteen languages each: 28 translations out of 28 written with zero structural drift, no segment re-run, intact internal links, English quotes copied as-is, and, in English, the French translation lines removed by the model itself. Claude Sonnet 5 scored 11 and 12 out of 14 via the API on a longer revision of this README, and 13 and 13 via Claude Code. Pricing remains unchanged: $2 and $10 per million tokens input and output, or $9.21 for all 28 translations.

  - **`--eco` switches to Claude Haiku 5.5, thinking included.** Measured on the same documents: with thinking disabled, Haiku 5.5 leaves entire paragraphs in French, which the untranslated snippet guard rejects—9 translations written out of 28. With its adaptive thinking, it writes 26, 23 of them without drift; two READMEs are rejected, in Arabic and Hindi, with inline code lost in the return. Claude Haiku 4.5, the previous default, measured for the first time via the API, writes all 28 but only 21 without drift: on the article, it promotes a heading to level 1 in seven languages, and leaves it in French in Japanese, which no guard catches. Haiku 5.5 costs $0.57 for the 28 translations, compared to $3.67, and runs twice as fast; aipmt therefore lets it think.

  - **Codex no longer discards a segment it finishes after reconnecting.** When the server responds with a 429, `codex exec` reconnects on its own and reports each retry in its JSON stream with an event of type `error`, "Reconnecting... 2/5", before resuming the turn, which can succeed. aipmt took this first `error` for a failure and abandoned the file: three of the fourteen failures during a regeneration of this repository on October 19 carried this message. Only the end of the turn is now authoritative, `turn.completed` or `turn.failed`, as expected by the Codex 0.162.1 source code. The 429 that exhausted Codex's retries, which arrives only as plain text, is also recognized: aipmt waits, then retries the segment instead of losing the file. An exhausted subscription quota remains an immediate failure.

  - **`--use_codex` switches to GPT-6.1-Sol.** This is the first model in the catalog that Codex serves to a ChatGPT account, and aipmt still preferred GPT-5.6-Sol for it. Measured on October 19 on this CHANGELOG in German, one translation per model, launched at the same time: GPT-6.1-Sol in 527 seconds, segments ranging from 46 to 70 seconds, identical source structure; GPT-5.6-Sol in 906 seconds, served fitfully that evening, up to 211 seconds for a segment, and 429s as soon as four translations ran in parallel. The GPT-6 family no longer triggers the "unusual model" warning. GPT-5.6-Sol remains accessible via `--model gpt-5.6-sol`, and `--eco` keeps GPT-5.6-Luna.

  - **Dependabot runs every day, including weekends.** Set to `daily`, it only ran Monday through Friday: a release whose three-day delay expired on a Friday after the morning run waited until Monday, and the daily freshness check, calibrated for one run per day, would have flagged it overdue on Sunday. On October 18, google-genai 2.30.1 escaped this by 1 hour and 35 minutes. Dependabot now follows a daily cron schedule, and the test aligning the check's delay with its schedule counts three days for `daily`: reverting to it without extending the delay makes it fail.

  - **The splitting purity checker is removed**, as planned since 1.13.0. It compared the package against the snapshot taken at splitting, and every code change had to declare its deviations there. Its most useful check remains: `check-release-ready.sh` rejects an untracked Python module that git ignores, invisible to both hooks and CI.

  - **Two defects flagged by SonarCloud are fixed**: the function that packs code tokens in a `--news` quote, which was too complex, is split in two, and an exception test now calls only one function inside its block.

  - **Dependencies up to date since 1.16.3.** In the pinned versions, `anthropic`, `openai`, `google-genai`, `mistralai`, and `python-dotenv` received their minor and patch updates, submitted by Dependabot and merged automatically; the release and SonarCloud analysis actions were bumped manually. The two questions left open by auto-merge are settled: it works without extra permissions, and it triggers no push workflow—the daily check on `main` serves that purpose.

- **1.16.3** End of file: an API translation preserves its source's trailing newline, and Mistral SDK 3.0 is validated (2026-10-04):

  - **An API translation preserves its source's trailing newline.** API providers—OpenAI, Anthropic, Gemini, Mistral—strip surrounding whitespace from the model's response. On the final segment, this cleanup stripped the source's trailing newline: a translated file without a translation note ended without a newline, which git flags and formatters fix on every run. Spotted while validating Mistral SDK 3.0 on a guide ending with a newline whose translation no longer had one. The translation note added one back, and CLI providers—Codex, Grok CLI, Antigravity, Claude Code, OpenCode—copy the end of the segment: only an API translation without a note was affected. Translations now preserve the source's trailing newline across all providers, and do not add one to a source that lacks it.

  - **Mistral: SDK 3.0 validated with a real call.** `mistralai` 3.0.0 replaces the `httpx` HTTP library with `httpx2`; imports and the translation call remain unchanged. A fresh installation of aipmt already received it, as dependencies have no upper version cap, but no real call had tested it yet: a Markdown guide translated via the Mistral API using SDK 3.0 maintains an identical structure to the source. Development pinned versions move to this SDK, and retry tests supply it with an `httpx2` client, the one it uses in production.

- **1.16.2** Code protection: quoted code inside a `--news` blockquote and an indented code block inside a list no longer cause translation to be rejected across all languages (2026-10-03):

  - **Quoted code inside a blockquote no longer blocks translation.** In `--news` mode, aipmt protects inline code before setting aside English blockquotes, which are restored as-is. Code located within a quote was therefore removed along with it: the model never saw its token, and validation declared it lost for all languages. The author's daily news watch was halted by this on October 2: a `/plugin enable …` command quoted in a tweet caused the probe language to fail twice, and the other thirteen were never started. Tokens swept up by a blockquote are now resolved in the sidelined text. For English targets, the French translation line of a quote is no longer sent to the model: the prompt instructed it to remove it, and the code it contained was then counted as lost even though the model had complied. The published output remains unchanged. Finally, restoring a quote no longer reinterprets its backslashes: a quoted `\n` stays `\n`. Verified end-to-end on the article that failed: English and German translated on the first attempt with `gpt-6.1-sol`, structure identical to the published versions.

  - **An indented code block in a list is protected.** CommonMark allows an indented block fence, which is standard for a block documenting a numbered list step: it belongs to the list item, so it is indented. Anchored to column 0, the protection pattern missed all of them: measured on an actual README, 8 blocks spotted out of 14. The other six were sent to the model as prose, returned unchanged since they are commands, and the guard that rejects a word-for-word copied translation rejected the file for all languages, with an error message naming the symptom rather than the cause. The pattern now accepts an indented fence, and the round trip between protection and restoration reproduces the document identically, indentation included.

- **1.16.1** Internal links: the anchor token leaves parentheses to the link, and a translated link is no longer silently duplicated (2026-09-27):

  - **An internal link no longer breaks silently.** To protect a link to a section, `[texte](#ancre)`, aipmt replaced its parenthesized portion, parentheses included, with a token: the model received brackets followed by a bare token, an apparently broken link, and sometimes "fixed" it. Restoration then yielded `[texte]((#ancre))`, a link leading nowhere, without any guard catching it. The defect recurred with every regeneration of this repository's translations—in Spanish, Korean, then Italian for 1.15.0, in German for 1.16.0—with every Gemini Flash tested, and even with Claude Sonnet and Haiku. The token for a Markdown link now retains its parentheses: the model receives a valid link that it has no reason to fix, and restoration also accepts a token from which it might have stripped the parentheses. HTML anchors retain a bare token. Verified end-to-end with the most fragile model, `gemini-3.8-flash-low`, on a README where a link was in parentheses: without the fix, README rejected, three duplicated links, and one re-run segment; with it, three intact links out of three, no retries. Then on this README, in German, Japanese, and Hindi via `gemini-3.8-flash-medium`, and in German via Claude Code with `sonnet`: identical structure to the source, all three internal links intact everywhere.

  - **Tests can no longer alter the repository that runs them.** When pushed from a linked worktree, git passes the variable pointing to the repository to its hooks, and the pre-push hook runs the tests: a test's `git init`, intended for a temporary directory, reset the real repository, suddenly reported as having no working tree. Tests running git now strip any `GIT_*` variable from their environment, and a regression test pointing this variable to a decoy repository verifies this.

- **1.16.0** `--use_claude_code` provider: translate using Claude Pro or Max subscription quota via the official `claude -p` CLI—no pay-per-use path, and each call proves it (2026-09-26):

  - **Eleventh path: the Claude subscription, without pay-per-use billing.** `--use_claude_code` drives the official Claude Code binary in `-p` mode, on the same foundation as Codex, Grok CLI, and Antigravity—dedicated process group, safe shutdown on timeout, Ctrl-C, or terminal closure. Not to be confused with `--use_claude`, the pay-per-use Anthropic API. aipmt never reads the token.

  - **No paid path, verified at three levels.** The subprocess environment is an allowlist: no API key, no token, no cloud provider, no marker of the Claude Code session from which aipmt would be launched—the one that wrote this provider exported fifteen. The preflight, without a model turn, requires from `claude auth status` the subscription connection without a Console key, and from `/usage` the phrase certifying the subscription. Each call must then certify it in its initialization event—`apiKeySource: none`, forced environment successfully received, model of the requested family, no fast mode—and in its quota report: paid "extra usage" stops translation immediately.

  - **The quota is shared with Claude Code sessions, and the provider spares it.** Each call reports usage for the 5-hour and weekly windows; beyond 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), no further segment is launched. On the day of writing, the author's account week was already at 98%.

  - **Nothing from the user's configuration enters, nothing from the session remains.** No tools, in no-customization mode, user settings ignored, MCP servers and hooks disabled, private and disposable working directory, no transcript kept. Measured with canaries: without `CLAUDE_CODE_DISABLE_ATTACHMENTS`, a `@chemin` in the document became an attachment, and the model returned a read call instead of the translation; with it, nothing gets through. The `AGENTS.md`, `CLAUDE.md`, and hook canaries loaded and executed nothing.

  - **A segment starting with `/` did not reach the model.** Under `--disable-slash-commands`, Claude Code answers it itself with "… isn't available in this environment.", in `success` status, without any turns. A newline in front of the segment sends it to the model; the output contract rejects anyway any response returned without a turn, in more than one turn, truncated, or by a model other than the announced one.

  - **Models: aliases, never a hardcoded identifier.** `sonnet` by default, at `low` effort, and in `--eco` too—`--eco` therefore changes nothing on this path—, `opus` and `haiku` via `--model`; `fable` and the `[1m]` variants are rejected, because in `-p` they switch to paid credits without asking.

  - **Defects are measured, not assumed.** Using `aipmt --use_claude_code` itself, four parallel translations, on the two measurement documents of the README—the dense intelligence article, in `--news`, and this README in its 1.14.0 revision—fourteen languages each. `sonnet`, at `low` effort, writes all 28 translations, 26 without discrepancy: one extra bold word in Chinese on the article, and in Arabic, on the README, a table row joined to the previous one, which display masks. Internal links intact, English quotes copied as-is, and in English, the French translation lines removed by the model, without invented flags; 6 min 49 s median per language on the article, 2 min 20 s on the README. `opus` translates the README without any discrepancy, a quarter faster, but no articles: its guardrails stopped the response across all fourteen languages, on a biology brief. `haiku` writes everything—three section headings turned into level 1 on the article, internal links in the English README duplicated—but twice as slowly as `sonnet`: it reasons without any way to prevent it, 61% of its output tokens, and its lower price yields only 14% savings in API equivalent. Hence `sonnet` in `--eco` as well. Effort is useless for translating: on a preliminary batch—this README and this CHANGELOG in English, Japanese, and Hindi—`sonnet` produced zero reasoning tokens, `opus` at medium effort 1% of its output tokens, and medium effort gained nothing over low, neither in structure nor in duration. The `sonnet` campaign, 1.8 million source characters, took 9 points of the 5-hour window and 2 of the weekly window on the author's Max subscription—an upper bound: the session running the measurements drew from the same quota.

  - **A refusal by Anthropic's guardrails is identified as such.** Opus 5.5 has stricter guardrails than Sonnet, and Anthropic's error message warns that they sometimes flag work close to biological research. An intelligence brief on 279 molecules generated for a binding site was enough. Claude Code then cuts off the response, retries once, and the model returns "I can't continue this translation" with a success status, without errors, over two turns: only the single-turn contract stopped this response, with a message silent about its cause. Sent alone, the brief is rejected by the API under the "bio" category. aipmt now recognizes these signs, identifies the guardrails and their category, does not retry—the same text would trigger the same refusal again—and recommends `--model sonnet`, which translated the brief into all fourteen languages.

  - **Translations for this repository can go through this path, without an exemption.** `REGEN_PROVIDER=claude_code` is a subscription, not a billed API: it passes without `REGEN_ALLOW_PAID_API`, with four jobs—the campaigns ran four concurrent translations without a single rate error or connection lock—after a single preflight that consumes no quota. The default remains Codex with `gpt-5.6-sol`.

  - **Terms of service, stated plainly.** Claude Code's legal page does not prevent a user from connecting to the unmodified binary with their own subscription; it forbids third-party developers from routing requests through their users' Pro or Max credentials, and Anthropic prefers API keys for third-party tools, open-source projects included, reserving the right to charge their usage against paid credits. No text settles the case of a distributed tool launching the official binary: the user commits their own account.

  - **Tests**: new file `tests/test_claude_code_provider.py` (58 tests), 100% of statements and branches in the module, without ever running the real `claude`—cleared environment, nonexistent binary, `PATH` without `claude`, test doubles that raise if called.

- **1.15.0** Provider `--use_antigravity`: translate on Google AI Pro or Ultra subscription quota, via the official CLI `agy`; and, for all providers, Ctrl-C no longer abandons an in-flight agent, a whitespace segment no longer fails the file, a project `.env` no longer selects the executed binary (2026-09-26):

  - **Tenth provider path: the Google subscription, without pay-as-you-go billing.** Anyone paying for Google AI Pro or Ultra can now charge their translations against it instead of paying per token on the Gemini API. `agy`, Antigravity's official CLI, is the only path to this quota: Gemini CLI no longer serves Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK authenticates only via an API key or Google Cloud. `--use_antigravity` drives it in headless mode, like Codex and Grok CLI, on the same foundation—dedicated process group, `SIGTERM` then `SIGKILL` upon timeout, sanitized environment. Verified end-to-end on agy 1.2.11: a Markdown guide—front matter, bold, parenthesized link, inline code, indented code block in a list, table, blockquote—translated into English in 14 seconds, preflight included, structure identical to source, translation note added; then, after review fixes, into German in 19 seconds, identical structure, nothing written to `~/.gemini`.

  - **No paid path remains open, and every launch verifies it.** agy knows paths other than the subscription—API key, Google Cloud project, gateway, paid AI credits—and several environment variables switch it over without displaying anything. Measured: `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, `CLOUD_CODE_URL` hijacks the authenticated endpoint to any address. The subprocess environment is therefore an allowlist and not a denylist: `PATH`, language and timezone, terminal, identity, machine proxies and certificates, and the session bus—what a `env -i` proved agy needs—without any keys. A denylist by prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`...), tried first, missed some: a review found in the binary's strings endpoint overrides that no prefix covered, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings escape the environment and can only be read via `agy -p /config`: paid AI credits taking over when quota is exhausted, and logging in via a Google Cloud project. A preflight that consumes no quota—zero usage, measured—refuses to translate if either of them is active or if an API key is configured, and a missing setting in `/config` counts as a refusal for each of the three: an agy version renaming one must not pass a check that verified nothing. Finally, each call's log must certify authentication via subscription (`authMethod=consumer`), and any other authentication method appearing there, under either spelling used by the binary, causes the response to be rejected: the call itself is authoritative, not the prepared configuration.

  - **The translation agent has no tools, and its loading is proven on every call.** Each call writes, in a disposable directory, an agent in agy's project agent format: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. About 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone let a workspace hook execute its commands and inject its text. The real trap lies elsewhere: a missing agent does not make agy fail. Return code 0, status `SUCCESS`, and it is the coding agent, 57 active tools, that replies—to "The cat is sleeping.", it replied "Shh, let's not wake him! 🐱💤 What can I do for you today?". Nothing on stdout or stderr: only the call log says so. The response is therefore rejected if the log reports this fallback, and also if it lacks the positive marker of the agent loading—an evolution in the log format causes the translation to be rejected instead of silently dropping the guard. Each marker must occupy an entire line of the log, in the measured format—severity, date, time, thread, file, and line: the binary also contains a line that copies the user message into the log—never seen at the default log level across 78 real logs—and a document quoting these messages must not be able to satisfy the guard in place of agy.

  - **The user's agy settings and history are untouched.** Each call runs with a private HOME, temporary directory, and working directory, deleted afterwards. agy still authenticates via the system keychain, which aipmt never reads. Nothing is inherited: neither the user's permissions—which let the default agent run `ls` and `git` without asking—nor their global rules, plugins, MCP servers, hooks, and skills. And nothing is added to their history, where each call left a conversation of about 200 KB, including translated text: the probe campaign had left about 95 conversations there and evicted 17 entries from a cache capped at 100. Verified: no file written to `~/.gemini/antigravity-cli`.

  - **Fail-closed refusal where isolation would not hold.** On Linux without a D-Bus session bus—SSH session, container, server—agy stores its token in a file in `~/.gemini` instead of the keychain, as announced by its own changelog (1.1.3), and each call's isolation hides this file. The refusal now occurs before any launch, with its actual cause, instead of a one-minute wait for a login code followed by reconnection advice that would resolve nothing. On Windows, agy reads `USERPROFILE`, `APPDATA`, and `TEMP`, not `HOME` or `TMPDIR`—according to Go documentation and binary strings—: nothing would isolate the call from the user's settings or history there, and `--use_antigravity` is rejected there until measured. macOS passes without having been measured; the billing guard, which reads the effective configuration, holds up there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero exit code, a JSON object with status `SUCCESS`, a compliant log, no rejected actions, no commands, no errors in the JSON, no truncation warnings on stderr, and non-empty text. `--print-timeout` is never used: upon expiration, agy returns partial output with `SUCCESS`, exit code 0; the timeout is external and kills the process group. A segment starting with `/commande`, `!commande`, or `@fichier` is translated, never executed or resolved—without `--disable-slash-commands`, "/help" executed instead of translating. A whitespace segment no longer reaches agy, as the pipeline returns it as-is (see below), and remains rejected before the call as a last safety net: on empty input, agy opens its interactive interface with exit code 0. Retries follow the `retryable` field of the `AGY_ERROR` line that agy has written to stderr since 1.2.6: it already retries transient errors itself—502, 503, 504, per-minute limit—and knows whether the remaining failure is still transient. In the absence of this field, no retry when the message mentions exhaustion—at Google, `RESOURCE_EXHAUSTED` carries the same 429 code as a per-minute limit, but an exhausted 5-hour window does not return in 90 seconds—and otherwise on rate limiting only. The response preserves the segment's line ending: agy always terminates its response with a newline, which, at the join, split in two a paragraph broken mid-sentence. A logged-out session produces a message telling the user to run `agy` to log back in. Finally, `AGY_CLI_DISABLE_AUTO_UPDATE=true` prevents a fresh HOME from spawning an update checker in its own session on every call, out of reach of the timeout—the value `1`, for its part, has no effect.

  - **Models: reasoning effort is part of the name.** The identifiers are those of `agy models`—`gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`... A bare base name alone, which agy would reject, is rejected before the call, listing existing suffixes: `-medium` or `-low` for a Flash, `-high` or `-low` for a Pro. By default `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`, set by the campaigns described below. `--reasoning_effort` has no effect and states so. Claude and GPT-OSS draw from a separate and much smaller quota—about 1% of the 5-hour window per measured call, compared to 0.05% with Flash—and a warning points this out. Remaining quota can be read for free with `agy -p /usage`. Rejected in CI, like Codex and Grok CLI: the login lives in a personal keychain, and the message suggests `--use_gemini` with a Google key.

  - **Two campaigns on September 26: defaults are measured, not assumed.** Via `aipmt --use_antigravity` itself, four parallel translations, each compared to its source by `scripts/compare_structure.py`, the quota read by `agy -p /usage` before and after. In the morning, on the revision of this README published with 1.14.0 and on the dense monitoring article of the README measurements, in `--news`, `gemini-3.7-flash-medium` writes the fourteen languages of both documents: the article with zero discrepancies, 3 min 14 s per language median, and the README within one bold word in Korean, in 1 min 22 s. In the afternoon, at the author's request, Gemini 3.8 Flash against 3.7 on the same batch, this README and this CHANGELOG in their 1.15.0 version: at medium effort, same structure for both; 3.8 reasons as much as 3.7 — 63% of output tokens versus 60%, read from agy's JSON — and costs one-seventh more quota, for one-fourth more time. Then the morning campaign, replayed in `gemini-3.8-flash-medium`: fourteen languages out of fourteen without discrepancy on the article, 3 min 59 s median, as on the README, 1 min 43 s; internal links intact in the fourteen READMEs, where 3.7 broke some in Italian; and in English, the French translation lines removed by the model, without invented flags, English quotes intact. Hence the defaults: `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` in `--eco`. At low effort, neither Flash model reasons and each costs half as much, but 3.8 low duplicated in Hindi the three internal links of a README, which 3.7 low did not do in any of the translations it wrote. Measured cost on the author's account tier: 13 to 16 points of the 5-hour window per million source characters in `gemini-3.8-flash-medium` — the replayed campaign, 28 translations and 1.8 million characters, took 24.5 of it, and 4.1 of the week.

  - **Terms of service and data processing, plainly stated.** Antigravity's terms (section 6) and its FAQ prohibit accessing the service via third-party software using the Antigravity login — Claude Code, OpenClaw, and OpenCode are cited there —, under penalty of account suspension. aipmt never reads or reuses the token: it launches the official binary in the headless mode that Google documents for scripts and CI, and a Google member deemed it "standard", on the official forum, to launch `agy -p` from a local script for their own work — an answer, not a commitment. - **1.13.0** Provider `--use_openrouter`: a paid router to ~430 models, including open Chinese models (2026-09-05):

  - **Ninth provider pathway, delivered with the eighth.** 1.12.0 was not published on PyPI: both routers, OpenCode and OpenRouter, are released together. Since the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything distinguishing this provider lies in a preflight**, and every one of its rules stems from an API measurement.

  - **The same model is served by dozens of hosters with different limits, and routing is blind to this.** Measured: 33 hosters for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash` — including one capped at **2,048 output tokens**. One out of 23 long translations was thus returned truncated, at random, without the slightest warning. If no hoster meets the limit, the command stops: proceeding with the translation would mean accepting the silent truncation that this preflight exists to prevent.

  - **Reasoning is billed at the output rate, and active by default on many models.** Same query on `z-ai/glm-5.2`, “OK” response: **107 completion tokens at the model default, 2 with reasoning disabled**. The **288 out of 431 models** that require it (`reasoning.mandatory`) return `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for these, the preflight reads the accepted effort levels and requests the lowest one (next bullet) — effort allocates a **percentage of `max_tokens`** that reasoning consumes first, meaning a randomly chosen value shifts the blank page risk instead of reducing it.

The filter operates on a PATTERN and not on a list: surveyed across installed SDKs, twelve routing variables are read, six of which by the Anthropic client alone — a hand-written enumeration would have missed half of them. Therefore, any variable matching `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, proxies, and certificate stores (pointing to a controlled authority makes an interceptor indistinguishable from a real server), as well as `XDG_CONFIG_HOME` and `APPDATA`, are rejected from the project layer: setting them amounted to deciding which file constitutes the user layer, thus bypassing the filter through the back door. These variables are accepted only from the two layers controlled by the user: the exported environment and `~/.config/aipmt/.env`. The project layer is also read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` copied the real key under a name that subprocess pattern filtering does not recognize — it would then enter the environment of `codex exec`, violating the stated invariant. Finally, rejection displays only the variable name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into the logs, even though it was being rejected. A rejection is reported on stderr with the steps to follow — a corporate relay is declared in the user configuration.
  - **Fix: the OpenRouter output envelope is calculated for each call.** `context_length` covers input AND completion, and a fixed reserve calibrated for Latin text bounds nothing: measured with the `o200k_base` tokenizer, 16,000 characters equal 3,200 tokens in French, but 12,300 in Japanese and 17,500 in emoji. The budget is therefore derived from the text actually sent, bounded above by its UTF-8 byte count: for any byte-pair encoding / byte-level tokenizer — byte-level BPE, SentencePiece with byte fallback, the families used by the catalog — one token equals at least one byte, and this is the only upper bound available here, where OpenRouter routes to dozens of unknown tokenizers. No average ratio was adequate — a supplementary plane ideogram drops to 1.33 bytes per token, a combining character to 1.00 —, and input plus output now fit within the window by construction. A segment that is too dense for the chosen model is rejected before the call rather than after billing.
