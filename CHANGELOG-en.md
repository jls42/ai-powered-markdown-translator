- **1.15.0** Provider `--use_antigravity`: translate on the Google AI Pro or Ultra subscription quota, via the official `agy` CLI; and, for all providers, Ctrl-C no longer leaves an in-flight agent behind, a blank segment no longer fails the file, and a project `.env` no longer chooses the executed binary (2026-09-26):

  - **Tenth provider path: the Google subscription, without pay-as-you-go billing.** Anyone paying for Google AI Pro or Ultra can now draw their translations against it instead of paying per token on the Gemini API. `agy`, the official Antigravity CLI, is the only route to this quota: Gemini CLI no longer serves Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK only authenticates via an API key or Google Cloud. `--use_antigravity` drives it in headless mode, like Codex and Grok CLI, on the same foundation—clean process group, `SIGTERM` then `SIGKILL` on timeout, sanitized environment. Verified end-to-end on agy 1.2.11: a Markdown guide—front matter, bold, parenthesized link, inline code, indented code block in a list, table, blockquote—translated into English in 14 seconds, including preflight, identical structure to source, translation note added; then, after review fixes, into German in 19 seconds, identical structure, nothing written to `~/.gemini`.

  - **No paid route remains open, and every launch checks this.** agy knows routes other than the subscription—API key, Google Cloud project, proxy, paid AI credits—and several environment variables switch it over without displaying anything. Measured: `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, `CLOUD_CODE_URL` hijacks the authenticated endpoint to any address. The subprocess environment is therefore an allowlist, not a denylist: `PATH`, language and timezone, terminal, identity, machine proxies and certificates, and the session bus—what a `env -i` proved agy needs—without any keys. A denylist by prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), tried first, missed some: a review found endpoint overrides in the binary strings that no prefix covered, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings bypass the environment and can only be read via `agy -p /config`: paid AI credits taking over when quota is exhausted, and logging in via a Google Cloud project. A preflight that consumes zero quota—zero usage, measured—refuses to translate if either of them is active or if an API key is configured, and a setting missing from `/config` counts as a refusal for each of the three: an agy version renaming one must not pass a check that verified nothing. Finally, the log of each call must certify authentication via the subscription (`authMethod=consumer`), and any other authentication method appearing there, under either of the two spellings the binary uses, causes the response to be rejected: the call itself is authoritative, not the configuration that was prepared.

  - **The translation agent has no tools, and its loading is verified on every call.** Each call writes, in a disposable directory, an agent matching the format of agy project agents: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Around 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone allowed a workspace hook to execute its commands and inject its text. The real pitfall lies elsewhere: a missing agent does not cause agy to fail. Exit code 0, status `SUCCESS`, and the coding agent, with 57 active tools, responds—to "The cat is sleeping.", it replied "Shh, let's not wake it! 🐱💤 What can I do for you today?". Nothing on stdout or stderr: only the call log says so. The response is therefore rejected if the log reports this fallback, and also if it does not carry the positive marker of the agent loading—a change in the log format causes the translation to be rejected rather than silently dropping the guard. Each marker must occupy an entire line in the log, in the measured format—severity, date, time, thread, file, and line: the binary also contains a line that copies the user message into the log—never seen at the default log level across 78 real logs—and a document quoting these messages must not be able to satisfy the guard in place of agy.

  - **The user's agy settings and history are untouched.** Each call runs with a private HOME, temporary directory, and working directory, deleted afterward. agy still authenticates via the system keyring, which aipmt never reads. Nothing is inherited: neither the user's permissions—which allowed the default agent to run `ls` and `git` without prompting—nor their global rules, plugins, MCP servers, hooks, and skills. And nothing is added to their history, where each call used to leave a conversation of roughly 200 KB, translated text included: the probe campaign had left about 95 conversations there and evicted 17 entries from a cache capped at 100. Verified: no files written to `~/.gemini/antigravity-cli`.

  - **Fail-closed where isolation would not hold.** On Linux without a D-Bus session bus—SSH session, container, server—agy stores its token in a file in `~/.gemini` instead of the keyring, as noted in its own changelog (1.1.3), and per-call isolation hides this file. Rejection now occurs before any launch, with its true cause, instead of a one-minute wait for a login code followed by a reconnection tip that would resolve nothing. On Windows, agy reads `USERPROFILE`, `APPDATA`, and `TEMP`, not `HOME` or `TMPDIR`—according to Go documentation and binary strings—: nothing would isolate the call from user settings or history there, and `--use_antigravity` is rejected there until measured. macOS passes without having been measured; the billing guard, which reads the effective configuration, holds there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero exit code, a JSON object with status `SUCCESS`, a compliant log, no rejected actions, no commands, no errors in the JSON, no truncation warnings on stderr, and non-empty text. `--print-timeout` is never used: upon its expiration, agy returns partial output with `SUCCESS`, code 0; the timeout is external and kills the process group. A segment starting with `/commande`, `!commande`, or `@fichier` is translated, never executed or resolved—without `--disable-slash-commands`, "/help" was executed instead of translated. A blank segment no longer reaches agy, as the pipeline returns it as is (see below), and remains rejected before the call as a last line of defense: on empty input, agy opens its interactive interface with code 0. Retries follow the `retryable` field of the `AGY_ERROR` line that agy has written to stderr since 1.2.6: it already retries transient errors itself—502, 503, 504, rate limit per minute—and it knows whether the remaining failure is still transient. In the absence of this field, no retry when the message mentions exhaustion—at Google, `RESOURCE_EXHAUSTED` carries the same 429 code as a per-minute rate limit, but an exhausted 5-hour window does not recover in 90 seconds—and otherwise on rate limiting only. The response matches the segment's line ending: agy always ends its output with a newline, which, at the join, split a paragraph broken mid-sentence in two. A disconnected session produces a message telling the user to run `agy` to log back in. Finally, `AGY_CLI_DISABLE_AUTO_UPDATE=true` prevents a fresh HOME from launching an update checker in its own session on each call, beyond the reach of the timeout—the value `1`, however, has no effect.

  - **Models: reasoning effort is part of the name.** Identifiers match those of `agy models`—`gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… A bare base name alone, which agy would reject, is rejected before the call, along with existing suffixes: `-medium` or `-low` for Flash, `-high` or `-low` for Pro. Default is `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` for `--eco`, established by the campaigns described below. `--reasoning_effort` has no effect and states so. Claude and GPT-OSS draw from a separate, much smaller quota—about 1% of the 5-hour window per measured call, compared to 0.05% with Flash—and a warning reminds the user. Remaining quota can be checked for free via `agy -p /usage`. Rejected in CI, like Codex and Grok CLI: login credentials live in a personal keyring, and the message suggests `--use_gemini` with a Google key.

  - **Two campaigns on September 26: defaults are measured, not assumed.** Using `aipmt --use_antigravity` itself, four parallel translations, each compared to its source with `scripts/compare_structure.py`, quota read via `agy -p /usage` before and after. In the morning, on the revision of this README published with 1.14.0 and on the dense monitoring article measuring the README, in `--news`, `gemini-3.7-flash-medium` wrote all fourteen languages for both documents: the article with zero discrepancies, 3 min 14 s median per language, and the README within one bold word in Korean, in 1 min 22 s. In the afternoon, at the author's request, Gemini 3.8 Flash vs. 3.7 on the same batch, this README and this CHANGELOG in their 1.15.0 version: at medium effort, identical structure for both; 3.8 reasons as much as 3.7—63% of output tokens versus 60%, read from agy's JSON—and costs one-seventh more quota, for a quarter more time. Then the morning campaign, re-run with `gemini-3.8-flash-medium`: fourteen out of fourteen languages with no discrepancies on the article, 3 min 59 s median, just like on the README, 1 min 43 s; internal links intact across all fourteen READMEs, whereas 3.7 broke some in Italian; and in English, French translation lines removed by the model, without invented flags, English blockquotes intact. Hence the defaults: `gemini-3.8-flash-medium`, and `gemini-3.7-flash-low` for `--eco`. At low effort, neither Flash model reasons and each costs half as much, but 3.8 low duplicated the three internal links of a README in Hindi, which 3.7 low never did in any translation it wrote. Measured cost on the author's account tier: 13 to 16 points of the 5-hour window per million source characters with `gemini-3.8-flash-medium`—the re-run campaign, 28 translations and 1.8 million characters, used 24.5, and 4.1 from the weekly quota.

  - **Terms of service and data processing, stated plainly.** Antigravity's terms (section 6) and FAQ forbid accessing the service through third-party software using Antigravity authentication—Claude Code, OpenClaw, and OpenCode are explicitly mentioned—under penalty of account suspension. aipmt never reads or reuses the token: it runs the official binary in the headless mode documented by Google for scripts and CI, and a Google team member described running `agy -p` from a local script for one's own work as "standard" on the official forum—an answer, not a commitment. No document rules on the case of a distributed tool: the README notes that users do so at their own risk. Section 5 of the same terms permits Google to use interactions—prompts, responses, metadata—to improve its products and machine learning, and to have them reviewed by humans, without distinguishing the free tier from Pro and Ultra: the README reserves this path for public documents, and its final warning notes this.

  - **Translations for this repository can use this route, with no exception needed.** `REGEN_PROVIDER=antigravity` is a subscription, not a billed API: it passes without `REGEN_ALLOW_PAID_API`, with four jobs—the entire campaign ran at four in parallel, without an error—and Codex's 1,800-second ceiling per job, which measurement justifies: the entire CHANGELOG in Hindi, the file where Codex drops placeholders, was translated without discrepancy in 4 min 33 s by 3.7 Flash in its 1.14.1 version, and in 5 min 50 s by 3.8 Flash in its 1.15.0 version, one-fifth longer: at least five times under the ceiling. A full regeneration, 2.2 million characters, amounts to 30 to 36 points of the 5-hour window with `gemini-3.8-flash-medium`. A single check, the module's preflight, precedes the 28 jobs: a disconnected agy or one configured for billing launches none of them. The default remains Codex with `gpt-5.6-sol`.

  - **An internal link was breaking undetected.** The token protecting an anchor absorbs its parentheses: the model receives an apparently broken link, brackets followed by the bare token, and sometimes "fixes" it. Restoration then produces `[texte]((#ancre))`, which leads nowhere, without any guard or `compare_structure.py` flagging it. This happened in two READMEs during the first regeneration of this version, across all tested models, more often when the link itself was parenthesized—the case for a link this version had just added to this README. Publication checks now count intact internal links in each translation, and this README no longer places any in parentheses; fixing the token itself remains to be done.

  - **Ctrl-C and terminal closure now stop the agent, across all four CLIs.** Codex, Grok CLI, OpenCode, and Antigravity run in their own session, outside the foreground group: Ctrl-C's `SIGINT` does not reach them, and on Ctrl-C, `Popen` only waits a quarter of a second for them before returning control. Verified by review on a mock binary: the agent outlived aipmt and finished its turn on the quota, with the result discarded—four at a time during regen. A `KeyboardInterrupt` or `SystemExit` during the call now kills the agent's process group before bubbling up. Closing the terminal or dropping an SSH session (`SIGHUP`) killed Python without any cleanup: the agent kept running, and Antigravity's private directory remained on disk along with its log, which contains the account address. `SIGHUP` now follows the `SIGTERM` path: agent process group killed, then exit with 129. An ignored `SIGHUP`, from launching under `nohup`, remains ignored: that is the user's choice. Antigravity's preflight—`agy --version`, then `agy -p /config`—goes through the same handler: a signal received during this check stops agy and also cleans up the private directory, instead of leaving it on disk with its log.

  - **The subprocess driver can no longer target the entire session.** On Linux, `killpg(1, sig)` equals `kill(-1, sig)`: the signal goes out to all of the user's processes. This happened while writing this release during a mutation testing run: a mutant called a `Popen` paired with a bare `MagicMock`, the resulting error went through the new interrupt path, and the mock process's pid, which Python converts to 1, caused the entire graphical session to be killed. `_codex_kill_group`, shared across all four CLIs, now only targets a group if the pid is a real integer greater than 1, `getpgid` returns that same pid — an agent started in its own session is the leader of its group — and it is not the current process's group; otherwise, only the direct child is targeted. In production, this safeguard changes nothing: it closes the case where a bug might return something else. Test doubles of `Popen` that should not be used now fail immediately, mock processes carry an impossible pid, and mutation testing runs operate within a PID namespace.

  - **A blank segment no longer fails the file, regardless of provider.** `segment_text` can isolate trailing whitespace in a document: 16,001 characters ending with three line breaks yield a second segment made up of two line breaks. Antigravity rejected it before the call — reproduced during review — and, for an API provider, an empty response triggered the empty content guard: in both cases, the entire file failed, after the previous segments' quota had already been consumed. A whitespace-only segment is now returned as is, without any call.

  - **Security: a project `.env` can no longer select the executed binary.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`, and `AGY_BIN` specify the program executed by translation, running with the user's permissions: set by the `.env` of a newly cloned repository, they would run a file from that repository upon the very first translation. The `_BIN` suffix therefore joins `_BASE_URL`, `_API_BASE`, and `_ENDPOINT` in the project layer filter, along with `GROK_HOME`, under which the Grok binary is searched (`$GROK_HOME/bin/grok`). These variables remain accepted from the environment and from `~/.config/aipmt/.env`, and each rejection is reported on stderr along with where to set them.

  - **Tests**: new `tests/test_antigravity_provider.py` file (103 tests), covering 100% of the module's statements and branches — exact argv and never `-p`, segment via stdin, agent written without tools or inheritance, environment restricted to the allowlist, private directory removed after success, failure, timeout, or signal, complete output contract, agent fallback and billing tier parsed from real-format log lines, `AGY_ERROR` and `retryable`, strict billing preflight, rejection under Windows and without a session bus, effort suffixes, newline style preserved from the segment, dispatch wiring, and regen branch. No tests run agy: a mock binary placed at the head of `PATH` was not called during any run, including under CI conditions with a hidden session bus and `CI=true`. `tests/test_provider_base.py` interrupts a real subprocess via Ctrl-C and via `SIGHUP`, including under `nohup`, and locks down the `killpg` safeguard — pid `MagicMock`, boolean, 1 or less, current group or another's group: never a group signal; `tests/test_key_resolution.py` launches a fresh process for each `_BIN` variable; `tests/test_orchestration.py` translates a document whose trailing whitespace forms a separate segment. Full suite at **650 tests**.

- **1.14.1** Mistral: rate limit exceedance no longer fails the file, and default models are confirmed by benchmarks (2026-09-17):

  - **An HTTP 429 caused the entire file to be lost.** The `mistralai` SDK does not retry by default, unlike those of OpenAI and Anthropic, and Mistral's rate limits are low and model-specific: 15 requests per minute for Large 3, 100,000 tokens per minute for Small 4, measured on the repository's account. A benchmark run with four concurrent translations on Small lost five out of eighty-four. The client now retries on 429, 5xx, and connection errors, with backoff increasing from 2 to 60 seconds for at most five minutes: Mistral's 429 does not specify how long to wait, and its limits are tracked per minute. API cross-check: twenty consecutive calls on Large 3, twenty succeeded, the sixteenth after a 33-second wait.
  - **A response in reasoning blocks no longer breaks translation.** Small 4 and Medium 3.5 reason when requested, turning the response into a list of `thinking` followed by `text` blocks instead of a string. Neither reasons by default (measured), but a change in defaults on the provider side would have ended in `AttributeError`: reasoning blocks are discarded, as with Claude.
  - **Default models confirmed: `mistral-large-latest` and `mistral-small-latest`.** The only newer model, Mistral Medium 3.5, was benchmarked against them across all fourteen languages, on the dense tech-watch article from the compatibility table and on the README. On the article, it drops or changes the level of subheadings in 9 out of 14 languages — only a single translation with zero discrepancies, compared to 6 for Large 3 and 8 for Small 4 — and it costs 3 times more than Large 3 for input, 5 times for output. Aliases point to Large 3 (`mistral-large-2512`) and Small 4 (`mistral-small-2603`).
  - **`MODEL_TOKEN_LIMITS` aligned with the API**: 262,144 tokens for the Mistral lineup instead of 256,000, 131,072 for `ministral-3b`, and dated identifiers, including `mistral-medium-2604`, no longer trigger the "unlisted" warning. Chunking, capped at 16,000 characters, remains unchanged.

- **1.14.0** A compatibility table at the top of the README, and the benchmark campaign behind it (2026-09-09):

  - **The verdict by model, at the top of the README, in French.** Over three hundred translations were sitting in the middle of the document, spread across three tables that had to be read and cross-referenced. The new table settles it with one line per model, highlighting above all what differs: "one forgotten bold word, in Arabic and Japanese" rather than a ratio. Three models have zero discrepancies detected by the comparator across both dense documents — `gemini-3.7-flash`, `gpt-5.6-sol` on the ChatGPT subscription, `z-ai/glm-5.2` via OpenRouter.
  - **A re-benchmarking campaign of 176 translations.** The original measurements dated from September 4 and were conducted on a README that has changed significantly since. Eight models were re-benchmarked on this README, two on a blog tech-watch article in `--news` mode, one on four public READMEs — FastAPI, Ollama, tldr-pages, and Vue.js. Three findings were worth writing down: Mistral drops an **entire section title** in Arabic, Hindi, and Korean without any pipeline guard noticing — a title cannot be replaced by a token, and nothing currently monitors it during translation, even though the comparator detects it after the fact; Grok fails on five languages of a tech-watch article, losing four inline code spans and three URLs starting from the very first segment, even though it holds up on a README; and Gemini delivers 55 zero-discrepancy translations out of 56 across the four public READMEs.
  - **The structural comparator enters the repository.** The README described this protocol as the right way to evaluate a model — "compare the number of sections, links, distinct URLs, code blocks" — without providing the tool. `scripts/compare_structure.py` is what generated these tables, with eleven tests proving it detects a lost URL, code block, section, inline code span, table row, or blockquote. It incorporates the two non-Latin script fixes that made it reliable: a URL followed by a full-width parenthesis is no longer counted as different, and a shorter blockquote in Chinese is no longer treated as a lost blockquote.
  - **Package verification, before and after publishing.** The test suite runs against source files and can remain green even when the distributed package is broken — a module omitted from the setuptools configuration, an entry point that fails to resolve. `scripts/check-package-smoke.sh --wheel` builds the wheel, installs it in a disposable venv outside the repository, verifies that it contains only the package, that both invocation forms work, that all modules import cleanly, then translates a real document and checks its structure. `--pypi` does the same from the index: it is the only verification proving that these exact bytes were published, and PyPI never allows re-releasing a version. The `--full` gate runs the offline portion, without model calls or costs.
  - **Seven claims in the README corrected, all reproduced before being rewritten.** "Nothing false reaches your disk" was untrue: a model that deletes a section or modifies a front matter date yields a file that the pipeline writes with status `success`, reproduced using a mock response. The README now specifies what tokens protect — code blocks, inline code, URLs, anchors, blockquotes — and what pipeline guards do not currently check. "Zero discrepancies" does not mean "identical": the comparator counts elements without inspecting their contents, and flags neither the deletion of an H4 heading, nor the replacement of inline code text, nor a swapped CLI flag — three measured cases, with the phrase "same flags" removed since the comparator has no flag counter. The installation instructions for contributing did not produce a usable tool: `pip install -r requirements.txt` only installs dependencies, `python -m aipmt` returned `No module named aipmt`, and `pip install -e .` was missing — as was the install command for `pre-commit`, which was absent from both dependency files. The OpenRouter promise regarding small contexts stated the opposite of what the code did: a model with a context window under **16,400 tokens** is rejected before any call, measured at 4,095, 8,192, and 16,384. The filter preventing a project `.env` from redirecting API calls was documented nowhere; it is now, complete with the list of affected variables. Finally, two figures: a Grok cell in the top table came from a September 9 run while its column announced the September 4 one, and "one broken link" attributed to Gemini was the opposite of the measurement — it converts three bare URLs into links, losing none.

  - **A write failure no longer leaves a truncated translation on disk.** `open(cible, "w")` truncates the file before writing to it: an error during writing — disk full — left a partial target file. Reproduced: eight bytes written, status `failure` returned, then the next run found this file, replied `skipped`, and kept it. A failure turned into a truncated translation that went unnoticed, and the exit code was 0. Content is now written to a temporary file in the same directory — `os.replace` is only atomic on the same filesystem — and then renamed, with the temporary file being deleted if writing fails, including upon interruption. This temporary file comes from `mkstemp`, and a review showed that a predictable name would only have shifted the problem: a symlink placed at `cible.md.aipmt-tmp` caused the translation to be written to the target file, outside the output directory, while returning `success`; and two concurrent runs on the same target shared that name, the second renaming while the first was still writing to the same inode — target reported successful, contents scrambled (`BBBAAAAA` instead of `BBBBBBBB`, measured). `mkstemp` creates with `O_CREAT | O_EXCL` under a unique name, closing both loopholes. Existing target permissions are explicitly preserved before replacement: `mkstemp` creates files with 0600, and a target deliberately set to 0600 would otherwise switch to 0664, while a 0644 target served by a web server would have become unreadable. Eight tests lock this down, and two code mutations turn them red.

  - **The purity manifest can declare a rewritten suppression marker.** The check required every line bearing a reference `# nosec`, `# nosemgrep`, or `NOSONAR` to survive verbatim. But moving a write operation to a temporary file renames the opened variable: the Sonar suppression remains the same, but its line changes. The manifest's `markers` category declares this pair `old` → `new` along with its rationale. Two conditions, the second coming from a code review: the replacement must exist, **and bear the exact same suppressions as the original line**. Without it, declaring `value = 1  # NOSONAR` → `value = 1` passed, meaning a mere declaration sufficed to drop a marker — exactly what this check exists to prevent. An undeclared disappearance remains rejected.

  - **Two benchmark runs removed from tables because they were interrupted by factors external to the model.** Grok lost its CLI session after twelve languages of this README — two languages failed in four seconds, without calling the model — and `qwen3.8-flash` was throttled by an HTTP 429 from its upstream host after two. An interrupted run is not scored: they will be re-run in full or not at all. At the same time, durations in the "This project's README" table were recalibrated against the September 9 benchmark run — they dated from a 508-line revision, versus the 785 lines measured, and showed 2 min 04 s for `gpt-5.6-sol` where the benchmark yields 6 min 46 s.

  - **The README has been overhauled: 600 lines down from 1,007, organized for the reader.** What the tool does, installation, configuration, quick start, then the compatibility table — placed after installation, once you know what you are running —, options, a chapter per provider, detailed benchmarks, and finally how to contribute. Campaign narratives, benchmarking anecdotes, and repetitions across sections have been removed; every retained number matches the tables, and every behavioral claim aligns with the code of this release. The overhaul log remains in git history.

  - **The top table now states on HOW MANY languages each discrepancy occurs.** It previously showed "✅ 14 languages" and then, in the neighboring column, "one bold word" — without clarifying whether that applied to one language or all fourteen. Readers had no way of knowing, leaving a poor impression where the actual benchmark was strong: on this README, Gemini has only one language out of fourteen with an extra bold word, Sol two, GLM three. Each cell now specifies the number of affected languages and which ones, the figure in the verdict columns is defined in a single sentence — the number of languages, out of fourteen, where the translation is written and zero discrepancies exist —, and a legend explains what the three symbols mean. The breakdown is defined as follows: ✅ zero discrepancies; ⚠️ everything is translated and only markup shifts, nothing is missing; ❌ at least one language was rejected, or content is missing from a written file.

The note on `gpt-oss` is corrected at the same time: passages left in French never reached an output file, as the untranslated excerpt guard rejected the four affected languages — this is the difference between catching a model in its tracks and letting errors slip by unseen, and the README spells it out.

Four points are therefore clearly stated: machine translation must be reviewed before publishing, as the guards cover neither headings, tables, front matter, nor meaning; the translated document is sent to the chosen provider, under their own terms, with certain free models potentially reusing interactions—a local model remaining the only path without data egress; API calls are billed and the program does not cap spending; and published benchmarks are dated observations, not warranties.

The default remains `gpt-5.6-sol`, the only model benchmarked across fourteen languages without loss on a dense document, and it is the one translating this repository.

- **1.13.1** Dependency freshness: falling behind stops being a warning that can be ignored (2026-09-09):

  - **An uncounted warning is a missed warning.** `check-deps-fresh.sh` had been reporting for several days that `openai` and `anthropic` were out of date, but the gate's summary line only counted failures: it announced "READY: N checks passed" even though an outdated status was reported a few lines earlier. Anyone reading only the last line—which is what everyone does—could not know. The verdict now includes the warning count, and a dedicated counter tracks them instead of printing them inline on the fly.
  - **Outdated status comes with release notes.** A version number does not explain what changed, and finding the right file yourself is precisely the friction that causes people to skip the step. - **1.13.0** `--use_openrouter` provider: a paid router to ~430 models, including open Chinese models (2026-09-05):

[OpenRouter](https://openrouter.ai) provides single-key access to models that no other provider exposes here—Kimi, Qwen, DeepSeek, Z.ai—on a single pay-as-you-go credit balance. Since the endpoint is OpenAI-compatible, the client is identical to the one for xAI; **everything distinguishing this provider lies in a preflight check**, and every single one of its rules stems from API benchmarks.

  - **A single model is served by dozens of providers with different limits, and routing is blind to this.** Measured: 33 providers for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash`—including one capped at **2,048 output tokens**. One long translation out of 23 therefore ended up truncated, randomly, without any warning. The preflight check inspects `/api/v1/models/{modèle}/endpoints`, rules out providers under 8,000 output tokens, those with degraded status, and those declaring no cap at all, then pins the rest. `provider.only` **without** `allow_fallbacks: false` is merely a preference: the router falls back to a discarded provider, making the pinning useless. If no provider satisfies the cap, execution halts: translating anyway would mean accepting the silent truncation that this preflight check was created to prevent.

  - **Reasoning is billed at output rates, and enabled by default on many models.** Same prompt on `z-ai/glm-5.2`, responding "OK": **107 completion tokens under model defaults, 2 with reasoning turned off**. For translation, where reasoning adds no value, that is an 18x multiplier across every chunk of every file. It is therefore disabled by default. The **288 models out of 431** that mandate it (`reasoning.mandatory`) return `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for those, preflight reads the accepted effort levels and requests the lowest one (next bullet)—effort allocates a **percentage of `max_tokens`** consumed first by reasoning, so an arbitrary value shifts the risk of blank outputs rather than reducing it.

  - **A model that mandates reasoning receives the lowest effort level it accepts, and this was decided by benchmark data.** The initial approach was to send nothing, avoiding second-guessing the model. Tested on `z-ai/glm-5.3-flash`, whose catalog default is `max`, this approach yielded an output **truncated at 32,768 tokens** before the translation completed—two languages out of fourteen lost. Increasing the token limit would not have helped: effort allocates a percentage of it, and reasoning scales alongside it. The provider thus checks `supported_efforts` during preflight and requests the lowest one, falling back to "nothing" when the catalog reports no usable values. Verification test on the failing language: previously failing due to an exhausted budget, it now finishes in 9 minutes with a structure identical to the source.

  - **Upstream provider outages now carry their actual name.** The router normalizes this case into `finish_reason=error` with a null `native_finish_reason`—measured twice, across two languages, at exactly 750 seconds. The generic message previously pointed toward a flaw in the document or chunking; it now states that the failure is upstream on the provider side and that retrying is often sufficient.

  - **`finish_reason=length` with empty output is not a truncation.** It is the budget consumed by reasoning before the first usable character—measured at 15,850 reasoning tokens for 148 usable tokens. The two situations call for opposite actions: reducing segment size is useless in the first case. The error message explicitly distinguishes them. Two other guards originate from benchmarks: the router returns a **200 status code with a body containing only an error** when the upstream provider fails (`choices[0]` raised an opaque `TypeError` hiding the message), and the context window is retrieved from the catalog then populated in `MODEL_TOKEN_LIMITS`—`DEFAULT_TOKEN_LIMIT` is inaccurate for 44 models in the catalog, including two capped at 4,095 tokens.

OpenCode responds with its contract error, and not a `AttributeError`, on a `part: null` event, and rejects a JSONL stream where an event line is unreadable rather than accepting partial text. The three agentic CLIs kill the agent's process group when that process receives `SIGTERM` during the call — the `timeout` of the regen allowed the agent to survive and consume its quota — and the `SIGKILL` of the group always follows the grace period, a cleanly dying shim leaving its grandchild alive. A `# fmt: off` / `# fmt: on` pair split by the refactor is rejoined; the help text of `--reasoning_effort` names the four providers that consume it.

The agentic CLI foundation falls back to `terminate` then `kill` where POSIX process groups do not exist, instead of letting a `AttributeError` bypass the timeout guard and prolonging the wait. OpenCode's `429` marker is searched as a number and no longer as a substring, where an error identifier like `err_84290b` triggered 90 seconds of back-off before failing anyway. Finally, a non-canonical OpenRouter endpoint is displayed at preflight: a project `.env` is enough to set one, and the real key would be sent next.
  - **Security: a project `.env` can no longer redirect API calls.** `find_dotenv(usecwd=True)` searches for the file from the current directory and its parents: an untrusted directory tree — a repository just cloned — could place `OPENROUTER_BASE_URL`, `XAI_BASE_URL`, or `OPENAI_BASE_URL` (the latter read by the SDK itself) there without knowing any keys, and the real key, coming from the environment or user configuration, would then be sent in the authorization header of a third-party server. The filter operates on a PATTERN and not on a list: identified across installed SDKs, twelve routing variables are read, six of them by the Anthropic client alone — a hand-written enumeration would have missed half of them. Therefore, any variable in `_BASE_URL`, `_API_BASE`, or `_ENDPOINT`, proxies, and certificate stores (pointing to a controlled CA makes an interceptor indistinguishable from a real server), as well as `XDG_CONFIG_HOME` and `APPDATA`, are rejected from the project layer: setting them amounted to deciding which file constitutes the user layer, thereby bypassing the filter through the backdoor. These variables are only accepted from the two layers that the user controls: the exported environment and `~/.config/aipmt/.env`. The project layer is also read WITHOUT interpolation: `load_dotenv` expands `${VAR}` by default, and an untrusted `.env` containing `NOM_ANODIN=${OPENAI_API_KEY}` copied the real key under a name that subprocess pattern filtering does not recognize — it would then enter the environment of `codex exec`, against the announced invariant. Finally, the rejection only displays the variable name: a URL of the form `https://${CLE}@hôte/` leaked the interpolated key into logs, even while rejecting it. Rejection is reported on stderr with instructions on how to proceed — an enterprise proxy is declared in user configuration.
  - **Fix: the OpenRouter output envelope is calculated for each call.** `context_length` covers input AND completion, and a fixed reserve calibrated on Latin text bounds nothing: measured with tokenizer `o200k_base`, 16,000 characters equal 3,200 tokens in French but 12,300 in Japanese and 17,500 in emoji. The budget therefore comes from the text actually sent, bounded upward by its number of UTF-8 bytes: for any byte-pair encoding tokenizer — byte-level BPE, SentencePiece with byte fallback, the families used by the catalog — one token is worth at least one byte, and this is the only upper bound available here, where OpenRouter routes to dozens of unknown tokenizers. No average ratio was suitable — a supplementary plane ideogram drops to 1.33 bytes per token, a combining character to 1.00 —, and input plus output now fit within the window by design. A segment that is too dense for the chosen model is rejected before the call rather than after billing.

Consequence: `_validate_news_post` looked for this string in the translated output and failed systematically (two reasons: truncated `)` + "relayé par" translated to `relayed by`/`weitergeleitet von`/...). Full cascade low → medium → high → gpt-5.5 could not succeed.
  - **Fix**: the regex becomes `re.search(r"\]\(([^)]+)\)", attribution)` — specifically targets the `](url)` of the markdown link, capturing **only the raw URL** (without FR prefix or truncation), an invariant preserved by `#URL{N}#` placeholders during translation. Robust against both problematic patterns:
    - `(relayé par [@account sur X](url))` — nested parentheses
    - `via [@source](url)` or `selon [@author](url)` — FR prefix without enclosing parentheses
