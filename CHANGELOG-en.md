- **1.18.0** Gemini moves to 3.8 Flash, retries transient failures and no longer waits indefinitely; Python 3.11 minimum and Python 3.15 tested; the new major version of the Gemini SDK is validated (2026-11-15):

  - **`--use_gemini` moves to Gemini 3.8 Flash.** Google deprecated Gemini 3.7 Flash on October 8: it disappeared from AI Studio, and its endpoint serves Gemini 3.8 Flash instead. The aipmt default therefore named a model that was no longer the one doing the translating. On November 14, on the API's free tier, around twenty calls addressed to 3.7 Flash exhausted the daily quota for 3.8 Flash. Pricing and reasoning levels remain unchanged, and `--model gemini-3.7-flash` is still accepted. Measured on November 15 on the free tier, with a short file translated twice with identical structure: 3.8 Flash rejects `minimal` reasoning, like 3.7, and accepts the next level up, but took 4 then 8 minutes while Google reported high demand; the previous evening, `--eco` responded in one second. The model used by `--eco`, Gemini 3.1 Flash Lite, will be shut down on May 7, 2027: its designated replacement, Gemini 3.5 Flash Lite, will be measured before taking its place.

  - **A transient Gemini failure no longer costs you the file.** Google's SDK does not retry anything by default: at the first “503 high demand”, aipmt abandoned the file, whereas the same failure has been retried on Antigravity since 1.17.1. A 503, a 429 or a timeout now retries the call up to three times, after 10, 20 then 40 seconds. Exhausted prepaid credit or a rejected request still fails immediately.

  - **An unanswered Gemini call no longer ties up aipmt.** The SDK used to wait indefinitely: on November 14, a translation spent more than five minutes waiting on an unresponsive server, until it was stopped manually. Each attempt is now abandoned after 5 minutes, then retried as a transient failure: an unresponsive server causes the segment to fail within roughly twenty minutes at most. This requires a Gemini SDK version recent enough to retry a timeout, and pip updates it if needed.

  - **Gemini retries are visible.** Google's SDK announces its retries in a log that nobody displays: four minutes of waiting on a small file looked just like a hang. Each retry is now displayed, with the error and the wait time: on November 15, a “504 DEADLINE_EXCEEDED” after 5 minutes was successfully retried 10 seconds later. The warnings the SDK already displayed are still shown.

  - **The new major version of google-genai, validated with a real call.** This SDK no longer includes `httpx`, which has become optional, and switches to `httpx2`. aipmt imports neither, and its translation call remains unchanged. A Markdown guide translated into `--eco` by `gemini-3.1-flash-lite` with this version retains the same structure as the source. A single test constructed an Anthropic error using `httpx`: under Python 3.11 and 3.12, nothing installed it anymore, and the suite failed at import time. It now uses `httpx2`, like the Anthropic and Mistral SDKs.

  - **Python 3.11 becomes the minimum.** Python 3.10 has been unsupported since October 1, 2026, and the new major version of google-genai, released on November 6, requires Python 3.11 or later to install; six other packages in the pinned dependencies also require it. Under Python 3.10, pip now installs only 1.17.1, the last version that supports it.

  - **Python 3.15 is tested.** The test suite runs on every Python version from 3.11 to 3.15, with the package installed and its dependencies set to their declared public bounds. SonarCloud analysis, dependency checks and PyPI publishing run under Python 3.15.

  - **Dependencies.** In the pinned dependencies, `anthropic`, `openai` and `mistralai` received their minor updates, proposed by Dependabot and merged automatically. `pyasn1`, brought in by Google authentication, received fixes for four high-severity security alerts: decoding operations with quadratic cost that malicious data could make run for a very long time. An installation from PyPI already picked up the fixed version. `httpx` and `httpcore` are removed from the pinned dependencies, since no package requires them anymore. The actions for installing Python, publishing to PyPI and running SonarCloud analysis were updated manually.

- **1.17.1** Grok CLI moves to Grok 4.7, the only model it still accepts; a transient Antigravity failure and a Grok token refresh no longer cost you a file (2026-10-21):

  - **`--use_grok_cli` translates again, with Grok 4.7.** Since version 1.0.52, the Grok CLI has rejected Grok 4.6 and Grok 4.5, aipmt's models for quality and `--eco` (“unknown model id”): every translation failed at the first segment. On October 19, Grok 4.6 was still translating. Grok 4.7 becomes the default and, with no second model available on the subscription, `--eco` has no effect on this path. The xAI API still serves Grok 4.6 and Grok 4.3: `--use_grok` remains unchanged. Rerun on the 1.17.0 test set, a guide and a short `--news` article whose English quotation contains code: three successful translations out of three, with the same results as the other providers.

  - **Antigravity retries transient service failures.** On October 20, agy returned “API error (attempt 2): UNAVAILABLE (code 503)” at the fourth segment of a CHANGELOG, after retrying once itself. Nothing in the message marked the failure as retryable: aipmt abandoned the file after consuming the quota for the first three segments, even though a manual retry succeeded. Codes 502, 503 and 504, which agy already retries on its own, now trigger a segment retry after 30 then 60 seconds. An exhausted quota window still fails immediately, and when agy itself states whether the failure is retryable, its decision takes precedence.

  - **The Grok CLI preflight no longer mistakes a token refresh for a logged-out session.** Before translating, aipmt checks the session using `grok models`, which consumes nothing. However, the call that refreshes an expired token itself responds “You are not authenticated.”, and the next one succeeds: aipmt advised logging in again with `grok login` when simply retrying was enough. It now checks again five seconds later before drawing a conclusion. Observed on October 19, reproduced on October 21.

  - **The retry notice explains why.** Codex, Grok CLI, Antigravity, OpenCode and Claude Code announced every retry as a “rate limit”, including a 503: enough to send you looking for a quota issue. The notice now quotes the error returned by the CLI.

  - **Dependencies.** In the pinned dependencies, `openai` received its minor update, and `certifi` received a fix for a critical security alert, removing emSign roots whose intermediate keys were compromised. An installation from PyPI already picked up the fixed version.

- **1.17.0** Claude 5.5 through the API, Codex on GPT-6.1-Sol: Sonnet 5.5, which rejected disabled thinking, can now translate and becomes the default model, while Haiku 5.5 takes over `--eco` mode; Codex moves to GPT-6.1-Sol and no longer discards a segment it finishes after reconnecting; Dependabot now runs on weekends too (2026-10-20):

  - **`--use_claude` translates with Claude Sonnet 5.5, Opus 5.5 and Fable 5.1.** aipmt disabled Claude's thinking with `thinking: {"type": "disabled"}`, which these three models reject: HTTP 400 at the first segment, measured with a real call. aipmt now sends the lowest setting each model accepts, as listed in the capabilities published by Anthropic's API: `between_tools` for Sonnet 5.5, which disables its preliminary thinking, and no setting for Opus 5.5 and Fable 5.x, which then think as they see fit. On the first rejection, a model that is still unknown tries settings from the most economical to the most permissive, then keeps the successful one for subsequent segments — the logic already used for Gemini. Any other error is passed through unchanged. All four 5.x models are added to the context window table, at one million tokens.

  - **Claude Sonnet 5.5 becomes the default model for `--use_claude`.** Measured by aipmt itself on the two documents used for the README measurements — the dense news roundup article, in `--news`, and this README at revision 1.14.0 — in fourteen languages each: 28 translations out of 28 written with no structural differences, no segment retried, internal links intact, English quotations copied verbatim and, in English, the French translation lines removed by the model itself. Claude Sonnet 5 achieved 11 and 12 out of 14 through the API on a longer revision of this README, and 13 and 13 through Claude Code. Pricing remains unchanged: $2 and $10 per million input and output tokens, or $9.21 for the 28 translations.

  - **`--eco` moves to Claude Haiku 5.5, thinking included.** Measured on the same documents: with thinking disabled, Haiku 5.5 leaves entire paragraphs in French, which the untranslated-excerpt guard rejects — 9 translations written out of 28. With adaptive thinking, it writes 26, including 23 with no differences; two READMEs are rejected, in Arabic and Hindi, because inline code was lost in the output. Claude Haiku 4.5, the previous default, measured through the API for the first time, writes all 28 but only 21 with no differences: in the article, it promotes a heading to level 1 in seven languages, and leaves it in French in Japanese, which no guard detects. Haiku 5.5 costs $0.57 for the 28 translations, compared with $3.67, and runs twice as fast; aipmt therefore lets it think.

  - **Codex no longer discards a segment it finishes after reconnecting.** When the server responds with a 429, `codex exec` reconnects on its own and announces each retry in its JSON stream with an event of type `error`, “Reconnecting... 2/5”, before resuming the turn, which may succeed. aipmt treated this first `error` as a failure and abandoned the file: three of the fourteen failures during a regeneration of this repository on October 19 carried this message. Only the end of the turn now determines the outcome, `turn.completed` or `turn.failed`, as specified by the Codex 0.162.1 source code. A 429 that exhausts Codex's retries, which arrives only as text, is also recognized: aipmt waits, then retries the segment instead of losing the file. Exhausting the plan's quota still fails immediately.

  - **`--use_codex` moves to GPT-6.1-Sol.** It is the first model in the catalog that Codex serves to a ChatGPT account, yet aipmt still preferred GPT-5.6-Sol. Measured on October 19 on this CHANGELOG in German, one translation per model, launched simultaneously: GPT-6.1-Sol in 527 seconds, with segments taking 46 to 70 seconds and structure identical to the source; GPT-5.6-Sol in 906 seconds, served intermittently that evening, with up to 211 seconds for a segment and 429s with as few as four translations running in parallel. The GPT-6 family no longer triggers the “unusual model” warning. GPT-5.6-Sol remains accessible through `--model gpt-5.6-sol`, and `--eco` keeps GPT-5.6-Luna.

  - **Dependabot runs every day, including weekends.** Set to `daily`, it only ran Monday through Friday: a version that passed its three-day waiting period on a Friday, after the morning run, waited until Monday, and the daily freshness check, calibrated for one run per day, would have flagged it as overdue on Sunday. On October 18, google-genai 2.30.1 avoided that by just 1 h 35. Dependabot now follows a daily cron schedule, and the test that aligns the check's grace period with its schedule allows three days for `daily`: switching back without extending the grace period makes it fail.

  - **The split purity checker is removed**, as planned since 1.13.0. It compared the package with the snapshot taken when the code was split, and every code change had to declare its differences there. Its most useful check remains: `check-release-ready.sh` rejects a Python module that git does not track, invisible to both hooks and CI.

  - **Two issues reported by SonarCloud are fixed**: the overly complex function that organizes code tokens in a `--news` quotation is split in two, and an exception test now calls only one function in its block.

  - **Dependencies updated since 1.16.3.** In the pinned dependencies, `anthropic`, `openai`, `google-genai`, `mistralai` and `python-dotenv` received minor and patch updates, proposed by Dependabot and merged automatically; the publishing and SonarCloud analysis actions were upgraded manually. The two questions left open by automatic merging are settled: it works without additional permissions, and it does not trigger any push workflows — the daily `main` check serves that purpose.

- **1.16.3** End of file: an API translation preserves its source's trailing newline, and Mistral SDK 3.0 is validated (2026-10-04):

  - **An API translation preserves its source's trailing newline.** The API providers — OpenAI, Anthropic, Gemini, Mistral — strip surrounding whitespace from the model's response. On the last segment, this cleanup removed the source's trailing newline: a translated file without a translation note ended without a newline, which git flags and formatters fix on every pass. This was observed while validating Mistral SDK 3.0, on a guide that ended with a newline but whose translation no longer had one. The translation note added one back, and the command-line providers — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — copy the end of the segment: only an API translation without a note was affected. The translation now preserves the source's trailing newline, regardless of provider, and adds none to a source that has none.

  - **Mistral: SDK 3.0 validated with a real call.** `mistralai` 3.0.0 replaces the HTTP library `httpx` with `httpx2`; the imports and translation call remain unchanged. A fresh aipmt installation already received it, since dependencies have no upper version limit, but no real call had tested it yet: a Markdown guide translated through the Mistral API with SDK 3.0 retains the same structure as the source. The pinned development dependencies move to this SDK, and the retry tests provide it with an `httpx2` client, the one it uses in production.

- **1.16.2** Code protection: code quoted inside a `--news` quotation and an indented block inside a list no longer cause translations to be rejected in every language (2026-10-03):
  - **Code quoted inside a quotation no longer blocks translation.** In `--news` mode, aipmt protects inline code before setting aside English quotations, which are restored unchanged. Code inside a quotation therefore went along with it: the model never saw its token, and validation reported it missing, for every language. The author's daily news roundup stopped there on October 2: an `/plugin enable …` command quoted in a tweet, the probe language rejected twice, the other thirteen never started. Tokens carried away by a quotation are now resolved in the text set aside. When targeting English, a quotation's French translation line is no longer sent to the model: the instruction told it to remove that line, and the code it contained was then counted as missing even though the model had complied. The published result is unchanged. Finally, restoring a quotation no longer reinterprets its backslashes: a quoted `\n` remains an `\n`. Verified end to end on the article that had failed: English and German translated on the first attempt by `gpt-6.1-sol`, with the same structure as the published versions.

  - **An indented code block inside a list is protected.** CommonMark allows an indented block fence, which is normal for a block documenting a numbered list step: it belongs to the list item, so it is indented. Anchored at column 0, the protection pattern missed all of them: measured on a real README, 8 blocks detected out of 14. The other six were sent to the model as prose, came back unchanged because they were commands, and the guard that rejects a translation copied verbatim rejected the file for every language, with a message that named the symptom but never the cause. The pattern now accepts an indented fence, and the round trip through protection and restoration returns the document unchanged, including indentation.

- **1.16.1** Internal links: the anchor token leaves its parentheses with the link, and a translated link no longer silently doubles up (2026-09-27):

  - **An internal link no longer breaks undetected.** To protect a link to a section, `[texte](#ancre)`, aipmt replaced its parenthesized part, including the parentheses, with a token: the model received brackets followed by a bare token, a seemingly broken link, and sometimes “fixed” it. Restoration then produced `[texte]((#ancre))`, a link leading nowhere, without any guard reporting it. The defect recurred whenever this repository's translations were regenerated — in Spanish, Korean, then Italian for 1.15.0, in German for 1.16.0 — with every Gemini Flash tried, and even with Claude Sonnet and Haiku. A Markdown link's token now keeps its parentheses: the model receives a valid link, which it no longer has any reason to fix, and restoration also accepts a token whose parentheses it might have removed. HTML anchors keep a bare token. Verified end to end with the most fragile model, `gemini-3.8-flash-low`, on a README with a parenthesized link: without the fix, README rejected, three doubled links and one segment retried; with it, all three links intact, no retries. Then on this README, in German, Japanese, and Hindi through `gemini-3.8-flash-medium`, and in German through Claude Code with `sonnet`: structure identical to the source, all three internal links intact everywhere.

  - **Tests can no longer modify the repository that runs them.** When pushing from a linked worktree, git passes its hooks the variable identifying the repository, and the pre-push hook runs the tests: a test's `git init`, intended for a temporary directory, reinitialized the real repository, which was suddenly reported as having no working tree. Tests that run git now remove every `GIT_*` variable from their environment, and a regression test that points this variable at a decoy repository verifies this.

- **1.16.0** `--use_claude_code` provider: translate using the Claude Pro or Max subscription quota, through the official `claude -p` CLI — no paid route, and every call proves it (2026-09-26):

  - **Eleventh route: the Claude subscription, without usage-based billing.** `--use_claude_code` drives the official Claude Code binary in `-p` mode, on the same foundation as Codex, Grok CLI, and Antigravity — its own process group, safe termination on timeout, Ctrl-C, or terminal closure. Not to be confused with `--use_claude`, Anthropic's API billed by usage. aipmt never reads the token.

  - **No paid route, verified at three levels.** The subprocess environment uses an allowlist: no API key, token, cloud provider, or marker from the Claude Code session that aipmt might be launched from — the session that wrote this provider exported fifteen of them. The preflight, without a model turn, requires `claude auth status` to show a subscription login without a Console key, and `/usage` to show the phrase confirming the subscription. Each call must then confirm it in its initialization event — `apiKeySource: none`, forced environment correctly received, model from the requested family, no fast mode — and in its quota report: paid “extra usage” stops translation immediately.

  - **The quota is shared with Claude Code sessions, and the provider conserves it.** Each call reports usage for the 5-hour and weekly windows; above 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), no further segment is started. On the day this was written, the author's account was already at 98% for the week.

  - **No user configuration gets in, and nothing from the session remains.** No tools, no customization, user settings ignored, MCP servers and hooks disabled, private disposable working directory, no transcript retained. Measured with canaries: without `CLAUDE_CODE_DISABLE_ATTACHMENTS`, an `@chemin` in the document became an attachment, and the model returned a read call instead of the translation; with it, nothing gets through. The `AGENTS.md`, `CLAUDE.md`, and hook canaries loaded or executed nothing.

  - **A segment starting with `/` never reached the model.** Under `--disable-slash-commands`, Claude Code answers it itself with “… isn't available in this environment.”, with `success` status, without any turn. A newline before the segment sends it to the model; the output contract rejects any response returned without a turn, in more than one turn, truncated, or from a model other than the one announced anyway.

  - **Models: aliases, never a fixed identifier.** `sonnet` by default, at `low` effort, and in `--eco` too — so `--eco` changes nothing on this route —, `opus` and `haiku` through `--model`; `fable` and `[1m]` variants are rejected because in `-p` they switch to paid credits without asking.

  - **Defaults are measured, not assumed.** Through `aipmt --use_claude_code` itself, four translations in parallel, on the two documents used for the README measurements — the dense news roundup article, in `--news`, and this README at revision 1.14.0 —, fourteen languages each. `sonnet`, at `low` effort, writes all 28 translations, 26 without discrepancies: one extra bold word in Chinese in the article, and in Arabic, in the README, a table row joined to the previous one, which rendering hides. Internal links intact, English quotations copied unchanged, and in English the French translation lines removed by the model, without an invented flag; a median of 6 min 49 s per language for the article, 2 min 20 s for the README. `opus` translates the README without any discrepancies, a quarter faster, but no article: its guardrails stopped the response in all fourteen languages over a biology brief. `haiku` writes everything — three section headings promoted to level 1 in the article, internal links doubled in the English README —, but takes twice as long as `sonnet`: it reasons with no way to prevent it, using 61% of its output tokens, and its lower price leaves only a 14% saving in API-equivalent cost. Hence `sonnet` in `--eco` too. Effort does nothing for translation: on a preliminary batch — this README and this CHANGELOG in English, Japanese, and Hindi —, `sonnet` produced no reasoning tokens, `opus` at medium effort used 1% of its output tokens, and medium effort gained nothing over low effort, either in structure or duration. The `sonnet` campaign, 1.8 million source characters, used 9 percentage points of the 5-hour window and 2 of the weekly window on the author's Max subscription — an upper bound: the session driving the measurements drew from the same quota.

  - **A refusal by Anthropic's guardrails is identified as such.** Opus 5.5 has stricter guardrails than Sonnet, and Anthropic's error message warns that they sometimes flag work related to biological research. A news brief about 279 molecules generated for a binding site was enough. Claude Code then cuts off the response, retries once, and the model returns “I can't continue this translation” with a success status, without an error, over two turns: only the single-turn contract stopped this response, with a message that said nothing about the cause. Sent on its own, the brief is refused by the API under the “bio” category. aipmt now recognizes these signs, names the guardrails and their category, does not retry — the same text would trigger the same refusal again — and recommends `--model sonnet`, which translated the brief into all fourteen languages.

  - **This repository's translations can use this route without an exception.** `REGEN_PROVIDER=claude_code` is a subscription, not a billed API: it runs without `REGEN_ALLOW_PAID_API`, with four jobs — the campaigns ran four simultaneous translations without a single rate-limit or login-lock error —, after a single preflight that consumes no quota. The default remains Codex with `gpt-5.6-sol`.

  - **The terms of use, stated plainly.** Claude Code's legal page does not prevent a user from logging into the unmodified binary with their own subscription; it prohibits third-party developers from routing requests through their users' Pro or Max credentials, and Anthropic prefers API keys for third-party tools, including open source projects, while reserving the right to charge their usage against paid credits. No text settles the case of a distributed tool that launches the official binary: the user puts their account on the line.

  - **Tests**: new file `tests/test_claude_code_provider.py` (58 tests), 100% statement and branch coverage for the module, without ever launching the real `claude` — cleared environment, nonexistent binary, `PATH` without `claude`, test doubles that raise if called.

- **1.15.0** `--use_antigravity` provider: translate using the Google AI Pro or Ultra subscription quota, through the official `agy` CLI; and, for all providers, Ctrl-C no longer leaves an agent running, a blank segment no longer causes the file to fail, and a project's `.env` no longer chooses which binary runs (2026-09-26):

  - **Tenth provider route: the Google subscription, without usage-based billing.** Anyone paying for Google AI Pro or Ultra can now charge translations against it instead of paying per token through the Gemini API. `agy`, Antigravity's official CLI, is the only route to this quota: Gemini CLI has no longer served Pro, Ultra, or free accounts since June 18, 2026, and the Antigravity SDK authenticates only through an API key or Google Cloud. `--use_antigravity` drives it in headless mode, like Codex and Grok CLI, on the same foundation — its own process group, `SIGTERM` then `SIGKILL` on timeout, sanitized environment. Verified end to end on agy 1.2.11: a Markdown guide — front matter, bold, link with parentheses, inline code, indented code block inside a list, table, quotation — translated into English in 14 seconds, including preflight, structure identical to the source, translation note added; then, after the review fixes, into German in 19 seconds, identical structure, nothing written to `~/.gemini`.

  - **No paid route remains open, and every launch verifies it.** agy supports routes other than the subscription — API key, Google Cloud project, gateway, paid AI credits — and several environment variables switch it to those routes silently. Measured: `AGY_GATEWAY_URL` sends the document to a third-party gateway, `AGY_ADC_AUTH` switches to a billed Google Cloud project, `CLOUD_CODE_URL` redirects the authenticated endpoint to any address. The subprocess environment therefore uses an allowlist rather than a denylist: `PATH`, language and time zone, terminal, identity, machine proxies and certificates, and session bus — what an `env -i` proved agy needs —, without any key. A denylist by prefix families (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), tried first, missed some: a review found endpoint overrides in the binary's strings that no prefix covered, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Two settings bypass the environment and can only be read through `agy -p /config`: paid AI credits that take over when the quota is exhausted, and login through a Google Cloud project. A preflight that consumes no quota — zero usage, measured — refuses to translate if either is active or an API key is configured, and a setting missing from `/config` means rejection for each of the three: an agy version that renamed one must not pass a check that verified nothing. Finally, each call's log must confirm subscription authentication (`authMethod=consumer`), and any other authentication method appearing there, under either spelling used by the binary, causes the response to be rejected: the call itself is the authority, not the configuration prepared for it.

  - **The translation agent has no tools, and its loading is proven on every call.** Each call writes an agent in agy's project-agent format into a disposable directory: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Around 800 input tokens instead of 12,400 with the default agent, and the third setting is not redundant: `excludeDefaultComponents` alone let a workspace hook execute its commands and inject its text. The real trap lies elsewhere: an agent that cannot be found does not cause agy to fail. Exit code 0, `SUCCESS` status, and the coding agent, with 57 active tools, answers — to “The cat is sleeping.”, it replied “Shh, let's not wake it! 🐱💤 What can I do for you today?”. Nothing on stdout or stderr: only the call's log reports it. The response is therefore rejected if the log announces this fallback, and also if it lacks the positive marker confirming that the agent loaded — a change in log format causes the translation to be rejected instead of silently removing the guard. Each marker must occupy a whole log line, in the measured format — severity, date, time, thread, file, and line: the binary also contains a line that copies the user's message into the log — never seen at the default log level across 78 real logs —, and a document quoting these messages must not be able to satisfy the guard in agy's place.
  - **The user's agy settings and history are untouched.** Each call runs with a private HOME, temporary directory and working directory, which are deleted afterward. agy still authenticates through the system keyring, which aipmt never reads. Nothing is inherited: neither the user's permissions — which allowed the default agent to run `ls` and `git` without asking — nor their global rules, plugins, MCP servers, hooks and skills. And nothing is added to their history, where each call used to leave a conversation of about 200 KB, including the translated text: the probe campaign had left about 95 conversations there and evicted 17 entries from a cache capped at 100. Verified: no files written to `~/.gemini/antigravity-cli`.

  - **Fail closed where isolation would not hold.** On Linux without a D-Bus session bus — an SSH session, container or server — agy stores its token in a file under `~/.gemini` instead of the keyring, as its own changelog (1.1.3) states, and per-call isolation hides that file. The refusal now comes before any launch, with the actual cause, instead of a minute spent waiting for a login code followed by advice to reconnect that would solve nothing. On Windows, agy reads `USERPROFILE`, `APPDATA` and `TEMP`, not `HOME` or `TMPDIR` — according to the Go documentation and strings in the binary — so nothing there would isolate the call from the user's settings or history, and `--use_antigravity` is refused there until this has been measured. macOS passes, without having been measured; the billing guard, which reads the effective configuration, holds there.

  - **`exit 0` proves nothing, fourth CLI.** A response is accepted only with a zero exit code, a JSON object with status `SUCCESS`, a compliant log, no denied action, command or error in the JSON, no truncation warning on stderr, and nonempty text. `--print-timeout` is never used: when it expires, agy returns partial output as `SUCCESS`, exit code 0; the timeout is external and kills the process group. A segment starting with `/commande`, `!commande` or `@fichier` is translated, never executed or resolved — without `--disable-slash-commands`, “/help” ran instead of being translated. A whitespace-only segment no longer reaches agy, as the pipeline returns it unchanged (see below), and is still rejected before the call as a final safeguard: on empty input, agy opens its interactive interface with exit code 0. Retries follow the `retryable` field of the `AGY_ERROR` line that agy has written to stderr since 1.2.6: it already retries transient errors itself — 502, 503, 504, per-minute limits — and it knows whether the remaining failure is still transient. Without this field, there is no retry when the message refers to exhaustion — at Google, `RESOURCE_EXHAUSTED` carries the same 429 code as a per-minute limit, but an exhausted 5-hour window does not recover in 90 seconds — and otherwise only for rate limiting. The response preserves the segment's line ending: agy always ends its own with a newline, which, at the join, split a paragraph in two when it had been segmented mid-sentence. A disconnected session produces a message saying to run `agy` to reconnect. - **1.13.0** `--use_openrouter` provider: a paid router to ~430 models, including open Chinese models (2026-09-05):
  - **Ninth provider path, shipped with the eighth.** 1.12.0 was not published on PyPI: the two routers, OpenCode and OpenRouter, are released together. Since the endpoint is OpenAI-compatible, the client is the same as for xAI; **everything that distinguishes this provider fits into a preflight**, and each of its rules comes from a measurement against the API.

  - **The same model is served by dozens of hosts with different limits, and routing is blind to them.** Measured: 33 hosts for `z-ai/glm-5.2`, 23 for `z-ai/glm-5.3-flash` — including one capped at **2 048 output tokens**. One long translation in 23 would therefore come back truncated, at random, without any signal. The preflight reads `/api/v1/models/{modèle}/endpoints`, excludes hosts below 8 000 output tokens, those with degraded status, and those that declare no limit, then pins the others. `provider.only` **without** `allow_fallbacks: false` is merely a preference: the router falls back to an excluded host, and pinning becomes worthless. If no host meets the limit, the command stops: translating anyway would mean accepting the silent truncation this preflight exists to prevent.

  - **Reasoning is billed at the output rate, and enabled by default on many models.** Same request on `z-ai/glm-5.2`, response “OK”: **107 completion tokens with the model default, 2 with reasoning disabled**. For a translation, where reasoning adds nothing, that is a factor of 18 on every segment of every file. It is therefore disabled by default. The **288 models out of 431** that require it (`reasoning.mandatory`) return `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: for those, the preflight reads the accepted effort levels and requests the lowest (next bullet) — effort allocates a **percentage of `max_tokens`** that reasoning consumes first, so a randomly chosen value shifts the risk of a blank response instead of reducing it.
