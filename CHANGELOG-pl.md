- **1.16.3** Koniec pliku: tłumaczenie przez API zachowuje końcowy znak nowego wiersza źródła, a SDK 3.0 Mistral zostało zweryfikowane (2026-10-04):

  - **Tłumaczenie przez API zachowuje końcowy znak nowego wiersza źródła.** Providerzy API — OpenAI, Anthropic, Gemini, Mistral — usuwają z odpowiedzi modelu otaczające ją białe znaki. W ostatnim segmencie to czyszczenie usuwało końcowy znak nowego wiersza źródła: przetłumaczony plik bez noty o tłumaczeniu kończył się bez znaku nowego wiersza, co zgłasza git i co formatery poprawiają przy każdym uruchomieniu. Zauważono to podczas weryfikowania SDK 3.0 Mistral na przewodniku zakończonym znakiem nowego wiersza, którego tłumaczenie już go nie miało. Nota o tłumaczeniu przywracała ten znak, a providerzy wiersza poleceń — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — kopiują zakończenie segmentu: problem dotyczył wyłącznie tłumaczenia przez API bez noty. Tłumaczenie zachowuje teraz końcowy znak nowego wiersza źródła niezależnie od providera i nie dodaje go do źródła, które go nie ma.

  - **Mistral: SDK 3.0 zweryfikowane rzeczywistym wywołaniem.** `mistralai` 3.0.0 zastępuje bibliotekę HTTP `httpx` biblioteką `httpx2`; importy i wywołanie tłumaczenia pozostają bez zmian. Nowa instalacja aipmt już je otrzymywała, ponieważ zależności nie mają górnej granicy wersji, ale nie sprawdzono go dotąd żadnym rzeczywistym wywołaniem: przewodnik Markdown przetłumaczony przez API Mistral przy użyciu SDK 3.0 zachowuje strukturę identyczną ze źródłem. Wersje przypięte na potrzeby rozwoju zostały zaktualizowane do tego SDK, a testy ponawiania prób przekazują mu klienta `httpx2`, którego używa w środowisku produkcyjnym.

- **1.16.2** Ochrona kodu: kod przytoczony w cytacie `--news` oraz wcięty blok w liście nie powodują już odrzucenia tłumaczenia wszystkich języków (2026-10-03):

  - **Kod przytoczony w cytacie nie blokuje już tłumaczenia.** W trybie `--news` aipmt chroni kod inline przed odłożeniem na bok cytatów w języku angielskim, które są później przywracane bez zmian. Kod umieszczony w cytacie był więc odkładany razem z nim: model nigdy nie widział jego tokenu, a walidacja uznawała go za utracony we wszystkich językach. Codzienny monitoring wiadomości autora zatrzymał się na tym 2 października: polecenie `/plugin enable …` przytoczone w tweecie, język kontrolny odrzucony dwukrotnie, pozostałe trzynaście nigdy nie zostało uruchomionych. Tokeny zabrane wraz z cytatem są teraz rozpoznawane w odłożonym tekście. W przypadku języka docelowego angielskiego francuski wiersz tłumaczenia cytatu nie jest już wysyłany do modelu: instrukcja nakazywała mu go usunąć, a zawarty w nim kod był następnie uznawany za utracony, mimo że model wykonał polecenie. Opublikowany wynik pozostaje bez zmian. Ponadto przywracanie cytatu nie interpretuje już ponownie jego ukośników odwrotnych: przytoczony `\n` pozostaje `\n`. Zweryfikowano od początku do końca na artykule, którego przetwarzanie wcześniej się nie powiodło: tłumaczenia angielskie i niemieckie wykonane za pierwszym razem przez `gpt-6.1-sol`, ze strukturą identyczną z opublikowanymi wersjami.

  - **Wcięty blok kodu w liście jest chroniony.** CommonMark zezwala na przesunięte zamknięcie bloku i jest to normalny przypadek bloku dokumentującego krok listy numerowanej: należy on do elementu listy, więc jest wcięty. Wzorzec ochrony zakotwiczony w kolumnie 0 pomijał je wszystkie: w rzeczywistym pliku README wykrywał 8 bloków z 14. Pozostałe sześć trafiało do modelu jako proza i wracało bez zmian, ponieważ były poleceniami, a mechanizm ochronny odrzucający tłumaczenie skopiowane bez zmian odrzucał plik dla wszystkich języków, komunikatem wskazującym objaw, ale nigdy przyczynę. Wzorzec dopuszcza teraz wcięte zamknięcie, a cykl ochrony i przywracania odtwarza dokument identycznie, łącznie z wcięciami.

- **1.16.1** Linki wewnętrzne: token kotwicy pozostawia nawiasy linkowi, a przetłumaczony link nie jest już po cichu dublowany (2026-09-27):

  - **Link wewnętrzny nie psuje się już niezauważenie.** Aby chronić link do sekcji, `[texte](#ancre)`, aipmt zastępował jego część w nawiasach, łącznie z nawiasami, tokenem: model otrzymywał nawiasy kwadratowe, po których następował nieopakowany token, czyli pozornie uszkodzony link, i zdarzało mu się go „naprawiać”. Po przywróceniu powstawał wtedy `[texte]((#ancre))`, link prowadzący donikąd, czego nie wykrywał żaden mechanizm ochronny. Błąd powracał przy każdym ponownym generowaniu tłumaczeń tego repozytorium — po hiszpańsku, koreańsku, a następnie włosku dla wersji 1.15.0 oraz po niemiecku dla wersji 1.16.0 — z każdym wypróbowanym Gemini Flash, a nawet z Claude Sonnet i Haiku. Token linku Markdown zachowuje teraz nawiasy: model otrzymuje prawidłowy link, którego nie ma już powodu naprawiać, a przywracanie akceptuje również token, z którego model usunąłby nawiasy. Kotwice HTML zachowują nieopakowany token. Zweryfikowano od początku do końca przy użyciu najbardziej zawodnego modelu, `gemini-3.8-flash-low`, na pliku README, w którym jeden link znajdował się w nawiasach: bez poprawki plik README został odrzucony, trzy linki zdublowane, a jeden segment przetworzony ponownie; z poprawką wszystkie trzy linki pozostały nienaruszone, bez żadnych powtórek. Następnie na tym pliku README, po niemiecku, japońsku i w hindi przez `gemini-3.8-flash-medium` oraz po niemiecku przez Claude Code z `sonnet`: struktura identyczna ze źródłem, wszystkie trzy linki wewnętrzne wszędzie nienaruszone.

  - **Testy nie mogą już modyfikować repozytorium, które je uruchamia.** Podczas wysyłania zmian z powiązanego worktree git przekazuje swoim hookom zmienną wskazującą repozytorium, a hook pre-push uruchamia testy: `git init` jednego z testów, przeznaczony dla katalogu tymczasowego, zresetował prawdziwe repozytorium, które nagle zostało uznane za pozbawione drzewa roboczego. Testy uruchamiające git usuwają teraz ze swojego środowiska wszystkie zmienne `GIT_*`, a test regresji wskazujący za pomocą tej zmiennej repozytorium-wabik potwierdza to zachowanie.

- **1.16.0** Provider `--use_claude_code`: tłumaczenie w ramach limitu subskrypcji Claude Pro lub Max za pośrednictwem oficjalnego CLI `claude -p` — bez żadnej płatnej ścieżki, czego dowodzi każde wywołanie (2026-09-26):

  - **Jedenasta ścieżka: subskrypcja Claude bez rozliczeń za użycie.** `--use_claude_code` steruje oficjalnym programem wykonywalnym Claude Code w trybie `-p`, na tej samej podstawie co Codex, Grok CLI i Antigravity — osobna grupa procesów, bezpieczne zatrzymanie po przekroczeniu limitu czasu, naciśnięciu Ctrl-C lub zamknięciu terminala. Nie należy mylić go z `--use_claude`, API Anthropic rozliczanym za użycie. aipmt nigdy nie odczytuje tokenu.

  - **Żadnej płatnej ścieżki, co zweryfikowano na trzech poziomach.** Środowisko podprocesu jest listą dozwolonych elementów: bez klucza API, tokenu, dostawcy chmurowego ani znacznika sesji Claude Code, z której uruchomiono by aipmt — sesja, w której napisano ten provider, eksportowała ich piętnaście. Preflight, bez uruchamiania modelu, wymaga od `claude auth status` połączenia subskrypcyjnego bez klucza Console, a od `/usage` frazy potwierdzającej subskrypcję. Następnie każde wywołanie musi potwierdzić ją w zdarzeniu inicjalizacji — `apiKeySource: none`, wymuszone środowisko zostało prawidłowo odebrane, model należy do żądanej rodziny, brak trybu szybkiego — oraz w raporcie limitu: płatne „extra usage” natychmiast zatrzymuje tłumaczenie.

  - **Limit jest współdzielony z sesjami Claude Code, a provider korzysta z niego oszczędnie.** Każde wywołanie raportuje wykorzystanie pięciogodzinnych i tygodniowych okien; powyżej 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`) nie jest uruchamiany żaden kolejny segment. W dniu powstania tej funkcji tygodniowy limit konta autora był już wykorzystany w 98%.

  - **Nic z konfiguracji użytkownika nie przenika do środka i nic z sesji nie pozostaje.** Bez narzędzi, w trybie bez personalizacji, z ignorowanymi ustawieniami użytkownika, wyłączonymi serwerami MCP i hookami, prywatnym i jednorazowym katalogiem roboczym oraz bez zachowywania transkrypcji. Zmierzono za pomocą kanarków: bez `CLAUDE_CODE_DISABLE_ATTACHMENTS` element `@chemin` z dokumentu stawał się załącznikiem, a model zwracał wywołanie odczytu zamiast tłumaczenia; z nim nic nie przenika. Kanarki `AGENTS.md`, `CLAUDE.md` i hook nie zostały ani załadowane, ani wykonane.

  - **Segment zaczynający się od `/` nie docierał do modelu.** W trybie `--disable-slash-commands` Claude Code sam odpowiada na niego „… isn't available in this environment.” ze statusem `success`, bez ani jednej tury. Znak nowego wiersza przed segmentem wysyła go do modelu; kontrakt wyjściowy i tak odrzuca odpowiedź zwróconą bez tury, po więcej niż jednej turze, uciętą albo przez inny model niż zapowiedziany.

  - **Modele: aliasy, nigdy przypięty identyfikator.** Domyślnie `sonnet`, z poziomem wysiłku `low`, również w `--eco` — `--eco` nic więc nie zmienia na tej ścieżce — oraz `opus` i `haiku` przez `--model`; `fable` i warianty `[1m]` są odrzucane, ponieważ w `-p` bez pytania przechodzą na płatne kredyty.

  - **Wartości domyślne są mierzone, a nie zakładane.** Za pomocą samego `aipmt --use_claude_code`, cztery równoległe tłumaczenia dwóch dokumentów używanych do pomiarów w README — obszernego artykułu przeglądowego w `--news` oraz tego pliku README w rewizji 1.14.0 — po czternaście języków każdy. `sonnet`, z poziomem wysiłku `low`, tworzy wszystkie 28 tłumaczeń, z czego 26 bez odchyleń: jedno dodatkowe pogrubione słowo w chińskiej wersji artykułu oraz, w arabskiej wersji README, wiersz tabeli sklejony z poprzednim, co jest niewidoczne podczas wyświetlania. Linki wewnętrzne pozostają nienaruszone, angielskie cytaty są kopiowane bez zmian, a w wersji angielskiej francuskie wiersze tłumaczeń są usuwane przez model bez wymyślonej flagi; mediana wynosi 6 min 49 s na język dla artykułu i 2 min 20 s dla README. `opus` tłumaczy README bez żadnych odchyleń, o jedną czwartą szybciej, ale nie tłumaczy żadnego artykułu: jego mechanizmy ochronne zatrzymały odpowiedź we wszystkich czternastu językach na krótkiej wiadomości biologicznej. `haiku` tworzy wszystko — trzy tytuły sekcji artykułu zmienione na poziom 1, wewnętrzne linki angielskiego README zdublowane — ale dwukrotnie wolniej niż `sonnet`: prowadzi rozumowanie, którego nie da się wyłączyć, stanowiące 61% jego tokenów wyjściowych, a jego niższa cena daje tylko 14% oszczędności w przeliczeniu na API. Stąd `sonnet` również w `--eco`. Wysiłek nie daje nic w tłumaczeniu: we wcześniejszej partii — ten README i ten CHANGELOG po angielsku, japońsku i w hindi — `sonnet` nie wygenerował żadnego tokenu rozumowania, `opus` przy średnim wysiłku przeznaczył na nie 1% tokenów wyjściowych, a średni wysiłek nie przyniósł żadnej korzyści względem niskiego ani pod względem struktury, ani czasu. Kampania `sonnet`, obejmująca 1,8 miliona znaków źródłowych, zużyła 9 punktów pięciogodzinnego okna i 2 punkty tygodniowego limitu w subskrypcji Max autora — jest to górne ograniczenie, ponieważ sesja sterująca pomiarami korzystała z tego samego limitu.

  - **Odmowa mechanizmów ochronnych Anthropic jest nazywana wprost.** Opus 5.5 ma bardziej rygorystyczne mechanizmy ochronne niż Sonnet, a komunikat błędu Anthropic ostrzega, że czasami oznaczają one prace zbliżone do badań biologicznych. Wystarczyła krótka wiadomość przeglądowa o 279 cząsteczkach wygenerowanych dla miejsca wiązania. Claude Code ucina wtedy odpowiedź, ponawia próbę raz, a model zwraca „I can't continue this translation” ze statusem sukcesu, bez błędu, w dwóch turach: jedynie kontrakt pojedynczej tury zatrzymywał tę odpowiedź, komunikatem przemilczającym przyczynę. Wysłana samodzielnie wiadomość zostaje odrzucona przez API w kategorii „bio”. aipmt rozpoznaje teraz te oznaki, wskazuje mechanizmy ochronne i ich kategorię, nie ponawia próby — ten sam tekst wywołałby ponownie tę samą odmowę — i zaleca `--model sonnet`, który przetłumaczył wiadomość na wszystkie czternaście języków.

  - **Tłumaczenia tego repozytorium mogą korzystać z tej ścieżki bez wyjątku.** `REGEN_PROVIDER=claude_code` jest subskrypcją, a nie API rozliczanym za użycie: działa bez `REGEN_ALLOW_PAID_API`, z czterema zadaniami — kampanie działały z czterema równoczesnymi tłumaczeniami bez ani jednego błędu limitu przepustowości lub blokady połączenia — po pojedynczym preflight, który nie zużywa żadnego limitu. Domyślną opcją pozostaje Codex z `gpt-5.6-sol`.

  - **Warunki użytkowania przedstawione bez ogródek.** Strona prawna Claude Code nie zabrania użytkownikowi logowania się do niezmodyfikowanego programu wykonywalnego za pomocą własnej subskrypcji; zabrania zewnętrznym deweloperom przekazywania zapytań przez dane uwierzytelniające Pro lub Max swoich użytkowników, a Anthropic preferuje klucz API dla narzędzi zewnętrznych, w tym projektów open source, zastrzegając sobie prawo do rozliczania ich użycia w ramach płatnych kredytów. Żaden dokument nie rozstrzyga przypadku rozpowszechnianego narzędzia uruchamiającego oficjalny program wykonywalny: użytkownik angażuje własne konto.

  - **Testy**: nowy plik `tests/test_claude_code_provider.py` (58 testów), 100% pokrycia instrukcji i gałęzi modułu, bez uruchamiania prawdziwego `claude` — wyczyszczone środowisko, nieistniejący program wykonywalny, `PATH` bez `claude`, atrapy zgłaszające wyjątek w razie wywołania.

- **1.15.0** Provider `--use_antigravity`: tłumaczenie w ramach limitu subskrypcji Google AI Pro lub Ultra przez oficjalny CLI `agy`; a ponadto dla wszystkich providerów Ctrl-C nie pozostawia już działającego agenta, pusty segment nie powoduje już niepowodzenia całego pliku, a projektowy `.env` nie wybiera już wykonywanego programu (2026-09-26):

  - **Dziesiąta ścieżka providera: subskrypcja Google bez rozliczeń za użycie.** Osoby płacące za Google AI Pro lub Ultra mogą teraz rozliczać tłumaczenia w ramach tej subskrypcji zamiast płacić za tokeny w API Gemini. `agy`, oficjalny CLI Antigravity, jest jedyną ścieżką do tego limitu: Gemini CLI od 18 czerwca 2026 r. nie obsługuje już kont Pro, Ultra ani bezpłatnych, a SDK Antigravity uwierzytelnia się wyłącznie za pomocą klucza API lub Google Cloud. `--use_antigravity` steruje nim w trybie headless, tak jak Codex i Grok CLI, na tej samej podstawie — osobna grupa procesów, `SIGTERM`, a następnie `SIGKILL` po przekroczeniu limitu czasu, oczyszczone środowisko. Zweryfikowano od początku do końca na agy 1.2.11: przewodnik Markdown — front matter, pogrubienie, link z nawiasami, kod inline, wcięty blok kodu w liście, tabela, cytat — przetłumaczony na angielski w 14 sekund, łącznie z preflight, ze strukturą identyczną ze źródłem i dodaną notą o tłumaczeniu; następnie, po poprawkach z przeglądu, na niemiecki w 19 sekund, z identyczną strukturą i bez zapisania czegokolwiek w `~/.gemini`.
  - **Żadna płatna ścieżka nie pozostaje otwarta, a każde uruchomienie to sprawdza.** agy zna inne ścieżki niż subskrypcja — klucz API, projekt Google Cloud, bramę, płatne kredyty AI — a kilka zmiennych środowiskowych przełącza go na nie bez wyświetlania czegokolwiek. Ustalono pomiarowo: `AGY_GATEWAY_URL` wysyła dokument do zewnętrznej bramy, `AGY_ADC_AUTH` przełącza na rozliczany projekt Google Cloud, `CLOUD_CODE_URL` przekierowuje uwierzytelniony endpoint pod dowolny adres. Środowisko podprocesu jest więc listą dozwolonych elementów, a nie listą blokad: `PATH`, język i strefa czasowa, terminal, tożsamość, proxy i certyfikaty maszyny oraz magistrala sesji — czyli to, czego potrzeby po stronie agy dowiódł `env -i` — bez żadnego klucza. Wypróbowana najpierw lista blokad według rodzin prefiksów (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…) pomijała niektóre przypadki: przegląd wykrył w ciągach znaków pliku binarnego nadpisania endpointów, których nie obejmował żaden prefiks: `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Dwa ustawienia wymykają się środowisku i można je odczytać wyłącznie przez `agy -p /config`: płatne kredyty AI, które przejmują obsługę po wyczerpaniu limitu, oraz połączenie przez projekt Google Cloud. Preflight, który nie zużywa żadnego limitu — zmierzone zużycie wynosi zero — odmawia tłumaczenia, jeśli którekolwiek z nich jest aktywne lub skonfigurowano klucz API, a brak ustawienia w `/config` oznacza odmowę dla każdego z tych trzech przypadków: wersja agy, która zmieniłaby nazwę któregoś z nich, nie może przejść kontroli, która niczego nie zweryfikowała. Wreszcie dziennik każdego wywołania musi potwierdzać uwierzytelnienie przez subskrypcję (`authMethod=consumer`), a każda inna widniejąca w nim metoda uwierzytelnienia, zapisana w którejkolwiek z dwóch form używanych przez plik binarny, powoduje odrzucenie odpowiedzi: rozstrzygające jest samo wywołanie, a nie przygotowana konfiguracja.

  - **Agent tłumaczący nie ma żadnych narzędzi, a jego załadowanie jest potwierdzane przy każdym wywołaniu.** Każde wywołanie zapisuje w jednorazowym katalogu agenta w formacie agentów projektowych agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Około 800 tokenów wejściowych zamiast 12 400 z agentem domyślnym, a trzecie ustawienie nie jest zbędne: samo `excludeDefaultComponents` nadal pozwalało hookowi workspace wykonywać polecenia i wstrzykiwać tekst. Prawdziwa pułapka leży gdzie indziej: brak agenta nie powoduje błędu agy. Kod wyjścia 0, status `SUCCESS`, a odpowiedzi udziela agent programistyczny z 57 aktywnymi narzędziami — na „Kot śpi.” odpowiedział: „Ciii, nie budźmy go! 🐱💤 Co mogę dziś dla Ciebie zrobić?”. Ani stdout, ani stderr niczego nie ujawniają: informuje o tym wyłącznie dziennik wywołania. Odpowiedź jest więc odrzucana, jeśli dziennik informuje o tym przełączeniu awaryjnym, a także jeśli nie zawiera pozytywnego znacznika załadowania agenta — zmiana formatu dziennika powoduje odrzucenie tłumaczenia, zamiast po cichu wyłączać zabezpieczenie. Każdy znacznik musi zajmować cały wiersz dziennika w ustalonym pomiarowo formacie — poziom ważności, data, godzina, wątek, plik i wiersz: plik binarny zawiera również wiersz kopiujący wiadomość użytkownika do dziennika — nigdy niewidziany przy domyślnym poziomie logowania w 78 rzeczywistych dziennikach — a dokument cytujący te komunikaty nie może spełnić zabezpieczenia zamiast agy.

  - **Ustawienia ani historia agy użytkownika nie są naruszane.** Każde wywołanie działa z prywatnymi katalogami HOME, tymczasowym i roboczym, które są następnie usuwane. agy nadal się uwierzytelnia za pośrednictwem systemowego magazynu kluczy, którego aipmt nigdy nie odczytuje. Nic nie jest dziedziczone: ani uprawnienia użytkownika — pozwalające domyślnemu agentowi uruchamiać `ls` i `git` bez pytania — ani jego reguły globalne, pluginy, serwery MCP, hooki i skills. Nic nie jest też dodawane do jego historii, w której każde wywołanie pozostawiało rozmowę o rozmiarze około 200 KB, łącznie z przetłumaczonym tekstem: kampania prób pozostawiła w niej około 95 rozmów i wyparła 17 wpisów z cache ograniczonego do 100. Zweryfikowano: w `~/.gemini/antigravity-cli` nie zapisano żadnego pliku.

  - **Bezpieczna odmowa tam, gdzie izolacja nie byłaby skuteczna.** W systemie Linux bez magistrali sesji D-Bus — sesja SSH, kontener, serwer — agy przechowuje token w pliku w `~/.gemini` zamiast w magazynie kluczy, jak podaje jego własny changelog (1.1.3), a izolacja każdego wywołania ukrywa ten plik. Odmowa następuje teraz przed jakimkolwiek uruchomieniem i podaje rzeczywistą przyczynę, zamiast czekać minutę na kod logowania, a następnie zalecać ponowne połączenie, które niczego by nie rozwiązało. W systemie Windows agy odczytuje `USERPROFILE`, `APPDATA` i `TEMP`, a nie `HOME` ani `TMPDIR` — według dokumentacji Go i ciągów znaków pliku binarnego: nic nie izolowałoby tam wywołania od ustawień ani historii użytkownika, dlatego `--use_antigravity` jest tam odrzucany, dopóki nie zostanie to zmierzone. macOS przechodzi kontrolę, choć nie został pomiarowo sprawdzony; zabezpieczenie przed naliczaniem opłat, które odczytuje efektywną konfigurację, działa również tam.

  - **`exit 0` niczego nie dowodzi — dotyczy to wszystkich czterech CLI.** Odpowiedź jest akceptowana wyłącznie przy zerowym kodzie wyjścia, obiekcie JSON ze statusem `SUCCESS`, zgodnym dzienniku, braku odrzuconej akcji, polecenia i błędu w JSON, braku ostrzeżenia o obcięciu na stderr oraz niepustym tekście. `--print-timeout` nigdy nie jest używany: po jego upływie agy zwraca częściowe wyjście w `SUCCESS` z kodem 0; limit czasu jest zewnętrzny i zabija grupę procesów. Segment zaczynający się od `/commande`, `!commande` lub `@fichier` jest tłumaczony, a nigdy wykonywany ani rozwiązywany — bez `--disable-slash-commands` zamiast tłumaczenia wykonywane było „/help”. Biały segment nie dociera już do agy, ponieważ pipeline zwraca go bez zmian (patrz niżej), a jako ostatnie zabezpieczenie nadal jest odrzucany przed wywołaniem: przy pustym wejściu agy otwiera interaktywny interfejs z kodem 0. Ponowna próba opiera się na polu `retryable` z wiersza `AGY_ERROR`, który agy zapisuje na stderr od wersji 1.2.6: sam ponawia już przejściowe błędy — 502, 503, 504, limit minutowy — i to on wie, czy pozostały błąd nadal jest przejściowy. Jeśli tego pola brakuje, nie ma ponownej próby, gdy komunikat mówi o wyczerpaniu — w Google `RESOURCE_EXHAUSTED` ma ten sam kod 429 co limit minutowy, ale wyczerpanie 5-godzinnego okna nie ustąpi w ciągu 90 sekund — a w innych przypadkach ponowienie następuje wyłącznie przy ograniczeniu przepustowości. Odpowiedź zachowuje zakończenie wiersza segmentu: agy zawsze kończy swoją odpowiedź znakiem nowego wiersza, który na styku dzielił na dwie części akapit rozcięty w środku zdania. Rozłączona sesja generuje komunikat zalecający uruchomienie `agy` w celu ponownego połączenia. `AGY_CLI_DISABLE_AUTO_UPDATE=true` zapobiega wreszcie uruchamianiu przy każdym wywołaniu z nowym HOME mechanizmu sprawdzania aktualizacji we własnej sesji, poza zasięgiem limitu czasu — wartość `1` nie daje żadnego efektu.

Atrapy `Popen`, których nie należy używać, kończą się teraz jednoznacznym błędem, fałszywe procesy otrzymują niemożliwy pid, a kampanie mutacji działają w przestrzeni nazw PID.

- **1.13.0** Provider `--use_openrouter`: płatny router zapewniający dostęp do około 430 modeli, w tym otwartych modeli chińskich (2026-09-05):

  - **Dziewiąta ścieżka providera, dostarczona wraz z ósmą.** Wersja 1.12.0 nie została opublikowana w PyPI: oba routery, OpenCode i OpenRouter, ukazują się razem. [OpenRouter](https://openrouter.ai) zapewnia za pomocą jednego klucza dostęp do modeli, których nie udostępnia tutaj żaden inny provider — Kimi, Qwen, DeepSeek, Z.ai — w ramach jednego salda rozliczanego według użycia. Ponieważ endpoint jest zgodny z OpenAI, używany jest ten sam klient co dla xAI; **wszystkie różnice tego providera mieszczą się w preflight**, a każda z jego reguł wynika z pomiarów API.

  - **Ten sam model jest obsługiwany przez dziesiątki hosterów o różnych limitach, a routing tego nie uwzględnia.** Pomiary wykazały: 33 hosterów dla `z-ai/glm-5.2`, 23 dla `z-ai/glm-5.3-flash` — w tym jeden z limitem **2 048 tokenów wyjściowych**. Długie tłumaczenie wykonywane przez jednego z 23 hosterów mogło więc zostać losowo ucięte bez najmniejszego ostrzeżenia. Preflight odczytuje `/api/v1/models/{modèle}/endpoints`, wyklucza hosterów z limitem poniżej 8 000 tokenów wyjściowych, ze statusem ograniczonej sprawności oraz tych, którzy nie deklarują żadnego limitu, a następnie przypina pozostałych. `provider.only` **bez** `allow_fallbacks: false` jest jedynie preferencją: router przełącza się na wykluczonego hostera, przez co przypięcie traci sens. Jeśli żaden hoster nie spełnia limitu, polecenie zostaje zatrzymane: kontynuowanie tłumaczenia oznaczałoby zaakceptowanie cichego ucięcia, któremu ten preflight ma zapobiegać.

  - **Rozumowanie jest rozliczane według stawki za tokeny wyjściowe i w wielu modelach jest domyślnie aktywne.** To samo żądanie do `z-ai/glm-5.2`, odpowiedź „OK”: **107 tokenów uzupełnienia przy domyślnych ustawieniach modelu, 2 po wyłączeniu rozumowania**. W tłumaczeniu, w którym rozumowanie niczego nie wnosi, oznacza to 18-krotny wzrost dla każdego segmentu każdego pliku. Dlatego jest ono domyślnie wyłączone. **288 z 431 modeli**, które go wymagają (`reasoning.mandatory`), odpowiada kodem `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: w ich przypadku preflight odczytuje akceptowane poziomy wysiłku i żąda najniższego z nich (następny punkt) — poziom wysiłku przydziela **procent wartości `max_tokens`**, który rozumowanie zużywa jako pierwszy, dlatego arbitralnie wybrana wartość jedynie przenosi ryzyko pustej strony, zamiast je zmniejszać.

  - **Model wymagający rozumowania otrzymuje najniższy akceptowany poziom wysiłku, a zdecydowano o tym na podstawie pomiaru.** Pierwszym wyborem było niewysyłanie żadnej wartości, aby nie zgadywać za model. Test na `z-ai/glm-5.3-flash`, którego katalogową wartością domyślną jest `max`, wykazał, że taki wybór prowadził do **ucięcia wyjścia przy 32 768 tokenach** przed końcem tłumaczenia — utracono dwa z czternastu języków. Zwiększenie limitu niczego by nie zmieniło: poziom wysiłku przydziela jego procent, więc rozumowanie rośnie razem z nim. Provider odczytuje zatem `supported_efforts` podczas preflight i żąda najniższej wartości, a gdy katalog nie podaje żadnej użytecznej wartości, nie wysyła niczego. Próba kontrolna dla języka powodującego błąd: wcześniej tłumaczenie kończyło się niepowodzeniem z powodu wyczerpania budżetu, a teraz przechodzi w 9 minut ze strukturą identyczną ze źródłem.

  - **Awaria hostera upstream wskazuje teraz jego nazwę.** Router normalizuje ten przypadek jako `finish_reason=error` z pustym `native_finish_reason` — zmierzono to dwukrotnie, dla dwóch języków, za każdym razem dokładnie po 750 sekundach. Ogólny komunikat skłaniał do szukania błędu w dokumencie lub sposobie podziału; teraz informuje, że awaria wystąpiła po stronie dostawcy i że ponowienie próby często wystarcza.

  - **`finish_reason=length` z pustym wyjściem nie oznacza ucięcia.** Oznacza budżet zużyty przez rozumowanie przed wygenerowaniem pierwszego użytecznego znaku — pomiar wykazał 15 850 tokenów rozumowania wobec 148 użytecznych. Te dwa przypadki wymagają przeciwnych działań: w pierwszym zmniejszenie rozmiaru segmentów nic nie daje. Komunikat wyraźnie je rozróżnia. Dwie pozostałe kontrole również wynikają z pomiarów: gdy hoster upstream ulega awarii, router odpowiada kodem **200 z treścią zawierającą wyłącznie błąd** (`choices[0]` zgłaszał niejasny `TypeError`, który ukrywał komunikat), a okno kontekstu jest odczytywane z katalogu i zapisywane w `MODEL_TOKEN_LIMITS` — `DEFAULT_TOKEN_LIMIT` ma błędną wartość dla 44 modeli w katalogu, w tym dwóch ograniczonych do 4 095 tokenów.

  - **`--model fournisseur/modèle` jest obowiązkowe, a jego format jest sprawdzany przed wykonaniem jakiegokolwiek połączenia sieciowego.** OpenRouter nie jest dostawcą: ten wybór wpływa na cenę, licencję i przetwarzanie danych, więc nie jest podejmowany za użytkownika. Ponieważ slug jest interpolowany w adresie URL preflight, walidacja nie jest wyłącznie uprzejmym udogodnieniem, lecz zabezpieczeniem zapobiegającym wstrzyknięciu ścieżki: wspólne dla obu routerów wyrażenie regularne z przestrzenią nazw akceptuje `a/b/..`, stąd jawne odrzucanie segmentu nadrzędnego. `--eco` nie ma żadnego skutku i jasno o tym informuje.

  - **Poprawiono trzy sformułowania, w tym jedno nieprawdziwe.** Ostrzeżenie OpenAI dotyczące `codex exec` odnosiło się do wstrzyknięcia osobistego pliku sesji na współdzielonym runnerze, a nie do publicznego charakteru repozytorium: w README, CLAUDE.md i kodzie przytaczano je w niewłaściwym znaczeniu. Warstwa bazowa agentowych CLI przechodzi na `terminate`, a następnie `kill` tam, gdzie grupy procesów POSIX nie istnieją, zamiast przepuszczać `AttributeError` przez zabezpieczenie timeoutu i przedłużać oczekiwanie. Marker `429` OpenCode jest wyszukiwany jako liczba, a nie jako podciąg, przez co identyfikator błędu taki jak `err_84290b` powodował wcześniej 90 sekund back-offu, po czym i tak następowała awaria. Wreszcie niekanoniczny endpoint OpenRouter jest wyświetlany podczas preflightu: wystarczy projektowy `.env`, aby go ustawić, a później zostałby do niego wysłany rzeczywisty klucz.
  - **Bezpieczeństwo: projektowy `.env` nie może już przekierowywać wywołań API.** `find_dotenv(usecwd=True)` wyszukuje plik w bieżącym katalogu i jego katalogach nadrzędnych: niezaufane drzewo katalogów — na przykład świeżo sklonowane repozytorium — mogło umieścić w nim `OPENROUTER_BASE_URL`, `XAI_BASE_URL` lub `OPENAI_BASE_URL` (ten ostatni odczytywany przez samo SDK), nie znając żadnego klucza, po czym rzeczywisty klucz pochodzący ze środowiska lub konfiguracji użytkownika trafiał w nagłówku autoryzacji do zewnętrznego serwera. Filtr opiera się na WZORCU, a nie na liście: inwentaryzacja zainstalowanych SDK wykazała dwanaście odczytywanych zmiennych routingu, z czego sześć przez samego klienta Anthropic — ręcznie sporządzone wyliczenie pominęłoby połowę. Z warstwy projektowej odrzucane są zatem wszystkie zmienne w `_BASE_URL`, `_API_BASE` lub `_ENDPOINT`, proxy i magazyny certyfikatów (wskazanie kontrolowanego urzędu sprawia, że interceptor staje się nieodróżnialny od prawdziwego serwera), a także `XDG_CONFIG_HOME` i `APPDATA`: ich ustawienie oznaczało możliwość zdecydowania, który plik stanowi warstwę użytkownika, a tym samym boczne obejście filtra. Zmienne te są akceptowane wyłącznie z dwóch warstw kontrolowanych przez użytkownika: wyeksportowanego środowiska i `~/.config/aipmt/.env`. Warstwa projektowa jest ponadto odczytywana BEZ interpolacji: `load_dotenv` domyślnie rozwija `${VAR}`, a niezaufany `.env` zawierający `NOM_ANODIN=${OPENAI_API_KEY}` kopiował rzeczywisty klucz pod nazwę nierozpoznawaną przez filtrowanie podprocesów oparte na wzorcach — trafiał on następnie do środowiska `codex exec`, wbrew deklarowanemu niezmiennikowi. Komunikat odmowy wyświetla wreszcie wyłącznie nazwę zmiennej: URL w postaci `https://${CLE}@hôte/` powodował wyciek interpolowanego klucza do logów, mimo że sama wartość była odrzucana. Odmowa jest zgłaszana na stderr wraz z instrukcją postępowania — firmowy relay należy zadeklarować w konfiguracji użytkownika.
  - **Poprawka: koperta wyjściowa OpenRouter jest obliczana dla każdego wywołania.** `context_length` obejmuje wejście ORAZ uzupełnienie, a stała rezerwa skalibrowana dla tekstu łacińskiego niczego nie ogranicza: według pomiaru tokenizerem `o200k_base` 16 000 znaków odpowiada 3 200 tokenom po francusku, ale 12 300 po japońsku i 17 500 w przypadku emoji. Budżet wynika więc z rzeczywiście wysyłanego tekstu, powiększonego o jego liczbę bajtów UTF-8: w każdym tokenizerze stosującym scalanie bajtów — BPE na poziomie bajtów, SentencePiece z rezerwowym kodowaniem bajtowym, czyli rodzinach używanych przez modele z katalogu — jeden token odpowiada co najmniej jednemu bajtowi, a to jedyne dostępne tutaj zawyżenie, ponieważ OpenRouter kieruje żądania do dziesiątek nieznanych nam tokenizerów. Żaden średni współczynnik nie był odpowiedni — ideogram z dodatkowej płaszczyzny schodzi do 1,33 bajta na token, a znak łączący do 1,00 — natomiast teraz wejście i wyjście z założenia mieszczą się w oknie. Segment zbyt gęsty dla wybranego modelu jest odrzucany przed wywołaniem, a nie po naliczeniu opłat.
