- **1.17.0** Claude 5.5 przez API: Sonnet 5.5, który odrzucał wyłączone myślenie, staje się obsługiwany w tłumaczeniu i zostaje modelem domyślnym, Haiku 5.5 przejmuje tryb `--eco`; Dependabot działa również w weekendy (2026-10-19):

  - **`--use_claude` tłumaczy z modelami Claude Sonnet 5.5, Opus 5.5 i Fable 5.1.** aipmt wyłączał myślenie Claude za pomocą `thinking: {"type": "disabled"}`, co te trzy modele odrzucają: błąd HTTP 400 już przy pierwszym segmencie, zmierzony w rzeczywistym wywołaniu. aipmt wysyła teraz najniższe ustawienie akceptowane przez dany model, ustalone na podstawie możliwości publikowanych przez API Anthropic: `between_tools` dla Sonnet 5.5, co wyłącza jego wstępne myślenie, oraz brak ustawienia dla Opus 5.5 i Fable 5.x, które myślą wtedy swobodnie. W przypadku jeszcze nieznanego modelu, przy pierwszym odrzuceniu testowane są ustawienia od najbardziej oszczędnego do najbardziej permisywnego, a działające ustawienie jest zachowywane dla kolejnych segmentów — logika stosowana już dla Gemini. Każdy inny błąd jest zgłaszany bez zmian. Cztery modele 5.x trafiają do tabeli okien kontekstu z rozmiarem jednego miliona tokenów.

  - **Claude Sonnet 5.5 staje się domyślnym modelem dla `--use_claude`.** Zmierzone przez sam aipmt na dwóch dokumentach testowych z README — gęstym artykule przeglądowym w `--news` oraz tym README w wersji 1.14.0 —, po czternaście języków każdy: 28 na 28 przetłumaczonych dokumentów zapisanych bez rozbieżności w strukturze, żaden segment nie wymagał powtórzenia, linki wewnętrzne nienaruszone, angielskie cytaty skopiowane bez zmian, a w wersji angielskiej linie francuskiego tłumaczenia usunięte przez sam model. Claude Sonnet 5 osiągał 11 i 12 na 14 przez API na dłuższej wersji tego README oraz 13 i 13 przez Claude Code. Cena nie ulega zmianie: 2 $ i 10 $ za milion tokenów wejściowych i wyjściowych, czyli 9,21 $ za 28 tłumaczeń.

  - **`--eco` przechodzi na Claude Haiku 5.5, z włączonym myśleniem.** Zmierzone na tych samych dokumentach: przy wyłączonym myśleniu Haiku 5.5 pozostawia całe akapity po francusku, co strażnik nieprzetłumaczonych fragmentów odrzuca — zapisano 9 tłumaczeń na 28. Z myśleniem adaptacyjnym zapisuje 26, w tym 23 bez rozbieżności; dwa README zostały odrzucone (w języku arabskim i hindi) z powodu utraconych w odpowiedzi kodów inline. Claude Haiku 4.5, poprzedni model domyślny, zmierzony po raz pierwszy przez API, zapisuje wszystkie 28, ale tylko 21 bez rozbieżności: w artykule zmienił nagłówek na poziom 1 w siedmiu językach, a w języku japońskim pozostawił go po francusku, czego żaden strażnik nie wykrywa. Haiku 5.5 kosztuje 0,57 $ za 28 tłumaczeń w porównaniu do 3,67 $ i działa dwa razy szybciej; aipmt pozwala mu więc myśleć.

  - **Dependabot uruchamia się codziennie, włączając weekendy.** Przy ustawieniu na `daily` działał tylko od poniedziałku do piątku: wersja, której trzydniowy okres karencji upływał w piątek po porannym uruchomieniu, czekała do poniedziałku, a codzienna kontrola aktualności, oparta na jednym uruchomieniu dziennie, uznałaby ją w niedzielę za opóźnioną. 18 października pakiet google-genai 2.30.1 uniknął tego zaledwie o 1 godz. 35 min. Dependabot korzysta teraz z codziennego harmonogramu cron, a test dopasowujący limit czasu kontroli do jego harmonogramu liczy trzy dni dla `daily`: powrót do tego bez wydłużenia limitu powoduje błąd testu.

  - **Weryfikator czystości podziału został usunięty**, zgodnie z planem od wersji 1.13.0. Porównywał on pakiet ze zrzutem wykonanym podczas podziału, a każda zmiana w kodzie musiała deklarować w nim swoje rozbieżności. Rozstrzygnięto dwie kwestie, które automatyczne scalanie pozostawiało otwarte: działa bez dodatkowych uprawnień i nie wyzwala żadnego przepływu pracy push — codzienna kontrola `main` zastępuje go.

- **1.16.3** Koniec pliku: tłumaczenie przez API zachowuje końcowy znak nowej linii ze źródła, a SDK 3.0 Mistral zostało zweryfikowane (2026-10-04):

  - **Tłumaczenie przez API zachowuje końcowy znak nowej linii ze źródła.** Dostawcy API — OpenAI, Anthropic, Gemini, Mistral — oczyszczają odpowiedź modelu z otaczających ją białych znaków. Na ostatnim segmencie to czyszczenie usuwało końcowy znak nowej linii ze źródła: plik przetłumaczony bez noty tłumaczeniowej kończył się bez znaku nowej linii, co zgłasza git i co formatery poprawiają przy każdym uruchomieniu. Zauważono to podczas weryfikacji SDK 3.0 Mistral na przewodniku zakończonym znakiem nowej linii, którego tłumaczenie go utraciło. Nota tłumaczeniowa dodawała go z powrotem, a dostawcy CLI — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — kopiują koniec segmentu: dotyczyło to wyłącznie tłumaczeń przez API bez noty. Tłumaczenie zwraca teraz końcowy znak nowej linii ze źródła niezależnie od dostawcy i nie dodaje go do źródła, które go nie posiada.

  - **Mistral: SDK 3.0 zweryfikowane rzeczywistym wywołaniem.** `mistralai` 3.0.0 zastępuje bibliotekę HTTP `httpx` biblioteką `httpx2`; importy i wywołanie tłumaczenia pozostają bez zmian. Nowa instalacja aipmt już go otrzymywała, ponieważ zależności nie mają górnego limitu wersji, ale żadne rzeczywiste wywołanie jeszcze go nie przetestowało: przewodnik Markdown przetłumaczony przez API Mistral z użyciem SDK 3.0 zachowuje strukturę identyczną ze źródłem. Zablokowane wersje deweloperskie przechodzą na ten SDK, a testy ponawiania dostarczają mu klienta `httpx2`, czyli tego, którego używa w środowisku produkcyjnym.

- **1.16.2** Ochrona kodu: kod zacytowany w cytacie `--news` i wcięty blok w liście nie powodują już odrzucenia tłumaczenia dla wszystkich języków (2026-10-03):

  - **Kod zacytowany w cytacie nie blokuje już tłumaczenia.** W trybie `--news` aipmt chroni kod inline przed odłożeniem angielskich cytatów, przywracanych bez zmian. Kod umieszczony w cytacie trafiał więc razem z nim: model nigdy nie widział jego tokena, a walidacja uznawała go za utracony dla wszystkich języków. Codzienny przegląd aktualności autora zatrzymał się na tym 2 października: polecenie `/plugin enable …` zacytowane w tweecie, język próbny odrzucony dwukrotnie, pozostałe trzynaście nigdy nieuruchomione. Tokeny zabrane przez cytat są teraz rozwiązywane w odłożonym tekście. W przypadku docelowego języka angielskiego linia francuskiego tłumaczenia cytatu nie jest już wysyłana do modelu: instrukcja nakazywała jej usunięcie, a zawarty w niej kod był wówczas uznawany za utracony, mimo że model wykonał polecenie. Opublikowany wynik pozostaje bez zmian. Ponadto przywracanie cytatu nie reinterpretuje już ukośników odwrotnych: cytowane `\n` pozostaje `\n`. Zweryfikowano kompleksowo na artykule, w którym wystąpił błąd: angielski i niemiecki przetłumaczone za pierwszym razem przez `gpt-6.1-sol`, struktura identyczna z opublikowanymi wersjami.

  - **Wcięty blok kodu w liście jest chroniony.** CommonMark dopuszcza przesunięte zamknięcie bloku, co jest standardowym przypadkiem bloku dokumentującego krok w liście numerowanej: należy on do elementu listy, jest więc wcięty. Zakotwiczony w kolumnie 0 wzorzec ochrony pomijał je wszystkie: zmierzone na rzeczywistym README, wykryto 8 bloków na 14. Pozostałe sześć trafiało do modelu jako zwykły tekst i wracało bez zmian (ponieważ są to polecenia), a strażnik odrzucający dosłownie skopiowane tłumaczenie odrzucał plik dla wszystkich języków z komunikatem opisującym objaw, a nie przyczynę. Wzorzec akceptuje teraz wcięte zamknięcie, a pełny cykl ochrony i przywracania zwraca dokument w identycznej postaci, włącznie z wcięciami.

- **1.16.1** Linki wewnętrzne: token kotwicy pozostawia nawiasy linkowi, a przetłumaczony link nie duplikuje się już po cichu (2026-09-27):

  - **Link wewnętrzny nie psuje się już w sposób niezauważony.** Aby chronić link do sekcji, `[texte](#ancre)`, aipmt zastępował jego część w nawiasach okrągłych (wraz z nawiasami) tokenem: model otrzymywał nawiasy kwadratowe, po których następował pojedynczy token — z pozoru uszkodzony link — i zdarzało mu się go „naprawiać”. Przywracanie zwracało wtedy `[texte]((#ancre))`, czyli link prowadzący donikąd, bez ostrzeżenia ze strony strażników. Błąd ten powracał przy każdej regeneracji tłumaczeń tego repozytorium — w języku hiszpańskim, koreańskim, a potem włoskim w wersji 1.15.0, w niemieckim w 1.16.0 — z każdym testowanym modelem Gemini Flash, a nawet z Claude Sonnet i Haiku. Token linku Markdown zachowuje teraz nawiasy: model otrzymuje poprawny link, którego nie ma już powodu poprawiać, a przywracanie akceptuje także token, z którego usunięto nawiasy. Kotwice HTML zachowują pojedynczy token. Zweryfikowano kompleksowo z najbardziej podatnym na błędy modelem, `gemini-3.8-flash-low`, na README, w którym link znajdował się w nawiasach: bez poprawki README odrzucone, trzy zduplikowane linki i jeden powtórzony segment; z poprawką trzy linki nienaruszone na trzy, brak powtórzeń. Następnie na tym README w języku niemieckim, japońskim i hindi za pomocą `gemini-3.8-flash-medium`, oraz w języku niemieckim przez Claude Code z `sonnet`: struktura identyczna ze źródłem, wszystkie trzy linki wewnętrzne nienaruszone wszędzie.

  - **Testy nie mogą już modyfikować repozytorium, które je uruchamia.** Przy wypychaniu zmian z powiązanego drzewa roboczego (worktree) git przekazuje do swoich hooków zmienną wskazującą repozytorium, a hook pre-push uruchamia testy: polecenie `git init` w teście, przeznaczone dla katalogu tymczasowego, zresetowało prawdziwe repozytorium, które nagle zostało uznane za repozytorium bez drzewa roboczego. Testy uruchamiające gita usuwają teraz wszelkie zmienne `GIT_*` ze swojego środowiska, a test regresji wskazujący za pomocą tej zmiennej fałszywe repozytorium to weryfikuje.

- **1.16.0** Dostawca `--use_claude_code`: tłumaczenie w ramach limitu subskrypcji Claude Pro lub Max za pomocą oficjalnego CLI `claude -p` — bez płatnych ścieżek, co potwierdza każde wywołanie (2026-09-26):

  - **Jedenasta ścieżka: subskrypcja Claude, bez rozliczania według zużycia.** `--use_claude_code` steruje oficjalnym plikiem binarnym Claude Code w trybie `-p`, na tej samej bazie co Codex, Grok CLI i Antigravity — własna grupa procesów, bezpieczne zatrzymanie po upływie limitu czasu, Ctrl-C lub zamknięciu terminala. Nie mylić z `--use_claude`, czyli API Anthropic rozliczanym według zużycia. aipmt nigdy nie odczytuje tokena.

  - **Brak płatnych ścieżek, zweryfikowany na trzech poziomach.** Środowisko podprocesu stanowi białą listę: brak klucza API, tokena, dostawcy chmurowego czy znaczników sesji Claude Code, z której uruchomiono aipmt — ta, która utworzyła tego dostawcę, eksportowała ich piętnaście. Test wstępny (preflight), bez wywoływania modelu, wymaga od `claude auth status` połączenia subskrypcyjnego bez klucza Console, a od `/usage` frazy poświadczającej subskrypcję. Każde wywołanie musi następnie potwierdzić to w zdarzeniu inicjalizacji — `apiKeySource: none`, poprawnie odebrane wymuszone środowisko, model z żądanej rodziny, brak trybu szybkiego — oraz w odczycie limitu: płatne „extra usage” natychmiast zatrzymuje tłumaczenie.

  - **Limit jest współdzielony z sesjami Claude Code, a dostawca go oszczędza.** Każde wywołanie raportuje wykorzystanie okien 5-godzinnych i tygodniowych; powyżej 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`) żaden kolejny segment nie jest uruchamiany. W dniu tworzenia kodu tygodniowe zużycie konta autora wynosiło już 98%.

  - **Żadna konfiguracja użytkownika nie przenika, nic z sesji nie pozostaje.** Bez narzędzi, w trybie bez personalizacji, zignorowane ustawienia użytkownika, odłączone serwery MCP i hooki, prywatny i jednorazowy katalog roboczy, brak zapisywanych transkrypcji. Zmierzone za pomocą wartości kontrolnych (canary): bez `CLAUDE_CODE_DISABLE_ATTACHMENTS` element `@chemin` dokumentu stawał się załącznikiem, a model zwracał wywołanie odczytu zamiast tłumaczenia; z tą flagą nic nie przenika. Wartości kontrolne `AGENTS.md`, `CLAUDE.md` i hook niczego nie załadowały ani nie wykonały.

  - **Segment zaczynający się od `/` nie docierał do modelu.** W trybie `--disable-slash-commands` Claude Code sam odpowiada na to „… isn't available in this environment.”, ze statusem `success`, bez żadnej tury modelu. Znak nowej linii przed segmentem przesyła go do modelu; umowa wyjściowa i tak odrzuca odpowiedź zwróconą bez tury, w więcej niż jednej turze, obciętą lub pochodzącą z innego modelu niż zapowiedziany.

  - **Modele: aliasy, nigdy sztywny identyfikator.** `sonnet` domyślnie, z wysiłkiem `low`, a także w trybie `--eco` — `--eco` nie zmienia więc nic na tej ścieżce —, `opus` i `haiku` przez `--model`; `fable` i warianty `[1m]` są odrzucane, ponieważ w `-p` przełączają się na płatne kredyty bez pytania.

  - **Wady są mierzone, a nie zakładane.** Przez sam `aipmt --use_claude_code`, cztery tłumaczenia równolegle, na dwóch dokumentach testowych z README — gęstym artykule przeglądowym w `--news` oraz tym README w wersji 1.14.0 —, po czternaście języków każdy. `sonnet`, przy wysiłku `low`, zapisuje 28 tłumaczeń, 26 bez rozbieżności: jedno dodatkowe pogrubione słowo po chińsku w artykule, a po arabsku w README wiersz tabeli scalony z poprzednim, co maskuje renderowanie. Linki wewnętrzne nienaruszone, angielskie cytaty skopiowane bez zmian, a po angielsku linie francuskiego tłumaczenia usunięte przez model, bez zmyślonych flag; mediana 6 min 49 s na język w artykule, 2 min 20 s w README. `opus` tłumaczy README bez żadnych rozbieżności, o jedną czwartą szybciej, ale ani jednego artykułu: jego mechanizmy zabezpieczające zatrzymały odpowiedź we wszystkich czternastu językach przy krótkiej notatce biologicznej. `haiku` zapisuje wprawdzie wszystko — trzy nagłówki sekcji zmienione na poziom 1 w artykule, linki wewnętrzne w angielskim README zduplikowane —, ale dwa razy wolniej niż `sonnet`: rozumuje bez możliwości wyłączenia tego (61% jego tokenów wyjściowych), a jego niższa cena daje zaledwie 14% oszczędności w przeliczeniu na API. Stąd `sonnet` również w trybie `--eco`. Poziom wysiłku jest bezużyteczny przy tłumaczeniu: na wcześniejszej partii — to README i ten CHANGELOG w języku angielskim, japońskim i hindi — `sonnet` nie wygenerował żadnych tokenów rozumowania, `opus` przy średnim wysiłku wygenerował 1% swoich tokenów wyjściowych, a średni wysiłek nie przyniósł żadnej poprawy względem niskiego, ani pod względem struktury, ani czasu trwania. Kampania `sonnet`, licząca 1,8 miliona znaków źródłowych, zużyła 9 punktów procentowych z 5-godzinnego okna i 2 z okna tygodniowego w subskrypcji Max autora — jest to wartość zawyżona, ponieważ sesja sterująca pomiarami korzystała z tego samego limitu.

  - **Odmowa zabezpieczeń (guardrails) Anthropic jest nazywana wprost.** Opus 5.5 ma bardziej rygorystyczne zabezpieczenia niż Sonnet, a komunikat o błędzie Anthropic ostrzega, że czasami oznaczają one prace zbliżone do badań biologicznych. Wystarczyła krótka notatka przeglądowa o 279 cząsteczkach wygenerowanych dla miejsca wiązania. Claude Code przerywa wtedy odpowiedź, ponawia próbę raz, a model zwraca „I can't continue this translation” ze statusem sukcesu, bez błędu, w dwóch turach: jedynie kontrakt pojedynczej tury zatrzymywał tę odpowiedź, z niemym komunikatem o jej przyczynie. Wysłana samodzielnie notatka zostaje odrzucona przez API w ramach kategorii „bio”. aipmt rozpoznaje teraz te oznaki, nazywa zabezpieczenia i ich kategorię, nie ponawia próby — ten sam tekst wywołałby tę samą odmowę — i zaleca `--model sonnet`, który przetłumaczył notatkę na czternaście języków.

  - **Tłumaczenia tego repozytorium mogą korzystać z tej ścieżki, bez odstępstw.** `REGEN_PROVIDER=claude_code` to subskrypcja, a nie rozliczane API: działa bez `REGEN_ALLOW_PAID_API`, z czterema zadaniami — kampanie działały przy czterech jednoczesnych tłumaczeniach bez ani jednego błędu przepustowości czy blokady połączenia — po pojedynczym preflighcie, który nie zużywa limitu. Domyślnym wyborem pozostaje Codex z `gpt-5.6-sol`.

  - **Warunki użytkowania, ujęte bez ogródek.** Strona prawna Claude Code nie zabrania użytkownikowi łączenia się z niezmodyfikowanym plikiem binarnym za pomocą własnej subskrypcji; zabrania programistom zewnętrznym przesyłania żądań przy użyciu poświadczeń Pro lub Max ich użytkowników, a Anthropic preferuje klucz API w przypadku narzędzi innych firm, w tym projektów open source, zastrzegając sobie prawo do rozliczania ich użycia z płatnych środków. Żaden tekst nie rozstrzyga przypadku dystrybuowanego narzędzia, które uruchamia oficjalny plik binarny: użytkownik podejmuje ryzyko na własnym koncie.

  - **Testy**: nowy plik `tests/test_claude_code_provider.py` (58 testów), 100% instrukcji i gałęzi modułu, bez uruchamiania prawdziwego `claude` — wyczyszczone środowisko, nieistniejący plik binarny, `PATH` bez `claude`, dublerzy zgłaszający wyjątek w razie wywołania.

Preflight odczytuje `/api/v1/models/{modèle}/endpoints`, odrzuca hosty poniżej 8000 tokenów wyjściowych, te o obniżonym statusie oraz te, które nie deklarują żadnego limitu, po czym przypina pozostałe. `provider.only` **bez** `allow_fallbacks: false` to tylko preferencja: router wraca do odrzuconego hosta, a przypięcie traci znaczenie. Jeśli żaden host nie spełnia wymogu limitu, polecenie się zatrzymuje: tłumaczenie mimo to byłoby akceptacją cichego obcięcia, któremu ten preflight ma zapobiegać.

  - **Rozumowanie (reasoning) jest rozliczane według stawki tokenów wyjściowych i domyślnie włączone w wielu modelach.** To samo zapytanie do `z-ai/glm-5.2`, odpowiedź „OK”: **107 tokenów dopełnienia przy ustawieniu domyślnym modelu, 2 z wyłączonym rozumowaniem**. W przypadku tłumaczenia, któremu rozumowanie nic nie daje, jest to 18-krotny wzrost dla każdego segmentu każdego pliku. Jest ono zatem domyślnie wyłączone. **288 modeli na 431**, które je wymuszają (`reasoning.mandatory`), odpowiada `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: w ich przypadku preflight odczytuje akceptowane poziomy nakładu (effort) i żąda najniższego (następny punkt) — poziom nakładu przydziela **procent `max_tokens`**, który rozumowanie zużywa jako pierwsze, przez co losowo dobrana wartość jedynie przesuwa ryzyko pustej strony, zamiast je zmniejszać.

  - **Model, który wymusza rozumowanie, otrzymuje najniższy akceptowany nakład (effort), o czym zadecydował bezpośredni pomiar.** Początkowym wyborem było niewysyłanie niczego, aby nie zgadywać za model. Przetestowany na `z-ai/glm-5.3-flash`, którego domyślną wartością katalogową jest `max`, wybór ten dawał wynik **ucięty przy 32 768 tokenach** przed końcem tłumaczenia — utracono dwa języki na czternaście. Zwiększenie puli niczego by nie zmieniło: nakład przydziela jej określony procent, więc rozumowanie rosłoby razem z nią. Provider odczytuje zatem `supported_efforts` podczas preflightu i żąda najniższego, powracając do braku wartości, gdy katalog nie podaje żadnej zdatnej do użycia. Próba kontrolna na problematycznym języku: wcześniej kończyła się niepowodzeniem z powodu wyczerpania budżetu, teraz przechodzi w 9 minut ze strukturą identyczną jak w źródle.

  - **Awaria hosta nadrzędnego (upstream) jest teraz nazywana po imieniu.** Router normalizuje ten przypadek do `finish_reason=error` z zerowym `native_finish_reason` — zmierzone dwukrotnie, na dwóch językach, dokładnie po 750 sekundach. Ogólny komunikat błędu sugerował szukanie problemu w dokumencie lub w podziale na segmenty; obecnie informuje, że awaria leży po stronie dostawcy i ponowna próba często wystarcza.

- **1.9.2** Poprawka wyodrębniania adresu URL atrybucji wiadomości z zagnieżdżonymi nawiasami lub prefiksem FR (2026-05-11) :

  - **Naprawiony błąd** : wyodrębnianie adresów URL atrybucji w `_protect_news_quotes` wykorzystywało wyrażenie regularne `re.search(r"\((.+?)\)", attribution)` (leniwe przechwytywanie w nawiasach). Przy atrybucji typu `(relayé par [@user sur X](https://x.com/.../123))` (zagnieżdżone nawiasy : obejmujący `(` + `]()` z linku markdown) przechwytywanie zatrzymywało się na pierwszym napotkanym `)` → ciąg ucięty + zawierający prefiks FR : `relayé par [@user sur X](https://x.com/.../123` (bez końcowego `)`). Odporne na oba problematyczne wzorce :
    - `(relayé par [@account sur X](url))` — zagnieżdżone nawiasy
    - `via [@source](url)` lub `selon [@author](url)` — prefiks FR bez obejmujących nawiasów
