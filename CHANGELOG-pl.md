- **1.16.1** Linki wewnętrzne: token kotwicy pozostawia nawiasy przy linku, a przetłumaczony link nie jest już po cichu dublowany (2026-09-27):

  - **Link wewnętrzny nie psuje się już niezauważenie.** Aby chronić link do sekcji, `[texte](#ancre)`, aipmt zastępował jego część w nawiasach, łącznie z samymi nawiasami, tokenem: model otrzymywał nawiasy kwadratowe, po których następował sam token, czyli link wyglądający na uszkodzony, i czasem próbował go „naprawić”. Po przywróceniu powstawał wtedy `[texte]((#ancre))`, link prowadzący donikąd, czego nie wykrywało żadne zabezpieczenie. Usterka powracała przy każdym ponownym generowaniu tłumaczeń tego repozytorium — po hiszpańsku, koreańsku, a następnie włosku dla wersji 1.15.0, po niemiecku dla wersji 1.16.0 — z każdym wypróbowanym Gemini Flash, a nawet z Claude Sonnet i Haiku. Token linku Markdown zachowuje teraz nawiasy: model otrzymuje prawidłowy link, którego nie ma już powodu naprawiać, a przywracanie akceptuje również token, z którego model usunąłby nawiasy. Kotwice HTML zachowują sam token. Zweryfikowano od początku do końca przy użyciu najbardziej zawodnego modelu, `gemini-3.8-flash-low`, na README, w którym link znajdował się w nawiasach: bez poprawki README został odrzucony, trzy linki zdublowane, a jeden segment przetworzony ponownie; z poprawką wszystkie trzy linki pozostały nienaruszone i nie było żadnych ponowień. Następnie sprawdzono ten README po niemiecku, japońsku i w hindi za pomocą `gemini-3.8-flash-medium` oraz po niemiecku przez Claude Code z `sonnet`: struktura wszędzie identyczna ze źródłem, a wszystkie trzy linki wewnętrzne pozostały nienaruszone.

  - **Testy nie mogą już modyfikować repozytorium, z którego są uruchamiane.** Przy wysyłaniu z połączonego worktree git przekazuje swoim hookom zmienną wskazującą repozytorium, a hook pre-push uruchamia testy: `git init` jednego z testów, przeznaczone dla katalogu tymczasowego, zresetowało prawdziwe repozytorium, które nagle zostało zgłoszone jako pozbawione drzewa roboczego. Testy uruchamiające git usuwają teraz ze swojego środowiska wszystkie zmienne `GIT_*`, a test regresji, który za pomocą tej zmiennej wskazuje repozytorium-wabik, to weryfikuje.

- **1.16.0** Provider `--use_claude_code`: tłumaczenie w ramach limitu subskrypcji Claude Pro lub Max za pośrednictwem oficjalnego CLI `claude -p` — bez żadnej płatnej ścieżki, co potwierdza każde wywołanie (2026-09-26):

  - **Jedenasta ścieżka: subskrypcja Claude bez rozliczania za użycie.** `--use_claude_code` steruje oficjalnym plikiem binarnym Claude Code w trybie `-p`, na tej samej bazie co Codex, Grok CLI i Antigravity — osobna grupa procesów, bezpieczne zatrzymanie po przekroczeniu czasu, naciśnięciu Ctrl-C lub zamknięciu terminala. Nie należy mylić tego z `--use_claude`, rozliczanym za użycie API Anthropic. aipmt nigdy nie odczytuje tokenu.

  - **Brak płatnej ścieżki, co zweryfikowano na trzech poziomach.** Środowisko podprocesu jest listą dozwolonych elementów: bez klucza API, tokenu, dostawcy chmurowego ani znacznika sesji Claude Code, z której uruchomiono by aipmt — sesja, w której napisano ten provider, eksportowała ich piętnaście. Preflight, bez tury modelu, wymaga od `claude auth status` połączenia subskrypcyjnego bez klucza Console, a od `/usage` frazy potwierdzającej subskrypcję. Każde wywołanie musi następnie potwierdzić ją w swoim zdarzeniu inicjalizacyjnym — `apiKeySource: none`, prawidłowo odebrane wymuszone środowisko, model z żądanej rodziny, brak trybu szybkiego — oraz w zestawieniu limitu: płatne „extra usage” natychmiast zatrzymuje tłumaczenie.

  - **Limit jest współdzielony z sesjami Claude Code, a provider używa go oszczędnie.** Każde wywołanie raportuje wykorzystanie okien 5-godzinnych i tygodniowych; powyżej 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`) nie jest uruchamiany żaden kolejny segment. W dniu pisania tego tekstu tygodniowy limit konta autora był już wykorzystany w 98%.

  - **Nic z konfiguracji użytkownika nie przedostaje się do środka i nic z sesji nie pozostaje.** Bez narzędzi, w trybie bez personalizacji, z ignorowanymi ustawieniami użytkownika, wyłączonymi serwerami MCP i hookami, prywatnym jednorazowym katalogiem roboczym oraz bez zachowywania transkrypcji. Zmierzono to za pomocą kanarków: bez `CLAUDE_CODE_DISABLE_ATTACHMENTS` element `@chemin` dokumentu stawał się załącznikiem, a model zwracał wywołanie odczytu zamiast tłumaczenia; z nim nic nie przechodzi. Kanarki `AGENTS.md`, `CLAUDE.md` i hook niczego nie załadowały ani nie wykonały.

  - **Segment rozpoczynający się od `/` nie docierał do modelu.** Przy `--disable-slash-commands` Claude Code sam odpowiada „… isn't available in this environment.” ze statusem `success`, bez żadnej tury. Znak nowego wiersza przed segmentem wysyła go do modelu; kontrakt wyjściowy i tak odrzuca odpowiedź zwróconą bez tury, po więcej niż jednej turze, uciętą albo wygenerowaną przez model inny niż zapowiedziany.

  - **Modele: aliasy, nigdy stały identyfikator.** Domyślnie `sonnet`, z poziomem wysiłku `low`, również w `--eco` — `--eco` nic więc nie zmienia na tej ścieżce — oraz `opus` i `haiku` przez `--model`; `fable` i warianty `[1m]` są odrzucane, ponieważ w `-p` bez pytania przechodzą na płatne kredyty.

  - **Ustawienia domyślne są mierzone, a nie zakładane.** Za pomocą samego `aipmt --use_claude_code`, cztery równoległe tłumaczenia dwóch dokumentów użytych do pomiarów w README — obszernego artykułu przeglądowego w `--news` oraz tego README w rewizji 1.14.0 — po czternaście języków każdy. `sonnet`, przy poziomie wysiłku `low`, tworzy 28 tłumaczeń, z czego 26 bez rozbieżności: jedno dodatkowe pogrubione słowo w chińskiej wersji artykułu oraz, po arabsku w README, jeden wiersz tabeli sklejony z poprzednim, czego nie widać przy wyświetlaniu. Linki wewnętrzne pozostały nienaruszone, angielskie cytaty zostały skopiowane bez zmian, a w wersji angielskiej model usunął francuskie wiersze tłumaczenia bez wymyślania flagi; mediana wyniosła 6 min 49 s na język dla artykułu i 2 min 20 s dla README. `opus` tłumaczy README bez żadnych rozbieżności, o jedną czwartą szybciej, ale nie tłumaczy żadnego artykułu: jego zabezpieczenia zatrzymały odpowiedź we wszystkich czternastu językach na krótkiej notatce biologicznej. `haiku` zapisuje natomiast wszystko — trzy tytuły sekcji artykułu zmienione na poziom 1, zdublowane linki wewnętrzne angielskiego README — lecz dwa razy wolniej niż `sonnet`: przeprowadza rozumowanie bez możliwości jego wyłączenia, wykorzystując na nie 61% swoich tokenów wyjściowych, a jego niższa cena daje w przeliczeniu na API tylko 14% oszczędności. Stąd `sonnet` również w `--eco`. Poziom wysiłku nie ma znaczenia przy tłumaczeniu: we wcześniejszej partii — ten README i ten CHANGELOG po angielsku, japońsku i w hindi — `sonnet` nie wygenerował żadnego tokenu rozumowania, `opus` przy średnim poziomie wysiłku przeznaczył na nie 1% swoich tokenów wyjściowych, a średni poziom wysiłku nie przyniósł żadnej poprawy względem niskiego ani pod względem struktury, ani czasu. Kampania `sonnet`, obejmująca 1,8 miliona znaków źródłowych, zużyła 9 punktów z okna 5-godzinnego i 2 z tygodniowego limitu subskrypcji Max autora — jest to górne oszacowanie, ponieważ sesja sterująca pomiarami korzystała z tego samego limitu.

  - **Odmowa wynikająca z zabezpieczeń Anthropic jest nazywana wprost.** Opus 5.5 ma bardziej rygorystyczne zabezpieczenia niż Sonnet, a komunikat o błędzie Anthropic ostrzega, że czasami oznaczają one zadania zbliżone do badań biologicznych. Wystarczyła krótka notatka przeglądowa o 279 cząsteczkach wygenerowanych dla miejsca wiązania. Claude Code przerywa wtedy odpowiedź, ponawia próbę jeden raz, a model zwraca „I can't continue this translation” ze statusem sukcesu, bez błędu, w dwóch turach: jedynie kontrakt jednej tury zatrzymywał tę odpowiedź, wyświetlając komunikat, który nie podawał przyczyny. Wysłana osobno notatka jest odrzucana przez API jako należąca do kategorii „bio”. aipmt rozpoznaje teraz te oznaki, wskazuje zabezpieczenia oraz ich kategorię i nie ponawia próby — ten sam tekst wywołałby ponownie tę samą odmowę — oraz zaleca `--model sonnet`, który przetłumaczył notatkę na wszystkie czternaście języków.

  - **Tłumaczenia tego repozytorium mogą korzystać z tej ścieżki bez wyjątku.** `REGEN_PROVIDER=claude_code` jest subskrypcją, a nie rozliczanym API: działa bez `REGEN_ALLOW_PAID_API`, z czterema zadaniami — kampanie wykonywały cztery tłumaczenia jednocześnie bez ani jednego błędu limitu szybkości lub blokady połączenia — po pojedynczym preflight, który nie zużywa żadnego limitu. Domyślną opcją pozostaje Codex z `gpt-5.6-sol`.

  - **Warunki użytkowania przedstawione bez ogródek.** Strona prawna Claude Code nie zabrania użytkownikowi logowania się do niezmodyfikowanego pliku binarnego za pomocą własnej subskrypcji; zabrania zewnętrznym deweloperom przekazywania żądań przez dane uwierzytelniające Pro lub Max swoich użytkowników, a Anthropic preferuje klucz API dla narzędzi zewnętrznych, w tym projektów open source, zastrzegając sobie możliwość naliczania ich użycia z płatnych kredytów. Żaden dokument nie rozstrzyga przypadku dystrybuowanego narzędzia uruchamiającego oficjalny plik binarny: użytkownik angażuje własne konto.

  - **Testy**: nowy plik `tests/test_claude_code_provider.py` (58 testów), 100% instrukcji i gałęzi modułu, bez uruchamiania prawdziwego `claude` — wyczyszczone środowisko, nieistniejący plik binarny, `PATH` bez `claude`, atrapy zgłaszające wyjątek w razie wywołania.

- **1.15.0** Provider `--use_antigravity`: tłumaczenie w ramach limitu subskrypcji Google AI Pro lub Ultra za pośrednictwem oficjalnego CLI `agy`; a dla wszystkich providerów Ctrl-C nie pozostawia już działającego agenta, pusty segment nie powoduje już niepowodzenia pliku, a projektowy `.env` nie wybiera już wykonywanego pliku binarnego (2026-09-26):

  - **Dziesiąta ścieżka providera: subskrypcja Google bez rozliczania za użycie.** Osoby płacące za Google AI Pro lub Ultra mogą teraz rozliczać tłumaczenia w ramach tej subskrypcji zamiast płacić za tokeny w API Gemini. `agy`, oficjalny CLI Antigravity, jest jedyną ścieżką do tego limitu: od 18 czerwca 2026 r. Gemini CLI nie obsługuje już kont Pro, Ultra ani bezpłatnych, a SDK Antigravity uwierzytelnia się wyłącznie za pomocą klucza API lub Google Cloud. `--use_antigravity` steruje nim w trybie headless, podobnie jak Codex i Grok CLI, na tej samej bazie — osobna grupa procesów, `SIGTERM`, a następnie `SIGKILL` po przekroczeniu czasu, oczyszczone środowisko. Zweryfikowano od początku do końca na agy 1.2.11: przewodnik Markdown — front matter, pogrubienie, link z nawiasami, kod inline, wcięty blok kodu na liście, tabela, cytat — przetłumaczony na angielski w 14 sekund, łącznie z preflight, ze strukturą identyczną jak źródło i dodaną notą tłumaczeniową; następnie, po poprawkach z przeglądu, na niemiecki w 19 sekund, z identyczną strukturą i bez zapisywania czegokolwiek w `~/.gemini`.

  - **Żadna płatna ścieżka nie pozostaje otwarta, a każde uruchomienie to weryfikuje.** agy obsługuje inne ścieżki poza subskrypcją — klucz API, projekt Google Cloud, bramę, płatne kredyty AI — a kilka zmiennych środowiskowych przełącza go na nie bez wyświetlania jakiejkolwiek informacji. Zmierzono: `AGY_GATEWAY_URL` wysyła dokument do bramy strony trzeciej, `AGY_ADC_AUTH` przełącza się na rozliczany projekt Google Cloud, a `CLOUD_CODE_URL` przekierowuje uwierzytelniony endpoint pod dowolny adres. Środowisko podprocesu jest więc listą dozwolonych elementów, a nie listą zakazów: `PATH`, język i strefa czasowa, terminal, tożsamość, serwery proxy i certyfikaty maszyny oraz magistrala sesji — których potrzeby agy dowiódł `env -i` — bez żadnego klucza. Wypróbowana wcześniej lista zakazów według rodzin prefiksów (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…) pomijała niektóre z nich: podczas przeglądu w ciągach znaków pliku binarnego znaleziono nadpisania endpointów, których nie obejmował żaden prefiks: `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Dwa ustawienia nie należą do środowiska i można je odczytać wyłącznie przez `agy -p /config`: płatne kredyty AI przejmujące obsługę po wyczerpaniu limitu oraz połączenie za pośrednictwem projektu Google Cloud. Preflight, który nie zużywa żadnego limitu — zmierzono zerowe użycie — odmawia tłumaczenia, jeśli któreś z nich jest aktywne lub skonfigurowano klucz API, a brak ustawienia w `/config` oznacza odmowę dla każdego z tych trzech elementów: wersja agy, która zmieniłaby nazwę jednego z nich, nie może przejść kontroli, która niczego nie zweryfikowała. Wreszcie dziennik każdego wywołania musi potwierdzać uwierzytelnianie za pomocą subskrypcji (`authMethod=consumer`), a każda inna metoda uwierzytelniania, która się w nim pojawia, w dowolnym z dwóch zapisów używanych przez plik binarny, powoduje odrzucenie odpowiedzi: rozstrzygające jest samo wywołanie, a nie przygotowana konfiguracja.

  - **Agent tłumaczący nie ma żadnego narzędzia, a jego załadowanie jest potwierdzane przy każdym wywołaniu.** Każde wywołanie zapisuje w jednorazowym katalogu agenta w formacie agentów projektowych agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Około 800 tokenów wejściowych zamiast 12 400 z agentem domyślnym, a trzecie ustawienie nie jest zbędne: samo `excludeDefaultComponents` pozwalało hookowi workspace wykonywać polecenia i wstrzykiwać tekst. Prawdziwa pułapka leży gdzie indziej: brak agenta nie powoduje niepowodzenia agy. Kod wyjścia 0, status `SUCCESS`, a odpowiada agent programistyczny z 57 aktywnymi narzędziami — na „Kot śpi.” odpowiedział „Ciii, nie budźmy go! 🐱💤 Co mogę dziś dla ciebie zrobić?”. Ani stdout, ani stderr niczego nie ujawniają: informację zawiera wyłącznie dziennik wywołania. Odpowiedź jest więc odrzucana, jeśli dziennik zgłasza to przełączenie awaryjne, a także wtedy, gdy nie zawiera pozytywnego znacznika załadowania agenta — zmiana formatu dziennika powoduje odrzucenie tłumaczenia zamiast cichego usunięcia zabezpieczenia. Każdy znacznik musi zajmować cały wiersz dziennika w zmierzonym formacie — poziom ważności, data, godzina, wątek, plik i wiersz: plik binarny zawiera również wiersz kopiujący wiadomość użytkownika do dziennika — nigdy niewidziany przy domyślnym poziomie logowania w 78 rzeczywistych dziennikach — a dokument cytujący te komunikaty nie może spełnić zabezpieczenia zamiast agy.

  - **Ustawienia i historia agy użytkownika pozostają nietknięte.** Każde wywołanie działa z prywatnymi katalogami HOME, tymczasowym i roboczym, które są później usuwane. agy mimo to uwierzytelnia się za pomocą systemowego magazynu kluczy, którego aipmt nigdy nie odczytuje. Nic nie jest dziedziczone: ani uprawnienia użytkownika — które pozwalały domyślnemu agentowi uruchamiać `ls` i `git` bez pytania — ani jego reguły globalne, pluginy, serwery MCP, hooki i skills. Nic nie jest też dodawane do jego historii, w której każde wywołanie pozostawiało konwersację o rozmiarze około 200 KB wraz z przetłumaczonym tekstem: kampania sond pozostawiła tam około 95 konwersacji i wyparła 17 wpisów z cache ograniczonego do 100. Zweryfikowano: w `~/.gemini/antigravity-cli` nie zapisano żadnego pliku.

  - **Bezpieczna odmowa tam, gdzie izolacja nie byłaby skuteczna.** W systemie Linux bez magistrali sesji D-Bus — w sesji SSH, kontenerze lub na serwerze — agy zapisuje swój token w pliku w `~/.gemini` zamiast w magazynie kluczy, co opisuje jego własny changelog (1.1.3), a izolacja każdego wywołania ukrywa ten plik. Odmowa następuje teraz przed jakimkolwiek uruchomieniem i podaje prawdziwą przyczynę, zamiast czekać minutę na kod logowania, a następnie zalecać ponowne połączenie, które niczego by nie rozwiązało. W systemie Windows agy odczytuje `USERPROFILE`, `APPDATA` i `TEMP`, a nie `HOME` ani `TMPDIR` — zgodnie z dokumentacją Go i ciągami znaków w pliku binarnym — przez co nic nie izolowałoby wywołania od ustawień i historii użytkownika, dlatego `--use_antigravity` jest tam odrzucany, dopóki nie zostanie to zmierzone. macOS przechodzi kontrolę, choć nie został zmierzony; zabezpieczenie przed naliczaniem opłat, które odczytuje obowiązującą konfigurację, działa również tam.
  - **`exit 0` niczego nie dowodzi, czwarty CLI.** Odpowiedź jest akceptowana wyłącznie z zerowym kodem wyjścia, obiektem JSON ze statusem `SUCCESS`, zgodnym dziennikiem, bez odrzuconej akcji, polecenia ani błędu w JSON-ie, bez ostrzeżenia o obcięciu na stderr oraz z niepustym tekstem. `--print-timeout` nigdy nie jest używany: po jego upływie agy zwraca częściowe wyjście w `SUCCESS`, kod 0; limit czasu jest zewnętrzny i zabija grupę procesów. Segment rozpoczynający się od `/commande`, `!commande` lub `@fichier` jest tłumaczony, nigdy wykonywany ani rozwiązywany — bez `--disable-slash-commands` zamiast tłumaczenia wykonałoby się „/help”. Pusty segment nie trafia już do agy, ponieważ pipeline zwraca go bez zmian (zobacz niżej), a jako ostatnie zabezpieczenie nadal jest odrzucany przed wywołaniem: przy pustym wejściu agy otwiera interaktywny interfejs z kodem 0. Ponowienie opiera się na polu `retryable` w wierszu `AGY_ERROR`, który agy zapisuje na stderr od wersji 1.2.6: sam ponawia już błędy przejściowe — 502, 503, 504, limit na minutę — i to on wie, czy pozostały błąd nadal ma charakter przejściowy. W razie braku tego pola ponowienie nie następuje, gdy komunikat mówi o wyczerpaniu — w Google `RESOURCE_EXHAUSTED` ma ten sam kod 429 co limit na minutę, lecz wyczerpane okno 5-godzinne nie odnowi się w ciągu 90 sekund — a w pozostałych przypadkach następuje tylko przy ograniczeniu przepustowości. Odpowiedź zachowuje zakończenie wiersza segmentu: agy zawsze kończy własną odpowiedź znakiem nowego wiersza, który na łączeniu dzielił na dwie części akapit rozcięty w środku zdania. Rozłączona sesja zwraca komunikat zalecający uruchomienie `agy` w celu ponownego połączenia. `AGY_CLI_DISABLE_AUTO_UPDATE=true` zapobiega wreszcie uruchamianiu przez nowy HOME przy każdym wywołaniu modułu sprawdzającego aktualizacje we własnej sesji, poza zasięgiem limitu czasu — wartość `1` nie daje natomiast żadnego efektu.

  - **Modele: nakład rozumowania jest częścią nazwy.** Identyfikatory pochodzą z `agy models` — `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… Sama nazwa bazowa, którą agy by odrzucił, jest odrzucana przed wywołaniem wraz z dostępnymi sufiksami: `-medium` lub `-low` dla Flash, `-high` lub `-low` dla Pro. Zawartość jest teraz zapisywana do pliku tymczasowego w tym samym katalogu — `os.replace` jest atomowe tylko w obrębie tego samego systemu plików — a następnie zmieniana jest jego nazwa; plik tymczasowy jest usuwany, jeśli zapis się nie powiedzie, także w przypadku przerwania. Ten plik tymczasowy pochodzi z `mkstemp`, a przegląd wykazał, że przewidywalna nazwa jedynie przeniosłaby problem: dowiązanie symboliczne umieszczone pod `cible.md.aipmt-tmp` powodowało zapisanie tłumaczenia do wskazywanego pliku poza katalogiem wyjściowym, przy zwróceniu `success`; natomiast dwa równoczesne uruchomienia dla tego samego pliku docelowego współdzieliły tę nazwę, a drugie zmieniało ją, gdy pierwsze nadal zapisywało do tego samego inode — plik docelowy zgłaszano jako pomyślnie utworzony, choć zawierał wymieszaną treść (`BBBAAAAA` zamiast `BBBBBBBB`, zgodnie z pomiarem). `mkstemp` tworzy plik z użyciem `O_CREAT | O_EXCL` pod unikatową nazwą, co usuwa oba problemy. Uprawnienia istniejącego pliku docelowego są jawnie przejmowane przed zastąpieniem: `mkstemp` tworzy plik z trybem 0600, przez co plik docelowy celowo ustawiony na 0600 zmieniałby w przeciwnym razie tryb na 0664, a plik docelowy z trybem 0644 udostępniany przez serwer WWW stałby się nieczytelny. - **1.13.0** Provider `--use_openrouter`: płatny router do około 430 modeli, w tym otwartych modeli chińskich (2026-09-05):

  - **Dziewiąta ścieżka provider, dostarczona razem z ósmą.** Wersja 1.12.0 nie została opublikowana w PyPI: oba routery, OpenCode i OpenRouter, są wydawane razem. [OpenRouter](https://openrouter.ai) zapewnia za pomocą jednego klucza dostęp do modeli, których nie udostępnia tutaj żaden inny provider — Kimi, Qwen, DeepSeek, Z.ai — w ramach jednego kredytu rozliczanego według użycia. Ponieważ endpoint jest zgodny z OpenAI, używany jest ten sam klient co dla xAI; **wszystko, co odróżnia ten provider, mieści się w preflight**, a każda z jego reguł wynika z pomiaru API.

  - **Ten sam model jest obsługiwany przez dziesiątki hosting provider z różnymi limitami, a routing tego nie uwzględnia.** Zmierzono: 33 hosting provider dla `z-ai/glm-5.2`, 23 dla `z-ai/glm-5.3-flash` — w tym jeden z limitem **2 048 tokens wyjściowych**. Długie tłumaczenie wysłane do jednego z 23 provider było więc losowo ucinane bez najmniejszego sygnału. Preflight odczytuje `/api/v1/models/{modèle}/endpoints`, odrzuca hosting provider z limitem poniżej 8 000 tokens wyjściowych, ze statusem obniżonej sprawności oraz tych, którzy nie deklarują żadnego limitu, a następnie przypina pozostałych. `provider.only` **bez** `allow_fallbacks: false` jest tylko preferencją: router przełącza się na odrzuconego hosting provider, przez co przypięcie traci znaczenie. Jeśli żaden hosting provider nie spełnia limitu, polecenie się zatrzymuje: kontynuowanie tłumaczenia oznaczałoby zaakceptowanie cichego ucięcia, któremu ten preflight ma zapobiegać.

  - **Rozumowanie jest rozliczane według stawki za dane wyjściowe i domyślnie aktywne w wielu modelach.** To samo zapytanie w `z-ai/glm-5.2`, odpowiedź „OK”: **107 tokens ukończenia przy ustawieniu domyślnym modelu, 2 przy wyłączonym rozumowaniu**. W przypadku tłumaczenia, w którym rozumowanie niczego nie wnosi, oznacza to osiemnastokrotne zwiększenie dla każdego segmentu każdego pliku. Dlatego jest ono domyślnie wyłączone. **288 modeli z 431**, które go wymagają (`reasoning.mandatory`), odpowiada `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: w ich przypadku preflight odczytuje akceptowane poziomy wysiłku i wybiera najniższy (następny punkt) — poziom wysiłku przydziela **procent `max_tokens`**, który rozumowanie zużywa w pierwszej kolejności, więc losowo wybrana wartość jedynie przesuwa ryzyko pustej strony, zamiast je zmniejszać.
  - **Model wymuszający rozumowanie otrzymuje najniższy akceptowany poziom wysiłku — zdecydowano o tym na podstawie pomiarów.** Pierwszym wyborem było niewysyłanie niczego, aby nie zgadywać za model. Po przetestowaniu na `z-ai/glm-5.3-flash`, którego domyślna wartość w katalogu to `max`, wybór ten powodował, że dane wyjściowe były **obcinane przy 32 768 tokenach** przed zakończeniem tłumaczenia — utracono dwa z czternastu języków. Zwiększenie limitu niczego by nie zmieniło: wysiłek przydziela sobie jego procent, więc wraz z nim rośnie rozumowanie. Provider odczytuje zatem `supported_efforts` podczas preflightu i żąda najniższej wartości, wracając do „niczego”, gdy katalog nie podaje żadnej użytecznej. Próba kontrolna na problematycznym języku: wcześniej kończyła się niepowodzeniem z powodu wyczerpania budżetu, a teraz przechodzi w 9 minut, zachowując strukturę identyczną ze źródłem.

  - **Awaria hostingu nadrzędnego jest teraz nazywana wprost.** Router normalizuje ten przypadek do `finish_reason=error` z pustym `native_finish_reason` — zmierzonym dwukrotnie, dla dwóch języków, dokładnie po 750 sekund. Ogólny komunikat sugerował szukanie usterki w dokumencie lub jego podziale; teraz informuje, że awaria leży po stronie dostawcy i że ponowienie próby często wystarcza.

  - **`finish_reason=length` z pustym wyjściem nie oznacza obcięcia.** Oznacza budżet zużyty przez rozumowanie przed pierwszym użytecznym znakiem — zmierzono 15 850 tokenów rozumowania wobec 148 użytecznych. Te dwa przypadki wymagają przeciwnych działań: zmniejszanie rozmiaru segmentów w pierwszym z nich nic nie daje. Komunikat wyraźnie je rozróżnia. Dwa kolejne zabezpieczenia również wynikają z pomiarów: router odpowiada **kodem 200 z treścią zawierającą wyłącznie błąd**, gdy hosting nadrzędny zawiedzie (`choices[0]` zgłaszał niejasny `TypeError`, który przesłaniał komunikat), a okno kontekstu jest odczytywane z katalogu i zapisywane w `MODEL_TOKEN_LIMITS` — `DEFAULT_TOKEN_LIMIT` jest błędne dla 44 modeli z katalogu, w tym dwóch ograniczonych do 4 095 tokenów.

Marker `429` OpenCode jest wyszukiwany jako liczba, a nie jako podciąg, przez który identyfikator błędu taki jak `err_84290b` uruchamiał 90 sekund back-offu, po czym i tak kończył się niepowodzeniem. Wreszcie niestandardowy endpoint OpenRouter jest wyświetlany podczas preflightu: wystarczy projektowy `.env`, aby go ustawić, i to właśnie rzeczywisty klucz zostałby potem wysłany.
  - **Bezpieczeństwo: projektowy `.env` nie może już przekierowywać wywołań API.** `find_dotenv(usecwd=True)` szuka pliku w bieżącym katalogu i jego katalogach nadrzędnych: niezaufane drzewo katalogów — właśnie sklonowane repozytorium — mogło umieścić w nim `OPENROUTER_BASE_URL`, `XAI_BASE_URL` lub `OPENAI_BASE_URL` (ten ostatni odczytywany przez samo SDK), nie znając żadnego klucza, po czym prawdziwy klucz pochodzący ze środowiska lub konfiguracji użytkownika był wysyłany w nagłówku autoryzacji do zewnętrznego serwera. Filtr opiera się na WZORCU, a nie na liście: w zainstalowanych SDK zidentyfikowano dwanaście odczytywanych zmiennych routingu, z czego sześć w samym kliencie Anthropic — ręcznie sporządzone wyliczenie pominęłoby połowę. Z warstwy projektowej odrzucane są zatem wszystkie zmienne w `_BASE_URL`, `_API_BASE` lub `_ENDPOINT`, proxy i magazyny certyfikatów (wskazanie kontrolowanego urzędu sprawia, że interceptor jest nieodróżnialny od prawdziwego serwera), a także `XDG_CONFIG_HOME` i `APPDATA`: ich ustawienie oznaczało decydowanie, który plik stanowi warstwę użytkownika, a więc boczne obejście filtra. Zmienne te są akceptowane wyłącznie z dwóch warstw kontrolowanych przez użytkownika: wyeksportowanego środowiska i `~/.config/aipmt/.env`. Warstwa projektowa jest ponadto odczytywana BEZ interpolacji: `load_dotenv` domyślnie rozwija `${VAR}`, a niezaufany `.env` zawierający `NOM_ANODIN=${OPENAI_API_KEY}` kopiował prawdziwy klucz pod nazwę, której filtrowanie podprocesów oparte na wzorcu nie rozpoznawało — trafiał on następnie do środowiska `codex exec`, wbrew deklarowanemu niezmiennikowi. Komunikat o odrzuceniu wyświetla teraz wyłącznie nazwę zmiennej: adres URL w formie `https://${CLE}@hôte/` powodował wyciek interpolowanego klucza do logów, mimo że wartość była odrzucana. Odrzucenie jest zgłaszane na stderr wraz z instrukcją postępowania — przekaźnik firmowy należy zadeklarować w konfiguracji użytkownika.
  - **Poprawka: limit wyjściowy OpenRouter jest obliczany dla każdego wywołania.** `context_length` obejmuje dane wejściowe ORAZ uzupełnienie, a stała rezerwa skalibrowana na tekście łacińskim niczego nie ogranicza: według pomiaru tokenizerem `o200k_base` 16 000 znaków to 3 200 tokenów po francusku, ale 12 300 po japońsku i 17 500 w przypadku emoji. Budżet jest więc wyznaczany na podstawie faktycznie wysyłanego tekstu i zwiększany o liczbę jego bajtów UTF-8: w każdym tokenizerze z łączeniem bajtów — BPE na poziomie bajtów, SentencePiece z rezerwowym kodowaniem bajtowym, czyli rodzinach używanych przez katalog — jeden token odpowiada co najmniej jednemu bajtowi, a jest to jedyne dostępne tutaj bezpieczne zawyżenie, ponieważ OpenRouter kieruje ruch do dziesiątek nieznanych nam tokenizerów. Żaden średni współczynnik nie był odpowiedni — ideogram z płaszczyzny dodatkowej schodzi do 1,33 bajta na token, a znak łączący do 1,00 — dlatego dane wejściowe wraz z wyjściowymi mieszczą się teraz w oknie z samej konstrukcji. Segment zbyt gęsty dla wybranego modelu jest odrzucany przed wywołaniem, a nie po naliczeniu opłaty.

- **1.12.0** Provider `--use_opencode`: OpenCode, agent open source, kierujący do wybranego przez użytkownika dostawcy — modelu lokalnego, bezpłatnego bez konta, subskrypcji lub klucza (2026-09-04):

  - **Ósma ścieżka providera, mająca inną naturę niż siedem pierwszych.** [OpenCode](https://opencode.ai) (MIT) nie jest dostawcą modeli, lecz _routerem_ prowadzącym do tych, które użytkownik skonfigurował w samym OpenCode: klucza API, subskrypcji (GitHub Copilot, ChatGPT, SuperGrok), bramki OpenCode Zen — udostępniającej bezpłatne modele **bez konta** — albo modelu **lokalnego** (Ollama, LM Studio, llama.cpp). Skrypt steruje `opencode run` w trybie nieinteraktywnym, tak jak steruje Codex i Grok, oraz ponownie wykorzystuje tę samą warstwę podprocesów (własna grupa procesów, `SIGTERM`, a następnie `SIGKILL` po przekroczeniu czasu, stdin zawsze zamknięte, oczyszczone środowisko). Zweryfikowano za pomocą **dwóch rzeczywistych tłumaczeń**: całego tego README na język angielski przez `opencode/mimo-v2.5-free` — 49 s, jedno przejście, struktura identyczna z plikiem źródłowym (32 nagłówki, 26 zamknięć kodu, 18 linków, 37 adresów URL, 37 wierszy tabel, 135 fragmentów kodu inline) — oraz pliku testowego przez `ollama/qwen2.5:7b`, lokalnie, bez żadnego klucza.

  - **`--model provider/modèle` jest obowiązkowy i stanowi świadomy wybór.** Bez `--model` OpenCode wraca do własnej wartości domyślnej, którą w świeżej instalacji jest `opencode/big-pickle`, bezpłatny model „stealth”, którego interakcje mogą służyć do trenowania — pomiar potwierdził, że odpowiedział właśnie ten model. Ciche wybranie go za użytkownika byłoby dokładnie takim niewidocznym przełączeniem, jakie to repozytorium ma wykrywać; komunikat o błędzie wskazuje więc polecenie wyświetlające listę modeli (`opencode models`) oraz trzy przykłady (lokalny, bezpłatny, subskrypcyjny). `--eco` nie ma wpływu i wyraźnie o tym informuje. `--reasoning_effort` jest przekazywany bez zmian jako `--variant` OpenCode, wyłącznie na wyraźne żądanie.

  - **Izolacja zmierzona, a nie założona.** Konfiguracja inline (`OPENCODE_CONFIG_CONTENT`, ostatnia w kolejności scalania OpenCode, a więc mająca pierwszeństwo przed konfiguracją użytkownika bez jej zastępowania) definiuje agenta `aipmt`, któremu odmawia się dostępu do wszystkich narzędzi (`permission: {"*": "deny"}`): rejestr nawet nie udostępnia ich modelowi, który poproszony o „wyświetlenie plików i uruchomienie `id`” odpowiada, że nie ma narzędzi. Udostępnianie sesji jest wyłączone, zewnętrzne pluginy pominięte (`--pure`), nigdy `--auto`, a katalog roboczy jest tymczasowy i pusty. Zmierzono i wyłączono dwa ciche wstrzyknięcia: bez `OPENCODE_DISABLE_CLAUDE_CODE` należący do użytkownika `~/.claude/CLAUDE.md` trafia do **każdego** promptu (515 tokenów wejściowych zamiast 186 dla prostego „Dzień dobry”); bez `OPENCODE_DISABLE_PROJECT_CONFIG` trafia tam również `AGENTS.md` z bieżącego katalogu — instrukcja „zakończ każdą odpowiedź słowem BANANA” została zastosowana do tłumaczenia. Globalny `~/.config/opencode/AGENTS.md` nadal jest jednak wstrzykiwany: żaden przełącznik go nie wyłącza, a obejście tego za pomocą zmienionego `XDG_CONFIG_HOME` ukryłoby również dostawców użytkownika. Zostało to udokumentowane zamiast maskowane prowizorycznym rozwiązaniem.
  - **`exit 0` niczego nie dowodzi, trzecie CLI, te same odruchy — z dwiema pułapkami charakterystycznymi dla tego narzędzia.** Nieznany `--agent` nie powoduje niepowodzenia `opencode run`: ostrzeżenie na stderr i **ciche** przejście na agenta kodującego z aktywnymi narzędziami. Gdyby konfiguracja inline nie została uwzględniona, tłumaczenie zostałoby więc uruchomione z agentem zdolnym do zapisu; kontrakt wyjścia sprawdza brak tego komunikatu, a ponadto: kod wyjścia 0, brak zdarzeń `error`, brak `tool_use`, ostatni `step_finish` w `stop` (`length` oznacza uciętą odpowiedź), tekst niepusty. Druga pułapka: zdarzenie JSON błędu jest **nieprzejrzyste** — „Nieoczekiwany błąd serwera. Szczegóły znajdują się w logach serwera.”, z samym odwołaniem — a rzeczywista przyczyna (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) występuje wyłącznie w logach. Stąd `--print-logs --log-level ERROR` i odczyt pola `error="…"` ze stderr, bez następującego po nim stack trace Bun. Nieznany model kończy się więc błędem w ciągu sekundy, z podaną przyczyną. `--title` zapobiega przy okazji zbędnemu wywołaniu LLM: bez niego OpenCode generuje tytuł sesji za pomocą dodatkowej tury na `small_model`.

  - **Sekrety: takie samo filtrowanie według wzorca jak w Codex i Grok, z jednym imiennym wyjątkiem.** `OPENCODE_API_KEY` jest zachowywana: to klucz samego OpenCode (brama Zen, subskrypcja Go), przekazany mu po nazwie — odpowiednik jego `auth.json`, a nie klucz, którym aipmt miałby zarządzać lub za który mógłby naliczać opłaty. Providerów konfiguruje się w OpenCode (`opencode auth login`, `opencode.json`), nigdy w `.env` należącym do aipmt, z którego żaden klucz nie trafia do podprocesu. W CI nie ma odmowy, inaczej niż w przypadku CLI subskrypcyjnych: klucz API lub model self-hosted na runnerze są prawidłowymi zastosowaniami.

  - **Modele bezpłatne i modele lokalne — wyniki pomiarów.** `opencode/mimo-v2.5-free` tłumaczy akapit w 16 s, a ten README w 49 s; `opencode/big-pickle` potrzebuje 40 s na 200 słów, a dwa równoczesne żądania pozostawały bez odpowiedzi przez 5 minut, choć każde z osobna się kończyło; `opencode/nemotron-3.5-lightning-free` nie odpowiedział przez 3 minuty. - **1.9.2** Naprawa wyodrębniania URL-a atrybucji wiadomości z zagnieżdżonymi nawiasami lub francuskim prefiksem (2026-05-11):

  - **Naprawiony błąd**: wyodrębnianie URL-i atrybucji w `_protect_news_quotes` używało wyrażenia regularnego `re.search(r"\((.+?)\)", attribution)` (leniwe przechwytywanie między nawiasami). W przypadku atrybucji typu `(relayé par [@user sur X](https://x.com/.../123))` (zagnieżdżone nawiasy: obejmujący `(` + `]()` linku Markdown) przechwytywanie kończyło się przy pierwszym napotkanym `)` → ucięty ciąg zawierający francuski prefiks: `relayé par [@user sur X](https://x.com/.../123` (bez końcowego `)`). Skutek: `_validate_news_post` szukał tego ciągu w przetłumaczonym wyniku i zawsze kończył się niepowodzeniem (z dwóch powodów: ucięty `)` + „relayé par” przetłumaczone jako `relayed by`/`weitergeleitet von`/...). Pełna kaskada low → medium → high → gpt-5.5 nie mogła się powieść.
  - **Poprawka**: wyrażenie regularne ma teraz postać `re.search(r"\]\(([^)]+)\)", attribution)` — wyszukuje konkretnie `](url)` linku Markdown i przechwytuje **wyłącznie czysty URL** (bez francuskiego prefiksu ani ucięcia), którego niezmienność podczas tłumaczenia zapewniają placeholdery `#URL{N}#`. Jest odporne na oba problematyczne wzorce:
    - `(relayé par [@account sur X](url))` — zagnieżdżone nawiasy
    - `via [@source](url)` lub `selon [@author](url)` — francuski prefiks bez nawiasów obejmujących

- **1.9** Naprawa cichych niepowodzeń + kompletne narzędzia jakościowe + wielopozycyjna nota o tłumaczeniu (2026-05-07):
  - **Wielopozycyjna nota o tłumaczeniu + format markera „embed card”**:
    - Nowe opcje CLI (addytywne, domyślne ustawienia bez zmian → **non-breaking**):
      - `--note_position {top,bottom,both}` (domyślnie: `bottom`): umieszcza notę na górze, na dole lub w obu miejscach przetłumaczonego pliku.
      - `--note_format {legacy,marker}` (domyślnie: `legacy`):
        - `legacy` dokładnie odtwarza zachowanie wersji 1.8 (pogrubiony akapit `**…**`) **byte-for-byte**.
        - `marker` generuje niewidoczną definicję odwołania do linku Markdown (`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`), po której następuje ustrukturyzowany **3-akapitowy blockquote**, renderowany jako „GitHub repo embed card”: tytuł projektu w kodzie inline (`**\`ai-powered-markdown-translator\`\*\*`), opis przetłumaczony przez LLM oraz link CTA (`[Voir le projet sur GitHub ↗](URL)`) z widoczną strzałką. Może zostać wykorzystany podczas buildu przez plugin remark (zob. blog jls42.org → plugin `remark-translation-banner`).
    - **Niezmienniki nigdy niewysyłane do LLM**: tytuł repozytorium i URL GitHub są składane po stronie Pythona po przetłumaczeniu zdania opisowego. LLM nigdy nie widzi sluga `ai-powered-markdown-translator` ani `https://github.com/jls42/...`, co gwarantuje, że żaden renderer, wielkość liter ani scheme nie zostaną zmienione.
    - **Wstawianie uwzględniające frontmatter**: w trybie `top` lub `both` nota jest wstawiana **po zamykającym bloku `---`** frontmatter YAML (bezpieczeństwo Astro Content Collections / gray-matter). Helper `_split_frontmatter` wykrywa `---\n…\n---\n` na początku pliku i zachowuje jego integralność; **zgłasza `RuntimeError`** w przypadku otwartego frontmatter bez zamykającego fence (plik trafia do `failed_files`, zamiast zostać zapisany z notą w niewłaściwym miejscu).
    - **Sanitizer modelu oparty na whitelist**: `_sanitize_model` zastępuje każdy znak spoza `[A-Za-z0-9._:/-]` znakiem `_`, z fallbackiem `unknown` dla pustej wartości. Jest zgodny z walidatorem po stronie pluginu remark dla Astro i neutralizuje znaki, które mogłyby uszkodzić format markera (spacja, cudzysłów, nawias, przecinek itp.).

Builder i composer są rozdzielone (builder zwraca czysty blok bez separatora, a composer stosuje `\n\n` zależnie od pozycji); kod produkcyjny i helper źródłowy współdzielą ten sam 3-akapitowy assembler.
    - **`_quote_lines` zachowujący puste wiersze**: dodaje `> ` na początku każdego wiersza, przekształcając puste wiersze w samo `>`. Dzięki temu mdast widzi 3 odrębne akapity w blockquote (tytuł / opis / link), zamiast pojedynczego akapitu z podziałami wierszy.
