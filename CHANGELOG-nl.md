- **1.16.3** Bestandseinde: een vertaling via de API behoudt de afsluitende regeleinde van de bron en Mistral SDK 3.0 is gevalideerd (2026-10-04):

  - **Een vertaling via de API behoudt de afsluitende regeleinde van de bron.** De API-providers — OpenAI, Anthropic, Gemini, Mistral — verwijderen witruimte rond het antwoord van het model. Bij het laatste segment verwijderde deze opschoning ook de afsluitende regeleinde van de bron: een vertaald bestand zonder vertaalnotitie eindigde zonder regeleinde, wat git meldt en formatters bij elke uitvoering corrigeren. Dit werd opgemerkt tijdens de validatie van Mistral SDK 3.0, bij een handleiding die eindigde met een regeleinde waarvan de vertaling er geen meer had. De vertaalnotitie voegde er opnieuw een toe, en de command-lineproviders — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — nemen het einde van het segment over: alleen een API-vertaling zonder notitie werd getroffen. De vertaling neemt voortaan de afsluitende regeleinde van de bron over, ongeacht de provider, en voegt er geen toe aan een bron die er geen heeft.

  - **Mistral: SDK 3.0 gevalideerd met een echte aanroep.** `mistralai` 3.0.0 vervangt de HTTP-bibliotheek `httpx` door `httpx2`; de imports en de vertaalaanroep veranderen niet. Een nieuwe installatie van aipmt kreeg deze versie al, omdat de afhankelijkheden geen maximale versie hebben, maar er was nog geen echte aanroep mee getest: een Markdown-handleiding die met Mistral SDK 3.0 via de API is vertaald, behoudt dezelfde structuur als de bron. De voor ontwikkeling vastgezette versies schakelen over op deze SDK en de tests voor nieuwe pogingen leveren hem een `httpx2`-client, dezelfde die in productie wordt gebruikt.

- **1.16.2** Codebescherming: aangehaalde code in een citaat `--news` en een ingesprongen blok in een lijst zorgen er niet langer voor dat de vertaling in alle talen wordt geweigerd (2026-10-03):

  - **Aangehaalde code in een citaat blokkeert de vertaling niet langer.** In de modus `--news` beschermt aipmt inline code voordat Engelse citaten apart worden gezet om later ongewijzigd te worden hersteld. Code in een citaat werd daardoor samen met het citaat verwijderd: het model zag de token nooit en de validatie verklaarde deze verloren, voor alle talen. De dagelijkse nieuwsmonitoring van de auteur stopte daar op 2 oktober: een opdracht `/plugin enable …` die in een tweet werd geciteerd, de testtaal twee keer geweigerd en de dertien andere nooit gestart. Tokens die met een citaat zijn verwijderd, worden voortaan verwerkt in de apart gezette tekst. Bij Engels als doeltaal wordt de Franse vertaalregel van een citaat niet meer naar het model gestuurd: de instructie vroeg het model die te verwijderen, waarna de code op die regel als verloren werd beschouwd, hoewel het model de instructie juist had gevolgd. Het gepubliceerde resultaat verandert niet. Ten slotte interpreteert het herstellen van een citaat de backslashes daarin niet meer opnieuw: een geciteerde `\n` blijft een `\n`. Van begin tot eind gecontroleerd op het artikel dat was mislukt: Engels en Duits bij de eerste poging vertaald door `gpt-6.1-sol`, met dezelfde structuur als de gepubliceerde versies.

  - **Een ingesprongen codeblok in een lijst wordt beschermd.** CommonMark staat een ingesprongen blokafsluiting toe en dat is gebruikelijk bij een blok dat een stap in een genummerde lijst documenteert: het behoort tot het lijstitem en is daarom ingesprongen. Doordat het beschermingspatroon aan kolom 0 was verankerd, miste het ze allemaal: gemeten op een echte README werden 8 van de 14 blokken gezien. De overige zes werden als proza naar het model gestuurd, kwamen ongewijzigd terug omdat het opdrachten zijn, en de controle die een letterlijk overgenomen vertaling weigert, wees het bestand voor alle talen af met een bericht dat het symptoom benoemde maar nooit de oorzaak. Het patroon accepteert voortaan een ingesprongen afsluiting en de heen-en-terugverwerking tussen bescherming en herstel levert het document identiek op, inclusief inspringing.

- **1.16.1** Interne links: de ankertoken laat zijn haakjes bij de link staan en een vertaalde link wordt niet langer stilzwijgend verdubbeld (2026-09-27):

  - **Een interne link raakt niet langer ongemerkt defect.** Om een link naar een sectie te beschermen, `[texte](#ancre)`, verving aipmt het gedeelte tussen haakjes, inclusief de haakjes, door een token: het model ontving vierkante haken gevolgd door een losse token, die eruitzag als een defecte link, en probeerde die soms te „repareren”. Bij het herstellen ontstond dan `[texte]((#ancre))`, een link die nergens naartoe leidt, zonder dat een controle dit meldde. Het gebrek kwam terug bij elke regeneratie van de vertalingen van deze repository — in het Spaans, Koreaans en vervolgens Italiaans voor 1.15.0, en in het Duits voor 1.16.0 — met elke geteste Gemini Flash en zelfs met Claude Sonnet en Haiku. De token van een Markdown-link behoudt voortaan zijn haakjes: het model ontvangt een geldige link die het niet meer hoeft te repareren, en het herstel accepteert ook een token waarvan het model de haakjes toch heeft verwijderd. HTML-ankers behouden een losse token. Van begin tot eind gecontroleerd met het kwetsbaarste model, `gemini-3.8-flash-low`, op een README waarin een link tussen haakjes stond: zonder de correctie werd de README geweigerd, waren drie links verdubbeld en werd één segment opnieuw verwerkt; met de correctie bleven alle drie de links intact en hoefde niets opnieuw te worden verwerkt. Vervolgens getest op deze README, in het Duits, Japans en Hindi via `gemini-3.8-flash-medium`, en in het Duits via Claude Code met `sonnet`: dezelfde structuur als de bron en alle drie de interne links overal intact.

  - **Tests kunnen de repository waarin ze worden uitgevoerd niet langer wijzigen.** Bij een push vanuit een gekoppelde worktree geeft git de variabele die de repository aanwijst door aan zijn hooks, waarna de pre-push-hook de tests uitvoert: de `git init` van een test, bedoeld voor een tijdelijke map, heeft de echte repository opnieuw ingesteld, die plotseling zonder werkboom werd gemeld. Tests die git uitvoeren, verwijderen voortaan alle `GIT_*`-variabelen uit hun omgeving en een regressietest die met deze variabele een lokrepository aanwijst, controleert dit.

- **1.16.0** Provider `--use_claude_code`: vertalen met het quotum van een Claude Pro- of Max-abonnement via de officiële CLI `claude -p` — geen betaalde route, en elke aanroep bewijst dat (2026-09-26):

  - **Elfde route: het Claude-abonnement, zonder facturering op basis van gebruik.** `--use_claude_code` bestuurt het officiële binaire bestand van Claude Code in de modus `-p`, op dezelfde basis als Codex, Grok CLI en Antigravity — eigen procesgroep, veilige beëindiging bij een time-out, Ctrl-C of het sluiten van de terminal. Niet te verwarren met `--use_claude`, de op gebruik gebaseerde betaalde API van Anthropic. aipmt leest de token nooit.

  - **Geen betaalde route, op drie niveaus gecontroleerd.** De omgeving van het subproces is een allowlist: geen API-sleutel, token of cloudprovider, en ook geen marker van de Claude Code-sessie waaruit aipmt zou zijn gestart — de sessie die deze provider heeft geschreven, exporteerde er vijftien. De preflight, zonder modelbeurt, vereist van `claude auth status` dat het een abonnementsverbinding zonder Console-sleutel meldt en van `/usage` de zin die het abonnement bevestigt. Elke aanroep moet dit vervolgens bevestigen in zijn initialisatie-event — `apiKeySource: none`, de afgedwongen omgeving correct ontvangen, een model uit de gevraagde familie, geen snelle modus — en in zijn quotumoverzicht: betaald „extra usage” stopt de vertaling onmiddellijk.

  - **Het quotum wordt gedeeld met Claude Code-sessies en de provider springt er zuinig mee om.** Elke aanroep rapporteert het gebruik van de vensters van 5 uur en van de week; boven 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`) wordt geen volgend segment gestart. Op de dag dat dit werd geschreven, zat het weekgebruik van het account van de auteur al op 98%.

  - **Niets uit de gebruikersconfiguratie komt binnen en niets uit de sessie blijft achter.** Zonder tools, in een modus zonder personalisatie, met genegeerde gebruikersinstellingen, uitgeschakelde MCP-servers en hooks, een persoonlijke tijdelijke werkmap en zonder opgeslagen transcriptie. Gemeten met canaries: zonder `CLAUDE_CODE_DISABLE_ATTACHMENTS` veranderde een `@chemin` uit het document in een bijlage en gaf het model een leesaanroep terug in plaats van de vertaling; hiermee komt niets door. De canaries `AGENTS.md`, `CLAUDE.md` en de hook hebben niets geladen of uitgevoerd.

  - **Een segment dat begint met `/` bereikte het model niet.** Onder `--disable-slash-commands` antwoordt Claude Code daarop zelf met „… isn't available in this environment.”, met status `success`, zonder enige beurt. Een regeleinde vóór het segment stuurt het naar het model; het uitvoercontract weigert sowieso een antwoord dat zonder beurt, na meer dan één beurt, afgekapt of door een ander model dan aangekondigd wordt teruggegeven.

  - **Modellen: aliassen, nooit een vastgezette identifier.** Standaard `sonnet`, met inspanning `low`, en ook in `--eco` — `--eco` verandert op deze route dus niets —, `opus` en `haiku` via `--model`; `fable` en de varianten `[1m]` worden geweigerd, omdat ze in `-p` zonder waarschuwing op betaalde credits overschakelen.

  - **De standaardwaarden zijn gemeten, niet verondersteld.** Door `aipmt --use_claude_code` zelf, vier vertalingen parallel, op de twee documenten uit de metingen van de README — het informatierijke monitoringartikel, in `--news`, en deze README in revisie 1.14.0 —, elk in veertien talen. `sonnet`, met inspanning `low`, schrijft alle 28 vertalingen, waarvan 26 zonder afwijking: één extra vetgedrukt woord in het Chinese artikel en in het Arabisch op de README een tabelregel die aan de vorige regel is vastgeplakt, wat door de weergave wordt verborgen. Interne links intact, Engelse citaten letterlijk overgenomen en in het Engels de Franse vertaalregels door het model verwijderd, zonder een vlag te verzinnen; een mediaan van 6 min. 49 sec. per taal voor het artikel en 2 min. 20 sec. voor de README. `opus` vertaalt de README zonder enige afwijking, een kwart sneller, maar geen enkel artikel: zijn veiligheidsmechanismen hebben het antwoord in alle veertien talen gestopt bij een kort biologiebericht. `haiku` schrijft daarentegen alles — drie sectiekoppen in het artikel veranderd in niveau 1, de interne links van de Engelse README verdubbeld —, maar twee keer zo langzaam als `sonnet`: het redeneert zonder dat dit kan worden verhinderd, met 61% van zijn uitvoertokens, en zijn lagere prijs levert daardoor slechts 14% besparing op in API-equivalent. Vandaar `sonnet` ook in `--eco`. De inspanning heeft voor vertalingen geen nut: in een eerdere reeks — deze README en deze CHANGELOG in het Engels, Japans en Hindi — produceerde `sonnet` geen enkele redeneertoken, gebruikte `opus` met gemiddelde inspanning 1% van zijn uitvoertokens voor redeneren, en leverde gemiddelde inspanning ten opzichte van lage inspanning geen verbetering op in structuur of duur. De campagne `sonnet`, met 1,8 miljoen brontekens, verbruikte 9 procentpunten van het venster van 5 uur en 2 van het weekvenster op het Max-abonnement van de auteur — een bovengrens: de sessie die de metingen aanstuurde, putte uit hetzelfde quotum.
  - **Een weigering door de veiligheidsmaatregelen van Anthropic wordt als zodanig benoemd.** Opus 5.5 heeft strengere veiligheidsmaatregelen dan Sonnet, en het foutbericht van Anthropic waarschuwt dat deze soms werk signaleren dat dicht bij biologisch onderzoek ligt. Een korte monitoringsnotitie over 279 moleculen die voor een bindingsplaats waren gegenereerd, volstond. Claude Code breekt het antwoord dan af, probeert het eenmaal opnieuw en het model geeft gedurende twee beurten « I can't continue this translation » terug met een successtatus en zonder fout: alleen het contract voor één beurt hield dit antwoord tegen, met een bericht dat zweeg over de oorzaak. Wanneer de notitie afzonderlijk wordt verzonden, weigert de API deze vanwege de categorie « bio ». aipmt herkent deze signalen voortaan, benoemt de veiligheidsmaatregelen en hun categorie, probeert het niet opnieuw — dezelfde tekst zou opnieuw dezelfde weigering uitlokken — en adviseert `--model sonnet`, dat de notitie in alle veertien talen heeft vertaald.

  - **De vertalingen van deze repository kunnen zonder uitzondering via deze route verlopen.** `REGEN_PROVIDER=claude_code` is een abonnement, geen gefactureerde API: het werkt zonder `REGEN_ALLOW_PAID_API`, met vier jobs — de campagnes draaiden met vier gelijktijdige vertalingen zonder één fout vanwege snelheidslimieten of verbindingsvergrendeling —, na één preflight die geen quota verbruikt. Codex met `gpt-5.6-sol` blijft de standaard.

  - **De gebruiksvoorwaarden, zonder omwegen.** De juridische pagina van Claude Code verbiedt een gebruiker niet om met een eigen abonnement verbinding te maken met het ongewijzigde binaire bestand; ze verbiedt externe ontwikkelaars om verzoeken via de Pro- of Max-inloggegevens van hun gebruikers te laten lopen, en Anthropic geeft voor tools van derden, waaronder open-sourceprojecten, de voorkeur aan de API-key en behoudt zich het recht voor hun gebruik van betaalde credits af te trekken. Geen enkele tekst geeft uitsluitsel over het geval van een gedistribueerde tool die het officiële binaire bestand start: de gebruiker stelt zijn account bloot aan risico.

  - **Tests**: nieuw bestand `tests/test_claude_code_provider.py` (58 tests), 100% van de instructies en vertakkingen van de module, zonder ooit het echte `claude` te starten — leeggemaakte omgeving, niet-bestaand binair bestand, `PATH` zonder `claude`, testdubbels die een exception genereren als ze worden aangeroepen.

- **1.15.0** Provider `--use_antigravity`: vertalen met het quotum van het Google AI Pro- of Ultra-abonnement, via de officiële CLI `agy`; en voor alle providers geldt dat Ctrl-C niet langer een actieve agent achterlaat, een leeg segment het bestand niet meer laat mislukken en een `.env` van het project niet langer bepaalt welk binair bestand wordt uitgevoerd (2026-09-26):

  - **Tiende providerroute: het Google-abonnement, zonder facturering per gebruik.** Wie voor Google AI Pro of Ultra betaalt, kan vertalingen voortaan van dit quotum laten aftrekken in plaats van ze per token via de Gemini API te betalen. `agy`, de officiële CLI van Antigravity, is de enige route naar dit quotum: Gemini CLI bedient sinds 18 juni 2026 geen Pro-, Ultra- of gratis accounts meer, en de Antigravity SDK verifieert zich uitsluitend met een API-key of via Google Cloud. `--use_antigravity` bestuurt deze in headless-modus, zoals Codex en Grok CLI, op dezelfde basis — een eigen procesgroep, `SIGTERM` en vervolgens `SIGKILL` wanneer de timeout verstrijkt, en een opgeschoonde omgeving. End-to-end geverifieerd met agy 1.2.11: een Markdown-gids — front matter, vetgedrukte tekst, link met haakjes, inline code, ingesprongen codeblok in een lijst, tabel, citaat — werd inclusief preflight in 14 seconden naar het Engels vertaald, met dezelfde structuur als de bron en een toegevoegde vertaalnotitie; vervolgens, na de correcties uit de review, in 19 seconden naar het Duits, met dezelfde structuur en zonder dat er iets in `~/.gemini` werd geschreven.

  - **Geen enkele betaalde route blijft open en iedere start controleert dit.** agy kent naast het abonnement andere routes — API-key, Google Cloud-project, gateway, betaalde AI-credits — en meerdere omgevingsvariabelen laten het zonder enige melding daarop overschakelen. Gemeten: `AGY_GATEWAY_URL` stuurt het document naar een gateway van een derde partij, `AGY_ADC_AUTH` schakelt over naar een gefactureerd Google Cloud-project, `CLOUD_CODE_URL` leidt het geauthenticeerde endpoint om naar een willekeurig adres. De omgeving van het subproces is daarom gebaseerd op een allowlist en niet op een denylist: `PATH`, de taal en tijdzone, de terminal, de identiteit, de proxies en certificaten van de machine en de session bus — waarvan een `env -i` heeft bewezen dat agy die nodig heeft —, zonder enige sleutel. Een aanvankelijk uitgeprobeerde denylist op basis van prefixfamilies (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…) liet variabelen door de mazen glippen: een review vond in de strings van het binaire bestand endpoint-overschrijvingen die door geen enkele prefix werden gedekt, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Twee instellingen ontsnappen aan de omgeving en kunnen alleen via `agy -p /config` worden gelezen: de betaalde AI-credits die het overnemen wanneer een quotum is uitgeput, en de verbinding via een Google Cloud-project. Een preflight die geen quotum verbruikt — gemeten gebruik: nul — weigert te vertalen als een van beide actief is of als een API-key is ingesteld, en een instelling die in `/config` ontbreekt, geldt voor alle drie als een weigering: een versie van agy die er een hernoemt, mag een controle die niets heeft geverifieerd niet doorstaan. Ten slotte moet het logboek van iedere aanroep authenticatie via het abonnement bevestigen (`authMethod=consumer`), en iedere andere authenticatiemethode die daarin voorkomt, in een van beide schrijfwijzen die het binaire bestand gebruikt, leidt tot weigering van het antwoord: de aanroep zelf geldt als bewijs, niet de voorbereide configuratie.

  - **De vertaalagent heeft geen enkele tool en bij iedere aanroep wordt bewezen dat hij is geladen.** Iedere aanroep schrijft in een tijdelijke map een agent in de indeling voor projectagents van agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Ongeveer 800 inputtokens in plaats van 12.400 met de standaardagent, en de derde instelling is niet redundant: alleen `excludeDefaultComponents` liet een hook uit de workspace nog steeds zijn opdrachten uitvoeren en zijn tekst injecteren. De echte valkuil ligt elders: agy mislukt niet wanneer een agent niet kan worden gevonden. Exitcode 0, status `SUCCESS`, waarna de codeeragent met 57 actieve tools antwoordt — op « De kat slaapt. » antwoordde hij « Sst, laten we hem niet wakker maken! 🐱💤 Wat kan ik vandaag voor u doen? ». Niets op stdout of stderr: alleen het logboek van de aanroep vermeldt dit. Het antwoord wordt daarom geweigerd als het logboek deze fallback meldt, maar ook als het niet de positieve markering voor het laden van de agent bevat — een wijziging in de logindeling weigert de vertaling in plaats van de beveiliging stilzwijgend te verwijderen. Iedere markering moet een volledige regel van het logboek beslaan, in de gemeten indeling — ernstniveau, datum, tijd, thread, bestand en regel: het binaire bestand bevat ook een regel die het bericht van de gebruiker naar het logboek kopieert — nooit aangetroffen op het standaardlogniveau in 78 echte logboeken —, en een document dat deze berichten citeert, mag niet in plaats van agy aan de beveiliging kunnen voldoen.

[OpenRouter](https://openrouter.ai) geeft met één sleutel toegang tot modellen die geen enkele andere provider hier aanbiedt — Kimi, Qwen, DeepSeek, Z.ai — via één tegoed dat naar gebruik wordt gefactureerd. Omdat het endpoint compatibel is met OpenAI, wordt dezelfde client gebruikt als voor xAI; **alles wat deze provider onderscheidt, zit in een preflight**, en elk van de regels daarvan is gebaseerd op een meting van de API.

  - **Hetzelfde model wordt aangeboden door tientallen hosts met verschillende limieten, en de routering houdt daar geen rekening mee.** Gemeten: 33 hosts voor `z-ai/glm-5.2`, 23 voor `z-ai/glm-5.3-flash` — waaronder één met een limiet van **2.048 outputtokens**. Een lange vertaling via die 23 kon daardoor willekeurig worden afgekapt, zonder enig signaal. De preflight leest `/api/v1/models/{modèle}/endpoints`, sluit hosts uit met minder dan 8.000 outputtokens, met een verminderde status of zonder opgegeven limiet, en zet vervolgens de overige hosts vast. `provider.only` **zonder** `allow_fallbacks: false` is slechts een voorkeur: de router wijkt dan uit naar een uitgesloten host, waardoor het vastzetten waardeloos wordt. Als geen enkele host aan de limiet voldoet, stopt de opdracht: toch vertalen zou neerkomen op het accepteren van de stille afkapping die deze preflight juist moet voorkomen.

Bij een vertaling, waarvoor reasoning niets toevoegt, betekent dat een factor 18 voor elk segment van elk bestand. Daarom wordt het standaard uitgeschakeld. De **288 van de 431 modellen** die reasoning verplichten (`reasoning.mandatory`), antwoorden met `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: voor deze modellen leest de preflight welke efforts worden geaccepteerd en vraagt de laagste aan (volgende punt) — de effort reserveert een **percentage van `max_tokens`** dat eerst door reasoning wordt verbruikt, waardoor een willekeurig gekozen waarde het risico op een lege pagina alleen verplaatst in plaats van verkleint.

  - **Een model dat reasoning verplicht, ontvangt de laagste effort die het accepteert, en die keuze is op een meting gebaseerd.** De eerste keuze was om niets mee te sturen, om niet namens het model te gokken. Het verhogen van het budget zou niets hebben veranderd: de effort reserveert er een percentage van, waardoor reasoning met het budget meegroeit. De provider leest daarom tijdens de preflight `supported_efforts` en vraagt de laagste waarde aan, met ‘niets’ als fallback wanneer de catalogus geen bruikbare waarde vermeldt. Controletest op de problematische taal: die mislukte eerder doordat het budget was opgebruikt, maar slaagt nu in 9 minuten met een structuur die identiek is aan de bron.

Van begin tot eind geverifieerd: wanneer `codex` niet aanwezig is in `PATH`, vindt de resolutie de meegeleverde binary en wordt een volledige vertaling in 6 s voltooid.
  - **Garantie voor „abonnementsmodus”**: `OPENAI_API_KEY` en `CODEX_API_KEY` worden uit de omgeving van het subprocess verwijderd. Zonder deze beveiliging zou een in `.env` aanwezige sleutel Codex zonder enig zichtbaar signaal kunnen laten overschakelen op facturering per gebruik — precies wat deze provider moet voorkomen.
  - **Valkuilen van de CLI afgedekt met tests**:
    - `codex exec` leest stdin **zelfs** wanneer de prompt als argument wordt doorgegeven: zonder stdin te sluiten wacht de opdracht tot de timeout zonder ooit het model aan te roepen (gereproduceerd: exit 124 na 180 s, nul bytes). `communicate(input=...)` is daarom verplicht.
    - De via npm geïnstalleerde `codex` is een Node-shim die de echte Rust-binary met `spawn` start: die binary is een **kleinkindproces** van het Python-proces en overleeft de `SIGKILL` van `subprocess.run(timeout=)`, waarna hij quotum zou blijven verbruiken. Vandaar `Popen(start_new_session=True)` + `os.killpg`.
    - De CLI kan met code 0 afsluiten terwijl hij toch een `turn.failed` heeft uitgevoerd: de JSONL-output (`--json`) wordt naast de returncode geïnspecteerd, en het ontbreken van het bestand `-o` bij code 0 veroorzaakt een expliciete fout in plaats van een leeg segment te produceren.
  - **Back-off bij rate limit**: de CLI implementeert intern geen enkele retry (`max_retries = 0`). De classificatie gebeurt op basis van de structuur van de JSON-payload (`status: 429` / `error.type`), niet op basis van substrings — het woord „quota” komt zowel voor in een herstelbare 429 als in een definitieve `insufficient_quota`.
  - **CI-beveiliging**: `--use_codex` wordt geweigerd als `CI` of `GITHUB_ACTIONS` is ingesteld. Authenticatie via een abonnement is niet bedoeld voor een gedeelde runner en OpenAI raadt deze workflow expliciet af voor openbare repositories.
  - **Modellen**: `gpt-5.6-sol` (kwaliteit) en `gpt-5.6-luna` (`--eco`). De `gpt-5.6-*`-familie wordt gedeeld door de CLI en de API Platform, maar een ChatGPT-account heeft niet overal toegang toe: de allowlist wordt aan serverzijde toegepast, zonder lokale validatie, en een ongebruikelijk model veroorzaakt een waarschuwing. Bij een Plus-abonnement biedt Luna 250-2 000 berichten per venster van 5 uur tegenover 10-100 voor Sol: `--eco` is de aanbevolen modus voor elke batchverwerking.
  - **Bug opgelost — `regen_translations.sh` sloot ondanks volledig succes af met een fout**: de `trap ... Onder `set -u` veroorzaakte dit `failed_log: unbound variable` en sloot het script af met code 1, hoewel alle 28 vertalingen correct waren — wat `release.sh --auto` (`set -e`) direct na het opnieuw genereren, tijdens de kostbaarste stap, zou hebben onderbroken. De variabele is nu globaal en de trap controleert of deze bestaat. Nuttig neveneffect: echte vertaalfouten, die tot dan toe door deze fout werden gemaskeerd, zijn opnieuw zichtbaar in het eindoverzicht.
