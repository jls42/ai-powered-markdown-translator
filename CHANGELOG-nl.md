- **1.16.3** Bestandseinde: een vertaling via API behoudt de afsluitende regeleinde van de bron en Mistral SDK 3.0 is gevalideerd (2026-10-04):

  - **Een vertaling via API behoudt de afsluitende regeleinde van de bron.** De API-providers — OpenAI, Anthropic, Gemini, Mistral — verwijderen de omringende witruimte uit het antwoord van het model. Bij het laatste segment verdween door deze opschoning de afsluitende regeleinde van de bron: een vertaald bestand zonder vertaalnotitie eindigde zonder regeleinde, wat git meldt en formatters bij elke uitvoering corrigeren. Dit werd opgemerkt tijdens de validatie van Mistral SDK 3.0, bij een handleiding die eindigde met een regeleinde waarvan de vertaling er geen meer had. De vertaalnotitie voegde er opnieuw een toe en de command-lineproviders — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — nemen het einde van het segment over: alleen een vertaling via API zonder notitie werd getroffen. De vertaling geeft voortaan de afsluitende regeleinde van de bron terug, ongeacht de provider, en voegt er geen toe aan een bron die er geen heeft.

  - **Mistral: SDK 3.0 gevalideerd met een echte aanroep.** `mistralai` 3.0.0 vervangt de HTTP-bibliotheek `httpx` door `httpx2`; de imports en de vertaalaanroep veranderen niet. Een nieuwe installatie van aipmt kreeg deze versie al, omdat de dependencies geen bovengrens voor de versie hebben, maar er was nog geen echte aanroep mee getest: een Markdown-handleiding die via de Mistral API met SDK 3.0 is vertaald, behoudt dezelfde structuur als de bron. De voor ontwikkeling vastgezette versies gaan over op deze SDK en de tests voor nieuwe pogingen leveren er een `httpx2`-client aan, dezelfde die in productie wordt gebruikt.

- **1.16.2** Codebescherming: aangehaalde code in een citaat `--news` en een ingesprongen blok in een lijst zorgen er niet langer voor dat de vertaling voor alle talen wordt geweigerd (2026-10-03):

  - **Aangehaalde code in een citaat blokkeert de vertaling niet langer.** In de modus `--news` beschermt aipmt inline code voordat Engelse citaten apart worden gezet en ongewijzigd worden hersteld. Code die in een citaat stond, verdween dus samen met dat citaat: het model kreeg het token nooit te zien en de validatie verklaarde het voor alle talen verloren. De dagelijkse nieuwsrondgang van de auteur stopte daar op 2 oktober: een in een tweet aangehaalde opdracht `/plugin enable …`, de controletaal tweemaal geweigerd en de dertien andere nooit gestart. De tokens die samen met een citaat zijn weggenomen, worden voortaan opgelost in de apart gezette tekst. Bij Engels als doeltaal wordt de Franse vertaalregel van een citaat niet meer naar het model gestuurd: de instructie vroeg het model die te verwijderen, waarna de code op die regel als verloren werd geteld terwijl het model juist had gehoorzaamd. Het gepubliceerde resultaat verandert niet. Ten slotte interpreteert het herstellen van een citaat de backslashes niet langer opnieuw: een aangehaalde `\n` blijft een `\n`. Van begin tot eind geverifieerd op het artikel dat was mislukt: Engels en Duits bij de eerste poging vertaald door `gpt-6.1-sol`, met dezelfde structuur als de gepubliceerde versies.

  - **Een ingesprongen codeblok in een lijst wordt beschermd.** CommonMark staat een ingesprongen afsluiting van een blok toe, en dat is de normale situatie voor een blok dat een stap in een genummerde lijst documenteert: het behoort tot het lijstitem en is daarom ingesprongen. Doordat het beschermingspatroon aan kolom 0 was verankerd, miste het ze allemaal: gemeten op een echte README werden 8 van de 14 blokken herkend. De andere zes werden als proza naar het model gestuurd en kwamen ongewijzigd terug, omdat het opdrachten zijn, waarna de beveiliging die een letterlijk overgenomen vertaling weigert het bestand voor alle talen afwees, met een melding die het symptoom noemde maar nooit de oorzaak. Het patroon accepteert voortaan een ingesprongen afsluiting en de heen-en-terugbewerking tussen bescherming en herstel geeft het document identiek terug, inclusief inspringing.

- **1.16.1** Interne links: het ankertoken laat de haakjes bij de link staan en een vertaalde link wordt niet langer ongemerkt verdubbeld (2026-09-27):

  - **Een interne link raakt niet langer defect zonder dat dit wordt opgemerkt.** Om een link naar een sectie te beschermen, `[texte](#ancre)`, verving aipmt het gedeelte tussen haakjes, inclusief de haakjes zelf, door een token: het model kreeg vierkante haken gevolgd door een los token, wat op een defecte link leek, en probeerde die soms te ‘repareren’. Het herstel leverde dan `[texte]((#ancre))` op, een link die nergens heen leidt, zonder dat enige beveiliging dit meldde. Het defect keerde bij elke regeneratie van de vertalingen van deze repository terug — in het Spaans, Koreaans en vervolgens Italiaans voor 1.15.0, en in het Duits voor 1.16.0 — met elke geteste Gemini Flash, en zelfs met Claude Sonnet en Haiku. Het token van een Markdown-link behoudt voortaan zijn haakjes: het model krijgt een geldige link die het niet meer hoeft te repareren, en het herstel accepteert ook een token waarvan het model de haakjes zou hebben verwijderd. HTML-ankers behouden een los token. Van begin tot eind geverifieerd met het kwetsbaarste model, `gemini-3.8-flash-low`, op een README waarin een link tussen haakjes stond: zonder de correctie werd de README geweigerd, werden drie links verdubbeld en werd één segment opnieuw verwerkt; met de correctie bleven alle drie links intact en hoefde niets opnieuw te worden verwerkt. Daarna op deze README, in het Duits, Japans en Hindi via `gemini-3.8-flash-medium`, en in het Duits via Claude Code met `sonnet`: dezelfde structuur als de bron en alle drie interne links overal intact.

  - **De tests kunnen de repository waarin ze worden uitgevoerd niet langer wijzigen.** Wanneer vanuit een gekoppelde worktree wordt gepusht, geeft git de variabele die de repository aanwijst door aan zijn hooks, waarna de pre-push-hook de tests uitvoert: de `git init` van een test, bedoeld voor een tijdelijke map, heeft de echte repository opnieuw geïnitialiseerd, die daardoor plotseling zonder werkstructuur werd gemeld. Tests die git uitvoeren, verwijderen voortaan alle `GIT_*`-variabelen uit hun omgeving, en een regressietest die met deze variabele naar een lokrepository verwijst, verifieert dit.

- **1.16.0** Provider `--use_claude_code`: vertalen binnen het quotum van een Claude Pro- of Max-abonnement via de officiële CLI `claude -p` — geen betaald pad, en elke aanroep bewijst dat (2026-09-26):

  - **Elfde pad: het Claude-abonnement, zonder facturering per gebruik.** `--use_claude_code` bestuurt het officiële binaire bestand van Claude Code in de modus `-p`, op dezelfde basis als Codex, Grok CLI en Antigravity — een eigen procesgroep en veilige beëindiging bij een time-out, Ctrl-C of het sluiten van de terminal. Niet te verwarren met `--use_claude`, de per gebruik gefactureerde API van Anthropic. aipmt leest het token nooit.

  - **Geen betaald pad, op drie niveaus geverifieerd.** De omgeving van het subproces is een allowlist: geen API-sleutel, token, cloudprovider of marker van de Claude Code-sessie waaruit aipmt zou worden gestart — de sessie waarin deze provider werd geschreven, exporteerde er vijftien. De preflight, zonder modelbeurt, vereist van `claude auth status` een abonnementsaanmelding zonder Console-sleutel en van `/usage` de zin die het abonnement bevestigt. Elke aanroep moet dit vervolgens bevestigen in zijn initialisatie-event — `apiKeySource: none`, de afgedwongen omgeving correct ontvangen, een model uit de gevraagde familie en geen snelle modus — en in zijn quotumoverzicht: betaald ‘extra usage’ stopt de vertaling onmiddellijk.

  - **Het quotum wordt gedeeld met Claude Code-sessies en de provider springt er zuinig mee om.** Elke aanroep rapporteert het gebruik van de vensters van 5 uur en van de week; boven 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`) wordt geen extra segment gestart. Op de dag waarop dit werd geschreven, stond de week van het account van de auteur al op 98%.

  - **Niets uit de gebruikersconfiguratie komt binnen en niets van de sessie blijft achter.** Zonder tools, in een modus zonder personalisatie, met genegeerde gebruikersinstellingen, uitgeschakelde MCP-servers en hooks, een privéwerkmap die wordt weggegooid en zonder opgeslagen transcriptie. Gemeten met canaries: zonder `CLAUDE_CODE_DISABLE_ATTACHMENTS` werd een `@chemin` uit het document een bijlage en gaf het model een leesaanroep terug in plaats van de vertaling; met deze optie komt niets door. De canaries `AGENTS.md`, `CLAUDE.md` en de hook hebben niets geladen of uitgevoerd.

  - **Een segment dat met `/` begint, bereikte het model niet.** Onder `--disable-slash-commands` antwoordt Claude Code daarop zelf met ‘… isn't available in this environment.’, met status `success`, zonder enige beurt. Een regeleinde vóór het segment stuurt het naar het model; het uitvoercontract weigert sowieso een antwoord dat zonder beurt, na meer dan één beurt, afgekapt of door een ander model dan het aangekondigde model is teruggegeven.

  - **Modellen: aliassen, nooit een vastgezette identifier.** Standaard `sonnet`, met inspanning `low`, en ook in `--eco` — `--eco` verandert dus niets op dit pad —, `opus` en `haiku` via `--model`; `fable` en de varianten `[1m]` worden geweigerd, omdat ze in `-p` zonder bevestiging overschakelen op betaalde credits.

  - **De standaardinstellingen zijn gemeten, niet verondersteld.** Via `aipmt --use_claude_code` zelf, met vier parallelle vertalingen, op de twee documenten uit de metingen in de README — het compacte nieuwsoverzicht, in `--news`, en deze README in revisie 1.14.0 —, elk in veertien talen. `sonnet`, met inspanning `low`, schrijft de 28 vertalingen, waarvan 26 zonder afwijking: één extra vetgedrukt woord in het Chinees in het artikel en, in het Arabisch in de README, een tabelregel die aan de vorige was vastgeplakt maar door de weergave wordt verhuld. Interne links intact, Engelse citaten ongewijzigd overgenomen en in het Engels de Franse vertaalregels door het model verwijderd zonder een vlag te verzinnen; een mediaan van 6 min. 49 s per taal voor het artikel en 2 min. 20 s voor de README. `opus` vertaalt de README zonder enige afwijking, een kwart sneller, maar geen enkel artikel: zijn beveiligingen hebben het antwoord in alle veertien talen gestopt bij een kort biologisch bericht. `haiku` schrijft daarentegen alles — drie sectietitels in het artikel werden van niveau 1 en de interne links van de Engelse README werden verdubbeld —, maar tweemaal zo langzaam als `sonnet`: het redeneert zonder dat dit kan worden verhinderd, goed voor 61% van zijn uitvoertokens, en door de lagere prijs blijft daarvan slechts 14% besparing in API-equivalent over. Daarom ook `sonnet` in `--eco`. Inspanning is nutteloos voor vertalen: in een eerdere batch — deze README en deze CHANGELOG in het Engels, Japans en Hindi — produceerde `sonnet` geen enkel redeneertoken, terwijl `opus` bij gemiddelde inspanning 1% van zijn uitvoertokens daaraan besteedde; gemiddelde inspanning leverde ten opzichte van lage inspanning niets op, noch qua structuur, noch qua duur. De campagne `sonnet`, met 1,8 miljoen bronkarakters, kostte 9 procentpunten van het venster van 5 uur en 2 van de week op het Max-abonnement van de auteur — een bovengrens: de sessie die de metingen aanstuurde, gebruikte hetzelfde quotum.

  - **Een weigering door de beveiligingen van Anthropic wordt als zodanig benoemd.** Opus 5.5 heeft strengere beveiligingen dan Sonnet en de foutmelding van Anthropic waarschuwt dat die soms werkzaamheden signaleren die dicht bij biologisch onderzoek liggen. Een kort nieuwsbericht over 279 moleculen die voor een bindingsplaats waren gegenereerd, was voldoende. Claude Code kapt het antwoord dan af, probeert het eenmaal opnieuw en het model geeft ‘I can't continue this translation’ terug met een successtatus, zonder fout, verdeeld over twee beurten: alleen het contract dat één beurt vereist stopte dit antwoord, met een melding die niets over de oorzaak zei. Wanneer alleen het korte bericht wordt verzonden, weigert de API het onder de categorie ‘bio’. aipmt herkent deze signalen voortaan, benoemt de beveiligingen en hun categorie, probeert het niet opnieuw — dezelfde tekst zou dezelfde weigering opnieuw uitlokken — en beveelt `--model sonnet` aan, dat het korte bericht in alle veertien talen heeft vertaald.

  - **De vertalingen van deze repository kunnen zonder uitzondering via dit pad verlopen.** `REGEN_PROVIDER=claude_code` is een abonnement en geen per gebruik gefactureerde API: het werkt zonder `REGEN_ALLOW_PAID_API`, met vier jobs — de campagnes draaiden met vier gelijktijdige vertalingen zonder enige fout wegens snelheidsbeperking of een verbindingsvergrendeling —, na één preflight die geen quotum verbruikt. De standaard blijft Codex met `gpt-5.6-sol`.

  - **De gebruiksvoorwaarden, zonder omwegen uiteengezet.** De juridische pagina van Claude Code verhindert een gebruiker niet om met een eigen abonnement verbinding te maken met het ongewijzigde binaire bestand; ze verbiedt externe ontwikkelaars verzoeken via de Pro- of Max-inloggegevens van hun gebruikers te laten lopen, en Anthropic geeft voor externe tools, waaronder opensourceprojecten, de voorkeur aan de API-sleutel en behoudt zich het recht voor hun gebruik van betaalde credits af te trekken. Geen enkele tekst geeft uitsluitsel over een gedistribueerde tool die het officiële binaire bestand start: de gebruiker zet zijn account in.

  - **Tests**: nieuw bestand `tests/test_claude_code_provider.py` (58 tests), 100% van de instructies en vertakkingen van de module, zonder ooit de echte `claude` te starten — leeggemaakte omgeving, niet-bestaand binair bestand, `PATH` zonder `claude`, testdubbels die een uitzondering opwerpen als ze worden aangeroepen.

- **1.15.0** Provider `--use_antigravity`: vertalen binnen het quotum van het Google AI Pro- of Ultra-abonnement via de officiële CLI `agy`; en voor alle providers geldt dat Ctrl-C geen actieve agent meer achterlaat, een leeg segment niet langer het hele bestand laat mislukken en een `.env` van het project niet langer bepaalt welk binair bestand wordt uitgevoerd (2026-09-26):

  - **Tiende providerpad: het Google-abonnement, zonder facturering per gebruik.** Wie voor Google AI Pro of Ultra betaalt, kan vertalingen voortaan van dat quotum laten aftrekken in plaats van per token voor de Gemini API te betalen. `agy`, de officiële CLI van Antigravity, is het enige pad naar dit quotum: Gemini CLI ondersteunt Pro-, Ultra- en gratis accounts sinds 18 juni 2026 niet meer, en de Antigravity SDK verifieert zich uitsluitend met een API-sleutel of via Google Cloud. `--use_antigravity` bestuurt deze in headless-modus, net als Codex en Grok CLI, op dezelfde basis — een eigen procesgroep, `SIGTERM` en vervolgens `SIGKILL` bij het verstrijken van de tijdslimiet, en een opgeschoonde omgeving. Van begin tot eind geverifieerd met agy 1.2.11: een Markdown-handleiding — front matter, vetgedrukte tekst, een link met haakjes, inline code, een ingesprongen codeblok in een lijst, een tabel en een citaat — in 14 seconden naar het Engels vertaald, inclusief preflight, met dezelfde structuur als de bron en een toegevoegde vertaalnotitie; vervolgens, na de correcties uit de review, in 19 seconden naar het Duits, met dezelfde structuur en zonder iets naar `~/.gemini` te schrijven.
  - **Geen enkel betaald pad blijft open, en elke uitvoering controleert dat.** agy kent naast het abonnement nog andere paden — API-sleutel, Google Cloud-project, gateway, betaalde AI-tegoeden — en meerdere omgevingsvariabelen schakelen er zonder enige melding naartoe over. Gemeten: `AGY_GATEWAY_URL` stuurt het document naar een gateway van een derde partij, `AGY_ADC_AUTH` schakelt over op een gefactureerd Google Cloud-project, `CLOUD_CODE_URL` leidt het geauthenticeerde endpoint om naar een willekeurig adres. De omgeving van het subprocess is daarom gebaseerd op een allowlist en niet op een denylist: `PATH`, de taal en tijdzone, de terminal, de identiteit, de proxies en certificaten van de machine en de sessiebus — waarvan een `env -i` heeft aangetoond dat agy die nodig heeft —, zonder enige sleutel. Een denylist op basis van prefixfamilies (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), die eerst werd geprobeerd, miste er enkele: een review vond in de strings van de binary endpoint-overschrijvingen die door geen enkele prefix werden gedekt, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Twee instellingen vallen buiten de omgeving en kunnen alleen via `agy -p /config` worden gelezen: de betaalde AI-tegoeden die het overnemen wanneer een quotum is uitgeput, en de verbinding via een Google Cloud-project. Een preflight die geen quotum verbruikt — nul verbruik, gemeten — weigert te vertalen als een van beide actief is of als een API-sleutel is geconfigureerd, en een instelling die in `/config` ontbreekt, geldt voor elk van de drie als reden voor weigering: een versie van agy die een instelling zou hernoemen, mag niet slagen voor een controle die niets heeft geverifieerd. Ten slotte moet het logboek van elke aanroep authenticatie via het abonnement aantonen (`authMethod=consumer`), en elke andere authenticatiemethode die erin voorkomt, in een van de twee schrijfwijzen die de binary gebruikt, leidt tot weigering van het antwoord: de aanroep zelf is het bewijs, niet de configuratie die vooraf is ingesteld.

  - **De vertaalagent heeft geen enkel tool, en bij elke aanroep wordt bewezen dat hij is geladen.** Elke aanroep schrijft in een tijdelijke map een agent in de indeling van agy's projectagents: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Ongeveer 800 inputtokens in plaats van 12.400 met de standaardagent, en de derde instelling is niet overbodig: alleen `excludeDefaultComponents` liet een hook uit de workspace nog opdrachten uitvoeren en tekst injecteren. De echte valkuil zit elders: een niet-gevonden agent laat agy niet mislukken. Exitcode 0, status `SUCCESS`, waarna de coding agent met 57 actieve tools antwoordt — op ‘De kat slaapt.’ antwoordde hij: ‘Sst, laten we hem niet wakker maken! 🐱💤 Wat kan ik vandaag voor u doen?’. Niets op stdout of stderr: alleen het logboek van de aanroep vermeldt het. Het antwoord wordt daarom geweigerd als het logboek deze fallback meldt, maar ook als de positieve markering voor het laden van de agent ontbreekt — een wijziging van de logboekindeling laat de vertaling weigeren in plaats van de beveiliging stilzwijgend te verwijderen. Elke markering moet een volledige regel van het logboek beslaan, in de gemeten indeling — ernst, datum, tijd, thread, bestand en regel: de binary bevat ook een regel die het bericht van de gebruiker naar het logboek kopieert — nooit gezien op het standaardlogniveau, in 78 echte logboeken —, en een document dat deze berichten citeert, mag niet in plaats van agy aan de beveiliging kunnen voldoen.

  - **De instellingen en geschiedenis van agy van de gebruiker worden niet aangeraakt.** Elke aanroep draait met een eigen HOME, tijdelijke map en werkmap, die daarna worden verwijderd. agy authenticeert zich toch via de systeemkeyring, die aipmt nooit leest. Niets wordt overgenomen: noch de machtigingen van de gebruiker — waardoor de standaardagent `ls` en `git` zonder enige vraag kon uitvoeren —, noch diens globale regels, plugins, MCP-servers, hooks en skills. En er wordt niets aan diens geschiedenis toegevoegd, waarin elke aanroep een gesprek van ongeveer 200 KB achterliet, inclusief de vertaalde tekst: de testcampagne had daar ongeveer 95 gesprekken achtergelaten en 17 items verdrongen uit een cache met een limiet van 100. Geverifieerd: geen enkel bestand geschreven in `~/.gemini/antigravity-cli`.

  - **Standaard weigeren waar de isolatie niet standhoudt.** Onder Linux zonder D-Bus-sessiebus — SSH-sessie, container, server — slaat agy zijn token op in een bestand in `~/.gemini` in plaats van in de keyring, zoals het eigen changelog (1.1.3) vermeldt, en de isolatie van elke aanroep verbergt dat bestand. De weigering vindt nu plaats vóór elke uitvoering, met de werkelijke oorzaak, in plaats van na een minuut wachten op een verbindingscode, gevolgd door het advies opnieuw verbinding te maken, wat niets zou oplossen. Onder Windows leest agy `USERPROFILE`, `APPDATA` en `TEMP`, niet `HOME` of `TMPDIR` — volgens de Go-documentatie en de strings van de binary —: niets zou de aanroep daar isoleren van de instellingen of geschiedenis van de gebruiker, en `--use_antigravity` wordt er geweigerd zolang dit niet is gemeten. macOS slaagt, zonder te zijn gemeten; de factureringsbeveiliging, die de effectieve configuratie leest, houdt daar stand.

  - **`exit 0` bewijst niets, vierde CLI.** Een antwoord wordt alleen geaccepteerd met een exitcode van nul, een JSON-object met status `SUCCESS`, een conform logboek, geen geweigerde actie, geen opdracht, geen fout in de JSON, geen truncatiewaarschuwing op stderr en niet-lege tekst. `--print-timeout` wordt nooit gebruikt: wanneer die verstrijkt, retourneert agy de gedeeltelijke uitvoer als `SUCCESS`, met code 0; de timeout is extern en beëindigt de procesgroep. Een segment dat begint met `/commande`, `!commande` of `@fichier` wordt vertaald en nooit uitgevoerd of geïnterpreteerd — zonder `--disable-slash-commands` werd ‘/help’ uitgevoerd in plaats van vertaald. Een leeg segment bereikt agy niet meer, omdat de pipeline het ongewijzigd retourneert (zie hieronder), en wordt als laatste vangnet vóór de aanroep nog steeds geweigerd: bij lege invoer opent agy zijn interactieve interface met code 0. Opnieuw proberen volgt het veld `retryable` van de regel `AGY_ERROR` die agy sinds versie 1.2.6 naar stderr schrijft: het probeert tijdelijke fouten — 502, 503, 504, limiet per minuut — zelf al opnieuw, en alleen agy weet of de resterende fout nog tijdelijk is. Bij afwezigheid van dit veld wordt niet opnieuw geprobeerd wanneer het bericht over uitputting spreekt — bij Google heeft `RESOURCE_EXHAUSTED` dezelfde code 429 als een limiet per minuut, maar een uitgeput venster van 5 uur herstelt niet binnen 90 seconden —, en anders alleen bij rate limiting. Het antwoord neemt het regeleinde van het segment over: agy beëindigt zijn antwoord altijd met een regeleinde, dat bij het samenvoegen een midden in een zin gesplitste alinea in tweeën brak. Een verbroken sessie geeft een bericht dat zegt `agy` uit te voeren om opnieuw verbinding te maken. `AGY_CLI_DISABLE_AUTO_UPDATE=true` voorkomt ten slotte dat een nieuwe HOME bij elke aanroep in een eigen sessie een updatechecker start, buiten bereik van de timeout — de waarde `1` heeft daarentegen geen effect.

  - **Modellen: de reasoning effort maakt deel uit van de naam.** De identifiers zijn die van `agy models` — `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… Alleen een basisnaam, die agy zou weigeren, wordt vóór de aanroep geweigerd, met vermelding van de bestaande suffixen: `-medium` of `-low` voor een Flash, `-high` of `-low` voor een Pro. Standaard `gemini-3.8-flash-medium`, en `gemini-3.7-flash-low` in `--eco`, vastgesteld door de hieronder beschreven campagnes. `--reasoning_effort` heeft geen effect en meldt dat ook. De preflight leest `/api/v1/models/{modèle}/endpoints`, sluit hostingproviders uit met minder dan 8.000 uitvoertokens, met een degraded status of zonder opgegeven limiet, en zet de overige vervolgens vast. `provider.only` **zonder** `allow_fallbacks: false` is slechts een voorkeur: de router wijkt dan uit naar een uitgesloten hostingprovider, waardoor het vastzetten waardeloos wordt. Als geen enkele hostingprovider aan de limiet voldoet, stopt de opdracht: toch vertalen zou neerkomen op het accepteren van de stille afkapping die deze preflight juist moet voorkomen.

Bij een vertaling, waar reasoning niets toevoegt, betekent dat een factor 18 voor elk segment van elk bestand. Daarom is het standaard uitgeschakeld. De **288 van de 431 modellen** die het verplicht stellen (`reasoning.mandatory`), antwoorden met `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: voor deze modellen leest de preflight de geaccepteerde effort-niveaus en vraagt het laagste aan (volgende punt) — de effort wijst een **percentage van `max_tokens`** toe dat eerst door reasoning wordt verbruikt, waardoor een willekeurig gekozen waarde het risico op een lege pagina alleen verplaatst in plaats van vermindert.

  - **Een model dat reasoning verplicht stelt, krijgt de laagste effort die het accepteert, en die keuze is door een meting bepaald.** De eerste keuze was om niets te verzenden, om niet in plaats van het model te gokken. Getest op `z-ai/glm-5.3-flash`, waarvan de standaardwaarde in de catalogus `max` is: deze keuze leverde een uitvoer op die **na 32.768 tokens werd afgekapt** vóór het einde van de vertaling — twee van de veertien talen gingen verloren. De limiet verhogen zou niets hebben veranderd: de effort wijst er een percentage van toe, waardoor reasoning met de limiet meegroeit. De provider leest daarom tijdens de preflight `supported_efforts` en vraagt het laagste niveau aan, met een terugval naar “niets” wanneer de catalogus geen bruikbaar niveau vermeldt. Tegenproef met de problematische taal: eerder mislukte deze doordat het budget was uitgeput, nu slaagt deze in 9 minuten met een structuur die identiek is aan de bron.

  - **Een storing bij de upstream-hostingprovider draagt nu diens naam.** De router normaliseert dit geval als `finish_reason=error` met een lege `native_finish_reason` — tweemaal gemeten, in twee talen, telkens na precies 750 seconden. Het algemene bericht zette aan tot zoeken naar een fout in het document of in de segmentering; nu vermeldt het dat de storing bij de provider ligt en dat opnieuw proberen vaak volstaat.

- **1.9.2** Oplossing voor extractie van nieuwsbron-URL's met geneste haakjes of een Frans voorvoegsel (2026-05-11):

  - **Bug opgelost**: voor de extractie van bron-URL's in `_protect_news_quotes` werd de regex `re.search(r"\((.+?)\)", attribution)` gebruikt (luie capture tussen haakjes). Bij een bronvermelding van het type `(relayé par [@user sur X](https://x.com/.../123))` (geneste haakjes: het omsluitende `(` + `]()` van de Markdown-link) stopte de capture bij het eerste aangetroffen `)` → afgebroken tekenreeks waarin ook het Franse voorvoegsel zat: `relayé par [@user sur X](https://x.com/.../123` (zonder afsluitende `)`).
