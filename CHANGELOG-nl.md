- **1.16.2** Codebescherming: code geciteerd in een citaat `--news` en een ingesprongen blok in een lijst leiden er niet langer toe dat vertalingen voor alle talen worden geweigerd (2026-10-03):
  - **In een citaat geciteerde code blokkeert de vertaling niet meer.** In de modus `--news` beschermt aipmt inline code voordat citaten in het Engels apart worden gezet, die ongewijzigd worden hersteld. Code die in een citaat stond, verdween daarom daarmee: het model zag het token nooit, en de validatie verklaarde het als verloren, voor alle talen. De dagelijkse nieuwsmonitoring van de auteur stopte daar op 2 oktober: een in een tweet geciteerd `/plugin enable …`-commando, de sondetaal tweemaal geweigerd, de dertien overige nooit gestart. Tokens die door een citaat zijn meegenomen, worden nu opgelost in de apart gezette tekst. Bij een Engels doelbestand wordt de Franse vertaalregel van een citaat niet langer naar het model gestuurd: de instructie vroeg het model om deze te verwijderen, waardoor de code die erin stond als verloren werd geteld terwijl het model gehoorzaamde. Het gepubliceerde resultaat verandert niet. Tot slot herinterpreteert het herstellen van een citaat niet langer de backslashes: een geciteerde `\n` blijft een `\n`. End-to-end geverifieerd op het artikel dat was mislukt: Engels en Duits in één keer vertaald door `gpt-6.1-sol`, structuur identiek aan de gepubliceerde versies.

  - **Een ingesprongen codeblok in een lijst wordt beschermd.** CommonMark staat een verschoven afsluiting van een blok toe, en dit is het normale geval voor een blok dat een stap in een genummerde lijst documenteert: het hoort bij het lijstitem en is dus ingesprongen. Verankerd op kolom 0 miste het beschermingspatroon ze allemaal: gemeten op een echte README, 8 blokken gezien van de 14. De zes andere gingen als platte tekst naar het model, kwamen identiek terug omdat het commando's zijn, en de beveiliging die een letterlijk overgenomen vertaling weigert, wees het bestand voor alle talen af, met een melding die het symptoom noemde en nooit de oorzaak. Het patroon accepteert nu een ingesprongen afsluiting, en de roundtrip tussen bescherming en herstel levert het document identiek op, inclusief inspringing.

- **1.16.1** Interne links: het ankertoken behoudt de haakjes voor de link, en een vertaalde link verdubbelt niet langer geruisloos (2026-09-27):
  - **Een interne link breekt niet meer onopgemerkt.** Om een link naar een sectie te beschermen, `[texte](#ancre)`, verving aipmt het gedeelte tussen haakjes, inclusief haakjes, door een token: het model ontving rechte haken gevolgd door een kaal token, een schijnbaar gebroken link, en het kwam voor dat het model die ging "repareren". Het herstel leverde vervolgens `[texte]((#ancre))` op, een link die nergens heen leidt, zonder dat enige beveiliging dit meldde. De fout trad telkens op bij het opnieuw genereren van de vertalingen van deze repository — in het Spaans, Koreaans en vervolgens Italiaans voor 1.15.0, in het Duits voor 1.16.0 — bij elk geprobeerd Gemini Flash-model, en zelfs bij Claude Sonnet en Haiku. Het token van een Markdown-link behoudt nu zijn haakjes: het model ontvangt een geldige link die het niet langer hoeft te repareren, en het herstel accepteert ook een token waarvan het de haakjes zou hebben verwijderd. HTML-ankers behouden een kaal token. End-to-end geverifieerd met het meest kwetsbare model, `gemini-3.8-flash-low`, op een README waarvan een link tussen haakjes stond: zonder de fix, README geweigerd, drie gedupliceerde links en één segment opnieuw verwerkt; mét de fix, drie links van de drie intact, geen herhalingen. Vervolgens op deze README, in het Duits, Japans en Hindi door `gemini-3.8-flash-medium`, en in het Duits door Claude Code met `sonnet`: structuur identiek aan de bron, de drie interne links overal intact.

  - **Tests kunnen de repository die ze start niet langer wijzigen.** Wanneer git vanuit een gekoppelde worktree wordt gepusht, geeft het de variabele door die naar de repository verwijst aan zijn hooks, en de pre-push hook voert de tests uit: de `git init` van een test, bedoeld voor een tijdelijke map, herstelde de echte repository, die plotseling werd verklaard als zijnde zonder working tree. Tests die git aanroepen, verwijderen nu elke `GIT_*`-variabele uit hun omgeving, en een regressietest, die via deze variabele naar een dummy-repository verwijst, verifieert dit.

- **1.16.0** Provider `--use_claude_code`: vertalen via het quotum van het Claude Pro- of Max-abonnement, via de officiële CLI `claude -p` — geen betaald traject, en elke aanroep bewijst dit (2026-09-26):
  - **Elfde traject: het Claude-abonnement, zonder facturering naar verbruik.** `--use_claude_code` stuurt het officiële binaire bestand van Claude Code aan in modus `-p`, op dezelfde basis als Codex, Grok CLI en Antigravity — eigen procesgroep, veilige stop bij time-out, Ctrl-C of sluiting van de terminal. Niet te verwarren met `--use_claude`, de API van Anthropic die naar verbruik wordt gefactureerd. aipmt leest het token nooit.

  - **Geen betaald traject, geverifieerd op drie niveaus.** De omgeving van het subproces is een allowlist: geen API-sleutel, geen token, geen cloudprovider, geen markering van de Claude Code-sessie van waaruit aipmt zou worden gestart — degene die deze provider heeft geschreven, exporteerde er vijftien. De preflight, zonder modelturn, vereist van `claude auth status` de abonnementsverbinding zonder Console-sleutel, en van `/usage` de zin die het abonnement bevestigt. Elke aanroep moet dit vervolgens bevestigen in zijn initialisatie-event — `apiKeySource: none`, geforceerde omgeving correct ontvangen, model uit de gevraagde familie, geen snelle modus — en in het quotumoverzicht: betaald "extra usage" stopt de vertaling onmiddellijk.

  - **Het quotum wordt gedeeld met Claude Code-sessies, en de provider springt er zuinig mee om.** Elke aanroep rapporteert het gebruik van de vensters van 5 uur en de week; boven de 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`) wordt er geen enkel segment meer gestart. Op de dag van schrijven zat de week van het account van de auteur al op 98%.

  - **Niets uit de configuratie van de gebruiker komt binnen, niets van de sessie blijft achter.** Zonder tools, in modus zonder personalisatie, gebruikersinstellingen genegeerd, MCP-servers en hooks uitgeschakeld, private en tijdelijke werkmap, geen transcriptie bewaard. Gemeten met canaries: zonder `CLAUDE_CODE_DISABLE_ATTACHMENTS` werd een `@chemin` in het document een bijlage, en gaf het model een leesaanroep terug in plaats van de vertaling; mét komt er niets doorheen. De canaries `AGENTS.md`, `CLAUDE.md` en hook hebben niets geladen of uitgevoerd.

  - **Een segment dat begint met `/` bereikte het model niet.** Onder `--disable-slash-commands` antwoordt Claude Code daar zelf op met "… isn't available in this environment.", met status `success`, zonder enige modelturn. Een regeleinde vóór het segment stuurt het naar het model; het outputcontract weigert sowieso een antwoord dat wordt geretourneerd zonder turn, in meer dan één turn, afgekapt, of door een ander model dan het aangekondigde.

  - **Modellen: aliassen, nooit een vaste identifier.** `sonnet` standaard, met effort `low`, en ook in `--eco` — `--eco` verandert dus niets op dit traject —, `opus` en `haiku` via `--model`; `fable` en de varianten `[1m]` worden geweigerd, omdat ze in `-p` zonder waarschuwing overgaan op betaalde credits.

  - **Gebreken worden gemeten, niet aangenomen.** Door `aipmt --use_claude_code` zelf, vier vertalingen parallel, op de twee meetdocumenten van de README — het compacte nieuwsmonitoringsartikel, in `--news`, en deze README in revisie 1.14.0 —, elk veertien talen. `sonnet`, met effort `low`, schrijft de 28 vertalingen, waarvan 26 zonder afwijking: één extra vetgedrukt woord in het Chinees in het artikel, en in het Arabisch, in de README, een tabelrij die aan de vorige plakte, wat de weergave verbergt. Interne links intact, Engelse citaten letterlijk overgenomen, en in het Engels de Franse vertaalregels verwijderd door het model, zonder verzonnen vlaggen; mediaan van 6 min 49 s per taal op het artikel, 2 min 20 s op de README. `opus` vertaalt de README zonder enige afwijking, een kwart sneller, maar geen enkel artikel: de vangrails stopten het antwoord in alle veertien talen bij een kort biologiebericht. `haiku` schrijft daarentegen alles — drie sectietitels verlaagd naar niveau 1 in het artikel, de interne links in de Engelse README verdubbeld —, maar twee keer zo langzaam als `sonnet`: het redeneert zonder dat men het kan verhinderen, 61% van zijn output-tokens, en de lagere prijs levert slechts 14% besparing op in API-equivalent. Vandaar `sonnet` ook in `--eco`. Effort heeft geen enkel nut bij vertalen: bij een eerdere batch — deze README en deze CHANGELOG in het Engels, Japans en Hindi — produceerde `sonnet` geen enkel reasoning-token, `opus` bij gemiddelde effort 1% van zijn output-tokens, en gemiddelde effort leverde niets op ten opzichte van lage, noch qua structuur noch qua tijdsduur. De campagne `sonnet`, 1,8 miljoen brontekens, kostte 9 procentpunt van het 5-uursvenster en 2 van de week op het Max-abonnement van de auteur — een bovengrens: de sessie die de metingen aanstuurde, putte uit hetzelfde quotum.

  - **Een weigering door de vangrails van Anthropic wordt als zodanig benoemd.** Opus 5.5 heeft strengere vangrails dan Sonnet, en de foutmelding van Anthropic waarschuwt dat ze soms werk signaleren dat raakt aan biologisch onderzoek. Een kort nieuwsbericht over 279 gegenereerde moleculen voor een bindingsplaats was al voldoende. Claude Code breekt het antwoord dan af, probeert het één keer opnieuw, en het model geeft "I can't continue this translation" terug met een successtatus, zonder fout, over twee beurten: alleen het single-turn-contract stopte dit antwoord, met een nietszeggende melding over de oorzaak. Afzonderlijk verzonden wordt het korte bericht door de API geweigerd onder de categorie "bio". aipmt herkent deze signalen nu, noemt de vangrails en hun categorie, probeert het niet opnieuw — dezelfde tekst zou dezelfde weigering opnieuw triggeren — en adviseert `--model sonnet`, dat het bericht in alle veertien talen heeft vertaald.

  - **De vertalingen van deze repository kunnen via dit traject lopen, zonder uitzondering.** `REGEN_PROVIDER=claude_code` is een abonnement, geen gefactureerde API: het werkt zonder `REGEN_ALLOW_PAID_API`, met vier jobs — de campagnes draaiden met vier gelijktijdige vertalingen zonder een enkele rate limit- of verbindingsvergrendelingsfout —, na een eenmalige preflight die geen enkel quotum verbruikt. De standaard blijft Codex met `gpt-5.6-sol`.

  - **De gebruiksvoorwaarden, zonder omwegen verwoord.** De juridische pagina van Claude Code belet een gebruiker niet om verbinding te maken met het ongewijzigde binaire bestand via diens eigen abonnement; zij verbiedt externe ontwikkelaars om verzoeken via de Pro- of Max-inloggegevens van hun gebruikers te routeren, en Anthropic geeft de voorkeur aan de API-sleutel voor tools van derden, inclusief open-sourceprojecten, waarbij het zich het recht voorbehoudt om het gebruik af te trekken van betaalde credits. Geen enkele tekst beslist over het geval van een gedistribueerde tool die het officiële binaire bestand start: de gebruiker gebruikt zijn eigen account op eigen verantwoordelijkheid.

  - **Tests**: nieuw bestand `tests/test_claude_code_provider.py` (58 tests), 100% van de instructies en branches van de module, zonder ooit de echte `claude` te starten — leeggemaakte omgeving, niet-bestaand binair bestand, `PATH` zonder `claude`, test-doubles die excepties opwerpen als ze worden aangeroepen.

- **1.15.0** Provider `--use_antigravity`: vertalen via het quotum van het Google AI Pro- of Ultra-abonnement, via de officiële CLI `agy`; en voor alle providers laat Ctrl-C geen agents meer halverwege achter, doet een leeg segment het bestand niet langer mislukken en kiest een `.env` van een project niet langer het uitgevoerde binaire bestand (2026-09-26):
  - **Tiende provider-traject: het Google-abonnement, zonder facturering naar verbruik.** Wie betaalt voor Google AI Pro of Ultra kan voortaan vertalingen daarop laten afboeken in plaats van per token te betalen via de Gemini-API. `agy`, de officiële CLI van Antigravity, is het enige traject naar dit quotum: Gemini CLI bedient sinds 18 juni 2026 geen Pro-, Ultra- of gratis accounts meer, en de Antigravity-SDK authenticeert zich alleen via een API-sleutel of via Google Cloud. `--use_antigravity` stuurt deze aan in headless-modus, net als Codex en Grok CLI, op dezelfde basis — eigen procesgroep, `SIGTERM` en vervolgens `SIGKILL` bij time-out, opgeschoonde omgeving. End-to-end geverifieerd op agy 1.2.11: een Markdown-handleiding — front matter, vetgedrukte tekst, link met haakjes, inline code, ingesprongen codeblok in een lijst, tabel, citaat — vertaald naar het Engels in 14 seconden, inclusief preflight, structuur identiek aan de bron, vertaalnotitie toegevoegd; vervolgens, na de correcties uit de review, naar het Duits in 19 seconden, structuur identiek, niets weggeschreven in `~/.gemini`.

  - **Geen betaald traject blijft openstaan, en elke uitvoering verifieert dit.** agy kent andere routes dan het abonnement — API-sleutel, Google Cloud-project, gateway, betaalde AI-credits — en verschillende omgevingsvariabelen schakelen hier geruisloos naar over. Gemeten: `AGY_GATEWAY_URL` stuurt het document naar een gateway van derden, `AGY_ADC_AUTH` schakelt over naar een gefactureerd Google Cloud-project, `CLOUD_CODE_URL` leidt het geauthenticeerde endpoint om naar elk willekeurig adres. De omgeving van het subproces is daarom een allowlist en geen denylist: `PATH`, taal en tijdzone, terminal, identiteit, proxy's en certificaten van de machine en de sessiebus — waarvan een `env -i` heeft aangetoond dat agy ze nodig heeft —, zonder enige sleutel. Een denylist op basis van prefixfamilies (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), die eerst werd geprobeerd, zag er enkele over het hoofd: een inspectie vond in de strings van het binaire bestand endpoint-overrides die door geen enkele prefix werden gedekt, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Twee instellingen ontsnappen aan de omgeving en zijn alleen te lezen via `agy -p /config`: betaalde AI-credits die het overnemen wanneer een quotum is uitgeput, en de verbinding via een Google Cloud-project. Een preflight die geen enkel quotum verbruikt — nulverbruik, gemeten — weigert te vertalen als een van beide actief is of als er een API-sleutel is geconfigureerd, en een instelling die ontbreekt in `/config` geldt als een weigering voor elk van de drie: een versie van agy die er een hernoemt, mag niet door een controle komen die niets heeft geverifieerd. Ten slotte moet het logboek van elke aanroep de authenticatie via het abonnement aantonen (`authMethod=consumer`), en elke andere authenticatiemethode die daarin voorkomt, onder een van de twee spellingen die het binaire bestand gebruikt, leidt tot weigering van het antwoord: de aanroep zelf is doorslaggevend, niet de configuratie die is klaargezet.

  - **De vertaalagent heeft geen tools en het laden ervan wordt bij elke aanroep bewezen.** Elke aanroep schrijft, in een wegwerpmap, een agent in het formaat van agy-projectagents: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Ongeveer 800 invoertokens in plaats van 12.400 met de standaardagent, en de derde instelling is niet overbodig: `excludeDefaultComponents` alleen liet een workspace-hook zijn commando's uitvoeren en zijn tekst injecteren. De echte valkuil ligt elders: een niet-gevonden agent laat agy niet mislukken. Exitcode 0, status `SUCCESS`, en het is de programmeeragent, met 57 actieve tools, die antwoordt — op « Le chat dort. » antwoordde hij « Chut, ne le réveillons pas ! 🐱💤 Que puis-je faire pour vous aujourd'hui ? ». Niets op stdout of stderr: alleen het logboek van de aanroep meldt het. Het antwoord wordt daarom geweigerd als het logboek deze terugval aankondigt, en ook als het niet de positieve markering van het laden van de agent bevat — een wijziging in het logboekformaat zorgt ervoor dat de vertaling wordt geweigerd in plaats van de beveiliging geruisloos op te heffen. Elke markering moet een volledige regel van het logboek innemen, in het gemeten formaat — ernst, datum, tijd, thread, bestand en regel: het binaire bestand bevat ook een regel die het bericht van de gebruiker naar het logboek kopieert — nooit gezien op het standaard logniveau, over 78 echte logboeken —, en een document dat deze berichten citeert, mag niet in plaats van agy aan de beveiliging kunnen voldoen.

  - **De instellingen en agy-geschiedenis van de gebruiker worden niet aangeraakt.** Elke aanroep draait met een privé-HOME, een tijdelijke map en een werkmap die daarna worden gewist. agy verifieert zich toch via de systeemsleutelhanger, die aipmt nooit leest. Er wordt niets overgeërfd: noch de machtigingen van de gebruiker — waardoor de standaardagent `ls` en `git` kon starten zonder iets te vragen —, noch diens globale regels, plug-ins, MCP-servers, hooks en skills. En er wordt niets toegevoegd aan diens geschiedenis, waarin elke aanroep een gesprek van ongeveer 200 kB achterliet, inclusief vertaalde tekst: de testcampagne had daar ongeveer 95 gesprekken achtergelaten en 17 items verdrongen uit een cache met een limiet van 100. Geverifieerd: geen enkel bestand geschreven in `~/.gemini/antigravity-cli`.

  - **Fail-closed geweigerd waar isolatie niet stand zou houden.** Onder Linux zonder D-Bus-sessiebus — SSH-sessie, container, server — bewaart agy zijn token in een bestand van `~/.gemini` in plaats van de sleutelhanger, zoals vermeld in zijn eigen changelog (1.1.3), en de isolatie van elke aanroep verbergt dit bestand. De weigering volgt voortaan vóór elke start, met de werkelijke oorzaak, in plaats van een minuut te wachten op een inlogcode gevolgd door het advies om opnieuw in te loggen wat niets zou oplossen. Onder Windows leest agy `USERPROFILE`, `APPDATA` en `TEMP`, niet `HOME` of `TMPDIR` — volgens de Go-documentatie en de strings in het binaire bestand —: niets zou de aanroep daar isoleren van de instellingen of de geschiedenis van de gebruiker, en `--use_antigravity` wordt daar geweigerd zolang dit niet is gemeten. macOS slaagt, zonder te zijn gemeten; de facturatiebeveiliging, die de daadwerkelijke configuratie leest, houdt daar stand.

  - **`exit 0` bewijst niets, vierde CLI.** Een antwoord wordt alleen geaccepteerd met een returncode nul, een JSON-object met de status `SUCCESS`, een conform logboek, geen geweigerde actie, geen commando, geen fout in de JSON, geen waarschuwing voor afkapping op stderr en een niet-lege tekst. `--print-timeout` wordt nooit gebruikt: bij het verstrijken levert agy de gedeeltelijke uitvoer als `SUCCESS`, code 0; de time-out is extern en beëindigt de procesgroep. Een segment dat begint met `/commande`, `!commande` of `@fichier` wordt vertaald, nooit uitgevoerd of opgelost — zonder `--disable-slash-commands` werd « /help » uitgevoerd in plaats van de vertaling. Een witruimtesegment bereikt agy niet meer, omdat de pijplijn het ongewijzigd retourneert (zie hieronder), en blijft als vangnet vóór de aanroep geweigerd: bij lege invoer opent agy zijn interactieve interface met een code 0. De herhaling volgt het veld `retryable` van de regel `AGY_ERROR` die agy sinds versie 1.2.6 naar stderr schrijft: het probeert tijdelijke fouten — 502, 503, 504, limiet per minuut — zelf al opnieuw, en weet zelf of de resterende fout dat nog steeds is. Zonder dit veld vindt er geen herhaling plaats wanneer het bericht over uitputting spreekt — bij Google heeft `RESOURCE_EXHAUSTED` dezelfde code 429 als een limiet per minuut, maar een uitgeput 5-uursvenster herstelt zich niet binnen 90 seconden —, en anders alleen bij snelheidsbeperking. Het antwoord neemt het regeleinde van het segment over: agy eindigt het zijne altijd met een regeleinde, waardoor een halverwege een zin gesplitste alinea bij het samenvoegen in tweeën werd geknipt. Een verbroken sessie geeft een melding die aangeeft dat `agy` moet worden gestart om opnieuw verbinding te maken. `AGY_CLI_DISABLE_AUTO_UPDATE=true` voorkomt ten slotte dat een nieuw HOME bij elke aanroep een updatecontroleur in zijn eigen sessie start, buiten het bereik van de time-out — de waarde `1` heeft overigens geen effect.

  - **Modellen: de redeneerinspanning maakt deel uit van de naam.** De identifiers zijn die van `agy models` — `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… Een basisnaam alleen, die agy zou weigeren, wordt vóór de aanroep geweigerd, met de achtervoegsels die bestaan: `-medium` of `-low` voor een Flash, `-high` of `-low` voor een Pro. Standaard `gemini-3.8-flash-medium`, en `gemini-3.7-flash-low` als `--eco`, vastgesteld door de hieronder beschreven campagnes. `--reasoning_effort` heeft geen effect en meldt dat ook. Claude en GPT-OSS putten uit een apart en veel kleiner quotum — ongeveer 1% van het 5-uursvenster per gemeten aanroep, vergeleken met 0,05% bij Flash — en een waarschuwing herinnert daaraan. Het resterende quotum kan gratis worden uitgelezen met `agy -p /usage`. Geweigerd in CI, net als Codex en Grok CLI: de verbinding bevindt zich in een persoonlijke sleutelhanger, en het bericht stelt `--use_gemini` voor met een Google-sleutel.

  - **Twee campagnes op 26 september: de standaardwaarden zijn gemeten, niet aangenomen.** Door `aipmt --use_antigravity` zelf, vier vertalingen parallel, elk vergeleken met de bron via `scripts/compare_structure.py`, het quotum vooraf en achteraf uitgelezen via `agy -p /usage`. 's Middags, op verzoek van de auteur, Gemini 3.8 Flash tegen 3.7 op dezelfde batch, deze README en deze CHANGELOG in hun versie 1.15.0: bij gemiddelde inspanning dezelfde structuur voor beide; 3.8 redeneert evenveel als 3.7 — 63% van de uitvoertokens vergeleken met 60%, afgelezen in de JSON van agy — en kost een zevende meer quotum, voor een kwart meer tijd. Vervolgens de ochtendcampagne, opnieuw uitgevoerd in `gemini-3.8-flash-medium`: veertien van de veertien talen zonder afwijking op het artikel, mediaan van 3 min 59 s, net als op de README, 1 min 43 s; de interne links intact in de veertien README's, waar 3.7 er in het Italiaans verbrak; en in het Engels de Franse vertaalregels verwijderd door het model, zonder verzonnen vlag, Engelse citaten intact. Vandaar de standaardwaarden: `gemini-3.8-flash-medium`, en `gemini-3.7-flash-low` als `--eco`.
