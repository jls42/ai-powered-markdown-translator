- **1.16.0** Provider `--use_claude_code`: Übersetzen über das Kontingent des Claude Pro- oder Max-Abonnements über das offizielle CLI `claude -p` – keine kostenpflichtigen Wege, und jeder Aufruf belegt dies (2026-09-26):

  - **Elfter Pfad: das Claude-Abonnement ohne nutzungsbasierte Abrechnung.** `--use_claude_code` steuert die offizielle Binärdatei von Claude Code im Modus `-p` auf derselben Basis wie Codex, Grok CLI und Antigravity – eigene Prozessgruppe, sicheres Beenden bei Timeout, Strg+C oder Schließen des Terminals. Nicht zu verwechseln mit `--use_claude`, der nutzungsbasiert abgerechneten API von Anthropic. aipmt liest das Token niemals aus.

  - **Keine kostenpflichtigen Wege, auf drei Ebenen überprüft.** Die Umgebung des Unterprozesses ist eine Positivliste: weder API-Schlüssel noch Token noch Cloud-Anbieter noch Marker der Claude-Code-Sitzung, aus der aipmt gestartet werden könnte – diejenige, die diesen Provider geschrieben hat, exportierte fünfzehn. Der Preflight erfordert ohne Modell-Turn von `claude auth status` die Abonnement-Anmeldung ohne Console-Schlüssel und von `/usage` den Satz, der das Abonnement bestätigt. Jeder Aufruf muss dies anschließend in seinem Initialisierungsereignis bestätigen – `apiKeySource: none`, erzwungene Umgebung ordnungsgemäß empfangen, Modell der angeforderten Familie, kein Schnellmodus – sowie in seinem Kontingentbericht: kostenpflichtige „Extra Usage“ stoppt die Übersetzung auf der Stelle.

  - **Das Kontingent wird mit Claude-Code-Sitzungen geteilt, und der Provider schont es.** Jeder Aufruf meldet die Auslastung des 5-Stunden- und des Wochenfensters; ab 80 % (`AIPMT_CLAUDE_MAX_UTILIZATION`) wird kein weiteres Segment gestartet. Am Tag der Umsetzung lag die Woche des Autorenkontos bereits bei 98 %.

  - **Nichts aus der Benutzerkonfiguration dringt ein, nichts von der Sitzung bleibt zurück.** Ohne Werkzeuge, im Modus ohne Anpassungen, Benutzereinstellungen ignoriert, MCP-Server und Hooks deaktiviert, privates und temporäres Arbeitsverzeichnis, keine Transkripte aufbewahrt. Durch Canaries gemessen: Ohne `CLAUDE_CODE_DISABLE_ATTACHMENTS` wurde ein `@chemin` des Dokuments zu einem Anhang, und das Modell lieferte einen Leseaufruf anstelle der Übersetzung; damit dringt nichts durch. Die Canaries `AGENTS.md`, `CLAUDE.md` und der Hook haben weder etwas geladen noch ausgeführt.

  - **Ein Segment, das mit `/` beginnt, erreichte das Modell nicht.** Unter `--disable-slash-commands` antwortet Claude Code selbst darauf mit „… isn't available in this environment.“, mit dem Status `success`, ohne jeglichen Turn. Ein Zeilenumbruch vor dem Segment leitet es an das Modell weiter; der Ausgabevertrag weist eine Antwort ohnehin zurück, wenn sie ohne Turn, in mehr als einem Turn, abgeschnitten oder von einem anderen Modell als dem angekündigten geliefert wird.

  - **Modelle: Aliase, niemals eine starre Kennung.** Standardmäßig `sonnet`, mit Effort `low`, und auch in `--eco` – `--eco` ändert auf diesem Pfad also nichts –, `opus` und `haiku` über `--model`; `fable` und die Varianten `[1m]` werden abgelehnt, da sie in `-p` ungefragt auf kostenpflichtige Guthaben ausweichen.

  - **Mängel werden gemessen, nicht vermutet.** Über `aipmt --use_claude_code` selbst, vier parallele Übersetzungen für die beiden Messdokumente der README – der dichte Monitoring-Artikel in `--news` und diese README in ihrer Version 1.14.0 –, jeweils in vierzehn Sprachen. `sonnet` mit Effort `low` erstellt die 28 Übersetzungen, 26 davon ohne Abweichung: ein zusätzliches fettgedrucktes Wort im Chinesischen beim Artikel und im Arabischen bei der README eine Tabellenzeile, die an der vorherigen klebt, was die Darstellung jedoch kaschiert. Interne Links intakt, englische Zitate unverändert übernommen, und im Englischen wurden die französischen Übersetzungszeilen vom Modell entfernt, ohne erfundene Flaggen; median 6 Min. 49 Sek. pro Sprache beim Artikel, 2 Min. 20 Sek. bei der README. `opus` übersetzt die README ohne jede Abweichung, ein Viertel schneller, jedoch keinen einzigen Artikel: Dessen Guardrails stoppten die Antwort in allen vierzehn Sprachen bei einer Kurzmeldung zur Biologie. `haiku` schreibt hingegen alles – drei Abschnittsüberschriften beim Artikel wurden auf Ebene 1 hochgestuft, die internen Links der englischen README verdoppelt –, aber doppelt so langsam wie `sonnet`: Es führt unaufhaltsam Reasoning durch, 61 % seiner Output-Tokens, und sein niedrigerer Preis bringt als API-Äquivalent nur 14 % Ersparnis. Daher `sonnet` auch in `--eco`. Der Effort bringt beim Übersetzen keinen Nutzen: Bei einem vorherigen Batch – diese README und dieses CHANGELOG auf Englisch, Japanisch und Hindi – erzeugte `sonnet` keine Reasoning-Tokens, `opus` bei mittlerem Effort 1 % seiner Output-Tokens, und mittlerer Effort brachte gegenüber niedrigem weder bei Struktur noch bei Dauer einen Vorteil. Die Kampagne `sonnet` mit 1,8 Millionen Quellzeichen beanspruchte 9 Prozentpunkte des 5-Stunden- und 2 des Wochenfensters des Max-Abonnements des Autors – eine obere Schranke: Die Sitzung, die die Messungen steuerte, schöpfte aus demselben Kontingent.

  - **Eine Ablehnung durch Anthropics Guardrails wird als solche benannt.** Opus 5.5 besitzt strengere Guardrails als Sonnet, und die Fehlermeldung von Anthropic warnt davor, dass diese bisweilen Arbeiten im Umfeld der biologischen Forschung markieren. Eine Kurzmeldung über 279 generierte Moleküle für eine Bindungsstelle genügte bereits. Claude Code bricht daraufhin die Antwort ab, versucht es einmal erneut, und das Modell liefert „I can't continue this translation“ mit Erfolgsstatus, ohne Fehler, über zwei Turns: Nur der Vertrag des einzelnen Turns fing diese Antwort ab, mit einer unklaren Meldung über die Ursache. Isoliert gesendet wird die Meldung von der API unter der Kategorie „bio“ abgelehnt. aipmt erkennt diese Anzeichen nun, benennt die Guardrails sowie deren Kategorie, startet keinen Neuversuch – derselbe Text würde dieselbe Ablehnung erneut auslösen – und empfiehlt `--model sonnet`, das die Kurzmeldung in allen vierzehn Sprachen übersetzt hat.

  - **Die Übersetzungen dieses Repositorys können ohne Ausnahmeregelung über diesen Pfad laufen.** `REGEN_PROVIDER=claude_code` ist ein Abonnement, keine abgerechnete API: Es funktioniert ohne `REGEN_ALLOW_PAID_API`, mit vier Jobs – die Kampagnen liefen mit vier gleichzeitigen Übersetzungen ohne einen einzigen Ratenbegrenzungsfehler oder Login-Lock –, nach einem einmaligen Preflight, der kein Kontingent verbraucht. Der Standard bleibt Codex mit `gpt-5.6-sol`.

  - **Die Nutzungsbedingungen, ungeschönt dargelegt.** Die rechtliche Seite von Claude Code hindert Nutzer nicht daran, sich mit ihrem eigenen Abonnement bei der unmodifizierten Binärdatei anzumelden; sie untersagt Drittentwicklern, Anfragen über die Pro- oder Max-Zugangsdaten ihrer Nutzer zu leiten, und Anthropic bevorzugt für Drittanbieter-Tools einschließlich Open-Source-Projekten den API-Schlüssel, wobei sie sich vorbehalten, deren Nutzung über kostenpflichtige Guthaben abzurechnen. Kein Text regelt eindeutig den Fall eines verteilten Tools, das die offizielle Binärdatei startet: Der Nutzer haftet mit seinem Konto.

  - **Tests**: neue Datei `tests/test_claude_code_provider.py` (58 Tests), 100 % der Anweisungen und Zweige des Moduls, ohne jemals das echte `claude` zu starten – bereinigte Umgebung, nicht vorhandene Binärdatei, `PATH` ohne `claude`, Testdoubles, die bei Aufruf Exceptions auslösen.

- **1.15.0** Provider `--use_antigravity`: Übersetzen über das Kontingent des Google AI Pro- oder Ultra-Abonnements über das offizielle CLI `agy`; und für alle Provider bricht Strg+C keine laufenden Agenten mehr ab, ein leeres Segment führt nicht mehr zum Fehlschlagen der Datei, und eine Projekt-`.env` bestimmt nicht mehr die ausgeführte Binärdatei (2026-09-26):

  - **Zehnter Provider-Pfad: das Google-Abonnement ohne nutzungsbasierte Abrechnung.** Wer für Google AI Pro oder Ultra bezahlt, kann Übersetzungen nun über dieses Kontingent abrechnen lassen, anstatt sie pro Token über die Gemini-API zu bezahlen. `agy`, das offizielle CLI von Antigravity, ist der einzige Weg zu diesem Kontingent: Das Gemini-CLI bedient seit dem 18. Juni 2026 weder Pro-, Ultra- noch kostenlose Konten, und das Antigravity-SDK authentifiziert sich ausschließlich über einen API-Schlüssel oder über Google Cloud. `--use_antigravity` steuert es im Headless-Modus, wie Codex und Grok CLI, auf derselben Basis – eigene Prozessgruppe, `SIGTERM`, dann `SIGKILL` bei Timeout, bereinigte Umgebung. Durchgängig verifiziert auf agy 1.2.11: ein Markdown-Leitfaden – Front Matter, Fettdruck, Klammer-Links, Inline-Code, eingerückter Codeblock in einer Liste, Tabelle, Zitat – in 14 Sekunden ins Englische übersetzt, inklusive Preflight, identische Struktur wie die Quelle, Übersetzungshinweis hinzugefügt; danach, nach den Review-Korrekturen, in 19 Sekunden ins Deutsche, identische Struktur, nichts in `~/.gemini` geschrieben.

  - **Kein kostenpflichtiger Weg bleibt offen, und jeder Start überprüft dies.** agy kennt andere Wege als das Abonnement – API-Schlüssel, Google-Cloud-Projekt, Gateway, kostenpflichtige KI-Guthaben – und mehrere Umgebungsvariablen lassen es dorthin wechseln, ohne etwas anzuzeigen. Gemessen: `AGY_GATEWAY_URL` sendet das Dokument an ein Drittanbieter-Gateway, `AGY_ADC_AUTH` wechselt zu einem abgerechneten Google-Cloud-Projekt, `CLOUD_CODE_URL` leitet den authentifizierten Endpunkt an eine beliebige Adresse um. Die Umgebung des Unterprozesses ist daher eine Positivliste und keine Ausschlussliste: `PATH`, Sprache und Zeitzone, Terminal, Identität, Proxys und Zertifikate des Systems sowie der Session-Bus – das, wovon ein `env -i` bewiesen hat, dass agy es benötigt –, ganz ohne Schlüssel. Eine Ausschlussliste nach Präfixfamilien (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), die zuerst erprobt wurde, übersah einiges: Ein Review fand in den Strings der Binärdatei Endpunkt-Overrides, die von keinem Präfix abgedeckt wurden: `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Zwei Einstellungen entziehen sich der Umgebung und lassen sich nur über `agy -p /config` auslesen: kostenpflichtige KI-Guthaben, die bei erschöpftem Kontingent einspringen, und der Login über ein Google-Cloud-Projekt. Ein Preflight, der kein Kontingent verbraucht – Nutzung bei null, gemessen –, verweigert die Übersetzung, wenn eine davon aktiv ist oder ein API-Schlüssel konfiguriert wurde, und eine in `/config` fehlende Einstellung gilt bei allen dreien als Verweigerung: Eine Version von agy, die eine davon umbenennt, darf keine Prüfung bestehen lassen, die nichts verifiziert hat. Schließlich muss das Protokoll jedes Aufrufs die Authentifizierung über das Abonnement bestätigen (`authMethod=consumer`), und jede andere darin auftauchende Authentifizierungsmethode – in einer der beiden Schreibweisen, die die Binärdatei verwendet – führt zur Ablehnung der Antwort: Maßgeblich ist der Aufruf selbst, nicht die vorbereitete Konfiguration.

  - **Der Übersetzungsagent besitzt keinerlei Tools, und sein Laden wird bei jedem Aufruf nachgewiesen.** Jeder Aufruf schreibt in ein temporäres Verzeichnis einen Agenten im Format der Projektagenten von agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Etwa 800 Eingabetokens statt 12.400 beim Standardagenten, und die dritte Einstellung ist nicht redundant: `excludeDefaultComponents` allein erlaubte es einem Workspace-Hook noch, seine Befehle auszuführen und seinen Text einzuschleusen. Die eigentliche Falle liegt woanders: Ein nicht gefundener Agent bringt agy nicht zum Scheitern. Rückgabecode 0, Status `SUCCESS`, und der Programmieragent mit 57 aktiven Tools antwortet – auf „Le chat dort.“ antwortete er „Chut, ne le réveillons pas ! 🐱💤 Que puis-je faire pour vous aujourd'hui ?“. Nichts auf stdout oder stderr: Nur das Protokoll des Aufrufs verrät es. Die Antwort wird daher abgelehnt, wenn das Protokoll diesen Fallback meldet, und ebenso, wenn es den positiven Marker für das Laden des Agenten nicht enthält – eine Änderung des Protokollformats führt zur Ablehnung der Übersetzung, anstatt die Schutzmaßnahme stillschweigend aufzuheben. Jeder Marker muss eine ganze Zeile des Protokolls im gemessenen Format einnehmen – Schweregrad, Datum, Uhrzeit, Thread, Datei und Zeile: Die Binärdatei enthält auch eine Zeile, die die Benutzernachricht ins Protokoll kopiert – bei Standard-Loglevel in 78 realen Protokollen nie gesehen –, und ein Dokument, das solche Meldungen zitiert, darf nicht anstelle von agy die Schutzbedingung erfüllen können.

  - **Einstellungen und Verlauf von agy des Benutzers bleiben unberührt.** Jeder Aufruf läuft mit einem privaten HOME, temporären Verzeichnis und Arbeitsverzeichnis, die anschließend gelöscht werden. agy authentifiziert sich dennoch über den Schlüsselbund des Systems, den aipmt niemals ausliest. Nichts wird vererbt: weder die Berechtigungen des Benutzers – die es dem Standardagenten erlaubten, ungefragt `ls` und `git` auszuführen –, noch dessen globale Regeln, Plugins, MCP-Server, Hooks und Skills. Und dem Verlauf wird nichts hinzugefügt, in dem jeder Aufruf eine Konversation von etwa 200 KB hinterließ, inklusive des übersetzten Texts: Die Sondierungskampagne hatte dort etwa 95 Konversationen hinterlassen und 17 Einträge aus einem auf 100 Einträge begrenzten Cache verdrängt. Verifiziert: Es wird keine Datei in `~/.gemini/antigravity-cli` geschrieben.

  - **Fail-Closed-Ablehnung dort, wo die Isolation nicht halten würde.** Unter Linux ohne D-Bus-Session-Bus – SSH-Sitzung, Container, Server – legt agy sein Token in einer Datei unter `~/.gemini` anstelle des Schlüsselbunds ab, wie dessen eigenes Changelog (1.1.3) ankündigt, und die Isolation jedes Aufrufs blendet diese Datei aus. Die Ablehnung erfolgt nun vor jedem Start mit ihrer tatsächlichen Ursache, statt einer Minute Wartezeit auf einen Anmeldecode, gefolgt von einer Empfehlung zur Neuanmeldung, die nichts lösen würde. Unter Windows liest agy `USERPROFILE`, `APPDATA` und `TEMP`, nicht `HOME` oder `TMPDIR` – laut Go-Dokumentation und den Strings der Binärdatei –: Nichts würde dort den Aufruf von den Einstellungen oder dem Verlauf des Benutzers isolieren, und `--use_antigravity` wird dort abgelehnt, solange dies nicht messtechnisch überprüft ist. macOS wird unterstützt, ohne gemessen worden zu sein; die Abrechnungssperre, die die tatsächliche Konfiguration ausliest, greift dort.

  - **`exit 0` beweist nichts, viertes CLI.** Eine Antwort wird nur mit dem Rückgabecode 0, einem JSON-Objekt mit dem Status `SUCCESS`, einem konformen Protokoll, ohne abgelehnte Aktionen, ohne Befehle, ohne Fehler im JSON, ohne Trunkierungswarnung auf stderr und mit nicht-leerem Text akzeptiert. `--print-timeout` wird niemals verwendet: Bei dessen Ablauf liefert agy die Teilausgabe in `SUCCESS`, Code 0; der Timeout ist extern und beendet die Prozessgruppe. Ein Segment, das mit `/commande`, `!commande` oder `@fichier` beginnt, wird übersetzt, niemals ausgeführt oder aufgelöst – ohne `--disable-slash-commands` wurde „/help“ anstelle der Übersetzung ausgeführt. Ein leeres Segment erreicht agy nicht mehr, da die Pipeline es unverändert zurückgibt (siehe unten), und wird vor dem Aufruf als letztes Fangnetz weiterhin abgewiesen: Bei einer leeren Eingabe öffnet agy seine interaktive Oberfläche mit Code 0. Wiederholungsversuche richten sich nach dem Feld `retryable` der Zeile `AGY_ERROR`, die agy seit Version 1.2.6 auf stderr ausgibt: Es wiederholt vorübergehende Fehler – 502, 503, 504, Minutenlimit – bereits selbst, und es weiß am besten, ob der verbleibende Fehler noch vorübergehend ist. Fehlt dieses Feld, erfolgt kein Neuversuch, wenn die Meldung von Erschöpfung spricht – bei Google hat `RESOURCE_EXHAUSTED` denselben Code 429 wie ein Minutenlimit, aber ein erschöpftes 5-Stunden-Fenster erholt sich nicht in 90 Sekunden –, andernfalls nur bei Ratenbegrenzung. Die Antwort übernimmt das Zeilenende des Segments: agy beendet seine Ausgabe stets mit einem Zeilenumbruch, der an der Nahtstelle einen mitten im Satz geteilten Absatz entzweiriss. Eine getrennte Sitzung liefert eine Meldung mit dem Hinweis, `agy` zur Neuanmeldung auszuführen. `AGY_CLI_DISABLE_AUTO_UPDATE=true` verhindert schließlich, dass ein frisches HOME bei jedem Aufruf einen Update-Checker in einer eigenen Sitzung außerhalb der Reichweite des Timeouts startet – der Wert `1` selbst bleibt wirkungslos.

  - **Modelle: Der Reasoning-Aufwand ist Teil des Namens.** Die Bezeichner sind diejenigen von `agy models` – `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… Ein reiner Basisname, den agy ablehnen würde, wird vor dem Aufruf abgelehnt, zusammen mit den existierenden Suffixen: `-medium` oder `-low` für ein Flash, `-high` oder `-low` für ein Pro. Standardmäßig `gemini-3.8-flash-medium`, und `gemini-3.7-flash-low` bei `--eco`, festgelegt durch die unten beschriebenen Kampagnen. `--reasoning_effort` ist wirkungslos und teilt dies mit. Claude und GPT-OSS schöpfen aus einem separaten und viel kleineren Kontingent – etwa 1 % des 5-Stunden-Fensters pro gemessenem Aufruf, verglichen mit 0,05 % bei Flash – und eine Warnung erinnert daran. Das verbleibende Kontingent lässt sich kostenlos über `agy -p /usage` abfragen. In CI abgelehnt, wie auch Codex und Grok CLI: Das Login liegt in einem persönlichen Schlüsselbund, und die Meldung schlägt `--use_gemini` mit einem Google-Schlüssel vor.

  - **Zwei Kampagnen am 26. September: Die Standardwerte sind gemessen, nicht angenommen.** Über `aipmt --use_antigravity` selbst, vier Übersetzungen parallel, jede über `scripts/compare_structure.py` mit ihrer Quelle verglichen, das Kontingent über `agy -p /usage` davor und danach abgelesen. Am Vormittag schrieb `gemini-3.7-flash-medium` bei `--news` für die mit der Version 1.14.0 veröffentlichte Revision dieser README und für den dichten Monitoring-Artikel der README-Messungen alle vierzehn Sprachen beider Dokumente: den Artikel völlig ohne Abweichung, im Median 3 Min. 14 Sek. pro Sprache, und die README bis auf ein einziges fettgedrucktes Wort auf Koreanisch in 1 Min. 22 Sek. Am Nachmittag auf Wunsch des Autors: Gemini 3.8 Flash gegen 3.7 auf demselben Batch, dieser README und diesem CHANGELOG in ihrer Version 1.15.0: bei mittlerem Aufwand dieselbe Struktur bei beiden; 3.8 betreibt genauso viel Reasoning wie 3.7 – 63 % der Ausgabe-Tokens gegenüber 60 %, ausgelesen aus dem JSON von agy – und verbraucht ein Siebtel mehr Kontingent bei einem Viertel mehr Zeit. Dann die Vormittagskampagne, erneut ausgeführt mit `gemini-3.8-flash-medium`: vierzehn von vierzehn Sprachen ohne Abweichung beim Artikel, 3 Min. 59 Sek. im Median, ebenso bei der README, 1 Min. 43 Sek.; intakte interne Links in allen vierzehn READMEs, wo 3.7 noch welche im Italienischen beschädigte; und im Englischen vom Modell entfernte französische Übersetzungszeilen, ohne erfundene Flags, englische Zitate intakt. Daher die Standardwerte: `gemini-3.8-flash-medium`, und `gemini-3.7-flash-low` bei `--eco`. Bei niedrigem Aufwand betreibt keines der beiden Flash-Modelle Reasoning und jedes kostet die Hälfte, aber 3.8 low hat auf Hindi die drei internen Links einer README verdoppelt, was 3.7 low in keiner der von ihm erstellten Übersetzungen getan hat. Gemessene Kosten auf der Kontostufe des Autors: 13 bis 16 Punkte des 5-Stunden-Fensters pro Million Quellzeichen bei `gemini-3.8-flash-medium` – die wiederholte Kampagne mit 28 Übersetzungen und 1,8 Millionen Zeichen beanspruchte 24,5 davon und 4,1 des Wochenkontingents.

  - **Nutzungsbedingungen und Datenverarbeitung, ungeschminkt dargelegt.** Die Bedingungen von Antigravity (Abschnitt 6) und seine FAQ verbieten den Zugriff auf den Dienst über Drittanbietersoftware unter Verwendung des Antigravity-Logins – Claude Code, OpenClaw und OpenCode werden dort namentlich erwähnt –, andernfalls droht die Sperrung des Kontos. aipmt liest oder verwendet das Token zu keinem Zeitpunkt: Es startet das offizielle Binary im Headless-Modus, den Google für Skripte und CI dokumentiert, und ein Google-Mitarbeiter bezeichnete es im offiziellen Forum als „Standard“, `agy -p` für eigene Zwecke aus einem lokalen Skript heraus zu starten – eine Antwort, keine Zusage. Kein Dokument klärt den Fall eines distribuierten Werkzeugs: Die README weist darauf hin, dass der Nutzer auf eigenes Kontorisiko handelt. Abschnitt 5 derselben Bedingungen erlaubt es Google, Interaktionen – Prompts, Antworten, Metadaten – zur Verbesserung seiner Produkte und seines maschinellen Lernens zu nutzen und von Menschen gegenlesen zu lassen, ohne zwischen dem kostenlosen Angebot, Pro und Ultra zu unterscheiden: Die README behält diesen Weg öffentlichen Dokumenten vor, und ihr abschließender Warnhinweis erwähnt dies.

  - **Die Übersetzungen dieses Repositories können diesen Weg ohne Ausnahme nutzen.** `REGEN_PROVIDER=antigravity` ist ein Abonnement, keine abgerechnete API: Es läuft ohne `REGEN_ALLOW_PAID_API`, mit vier Jobs – die gesamte Kampagne lief mit vieren parallel ohne einen einzigen Fehler – und dem Limit von 1.800 Sekunden pro Job von Codex, was durch Messungen gerechtfertigt ist: Das gesamte CHANGELOG auf Hindi, die Datei, bei der Codex Placeholders verliert, wurde in der Version 1.14.1 von 3.7 Flash in 4 Min. 33 Sek. ohne Abweichung übersetzt, und in Version 1.15.0, die um ein Fünftel länger ist, von 3.8 Flash in 5 Min. 50 Sek.: mindestens fünfmal unter dem Limit. Eine vollständige Neugenerierung von 2,2 Millionen Zeichen beläuft sich bei `gemini-3.8-flash-medium` auf 30 bis 36 Punkte des 5-Stunden-Fensters. Eine einzige Vorabprüfung, der Preflight des Moduls, geht den 28 Jobs voraus: Ein nicht verbundener oder auf Abrechnung eingestellter agy startet keinen einzigen davon. Standard bleibt weiterhin Codex mit `gpt-5.6-sol`.

  - **Ein interner Link wurde unbemerkt beschädigt.** Das Token, das einen Anker schützt, schluckt dessen Klammern: Das Modell erhält einen scheinbar fehlerhaften Link – eckige Klammern, gefolgt vom bloßen Token –, und versucht gelegentlich, diesen zu „reparieren“. Die Wiederherstellung liefert dann `[texte]((#ancre))`, was ins Leere führt, ohne dass ein Guard oder `compare_structure.py` dies meldet. Dies trat bei zwei READMEs der ersten Neugenerierung dieser Version und bei allen getesteten Modellen auf, häufiger dann, wenn der Link selbst in Klammern steht – wie bei einem Link, den diese Version gerade erst zu dieser README hinzugefügt hatte. Die Veröffentlichungsprüfung zählt nun die intakten internen Links jeder Übersetzung, und diese README setzt keine mehr in Klammern; der Fix für das Token selbst steht noch aus.

  - **Strg+C und das Schließen des Terminals beenden den Agenten nun bei allen vier CLIs.** Codex, Grok CLI, OpenCode und Antigravity laufen in ihrer eigenen Session außerhalb der Vordergrundgruppe: Das `SIGINT` eines Strg+C erreicht sie nicht, und bei Strg+C wartet `Popen` nur eine Viertelsekunde auf sie, bevor die Kontrolle zurückgegeben wird. Im Review an einem Schein-Binary überprüft: Der Agent überlebte aipmt und verbrauchte weiter Kontingent für ein verworfenes Ergebnis – beim Regen vier auf einmal. Ein `KeyboardInterrupt` oder ein `SystemExit` während des Aufrufs beendet nun die Gruppe des Agenten, bevor die Exception weitergereicht wird. Das Schließen des Terminals oder das Abbrechen einer SSH-Sitzung (`SIGHUP`) beendete Python ohne jegliche Bereinigung: Der Agent lief weiter und das private Verzeichnis von Antigravity verblieb mitsamt seinem Protokoll, das die Kontoadresse enthält, auf der Festplatte. `SIGHUP` folgt nun dem Pfad von `SIGTERM`: Agentengruppe beendet, dann Exit mit 129. Im Produktivbetrieb ändert diese Schutzvorkehrung nichts: Sie schließt den Fall ab, dass ein Bug etwas anderes zurückgibt. Test-Doubles von `Popen`, die nicht verwendet werden dürfen, schlagen nun sofort fehl, Scheinprozesse tragen eine unmögliche PID und Mutationskampagnen laufen in einem PID-Namespace.

Eine lange Übersetzung von 23 wurde somit nach dem Zufallsprinzip abgeschnitten, ohne das geringste Signal. Der Preflight liest `/api/v1/models/{modèle}/endpoints`, schließt Hoster unter 8.000 Output-Tokens, solche mit beeinträchtigtem Status und jene aus, die keine Obergrenze deklarieren, und pinnt anschließend die übrigen fest. `provider.only` **ohne** `allow_fallbacks: false` ist lediglich eine Präferenz: Der Router wechselt wieder zu einem ausgeschlossenen Hoster, und das Pinning verliert jeglichen Wert. Wenn kein Hoster die Obergrenze einhält, stoppt der Befehl: Trotzdem zu übersetzen hieße, das lautlose Abschneiden zu akzeptieren, zu dessen Verhinderung dieser Preflight existiert.

  - **Reasoning wird zum Output-Tarif abgerechnet und ist bei vielen Modellen standardmäßig aktiv.** Dieselbe Anfrage an `z-ai/glm-5.2`, Antwort „OK“: **107 Completion-Tokens beim Standard des Modells, 2 bei deaktiviertem Reasoning**. Bei einer Übersetzung, der Reasoning keinerlei Mehrwert bringt, ist das ein Faktor 18 auf jedem Segment jeder Datei. Es ist daher standardmäßig deaktiviert. Die **288 von 431 Modellen**, die es erzwingen (`reasoning.mandatory`), antworten mit `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: Für sie liest der Preflight die akzeptierten Aufwandswerte (Efforts) aus und fordert den niedrigsten an (nächster Punkt) — der Aufwand weist einen **Prozentsatz von `max_tokens`** zu, den das Reasoning zuerst verbraucht, sodass ein zufällig gewählter Wert das Risiko einer leeren Ausgabe verlagert, statt es zu verringern.

  - **Ein Modell, das Reasoning erzwingt, erhält den niedrigsten Aufwand, den es akzeptiert, und eine Messung gab dafür den Ausschlag.** Die erste Wahl bestand darin, nichts zu senden, um nicht anstelle des Modells zu raten. Getestet an `z-ai/glm-5.3-flash`, dessen Katalogstandard `max` ist, erzeugte diese Wahl eine Ausgabe, die vor Ende der Übersetzung **auf 32.768 Tokens abgeschnitten** wurde – zwei von vierzehn Sprachen gingen verloren. Das Erhöhen des Limits hätte daran nichts geändert: Der Aufwand teilt ihm einen Prozentsatz zu, das Reasoning wächst mit ihm. Der Provider liest daher `supported_efforts` beim Preflight aus und fordert das Minimum an, mit Fallback auf „nichts“, wenn der Katalog keinen nutzbaren Wert angibt. Gegenprobe bei der betroffenen Sprache: Sie scheiterte zuvor an einem erschöpften Budget, läuft nun jedoch in 9 Minuten mit einer zur Quelle identischen Struktur durch.

Die generische Meldung verleitete dazu, nach einem Fehler im Dokument oder bei der Aufteilung zu suchen; nun besagt sie, dass der Ausfall auf Providerseite liegt und ein erneuter Versuch oft ausreicht.

Beide Fälle erfordern gegensätzliche Maßnahmen: Das Verringern der Segmentgröße nützt im ersten Fall nichts. Die Meldung unterscheidet sie nun explizit. - **1.9.2** Fix: Extraktion von News-Attributions-URLs mit verschachtelten Klammern oder FR-Präfix (2026-05-11):

  - **Behobener Bug**: Die Extraktion von Attributions-URLs in `_protect_news_quotes` verwendete den regulären Ausdruck `re.search(r"\((.+?)\)", attribution)` (Lazy-Capture in Klammern). Bei einer Attribution wie `(relayé par [@user sur X](https://x.com/.../123))` (verschachtelte Klammern: umschließende `(` + `]()` des Markdown-Links) stoppte die Erfassung bei der ersten gefundenen `)` → gekürzte Zeichenfolge + inklusive FR-Präfix: `relayé par [@user sur X](https://x.com/.../123` (ohne abschließendes `)`). Folge: `_validate_news_post` suchte nach dieser Zeichenfolge in der übersetzten Ausgabe und schlug systematisch fehl (zwei Gründe: abgeschnittenes `)` + „relayé par“ übersetzt in `relayed by`/`weitergeleitet von`/...). Die vollständige Kaskade low → medium → high → gpt-5.5 konnte nicht durchlaufen.
  - **Fix**: Der reguläre Ausdruck wird zu `re.search(r"\]\(([^)]+)\)", attribution)` – zielt spezifisch auf das `](url)` des Markdown-Links ab, erfasst **ausschließlich die reine URL** (ohne FR-Präfix oder Abschneiden), eine Invariante, die während der Übersetzung durch die Platzhalter `#URL{N}#` erhalten bleibt. Robust gegenüber beiden problematischen Mustern:

- **1.9** Behebung von Silent-Failures + umfassende Qualitätstools + Multi-Positions-Übersetzungshinweis (2026-05-07):
  - **Multi-Positions-Übersetzungshinweis + Format-Marker „Embed Card“**:
    - Neue CLI-Optionen (additiv, Standardwerte unverändert → **nicht-unterbrechend**):
      - `--note_position {top,bottom,both}` (Standard: `bottom`): platziert den Hinweis oben, unten oder an beiden Stellen der übersetzten Datei.
      - `--note_format {legacy,marker}` (Standard: `legacy`):
        - `legacy` reproduziert strikt das Verhalten der Version 1.8 (fetter Absatz `**…**`) **Byte für Byte**.
        - `marker` gibt eine unsichtbare Markdown-Link-Reference-Definition (`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`) aus, gefolgt von einem **3-Absatz-Blockquote**, das für ein Rendering im Stil einer „GitHub repo embed card“ strukturiert ist: Projekttitel in Inline-Code (`**\`ai-powered-markdown-translator\`\*\*`), vom LLM übersetzte Beschreibung und CTA-Link (`[Voir le projet sur GitHub ↗](URL)`) mit sichtbarem Pfeil. Zur Build-Zeit durch ein Remark-Plugin nutzbar (vgl. Blog jls42.org → Plugin `remark-translation-banner`).
    - **Niemals an das LLM gesendete Invarianten**: Repo-Titel und GitHub-URL werden auf Python-Seite nach der Übersetzung des beschreibenden Satzes zusammengesetzt. Das LLM sieht weder den Slug `ai-powered-markdown-translator` noch `https://github.com/jls42/...`, was garantiert, dass kein Renderer, keine Groß-/Kleinschreibung und kein Schema verändert wird.
    - **Frontmatter-bewusstes Einfügen (Frontmatter-aware)**: Im Modus `top` oder `both` wird der Hinweis **nach dem schließenden `---`-Block** des YAML-Frontmatters eingefügt (Sicherheit für Astro Content Collections / gray-matter). Der Helper `_split_frontmatter` erkennt `---\n…\n---\n` am Dateianfang und bewahrt dessen Integrität; **löst `RuntimeError` aus** bei geöffnetem Frontmatter ohne schließenden Fence (die Datei wird in `failed_files` gemeldet, anstatt mit einem falsch platzierten Hinweis geschrieben zu werden).
    - **Whitelist-Modell-Sanitizer**: `_sanitize_model` ersetzt jedes Zeichen außerhalb von `[A-Za-z0-9._:/-]` durch `_`, Fallback `unknown`, falls leer. Passt sich an den Validator auf der Seite des Astro-Remark-Plugins an und neutralisiert Zeichen, die das Marker-Format beschädigen würden (Leerzeichen, Anführungszeichen, Klammern, Kommas usw.).
    - **Internes Refactoring**: `_append_translation_note` (1 monolithische Funktion) → 7 reine Helper (`_translation_note_invariants`, `_build_translation_note_phrase`, `_assemble_translation_note_paragraphs`, `_build_translation_note_source`, `_sanitize_model`, `_quote_lines`, `_split_frontmatter`, `_build_translation_note_block`, `_compose_with_notes`). Builder/Composer getrennt (der Builder gibt einen reinen Block ohne Trennzeichen zurück, der Composer wendet die `\n\n` je nach Position an); Produktion und Quell-Helper teilen sich denselben 3-Absatz-Assembler.
    - **Leerzeilen-bewahrendes `_quote_lines` (blank-preserving)**: stellt jeder Zeile `> ` voran und wandelt Leerzeilen in ein einzelnes `>` um. Ermöglicht es mdast, 3 getrennte Absätze im Blockquote zu erkennen (Titel / Beschreibung / Link) anstelle eines einzelnen Absatzes mit Zeilenumbrüchen.
    - **Adaptives `_build_translation_note_block`**: abhängig von der Anzahl der Absätze, die das LLM beibehalten hat (3 = vollständiges Card-Format, 2 = Satz + Link, 1 = Fallback). Der 1-Absatz-Fallback **schließt nicht mehr in `**...**` ein**, wenn ein Markdown-Link `](` erkannt wird (fragiles Rendering von `<strong>` um einen Link herum).
    - **Abwärtskompatibilität**: `getattr(args, "note_position", "bottom")` und `getattr(args, "note_format", "legacy")` aufseiten von `_compose_with_notes` — Namespaces ohne diese Attribute (bestehende Tests, externe programmatische Aufrufe) funktionieren weiterhin ohne Änderungen.
