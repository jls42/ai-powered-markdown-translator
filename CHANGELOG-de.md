- **1.16.3** Dateiende: Eine Übersetzung per API behält den abschließenden Zeilenumbruch ihrer Quelle bei, und das Mistral SDK 3.0 wurde validiert (2026-10-04):

  - **Eine Übersetzung per API behält den abschließenden Zeilenumbruch ihrer Quelle bei.** Die API-Provider — OpenAI, Anthropic, Gemini, Mistral — entfernen den umgebenden Leerraum aus der Antwort des Modells. Beim letzten Segment entfernte diese Bereinigung auch den abschließenden Zeilenumbruch der Quelle: Eine übersetzte Datei ohne Übersetzungshinweis endete ohne Zeilenumbruch, was git meldet und Formatierungswerkzeuge bei jedem Durchlauf korrigieren. Dies fiel bei der Validierung des Mistral SDK 3.0 anhand eines Leitfadens auf, der mit einem Zeilenumbruch endete, dessen Übersetzung jedoch keinen mehr besaß. Der Übersetzungshinweis fügte wieder einen hinzu, und die Kommandozeilen-Provider — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — übernehmen das Segmentende: Betroffen war nur eine API-Übersetzung ohne Hinweis. Die Übersetzung gibt nun unabhängig vom Provider den abschließenden Zeilenumbruch der Quelle wieder und fügt einer Quelle ohne abschließenden Zeilenumbruch keinen hinzu.

  - **Mistral: Das SDK 3.0 wurde durch einen echten Aufruf validiert.** `mistralai` 3.0.0 ersetzt die HTTP-Bibliothek `httpx` durch `httpx2`; die Imports und der Übersetzungsaufruf ändern sich nicht. Eine Neuinstallation von aipmt erhielt es bereits, da die Abhängigkeiten keine Versionsobergrenze haben, doch war es noch nicht durch einen echten Aufruf erprobt worden: Ein über die Mistral API mit dem SDK 3.0 übersetzter Markdown-Leitfaden behält eine mit der Quelle identische Struktur. Die für die Entwicklung festgeschriebenen Versionen werden auf dieses SDK aktualisiert, und die Wiederholungsversuche in den Tests stellen ihm einen `httpx2`-Client bereit, wie er ihn auch in der Produktion verwendet.

- **1.16.2** Codeschutz: Zitierter Code in einem Zitat `--news` und ein eingerückter Block in einer Liste führen nicht mehr dazu, dass die Übersetzung aller Sprachen abgelehnt wird (2026-10-03):

  - **Zitierter Code in einem Zitat blockiert die Übersetzung nicht mehr.** Im Modus `--news` schützt aipmt Inline-Code, bevor englische Zitate beiseitegelegt und später unverändert wiederhergestellt werden. Code innerhalb eines Zitats wurde daher zusammen mit diesem entfernt: Das Modell sah seinen Token nie, und die Validierung erklärte ihn für verloren — in allen Sprachen. Die tägliche Nachrichtenbeobachtung des Autors blieb am 2. Oktober daran hängen: ein in einem Tweet zitierter Befehl `/plugin enable …`, die Testsprache zweimal abgelehnt, die dreizehn anderen nie gestartet. Die von einem Zitat mitgenommenen Token werden nun im beiseitegelegten Text aufgelöst. Bei Englisch als Zielsprache wird die französische Übersetzungszeile eines Zitats nicht mehr an das Modell gesendet: Die Anweisung forderte es auf, diese zu entfernen, und der darin enthaltene Code wurde anschließend als verloren gewertet, obwohl das Modell die Anweisung befolgt hatte. Das veröffentlichte Ergebnis ändert sich nicht. Schließlich interpretiert die Wiederherstellung eines Zitats dessen Backslashes nicht mehr neu: Ein zitierter `\n` bleibt ein `\n`. Durchgängig anhand des fehlgeschlagenen Artikels überprüft: Englisch und Deutsch wurden beim ersten Versuch durch `gpt-6.1-sol` übersetzt, mit einer zu den veröffentlichten Versionen identischen Struktur.

  - **Ein eingerückter Codeblock in einer Liste wird geschützt.** CommonMark erlaubt einen eingerückten Blockabschluss, und dies ist der Normalfall bei einem Block, der einen Schritt einer nummerierten Liste dokumentiert: Er gehört zum Listenelement und ist daher eingerückt. Das an Spalte 0 verankerte Schutzmuster übersah sie alle: Bei einem echten README wurden 8 von 14 Blöcken erkannt. Die übrigen sechs wurden dem Modell als Prosa übergeben, kamen unverändert zurück, da es sich um Befehle handelte, und die Schutzprüfung, die eine unverändert kopierte Übersetzung ablehnt, wies die Datei für alle Sprachen zurück — mit einer Meldung, die das Symptom, aber nie die Ursache nannte. Das Muster akzeptiert nun einen eingerückten Abschluss, und der Durchlauf durch Schutz und Wiederherstellung gibt das Dokument einschließlich Einrückung identisch zurück.

- **1.16.1** Interne Links: Der Anker-Token belässt die Klammern beim Link, und ein übersetzter Link wird nicht mehr unbemerkt verdoppelt (2026-09-27):

  - **Ein interner Link wird nicht mehr unbemerkt beschädigt.** Um einen Link zu einem Abschnitt zu schützen, ersetzte aipmt bei `[texte](#ancre)` den Teil in Klammern einschließlich der Klammern durch einen Token: Das Modell erhielt eckige Klammern, gefolgt von einem nackten Token — also einen scheinbar defekten Link — und versuchte gelegentlich, ihn zu „reparieren“. Die Wiederherstellung ergab dann `[texte]((#ancre))`, einen Link, der nirgendwohin führt, ohne dass eine Schutzprüfung dies meldete. Der Fehler trat bei jeder Neuerstellung der Übersetzungen dieses Repositorys auf — für 1.15.0 auf Spanisch, Koreanisch und anschließend Italienisch, für 1.16.0 auf Deutsch —, mit jedem getesteten Gemini Flash und sogar mit Claude Sonnet und Haiku. Der Token eines Markdown-Links behält nun seine Klammern: Das Modell erhält einen gültigen Link, den es nicht mehr zu reparieren versucht, und die Wiederherstellung akzeptiert auch einen Token, dessen Klammern entfernt wurden. HTML-Anker behalten einen nackten Token. Durchgängig mit dem empfindlichsten Modell, `gemini-3.8-flash-low`, anhand eines README überprüft, in dem ein Link in Klammern stand: Ohne die Korrektur wurde das README abgelehnt, drei Links wurden verdoppelt und ein Segment erneut verarbeitet; mit der Korrektur blieben alle drei Links intakt, ohne Wiederholung. Anschließend wurde dieses README durch `gemini-3.8-flash-medium` auf Deutsch, Japanisch und Hindi sowie durch Claude Code mit `sonnet` auf Deutsch übersetzt: Die Struktur war mit der Quelle identisch, und alle drei internen Links blieben überall intakt.

  - **Die Tests können das Repository, aus dem sie gestartet werden, nicht mehr verändern.** Wird aus einem verknüpften Worktree gepusht, übergibt git seinen Hooks die Variable, die das Repository bezeichnet, und der pre-push-Hook startet die Tests: Das für ein temporäres Verzeichnis vorgesehene `git init` eines Tests setzte das echte Repository zurück, das daraufhin plötzlich als Repository ohne Arbeitsbaum galt. Tests, die git starten, entfernen nun alle `GIT_*`-Variablen aus ihrer Umgebung; ein Regressionstest, der über diese Variable auf ein Köder-Repository verweist, überprüft dies.

- **1.16.0** Provider `--use_claude_code`: Übersetzen über das Kontingent eines Claude-Pro- oder -Max-Abonnements mit dem offiziellen CLI `claude -p` — ohne kostenpflichtigen Weg, was bei jedem Aufruf nachgewiesen wird (2026-09-26):

  - **Elfter Weg: das Claude-Abonnement ohne nutzungsabhängige Abrechnung.** `--use_claude_code` steuert das offizielle Claude-Code-Binary im Modus `-p` auf derselben Grundlage wie Codex, Grok CLI und Antigravity — eigene Prozessgruppe, sicheres Beenden bei Zeitüberschreitung, Strg-C oder Schließen des Terminals. Nicht zu verwechseln mit `--use_claude`, der nutzungsabhängig abgerechneten API von Anthropic. aipmt liest den Token niemals.

  - **Kein kostenpflichtiger Weg, auf drei Ebenen überprüft.** Die Umgebung des Unterprozesses ist eine Positivliste: weder API-Schlüssel noch Token, Cloud-Anbieter oder Kennzeichnung der Claude-Code-Sitzung, aus der aipmt gestartet werden könnte — die Sitzung, in der dieser Provider geschrieben wurde, exportierte fünfzehn davon. Der Preflight ohne Modellrunde verlangt von `claude auth status` die Abonnementverbindung ohne Console-Schlüssel und von `/usage` den Satz, der das Abonnement bestätigt. Anschließend muss jeder Aufruf dies sowohl in seinem Initialisierungsereignis — `apiKeySource: none`, erzwungene Umgebung korrekt empfangen, Modell aus der angeforderten Familie, kein schneller Modus — als auch in seinem Kontingentbericht bestätigen: Eine kostenpflichtige „extra usage“ beendet die Übersetzung sofort.

  - **Das Kontingent wird mit Claude-Code-Sitzungen geteilt, und der Provider schont es.** Jeder Aufruf meldet die Nutzung der 5-Stunden- und Wochenfenster; oberhalb von 80 % (`AIPMT_CLAUDE_MAX_UTILIZATION`) wird kein weiteres Segment gestartet. Am Tag der Implementierung war das Wochenkontingent des Kontos des Autors bereits zu 98 % ausgeschöpft.

  - **Nichts aus der Benutzerkonfiguration gelangt hinein, nichts aus der Sitzung bleibt zurück.** Ohne Tools, im Modus ohne Personalisierung, Benutzereinstellungen ignoriert, MCP-Server und Hooks deaktiviert, privates und temporäres Arbeitsverzeichnis, keine gespeicherten Transkripte. Mit Canarys gemessen: Ohne `CLAUDE_CODE_DISABLE_ATTACHMENTS` wurde ein `@chemin` des Dokuments zu einem Anhang, und das Modell gab statt der Übersetzung einen Leseaufruf zurück; damit gelangt nichts hindurch. Die Canarys `AGENTS.md`, `CLAUDE.md` und der Hook haben nichts geladen oder ausgeführt.

  - **Ein Segment, das mit `/` beginnt, erreichte das Modell nicht.** Unter `--disable-slash-commands` antwortet Claude Code selbst darauf mit „… isn't available in this environment.“, mit dem Status `success` und ohne jede Runde. Ein Zeilenumbruch vor dem Segment sendet es an das Modell; der Ausgabevertrag lehnt ohnehin eine Antwort ab, die ohne Runde, nach mehr als einer Runde, abgeschnitten oder von einem anderen als dem angekündigten Modell zurückgegeben wurde.

  - **Modelle: Aliasse, niemals eine festgeschriebene Kennung.** `sonnet` standardmäßig mit dem Aufwand `low` und ebenso in `--eco` — `--eco` ändert auf diesem Weg also nichts —, `opus` und `haiku` über `--model`; `fable` und die Varianten `[1m]` werden abgelehnt, da sie in `-p` ohne Nachfrage auf kostenpflichtige Credits zurückgreifen.

  - **Die Standardwerte wurden gemessen, nicht angenommen.** Mit `aipmt --use_claude_code` selbst: vier parallele Übersetzungen für die beiden Dokumente der README-Messungen — der dichte Nachrichtenbeobachtungsartikel in `--news` und dieses README in seiner Revision 1.14.0 —, jeweils in vierzehn Sprachen. `sonnet` mit dem Aufwand `low` erstellt alle 28 Übersetzungen, davon 26 ohne Abweichung: ein zusätzlich fett gesetztes Wort im chinesischen Artikel und im arabischen README eine an die vorherige angefügte Tabellenzeile, was die Darstellung kaschiert. Interne Links blieben intakt, englische Zitate wurden unverändert übernommen, und in der englischen Version wurden die französischen Übersetzungszeilen vom Modell ohne erfundenes Flag entfernt; Median von 6 min 49 s pro Sprache für den Artikel und 2 min 20 s für das README. `opus` übersetzt das README ohne jede Abweichung und ein Viertel schneller, aber keinen Artikel: Seine Schutzmechanismen stoppten die Antwort in allen vierzehn Sprachen bei einer kurzen Biologiemeldung. `haiku` erstellt dagegen alles — drei Abschnittsüberschriften wurden im Artikel auf Ebene 1 hochgestuft, die internen Links im englischen README verdoppelt —, ist aber doppelt so langsam wie `sonnet`: Es schlussfolgert, ohne dass dies verhindert werden kann, mit 61 % seiner Ausgabetokens, und sein niedrigerer Preis lässt im API-Äquivalent nur 14 % Ersparnis übrig. Daher auch `sonnet` in `--eco`. Der Aufwand bringt beim Übersetzen nichts: In einer vorangegangenen Serie — dieses README und dieses CHANGELOG auf Englisch, Japanisch und Hindi — erzeugte `sonnet` keinen einzigen Reasoning-Token, `opus` mit mittlerem Aufwand 1 % seiner Ausgabetokens; der mittlere Aufwand brachte gegenüber dem niedrigen weder bei der Struktur noch bei der Dauer einen Vorteil. Die Kampagne `sonnet` mit 1,8 Millionen Quellzeichen verbrauchte 9 Prozentpunkte des 5-Stunden-Fensters und 2 des Wochenfensters im Max-Abonnement des Autors — eine Obergrenze, da die Sitzung, welche die Messungen steuerte, aus demselben Kontingent schöpfte.

  - **Eine Ablehnung durch die Schutzmechanismen von Anthropic wird als solche benannt.** Opus 5.5 besitzt strengere Schutzmechanismen als Sonnet, und die Fehlermeldung von Anthropic weist darauf hin, dass diese gelegentlich Arbeiten kennzeichnen, die biologischer Forschung ähneln. Eine kurze Nachricht über 279 für eine Bindungsstelle erzeugte Moleküle genügte. Claude Code bricht die Antwort dann ab, versucht es einmal erneut, und das Modell gibt über zwei Runden „I can't continue this translation“ mit Erfolgsstatus und ohne Fehler zurück: Nur der Vertrag über eine einzige Runde stoppte diese Antwort, allerdings mit einer Meldung, die deren Ursache verschwieg. Für sich allein gesendet, wird die Kurzmeldung von der API aufgrund der Kategorie „bio“ abgelehnt. aipmt erkennt diese Anzeichen nun, benennt die Schutzmechanismen und ihre Kategorie, versucht es nicht erneut — derselbe Text würde dieselbe Ablehnung erneut auslösen — und empfiehlt `--model sonnet`, das die Kurzmeldung in alle vierzehn Sprachen übersetzt hat.

  - **Die Übersetzungen dieses Repositorys können diesen Weg ohne Ausnahme nutzen.** `REGEN_PROVIDER=claude_code` ist ein Abonnement und keine kostenpflichtige API: Es funktioniert ohne `REGEN_ALLOW_PAID_API` mit vier Jobs — die Kampagnen liefen mit vier gleichzeitigen Übersetzungen ohne einen einzigen Durchsatz- oder Verbindungssperrfehler — nach einem einmaligen Preflight, der kein Kontingent verbraucht. Standard bleibt Codex mit `gpt-5.6-sol`.

  - **Die Nutzungsbedingungen, unmissverständlich dargestellt.** Die rechtliche Seite von Claude Code hindert einen Benutzer nicht daran, sich mit seinem eigenen Abonnement beim unveränderten Binary anzumelden; sie untersagt Drittentwicklern, Anfragen über die Pro- oder Max-Anmeldedaten ihrer Benutzer zu leiten, und Anthropic bevorzugt für Drittanbieter-Tools einschließlich Open-Source-Projekten den API-Schlüssel und behält sich vor, deren Nutzung von kostenpflichtigen Credits abzuziehen. Kein Text klärt den Fall eines verbreiteten Tools, das das offizielle Binary startet: Der Benutzer setzt sein Konto ein.

  - **Tests**: neue Datei `tests/test_claude_code_provider.py` (58 Tests), 100 % der Anweisungen und Verzweigungen des Moduls, ohne jemals das echte `claude` zu starten — geleerte Umgebung, nicht vorhandenes Binary, `PATH` ohne `claude`, Test-Doubles, die eine Ausnahme auslösen, falls sie aufgerufen werden.

- **1.15.0** Provider `--use_antigravity`: Übersetzen über das Kontingent eines Google-AI-Pro- oder -Ultra-Abonnements mit dem offiziellen CLI `agy`; außerdem lassen Strg-C bei keinem Provider mehr einen laufenden Agenten zurück, ein leeres Segment lässt die Datei nicht mehr fehlschlagen, und ein projektbezogenes `.env` bestimmt nicht mehr das ausgeführte Binary (2026-09-26):

  - **Zehnter Provider-Weg: das Google-Abonnement ohne nutzungsabhängige Abrechnung.** Wer für Google AI Pro oder Ultra bezahlt, kann Übersetzungen nun auf dieses Kontingent anrechnen lassen, statt sie pro Token über die Gemini API zu bezahlen. `agy`, das offizielle CLI von Antigravity, ist der einzige Weg zu diesem Kontingent: Gemini CLI unterstützt seit dem 18. Juni 2026 weder Pro-, Ultra- noch kostenlose Konten, und das Antigravity SDK authentifiziert sich nur über einen API-Schlüssel oder Google Cloud. `--use_antigravity` steuert es wie Codex und Grok CLI im Headless-Modus auf derselben Grundlage — eigene Prozessgruppe, `SIGTERM` und anschließend `SIGKILL` bei Zeitüberschreitung, bereinigte Umgebung. Durchgängig mit agy 1.2.11 überprüft: Ein Markdown-Leitfaden — Front Matter, Fettdruck, Link mit Klammern, Inline-Code, in eine Liste eingerückter Codeblock, Tabelle, Zitat — wurde einschließlich Preflight in 14 Sekunden ins Englische übersetzt, mit einer zur Quelle identischen Struktur und hinzugefügtem Übersetzungshinweis; anschließend, nach den Korrekturen aus der Überprüfung, in 19 Sekunden ins Deutsche, mit identischer Struktur und ohne Schreibvorgänge in `~/.gemini`.
  - **Kein kostenpflichtiger Weg bleibt offen, und jeder Aufruf überprüft dies.** agy kennt neben dem Abonnement noch weitere Wege — API-Schlüssel, Google-Cloud-Projekt, Gateway, kostenpflichtige KI-Credits — und mehrere Umgebungsvariablen lassen es ohne sichtbaren Hinweis darauf umschalten. Gemessen: `AGY_GATEWAY_URL` sendet das Dokument an ein Drittanbieter-Gateway, `AGY_ADC_AUTH` schaltet auf ein kostenpflichtiges Google-Cloud-Projekt um, `CLOUD_CODE_URL` leitet den authentifizierten Endpoint an eine beliebige Adresse um. Die Umgebung des Unterprozesses wird daher über eine Positivliste statt über eine Sperrliste festgelegt: `PATH`, Sprache und Zeitzone, Terminal, Identität, Proxies und Zertifikate des Rechners sowie der Session-Bus — von denen ein `env -i` nachgewiesen hat, dass agy sie benötigt —, jedoch keinerlei Schlüssel. Eine zunächst erprobte Sperrliste nach Präfixfamilien (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_` …) übersah einige davon: Eine Überprüfung fand in den Zeichenketten des Binärprogramms Endpoint-Überschreibungen, die von keinem Präfix erfasst wurden: `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Zwei Einstellungen entziehen sich der Umgebung und lassen sich nur über `agy -p /config` auslesen: kostenpflichtige KI-Credits, die bei ausgeschöpftem Kontingent einspringen, und die Verbindung über ein Google-Cloud-Projekt. Ein Preflight, der keinerlei Kontingent verbraucht — gemessene Nutzung: null — verweigert die Übersetzung, wenn eine davon aktiv oder ein API-Schlüssel konfiguriert ist; fehlt eine Einstellung in `/config`, gilt dies bei allen drei ebenfalls als Ablehnungsgrund: Eine Version von agy, die eine davon umbenennt, darf keine Prüfung bestehen, die nichts überprüft hat. Schließlich muss das Protokoll jedes Aufrufs die Authentifizierung über das Abonnement bestätigen (`authMethod=consumer`); jede darin aufgeführte andere Authentifizierungsmethode führt in jeder der beiden vom Binärprogramm verwendeten Schreibweisen zur Ablehnung der Antwort: Maßgeblich ist der Aufruf selbst, nicht die zuvor vorbereitete Konfiguration.

  - **Der Übersetzungsagent besitzt keinerlei Tools, und sein Laden wird bei jedem Aufruf nachgewiesen.** Jeder Aufruf schreibt in ein temporäres Verzeichnis einen Agenten im Format der Projektagenten von agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Rund 800 Eingabetokens statt 12.400 mit dem Standardagenten; die dritte Einstellung ist dabei nicht redundant: Mit `excludeDefaultComponents` allein konnte ein Hook des Workspace weiterhin seine Befehle ausführen und seinen Text einschleusen. Die eigentliche Falle liegt woanders: Ein nicht auffindbarer Agent führt bei agy nicht zu einem Fehler. Rückgabecode 0, Status `SUCCESS`, und stattdessen antwortet der Coding-Agent mit 57 aktiven Tools — auf „Die Katze schläft.“ antwortete er: „Psst, wecken wir sie nicht! 🐱💤 Was kann ich heute für Sie tun?“. Weder stdout noch stderr weisen darauf hin; nur das Aufrufprotokoll tut es. Die Antwort wird daher abgelehnt, wenn das Protokoll diesen Rückfall meldet, und ebenso, wenn darin der positive Marker für das Laden des Agenten fehlt — eine Änderung des Protokollformats führt zur Ablehnung der Übersetzung, statt die Schutzvorkehrung unbemerkt zu entfernen. Jeder Marker muss im gemessenen Format eine vollständige Protokollzeile belegen — Schweregrad, Datum, Uhrzeit, Thread, Datei und Zeile: Das Binärprogramm enthält außerdem eine Zeile, die die Nachricht des Benutzers in das Protokoll kopiert — in 78 echten Protokollen nie beim standardmäßigen Log-Level beobachtet —, und ein Dokument, das diese Meldungen zitiert, darf die Schutzprüfung nicht anstelle von agy erfüllen können.

  - **Die Einstellungen und der Verlauf des Benutzers in agy bleiben unberührt.** Jeder Aufruf läuft mit einem eigenen HOME, temporären Verzeichnis und Arbeitsverzeichnis, die anschließend gelöscht werden. agy authentifiziert sich dennoch über den Schlüsselbund des Systems, den aipmt niemals liest. Nichts wird übernommen: weder die Berechtigungen des Benutzers — die es dem Standardagenten erlaubten, `ls` und `git` ohne Nachfrage auszuführen — noch seine globalen Regeln, Plugins, MCP-Server, Hooks und Skills. Auch seinem Verlauf wird nichts hinzugefügt, in dem jeder Aufruf eine Unterhaltung von etwa 200 KB hinterließ, den übersetzten Text eingeschlossen: Die Testkampagne hatte dort rund 95 Unterhaltungen hinterlassen und 17 Einträge aus einem auf 100 begrenzten Cache verdrängt. Überprüft: In `~/.gemini/antigravity-cli` wurde keine Datei geschrieben.

  - **Geschlossene Ablehnung überall dort, wo die Isolation nicht greifen würde.** Unter Linux ohne D-Bus-Session-Bus — SSH-Session, Container, Server — speichert agy sein Token in einer Datei unter `~/.gemini` statt im Schlüsselbund, wie das eigene Changelog (1.1.3) angibt, und die Isolation jedes Aufrufs verbirgt diese Datei. Die Ablehnung erfolgt nun vor jedem Start und nennt die tatsächliche Ursache, statt nach einminütigem Warten auf einen Verbindungscode zu einer erneuten Anmeldung zu raten, die das Problem nicht lösen würde. Unter Windows liest agy `USERPROFILE`, `APPDATA` und `TEMP`, nicht `HOME` oder `TMPDIR` — gemäß der Go-Dokumentation und den Zeichenketten des Binärprogramms: Dort würde nichts den Aufruf von den Einstellungen und dem Verlauf des Benutzers isolieren, weshalb `--use_antigravity` dort abgelehnt wird, solange dies nicht gemessen wurde. macOS wird akzeptiert, ohne gemessen worden zu sein; die Abrechnungssperre, die die effektive Konfiguration ausliest, greift dort.

  - **`exit 0` beweist nichts, vierte CLI.** Eine Antwort wird nur akzeptiert, wenn der Rückgabecode null ist, das JSON-Objekt den Status `SUCCESS` besitzt, das Protokoll konform ist, weder eine abgelehnte Aktion noch ein Befehl oder Fehler im JSON enthalten ist, stderr keine Warnung über eine Kürzung enthält und der Text nicht leer ist. `--print-timeout` wird niemals verwendet: Nach dessen Ablauf gibt agy die Teilausgabe als `SUCCESS` mit Code 0 zurück; das Zeitlimit wird extern durchgesetzt und beendet die Prozessgruppe. Ein Segment, das mit `/commande`, `!commande` oder `@fichier` beginnt, wird übersetzt, niemals ausgeführt oder aufgelöst — ohne `--disable-slash-commands` wurde „/help“ anstelle der Übersetzung ausgeführt. Ein ausschließlich aus Leerraum bestehendes Segment erreicht agy nicht mehr, da die Pipeline es unverändert zurückgibt (siehe unten), und wird als letzte Absicherung weiterhin vor dem Aufruf abgelehnt: Bei einer leeren Eingabe öffnet agy seine interaktive Oberfläche mit Code 0. Das Budget wird daher aus dem tatsächlich gesendeten Text abgeleitet und um dessen Anzahl an UTF-8-Bytes erhöht: Bei jedem Tokenizer mit Byte-Fusion – BPE auf Byte-Ebene, SentencePiece mit Byte-Fallback, die vom Katalog verwendeten Familien – entspricht ein Token mindestens einem Byte, und dies ist die einzige hier verfügbare Obergrenze, da OpenRouter an Dutzende unbekannter Tokenizer weiterleitet. Kein durchschnittliches Verhältnis war geeignet – ein Ideogramm aus einer zusätzlichen Ebene sinkt auf 1,33 Byte pro Token, ein kombinierendes Zeichen auf 1,00 –, und Eingabe plus Ausgabe passen nun konstruktionsbedingt in das Kontextfenster. Ein für das gewählte Modell zu dichtes Segment wird vor dem Aufruf statt nach der Abrechnung abgelehnt.
