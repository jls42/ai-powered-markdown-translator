- **1.16.3** Dateiende: Eine Übersetzung über eine API behält den abschließenden Zeilenumbruch ihrer Quelle bei, und das Mistral SDK 3.0 wurde validiert (2026-10-04):

  - **Eine Übersetzung über eine API behält den abschließenden Zeilenumbruch ihrer Quelle bei.** Die API-Provider – OpenAI, Anthropic, Gemini, Mistral – entfernen umgebende Leerzeichen aus der Antwort des Modells. Beim letzten Segment entfernte diese Bereinigung auch den abschließenden Zeilenumbruch der Quelle: Eine übersetzte Datei ohne Übersetzungshinweis endete ohne Zeilenumbruch, was git meldet und Formatter bei jedem Lauf korrigieren. Beobachtet wurde dies bei der Validierung des Mistral SDK 3.0 an einem Leitfaden, der mit einem Zeilenumbruch endete, dessen Übersetzung jedoch keinen mehr besaß. Der Übersetzungshinweis fügte wieder einen hinzu, und die Kommandozeilen-Provider – Codex, Grok CLI, Antigravity, Claude Code, OpenCode – übernehmen das Segmentende: Betroffen war ausschließlich eine API-Übersetzung ohne Hinweis. Die Übersetzung gibt nun unabhängig vom Provider den abschließenden Zeilenumbruch der Quelle wieder und fügt einer Quelle ohne abschließenden Zeilenumbruch keinen hinzu.

  - **Mistral: SDK 3.0 durch einen echten Aufruf validiert.** `mistralai` 3.0.0 ersetzt die HTTP-Bibliothek `httpx` durch `httpx2`; die Imports und der Übersetzungsaufruf bleiben unverändert. Eine Neuinstallation von aipmt erhielt diese Version bereits, da für die Abhängigkeiten keine Versionsobergrenze gilt, doch bisher war sie noch nicht mit einem echten Aufruf getestet worden: Ein über die Mistral API mit SDK 3.0 übersetzter Markdown-Leitfaden behält dieselbe Struktur wie die Quelle. Die für die Entwicklung festgeschriebenen Versionen wechseln zu diesem SDK, und die Wiederholungsversuche in den Tests stellen ihm einen `httpx2`-Client bereit, wie er auch in der Produktion verwendet wird.

- **1.16.2** Codeschutz: Zitierter Code in einem Zitat `--news` und ein eingerückter Block in einer Liste führen nicht mehr dazu, dass die Übersetzung in allen Sprachen abgelehnt wird (2026-10-03):

  - **Zitierter Code in einem Zitat blockiert die Übersetzung nicht mehr.** Im Modus `--news` schützt aipmt Inline-Code, bevor englische Zitate beiseitegelegt und später unverändert wiederhergestellt werden. Code innerhalb eines Zitats wurde daher zusammen mit diesem entfernt: Das Modell sah sein Token nie, und die Validierung erklärte es für verloren – in allen Sprachen. Der tägliche Nachrichtenüberblick des Autors kam am 2. Oktober an dieser Stelle zum Stillstand: Ein in einem Tweet zitierter Befehl `/plugin enable …`, die Testsprache zweimal abgelehnt, die dreizehn anderen nie gestartet. Tokens, die zusammen mit einem Zitat entfernt wurden, werden nun im beiseitegelegten Text aufgelöst. Bei Englisch als Zielsprache wird die französische Übersetzungszeile eines Zitats nicht mehr an das Modell gesendet: Die Anweisung verlangte ihre Entfernung, woraufhin der darin enthaltene Code als verloren galt, obwohl das Modell die Anweisung befolgt hatte. Das veröffentlichte Ergebnis ändert sich nicht. Schließlich interpretiert die Wiederherstellung eines Zitats dessen Backslashes nicht mehr neu: Ein zitierter `\n` bleibt ein `\n`. Durchgängig an dem fehlgeschlagenen Artikel geprüft: Englisch und Deutsch wurden beim ersten Versuch von `gpt-6.1-sol` übersetzt, mit derselben Struktur wie die veröffentlichten Versionen.

  - **Ein eingerückter Codeblock innerhalb einer Liste wird geschützt.** CommonMark erlaubt einen eingerückten Blockabschluss, und dies ist der Normalfall für einen Block, der einen Schritt einer nummerierten Liste dokumentiert: Er gehört zum Listenelement und ist daher eingerückt. Das in Spalte 0 verankerte Schutzmuster übersah sie alle: Bei einer echten README wurden 8 von 14 Blöcken erkannt. Die sechs anderen wurden dem Modell als Prosa übergeben, kamen unverändert zurück, da es sich um Befehle handelt, und die Prüfung, die eine unverändert kopierte Übersetzung ablehnt, wies die Datei für alle Sprachen zurück – mit einer Meldung, die das Symptom, aber nie die Ursache nannte. Das Muster akzeptiert nun einen eingerückten Abschluss, und der Durchlauf aus Schutz und Wiederherstellung gibt das Dokument einschließlich der Einrückung unverändert zurück.

- **1.16.1** Interne Links: Das Anker-Token überlässt dem Link seine Klammern, und ein übersetzter Link wird nicht mehr unbemerkt verdoppelt (2026-09-27):

  - **Ein interner Link wird nicht mehr unbemerkt beschädigt.** Um einen Link zu einem Abschnitt zu schützen, ersetzte aipmt bei `[texte](#ancre)` den Teil in Klammern einschließlich der Klammern durch ein Token: Das Modell erhielt eckige Klammern, gefolgt von einem bloßen Token – einen scheinbar defekten Link –, und „reparierte“ ihn gelegentlich. Die Wiederherstellung erzeugte dann `[texte]((#ancre))`, einen Link, der nirgendwohin führt, ohne dass eine Prüfung dies meldete. Der Fehler trat bei jeder Neuerstellung der Übersetzungen dieses Repositorys erneut auf – auf Spanisch, Koreanisch und anschließend Italienisch für Version 1.15.0, auf Deutsch für Version 1.16.0 –, mit jeder getesteten Gemini-Flash-Version und sogar mit Claude Sonnet und Haiku. Das Token eines Markdown-Links behält nun seine Klammern: Das Modell erhält einen gültigen Link, den es nicht mehr reparieren muss, und die Wiederherstellung akzeptiert auch ein Token, dessen Klammern entfernt wurden. HTML-Anker behalten ein bloßes Token. Durchgängig mit dem empfindlichsten Modell, `gemini-3.8-flash-low`, an einer README geprüft, in der ein Link in Klammern stand: Ohne Korrektur wurde die README abgelehnt, drei Links wurden verdoppelt und ein Segment erneut verarbeitet; mit Korrektur blieben alle drei Links intakt, ohne Wiederholung. Anschließend wurde diese README auf Deutsch, Japanisch und Hindi mit `gemini-3.8-flash-medium` sowie auf Deutsch mit Claude Code und `sonnet` geprüft: dieselbe Struktur wie die Quelle, alle drei internen Links überall intakt.

  - **Tests können das Repository, aus dem sie gestartet werden, nicht mehr verändern.** Bei einem Push aus einem verknüpften Worktree übergibt git seinen Hooks die Variable, die das Repository bezeichnet, und der pre-push-Hook startet die Tests: Das `git init` eines Tests, das für ein temporäres Verzeichnis vorgesehen war, setzte das echte Repository zurück, das daraufhin plötzlich als Repository ohne Arbeitsbaum galt. Tests, die git starten, entfernen nun sämtliche `GIT_*`-Variablen aus ihrer Umgebung, und ein Regressionstest, der über diese Variable auf ein Köder-Repository verweist, überprüft dies.

- **1.16.0** Provider `--use_claude_code`: Übersetzen mit dem Kontingent eines Claude-Pro- oder Claude-Max-Abonnements über die offizielle CLI `claude -p` – kein kostenpflichtiger Weg, und jeder Aufruf weist dies nach (2026-09-26):

  - **Elfter Weg: das Claude-Abonnement ohne nutzungsabhängige Abrechnung.** `--use_claude_code` steuert das offizielle Claude-Code-Programm im Modus `-p`, auf derselben Grundlage wie Codex, Grok CLI und Antigravity – eigene Prozessgruppe, sicheres Beenden bei Zeitüberschreitung, Ctrl-C oder Schließen des Terminals. Nicht zu verwechseln mit `--use_claude`, der nutzungsabhängig abgerechneten API von Anthropic. aipmt liest das Token niemals.

  - **Kein kostenpflichtiger Weg, auf drei Ebenen geprüft.** Die Umgebung des Unterprozesses basiert auf einer Positivliste: weder API-Schlüssel noch Token noch Cloud-Provider noch Kennzeichnung der Claude-Code-Sitzung, aus der aipmt gestartet werden könnte – die Sitzung, in der dieser Provider geschrieben wurde, exportierte fünfzehn davon. Der Preflight ohne Modelldurchlauf verlangt von `claude auth status` eine Abonnementverbindung ohne Console-Schlüssel und von `/usage` den Satz, der das Abonnement bestätigt. Jeder Aufruf muss dies anschließend in seinem Initialisierungsereignis bestätigen – `apiKeySource: none`, erzwungene Umgebung korrekt übernommen, Modell aus der angeforderten Familie, kein schneller Modus – sowie in seiner Kontingentübersicht: Die kostenpflichtige „extra usage“ beendet die Übersetzung sofort.

  - **Das Kontingent wird mit Claude-Code-Sitzungen geteilt, und der Provider geht sparsam damit um.** Jeder Aufruf meldet die Auslastung der 5-Stunden- und Wochenfenster; oberhalb von 80 % (`AIPMT_CLAUDE_MAX_UTILIZATION`) wird kein weiteres Segment gestartet. Am Tag der Implementierung lag das Wochenkontingent des Autorenkontos bereits bei 98 %.

  - **Nichts aus der Benutzerkonfiguration gelangt hinein, nichts aus der Sitzung bleibt zurück.** Ohne Tools, im Modus ohne Personalisierung, Benutzereinstellungen ignoriert, MCP-Server und Hooks deaktiviert, privates temporäres Arbeitsverzeichnis, keine gespeicherten Transkripte. Mit Canaries gemessen: Ohne `CLAUDE_CODE_DISABLE_ATTACHMENTS` wurde ein `@chemin` des Dokuments zu einem Anhang, und das Modell gab statt der Übersetzung einen Leseaufruf zurück; damit gelangt nichts hindurch. Die Canaries `AGENTS.md`, `CLAUDE.md` und der Hook haben nichts geladen oder ausgeführt.

  - **Ein Segment, das mit `/` beginnt, erreichte das Modell nicht.** Unter `--disable-slash-commands` antwortet Claude Code selbst darauf mit „… isn't available in this environment.“, im Status `success`, ohne einen einzigen Modelldurchlauf. Ein Zeilenumbruch vor dem Segment sendet es an das Modell; der Ausgabevertrag lehnt ohnehin eine Antwort ab, die ohne Durchlauf, nach mehr als einem Durchlauf, abgeschnitten oder von einem anderen als dem angekündigten Modell zurückgegeben wurde.

  - **Modelle: Aliasse, niemals eine festgeschriebene Kennung.** Standardmäßig `sonnet` mit Aufwand `low`, auch in `--eco` – `--eco` ändert auf diesem Weg daher nichts –, `opus` und `haiku` über `--model`; `fable` und die Varianten `[1m]` werden abgelehnt, da sie unter `-p` ohne Nachfrage auf kostenpflichtige Credits wechseln.

  - **Die Standardwerte werden gemessen, nicht angenommen.** Mit `aipmt --use_claude_code` selbst, vier parallelen Übersetzungen, anhand der beiden Dokumente aus den Messungen der README – dem dichten Nachrichtenüberblick in `--news` und dieser README in Revision 1.14.0 –, jeweils in vierzehn Sprachen. `sonnet` mit Aufwand `low` schreibt alle 28 Übersetzungen, davon 26 ohne Abweichung: ein zusätzlich fett gedrucktes Wort im chinesischen Artikel und in der arabischen README eine an die vorherige angefügte Tabellenzeile, was von der Darstellung verdeckt wird. Interne Links intakt, englische Zitate unverändert übernommen und in der englischen Fassung die französischen Übersetzungszeilen vom Modell entfernt, ohne ein Flag zu erfinden; median 6 min 49 s pro Sprache für den Artikel, 2 min 20 s für die README. `opus` übersetzt die README ohne jede Abweichung und ein Viertel schneller, aber keinen einzigen Artikel: Seine Schutzvorkehrungen stoppten die Antwort in allen vierzehn Sprachen bei einer kurzen Biologiemeldung. `haiku` schreibt hingegen alles – drei Abschnittsüberschriften im Artikel auf Ebene 1 angehoben, die internen Links der englischen README verdoppelt –, ist jedoch doppelt so langsam wie `sonnet`: Es denkt nach, ohne dass sich dies verhindern lässt, verwendet dafür 61 % seiner Ausgabe-Tokens, und sein niedrigerer Preis führt im API-Äquivalent nur zu einer Ersparnis von 14 %. Daher auch `sonnet` in `--eco`. Der Aufwand bringt beim Übersetzen nichts: In einem vorherigen Durchlauf – diese README und dieses CHANGELOG auf Englisch, Japanisch und Hindi – erzeugte `sonnet` kein einziges Denk-Token, `opus` mit mittlerem Aufwand verwendete dafür 1 % seiner Ausgabe-Tokens, und der mittlere Aufwand brachte gegenüber dem niedrigen weder bei der Struktur noch bei der Dauer einen Vorteil. Die Kampagne `sonnet` mit 1,8 Millionen Quellzeichen verbrauchte 9 Prozentpunkte des 5-Stunden-Fensters und 2 des Wochenfensters im Max-Abonnement des Autors – eine Obergrenze, da die Sitzung zur Steuerung der Messungen dasselbe Kontingent nutzte.
  - **Eine Ablehnung durch die Schutzmechanismen von Anthropic wird als solche benannt.** Opus 5.5 hat strengere Schutzmechanismen als Sonnet, und die Fehlermeldung von Anthropic warnt davor, dass sie bisweilen Arbeiten kennzeichnen, die der biologischen Forschung nahestehen. Eine kurze Meldung über 279 für eine Bindungsstelle erzeugte Moleküle genügte. Claude Code bricht daraufhin die Antwort ab, versucht es einmal erneut, und das Modell gibt über zwei Durchläufe hinweg „I can't continue this translation“ mit einem Erfolgsstatus und ohne Fehler zurück: Nur der Vertrag für einen einzelnen Durchlauf stoppte diese Antwort, wobei die Meldung ihre Ursache verschwieg. Allein gesendet wird die Meldung von der API wegen der Kategorie „bio“ abgelehnt. aipmt erkennt diese Anzeichen nun, benennt die Schutzmechanismen und ihre Kategorie, versucht es nicht erneut — derselbe Text würde dieselbe Ablehnung erneut auslösen — und empfiehlt `--model sonnet`, das die Meldung in alle vierzehn Sprachen übersetzt hat.

  - **Die Übersetzungen dieses Repositorys dürfen diesen Weg ohne Ausnahme verwenden.** `REGEN_PROVIDER=claude_code` ist ein Abonnement, keine nutzungsabhängig abgerechnete API: Es läuft ohne `REGEN_ALLOW_PAID_API` mit vier Jobs — die Kampagnen liefen mit vier gleichzeitigen Übersetzungen, ohne einen einzigen Ratenbegrenzungs- oder Verbindungssperrfehler — nach einem einmaligen Preflight, der kein Kontingent verbraucht. Standard bleibt Codex mit `gpt-5.6-sol`.

  - **Die Nutzungsbedingungen, unmissverständlich formuliert.** Die rechtliche Seite von Claude Code hindert einen Benutzer nicht daran, sich mit seinem eigenen Abonnement beim unveränderten Binärprogramm anzumelden; sie verbietet Drittentwicklern, Anfragen über die Pro- oder Max-Zugangsdaten ihrer Benutzer zu leiten, und Anthropic bevorzugt für Drittanbieter-Tools einschließlich Open-Source-Projekten den API-Schlüssel, wobei es sich vorbehält, deren Nutzung von bezahlten Guthaben abzuziehen. Kein Text entscheidet den Fall eines verteilten Tools, das das offizielle Binärprogramm startet: Der Benutzer setzt sein Konto ein.

  - **Tests**: neue Datei `tests/test_claude_code_provider.py` (58 Tests), 100 % der Anweisungen und Verzweigungen des Moduls, ohne jemals das echte `claude` zu starten — geleerte Umgebung, nicht vorhandenes Binärprogramm, `PATH` ohne `claude`, Test-Doubles, die beim Aufruf eine Ausnahme auslösen.

- **1.15.0** Provider `--use_antigravity`: Übersetzen mit dem Kontingent des Google-AI-Pro- oder -Ultra-Abonnements über das offizielle CLI `agy`; außerdem lässt Ctrl-C bei keinem Provider mehr einen laufenden Agenten zurück, ein leerer Abschnitt führt nicht mehr zum Fehlschlagen der Datei, und ein projektbezogenes `.env` bestimmt nicht mehr das ausgeführte Binärprogramm (2026-09-26):

  - **Zehnter Provider-Weg: das Google-Abonnement ohne nutzungsabhängige Abrechnung.** Wer für Google AI Pro oder Ultra bezahlt, kann seine Übersetzungen nun von diesem Kontingent abbuchen lassen, statt sie pro Token über die Gemini API zu bezahlen. `agy`, das offizielle CLI von Antigravity, ist der einzige Weg zu diesem Kontingent: Gemini CLI unterstützt seit dem 18. Juni 2026 keine Pro-, Ultra- oder kostenlosen Konten mehr, und das Antigravity SDK authentifiziert sich nur über einen API-Schlüssel oder Google Cloud. `--use_antigravity` steuert es im Headless-Modus wie Codex und Grok CLI auf derselben Grundlage — eigene Prozessgruppe, bei Zeitüberschreitung `SIGTERM` und danach `SIGKILL`, bereinigte Umgebung. Durchgängig mit agy 1.2.11 überprüft: Ein Markdown-Leitfaden — Front Matter, Fettdruck, Link mit Klammern, Inline-Code, eingerückter Codeblock in einer Liste, Tabelle, Zitat — wurde einschließlich Preflight in 14 Sekunden ins Englische übersetzt, mit derselben Struktur wie die Quelle und einer hinzugefügten Übersetzungsnotiz; nach den Korrekturen aus dem Review dann in 19 Sekunden ins Deutsche, mit identischer Struktur und ohne Schreibvorgang in `~/.gemini`.

  - **Kein kostenpflichtiger Weg bleibt offen, und jeder Start überprüft dies.** agy kennt neben dem Abonnement weitere Wege — API-Schlüssel, Google-Cloud-Projekt, Gateway, kostenpflichtige KI-Guthaben — und mehrere Umgebungsvariablen lassen es ohne sichtbaren Hinweis darauf umschalten. Gemessen: `AGY_GATEWAY_URL` sendet das Dokument an ein Drittanbieter-Gateway, `AGY_ADC_AUTH` schaltet auf ein kostenpflichtiges Google-Cloud-Projekt um, `CLOUD_CODE_URL` leitet den authentifizierten Endpoint an eine beliebige Adresse um. Die Umgebung des Unterprozesses basiert daher auf einer Positivliste statt einer Sperrliste: `PATH`, Sprache und Zeitzone, Terminal, Identität, Proxys und Zertifikate des Rechners sowie der Session-Bus — dessen Notwendigkeit für agy durch ein `env -i` belegt wurde —, ohne jeglichen Schlüssel. Eine zunächst erprobte Sperrliste nach Präfixfamilien (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_` …) übersah Variablen: Ein Review fand in den Zeichenketten des Binärprogramms Endpoint-Überschreibungen, die von keinem Präfix erfasst wurden, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Zwei Einstellungen entziehen sich der Umgebung und können nur über `agy -p /config` ausgelesen werden: die kostenpflichtigen KI-Guthaben, die bei erschöpftem Kontingent einspringen, und die Verbindung über ein Google-Cloud-Projekt. Ein Preflight, der nachweislich bei einer Nutzung von null kein Kontingent verbraucht, verweigert die Übersetzung, wenn eine dieser Einstellungen aktiv oder ein API-Schlüssel konfiguriert ist; fehlt eine Einstellung in `/config`, gilt dies bei allen drei als Ablehnungsgrund: Eine agy-Version, die eine davon umbenennt, darf eine Prüfung, die nichts überprüft hat, nicht bestehen. Schließlich muss das Protokoll jedes Aufrufs die Authentifizierung über das Abonnement bestätigen (`authMethod=consumer`), und jede andere darin aufgeführte Authentifizierungsmethode führt unabhängig von der jeweiligen der beiden vom Binärprogramm verwendeten Schreibweisen zur Ablehnung der Antwort: Maßgeblich ist der Aufruf selbst, nicht die vorbereitete Konfiguration.

  - **Der Übersetzungsagent besitzt keine Tools, und sein Laden wird bei jedem Aufruf nachgewiesen.** Jeder Aufruf schreibt in ein temporäres Verzeichnis einen Agenten im Format der Projektagenten von agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. - **1.13.0** Provider `--use_openrouter`: ein kostenpflichtiger Router zu etwa 430 Modellen, darunter offene chinesische Modelle (2026-09-05):

  - **Neunter Provider-Pfad, gemeinsam mit dem achten ausgeliefert.** 1.12.0 wurde nicht auf PyPI veröffentlicht: Die beiden Router OpenCode und OpenRouter erscheinen gemeinsam. [OpenRouter](https://openrouter.ai) bietet mit einem einzigen Schlüssel Zugriff auf Modelle, die hier kein anderer Provider bereitstellt – Kimi, Qwen, DeepSeek, Z.ai – über ein gemeinsames, nutzungsabhängig abgerechnetes Guthaben. Da der Endpoint OpenAI-kompatibel ist, wird derselbe Client wie für xAI verwendet; **alles, was diesen Provider unterscheidet, steckt in einem Preflight**, und jede seiner Regeln beruht auf einer Messung an der API.

  - **Dasselbe Modell wird von Dutzenden Hosts mit unterschiedlichen Limits bereitgestellt, und das Routing berücksichtigt diese nicht.** Gemessen wurden 33 Hosts für `z-ai/glm-5.2` und 23 für `z-ai/glm-5.3-flash` – darunter einer mit einem Limit von **2.048 Ausgabe-Tokens**. Eine lange Übersetzung über einen dieser 23 Hosts wurde daher zufällig und ohne jedes Signal abgeschnitten. Der Preflight liest `/api/v1/models/{modèle}/endpoints`, schließt Hosts mit weniger als 8.000 Ausgabe-Tokens, mit beeinträchtigtem Status oder ohne angegebenes Limit aus und pinnt anschließend die übrigen. `provider.only` **ohne** `allow_fallbacks: false` ist lediglich eine Präferenz: Der Router weicht auf einen ausgeschlossenen Host aus, wodurch das Pinning wirkungslos wird. Erfüllt kein Host das Limit, wird der Befehl abgebrochen: Trotzdem zu übersetzen hieße, genau die stille Trunkierung hinzunehmen, die dieser Preflight verhindern soll.

  - **Reasoning wird zum Ausgabetarif abgerechnet und ist bei vielen Modellen standardmäßig aktiviert.** Dieselbe Anfrage an `z-ai/glm-5.2` mit der Antwort „OK“: **107 Completion-Tokens mit der Standardeinstellung des Modells, 2 bei deaktiviertem Reasoning**. Bei einer Übersetzung, zu der Reasoning nichts beiträgt, ergibt das den Faktor 18 für jedes Segment jeder Datei. Daher ist es standardmäßig deaktiviert. Die **288 von 431 Modellen**, die es erzwingen (`reasoning.mandatory`), antworten mit `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: Für sie liest der Preflight die unterstützten Effort-Stufen und fordert die niedrigste an (nächster Punkt). Der Effort weist einen **Prozentsatz von `max_tokens`** zu, den das Reasoning zuerst verbraucht; ein willkürlich gewählter Wert verlagert daher lediglich das Risiko einer leeren Ausgabe, statt es zu senken.

  - **Ein Modell, das Reasoning erzwingt, erhält den niedrigsten von ihm unterstützten Effort, und diese Entscheidung beruht auf einer Messung.** Ursprünglich sollte gar nichts übermittelt werden, um nicht anstelle des Modells zu raten. Bei einem Test mit `z-ai/glm-5.3-flash`, dessen Katalogstandard `max` ist, führte diese Entscheidung zu einer **bei 32.768 Tokens abgeschnittenen Ausgabe**, noch bevor die Übersetzung abgeschlossen war – zwei von vierzehn Sprachen gingen verloren. Eine größere Obergrenze hätte daran nichts geändert: Der Effort weist einen Prozentsatz davon zu, sodass das Reasoning mit ihr wächst. Der Provider liest deshalb beim Preflight `supported_efforts` und fordert die niedrigste Stufe an; meldet der Katalog keine verwendbare Stufe, wird ersatzweise „nichts“ angefordert. Gegenprobe mit der fehlerhaften Sprache: Zuvor scheiterte sie an einem erschöpften Budget, jetzt wird sie in 9 Minuten mit einer zur Quelle identischen Struktur abgeschlossen.

Die allgemeine Meldung verleitete dazu, nach einem Fehler im Dokument oder in der Segmentierung zu suchen; jetzt weist sie darauf hin, dass die Störung beim Anbieter liegt und ein erneuter Versuch häufig genügt.

Die beiden Fälle erfordern gegensätzliche Maßnahmen: Im ersten Fall bringt es nichts, die Segmente zu verkleinern. Die Meldung unterscheidet sie ausdrücklich.
