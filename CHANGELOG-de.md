- **1.16.2** Codeschutz: In einem Zitat zitierter Code `--news` und ein in einer Liste eingerückter Block führen nicht mehr dazu, dass die Übersetzung für alle Sprachen abgelehnt wird (2026-10-03):
  - **In einem Zitat zitierter Code blockiert die Übersetzung nicht mehr.** Im Modus `--news` schützt aipmt Inline-Code, bevor englische Zitate beiseitegelegt werden, die unverändert wiederhergestellt werden. Ein in einem Zitat platzierter Code wurde daher mit diesem entfernt: Das Modell sah dessen Token nie, und die Validierung stufte ihn als verloren ein – für alle Sprachen. Das tägliche Tech-Monitoring des Autors kam am 2. Oktober genau hier zum Stillstand: Ein in einem Tweet zitierter `/plugin enable …`-Befehl führte dazu, dass die Test-Sonde zweimal abgelehnt und die dreizehn weiteren Sprachen gar nicht erst gestartet wurden. Die von einem Zitat mitgenommenen Token werden nun im beiseitegelegten Text aufgelöst. Bei englischem Ziel wird die französische Übersetzungszeile eines Zitats nicht mehr an das Modell gesendet: Die Anweisung verlangte von ihm, sie zu löschen, und der darin enthaltene Code galt daraufhin als verloren, obwohl das Modell der Anweisung gefolgt war. Das veröffentlichte Ergebnis ändert sich nicht. Schließlich reinterpretiert die Wiederherstellung eines Zitats dessen Backslashes nicht mehr: Ein zitiertes `\n` bleibt ein `\n`. End-to-End an dem Artikel überprüft, der zuvor fehlgeschlagen war: Englisch und Deutsch auf Anhieb durch `gpt-6.1-sol` übersetzt, Struktur identisch mit den veröffentlichten Versionen.

  - **Ein in einer Liste eingerückter Codeblock wird geschützt.** CommonMark erlaubt einen eingerückten Blockabschluss, was der Normalfall für einen Block ist, der einen nummerierten Listenschritt dokumentiert: Er gehört zum Listenelement und ist daher eingerückt. Da das Schutzmuster an Spalte 0 verankert war, verfehlte es sie alle: An einer echten README gemessen wurden nur 8 von 14 Blöcken erkannt. Die sechs anderen gingen als Fließtext an das Modell, kamen unverändert zurück, da es sich um Befehle handelt, und die Schutzprüfung, die eine unverändert kopierte Übersetzung ablehnt, wies die Datei für alle Sprachen ab – mit einer Meldung, die das Symptom, aber nie die Ursache benannte. Das Muster akzeptiert nun einen eingerückten Abschluss, und der Roundtrip zwischen Schutz und Wiederherstellung liefert das Dokument identisch zurück, einschließlich der Einrückung.

- **1.16.1** Interne Links: Das Anker-Token überlässt dem Link seine Klammern, und ein übersetzter Link wird nicht mehr stillschweigend verdoppelt (2026-09-27):
  - **Ein interner Link bricht nicht mehr unbemerkt ab.** Um einen Link zu einem Abschnitt, `[texte](#ancre)`, zu schützen, ersetzte aipmt dessen eingeklammerten Teil samt Klammern durch ein Token: Das Modell erhielt eckige Klammern gefolgt von einem nackten Token – ein scheinbar defekter Link –, den es gelegentlich zu „reparieren“ versuchte. Die Wiederherstellung erzeugte daraufhin `[texte]((#ancre))`, einen Link ins Leere, ohne dass eine Schutzprüfung dies meldete. Der Fehler trat bei jeder Neuerstellung der Übersetzungen dieses Repositorys auf – auf Spanisch, Koreanisch und dann Italienisch für Version 1.15.0, auf Deutsch für Version 1.16.0 – bei jedem getesteten Gemini Flash und sogar bei Claude Sonnet und Haiku. Das Token eines Markdown-Links behält nun seine Klammern: Das Modell erhält einen gültigen Link, den es nicht mehr zu reparieren versucht, und die Wiederherstellung akzeptiert auch ein Token, aus dem es die Klammern entfernt haben sollte. HTML-Anker behalten ein nacktes Token. End-to-End mit dem fragilsten Modell, `gemini-3.8-flash-low`, an einer README überprüft, deren Link in Klammern stand: Ohne den Fix wurde die README abgelehnt, drei Links verdoppelt und ein Segment erneut verarbeitet; mit ihm blieben drei von drei Links intakt, keine Wiederholungen. Anschließend an dieser README auf Deutsch, Japanisch und Hindi mit `gemini-3.8-flash-medium` sowie auf Deutsch über Claude Code mit `sonnet` getestet: Struktur identisch zur Quelle, alle drei internen Links überall intakt.

  - **Tests können das Repository, das sie ausführt, nicht mehr verändern.** Beim Pushen aus einem verknüpften Worktree übergibt git die Variable, die das Repository bezeichnet, an seine Hooks, und der Pre-Push-Hook führt die Tests aus: Das für ein temporäres Verzeichnis gedachte `git init` eines Tests setzte das echte Repository zurück, das plötzlich als arbeitsbaumlos deklariert wurde. Tests, die git aufrufen, entfernen nun jegliche `GIT_*`-Variable aus ihrer Umgebung, und ein Regressionstest, der über diese Variable auf ein Schein-Repository verweist, überprüft dies.

- **1.16.0** Provider `--use_claude_code`: Übersetzen über das Kontingent des Claude Pro- oder Max-Abonnements über die offizielle CLI `claude -p` – kein kostenpflichtiger Weg, und jeder Aufruf belegt dies (2026-09-26):
  - **Elfter Pfad: Das Claude-Abonnement ohne nutzungsbasierte Abrechnung.** `--use_claude_code` steuert die offizielle Binärdatei von Claude Code im Modus `-p` auf derselben Basis wie Codex, Grok CLI und Antigravity – eigene Prozessgruppe, sicheres Beenden bei Timeout, Strg-C oder Schließen des Terminals. Nicht zu verwechseln mit `--use_claude`, der nach Verbrauch abgerechneten API von Anthropic. aipmt liest das Token niemals aus.

  - **Kein kostenpflichtiger Pfad, auf drei Ebenen überprüft.** Die Umgebung des Unterprozesses basiert auf einer Allowlist: kein API-Schlüssel, kein Token, kein Cloud-Provider, keine Markierung der Claude Code-Sitzung, aus der aipmt gestartet worden sein könnte – die Sitzung, die diesen Provider geschrieben hat, exportierte fünfzehn davon. Der Preflight erfordert ohne Modell-Turn von `claude auth status` die Abonnement-Anmeldung ohne Console-Schlüssel und von `/usage` den Satz, der das Abonnement bestätigt. Jeder Aufruf muss dies anschließend in seinem Initialisierungsereignis bestätigen – `apiKeySource: none`, erzwungene Umgebung erfolgreich empfangen, Modell aus der angeforderten Familie, kein Schnellmodus – sowie in seiner Kontingentübersicht: Eine kostenpflichtige „Extra-Nutzung“ stoppt die Übersetzung auf der Stelle.

  - **Das Kontingent wird mit Claude Code-Sitzungen geteilt, und der Provider schont es.** Jeder Aufruf meldet die Auslastung der 5-Stunden- und Wochenfenster; ab 80 % (`AIPMT_CLAUDE_MAX_UTILIZATION`) wird kein weiteres Segment gestartet. Am Tag der Implementierung lag die Woche des Autorenkontos bereits bei 98 %.

  - **Nichts aus der Benutzerkonfiguration dringt ein, nichts von der Sitzung bleibt zurück.** Ohne Werkzeuge, im Modus ohne Anpassungen, Benutzereinstellungen ignoriert, MCP-Server und Hooks getrennt, privates Einweg-Arbeitsverzeichnis, kein Transkript aufbewahrt. Gemessen anhand von Kanarienvögeln: Ohne `CLAUDE_CODE_DISABLE_ATTACHMENTS` wurde ein `@chemin` des Dokuments zu einem Anhang, und das Modell lieferte einen Leseaufruf anstelle der Übersetzung; mit der Option dringt nichts durch. Die Kanarienvögel `AGENTS.md`, `CLAUDE.md` und der Hook haben weder etwas geladen noch ausgeführt.

  - **Ein Segment, das mit `/` beginnt, erreichte das Modell nicht.** Unter `--disable-slash-commands` antwortet Claude Code selbst mit „… isn't available in this environment.“, mit Status `success`, ohne jeglichen Turn. Ein Zeilenumbruch vor dem Segment leitet es an das Modell weiter; der Ausgabevertrag verweigert ohnehin jede Antwort, die ohne Turn, in mehr als einem Turn, abgeschnitten oder von einem anderen als dem angekündigten Modell zurückgegeben wird.

  - **Modelle: Aliase, niemals ein fester Bezeichner.** `sonnet` standardmäßig, mit Aufwand `low`, und auch in `--eco` – `--eco` ändert auf diesem Pfad also nichts –, `opus` und `haiku` über `--model`; `fable` und die `[1m]`-Varianten werden abgelehnt, da sie in `-p` ohne Nachfrage über kostenpflichtige Guthaben abgerechnet werden.

  - **Fehler werden gemessen, nicht vermutet.** Durch `aipmt --use_claude_code` selbst, vier parallele Übersetzungen, an den beiden Messdokumenten der README – dem dichten Monitoring-Artikel in `--news` und dieser README in Version 1.14.0 –, jeweils vierzehn Sprachen. `sonnet`, mit Aufwand `low`, erzeugt die 28 Übersetzungen, 26 davon ohne Abweichungen: ein zusätzliches fettgedrucktes Wort auf Chinesisch im Artikel und auf Arabisch in der README eine an die vorherige Zeile angehängte Tabellenzeile, was in der Darstellung unsichtbar bleibt. Interne Links intakt, englische Zitate unverändert übernommen, und auf Englisch wurden die französischen Übersetzungszeilen vom Modell entfernt, ohne erfundene Kennzeichnungen; 6 Min. 49 Sek. Median pro Sprache für den Artikel, 2 Min. 20 Sek. für die README. `opus` übersetzt die README ohne jede Abweichung, ein Viertel schneller, jedoch keinen einzigen Artikel: Seine Sicherheitsfilter stoppten die Antwort in allen vierzehn Sprachen bei einer Kurzmeldung zur Biologie. `haiku` schreibt zwar alles – drei Abschnittsüberschriften im Artikel wurden auf Ebene 1 hochgestuft, die internen Links der englischen README verdoppelt –, jedoch doppelt so langsam wie `sonnet`: Es schlussfolgert, ohne dass man es daran hindern könnte (61 % seiner Ausgabe-Token), und sein niedrigerer Preis bringt als API-Äquivalent lediglich 14 % Ersparnis. Daher auch `sonnet` in `--eco`. Der Aufwand bringt beim Übersetzen nichts: Bei einem vorherigen Batch – dieser README und diesem CHANGELOG auf Englisch, Japanisch und Hindi – erzeugte `sonnet` keinerlei Reasoning-Token, `opus` bei mittlerem Aufwand 1 % seiner Ausgabe-Token, und der mittlere Aufwand brachte gegenüber dem niedrigen weder strukturell noch zeitlich einen Gewinn. Der Durchlauf mit `sonnet`, 1,8 Millionen Quellzeichen, verbrauchte 9 Prozentpunkte des 5-Stunden-Fensters und 2 der Woche auf dem Max-Abonnement des Autors – eine Obergrenze, da die Sitzung, die die Messungen steuerte, aus demselben Kontingent schöpfte.

  - **Eine Ablehnung durch die Sicherheitsfilter von Anthropic wird als solche benannt.** Opus 5.5 verfügt über strengere Schutzmechanismen als Sonnet, und die Fehlermeldung von Anthropic weist darauf hin, dass diese mitunter Arbeiten im Umfeld der biologischen Forschung markieren. Eine kurze Meldung über 279 für eine Bindungsstelle generierte Moleküle genügte bereits. Claude Code bricht die Antwort daraufhin ab, startet einen Neuversuch, und das Modell meldet „I can't continue this translation“ mit Erfolgsstatus, ohne Fehler, über zwei Turns: Lediglich der Single-Turn-Vertrag fing diese Antwort ab, mit einer Meldung, die über die Ursache schwieg. Separat gesendet wird die Meldung von der API unter der Kategorie „bio“ abgelehnt. aipmt erkennt diese Anzeichen nun, benennt die Sicherheitsfilter sowie deren Kategorie, verzichtet auf Neuversuche – derselbe Text würde dieselbe Ablehnung auslösen – und empfiehlt `--model sonnet`, das die Meldung in alle vierzehn Sprachen übersetzt hat.

  - **Die Übersetzungen dieses Repositorys können ohne Ausnahme über diesen Pfad laufen.** `REGEN_PROVIDER=claude_code` ist ein Abonnement, keine abgerechnete API: Es läuft ohne `REGEN_ALLOW_PAID_API` mit vier Jobs – die Testläufe arbeiteten mit vier gleichzeitigen Übersetzungen ohne einen einzigen Rate-Limit- oder Sperrfehler –, nach einem einmaligen Preflight, der kein Kontingent verbraucht. Der Standard bleibt Codex mit `gpt-5.6-sol`.

  - **Die Nutzungsbedingungen, unumwunden dargelegt.** Die rechtliche Seite von Claude Code hindert Nutzer nicht daran, sich mit dem unveränderten Binary über das eigene Abonnement anzumelden; sie untersagt Drittanbieter-Entwicklern, Anfragen über die Pro- oder Max-Anmeldedaten ihrer Nutzer zu leiten, und Anthropic bevorzugt für Drittanbieter-Tools einschließlich Open-Source-Projekten den API-Schlüssel, wobei vorbehalten bleibt, deren Nutzung über kostenpflichtige Guthaben abzurechnen. Kein Text regelt den Fall eines verteilten Tools, das die offizielle Binärdatei startet: Der Nutzer haftet mit seinem Konto.

  - **Tests**: Neue Datei `tests/test_claude_code_provider.py` (58 Tests), 100 % der Anweisungen und Zweige des Moduls abgedeckt, ohne jemals das echte `claude` zu starten – bereinigte Umgebung, nicht vorhandene Binärdatei, `PATH` ohne `claude`, Testdoubles, die bei Aufruf Exceptions werfen.

- **1.15.0** Provider `--use_antigravity`: Übersetzen über das Kontingent des Google AI Pro- oder Ultra-Abonnements über die offizielle CLI `agy`; und für alle Provider gilt: Strg-C lässt keine aktiven Agenten mehr zurück, ein Leer-Segment bringt die Datei nicht mehr zum Scheitern, eine Projekt-`.env` bestimmt nicht mehr die ausgeführte Binärdatei (2026-09-26):
  - **Zehnter Provider-Pfad: Das Google-Abonnement ohne nutzungsbasierte Abrechnung.** Wer für Google AI Pro oder Ultra bezahlt, kann seine Übersetzungen nun darüber abrechnen lassen, anstatt sie tokenbasiert über die Gemini-API zu bezahlen. `agy`, die offizielle CLI von Antigravity, ist der einzige Weg zu diesem Kontingent: Die Gemini CLI bedient seit dem 18. Juni 2026 keine Pro-, Ultra- oder kostenlosen Konten mehr, und das Antigravity-SDK authentifiziert sich ausschließlich über einen API-Schlüssel oder Google Cloud. `--use_antigravity` steuert sie im Headless-Modus, genau wie Codex und Grok CLI, auf derselben Basis – eigene Prozessgruppe, `SIGTERM` gefolgt von `SIGKILL` bei Timeout, bereinigte Umgebung. End-to-End auf agy 1.2.11 überprüft: Ein Markdown-Leitfaden – Front Matter, Fettschrift, Link mit Klammern, Inline-Code, in einer Liste eingerückter Codeblock, Tabelle, Zitat – auf Englisch in 14 Sekunden übersetzt, einschließlich Preflight, Struktur identisch zur Quelle, Übersetzungshinweis hinzugefügt; anschließend, nach den Korrekturen aus dem Review, auf Deutsch in 19 Sekunden, identische Struktur, keinerlei Schreibzugriffe in `~/.gemini`.

  - **Kein kostenpflichtiger Pfad bleibt offen, und jeder Start prüft dies nach.** agy kennt neben dem Abonnement weitere Wege – API-Schlüssel, Google Cloud-Projekt, Gateway, kostenpflichtige KI-Guthaben – und mehrere Umgebungsvariablen lassen es unbemerkt darauf umschalten. Gemessen: `AGY_GATEWAY_URL` sendet das Dokument an ein Drittanbieter-Gateway, `AGY_ADC_AUTH` wechselt zu einem abgerechneten Google Cloud-Projekt, `CLOUD_CODE_URL` leitet den authentifizierten Endpunkt an eine beliebige Adresse um. Die Umgebung des Unterprozesses ist daher eine Allowlist und keine Denylist: `PATH`, Sprache und Zeitzone, Terminal, Identität, Proxys und Zertifikate des Systems sowie der Session-Bus – alles, wovon ein `env -i` gezeigt hat, dass agy es benötigt –, ohne jeglichen Schlüssel. Eine Denylist nach Präfixfamilien (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), die zuerst erprobt wurde, übersah Einträge: Eine Überprüfung fand in den Zeichenketten der Binärdatei Endpunkt-Überschreibungen, die von keinem Präfix abgedeckt wurden: `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Zwei Einstellungen entziehen sich der Umgebung und lassen sich nur über `agy -p /config` auslesen: kostenpflichtige KI-Guthaben, die bei erschöpftem Kontingent einspringen, und die Verbindung über ein Google Cloud-Projekt. Ein Preflight, der kein Kontingent verbraucht – gemessener Verbrauch gleich null –, verweigert die Übersetzung, falls eine davon aktiv oder ein API-Schlüssel konfiguriert ist, und eine in `/config` fehlende Einstellung wird für jede der drei Optionen als Ablehnung gewertet: Eine agy-Version, die eine davon umbenennt, darf keine Prüfung bestehen, die nichts verifiziert hat. Schließlich muss das Protokoll jedes Aufrufs die Authentifizierung über das Abonnement nachweisen (`authMethod=consumer`), und jede andere dort aufgeführte Authentifizierungsmethode – unter welcher der beiden von der Binärdatei verwendeten Schreibweisen auch immer – führt zur Zurückweisung der Antwort: Maßgeblich ist der Aufruf selbst, nicht die vorbereitete Konfiguration.

  - **Der Übersetzungs-Agent besitzt keinerlei Tools, und sein Laden wird bei jedem Aufruf nachgewiesen.** Jeder Aufruf schreibt in ein temporäres Verzeichnis einen Agenten im Format der agy-Projekt-Agenten: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Ungefähr 800 Eingabe-Tokens statt 12.400 beim Standard-Agenten, und die dritte Einstellung ist nicht redundant: `excludeDefaultComponents` allein ließ einen Workspace-Hook seine Befehle ausführen und seinen Text einschleusen. Die eigentliche Falle liegt woanders: Ein nicht gefundener Agent führt bei agy nicht zum Fehlschlag. Rückgabecode 0, Status `SUCCESS`, und der Coding-Agent mit 57 aktiven Tools antwortet – auf „Le chat dort.“ antwortete er „Chut, ne le réveillons pas ! 🐱💤 Que puis-je faire pour vous aujourd'hui ?“. Nichts auf stdout oder stderr: Nur das Protokoll des Aufrufs verrät es. Die Antwort wird daher abgelehnt, wenn das Protokoll dieses Fallback meldet, und ebenso, wenn es die positive Markierung für das Laden des Agenten nicht enthält – eine Änderung des Protokollformats führt zur Ablehnung der Übersetzung, anstatt die Schutzfunktion stillschweigend zu entfernen. Jede Markierung muss eine ganze Zeile des Protokolls im gemessenen Format einnehmen – Schweregrad, Datum, Uhrzeit, Thread, Datei und Zeile: Die Binärdatei enthält außerdem eine Zeile, die die Benutzernachricht ins Protokoll kopiert – bei der Standard-Protokollierungsstufe in 78 echten Protokollen nie beobachtet –, und ein Dokument, das solche Nachrichten zitiert, darf die Schutzfunktion nicht anstelle von agy erfüllen können.

  - **Die agy-Einstellungen und der Verlauf des Benutzers bleiben unangetastet.** Jeder Aufruf läuft mit einem privaten HOME, temporären Verzeichnis und Arbeitsverzeichnis, die anschließend gelöscht werden. agy authentifiziert sich dennoch über den System-Schlüsselbund, den aipmt niemals liest. Nichts wird vererbt: weder die Berechtigungen des Benutzers – die es dem Standard-Agenten erlaubten, `ls` und `git` ohne Nachfrage auszuführen –, noch seine globalen Regeln, Plugins, MCP-Server, Hooks und Skills. Und dem Verlauf wird nichts hinzugefügt, in dem jeder Aufruf eine Konversation von etwa 200 KB einschließlich des übersetzten Textes hinterließ: Die Test-Kampagne hatte dort rund 95 Konversationen hinterlassen und 17 Einträge aus einem auf 100 begrenzten Cache verdrängt. Überprüft: Keine geschriebene Datei in `~/.gemini/antigravity-cli`.

  - **Fail-Closed-Ablehnung dort, wo die Isolation nicht greifen würde.** Unter Linux ohne D-Bus-Sitzungsbus – SSH-Sitzung, Container, Server – legt agy sein Token in einer Datei in `~/.gemini` statt im Schlüsselbund ab, wie das eigene Changelog (1.1.3) ankündigt, und die Isolation jedes Aufrufs blendet diese Datei aus. Die Ablehnung erfolgt nun vor jedem Start mit ihrer tatsächlichen Ursache, anstelle einer einminütigen Wartezeit auf einen Login-Code gefolgt von einem Ratschlag zur erneuten Anmeldung, der nichts lösen würde. Unter Windows liest agy `USERPROFILE`, `APPDATA` und `TEMP`, nicht aber `HOME` oder `TMPDIR` – laut Go-Dokumentation und Zeichenketten in der Binärdatei –: Nichts würde dort den Aufruf von den Einstellungen oder dem Verlauf des Benutzers isolieren, und `--use_antigravity` wird dort abgelehnt, solange dies nicht vermessen ist. macOS läuft durch, ohne vermessen worden zu sein; die Abrechnungsschutzfunktion, die die effektive Konfiguration liest, greift dort.

  - **`exit 0` beweist nichts, viertes CLI.** Eine Antwort wird nur mit einem Null-Rückgabecode akzeptiert, einem JSON-Objekt mit Status `SUCCESS`, einem konformen Protokoll, weder abgelehnter Aktion noch Befehl noch Fehler im JSON, keinerlei Abschneidewarnung auf stderr und einem nicht-leeren Text. `--print-timeout` wird nie verwendet: Bei Ablauf liefert agy die Teilausgabe in `SUCCESS`, Code 0; der Timeout ist extern und beendet die Prozessgruppe. Ein Segment, das mit `/commande`, `!commande` oder `@fichier` beginnt, wird übersetzt, niemals ausgeführt oder aufgelöst – ohne `--disable-slash-commands` wurde „/help“ anstelle der Übersetzung ausgeführt. Ein Leerraum-Segment erreicht agy nicht mehr, da die Pipeline es unverändert zurückgibt (siehe unten), und wird vor dem Aufruf als letztes Netz weiterhin abgelehnt: Bei einer leeren Eingabe öffnet agy seine interaktive Oberfläche mit Code 0. Wiederholungsversuche folgen dem Feld `retryable` der Zeile `AGY_ERROR`, die agy seit Version 1.2.6 auf stderr schreibt: Es wiederholt vorübergehende Fehler bereits selbst – 502, 503, 504, Limit pro Minute –, und es weiß selbst, ob der verbleibende Fehler weiterhin temporär ist. Fehlt dieses Feld, erfolgt kein Wiederholungsversuch, wenn die Meldung von Erschöpfung spricht – bei Google hat `RESOURCE_EXHAUSTED` denselben 429-Code wie ein Limit pro Minute, aber ein erschöpftes 5-Stunden-Fenster erholt sich nicht in 90 Sekunden –, und ansonsten nur bei Ratenbegrenzung. Die Antwort übernimmt das Zeilenende des Segments: agy beendet seine Ausgabe stets mit einem Zeilenumbruch, der an der Nahtstelle einen mitten im Satz geteilten Absatz zerschnitt. Eine getrennte Sitzung liefert eine Meldung, die anweist, `agy` auszuführen, um sich erneut zu verbinden. `AGY_CLI_DISABLE_AUTO_UPDATE=true` verhindert schließlich, dass ein frisches HOME bei jedem Aufruf einen Update-Checker in einer eigenen Sitzung startet, außerhalb der Reichweite des Timeouts – der Wert `1` selbst hat keine Wirkung.

  - **Modelle: Der Reasoning-Aufwand ist Teil des Namens.** Die Bezeichner sind diejenigen von `agy models` – `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6` … Ein Basisname allein, den agy ablehnen würde, wird vor dem Aufruf abgelehnt, unter Angabe der existierenden Suffixe: `-medium` oder `-low` für ein Flash, `-high` oder `-low` für ein Pro. Standardmäßig `gemini-3.8-flash-medium` und `gemini-3.7-flash-low` in `--eco`, festgelegt durch die unten beschriebenen Kampagnen. `--reasoning_effort` ist wirkungslos und weist darauf hin. Claude und GPT-OSS schöpfen aus einem separaten und deutlich kleineren Kontingent – etwa 1 % des 5-Stunden-Fensters pro gemessenem Aufruf gegenüber 0,05 % bei Flash –, woran eine Warnung erinnert. Das verbleibende Kontingent lässt sich kostenlos über `agy -p /usage` ablesen. In CI abgelehnt, wie Codex und Grok CLI: Das Login liegt in einem persönlichen Schlüsselbund, und die Meldung schlägt `--use_gemini` mit einem Google-Schlüssel vor.

    - Die CLI kann mit 0 beendet werden, obwohl sie ein `turn.failed` ausgegeben hat: Die JSONL-Ausgabe (`--json`) wird zusätzlich zum Rückgabecode geprüft, und das Fehlen der Datei `-o` bei einem Exit-Code 0 löst einen expliziten Fehler aus, anstatt ein leeres Segment zu erzeugen.
  - **Backoff bei Rate-Limit**: Die CLI implementiert keine internen Wiederholungsversuche (`max_retries = 0`). Die Klassifizierung erfolgt anhand der Struktur der JSON-Nutzlast (`status: 429` / `error.type`), nicht anhand von Teilzeichenfolgen – da das Wort „quota“ sowohl bei einem behebbaren 429 als auch bei einem endgültigen `insufficient_quota` vorkommt.
  - **CI-Schutzmaßnahme**: `--use_codex` wird abgelehnt, wenn `CI` oder `GITHUB_ACTIONS` definiert ist. Die abonnementbasierte Authentifizierung ist nicht für einen geteilten Runner ausgelegt, und OpenAI rät auf öffentlichen Repositories explizit von diesem Workflow ab.
  - **Modelle**: `gpt-5.6-sol` (Qualität) und `gpt-5.6-luna` (`--eco`). Die Familie `gpt-5.6-*` ist der CLI und der Platform-API gemeinsam, aber ein ChatGPT-Konto hat nicht auf alles Zugriff: Die Allowlist wird serverseitig ohne lokale Validierung angewendet, und ein ungewöhnliches Modell löst eine Warnung aus. Bei einem Plus-Tarif bietet Luna 250–2.000 Nachrichten pro 5-Stunden-Fenster im Vergleich zu 10–100 bei Sol: `--eco` ist der empfohlene Modus für jede Stapelverarbeitung.
  - **Fehler behoben — `regen_translations.sh` brach trotz vollständigem Erfolg mit einem Fehler ab**: Der `trap ... EXIT` referenzierte `failed_log`, eine Variable `local` von `main()`, die zu dem Zeitpunkt, an dem der Trap ausgeführt wird, nicht mehr existiert. Unter `set -u` löste dies `failed_log: unbound variable` aus und führte dazu, dass das Skript mit 1 beendet wurde, obwohl alle 28 Übersetzungen korrekt waren – was `release.sh --auto` (`set -e`) direkt nach der Neugenerierung beim kostspieligsten Schritt unterbrochen hätte. Die Variable wird global und der Trap prüft ihre Existenz. Nützlicher Nebeneffekt: Echte Übersetzungsfehler, die bisher durch diesen Fehler verdeckt wurden, sind in der abschließenden Zusammenfassung wieder sichtbar.
  - **`REGEN_MODEL`**: Neue Umgebungsvariable von `regen_translations.sh`, die ein bestimmtes Modell über den Standard des Providers erzwingt, beispielsweise `REGEN_PROVIDER=codex REGEN_MODEL=gpt-5.6-sol`, um mit dem High-End-Modell des Abonnement-Kontingents anstelle des volumenorientierten Modells `--eco` neu zu generieren.

- **1.9.2** Fix bei der Extraktion von News-Attributions-URLs mit verschachtelten Klammern oder FR-Präfix (11.05.2026):
  - **Fehler behoben**: Die Extraktion von Attributions-URLs in `_protect_news_quotes` verwendete den Regex `re.search(r"\((.+?)\)", attribution)` (Lazy-Capture in Klammern). Bei einer Attribution des Typs `(relayé par [@user sur X](https://x.com/.../123))` (verschachtelte Klammern: umschließende `(` + `]()` des Markdown-Links) stoppte die Erfassung bei der ersten angetroffenen `)` → abgeschnittene Zeichenfolge + einschließlich des FR-Präfixes: `relayé par [@user sur X](https://x.com/.../123` (ohne abschließendes `)`). Folge: `_validate_news_post` suchte nach dieser Zeichenfolge in der übersetzten Ausgabe und schlug systematisch fehl (zwei Gründe: abgeschnittenes `)` + „relayé par“ übersetzt als `relayed by`/`weitergeleitet von` / ...). Vollständige Kaskade low → medium → high → gpt-5.5 konnte nicht durchlaufen werden.
  - **Fix**: Der Regex wird zu `re.search(r"\]\(([^)]+)\)", attribution)` – zielt spezifisch auf das `](url)` des Markdown-Links ab, erfasst **ausschließlich die reine URL** (ohne FR-Präfix oder Abschneiden), eine Invariante, die durch die Platzhalter `#URL{N}#` während der Übersetzung beibehalten wird. Robust gegenüber beiden problematischen Mustern:
    - `(relayé par [@account sur X](url))` — verschachtelte Klammern
    - `via [@source](url)` oder `selon [@author](url)` — FR-Präfix ohne umschließende Klammern
  - **Tests**: 2 neue in `test_silent_failure.py`, Klasse `TestNewsCitationExtraction`:
