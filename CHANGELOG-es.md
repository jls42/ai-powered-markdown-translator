- **1.16.2** Protección de código: el código citado dentro de una cita `--news` y un bloque indentado en una lista ya no provocan el rechazo de la traducción para todos los idiomas (2026-10-03):
  - **El código citado dentro de una cita ya no bloquea la traducción.** En modo `--news`, aipmt protege el código inline antes de apartar las citas en inglés, que se restauran tal cual. Por lo tanto, el código ubicado dentro de una cita se iba con ella: el modelo nunca veía su token, y la validación lo declaraba perdido para todos los idiomas. El seguimiento diario de noticias del autor se detuvo ahí el 2 de octubre: un comando `/plugin enable …` citado en un tuit, el idioma de sondeo rechazado dos veces y los otros trece nunca iniciados. Los tokens que una cita se llevó ahora se resuelven en el texto apartado. En destino en inglés, la línea de traducción en francés de una cita ya no se envía al modelo: la instrucción le pedía que la eliminara, y el código que contenía se contabilizaba entonces como perdido a pesar de que el modelo había obedecido. El resultado publicado no cambia. Por último, la restauración de una cita ya no reinterpreta sus barras invertidas: un `\n` citado sigue siendo un `\n`. Comprobado de principio a fin en el artículo que había fallado: inglés y alemán traducidos a la primera por `gpt-6.1-sol`, con estructura idéntica a las versiones publicadas.

  - **Los bloques de código indentados en una lista están protegidos.** CommonMark permite un cierre de bloque desplazado, y este es el caso normal de un bloque que documenta un paso en una lista numerada: pertenece al elemento de la lista, por lo que está indentado. Anclado en la columna 0, el patrón de protección los omitía todos: medido en un README real, 8 bloques detectados de 14. Los otros seis se enviaban al modelo como prosa, volvían idénticos por ser comandos, y la comprobación de seguridad que rechaza una traducción copiada tal cual rechazaba el archivo para todos los idiomas, con un mensaje que señalaba el síntoma pero nunca la causa. Ahora el patrón acepta un cierre indentado, y el viaje de ida y vuelta entre protección y restauración devuelve el documento idéntico, incluida la indentación.

- **1.16.1** Enlaces internos: el token de anclaje deja sus paréntesis al enlace, y un enlace traducido ya no se duplica en silencio (2026-09-27):
  - **Los enlaces internos ya no se rompen de forma inadvertida.** Para proteger un enlace a una sección, `[texte](#ancre)`, aipmt reemplazaba su parte entre paréntesis, incluidos los paréntesis, por un token: el modelo recibía corchetes seguidos de un token sin rodear, un enlace con apariencia de estar roto, y en ocasiones intentaba «repararlo». La restauración devolvía entonces `[texte]((#ancre))`, un enlace que no conduce a ninguna parte, sin que ninguna comprobación lo advirtiera. El fallo reaparecía en cada regeneración de las traducciones de este repositorio —en español, coreano y luego italiano para la 1.15.0, en alemán para la 1.16.0— con cada Gemini Flash probado, e incluso con Claude Sonnet y Haiku. El token de un enlace Markdown ahora conserva sus paréntesis: el modelo recibe un enlace válido que ya no tiene motivos para reparar, y la restauración también acepta un token al que se le hayan retirado los paréntesis. Las anclas HTML conservan un token sin rodear. Comprobado de principio a fin con el modelo más frágil, `gemini-3.8-flash-low`, en un README donde un enlace estaba entre paréntesis: sin la corrección, README rechazado, tres enlaces duplicados y un segmento reintentado; con ella, tres enlaces intactos de tres, ninguna reejecución. Luego en este README, en alemán, japonés e hindi con `gemini-3.8-flash-medium`, y en alemán con Claude Code usando `sonnet`: estructura idéntica al original, con los tres enlaces internos intactos en todas partes.

  - **Las pruebas ya no pueden modificar el repositorio que las ejecuta.** Al hacer push desde un worktree vinculado, git transmite a sus hooks la variable que designa el repositorio, y el hook pre-push ejecuta las pruebas: el `git init` de una prueba, previsto para un directorio temporal, reinicializó el repositorio real, declarándolo repentinamente sin árbol de trabajo. Las pruebas que ejecutan git ahora eliminan cualquier variable `GIT_*` de su entorno, y una prueba de no regresión, que apunta mediante esta variable a un repositorio señuelo, lo comprueba.

- **1.16.0** Proveedor `--use_claude_code`: traducir con la cuota de la suscripción a Claude Pro o Max, mediante la CLI oficial `claude -p` —ninguna vía de pago, y cada llamada lo demuestra (2026-09-26):
  - **Undécima vía: la suscripción a Claude, sin facturación por uso.** `--use_claude_code` controla el binario oficial de Claude Code en modo `-p`, sobre la misma base que Codex, Grok CLI y Antigravity: grupo de procesos propio, detención segura por tiempo de espera, Ctrl-C o cierre de la terminal. No debe confundirse con `--use_claude`, la API de Anthropic con facturación por uso. aipmt nunca lee el token.

  - **Ninguna vía de pago, comprobado en tres niveles.** El entorno del subproceso es una lista de elementos permitidos: sin clave de API, sin token, sin proveedor en la nube y sin marcas de la sesión de Claude Code desde la que se pudiera ejecutar aipmt —la que programó este proveedor exportaba quince—. La comprobación previa, sin turnos del modelo, exige de `claude auth status` el inicio de sesión por suscripción sin clave de Console, y de `/usage` la frase que certifica la suscripción. Cada llamada debe luego certificarlo en su evento de inicialización —`apiKeySource: none`, entorno forzado recibido correctamente, modelo de la familia solicitada, sin modo rápido— y en su reporte de cuota: el «extra usage» de pago detiene la traducción de inmediato.

  - **La cuota se comparte con las sesiones de Claude Code y el proveedor la gestiona con cuidado.** Cada llamada informa del uso en las ventanas de 5 horas y semanal; por encima del 80 % (`AIPMT_CLAUDE_MAX_UTILIZATION`), no se lanza ningún segmento adicional. El día en que se escribió, la ventana semanal de la cuenta del autor ya estaba al 98 %.

  - **Nada de la configuración del usuario entra, nada de la sesión permanece.** Sin herramientas, en modo sin personalización, ajustes del usuario ignorados, servidores MCP y hooks desconectados, directorio de trabajo privado y desechable, sin transcripciones guardadas. Medido con canarios: sin `CLAUDE_CODE_DISABLE_ATTACHMENTS`, un `@chemin` del documento se convertía en archivo adjunto y el modelo devolvía una llamada de lectura en lugar de la traducción; con él, nada pasa. Los canarios `AGENTS.md`, `CLAUDE.md` y de hooks no cargaron ni ejecutaron nada.

  - **Un segmento que comience por `/` no llegaba al modelo.** Con `--disable-slash-commands`, Claude Code responde por sí mismo « … isn't available in this environment. », con estado `success`, sin ningún turno. Un salto de línea antes del segmento lo envía al modelo; el contrato de salida rechaza de todos modos cualquier respuesta devuelta sin turnos, en más de un turno, truncada o generada por un modelo distinto al anunciado.

  - **Modelos: alias, nunca un identificador fijo.** `sonnet` por defecto, con esfuerzo `low`, y también en `--eco` —por lo que `--eco` no cambia nada en esta vía—, `opus` y `haiku` mediante `--model`; `fable` y las variantes `[1m]` son rechazados, ya que en `-p` consumen créditos de pago sin consultar.

  - **Los defectos se miden, no se suponen.** Mediante el propio `aipmt --use_claude_code`, cuatro traducciones en paralelo, en los dos documentos de referencia del README —el denso artículo de seguimiento, en `--news`, y este README en su revisión 1.14.0—, catorce idiomas cada uno. `sonnet`, con esfuerzo `low`, genera las 28 traducciones, 26 de ellas sin discrepancias: una palabra en negrita de más en chino en el artículo, y en árabe, en el README, una fila de tabla pegada a la anterior, que la visualización oculta. Enlaces internos intactos, citas en inglés copiadas tal cual y, en inglés, las líneas de traducción al francés retiradas por el modelo, sin flags inventados; 6 min 49 s de mediana por idioma en el artículo, 2 min 20 s en el README. `opus` traduce el README sin ninguna discrepancia, un cuarto más rápido, pero ningún artículo: sus filtros de seguridad detuvieron la respuesta en los catorce idiomas debido a una breve noticia de biología. Por su parte, `haiku` lo escribe todo —tres encabezados de sección convertidos a nivel 1 en el artículo, los enlaces internos del README en inglés duplicados—, pero el doble de lento que `sonnet`: razona sin que se pueda evitar, con un 61 % de sus tokens de salida dedicados a ello, y su menor precio solo deja un 14 % de ahorro equivalente en API. De ahí que se use `sonnet` también en `--eco`. El esfuerzo no aporta nada a la traducción: en un lote previo —este README y este CHANGELOG en inglés, japonés e hindi—, `sonnet` no produjo ningún token de razonamiento, `opus` con esfuerzo medio produjo un 1 % de sus tokens de salida, y el esfuerzo medio no aportó mejoras respecto al bajo, ni en estructura ni en tiempo. La campaña `sonnet`, con 1,8 millones de caracteres fuente, consumió 9 puntos porcentuales de la ventana de 5 horas y 2 de la semanal en la suscripción Max del autor —un límite superior: la sesión que gestionaba las mediciones consumía de la misma cuota—.

  - **El rechazo por parte de los filtros de seguridad de Anthropic se identifica explícitamente.** Opus 5.5 tiene filtros de seguridad más estrictos que Sonnet, y el mensaje de error de Anthropic advierte que a veces señalan trabajos relacionados con la investigación biológica. Bastó una breve noticia informativa sobre 279 moléculas generadas para un sitio de unión. Claude Code interrumpe entonces la respuesta, reintenta una vez y el modelo devuelve « I can't continue this translation » con estado de éxito, sin error, en dos turnos: únicamente el contrato de turno único detenía esta respuesta, con un mensaje silencioso sobre la causa. Enviada por separado, la API rechaza la noticia bajo la categoría «bio». aipmt ahora reconoce estas señales, identifica los filtros de seguridad y su categoría, no reintenta —el mismo texto volvería a provocar el mismo rechazo— y aconseja `--model sonnet`, que tradujo la noticia en los catorce idiomas.

  - **Las traducciones de este repositorio pueden realizarse por esta vía, sin excepciones.** `REGEN_PROVIDER=claude_code` es una suscripción, no una API facturada: se ejecuta sin `REGEN_ALLOW_PAID_API`, con cuatro trabajos —las campañas funcionaron con cuatro traducciones simultáneas sin un solo error de límite de peticiones ni de bloqueo de conexión—, tras una única comprobación previa que no consume cuota. El valor predeterminado sigue siendo Codex con `gpt-5.6-sol`.

  - **Los términos de uso, explicados claramente.** La página legal de Claude Code no impide que un usuario inicie sesión en el binario sin modificar con su propia suscripción; prohíbe a terceros desarrolladores canalizar solicitudes a través de las credenciales Pro o Max de sus usuarios, y Anthropic prefiere las claves de API para herramientas de terceros, incluidos los proyectos de código abierto, reservándose el derecho de descontar su uso de los créditos de pago. Ningún texto define claramente el caso de una herramienta distribuida que ejecute el binario oficial: el usuario asume la responsabilidad con su cuenta.

  - **Pruebas**: nuevo archivo `tests/test_claude_code_provider.py` (58 pruebas), 100 % de las instrucciones y ramas del módulo, sin ejecutar jamás el `claude` real —entorno vaciado, binario inexistente, `PATH` sin `claude`, dobles de prueba que lanzan excepciones si se les invoca.

- **1.15.0** Proveedor `--use_antigravity`: traducir con la cuota de la suscripción a Google AI Pro o Ultra, mediante la CLI oficial `agy`; y, para todos los proveedores, Ctrl-C ya no deja agentes en ejecución, un segmento en blanco ya no hace fallar el archivo, y un `.env` de proyecto ya no elige el binario ejecutado (2026-09-26):
  - **Décima vía de proveedor: la suscripción a Google, sin facturación por uso.** Quien pague Google AI Pro o Ultra ahora puede descontar de allí sus traducciones en lugar de pagarlas por token en la API de Gemini. `agy`, la CLI oficial de Antigravity, es la única vía hacia esta cuota: Gemini CLI ya no da servicio a cuentas Pro, Ultra ni gratuitas desde el 18 de junio de 2026, y el SDK de Antigravity solo se autentica mediante clave de API o Google Cloud. `--use_antigravity` lo controla en modo headless, como Codex y Grok CLI, sobre la misma base: grupo de procesos propio, `SIGTERM` y luego `SIGKILL` al expirar el tiempo de espera, entorno depurado. Comprobado de principio a fin en agy 1.2.11: una guía en Markdown —front matter, negrita, enlaces con paréntesis, código en línea, bloques de código indentados en una lista, tablas, citas— traducida al inglés en 14 segundos, incluida la comprobación previa, estructura idéntica al original, nota de traducción añadida; y luego, tras las correcciones de la revisión, al alemán en 19 segundos, estructura idéntica, sin escribir nada en `~/.gemini`.

  - **Ninguna vía de pago queda abierta, y cada ejecución lo comprueba.** agy admite otras vías además de la suscripción —clave de API, proyecto de Google Cloud, pasarela, créditos de IA de pago— y varias variables de entorno hacen que cambie a ellas sin mostrar nada. Medido: `AGY_GATEWAY_URL` envía el documento a una pasarela de terceros, `AGY_ADC_AUTH` cambia a un proyecto facturado de Google Cloud, `CLOUD_CODE_URL` redirige el endpoint autenticado hacia cualquier dirección. Por tanto, el entorno del subproceso es una lista de elementos permitidos y no de exclusión: `PATH`, el idioma y la zona horaria, la terminal, la identidad, los proxies y certificados del sistema y el bus de sesión —lo que un `env -i` demostró que agy necesita—, sin ninguna clave. Una lista de exclusión por familias de prefijos (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), probada inicialmente, dejaba elementos fuera: una revisión encontró en las cadenas del binario modificaciones de endpoint que ningún prefijo cubría: `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Dos ajustes escapan al entorno y solo pueden leerse mediante `agy -p /config`: los créditos de IA de pago que toman el relevo cuando se agota la cuota, y la conexión a través de un proyecto de Google Cloud. Una comprobación previa que no consume cuota —uso en cero, medido— rechaza traducir si alguno de ellos está activo o si se ha configurado una clave de API, y la ausencia de un ajuste en `/config` equivale a un rechazo para cada uno de los tres: una versión de agy que renombrara alguno no debe superar un control que no haya verificado nada. Por último, el registro de cada llamada debe certificar la autenticación mediante la suscripción (`authMethod=consumer`), y cualquier otro método de autenticación que aparezca en él, bajo cualquiera de las dos grafías que emplea el binario, provoca el rechazo de la respuesta: es la propia llamada la que da fe, no la configuración preparada.

  - **El agente de traducción no tiene ninguna herramienta y su carga se comprueba en cada llamada.** Cada llamada escribe, en un directorio desechable, un agente con el formato de los agentes de proyecto de agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Alrededor de 800 tokens de entrada en lugar de 12 400 con el agente predeterminado, y el tercer ajuste no es redundante: `excludeDefaultComponents` por sí solo permitía que un hook del workspace ejecutara sus comandos e inyectara su texto. La verdadera trampa está en otra parte: un agente no encontrado no hace fallar a agy. Código de salida 0, estado `SUCCESS`, y es el agente de programación, con 57 herramientas activas, el que responde —a «Le chat dort.», respondió «Chut, ne le réveillons pas ! 🐱💤 Que puis-je faire pour vous aujourd'hui ?»—. Nada en stdout ni en stderr: solo el registro de la llamada lo dice. Por lo tanto, la respuesta se rechaza si el registro anuncia este repliegue, y también si no lleva el marcador positivo de la carga del agente —una evolución del formato del registro hace que se rechace la traducción en lugar de retirar la protección en silencio—. Cada marcador debe ocupar una línea completa del registro, en el formato medido —severidad, fecha, hora, hilo, archivo y línea—: el binario también contiene una línea que copia el mensaje del usuario en el registro —nunca vista con el nivel de registro predeterminado, en 78 registros reales—, y un documento que cite estos mensajes no debe poder satisfacer la protección en lugar de agy.

  - **La configuración y el historial de agy del usuario no se tocan.** Cada llamada se ejecuta con un HOME, un directorio temporal y un directorio de trabajo privados, eliminados posteriormente. Aun así, agy se autentica mediante el llavero del sistema, que aipmt nunca lee. Nada se hereda: ni los permisos del usuario —que permitían al agente predeterminado ejecutar `ls` y `git` sin preguntar nada—, ni sus reglas globales, plugins, servidores MCP, hooks y skills. Y nada se añade a su historial, donde cada llamada dejaba una conversación de unos 200 KB, texto traducido incluido: la campaña de sondeos había dejado allí unas 95 conversaciones y desalojado 17 entradas de una caché limitada a 100. Verificado: ningún archivo escrito en `~/.gemini/antigravity-cli`.

  - **Rechazo seguro donde el aislamiento no se sostendría.** En Linux sin bus de sesión D-Bus —sesión SSH, contenedor, servidor—, agy guarda su token en un archivo de `~/.gemini` en lugar de en el llavero, como anuncia su propio registro de cambios (1.1.3), y el aislamiento de cada llamada oculta este archivo. Ahora el rechazo se produce antes de cualquier inicio, con su causa real, en lugar de un minuto de espera de un código de inicio de sesión seguido de un consejo de reconexión que no resolvería nada. En Windows, agy lee `USERPROFILE`, `APPDATA` y `TEMP`, no `HOME` ni `TMPDIR` —según la documentación de Go y las cadenas del binario—: nada aislaría allí la llamada de la configuración ni del historial del usuario, y `--use_antigravity` queda rechazado allí mientras no esté medido. macOS pasa, sin haber sido medido; la protección de facturación, que lee la configuración efectiva, se mantiene allí.

  - **`exit 0` no demuestra nada, cuarta CLI.** Solo se acepta una respuesta con un código de salida cero, un objeto JSON con el estado `SUCCESS`, un registro conforme, sin acciones rechazadas, ni comandos, ni errores en el JSON, ninguna advertencia de truncamiento en stderr y un texto no vacío. `--print-timeout` nunca se utiliza: al expirar, agy devuelve la salida parcial en `SUCCESS`, código 0; el tiempo de espera es externo y mata el grupo de procesos. Un segmento que comience por `/commande`, `!commande` o `@fichier` se traduce, nunca se ejecuta ni se resuelve —sin `--disable-slash-commands`, «/help» se ejecutaba en lugar de la traducción—. Un segmento en blanco ya no llega a agy, ya que la canalización lo devuelve tal cual (véase más abajo), y sigue rechazándose antes de la llamada como última red de seguridad: ante una entrada vacía, agy abre su interfaz interactiva con un código 0. El reintento sigue el campo `retryable` de la línea `AGY_ERROR` que agy escribe en stderr desde su versión 1.2.6: él mismo ya reintenta los errores transitorios —502, 503, 504, límite por minuto—, y es él quien sabe si el fallo restante sigue siéndolo. A falta de este campo, no hay reintento cuando el mensaje habla de agotamiento —en Google, `RESOURCE_EXHAUSTED` lleva el mismo código 429 que un límite por minuto, pero una ventana de 5 horas agotada no se restablece en 90 segundos—, y de lo contrario solo ante limitación de tasa. La respuesta conserva el final de línea del segmento: agy siempre termina la suya con un salto de línea, que, en la unión, partía en dos un párrafo dividido a mitad de frase. Una sesión desconectada produce un mensaje que indica ejecutar `agy` para volver a conectarse. Por último, `AGY_CLI_DISABLE_AUTO_UPDATE=true` evita que un HOME nuevo lance en cada llamada un comprobador de actualizaciones en su propia sesión, fuera del alcance del tiempo límite —el valor `1`, por su parte, no tiene efecto—.

  - **Modelos: el esfuerzo de razonamiento forma parte del nombre.** Los identificadores son los de `agy models` — `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… Un nombre base solo, que agy rechazaría, se rechaza antes de la llamada, indicando los sufijos existentes: `-medium` o `-low` para un Flash, `-high` o `-low` para un Pro. Por defecto `gemini-3.8-flash-medium`, y `gemini-3.7-flash-low` en `--eco`, fijados por las campañas descritas a continuación. `--reasoning_effort` no tiene efecto y así lo indica. Claude y GPT-OSS consumen de una cuota distinta y mucho menor —alrededor del 1 % de la ventana de 5 horas por llamada medida, frente al 0,05 % en Flash— y una advertencia lo recuerda. La cuota restante se consulta gratuitamente mediante `agy -p /usage`. Rechazado en CI, al igual que Codex y Grok CLI: la conexión reside en un llavero personal, y el mensaje propone `--use_gemini` con una clave de Google.

  - **Dos campañas el 26 de septiembre: los valores predeterminados se miden, no se suponen.** Mediante el propio `aipmt --use_antigravity`, cuatro traducciones en paralelo, cada una comparada con su fuente mediante `scripts/compare_structure.py`, con la cuota leída por `agy -p /usage` antes y después. Por la mañana, sobre la revisión de este README publicada con la 1.14.0 y sobre el denso artículo de vigilancia de las mediciones del README, en `--news`, `gemini-3.7-flash-medium` escribe los catorce idiomas de ambos documentos: el artículo sin ninguna discrepancia, 3 min 14 s por idioma de mediana, y el README a falta de una sola palabra en negrita, en coreano, en 1 min 22 s. Por la tarde, a petición del autor, Gemini 3.8 Flash frente a 3.7 en un mismo lote, este README y este CHANGELOG en su versión 1.15.0: con esfuerzo medio, misma estructura para ambos; 3.8 razona tanto como 3.7 —63 % de los tokens de salida frente al 60 %, leídos en el JSON de agy— y cuesta un séptimo más de cuota, por un cuarto más de tiempo. Luego la campaña de la mañana, repetida en `gemini-3.8-flash-medium`: catorce idiomas de catorce sin discrepancias en el artículo, 3 min 59 s de mediana, al igual que en el README, 1 min 43 s; los enlaces internos intactos en los catorce README, donde 3.7 rompía algunos en italiano; y en inglés, las líneas de traducción francesa eliminadas por el modelo, sin banderas inventadas, citas en inglés intactas. De ahí los valores predeterminados: `gemini-3.8-flash-medium`, y `gemini-3.7-flash-low` en `--eco`. Con esfuerzo bajo, ninguno de los dos Flash razona y cada uno cuesta la mitad, pero 3.8 low duplicó en hindi los tres enlaces internos de un README, cosa que 3.7 low no hizo en ninguna de las traducciones que escribió. Coste medido en el nivel de la cuenta del autor: de 13 a 16 puntos de la ventana de 5 horas por millón de caracteres fuente en `gemini-3.8-flash-medium` —la campaña repetida, 28 traducciones y 1,8 millones de caracteres, consumió 24,5, y 4,1 de la semana—.

  - **Los términos de uso y el tratamiento de datos, explicados sin rodeos.** Las condiciones de Antigravity (sección 6) y sus preguntas frecuentes prohíben acceder al servicio mediante software de terceros utilizando la conexión de Antigravity —Claude Code, OpenClaw y OpenCode se mencionan allí—, bajo pena de suspensión de la cuenta. aipmt nunca lee ni reutiliza el token: ejecuta el binario oficial en el modo headless que Google documenta para scripts y CI, y un miembro de Google consideró «estándar», en el foro oficial, ejecutar `agy -p` desde un script local para su propio trabajo —una respuesta, no un compromiso—. Ningún texto resuelve el caso de una herramienta distribuida: el README indica que el usuario compromete su propia cuenta. La sección 5 de esas mismas condiciones permite a Google utilizar las interacciones —prompts, respuestas, metadatos— para mejorar sus productos y su aprendizaje automático, y someterlos a revisión humana, sin distinguir entre la oferta gratuita y Pro o Ultra: el README reserva esta vía para documentos públicos, y su advertencia final así lo menciona.

  - **Las traducciones de este repositorio pueden pasar por esta vía, sin excepción.** `REGEN_PROVIDER=antigravity` es una suscripción, no una API facturada: pasa sin `REGEN_ALLOW_PAID_API`, con cuatro trabajos —toda la campaña se ejecutó con cuatro en paralelo, sin un solo error— y el límite de 1 800 segundos por trabajo de Codex, que las mediciones justifican: el CHANGELOG completo en hindi, el archivo donde Codex pierde marcadores de posición, se tradujo sin discrepancias en 4 min 33 s con 3.7 Flash en su versión 1.14.1, y en 5 min 50 s con 3.8 Flash en su versión 1.15.0, un quinto más larga: al menos cinco veces por debajo del límite. Una regeneración completa, 2,2 millones de caracteres, representa entre 30 y 36 puntos de la ventana de 5 horas en `gemini-3.8-flash-medium`. Un control único, el preflight del módulo, precede a los 28 trabajos: un agy desconectado o configurado para facturar no inicia ninguno. El valor predeterminado sigue siendo Codex con `gpt-5.6-sol`.

  - **Un enlace interno se rompía sin que nada lo detectara.** El token que protege un ancla absorbe sus paréntesis: el modelo recibe un enlace con apariencia rota, corchetes seguidos del token sin envolver, y a veces se le ocurre «repararlo». La restauración devuelve entonces `[texte]((#ancre))`, que no lleva a ninguna parte, sin que ninguna protección ni `compare_structure.py` lo señale. Ocurrió en dos README de la primera regeneración de esta versión, y con todos los modelos probados, más a menudo cuando el enlace está entre paréntesis —el caso de un enlace que esta versión acababa de añadir a este README—. La comprobación de publicación ahora cuenta los enlaces internos intactos de cada traducción, y este README ya no coloca ninguno entre paréntesis; la corrección del propio token queda pendiente.

  - **Ctrl-C y el cierre del terminal ahora detienen el agente, para las cuatro CLI.** Codex, Grok CLI, OpenCode y Antigravity se ejecutan en su propia sesión, fuera del grupo de primer plano: el `SIGINT` de un Ctrl-C no los alcanza, y, ante Ctrl-C, `Popen` solo los espera un cuarto de segundo antes de devolver el control. Comprobado en la revisión con un binario falso: el agente sobrevivía a aipmt y terminaba su turno consumiendo cuota, para un resultado descartado —cuatro a la vez durante el regen—. Un `KeyboardInterrupt` o un `SystemExit` durante la llamada ahora mata el grupo del agente antes de propagarse. El cierre del terminal o la desconexión de una sesión SSH (`SIGHUP`) mataba a Python sin ninguna limpieza: el agente continuaba y el directorio privado de Antigravity permanecía en el disco con su registro, que contiene la dirección de la cuenta. `SIGHUP` sigue ahora el camino de `SIGTERM`: grupo del agente terminado y luego salida con código 129. Un `SIGHUP` ignorado, por haberse iniciado bajo `nohup`, sigue estándolo: es elección del usuario. El preflight de Antigravity —`agy --version`, luego `agy -p /config`— pasa por el mismo manejador: una señal recibida durante este control detiene agy y también elimina el directorio privado, en lugar de dejarlo en el disco con su registro.

  - **El controlador de subprocesos ya no puede apuntar a toda la sesión.** En Linux, `killpg(1, sig)` equivale a `kill(-1, sig)`: la señal se envía a todos los procesos del usuario. Esto ocurrió durante la escritura de esta versión, a través de una campaña de mutaciones: un mutante llamaba a un `Popen` simulado con un `MagicMock` desnudo, el error resultante pasaba por la nueva ruta de interrupción, y el pid del proceso falso, que Python convierte en 1, provocó la terminación de toda la sesión gráfica. `_codex_kill_group`, común a las cuatro CLI, ahora solo apunta a un grupo si el pid es un entero real mayor que 1, `getpgid` devuelve ese mismo pid —un agente iniciado en su propia sesión es líder de su grupo— y no es el grupo del proceso actual; de lo contrario, solo se apunta al hijo directo. En producción, esta salvaguarda no cambia nada: cierra el caso en el que un error propagara otra cosa. Los dobles de prueba de `Popen` que no deben usarse ahora fallan de inmediato, los procesos simulados llevan un pid imposible y las campañas de mutaciones se ejecutan en un espacio de nombres PID.

  - **Un segmento en blanco ya no hace fallar el archivo, independientemente del proveedor.** `segment_text` puede aislar el final en blanco de un documento: 16 001 caracteres terminados en tres saltos de línea producen un segundo segmento formado por dos saltos de línea. Antigravity lo rechazaba antes de la llamada —reproducido durante la revisión— y, en un proveedor de API, una respuesta vacía caía bajo la protección de contenido vacío: en ambos casos, fallaba el archivo completo, después de que se hubiera consumido la cuota de los segmentos anteriores. A partir de ahora, un segmento en blanco se devuelve tal cual, sin llamada.

  - **Seguridad: un `.env` de proyecto ya no puede elegir el binario ejecutado.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN` y `AGY_BIN` designan el programa que la traducción ejecuta, con los permisos del usuario: definidos por el `.env` de un repositorio recién clonado, hacían que se ejecutara un archivo de dicho repositorio desde la primera traducción. Por tanto, el sufijo `_BIN` se une a `_BASE_URL`, `_API_BASE` y `_ENDPOINT` en el filtro de la capa de proyecto, junto con `GROK_HOME`, bajo el cual se busca el binario de Grok (`$GROK_HOME/bin/grok`). Estas variables siguen aceptándose desde el entorno y desde `~/.config/aipmt/.env`, y cada rechazo se indica en stderr junto con el lugar donde configurarlas.

  - **Pruebas**: nuevo archivo `tests/test_antigravity_provider.py` (103 pruebas), que cubre el 100 % de las instrucciones y ramas del módulo —argv exacto y nunca `-p`, segmento por stdin, agente escrito sin herramientas ni herencia, entorno reducido a la lista de permitidos, directorio privado eliminado tras un éxito, un fallo, un tiempo de espera o una señal, contrato de salida completo, repliegue de agente y vía de facturación leídos en líneas de registro en formato real, `AGY_ERROR` y `retryable`, preflight de facturación estricto, rechazo en Windows y sin bus de sesión, sufijos de esfuerzo, fin de línea recuperado del segmento, cableado del dispatch y rama del regen. Ninguna prueba ejecuta agy: un binario falso colocado al principio del `PATH` no fue invocado en ninguna pasada, incluso en las condiciones de CI, con bus de sesión oculto y `CI=true`. `tests/test_provider_base.py` interrumpe un subproceso real mediante Ctrl-C y mediante `SIGHUP`, incluido bajo `nohup`, y asegura la protección del `killpg` —pid `MagicMock`, booleano, 1 o menor, grupo actual o grupo de otro: nunca una señal de grupo—; `tests/test_key_resolution.py` inicia un proceso nuevo para cada variable `_BIN`; `tests/test_orchestration.py` traduce un documento cuyo final en blanco forma un segmento aparte. Suite completa con **650 pruebas**.

  - **Un fallo de escritura ya no deja una traducción truncada en el disco.** `open(cible, "w")` trunca el archivo antes de llenarlo: un error durante la escritura —disco lleno— dejaba en él un destino parcial. Reproducido: ocho bytes escritos, estado `failure` devuelto, y luego la siguiente ejecución encontraba este archivo, respondía `skipped` y lo conservaba. Un fallo se convertía en una traducción truncada que ya nada señalaba, y el código de salida era 0. El contenido ahora se escribe en un archivo temporal del mismo directorio —`os.replace` solo es atómico dentro de un mismo sistema de archivos— y luego se renombra; el temporal se elimina si la escritura falla, incluso por interrupción. Este temporal proviene de `mkstemp`, y una revisión demostró que un nombre predecible solo habría desplazado el problema: un enlace simbólico colocado en `cible.md.aipmt-tmp` hacía que la traducción se escribiera en el archivo de destino, fuera del directorio de salida, devolviendo `success`; y dos ejecuciones simultáneas sobre el mismo destino compartían ese nombre, renombrando la segunda mientras la primera aún escribía en el mismo inodo —destino reportado como exitoso, contenido mezclado (`BBBAAAAA` en lugar de `BBBBBBBB`, medido). `mkstemp` crea en `O_CREAT | O_EXCL` bajo un nombre único, lo que resuelve ambos problemas. Los permisos del destino existente se recuperan explícitamente antes del reemplazo: `mkstemp` crea en 0600, y un destino deliberadamente en 0600 pasaba de lo contrario a 0664, mientras que un destino en 0644 servido por un servidor web se habría vuelto ilegible. Ocho pruebas blindan el conjunto y dos mutaciones del código las hacen ponerse en rojo.

  - **El manifiesto de pureza admite declarar un marcador de supresión reescrito.** El control exigía que cada línea con un `# nosec`, `# nosemgrep` o `NOSONAR` de la referencia sobreviviera palabra por palabra. Ahora bien, mover una escritura a un temporal renombra la variable abierta: la supresión de Sonar es la misma, pero su línea cambia. La categoría `markers` del manifiesto declara este par `old` → `new` junto con su motivo. Dos condiciones, y la segunda proviene de una revisión: el sustituto debe existir **y llevar las mismas supresiones que la línea original**. Sin ella, declarar `value = 1  # NOSONAR` → `value = 1` pasaba en verde, de modo que una declaración bastaba para retirar un marcador —exactamente lo que este control existe para impedir. Una desaparición no declarada sigue siendo rechazada.

[OpenRouter](https://openrouter.ai) da acceso con una sola clave a modelos que ningún otro proveedor expone aquí —Kimi, Qwen, DeepSeek, Z.ai— sobre un crédito único facturado por uso. Dado que el endpoint es compatible con OpenAI, el cliente es el mismo que para xAI; **todo lo que distingue a este proveedor reside en un preflight**, y cada una de sus reglas proviene de una medición en la API.

  - **Un mismo modelo es servido por decenas de proveedores de alojamiento con límites diferentes, y el enrutamiento es ciego a ello.** Medido: 33 proveedores de alojamiento para `z-ai/glm-5.2`, 23 para `z-ai/glm-5.3-flash` —incluido uno limitado a **2 048 tokens de salida**. Por lo tanto, una de cada 23 traducciones largas salía truncada, al azar, sin la menor señal. El preflight lee `/api/v1/models/{modèle}/endpoints`, descarta los proveedores de alojamiento por debajo de 8 000 tokens de salida, aquellos con estado degradado y los que no declaran ningún límite, y luego fija los demás. `provider.only` **sin** `allow_fallbacks: false` no es más que una preferencia: el router vuelve a dirigirse hacia un proveedor de alojamiento descartado y la fijación deja de servir. Si ningún proveedor de alojamiento mantiene el límite, el comando se detiene: traducir de todos modos equivaldría a aceptar el truncamiento silencioso que este preflight existe para evitar.

  - **El razonamiento se factura a la tarifa de salida y está activo por defecto en muchos modelos.** Misma petición en `z-ai/glm-5.2`, respuesta «OK»: **107 tokens de completado por defecto del modelo, 2 con el razonamiento desactivado**. En una traducción, a la que el razonamiento no aporta nada, esto supone un factor de 18 en cada segmento de cada archivo. Por lo tanto, se desactiva por defecto. Los **288 modelos de 431** que lo imponen (`reasoning.mandatory`) responden `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: para ellos, el preflight lee los esfuerzos aceptados y solicita el más bajo (siguiente punto); el esfuerzo asigna un **porcentaje de `max_tokens`** que el razonamiento consume primero, de modo que un valor elegido al azar desplaza el riesgo de una página en blanco en lugar de reducirlo.

  - **Un modelo que impone el razonamiento recibe el menor esfuerzo que acepte, y fue una medición la que lo decidió.** La primera opción era no enviar nada, para no suponer en lugar del modelo. Probada en `z-ai/glm-5.3-flash`, cuyo valor por defecto en el catálogo es `max`, esta opción producía una salida **truncada a 32 768 tokens** antes del final de la traducción —dos idiomas de catorce perdidos. Aumentar el límite no habría cambiado nada: el esfuerzo asigna un porcentaje de él, el razonamiento crece con él. Por tanto, el proveedor lee `supported_efforts` en el preflight y solicita el más bajo, recurriendo a «nada» cuando el catálogo no anuncia ninguno aprovechable. Contraprueba en el idioma fallido: antes fallaba por agotar el presupuesto, ahora se completa en 9 minutos con una estructura idéntica a la fuente.

  - **Una avería del proveedor de alojamiento ascendente ahora lleva su nombre.** El router normaliza este caso en `finish_reason=error` con un `native_finish_reason` nulo —medido dos veces, en dos idiomas, exactamente a los 750 segundos. El mensaje genérico remitía a buscar un fallo en el documento o en la división; ahora indica que la avería proviene del proveedor y que reintentar suele bastar.

  - **`finish_reason=length` con una salida vacía no es un truncamiento.** Es el presupuesto consumido por el razonamiento antes del primer carácter útil —medido en 15 850 tokens de razonamiento frente a 148 útiles. Ambos casos requieren acciones opuestas: reducir el tamaño de los segmentos no sirve de nada en el primero. El mensaje los distingue explícitamente. Otras dos protecciones provienen de mediciones: el router responde **200 con un cuerpo que solo contiene un error** cuando el proveedor de alojamiento ascendente falla (`choices[0]` generaba un `TypeError` opaco que ocultaba el mensaje), y la ventana de contexto se lee del catálogo y luego se inscribe en `MODEL_TOKEN_LIMITS` —`DEFAULT_TOKEN_LIMIT` es falso para 44 modelos del catálogo, incluidos dos con un tope de 4 095 tokens.

  - **`--model fournisseur/modèle` es obligatorio y su formato se valida antes de cualquier operación de red.** OpenRouter no es un proveedor: la elección compromete el precio, la licencia y el tratamiento de los datos, no se toma en lugar del usuario. Dado que el slug se interpola en la URL del preflight, la validación no es una mera cortesía de ergonomía, sino la protección que impide inyectar una ruta en ella: la regex con espacio de nombres común a ambos routers acepta `a/b/..`, de ahí el rechazo explícito del segmento padre. `--eco` no tiene efecto y así lo indica.

  - **Tres formulaciones corregidas, incluida una errónea.** La advertencia de OpenAI sobre `codex exec` apuntaba a la inyección de un archivo de sesión personal en un runner compartido, no al carácter público del repositorio: se citaba en sentido inverso en el README, en CLAUDE.md y en el código. La ubicación de autenticación de OpenCode cambió en 1.18.27 (tabla `credential` de `opencode.db`, en lugar de `auth.json`); el invariante «nunca leída aquí» seguía siendo válido, pero la dirección estaba obsoleta. Por último, la sección de OpenCode ya no presenta como equivalentes vías que nunca se han probado: la pasarela Zen y Ollama se midieron de extremo a extremo; GitHub Copilot, LM Studio y llama.cpp no lo fueron, y el README ahora lo indica.

  - **Una campaña de mediciones y una tabla de modelos recomendados en el README.** Más de trescientas traducciones ejecutadas sobre tres conjuntos de documentos —un artículo de blog denso en modo `--news`, este README en Markdown estándar y cuatro README de proyectos conocidos tomados tal cual de GitHub— hacia catorce idiomas. La tabla distingue dos aspectos que se solían confundir: las traducciones que **terminan con éxito** y aquellas cuya **estructura es idéntica** a la fuente. Tres modelos nunca perdieron la menor información en los dos documentos densos: `gemini-3.7-flash`, `gpt-5.6-sol` con la suscripción a ChatGPT y `z-ai/glm-5.2` a través de OpenRouter —sus únicas discrepancias son un par de `**` no trasladados en uno o dos idiomas. La conclusión principal es que **el factor determinante es la densidad del documento, no el modo `--news`**: Grok por suscripción falla trece de cada catorce veces en el artículo de blog y tiene éxito en catorce de dieciséis README públicos, siendo la causa una desconexión en segmentos largos verificada mediante contraprueba. La tabla incluye su propia advertencia: no es exhaustiva, tiene fecha, las duraciones no establecen ninguna clasificación y el enfoque correcto sigue siendo medir sobre los propios documentos.

  - **El comparador de estructuras se corrigió antes de publicar sus cifras, porque producía dos falsos positivos en escrituras no latinas.** Una URL seguida de un paréntesis de ancho completo `）` no era truncada por una regex que se detiene en `)`, y la cadena extraída difería a pesar de que la URL era idéntica; una cita de cinco líneas en francés que ocupaba tres líneas en chino hacía caer el conteo por líneas. Ambas correcciones fueron validadas mediante contraprueba: la eliminación de una URL, una sección o un código en línea sigue detectándose. Sin ellas, Gemini y Codex se habrían publicado con once idiomas de catorce en lugar de trece y doce.

  - **Pruebas**: nuevo archivo `tests/test_openrouter_provider.py` (76 pruebas) —validación del modelo y rechazo del segmento padre, fijación de proveedores de alojamiento (límite, estado, límite no declarado, mínimo común), `allow_fallbacks` siempre falso, razonamiento desactivado o mantenido según `mandatory`, contrato de salida completo (error en un 200, ninguna opción, página en blanco diferenciada del truncamiento, `finish_reason` anómalo, contenido nulo), preflight fail-closed ante catálogo inaccesible, slug ausente y ausencia de proveedor de alojamiento en buen estado, exclusividad del flag y etiqueta de nombre de archivo. Suite completa con **502 pruebas**.

  - **Refactorización: el módulo único de 4 253 líneas se divide en módulos, sin alterar una sola línea de comportamiento.** `src/aipmt/translate.py` se distribuye en `config`, `markdown`, `segmentation`, `guards`, `placeholders`, `news`, `prompts`, `notes`, `naming`, `pipeline`, `cli` y un subpaquete `providers/` (un módulo por proveedor, `base` como base, `registry` para la resolución y el despacho). Cada traslado es un commit cuya prueba es mecánica: un verificador compara el AST de todos los nodos de primer nivel del paquete con una instantánea de referencia, comprueba la ubicación de cada símbolo, la conservación exacta de los marcadores de seguridad y la ausencia de archivos sin seguimiento —herramientas temporales, eliminadas en la siguiente versión. Lo que cambia y resulta visible: `aipmt.translate` se convierte en una fachada que reexpone, por identidad de objeto, los 64 nombres que el módulo exponía sin el prefijo `_` (`__all__` contiene nueve, la API admitida; los demás son alias de compatibilidad), y deja de reexportar los 29 nombres de dependencias y de la biblioteca estándar que recopilaba un `import *`; la ejecución directa del archivo (`python src/aipmt/translate.py`) ya no existe —`aipmt` y `python -m aipmt` siguen siendo las dos formas compatibles; el `__module__` de las funciones públicas corresponde al de su módulo de definición; los SDK se importan tras la carga de `.env` y ya no antes, sin consecuencias conocidas. Las 427 pruebas se conservan con su identificador exacto y se migran hacia los módulos que ejercitan: 91 parches que pasaban por la fachada ahora apuntan al módulo que consulta el nombre (dos de ellos seguían dando verde sin su parche, comprobado mediante mediciones), siete pruebas de contrato blindan la fachada, y las herramientas de los gates se reescribieron ANTES del primer traslado para que ninguno pudiera pasar a verde dejando de verificar —alcance de Lizard en directorios con umbral mínimo, flags leídos desde el parser construido, umbral mínimo de cobertura por paquete, `release.sh` que enumera los módulos monitorizados.
  - **Corrección (revisión de la pull request)**: OpenRouter rechaza una ficha de catálogo sin `context_length` en lugar de registrar el valor por defecto de 128 000 tokens como una medición —lo que también desactivaba la advertencia «modelo no listado»— y, cuando `finish_reason` es nulo (tipo documentado `string | null`), prevalece el motivo en bruto del proveedor de alojamiento, equivaliendo `max_tokens` a `length`; un error contenido en la propia opción rechaza el contenido parcial que lo acompaña, con el mismo mensaje que la avería ascendente normalizada —detalle del proveedor de alojamiento, motivo en bruto y recomendación combinados. OpenCode responde con su error de contrato, y no con un `AttributeError`, ante un evento `part: null`, y rechaza un flujo JSONL si alguna línea de evento resulta ilegible en vez de aceptar texto parcial. Las tres CLI agénticas terminan el grupo del agente cuando este proceso recibe `SIGTERM` durante la llamada —el `timeout` del regen permitía que el agente sobreviviera y consumiera su cuota— y el `SIGKILL` del grupo siempre respeta el período de gracia, ya que un shim que termina de forma limpia dejaba con vida a su proceso nieto. Se vuelve a unir un par `# fmt: off` / `# fmt: on` dividido por la partición; la ayuda de `--reasoning_effort` nombra a los cuatro proveedores que lo utilizan.
  - **Corrección (segunda revisión)**: el límite de salida solicitado a OpenRouter ahora reserva la porción del contexto que ocupan el prompt y el segmento —`context_length` cubre la entrada Y el completado, y seis modelos del catálogo veían enviarse su solicitud sin espacio para la entrada; un contexto demasiado corto se rechaza antes de cualquier facturación. La base de las CLI agénticas recurre a `terminate` y luego a `kill` donde no existen grupos de procesos POSIX, en lugar de permitir que una `AttributeError` atraviese la protección de timeout y la espera se prolonge. El marcador `429` de OpenCode se busca como un número y ya no como subcadena, donde un identificador de error como `err_84290b` provocaba 90 segundos de back-off antes de fallar de todos modos. Por último, se muestra un endpoint no canónico de OpenRouter en el preflight: un `.env` de proyecto basta para definir uno, y sería la clave real la que se enviaría a continuación.
  - **Seguridad: un `.env` de proyecto ya no puede redirigir las llamadas a la API.** `find_dotenv(usecwd=True)` busca el archivo desde el directorio actual y sus padres: un árbol no confiable —un repositorio recién clonado— podía colocar allí `OPENROUTER_BASE_URL`, `XAI_BASE_URL` o `OPENAI_BASE_URL` (esta última leída por el propio SDK) sin conocer ninguna clave, y la clave real, procedente del entorno o de la configuración del usuario, se enviaba luego en la cabecera de autorización a un servidor de terceros. El filtro se basa en un PATRÓN y no en una lista: según lo comprobado en los SDK instalados, se leen doce variables de enrutamiento, seis de ellas solo por el cliente de Anthropic —una enumeración escrita a mano habría omitido la mitad. Por lo tanto, se rechazan de la capa de proyecto cualquier variable en `_BASE_URL`, `_API_BASE` o `_ENDPOINT`, los proxies y los almacenes de certificados (apuntar a una autoridad controlada hace que un interceptor sea indistinguible de un servidor real), así como `XDG_CONFIG_HOME` y `APPDATA`: definirlas equivalía a decidir qué archivo constituye la capa de usuario, eludiendo así el filtro de forma indirecta. Estas variables solo se aceptan desde las dos capas que el usuario controla: el entorno exportado y `~/.config/aipmt/.env`. Además, la capa de proyecto se lee SIN interpolación: `load_dotenv` expande `${VAR}` por defecto, y un `.env` no confiable que contuviera `NOM_ANODIN=${OPENAI_API_KEY}` copiaba la clave real bajo un nombre que el filtrado por patrón de los subprocesos no reconoce —ingresando así en el entorno de `codex exec`, en contra del invariante anunciado. Por último, el rechazo solo muestra el nombre de la variable: una URL de la forma `https://${CLE}@hôte/` filtraba la clave interpolada en los registros, aun cuando se rechazaba. El rechazo se notifica en stderr junto con los pasos a seguir —un repetidor corporativo se declara en la configuración de usuario.
  - **Corrección: el límite de salida de OpenRouter se calcula para cada llamada.** `context_length` cubre la entrada Y el completado, y una reserva fija calibrada sobre texto latino no acota nada: medido con el tokenizador `o200k_base`, 16 000 caracteres equivalen a 3 200 tokens en francés, pero a 12 300 en japonés y 17 500 en emojis. El presupuesto procede, por tanto, del texto realmente enviado, acotado superiormente por su número de bytes UTF-8: en cualquier tokenizador de fusión de bytes —BPE a nivel de byte, SentencePiece con retroceso a byte, las familias que utiliza el catálogo—, un token equivale al menos a un byte, y es la única cota superior disponible aquí, donde OpenRouter enruta hacia decenas de tokenizadores desconocidos. Ninguna proporción media resultaba adecuada —un ideograma del plano suplementario desciende a 1,33 bytes por token, un carácter combinable a 1,00—, y ahora la entrada más la salida caben en la ventana por diseño. Un segmento demasiado denso para el modelo seleccionado se rechaza antes de la llamada en lugar de hacerlo después de la facturación.

- **1.12.0** Proveedor `--use_opencode`: OpenCode, el agente de código abierto, hacia el proveedor que elijas — modelo local, gratuito sin cuenta, suscripción o clave (2026-09-04):
  - **Octava vía de proveedor, de una naturaleza distinta a las siete primeras.** [OpenCode](https://opencode.ai) (MIT) no es un proveedor de modelos sino un _enrutador_ hacia aquellos que el usuario ha configurado en el propio OpenCode: una clave de API, una suscripción (GitHub Copilot, ChatGPT, SuperGrok), la pasarela OpenCode Zen —que sirve modelos gratuitos **sin cuenta**—, o un modelo **local** (Ollama, LM Studio, llama.cpp). El script controla `opencode run` en modo no interactivo, tal como controla Codex y Grok, y reutiliza la misma base de subprocesos (grupo de procesos propio, `SIGTERM` y luego `SIGKILL` en caso de timeout, stdin siempre cerrado, entorno depurado). Verificado mediante **dos traducciones reales**: este README completo en inglés a través de `opencode/mimo-v2.5-free` —49 s, una sola pasada, estructura idéntica a la del archivo fuente (32 encabezados, 26 cierres de código, 18 enlaces, 37 URL, 37 filas de tabla, 135 códigos inline)— y un archivo de prueba mediante `ollama/qwen2.5:7b`, en local, sin ninguna clave.

  - **`--model provider/modèle` es obligatorio, y es una elección deliberada.** Sin `--model`, OpenCode recurre a su propio valor predeterminado, que en una instalación limpia es `opencode/big-pickle`, un modelo gratuito «stealth» cuyos intercambios pueden utilizarse para entrenamiento —medido empíricamente, fue este modelo el que respondió. Elegir esto silenciosamente en lugar del usuario sería exactamente el tipo de alternancia invisible que este repositorio rastrea; por tanto, el mensaje de error indica el comando que lista los modelos (`opencode models`) y tres ejemplos (local, gratuito, suscripción). `--eco` no tiene efecto y así lo indica. `--reasoning_effort` se transmite tal cual como `--variant` de OpenCode, solo bajo petición explícita.

  - **Aislamiento medido, no supuesto.** Una configuración inline (`OPENCODE_CONFIG_CONTENT`, última en el orden de fusión de OpenCode, por lo que tiene prioridad sobre la del usuario sin reemplazarla) define un agente `aipmt` cuyas herramientas quedan todas denegadas (`permission: {"*": "deny"}`): el registro ya ni siquiera se las propone al modelo, el cual, al pedírsele «listar los archivos y ejecutar `id`», responde que no tiene herramientas. Compartición de sesiones desactivada, plugins externos descartados (`--pure`), nunca `--auto`, directorio de trabajo desechable y vacío. Se midieron y cortaron dos inyecciones silenciosas: sin `OPENCODE_DISABLE_CLAUDE_CODE`, el `~/.claude/CLAUDE.md` del usuario entra en **cada** prompt (515 tokens de entrada en lugar de 186 para un simple «Hola»); sin `OPENCODE_DISABLE_PROJECT_CONFIG`, el `AGENTS.md` del directorio actual también —una instrucción de «terminar cada respuesta con BANANA» se aplicó a la traducción. El `~/.config/opencode/AGENTS.md` global, por su parte, sigue inyectándose: ningún interruptor lo descarta, y eludirlo mediante un `XDG_CONFIG_HOME` desviado también ocultaría los proveedores del usuario. Documentado en lugar de recurrir a parches improvisados.

  - **`exit 0` no demuestra nada, tercera CLI, mismos reflejos —con dos trampas propias de esta.** Un `--agent` desconocido no hace fallar `opencode run`: advertencia en stderr y repliegue **silencioso** hacia el agente de programación, con herramientas activas. Si la configuración inline no se tuviera en cuenta, la traducción se ejecutaría con un agente capaz de escribir; por tanto, el contrato de salida verifica la ausencia de este mensaje, además de: código de retorno 0, ningún evento `error`, ningún `tool_use`, último `step_finish` en `stop` (un `length` es una respuesta truncada), texto no vacío. Segunda trampa: el evento JSON de error es **opaco** —«Unexpected server error. Check server logs for details.», con una simple referencia— y la causa real (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) solo reside en los registros. De ahí `--print-logs --log-level ERROR` y la lectura del campo `error="…"` de stderr, sin la traza de Bun que le sigue. Así, un modelo desconocido falla en un segundo, con su causa identificada. `--title` evita además una llamada a LLM parásita: sin él, OpenCode genera un título de sesión mediante una ronda adicional sobre el `small_model`.

  - **Secretos: mismo filtrado por patrones que Codex y Grok, salvo una excepción nominal.** `OPENCODE_API_KEY` se conserva: es la clave del propio OpenCode (pasarela Zen, suscripción Go), dirigida a él por su nombre —el equivalente a su `auth.json`, no una clave que aipmt gestione ni pueda facturar. Los proveedores se configuran en OpenCode (`opencode auth login`, `opencode.json`), nunca en el `.env` de aipmt, del cual ninguna clave llega al subproceso. Sin denegación en CI, a diferencia de las CLI por suscripción: una clave de API o un modelo autoalojado en un runner son usos legítimos.

  - **La protección contra recorrido de rutas ahora controla el valor interpolado, no el valor en bruto.** `provider/modèle` contiene un `/` que la protección de la versión 1.10.0 rechazaba —con razón, ya que `--model` se interpola en el nombre del archivo `--include_model`. La etiqueta de nombre de archivo ahora reemplaza `/`, `\` y `:` por `-` antes de cualquier interpolación (`ollama/qwen2.5:7b` → `ollama-qwen2.5-7b`, siendo `:` ilegal en Windows), y la protección previa examina esta etiqueta: `../../evil` se convierte en el simple nombre `doc-en-..-..-evil.md` bajo el destino, `..` por sí solo sigue siendo rechazado, al igual que `--target_lang ../x`. La protección de perímetro `_ensure_within_directory` permanece como segunda capa, sin cambios.

  - **Modelos gratuitos y modelos locales: lo que se midió.** `opencode/mimo-v2.5-free` traduce un párrafo en 16 s y este README en 49 s; `opencode/big-pickle` tarda 40 s para 200 palabras, y dos peticiones simultáneas permanecieron sin respuesta durante 5 minutos, cuando cada una por separado se completa con éxito; `opencode/nemotron-3.5-lightning-free` no respondió nada en 3 minutos. De ahí `REGEN_PROVIDER=opencode` con `REGEN_MODEL` obligatorio y **2 trabajos** en paralelo. En el ámbito local, Ollama suele configurar 4096 tokens de contexto cuando los segmentos alcanzan hasta 16 000 caracteres: se impone un `Modelfile` con `PARAMETER num_ctx 32768`, y la calidad depende del modelo —un modelo de 7B invirtió una lista y dañó un cierre de bloque de código en el archivo de prueba, mientras que el modelo de la pasarela lo conservó todo.

  - **Las traducciones de este repositorio ya no pasan nunca por una API de pago.** `regen_translations.sh` seleccionaba la API de OpenAI en cuanto había una clave presente en `.env`, y dejaba a Codex solo como una opción opt-in. Esto es exactamente lo que ocurrió al preparar esta versión: las 28 traducciones se enviaron a la API de OpenAI, y luego el CHANGELOG en hindi a la de Gemini, cuando la suscripción a ChatGPT existe precisamente para evitar pagar por uso. La detección automática de claves desaparece: **Codex es la opción predeterminada, con `gpt-5.6-sol`**, el modelo de calidad; `openai`, `gemini` y `grok` exigen `REGEN_ALLOW_PAID_API=1` además de `REGEN_PROVIDER`, una excepción explícita para que la regla actúe en el momento de la decisión; un `REGEN_PROVIDER` desconocido falla en lugar de recurrir a la API. Diez pruebas blindan el valor predeterminado, el rechazo y la excepción. Las 28 traducciones de esta versión se rehicieron a través de Codex.

  - **El back-off por límite de tasa se factoriza** (`_retry_on_rate_limit`): los bucles de Codex y Grok eran idénticos salvo por sus mensajes descriptivos, y una tercera copia habría superado el umbral de duplicación. Los tres errores de CLI derivan de una misma clase `_CliCallError`; una prueba prohíbe que alguno de los tres deje de heredar de ella, ya que de lo contrario el bucle compartido dejaría de detectarlo.

  - **Pruebas**: nuevo archivo `tests/test_opencode_provider.py` (61 pruebas) — contrato de salida completo, repliegue de agente, causa leída en los registros, partes de texto desduplicadas y partes sintéticas ignoradas, timeout terminando el grupo de procesos, back-off ante errores 429, modelo obligatorio y validado, preflight sin secretos, resolución del binario, cableado del dispatch, etiquetado del nombre de archivo y contraprueba de recorrido de rutas. `tests/test_review_hardening.py` extiende la exclusividad de los flags y la ausencia de secretos al nuevo proveedor. El gate exige ahora **22 flags** de argparse documentados. Suite completa con **382 pruebas**.

Un rechazo o un límite de turnos excedido se comportan de la misma manera. Por lo tanto, el contrato de salida exige cuatro condiciones simultáneas: código de retorno 0, ausencia de payload de error, `stopReason == end_turn`, y texto no vacío. El preflight sigue la misma lógica: `grok models` sale con 0 incluso desconectado, solo la presencia de « not authenticated » en stdout permite concluir.
  - **Aislamiento: asimetría asumida y documentada.** Mientras que Codex se ejecuta en `--sandbox read-only`, el sandbox de Grok es inaplicable en muchos equipos Linux recientes, debido a dos causas del sistema independientes y no eludibles sin `sudo`: AppArmor bloquea los user namespaces no privilegiados desde Ubuntu 24.04 (`bwrap: setting up uid map: Permission denied`, reproducido fuera de Grok), y la deny-list de los sockets de runtime de contenedores falla cuando `/run/podman` está en `0700` (el resolver solo captura `ErrorKind::NotFound`, el EACCES se vuelve fatal). Trampa principal: un perfil **integrado** que no puede aplicarse **se inicia sin aislar en silencio**. Por lo tanto, el script no solicita ningún perfil por defecto y nunca recurre a un fallback silencioso — advierte en stderr. La protección se basa en las reglas `--deny` de la CLI, catch-all `*` incluido, única capa medida _fail-closed_ (una regla con prefijo desconocido hace que se rechace el inicio). `GROK_TRANSLATE_SANDBOX=read-only` permite exigirlo, en cuyo caso el inicio falla si la máquina no puede cumplirlo.
  - **Mecanismos de protección**: `XAI_API_KEY`, `GROK_API_KEY` y `GROK_SANDBOX` se eliminan del entorno del subproceso (una clave provocaría el cambio a facturación por uso; un `GROK_SANDBOX` heredado impondría un perfil inaplicable con un mensaje engañoso), interruptores MCP/hooks/skills/agents desactivados, `--disable-web-search`, `--no-subagents`, `--no-plan`, workdir desechable, rechazo en CI, timeout que mata el grupo de procesos, back-off ante rate limit. `--max-turns` se establece en 6 y no en 1: el contador se incrementa tras la ronda de herramientas, y 1 truncaría la salida.
  - **Cuota**: el pool de Grok es semanal y está **compartido con Chat, Imagine y Voice**, y ningún comando lo expone — a diferencia de Codex, cuyo `account/rateLimits/read` permite cuantificar el consumo. Por lo tanto, `regen_translations.sh` limita la concurrencia a 2 y advierte explícitamente.

- **1.9.2** Corrección de la extracción de URL de atribución de noticias con paréntesis anidados o prefijo FR (2026-05-11):
  - **Error corregido**: la extracción de las URL de atribución en `_protect_news_quotes` utilizaba la expresión regular `re.search(r"\((.+?)\)", attribution)` (captura lazy entre paréntesis). En una atribución del tipo `(relayé par [@user sur X](https://x.com/.../123))` (paréntesis anidados: `(` envolvente + `]()` del enlace markdown), la captura se detenía en el primer `)` encontrado → cadena truncada + incluyendo el prefijo FR: `relayé par [@user sur X](https://x.com/.../123` (sin `)` final).     - `via [@source](url)` o `selon [@author](url)` — prefijo FR sin paréntesis envolventes
