- **1.16.3** Final de archivo: una traducción mediante API conserva el salto de línea final de su fuente, y el SDK 3.0 de Mistral queda validado (2026-10-04):

  - **Una traducción mediante API conserva el salto de línea final de su fuente.** Los providers de API —OpenAI, Anthropic, Gemini, Mistral— eliminan de la respuesta del modelo los espacios en blanco que la rodean. En el último segmento, esta limpieza se llevaba consigo el salto de línea final de la fuente: un archivo traducido sin nota de traducción terminaba sin salto de línea, algo que git señala y que los formateadores corrigen en cada ejecución. Se detectó al validar el SDK 3.0 de Mistral, en una guía que terminaba con un salto de línea cuya traducción ya no lo tenía. La nota de traducción volvía a añadir uno, y los providers de línea de comandos —Codex, Grok CLI, Antigravity, Claude Code, OpenCode— reproducen el final del segmento: solo se veía afectada una traducción mediante API sin nota. La traducción ahora reproduce el salto de línea final de la fuente, sea cual sea el provider, y no añade ninguno a una fuente que no lo tenga.

  - **Mistral: el SDK 3.0 validado mediante una llamada real.** `mistralai` 3.0.0 sustituye la biblioteca HTTP `httpx` por `httpx2`; los imports y la llamada de traducción no cambian. Una instalación nueva de aipmt ya lo recibía, puesto que las dependencias no tienen una versión máxima, pero todavía no se había probado con ninguna llamada real: una guía Markdown traducida mediante la API de Mistral con el SDK 3.0 conserva una estructura idéntica a la fuente. Las versiones fijadas para el desarrollo pasan a utilizar este SDK, y las pruebas de reintento le proporcionan un cliente `httpx2`, el que utiliza en producción.

- **1.16.2** Protección del código: el código citado dentro de una cita `--news` y un bloque indentado en una lista ya no hacen que se rechace la traducción de todos los idiomas (2026-10-03):

  - **El código citado dentro de una cita ya no bloquea la traducción.** En modo `--news`, aipmt protege el código inline antes de apartar las citas en inglés, que se restauran sin cambios. Por tanto, el código incluido en una cita se iba junto con ella: el modelo nunca veía su token y la validación lo declaraba perdido para todos los idiomas. La vigilancia diaria de noticias del autor se detuvo ahí el 2 de octubre: un comando `/plugin enable …` citado en un tuit, el idioma de sondeo rechazado dos veces y los otros trece sin llegar a iniciarse. Los tokens que una cita se ha llevado ahora se resuelven en el texto apartado. Cuando el idioma de destino es el inglés, la línea de traducción francesa de una cita ya no se envía al modelo: la instrucción le pedía eliminarla, y el código que contenía se contabilizaba entonces como perdido aunque el modelo hubiera obedecido. El resultado publicado no cambia. Por último, la restauración de una cita ya no reinterpreta sus barras invertidas: un `\n` citado sigue siendo un `\n`. Verificado de principio a fin en el artículo que había fallado: inglés y alemán traducidos al primer intento mediante `gpt-6.1-sol`, con una estructura idéntica a las versiones publicadas.

  - **Un bloque de código indentado dentro de una lista está protegido.** CommonMark permite que el cierre de un bloque esté desplazado, y este es el caso normal de un bloque que documenta un paso de una lista numerada: pertenece al elemento de la lista, por lo que está indentado. Al estar anclado en la columna 0, el patrón de protección no detectaba ninguno: medido en un README real, se detectaron 8 bloques de 14. Los otros seis se enviaban al modelo como prosa, regresaban sin cambios, puesto que eran comandos, y la protección que rechaza una traducción copiada literalmente rechazaba el archivo para todos los idiomas, con un mensaje que indicaba el síntoma, pero nunca la causa. El patrón admite ahora un cierre indentado, y el recorrido de protección y restauración devuelve el documento sin cambios, incluida la indentación.

- **1.16.1** Enlaces internos: el token del ancla deja sus paréntesis en el enlace, y un enlace traducido ya no se duplica silenciosamente (2026-09-27):

  - **Un enlace interno ya no se rompe sin que nadie lo detecte.** Para proteger un enlace hacia una sección, `[texte](#ancre)`, aipmt sustituía su parte entre paréntesis, incluidos los paréntesis, por un token: el modelo recibía unos corchetes seguidos de un token suelto, un enlace que parecía roto, y en ocasiones intentaba «repararlo». La restauración producía entonces `[texte]((#ancre))`, un enlace que no llevaba a ninguna parte, sin que ninguna protección lo señalara. El defecto reaparecía con cada regeneración de las traducciones de este repositorio —en español, coreano y después italiano para la versión 1.15.0, y en alemán para la 1.16.0— con cada Gemini Flash probado, e incluso con Claude Sonnet y Haiku. El token de un enlace Markdown ahora conserva sus paréntesis: el modelo recibe un enlace válido que ya no tiene motivos para reparar, y la restauración también admite un token al que le haya quitado los paréntesis. Las anclas HTML conservan un token suelto. Verificado de principio a fin con el modelo más frágil, `gemini-3.8-flash-low`, en un README donde un enlace estaba entre paréntesis: sin la corrección, README rechazado, tres enlaces duplicados y un segmento procesado de nuevo; con ella, tres enlaces intactos de tres, sin ninguna repetición. Después, en este README, en alemán, japonés e hindi mediante `gemini-3.8-flash-medium`, y en alemán mediante Claude Code con `sonnet`: estructura idéntica a la fuente y los tres enlaces internos intactos en todos los casos.

  - **Las pruebas ya no pueden modificar el repositorio que las ejecuta.** Cuando se hace push desde un worktree vinculado, git transmite a sus hooks la variable que designa el repositorio, y el hook pre-push ejecuta las pruebas: el `git init` de una prueba, previsto para un directorio temporal, reinicializó el repositorio real, que de repente quedó declarado sin árbol de trabajo. Las pruebas que ejecutan git eliminan ahora de su entorno todas las variables `GIT_*`, y una prueba de regresión que utiliza esta variable para designar un repositorio señuelo lo comprueba.

- **1.16.0** Provider `--use_claude_code`: traducir con la cuota de la suscripción Claude Pro o Max mediante el CLI oficial `claude -p` —sin ninguna vía de pago, y cada llamada lo demuestra— (2026-09-26):

  - **Undécima vía: la suscripción Claude, sin facturación por uso.** `--use_claude_code` controla el binario oficial de Claude Code en modo `-p`, sobre la misma base que Codex, Grok CLI y Antigravity: grupo de procesos independiente y detención segura al alcanzar el tiempo límite, pulsar Ctrl-C o cerrar el terminal. No debe confundirse con `--use_claude`, la API de Anthropic facturada por uso. aipmt nunca lee el token.

  - **Ninguna vía de pago, verificado en tres niveles.** El entorno del subproceso es una lista de permitidos: ni clave API, ni token, ni proveedor cloud, ni indicador de la sesión de Claude Code desde la que se hubiera iniciado aipmt —la sesión que escribió este provider exportaba quince—. El preflight, sin ningún turno del modelo, exige que `claude auth status` muestre una conexión de suscripción sin clave de Console y que `/usage` contenga la frase que acredita la suscripción. Después, cada llamada debe acreditarlo en su evento de inicialización —`apiKeySource: none`, entorno forzado recibido correctamente, modelo de la familia solicitada y sin modo rápido— y en su informe de cuota: el «extra usage» de pago detiene inmediatamente la traducción.

  - **La cuota se comparte con las sesiones de Claude Code, y el provider la administra con cuidado.** Cada llamada informa del uso de las ventanas de 5 horas y de la semana; por encima del 80 % (`AIPMT_CLAUDE_MAX_UTILIZATION`), no se inicia ningún segmento adicional. El día en que se escribió, la cuota semanal de la cuenta del autor ya estaba al 98 %.

  - **No entra nada de la configuración del usuario ni queda nada de la sesión.** Sin herramientas, en modo sin personalización, con los ajustes del usuario ignorados, los servidores MCP y hooks desactivados, un directorio de trabajo privado y desechable, y sin conservar ninguna transcripción. Medido mediante canarios: sin `CLAUDE_CODE_DISABLE_ATTACHMENTS`, un `@chemin` del documento se convertía en un archivo adjunto, y el modelo devolvía una llamada de lectura en lugar de la traducción; con él, no pasa nada. Los canarios `AGENTS.md`, `CLAUDE.md` y hook no cargaron ni ejecutaron nada.

  - **Un segmento que comienza por `/` no llegaba al modelo.** Bajo `--disable-slash-commands`, Claude Code responde por sí mismo «… isn't available in this environment.», con estado `success`, sin ningún turno. Un salto de línea delante del segmento lo envía al modelo; en cualquier caso, el contrato de salida rechaza una respuesta devuelta sin turno, en más de un turno, truncada o por un modelo distinto del anunciado.

  - **Modelos: alias, nunca un identificador fijo.** `sonnet` de forma predeterminada, con esfuerzo `low`, y también en `--eco` —por tanto, `--eco` no cambia nada en esta vía—; `opus` y `haiku` mediante `--model`; `fable` y las variantes `[1m]` se rechazan porque, en `-p`, pasan a créditos de pago sin preguntar.

  - **Los valores predeterminados se miden, no se presuponen.** Mediante el propio `aipmt --use_claude_code`, cuatro traducciones en paralelo, en los dos documentos de las mediciones del README —el denso artículo de vigilancia, en `--news`, y este README en su revisión 1.14.0—, a catorce idiomas cada uno. `sonnet`, con esfuerzo `low`, escribe las 28 traducciones, 26 sin diferencias: una palabra adicional en negrita en chino en el artículo y, en árabe, en el README, una línea de tabla pegada a la anterior que la visualización oculta. Enlaces internos intactos, citas en inglés reproducidas sin cambios y, en inglés, líneas de traducción francesa eliminadas por el modelo, sin ningún indicador inventado; mediana de 6 min 49 s por idioma en el artículo y de 2 min 20 s en el README. `opus` traduce el README sin ninguna diferencia, un cuarto más rápido, pero ningún artículo: sus mecanismos de protección detuvieron la respuesta en los catorce idiomas por una breve noticia de biología. `haiku` sí lo escribe todo —tres títulos de sección convertidos al nivel 1 en el artículo y los enlaces internos del README en inglés duplicados—, pero tarda el doble que `sonnet`: razona sin que se pueda impedir, el 61 % de sus tokens de salida, y su precio más bajo solo permite un ahorro del 14 % en equivalente de API. De ahí que se use `sonnet` también en `--eco`. El esfuerzo no sirve de nada para traducir: en un lote previo —este README y este CHANGELOG en inglés, japonés e hindi—, `sonnet` no produjo ningún token de razonamiento, `opus` con esfuerzo medio dedicó a ello el 1 % de sus tokens de salida, y el esfuerzo medio no mejoró nada respecto al bajo, ni en estructura ni en duración. La campaña `sonnet`, con 1,8 millones de caracteres de la fuente, consumió 9 puntos de la ventana de 5 horas y 2 de la semana en la suscripción Max del autor; es un límite superior, pues la sesión que controlaba las mediciones utilizaba la misma cuota.

  - **Un rechazo de los mecanismos de protección de Anthropic se identifica como tal.** Opus 5.5 tiene mecanismos de protección más estrictos que Sonnet, y el mensaje de error de Anthropic advierte que a veces señalan trabajos cercanos a la investigación biológica. Bastó una breve noticia de vigilancia sobre 279 moléculas generadas para un sitio de unión. Claude Code interrumpe entonces la respuesta, vuelve a intentarlo una vez, y el modelo devuelve «I can't continue this translation» con un estado correcto, sin error, en dos turnos: solo el contrato de turno único detenía esta respuesta, con un mensaje que no indicaba su causa. Enviada por separado, la breve noticia es rechazada por la API dentro de la categoría «bio». aipmt reconoce ahora estas señales, identifica los mecanismos de protección y su categoría, no vuelve a intentarlo —el mismo texto provocaría de nuevo el mismo rechazo— y recomienda `--model sonnet`, que tradujo la breve noticia a los catorce idiomas.

  - **Las traducciones de este repositorio pueden usar esta vía, sin excepción.** `REGEN_PROVIDER=claude_code` es una suscripción, no una API facturada: funciona sin `REGEN_ALLOW_PAID_API`, con cuatro jobs —las campañas se ejecutaron con cuatro traducciones simultáneas sin ningún error de límite de solicitudes ni de bloqueo de conexión—, tras un único preflight que no consume cuota. El valor predeterminado sigue siendo Codex con `gpt-5.6-sol`.

  - **Las condiciones de uso, expresadas sin rodeos.** La página legal de Claude Code no impide que un usuario inicie sesión en el binario sin modificar con su propia suscripción; prohíbe a los desarrolladores externos canalizar solicitudes mediante las credenciales Pro o Max de sus usuarios, y Anthropic prefiere la clave API para las herramientas de terceros, incluidos los proyectos open source, reservándose el derecho de descontar su uso de los créditos de pago. Ningún texto resuelve el caso de una herramienta distribuida que ejecuta el binario oficial: el usuario compromete su cuenta.

  - **Pruebas**: nuevo archivo `tests/test_claude_code_provider.py` (58 pruebas), 100 % de las instrucciones y ramas del módulo, sin ejecutar nunca el `claude` real: entorno vaciado, binario inexistente, `PATH` sin `claude` y dobles que generan una excepción si se los llama.

- **1.15.0** Provider `--use_antigravity`: traducir con la cuota de la suscripción Google AI Pro o Ultra mediante el CLI oficial `agy`; y, para todos los providers, Ctrl-C ya no abandona ningún agente en ejecución, un segmento en blanco ya no hace fallar el archivo y un `.env` del proyecto ya no elige el binario que se ejecuta (2026-09-26):

  - **Décima vía de provider: la suscripción de Google, sin facturación por uso.** Quien pague Google AI Pro o Ultra ahora puede descontar de ella sus traducciones en lugar de pagarlas por token en la API de Gemini. `agy`, el CLI oficial de Antigravity, es la única vía hacia esta cuota: Gemini CLI dejó de prestar servicio a las cuentas Pro, Ultra y gratuitas el 18 de junio de 2026, y el SDK de Antigravity solo se autentica mediante una clave API o Google Cloud. `--use_antigravity` lo controla en modo headless, como Codex y Grok CLI, sobre la misma base: grupo de procesos independiente, `SIGTERM` y después `SIGKILL` al alcanzar el tiempo límite, y entorno depurado. Verificado de principio a fin con agy 1.2.11: una guía Markdown —front matter, negrita, enlace con paréntesis, código inline, bloque de código indentado dentro de una lista, tabla y cita— traducida al inglés en 14 segundos, incluido el preflight, con una estructura idéntica a la fuente y una nota de traducción añadida; después, tras las correcciones de la revisión, al alemán en 19 segundos, con una estructura idéntica y sin escribir nada en `~/.gemini`.
  - **No queda abierta ninguna vía de pago, y cada ejecución lo verifica.** agy conoce otras vías además de la suscripción —clave API, proyecto de Google Cloud, pasarela, créditos de IA de pago— y varias variables de entorno hacen que cambie a ellas sin mostrar nada. Comprobado: `AGY_GATEWAY_URL` envía el documento a una pasarela de terceros, `AGY_ADC_AUTH` cambia a un proyecto de Google Cloud facturado, `CLOUD_CODE_URL` desvía el endpoint autenticado a cualquier dirección. Por tanto, el entorno del subproceso es una lista de permitidos y no de bloqueados: `PATH`, el idioma y la zona horaria, el terminal, la identidad, los proxies y certificados de la máquina y el bus de sesión —que un `env -i` demostró que agy necesita—, sin ninguna clave. Una lista de bloqueados por familias de prefijos (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), probada primero, dejaba algunos fuera: una revisión encontró en las cadenas del binario sobrescrituras de endpoint que ningún prefijo cubría, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Dos ajustes escapan al entorno y solo pueden leerse mediante `agy -p /config`: los créditos de IA de pago que toman el relevo de una cuota agotada y la conexión mediante un proyecto de Google Cloud. Un preflight que no consume cuota alguna —uso cero, comprobado— se niega a traducir si alguno de ellos está activo o si hay configurada una clave API, y la ausencia de un ajuste en `/config` equivale a un rechazo para cada uno de los tres: una versión de agy que cambiara el nombre de uno de ellos no debe superar un control que no ha verificado nada. Por último, el registro de cada llamada debe certificar la autenticación mediante la suscripción (`authMethod=consumer`), y cualquier otro método de autenticación que aparezca en él, bajo cualquiera de las dos grafías que emplea el binario, hace que se rechace la respuesta: lo que da fe es la propia llamada, no la configuración que se haya preparado.

  - **El agente de traducción no tiene ninguna herramienta, y su carga se demuestra en cada llamada.** Cada llamada escribe, en un directorio desechable, un agente con el formato de los agentes de proyecto de agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Unos 800 tokens de entrada en lugar de 12 400 con el agente predeterminado, y el tercer ajuste no es redundante: `excludeDefaultComponents` por sí solo permitía que un hook del workspace ejecutara sus comandos e inyectara su texto. La verdadera trampa está en otro lugar: un agente que no se encuentra no hace que agy falle. Código de salida 0, estado `SUCCESS`, y es el agente de programación, con 57 herramientas activas, el que responde: a «El gato duerme.», respondió «¡Chist, no lo despertemos! 🐱💤 ¿Qué puedo hacer por usted hoy?». Nada en stdout ni en stderr: solo lo indica el registro de la llamada. Por tanto, la respuesta se rechaza si el registro anuncia esta alternativa y también si no contiene el marcador positivo de carga del agente; una evolución del formato del registro hace que se rechace la traducción en vez de eliminar silenciosamente la protección. Cada marcador debe ocupar una línea completa del registro, con el formato comprobado —gravedad, fecha, hora, hilo, archivo y línea—: el binario también contiene una línea que copia el mensaje del usuario en el registro —nunca vista con el nivel de log predeterminado, en 78 registros reales—, y un documento que cite esos mensajes no debe poder satisfacer la protección en lugar de agy.

  - **No se modifican los ajustes ni el historial de agy del usuario.** Cada llamada se ejecuta con un HOME, un directorio temporal y un directorio de trabajo privados, que se eliminan después. Aun así, agy se autentica mediante el llavero del sistema, que aipmt nunca lee. No se hereda nada: ni los permisos del usuario —que permitían al agente predeterminado ejecutar `ls` y `git` sin preguntar nada—, ni sus reglas globales, plugins, servidores MCP, hooks y skills. Y no se añade nada a su historial, donde cada llamada dejaba una conversación de unos 200 KB, incluido el texto traducido: la campaña de pruebas había dejado allí unas 95 conversaciones y expulsado 17 entradas de una caché limitada a 100. Verificado: ningún archivo escrito en `~/.gemini/antigravity-cli`.

  - **Rechazo seguro cuando el aislamiento no se mantendría.** En Linux sin bus de sesión D-Bus —sesión SSH, contenedor, servidor—, agy guarda su token en un archivo de `~/.gemini` en lugar de hacerlo en el llavero, como anuncia su propio changelog (1.1.3), y el aislamiento de cada llamada oculta ese archivo. Ahora el rechazo se produce antes de cualquier ejecución, con su causa real, en vez de esperar un minuto un código de conexión y mostrar después un consejo para volver a conectarse que no resolvería nada. En Windows, agy lee `USERPROFILE`, `APPDATA` y `TEMP`, no `HOME` ni `TMPDIR` —según la documentación de Go y las cadenas del binario—: nada aislaría allí la llamada de los ajustes ni del historial del usuario, y `--use_antigravity` se rechaza hasta que esto se compruebe. macOS se admite, sin haber sido comprobado; la protección contra la facturación, que lee la configuración efectiva, se mantiene allí.

  - **`exit 0` no demuestra nada, cuarta CLI.** Una respuesta solo se acepta con un código de salida cero, un objeto JSON con estado `SUCCESS`, un registro conforme, sin acciones rechazadas, comandos ni errores en el JSON, sin advertencias de truncamiento en stderr y con un texto no vacío. `--print-timeout` nunca se utiliza: cuando vence, agy devuelve la salida parcial en `SUCCESS`, código 0; el tiempo límite es externo y mata el grupo de procesos. Un segmento que empieza por `/commande`, `!commande` o `@fichier` se traduce, nunca se ejecuta ni se resuelve; sin `--disable-slash-commands`, «/help» se ejecutaba en vez de traducirse. Un segmento en blanco ya no llega a agy, pues el pipeline lo devuelve tal cual (véase más abajo), y sigue rechazándose antes de la llamada como última salvaguarda: con una entrada vacía, agy abre su interfaz interactiva con un código 0. El reintento sigue el campo `retryable` de la línea `AGY_ERROR` que agy escribe en stderr desde su versión 1.2.6: ya reintenta por sí mismo los errores transitorios —502, 503, 504, límite por minuto—, y es quien sabe si el fallo restante aún lo es. A falta de ese campo, no se reintenta cuando el mensaje habla de agotamiento —en Google, `RESOURCE_EXHAUSTED` lleva el mismo código 429 que un límite por minuto, pero una ventana de 5 horas agotada no se restablece en 90 segundos—, y en los demás casos solo se reintenta por limitación de tasa. La respuesta conserva el final de línea del segmento: agy siempre termina la suya con un salto de línea que, al unirlas, dividía en dos un párrafo segmentado a mitad de una frase. Una sesión desconectada muestra un mensaje que indica que se ejecute `agy` para volver a conectarse. Por último, `AGY_CLI_DISABLE_AUTO_UPDATE=true` evita que un HOME nuevo ejecute en cada llamada un comprobador de actualizaciones en su propia sesión, fuera del alcance del tiempo límite; el valor `1`, en cambio, no tiene efecto.

  - **Modelos: el esfuerzo de razonamiento forma parte del nombre.** Los identificadores son los de `agy models` —`gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`…—. Un nombre base por sí solo, que agy rechazaría, se rechaza antes de la llamada, mostrando los sufijos existentes: `-medium` o `-low` para un Flash, `-high` o `-low` para un Pro. De forma predeterminada, `gemini-3.8-flash-medium`, y `gemini-3.7-flash-low` en `--eco`, fijados por las campañas descritas más abajo. `--reasoning_effort` no tiene efecto y así lo indica. Claude y GPT-OSS consumen una cuota distinta y mucho menor —alrededor del 1 % de la ventana de 5 horas por llamada comprobada, frente al 0,05 % con Flash—, y una advertencia lo recuerda. La cuota restante puede consultarse gratuitamente mediante `agy -p /usage`. Se rechaza en CI, al igual que Codex y Grok CLI: la conexión reside en un llavero personal y el mensaje propone `--use_gemini` con una clave de Google.

  - **Dos campañas el 26 de septiembre: los valores predeterminados se midieron, no se supusieron.** Mediante el propio `aipmt --use_antigravity`, cuatro traducciones en paralelo, cada una comparada con su fuente mediante `scripts/compare_structure.py`, y la cuota leída mediante `agy -p /usage` antes y después. Por la mañana, sobre la revisión de este README publicada con la versión 1.14.0 y sobre el denso artículo de seguimiento de las mediciones del README, en `--news`, `gemini-3.7-flash-medium` escribe los catorce idiomas de ambos documentos: el artículo sin ninguna diferencia, con una mediana de 3 min 14 s por idioma, y el README con una única diferencia en una palabra en negrita, en coreano, en 1 min 22 s.   - **Ctrl-C y el cierre del terminal detienen ahora al agente, para las cuatro CLI.** Codex, Grok CLI, OpenCode y Antigravity se ejecutan en su propia sesión, fuera del grupo en primer plano: el `SIGINT` de un Ctrl-C no los alcanza y, al pulsar Ctrl-C, `Popen` solo los espera durante un cuarto de segundo antes de devolver el control. La revisión lo verificó con un binario simulado: el agente sobrevivía a aipmt y terminaba su turno consumiendo cuota, para luego desechar el resultado —cuatro a la vez durante la regeneración—. Un `KeyboardInterrupt` o un `SystemExit` durante la llamada mata ahora el grupo del agente antes de propagarse. Cerrar el terminal o interrumpir una sesión SSH (`SIGHUP`) mataba Python sin efectuar ninguna limpieza: el agente continuaba y el directorio privado de Antigravity permanecía en el disco con su registro, que contiene la dirección de la cuenta. `SIGHUP` sigue ahora la ruta de `SIGTERM`: se mata el grupo del agente y después se sale con 129. Un `SIGHUP` ignorado por una ejecución bajo `nohup` sigue ignorándose: es la elección del usuario. El preflight de Antigravity —`agy --version` y después `agy -p /config`— pasa por el mismo gestor: una señal recibida durante este control detiene agy y elimina también el directorio privado, en vez de dejarlo en el disco con su registro.

  - **El controlador de subprocesos ya no puede apuntar a toda la sesión.** En Linux, `killpg(1, sig)` equivale a `kill(-1, sig)`: la señal se envía a todos los procesos del usuario. Esto ocurrió durante la escritura de esta versión, en una campaña de mutaciones: un mutante llamaba a un `Popen` sustituido por un `MagicMock` sin envolver, el error resultante pasaba por la nueva ruta de interrupción y el pid del proceso simulado, que Python convierte en 1, hizo que se matara toda la sesión gráfica. `_codex_kill_group`, común a las cuatro CLI, solo apunta ahora a un grupo si el pid es un entero real superior a 1, si `getpgid` devuelve ese mismo pid —un agente iniciado en su propia sesión es el líder de su grupo— y si no es el grupo del proceso actual; de lo contrario, solo se apunta al hijo directo. En producción, esta salvaguarda no cambia nada: cubre el caso en el que un bug hiciera aparecer otra cosa. Los dobles de `Popen` que no deben utilizarse fallan ahora de forma clara, los procesos simulados llevan un pid imposible y las campañas de mutaciones se ejecutan en un namespace PID.

  - **Un segmento en blanco ya no hace fallar el archivo, sea cual sea el provider.** `segment_text` puede aislar el final en blanco de un documento: 16 001 caracteres terminados por tres saltos de línea producen un segundo segmento compuesto por dos saltos de línea. Antigravity lo rechazaba antes de la llamada —reproducido por la revisión— y, con un provider de API, una respuesta vacía activaba la protección contra contenido vacío: en ambos casos fallaba el archivo completo, después de haberse consumido la cuota de los segmentos anteriores. Ahora un segmento en blanco se devuelve tal cual, sin efectuar ninguna llamada.
  - **Seguridad: un `.env` de proyecto ya no puede elegir el binario ejecutado.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN` y `AGY_BIN` designan el programa que ejecuta la traducción, con los permisos del usuario: definidos por el `.env` de un repositorio recién clonado, hacían que se ejecutara un archivo de ese repositorio desde la primera traducción. Por tanto, el sufijo `_BIN` se une a `_BASE_URL`, `_API_BASE` y `_ENDPOINT` en el filtro de la capa de proyecto, con `GROK_HOME`, bajo el cual se busca el binario de Grok (`$GROK_HOME/bin/grok`). Estas variables siguen aceptándose desde el entorno y desde `~/.config/aipmt/.env`, y cada rechazo se comunica por stderr junto con el lugar donde deben definirse.

  - **Pruebas**: nuevo archivo `tests/test_antigravity_provider.py` (103 pruebas), que cubre el 100 % de las instrucciones y las ramas del módulo: argv exacto y nunca `-p`, segmento por stdin, agente escrito sin herramienta ni herencia, entorno reducido a la lista de permitidos, directorio privado eliminado después de un éxito, un fallo, un tiempo de espera o una señal, contrato de salida completo, fallback del agente y vía de facturación leídos en líneas de registro con formato real, `AGY_ERROR` y `retryable`, preflight de facturación estricto, rechazo en Windows y sin bus de sesión, sufijos de esfuerzo, conservación del final de línea del segmento, cableado del dispatch y rama del regen. Ninguna prueba ejecuta agy: ningún caso llamó a un binario falso situado al principio de `PATH`, incluidas las condiciones de la CI, con el bus de sesión oculto y `CI=true`. `tests/test_provider_base.py` interrumpe un subproceso real mediante Ctrl-C y `SIGHUP`, también bajo `nohup`, y asegura la protección de `killpg`: pid `MagicMock`, booleano, 1 o menos, grupo actual o grupo de otro proceso: nunca una señal de grupo; `tests/test_key_resolution.py` inicia un proceso nuevo para cada variable `_BIN`; `tests/test_orchestration.py` traduce un documento cuyo final en blanco forma un segmento aparte. Suite completa de **650 pruebas**.

  - **Un fallo de escritura ya no deja una traducción truncada en el disco.** `open(cible, "w")` trunca el archivo antes de llenarlo: un error durante la escritura —disco lleno— dejaba un destino parcial. Reproducido: ocho bytes escritos, estado `failure` devuelto y, después, la siguiente ejecución encontraba este archivo, respondía `skipped` y lo conservaba. Un fallo se convertía en una traducción truncada que ya no se señalaba de ninguna forma, y el código de salida era 0. Ahora el contenido se escribe en un archivo temporal del mismo directorio —`os.replace` solo es atómico en un mismo sistema de archivos— y después se renombra; el archivo temporal se elimina si la escritura falla, incluso en caso de interrupción. Este archivo temporal procede de `mkstemp`, y una revisión demostró que un nombre predecible solo habría trasladado el problema: un enlace simbólico colocado en `cible.md.aipmt-tmp` hacía que la traducción se escribiera en el archivo de destino, fuera del directorio de salida, devolviendo `success`; además, dos ejecuciones simultáneas sobre el mismo destino compartían ese nombre, y la segunda lo renombraba mientras la primera aún escribía en el mismo inode: destino anunciado como correcto, contenido mezclado (`BBBAAAAA` en lugar de `BBBBBBBB`, según las mediciones). `mkstemp` crea en `O_CREAT | O_EXCL` con un nombre único, lo que resuelve ambos problemas. Los permisos del destino existente se recuperan explícitamente antes de sustituirlo: `mkstemp` crea con 0600 y, de lo contrario, un destino configurado deliberadamente con 0600 pasaba a 0664, mientras que un destino con 0644 servido por un servidor web habría dejado de ser legible. Ocho pruebas aseguran el conjunto, y dos mutaciones del código hacen que fallen.

  - **El manifiesto de pureza permite declarar un marcador de supresión reescrito.** La comprobación exigía que cada línea de la referencia que contuviera un `# nosec`, `# nosemgrep` o `NOSONAR` sobreviviera palabra por palabra. Sin embargo, trasladar una escritura a un archivo temporal cambia el nombre de la variable abierta: la supresión de Sonar es la misma, pero su línea cambia. La categoría `markers` del manifiesto declara este par `old` → `new` junto con su motivo. Hay dos condiciones, y la segunda procede de una revisión: el sustituto debe existir **y contener las mismas supresiones que la línea original**. Sin ella, declarar `value = 1  # NOSONAR` → `value = 1` daba resultado verde, de modo que bastaba una declaración para retirar un marcador, exactamente lo que esta comprobación pretende impedir. Una desaparición no declarada continúa rechazándose.

Un lector no podía determinarlo y la impresión era negativa donde la medición es buena: en este README, Gemini solo tiene un idioma de catorce con una palabra adicional en negrita, Sol dos y GLM tres. Ahora cada celda indica el número de idiomas afectados y cuáles son; la cifra de las columnas de veredicto se define en una frase —el número de idiomas, de catorce, en los que se escribe la traducción y nada difiere— y una leyenda explica el significado de los tres símbolos. - **1.12.0** Provider `--use_opencode`: OpenCode, el agente open source, hacia el proveedor que elija —modelo local, gratuito sin cuenta, suscripción o clave (2026-09-04):

  - **Octava vía de provider, de distinta naturaleza que las siete primeras.** [OpenCode](https://opencode.ai) (MIT) no es un proveedor de modelos, sino un _router_ hacia los que el usuario haya configurado en el propio OpenCode: una clave de API, una suscripción (GitHub Copilot, ChatGPT, SuperGrok), la pasarela OpenCode Zen —que ofrece modelos gratuitos **sin cuenta**— o un modelo **local** (Ollama, LM Studio, llama.cpp). El script controla `opencode run` en modo no interactivo, como controla Codex y Grok, y reutiliza la misma base de subprocesos (grupo de procesos propio, `SIGTERM` y después `SIGKILL` al producirse un timeout, stdin siempre cerrado, entorno depurado). Verificado mediante **dos traducciones reales**: este README completo al inglés mediante `opencode/mimo-v2.5-free` —49 s, una sola pasada, estructura idéntica a la del archivo fuente (32 títulos, 26 cierres de código, 18 enlaces, 37 URL, 37 líneas de tabla y 135 fragmentos de código inline)— y un archivo de prueba mediante `ollama/qwen2.5:7b`, en local, sin ninguna clave.

  - **`--model provider/modèle` es obligatorio, y se trata de una elección.** Sin `--model`, OpenCode vuelve a su propio valor predeterminado, que en una instalación nueva es `opencode/big-pickle`, un modelo gratuito «stealth» cuyas interacciones pueden utilizarse para entrenamiento; según las mediciones, ese es el modelo que respondió. Elegirlo silenciosamente en lugar del usuario sería exactamente el tipo de cambio invisible que este repositorio vigila; por eso el mensaje de error indica el comando que enumera los modelos (`opencode models`) y ofrece tres ejemplos (local, gratuito y suscripción). `--eco` no tiene efecto y así lo indica. `--reasoning_effort` se transmite sin cambios como `--variant` de OpenCode, únicamente cuando se solicita de forma explícita.

  - **Confinamiento medido, no supuesto.** Una configuración inline (`OPENCODE_CONFIG_CONTENT`, la última en el orden de fusión de OpenCode y, por tanto, prioritaria sobre la del usuario sin reemplazarla) define un agente `aipmt` que tiene todas las herramientas denegadas (`permission: {"*": "deny"}`): el registro ni siquiera se las ofrece al modelo, que, cuando se le ordena «enumerar los archivos y ejecutar `id`», responde que no dispone de herramientas. Uso compartido de sesiones desactivado, plugins externos excluidos (`--pure`), nunca `--auto`, directorio de trabajo desechable y vacío. Se midieron y desactivaron dos inyecciones silenciosas: sin `OPENCODE_DISABLE_CLAUDE_CODE`, el `~/.claude/CLAUDE.md` del usuario entra en **cada** prompt (515 tokens de entrada en vez de 186 para un simple «Hola»); sin `OPENCODE_DISABLE_PROJECT_CONFIG`, también lo hace el `AGENTS.md` del directorio actual: durante la traducción se aplicó una instrucción de «terminar cada respuesta con BANANA». El `~/.config/opencode/AGENTS.md` global, en cambio, sigue inyectándose: ningún interruptor lo excluye, y eludirlo mediante un `XDG_CONFIG_HOME` desviado también ocultaría los proveedores del usuario. Se documenta en lugar de improvisar una solución.

  - **`exit 0` no demuestra nada: tercera CLI, mismos reflejos, con dos trampas propias.** Un `--agent` desconocido no hace fallar `opencode run`: muestra una advertencia en stderr y recurre **silenciosamente** al agente de programación, con las herramientas activas. Por tanto, si no se tuviera en cuenta la configuración inline, la traducción se ejecutaría con un agente capaz de escribir; el contrato de salida comprueba la ausencia de ese mensaje, además de lo siguiente: código de retorno 0, ningún evento `error`, ningún `tool_use`, último `step_finish` en `stop` (un `length` es una respuesta truncada) y texto no vacío. Segunda trampa: el evento JSON de error es **opaco** —«Error inesperado del servidor. Consulta los registros del servidor para obtener más detalles.»—, con una simple referencia, y la causa real (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) solo se encuentra en los logs. De ahí `--print-logs --log-level ERROR` y la lectura del campo `error="…"` de stderr, sin la traza de Bun que aparece después. Así, un modelo desconocido falla en un segundo e indica su causa. De paso, `--title` evita una llamada LLM parásita: sin él, OpenCode genera un título de sesión mediante un turno adicional en el `small_model`.

  - **Secretos: el mismo filtrado por patrón que Codex y Grok, con una única excepción nominal.** Se conserva `OPENCODE_API_KEY`: es la clave del propio OpenCode (pasarela Zen, suscripción Go), dirigida a él por su nombre; el equivalente de su `auth.json`, no una clave que aipmt gestione ni pueda facturar. Los proveedores se configuran en OpenCode (`opencode auth login`, `opencode.json`), nunca en el `.env` de aipmt, cuyas claves no llegan al subproceso. No se rechaza en CI, a diferencia de las CLI de suscripción: una clave de API o un modelo autoalojado en un runner son usos legítimos.

  - **La protección contra path traversal ahora comprueba el valor interpolado, no el valor sin procesar.** `provider/modèle` contiene un `/` que la protección de la versión 1.10.0 rechazaba —con razón, ya que `--model` se interpolaba en el nombre del archivo `--include_model`—. La etiqueta del nombre de archivo ahora sustituye `/`, `\` y `:` por `-` antes de cualquier interpolación (`ollama/qwen2.5:7b` → `ollama-qwen2.5-7b`, dado que `:` es ilegal en Windows), y la protección ascendente examina esa etiqueta: `../../evil` se convierte en el nombre simple `doc-en-..-..-evil.md` bajo el destino, únicamente `..` sigue rechazándose, al igual que `--target_lang ../x`. La protección de perímetro `_ensure_within_directory` permanece como segunda capa, sin cambios.

De ahí `REGEN_PROVIDER=opencode`, con `REGEN_MODEL` obligatorio y **2 jobs** en paralelo. En local, Ollama suele configurar 4 096 tokens de contexto, mientras que los segmentos alcanzan los 16 000 caracteres: se necesita un `Modelfile` con `PARAMETER num_ctx 32768`, y la calidad depende del modelo; un 7B invirtió una lista y dañó el cierre de un bloque de código en el archivo de prueba, mientras que el modelo de la pasarela lo conservó todo.

- **1.9.2** Corrección de la extracción de URLs de atribución de noticias con paréntesis anidados o prefijo FR (2026-05-11):
