- **1.16.3** Sfârșit de fișier: o traducere prin API păstrează sfârșitul de linie final din sursă, iar SDK-ul 3.0 al Mistral este validat (2026-10-04):

  - **O traducere prin API păstrează sfârșitul de linie final din sursă.** Furnizorii API — OpenAI, Anthropic, Gemini, Mistral — elimină spațiile albe din jurul răspunsului modelului. La ultimul segment, această curățare elimina sfârșitul de linie final al sursei: un fișier tradus fără notă de traducere se termina fără sfârșit de linie, ceea ce git semnalează și formaterii corectează la fiecare trecere. Observat la validarea SDK-ului 3.0 Mistral, pe un ghid încheiat cu un sfârșit de linie a cărui traducere nu îl mai avea. Nota de traducere adăuga unul înapoi, iar furnizorii în linie de comandă — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — recopiază finalul segmentului: doar o traducere prin API fără notă era afectată. Traducerea redă acum sfârșitul de linie final al sursei, indiferent de furnizor, și nu adaugă niciunul unei surse care nu are.

  - **Mistral: SDK-ul 3.0 validat printr-un apel real.** `mistralai` 3.0.0 înlocuiește biblioteca HTTP `httpx` cu `httpx2`; importurile și apelul de traducere nu se schimbă. O instalare nouă de aipmt îl primea deja, deoarece dependențele nu au o versiune plafon, dar niciun apel real nu îl testase încă: un ghid Markdown tradus prin API-ul Mistral cu SDK-ul 3.0 păstrează o structură identică cu sursa. Versiunile fixate pentru dezvoltare trec la acest SDK, iar testele de reîncercare îi furnizează un client `httpx2`, cel pe care îl folosește în producție.

- **1.16.2** Protecția codului: codul citat într-un citat `--news` și un bloc indentat într-o listă nu mai provoacă refuzul traducerii pentru toate limbile (2026-10-03):

  - **Codul citat într-un citat nu mai blochează traducerea.** În modul `--news`, aipmt protejează codul inline înainte de a pune deoparte citatele în engleză, restaurate ca atare. Un cod plasat într-un citat pleca așadar odată cu acesta: modelul nu îi vedea niciodată tokenul, iar validarea îl declara pierdut, pentru toate limbile. Monitorizarea zilnică de știri a autorului s-a oprit aici pe 2 octombrie: o comandă `/plugin enable …` citată într-un tweet, limba de sondare respinsă de două ori, celelalte treisprezece nelansate vreodată. Tokenurile pe care un citat le-a preluat sunt acum rezolvate în textul pus deoparte. Pentru limba țintă engleză, linia de traducere franceză a unui citat nu mai este trimisă modelului: instrucțiunea îi cerea să o șteargă, iar codul pe care îl conținea era considerat atunci pierdut, deși modelul se conformase. Rezultatul publicat nu se schimbă. În sfârșit, restaurarea unui citat nu îi mai reinterpretează backslash-urile: un `\n` citat rămâne un `\n`. Verificat cap-coadă pe articolul care eșuase: engleză și germană traduse din prima încercare de `gpt-6.1-sol`, structură identică cu versiunile publicate.

  - **Un bloc de cod indentat într-o listă este protejat.** CommonMark permite o închidere decalată a blocului, iar acesta este cazul normal al unui bloc care documentează o etapă dintr-o listă numerotată: aparține elementului de listă, deci este indentat. Ancorat pe coloana 0, modelul de protecție le rata pe toate: măsurat pe un README real, 8 blocuri detectate din 14. Celelalte șase plecau la model ca proză, se întorceau identice, deoarece sunt comenzi, iar mecanismul de protecție care refuză o traducere copiată ca atare respingea fișierul pentru toate limbile, cu un mesaj care numea simptomul și niciodată cauza. Modelul de căutare acceptă acum o închidere indentată, iar parcursul dus-întors între protecție și restaurare redă documentul identic, inclusiv indentarea.

- **1.16.1** Linkuri interne: tokenul de ancoră lasă parantezele linkului, iar un link tradus nu se mai dublează în tăcere (2026-09-27):

  - **Un link intern nu se mai rupe fără să fie observat.** Pentru a proteja un link către o secțiune, `[texte](#ancre)`, aipmt înlocuia partea sa dintre paranteze, inclusiv parantezele, cu un token: modelul primea paranteze drepte urmate de un token gol, un link cu aspect rupt, și i se întâmpla să îl „repare”. Restaurarea reda atunci `[texte]((#ancre))`, un link care nu duce nicăieri, fără ca vreun mecanism de protecție să îl semnaleze. Defectul reapărea la fiecare regenerare a traducerilor acestui depozit — în spaniolă, coreeană și apoi italiană pentru 1.15.0, în germană pentru 1.16.0 — cu fiecare Gemini Flash încercat, și chiar cu Claude Sonnet și Haiku. Tokenul unui link Markdown își păstrează acum parantezele: modelul primește un link valid, pe care nu mai are motive să îl repare, iar restaurarea acceptă și un token din care ar fi eliminat parantezele. Ancorele HTML păstrează un token gol. Verificat cap-coadă cu cel mai fragil model, `gemini-3.8-flash-low`, pe un README în care un link era între paranteze: fără corecție, README respins, trei linkuri dublate și un segment reluat; cu ea, trei linkuri intacte din trei, nicio reluare. Apoi pe acest README, în germană, japoneză și hindi cu `gemini-3.8-flash-medium`, și în germană cu Claude Code cu `sonnet`: structură identică cu sursa, cele trei linkuri interne intacte peste tot.

  - **Testele nu mai pot modifica depozitul care le lansează.** Trimis prin push dintr-un worktree legat, git transmite către hookurile sale variabila care desemnează depozitul, iar hookul pre-push rulează testele: comanda `git init` a unui test, prevăzută pentru un director temporar, a reinițializat depozitul real, declarat brusc fără arbore de lucru. Testele care lansează git elimină acum orice variabilă `GIT_*` din mediul lor, iar un test de non-regresie, care desemnează prin această variabilă un depozit momeală, verifică acest lucru.

- **1.16.0** Furnizorul `--use_claude_code`: traducere pe cota abonamentului Claude Pro sau Max, prin CLI-ul oficial `claude -p` — nicio cale cu plată, iar fiecare apel o dovedește (2026-09-26):

  - **A unsprezecea cale: abonamentul Claude, fără facturare pe consum.** `--use_claude_code` controlează binarul oficial Claude Code în modul `-p`, pe aceeași bază ca și Codex, Grok CLI și Antigravity — grup propriu de procese, oprire sigură la timeout, Ctrl-C sau închiderea terminalului. A nu se confunda cu `--use_claude`, API-ul Anthropic facturat pe consum. aipmt nu citește niciodată tokenul.

  - **Nicio cale cu plată, verificată pe trei niveluri.** Mediul subprocesului este o listă de permisiuni: fără cheie API, fără token, fără furnizor cloud, fără marcator al sesiunii Claude Code din care ar fi lansat aipmt — cea care a scris acest furnizor exporta cincisprezece. Preflight-ul, fără apeluri către model, cere de la `claude auth status` conectarea prin abonament fără cheie Console, iar de la `/usage` fraza care atestă abonamentul. Fiecare apel trebuie apoi să o ateste în evenimentul său de inițializare — `apiKeySource: none`, mediu forțat primit cu succes, model din familia cerută, fără mod rapid — și în raportul său de cotă: utilizarea suplimentară („extra usage”) plătită oprește traducerea pe loc.

  - **Cota este partajată cu sesiunile Claude Code, iar furnizorul o menajează.** Fiecare apel raportează utilizarea ferestrelor de 5 ore și a celei săptămânale; peste 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), nu se mai lansează niciun segment. În ziua redactării, săptămâna contului autorului era deja la 98%.

  - **Nimic din configurația utilizatorului nu intră, nimic din sesiune nu rămâne.** Fără instrumente, în mod fără personalizare, setările utilizatorului ignorate, serverele MCP și hookurile deconectate, director de lucru privat și de unică folosință, nicio transcriere păstrată. Măsurat prin canari: fără `CLAUDE_CODE_DISABLE_ATTACHMENTS`, un `@chemin` din document devenea un atașament, iar modelul returna un apel de citire în loc de traducere; cu acesta, nimic nu trece. Canarii `AGENTS.md`, `CLAUDE.md` și hook nu au încărcat și nu au executat nimic.

  - **Un segment care începe cu `/` nu ajungea la model.** Sub `--disable-slash-commands`, Claude Code răspunde el însuși « … isn't available in this environment. », cu starea `success`, fără niciun tur. O linie nouă înaintea segmentului îl trimite modelului; contractul de ieșire refuză oricum un răspuns returnat fără niciun tur, în mai mult de un tur, trunchiat sau de către un alt model decât cel anunțat.

  - **Modele: aliasuri, niciodată un identificator fixat.** `sonnet` în mod implicit, cu efortul `low`, și în `--eco` la fel — `--eco` nu schimbă deci nimic pe această cale —, `opus` și `haiku` prin `--model`; `fable` și variantele `[1m]` sunt refuzate, deoarece în `-p` trec pe credite plătite fără a cere confirmare.

  - **Defectele sunt măsurate, nu presupuse.** Prin `aipmt --use_claude_code` însuși, patru traduceri în paralel, pe cele două documente de măsurare din README — articolul dens de sinteză, în `--news`, și acest README în revizia 1.14.0 —, paisprezece limbi fiecare. `sonnet`, la efortul `low`, scrie cele 28 de traduceri, 26 fără nicio abatere: un cuvânt îngroșat în plus în chineză pe articol, iar în arabă, pe README, o linie de tabel lipită de cea precedentă, pe care afișajul o maschează. Linkuri interne intacte, citate în engleză recopiate ca atare, iar în engleză liniile de traducere în franceză eliminate de model, fără steag inventat; mediană de 6 min 49 s pe limbă pentru articol, 2 min 20 s pentru README. `opus` traduce README-ul fără nicio abatere, cu un sfert mai rapid, dar niciun articol: mecanismele sale de siguranță au oprit răspunsul în toate cele paisprezece limbi, la o știre scurtă de biologie. `haiku` scrie tot — trei titluri de secțiune trecute la nivelul 1 pe articol, linkurile interne din README-ul în engleză dublate —, dar de două ori mai lent decât `sonnet`: acesta raționează fără să poată fi oprit, 61% din tokenurile sale de ieșire, iar prețul său mai mic lasă doar 14% economie în echivalent API. De unde și `sonnet` în `--eco`, de asemenea. Efortul nu folosește la nimic pentru traducere: pe un lot preliminar — acest README și acest CHANGELOG în engleză, japoneză și hindi —, `sonnet` nu a produs niciun token de raționament, `opus` la efort mediu 1% din tokenurile sale de ieșire, iar efortul mediu nu a adus niciun câștig față de cel redus, nici ca structură, nici ca durată. Campania `sonnet`, 1,8 milioane de caractere sursă, a consumat 9 puncte din fereastra de 5 ore și 2 din cea săptămânală pe abonamentul Max al autorului — o limită superioară: sesiunea care coordona măsurătorile consuma din aceeași cotă.

  - **Un refuz al mecanismelor de siguranță Anthropic este numit ca atare.** Opus 5.5 are filtre de siguranță mai stricte decât Sonnet, iar mesajul de eroare de la Anthropic avertizează că acestea semnalează uneori lucrări apropiate de cercetarea biologică. O scurtă știre de monitorizare despre 279 de molecule generate pentru un situs de legare a fost de ajuns. Claude Code întrerupe atunci răspunsul, reîncearcă o dată, iar modelul întoarce « I can't continue this translation » cu stare de succes, fără eroare, pe parcursul a două tururi: doar contractul de tur unic oprea acest răspuns, cu un mesaj mut privind cauza sa. Trimisă singură, știrea este refuzată de API la categoria « bio ». aipmt recunoaște acum aceste semne, denumește filtrele de siguranță și categoria lor, nu reîncearcă — același text ar declanșa din nou același refuz — și recomandă `--model sonnet`, care a tradus știrea în toate cele paisprezece limbi.

  - **Traducerile acestui depozit pot trece pe această cale, fără derogare.** `REGEN_PROVIDER=claude_code` este un abonament, nu un API facturat: rulează fără `REGEN_ALLOW_PAID_API`, cu patru joburi — campaniile au rulat cu patru traduceri simultane fără nicio eroare de rată sau de blocare a conexiunii —, după un preflight unic care nu consumă nicio cotă. Valoarea implicită rămâne Codex cu `gpt-5.6-sol`.

  - **Termenii de utilizare, spuși deschis.** Pagina cu termeni legali a Claude Code nu împiedică un utilizator să se conecteze la binarul nemodificat cu propriul abonament; ea interzice dezvoltatorilor terți să trimită cereri prin datele de identificare Pro sau Max ale utilizatorilor lor, iar Anthropic preferă cheia API pentru instrumentele terțe, inclusiv proiectele open source, rezervându-și dreptul de a deconta utilizarea lor pe credite plătite. Niciun text nu tranșează cazul unui instrument distribuit care lansează binarul oficial: utilizatorul își angajează propriul cont.

  - **Teste**: fișier nou `tests/test_claude_code_provider.py` (58 de teste), 100% din instrucțiunile și ramurile modulului, fără a lansa vreodată adevăratul `claude` — mediu golit, binar inexistent, `PATH` fără `claude`, dubluri de test care aruncă erori dacă sunt apelate.

- **1.15.0** Furnizorul `--use_antigravity`: traducere pe cota abonamentului Google AI Pro sau Ultra, prin CLI-ul oficial `agy`; și, pentru toți furnizorii, Ctrl-C nu mai lasă agenți abandonați în rulare, un segment gol nu mai duce la eșecul fișierului, iar un `.env` de proiect nu mai alege binarul executat (2026-09-26):

  - **A zecea cale de furnizor: abonamentul Google, fără facturare pe consum.** Cine plătește Google AI Pro sau Ultra își poate deconta de acum traducerile acolo în loc să le plătească la token pe API-ul Gemini. `agy`, CLI-ul oficial Antigravity, este singura cale către această cotă: Gemini CLI nu mai deservește conturile Pro, Ultra sau gratuite din 18 iunie 2026, iar SDK-ul Antigravity se autentifică doar printr-o cheie API sau prin Google Cloud. `--use_antigravity` îl controlează în mod headless, ca și Codex și Grok CLI, pe aceeași bază — grup propriu de procese, `SIGTERM` apoi `SIGKILL` la timeout, mediu curățat. Verificat cap-coadă pe agy 1.2.11: un ghid Markdown — front matter, caractere aldine, link cu paranteze, cod inline, bloc de cod indentat într-o listă, tabel, citat — tradus în engleză în 14 secunde, inclusiv preflight, structură identică cu sursa, notă de traducere adăugată; apoi, după corecțiile din revizuire, în germană în 19 secunde, structură identică, nimic scris în `~/.gemini`.

  - **Nicio cale cu plată nu rămâne deschisă, iar fiecare lansare verifică acest lucru.** agy cunoaște și alte căi în afară de abonament — cheie API, proiect Google Cloud, gateway, credite AI plătite — și mai multe variabile de mediu îl comută către acestea fără a afișa nimic. Măsurat: `AGY_GATEWAY_URL` trimite documentul către un gateway terț, `AGY_ADC_AUTH` comută pe un proiect Google Cloud facturat, `CLOUD_CODE_URL` redirecționează endpointul autentificat către orice adresă. Mediul subprocesului este așadar o listă de permisiuni și nu de refuz: `PATH`, limba și fusul orar, terminalul, identitatea, proxy-urile și certificatele mașinii și magistrala de sesiune — ceea ce un `env -i` a dovedit că are nevoie agy —, fără nicio cheie. O listă de refuz pe familii de prefixe (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), încercată mai întâi, omitea unele: o verificare a găsit în șirurile binarului suprascrieri de endpoint pe care niciun prefix nu le acoperea, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Două setări scapă mediului și nu pot fi citite decât prin `agy -p /config`: creditele AI plătite care preiau controlul la epuizarea unei cote, și conectarea printr-un proiect Google Cloud. Un preflight care nu consumă nicio cotă — consum zero, măsurat — refuză să traducă dacă vreuna dintre ele este activă sau dacă o cheie API este configurată, iar o setare absentă din `/config` echivalează cu un refuz pentru fiecare dintre cele trei: o versiune de agy care ar redenumi una dintre ele nu trebuie să treacă de o verificare care nu a controlat nimic. În sfârșit, jurnalul fiecărui apel trebuie să ateste autentificarea prin abonament (`authMethod=consumer`), iar orice altă metodă de autentificare care figurează în el, sub una sau cealaltă dintre cele două grafii pe care binarul le folosește, duce la refuzarea răspunsului: apelul însuși este cel care face dovada, nu configurația pregătită.

  - **Agentul de traducere nu are niciun instrument, iar încărcarea sa este dovedită la fiecare apel.** Fiecare apel scrie, într-un director de unică folosință, un agent în formatul agenților de proiect ai agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Aproximativ 800 de tokeni de intrare în loc de 12 400 cu agentul implicit, iar a treia setare nu este redundantă: doar `excludeDefaultComponents` lăsa un hook din workspace să-și execute comenzile și să-și injecteze textul. Adevărata capcană este în altă parte: un agent de negăsit nu provoacă eșecul agy. Cod de retur 0, stare `SUCCESS`, și agentul de codare, cu 57 de instrumente active, este cel care răspunde — la „Le chat dort.”, a răspuns „Chut, ne le réveillons pas ! 🐱💤 Que puis-je faire pour vous aujourd'hui ?”. Nimic pe stdout sau pe stderr: doar jurnalul apelului o spune. Răspunsul este așadar refuzat dacă jurnalul anunță această repliere și, de asemenea, dacă nu poartă marcajul pozitiv al încărcării agentului — o evoluție a formatului de jurnal face ca traducerea să fie refuzată în loc să elimine garda în tăcere. Fiecare marcaj trebuie să ocupe o linie întreagă din jurnal, în formatul măsurat — severitate, dată, oră, fir, fișier și linie: binarul conține și o linie care recopiază mesajul utilizatorului în jurnal — nemaivăzută la nivelul de log implicit, pe 78 de jurnale reale —, iar un document care citează aceste mesaje nu trebuie să poată satisface garda în locul lui agy.

  - **Setările și istoricul agy ale utilizatorului nu sunt atinse.** Fiecare apel rulează cu un HOME, un director temporar și un director de lucru private, șterse ulterior. agy se autentifică totuși prin brelocul de chei al sistemului, pe care aipmt nu îl citește niciodată. Nimic nu este moștenit: nici permisiunile utilizatorului — care îi permiteau agentului implicit să lanseze `ls` și `git` fără să ceară nimic —, nici regulile sale globale, pluginurile, serverele MCP, hook-urile și skill-urile. Și nimic nu se adaugă la istoricul său, unde fiecare apel lăsa o conversație de aproximativ 200 Ko, inclusiv textul tradus: campania de sonde lăsase în el aproximativ 95 de conversații și eliminase 17 intrări dintr-un cache plafonat la 100. Verificat: niciun fișier scris în `~/.gemini/antigravity-cli`.

  - **Refuz în sistem închis acolo unde izolarea nu ar rezista.** Pe Linux fără magistrală de sesiune D-Bus — sesiune SSH, container, server —, agy își păstrează tokenul într-un fișier din `~/.gemini` în loc de brelocul de chei, așa cum anunță propriul său changelog (1.1.3), iar izolarea fiecărui apel maschează acest fișier. Refuzul vine de acum înainte înainte de orice lansare, cu adevărata sa cauză, în loc de un minut de așteptare pentru un cod de conectare urmat de o recomandare de reconectare care nu ar rezolva nimic. Pe Windows, agy citește `USERPROFILE`, `APPDATA` și `TEMP`, nu `HOME` și nici `TMPDIR` — conform documentației Go și șirurilor din binar —: nimic nu ar izola acolo apelul de setările sau istoricul utilizatorului, iar `--use_antigravity` este refuzat acolo până când acest lucru nu este măsurat. macOS trece, fără a fi fost măsurat; garda de facturare, care citește configurația efectivă, rezistă acolo.

  - **`exit 0` nu dovedește nimic, al patrulea CLI.** Un răspuns este acceptat doar cu un cod de retur zero, un obiect JSON cu starea `SUCCESS`, un jurnal conform, fără acțiune refuzată, fără comandă, fără eroare în JSON, fără avertisment de trunchiere pe stderr și cu un text nevid. `--print-timeout` nu este folosit niciodată: la expirarea sa, agy returnează ieșirea parțială în `SUCCESS`, cod 0; timeout-ul este extern și oprește grupul de procese. Un segment care începe cu `/commande`, `!commande` sau `@fichier` este tradus, niciodată executat sau rezolvat — fără `--disable-slash-commands`, „/help” se executa în locul traducerii. Un segment gol nu mai ajunge la agy, pipeline-ul returnându-l ca atare (vezi mai jos), și rămâne refuzat înainte de apel ca o ultimă plasă de siguranță: la o intrare goală, agy își deschide interfața interactivă cu un cod 0. Reîncercarea urmează câmpul `retryable` din linia `AGY_ERROR` pe care agy o scrie pe stderr începând cu versiunea sa 1.2.6: el reîncearcă deja singur erorile tranzitorii — 502, 503, 504, limită pe minut —, și el este cel care știe dacă eșecul rămas mai este tranzitoriu. În lipsa acestui câmp, nu există nicio reîncercare când mesajul vorbește despre epuizare — la Google, `RESOURCE_EXHAUSTED` poartă același cod 429 ca o limită pe minut, dar o fereastră de 5 ore epuizată nu revine în 90 de secunde —, iar în rest doar la limitarea ratei. Răspunsul preia sfârșitul de linie al segmentului: agy îl termină întotdeauna pe al său cu o linie nouă, ceea ce, la îmbinare, tăia în două un paragraf scindat în mijlocul propoziției. O sesiune deconectată generează un mesaj care indică rularea `agy` pentru reconectare. În sfârșit, `AGY_CLI_DISABLE_AUTO_UPDATE=true` împiedică un HOME nou să lanseze la fiecare apel un verificator de actualizări în propria sa sesiune, în afara ariei de acțiune a timeout-ului — valoarea `1`, în schimb, este fără efect.

Cele **288 de modele din 431** care îl impun (`reasoning.mandatory`) răspund cu `400 « Reasoning is mandatory for this endpoint and cannot be disabled »`: pentru ele, preflight-ul citește eforturile acceptate și îl solicită pe cel mai mic (punctul următor) — efortul alocă un **procent din `max_tokens`** pe care raționamentul îl consumă mai întâi, astfel încât o valoare aleasă la întâmplare mută riscul de pagină albă în loc să îl reducă.

Mărirea limitei nu ar fi schimbat nimic: efortul alocă un procent din aceasta, iar raționamentul crește odată cu ea. - **1.12.0** Provider `--use_opencode`: OpenCode, agentul open source, către furnizorul dorit — model local, gratuit fără cont, abonament sau cheie (2026-09-04):

  - **Al optulea traseu de provider, de o natură diferită față de primele șapte.** [OpenCode](https://opencode.ai) (MIT) nu este un furnizor de modele, ci un _ruter_ către cele pe care utilizatorul le-a configurat în OpenCode însuși: o cheie API, un abonament (GitHub Copilot, ChatGPT, SuperGrok), gateway-ul OpenCode Zen — care oferă modele gratuite **fără cont** —, sau un model **local** (Ollama, LM Studio, llama.cpp). Scriptul controlează `opencode run` în mod non-interactiv, la fel cum controlează Codex și Grok, și reutilizează aceeași bază de subprocese (grup propriu de procese, `SIGTERM`, apoi `SIGKILL` la timeout, stdin întotdeauna închis, mediu curățat). Verificat prin **două traduceri reale**: întregul README în engleză prin `opencode/mimo-v2.5-free` — 49 s, o singură trecere, structură identică cu fișierul sursă (32 de titluri, 26 de închideri de cod, 18 linkuri, 37 de URL-uri, 37 de rânduri de tabel, 135 de coduri inline) — și un fișier de test prin `ollama/qwen2.5:7b`, local, fără nicio cheie.

  - **`--model provider/modèle` este obligatoriu, și aceasta este o alegere.** Fără `--model`, OpenCode revine la valoarea sa implicită, care pe o instalare curată este `opencode/big-pickle`, model gratuit „stealth” ale cărui conversații pot fi utilizate pentru antrenare — măsurat, acesta este modelul care a răspuns. Alegerea acestei opțiuni în mod silențios în locul utilizatorului ar fi exact genul de comutare invizibilă pe care acest depozit o urmărește; prin urmare, mesajul de eroare menționează comanda care listează modelele (`opencode models`) și trei exemple (local, gratuit, abonament). `--eco` nu are niciun efect și precizează acest lucru. `--reasoning_effort` este transmis ca atare drept `--variant` al OpenCode, doar la cerere explicită.

  - **Izolare măsurată, nu presupusă.** O configurație inline (`OPENCODE_CONFIG_CONTENT`, ultima în ordinea de îmbinare a OpenCode, deci prioritară față de cea a utilizatorului fără a o înlocui) definește un agent `aipmt` ale cărui instrumente sunt toate refuzate (`permission: {"*": "deny"}`): registrul nici măcar nu le mai propune modelului, care, somat să „listeze fișierele și să ruleze `id`”, răspunde că nu are instrumente. Partajarea sesiunii dezactivată, pluginuri externe eliminate (`--pure`), niciodată `--auto`, director de lucru de unică folosință și gol. Două injectări silențioase au fost măsurate și blocate: fără `OPENCODE_DISABLE_CLAUDE_CODE`, `~/.claude/CLAUDE.md`-ul utilizatorului intră în **fiecare** prompt (515 tokeni de intrare în loc de 186 pentru un simplu „Bună ziua”); fără `OPENCODE_DISABLE_PROJECT_CONFIG`, `AGENTS.md`-ul din directorul curent la fel — o instrucțiune „termină fiecare răspuns cu BANANA” a fost aplicată traducerii. În schimb, `~/.config/opencode/AGENTS.md`-ul global rămâne injectat: niciun comutator nu îl elimină, iar ocolirea lui printr-un `XDG_CONFIG_HOME` modificat ar masca și furnizorii utilizatorului. Documentat în loc de improvizat.

  - **`exit 0` nu dovedește nimic, al treilea CLI, aceleași reflexe — cu două capcane specifice acestuia.** Un `--agent` necunoscut nu face ca `opencode run` să eșueze: avertisment pe stderr și revenire **silențioasă** la agentul de codare, cu instrumentele active. Dacă configurația inline nu ar fi luată în considerare, traducerea ar porni așadar cu un agent capabil să scrie; contractul de ieșire verifică absența acestui mesaj, pe lângă: cod de retur 0, niciun eveniment `error`, niciun `tool_use`, ultimul `step_finish` ca `stop` (un `length` este un răspuns trunchiat), text nevid. A doua capcană: evenimentul JSON de eroare este **opac** — „Unexpected server error. Check server logs for details.”, cu o simplă referință — iar cauza reală (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) există doar în jurnale. De aici `--print-logs --log-level ERROR` și citirea câmpului `error="…"` din stderr, fără stack trace-ul Bun care îl urmează. Un model necunoscut eșuează astfel într-o secundă, cu cauza specificată. `--title` evită, în plus, un apel LLM parazit: fără el, OpenCode generează un titlu de sesiune printr-o rundă suplimentară pe `small_model`.

  - **Secrete: aceeași filtrare după tipar ca la Codex și Grok, cu o singură excepție nominativă.** `OPENCODE_API_KEY` este păstrată: este cheia OpenCode însuși (gateway-ul Zen, abonamentul Go), adresată acestuia pe nume — echivalentul `auth.json`-ului său, nu o cheie pe care aipmt ar gestiona-o sau ar putea-o factura. Furnizorii se configurează în OpenCode (`opencode auth login`, `opencode.json`), niciodată în `.env`-ul aipmt, de unde nicio cheie nu ajunge la subproces. Fără refuz în CI, spre deosebire de CLI-urile cu abonament: o cheie API sau un model auto-găzduit pe un runner sunt cazuri de utilizare legitime.

  - **Protecția anti-traversare controlează de acum valoarea interpolată, nu valoarea brută.** `provider/modèle` conține un `/` pe care protecția din 1.10.0 îl refuza — pe bună dreptate, `--model` fiind interpolat în numele fișierului `--include_model`. Protecția de perimetru `_ensure_within_directory` rămâne al doilea strat, neschimbată.

  - **Modele gratuite și modele locale, ce anume a fost măsurat.** `opencode/mimo-v2.5-free` traduce un paragraf în 16 s și acest README în 49 s; `opencode/big-pickle` are nevoie de 40 s pentru 200 de cuvinte, iar două cereri simultane au rămas acolo fără răspuns timp de 5 minute, în timp ce fiecare luată separat reușește; `opencode/nemotron-3.5-lightning-free` nu a răspuns nimic în 3 minute. Un proiect Python nu mai are nevoie, așadar, de o instalare npm globală pentru a utiliza `--use_codex`. Pachetul nu este adăugat la `requirements.txt`: binarul cântărește ~250 MO, ceea ce ar fi impus tuturor utilizatorilor pentru un provider opțional. Verificat cap-coadă: cu `codex` absent din `PATH`, rezolvarea găsește binarul împachetat și o traducere completă reușește în 6 s.
  - **Garanție „mod abonament”**: `OPENAI_API_KEY` și `CODEX_API_KEY` sunt eliminate din mediul subprocesului. Fără această protecție, o cheie prezentă în `.env` ar putea comuta Codex la facturare pe bază de utilizare fără niciun semnal vizibil — exact ceea ce acest provider este conceput să evite.
  - **Capcane ale CLI-ului securizate prin teste**:
    - `codex exec` citește stdin **chiar și** atunci când promptul este transmis ca argument: fără închiderea stdin, comanda așteaptă până la timeout fără a apela vreodată modelul (reprodus: exit 124 după 180 s, zero octeți). `communicate(input=...)` este așadar obligatoriu.
    - `codex` instalat prin npm este un shim Node care `spawn` binarul Rust real: acesta este un **nepot** al procesului Python și supraviețuiește la `SIGKILL` al `subprocess.run(timeout=)`, unde ar continua să consume cotă. De aici `Popen(start_new_session=True)` + `os.killpg`.
    - CLI-ul poate ieși cu codul 0 chiar dacă a emis un `turn.failed`: ieșirea JSONL (`--json`) este inspectată pe lângă codul de retur, iar absența fișierului `-o` cu un cod 0 declanșează o eroare explicită în loc să producă un segment gol.

Clasificarea se face pe baza structurii payload-ului JSON (`status: 429` / `error.type`), nu pe subșiruri — cuvântul „quota” apărând atât într-un 429 recuperabil, cât și într-un `insufficient_quota` definitiv.
