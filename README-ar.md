يترجم ملفات Markdown من لغة إلى أخرى مع الحفاظ على البنية: كتل الأكواد البرمجية، والأكواد المضمنة، وعناوين URL، والمراسخ، والجداول، وfront matter. عشر طرق لاستدعاء النموذج — خمس واجهات برمجة تطبيقات (APIs)، وثلاثة اشتراكات بدون فوترة حسب الاستخدام، وموجّهان — وقياس منشور لما يحافظ عليه كل نموذج فعلياً.

## باختصار

- **عشرة مسارات للمزودين**: واجهات برمجة التطبيقات لـ OpenAI وMistral وClaude وGemini وGrok؛ واشتراكات ChatGPT (Codex) وGrok وGoogle (Antigravity) بدون فوترة حسب الاستخدام؛ وموجّها OpenCode (مفتوح المصدر، مجاني أو محلي) وOpenRouter (أكثر من 400 نموذج).
- **لا شيء خاطئ بسبب رمز ضائع**: تُستبدل كتل الأكواد البرمجية، والأكواد المضمنة، وعناوين URL، والمراسخ، والاقتباسات برموز مميزة قبل الاستدعاء ويتم التحقق منها عند العودة. وإذا فُقد أحدها، لا يُكتب الملف.
- **المستندات الطويلة**: تقسيم وفقاً لنافذة سياق النموذج.
- **وضع `--news`**: حماية الاقتباسات الإنجليزية وإدارة الأعلام حسب اللغة، لمقالات الرصد الإخباري.
- **وضع `--eco`**: نماذج سريعة وأقل تكلفة.
- **ملاحظة ترجمة** اختيارية، في الأعلى أو في الأسفل أو في كليهما.

## الإعداد

تُقرأ المفاتيح من ثلاثة أماكن، من الأعلى أولوية إلى الأقل؛ ولا يسد كل منها إلا ما تركه السابق فارغاً.

|     | أين                                           | لأي غرض                               |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | متغيرات البيئة                                | CI، الحاويات، التجاوز المؤقت          |
| 2   | `.env` في الدليل الحالي (أو دليل أصل)  | مفتاح خاص بمشروع محدد                 |
| 3   | `~/.config/aipmt/.env`                                 | يُثبَّت مرة واحدة، ويعمل في كل مكان   |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

يُقبل `GEMINI_API_KEY` بدلاً من `GOOGLE_API_KEY`. يتبع ملف المستخدم `XDG_CONFIG_HOME` (مسار مطلق فقط) و`%APPDATA%` على Windows. وفي حال عدم وجود مفتاح، يسرد الأمر المواقع الثلاثة.

**لا يمكن لملف `.env` الخاص بالمشروع إعادة توجيه الاستدعاءات ولا اختيار البرنامج المُنفَّذ.** فهو يوفر المفاتيح فقط، ولا يحدد أبداً وجهة أو ملفاً تنفيذياً: أي متغير يبدأ بـ `_BASE_URL` أو `_API_BASE` أو `_ENDPOINT` أو `_BIN` (`CODEX_BIN`، `GROK_BIN`، `OPENCODE_BIN`، `AGY_BIN`)، و`GROK_HOME`، والخوادم الوكيلة (`HTTP_PROXY`، `HTTPS_PROXY`، `ALL_PROXY`)، ومخازن الشهادات (`SSL_CERT_FILE`، `SSL_CERT_DIR`، `REQUESTS_CA_BUNDLE`، `CURL_CA_BUNDLE`) و`XDG_CONFIG_HOME` / `APPDATA` يتم تجاهلها هناك، مع إصدار تحذير. يجب ألا يتمكن أي مستودع مستنسخ من اختلاس مفتاحك، ولا إجبارك على تشغيل برنامجه الخاص عند أول عملية ترجمة. كما يُقرأ هذا الملف دون استيفاء: فلا ينسخ `NOM=${OPENAI_API_KEY}` المفتاح فيه. ضع هذه المتغيرات في البيئة أو في `~/.config/aipmt/.env`.

المتغيرات الاختيارية: `XAI_BASE_URL` (الافتراضي `https://api.x.ai/v1`)، و`CLAUDE_TIMEOUT` (الثواني لكل استدعاء، الافتراضي 900)، و`CODEX_BIN`، و`CODEX_TIMEOUT` (الافتراضي 600)، و`GROK_BIN`، و`GROK_HOME` (الافتراضي `~/.grok`)، و`GROK_TIMEOUT` (الافتراضي 900)، و`GROK_TRANSLATE_SANDBOX`، و`AGY_BIN`، و`AGY_TIMEOUT` (الافتراضي 900)، و`OPENCODE_BIN`، و`OPENCODE_TIMEOUT` (الافتراضي 600)، و`OPENROUTER_BASE_URL` (يتطلب `https://`)، و`OPENROUTER_TIMEOUT` (الافتراضي 900)، و`OPENROUTER_PREFLIGHT_TIMEOUT` (الافتراضي 30). تم تفصيل كل منها في قسم المزود الخاص به.

## خطوات البداية

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

ينتج عن ترجمة `document.md` إلى الإسبانية `document-es.md` في `--target_dir`؛ ومع `--include_model`، يصبح `document-es-gpt-5.6-terra.md`. يصبح الامتداد دائماً `.md` — فيعطي `article.mdx` الملف `article-en.md` — باستثناء استخدام `--keep_filename`، الذي يحتفظ بالاسم الأصلي. يتم تخطي أي ترجمة موجودة بالفعل ما لم يُستخدم `--force`.

رموز الخروج: `0` إذا نجح كل شيء أو تم تخطيه، و`1` إذا بقي ملف فاشل (القائمة على مخرج الخطأ القياسي)، و`2` إذا كان السبب متعلقاً بالإعداد.
لا يُكتب الملف الفاشل أبداً، حتى لو فشلت عملية الكتابة نفسها: حيث يُكتب المحتوى في ملف جانبي ثم يُعاد تسميته. ويكفي إعادة التشغيل.

ما يجب استخلاصه من ذلك:

- **الترجمة المرفوضة ليست ترجمة معيبة.** عندما يُفقد رمز مميز عند العودة، لا يُكتب الملف وتُحسب اللغة على أنها مرفوضة. هذا ما حدث مع Grok في المقال: فُقدت أربعة أكواد مضمنة وثلاثة عناوين URL منذ الجزء الأول، في أنظمة الكتابة غير اللاتينية الخمسة.
- **شبكة الأمان هذه لا تغطي العناوين، أو الجداول، أو front matter، أو النص.** فالنموذج الذي يحذف قسماً يُرجع ملفاً تكتبه الأداة دون تردد — كما هو الحال مع Mistral. هذه العناصر لا يمكن استبدالها برمز مميز، ولا تتحقق منها تدابير الحماية الحالية؛ يكتشف `scripts/compare_structure.py` القسم المفقود ولكن بعد فوات الأوان.
- **لم يحصل Grok على تصنيف في ملف README هذا**: فقد انتهت صلاحية جلسة CLI الخاصة به بعد اثنتي عشرة لغة، إحدى عشرة منها دون أي اختلاف. وحملة الاختبار المنقطعة لا يتم تقييمها.
- **كثافة المستند أهم من اللغة.** يصمد Grok في ملفات README العادية ويتعثر في مقال مليء بالروابط، بما في ذلك باللغة الهولندية.

## جميع الخيارات

| الخيار                   | الوصف                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `--file`           | ملف Markdown فردي لترجمته (بديل لـ `--source_dir`)                                                            |
| `--source_dir`           | الدليل المصدري الذي يحتوي على ملفات Markdown (الافتراضي: `content/posts`)                                      |
| `--target_dir`           | دليل المخرجات للملفات المترجمة (الافتراضي: `traductions_en`)                                                    |
| `--source_lang`           | لغة المصدر (الافتراضي: `fr`)                                                                        |
| `--target_lang`           | اللغة المستهدفة (الافتراضي: `en`)                                                                   |
| `--model`           | نموذج محدد للاستخدام                                                                                          |
| `--eco`           | استخدام النماذج الاقتصادية                                                                                    |
| `--use_mistral`           | استخدام واجهة برمجة تطبيقات Mistral AI                                                                        |
| `--use_claude`           | استخدام واجهة برمجة تطبيقات Claude                                                                            |
| `--use_gemini`           | استخدام واجهة برمجة تطبيقات Gemini                                                                            |
| `--use_grok`           | استخدام واجهة برمجة تطبيقات xAI (Grok) — يتطلب `XAI_API_KEY`                                                 |
| `--use_codex`           | استخدام CLI الخاص بـ Codex ضمن حصة اشتراك ChatGPT                                                             |
| `--use_grok_cli`           | استخدام CLI الخاص بـ Grok ضمن حصة اشتراك Grok                                                                 |
| `--use_antigravity`           | استخدام CLI الخاص بـ Antigravity (`agy`) ضمن حصة اشتراك Google AI Pro أو Ultra                       |
| `--use_opencode`           | استخدام OpenCode (مفتوح المصدر) مع المزود الذي تم إعداده في OpenCode؛ يتطلب `--model provider/modèle`                    |
| `--use_openrouter`           | استخدام OpenRouter — يتطلب `OPENROUTER_API_KEY` و`--model fournisseur/modèle`                                                     |
| `--force`           | فرض إعادة الترجمة                                                                                             |
| `--keep_filename`           | الاحتفاظ باسم الملف الأصلي                                                                                    |
| `--news`           | وضع الأخبار: يحمي الاقتباسات الإنجليزية، ويدير الأعلام حسب اللغة                                              |
| `--add_translation_note`           | إضافة ملاحظة ترجمة                                                                                            |
| `--note_position`           | موضع الملاحظة: `top`، أو `bottom` (الافتراضي)، أو `both`                               |
| `--note_format`           | تنسيق الملاحظة: `legacy` (الافتراضي، فقرة بخط عريض) أو `marker`                                   |
| `--include_model`          | تضمين اسم النموذج في ملف المخرجات                                                                             |
| `--reasoning_effort`          | جهد التفكير الاستنتاجي لـ GPT-5.x: `none`/`low`/`medium`/`high`/`xhigh` |

أعلام `--use_*` التسعة حصرية تبادلياً: يُرفض الجمع بين اثنين منها.

### عبر اشتراك ChatGPT: `--use_codex`

يقود أداة CLI الرسمية لـ Codex: يُحسم استهلاك الترجمة من حصة اشتراك ChatGPT، دون الحاجة إلى مفتاح API أو فوترة بحسب الاستخدام.

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- يُبحث عن الملف التنفيذي في `CODEX_BIN`، ثم في `PATH`، ثم في حزمة `openai-codex-cli-bin`. لا تتم قراءة `~/.codex/auth.json` إطلاقًا.
- تُزال `OPENAI_API_KEY` و`CODEX_API_KEY` من بيئة العملية الفرعية: وجود مفتاح لا يؤدي أبدًا إلى التبديل نحو الـ API.
- يكلّف كل مقطع "رسالة" واحدة على الأقل من نافذة الـ 5 ساعات — ورسالتين إذا فشل التحقق منه وأُعيدت المحاولة. تعلن OpenAI، على سبيل التقدير، عن 250-2,000 رسالة/5 ساعات لـ `gpt-5.6-luna` (`--eco`) و10-100 لـ `gpt-5.6-sol` في خطة Plus.
- يمر `--model gpt-5.6-terra` و`--model gpt-5.6-luna` أيضًا عبر الاشتراك. أي نموذج ليس للحساب حق الوصول إليه يعيد خطأ 400 "model is not supported when using Codex with a ChatGPT account".
- أبطأ من الـ API، وتزداد الفجوة بازدياد حجم المستند: في ملف README هذا، بلغ الوسيط 6 دقائق و46 ثانية لكل لغة مع `gpt-5.6-sol`، مقابل 36 ثانية لـ `gemini-3.7-flash`.
- مرفوض في CI (إذا كان `CI` أو `GITHUB_ACTIONS` محددًا): تتم مصادقة الاشتراك عبر ملف جلسة شخصي، لا مكان له على بيئة تشغيل مشتركة.
- المتغيرات: `CODEX_BIN`، و`CODEX_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 600).

### عبر اشتراك Grok: `--use_grok_cli`

المبدأ نفسه مع أداة CLI الرسمية Grok Build، عبر اشتراك SuperGrok أو X Premium+.

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --eco --file README.md --target_dir . --target_lang pl
```

- **عزل أضعف من Codex.** لا تعمل بيئة الحماية (sandbox) على مستوى نظام التشغيل لـ Grok على العديد من أجهزة Linux الحديثة (AppArmor، ومقابس بيئة تشغيل الحاويات)، والملف التعريفي الذي يتعذر تطبيقه يبدأ التشغيل دون عزل وبشكل صامت. لذلك لا يطلب السكربت أي ملف تعريفي افتراضيًا، ويُعلن عن ذلك، ويعتمد على قواعد `--deny` لأداة الـ CLI، بما في ذلك القاعدة الشاملة `*` — وهي الطبقة الوحيدة التي ترفض بدء التشغيل بدلاً من إزالة الحماية دون إشعار. يتطلب `GROK_TRANSLATE_SANDBOX=read-only` استخدام بيئة حماية نظام التشغيل، ويفشل بدء التشغيل إذا عجز الجهاز عن الوفاء بذلك.
- الحصة أسبوعية، ومشتركة مع Chat وImagine وVoice، ولا يوجد أي أمر لقراءتها: يمكن لدفعة معالجة أن تستهلك من الاستخدام المخصص للمحادثة دون سابق إنذار.
- المتغيرات: `GROK_BIN`، و`GROK_HOME` (دليل أداة الـ CLI، الافتراضي `~/.grok`)، و`GROK_TIMEOUT` (الافتراضي 900)، و`GROK_TRANSLATE_SANDBOX`.

### عبر اشتراك Google: `--use_antigravity`

المبدأ نفسه مع `agy`، أداة الـ CLI الرسمية لـ Antigravity: لمن يدفع مقابل Google AI Pro أو Ultra، يُحسم استهلاك الترجمة من حصة الاشتراك بدلاً من الفوترة بحسب الرموز. هذا هو المسار الوحيد نحو هذه الحصة: لم تعد Gemini CLI تخدم هذه الحسابات منذ 18 يونيو 2026 ([إعلان](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/))، ولا تقبل حزمة SDK لـ Antigravity سوى مفتاح API أو مشروع Google Cloud.

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **لا يظل أي مسار مدفوع مفتوحًا.** لا يتلقى agy من بيئتك سوى قائمة مغلقة من المتغيرات — `PATH`، واللغة والمنطقة الزمنية، والطرفية، والهوية، والبروكسيات والشهادات، وناقل الجلسة — ولا يتلقى أي مفاتيح: تتسبب عدة متغيرات تابعة له في تحويل النداء دون إظهار أي شيء (تم قياس ذلك: أحدها يرسل المستند إلى بوابة طرف ثالث، وآخر يرسله إلى مشروع Google Cloud مدفوع)، وكانت قائمة الحظر تغفل بعضها عند كل مراجعة. قبل أي مقطع، يجب أن يُظهر `agy -p /config`، الذي لا يستهلك أي حصة، أن أرصدة الذكاء الاصطناعي المدفوعة معطلة، دون مفتاح API أو مشروع Google Cloud — ويُعد الإعداد الغائب بمثابة رفض —، وإلا فلن يُترجم أي شيء؛ كما يجب بعد ذلك أن يُثبت سجل كل استدعاء وجود الاشتراك (`authMethod=consumer`)، وإلا تُرفض الاستجابة.
- **العزل.** يعمل كل استدعاء داخل دليل شخصي خاص ومؤقت، مع وكيل ترجمة مجرد من الأدوات: لا تدخل إعداداتك أو قواعدك أو ملحقاتك أو خوادم MCP أو خطاطيف agy إلى هناك، ولا يُضاف أي شيء إلى سجلك، ويظل تسجيل الدخول في حلقة المفاتيح التي لا يقرؤها aipmt أبدًا. في حال عدم العثور على الوكيل، يتراجع agy بصمت إلى وكيل البرمجة وأدواته: يجب أن يؤكد سطر كامل من السجل وجود الوكيل الصحيح — ولا يُغني مستند يقتبس هذه الرسالة عن ذلك —، وإلا يتم الرفض.
- **المنصات**: Linux، ضمن جلسة تحتوي على حلقة مفاتيح (ناقل جلسة D-Bus، وSecret Service)؛ نظام macOS مدعوم، دون اختباره بالقياسات هنا. مرفوض على Windows، حيث لا يقرأ agy المتغيرات التي تعزل كل استدعاء، وعلى Linux دون ناقل جلسة — جلسة SSH، أو حاوية، أو خادم: يخزن agy رمزه التعريفي هناك في ملف داخل `~/.gemini`، وهو ما يحجبه العزل. يصدر الرفض قبل أي تشغيل مع توضيح سببه، بدلاً من الانتظار لمدة دقيقة للحصول على رمز تسجيل الدخول.
- **النماذج**: نماذج `agy models`. تحمل نماذج Gemini مستوى الجهد في اسمها (`gemini-3.8-flash-medium`...) : يُرفض أي اسم بدون لاحقة قبل الاستدعاء، ولا يكون لـ `--reasoning_effort` أي تأثير. افتراضيًا `gemini-3.8-flash-medium`، و`gemini-3.7-flash-low` في `--eco`؛ الحملات التي حددتها مشروحة في [قياسات تفصيلية](#قياسات-تفصيلية). يمتلك Claude وGPT-OSS حصتهما الخاصة، وهي أصغر بكثير: حوالي 1% من نافذة الـ 5 ساعات لكل استدعاء مقاس، مقابل 0.05% في Flash.
- **الحصة**: لكل مجموعة، نافذة من 5 ساعات وأخرى أسبوعية، بالتناسب مع تكلفة الرموز. مقاسًا على حساب المؤلف: حوالي 16 نقطة من نافذة الـ 5 ساعات لكل مليون حرف مصدر في `gemini-3.8-flash-medium`، و14 في `gemini-3.7-flash-medium` و7 إلى 8 عند الجهد المنخفض — وبذلك يكلف ملف README المكون من 40,000 حرف أكثر بقليل من نصف نقطة. أما الحد الأسبوعي فيعتمد على الفئة. تتبع إعادة المحاولة ما يحدده agy بأنه قابل للإعادة؛ وإلا، فإن النافذة المستنفدة لا يُعاد تشغيلها أبدًا: إذ تؤدي إلى فشل كل ملف حتى يحين وقت إعادة الضبط الذي يعرضه `/usage`.
- **أبطأ من الـ API**: في المقال الكثيف الخاص بالقياسات، بلغ الوسيط 3 دقائق و59 ثانية لكل لغة في `gemini-3.8-flash-medium` و3 دقائق و14 ثانية في `gemini-3.7-flash-medium`، مقابل دقيقة و18 ثانية لنموذج Gemini 3.7 Flash عبر الـ API.
- **المقاطعة**: يؤدي الضغط على Ctrl-C، أو إغلاق الطرفية، إلى إيقاف agy مع الأمر بدلاً من تركه يكمل جولته مستهلكًا حصتك؛ وينطبق الشيء نفسه على Codex وGrok CLI وOpenCode. تحت `nohup`، تستمر الترجمة.
- مرفوض في CI (إذا كان `CI` أو `GITHUB_ACTIONS` محددًا): يستقر تسجيل الدخول في حلقة مفاتيح شخصية. على بيئة تشغيل، استخدم `--use_gemini` مع `GOOGLE_API_KEY`.
- المتغيرات: `AGY_BIN` (وإلا `PATH`، ثم `~/.local/bin/agy`)، و`AGY_TIMEOUT` (بالثواني لكل مقطع، شاملاً بدء التشغيل، الافتراضي 900).

**شروط الاستخدام: أنت المسؤول عن حسابك.** تحظر [شروط Antigravity](https://antigravity.google/terms) (القسم 6) و[الأسئلة الشائعة](https://antigravity.google/docs/faq/) التابعة لها الوصول إلى الخدمة عبر برنامج تابع لجهة خارجية باستخدام تسجيل دخول Antigravity — وقد ورد ذكر Claude Code وOpenClaw وOpenCode هناك —، وذلك تحت طائلة تعليق الحساب. لا يقرأ aipmt الرمز المميز ولا يعيد استخدامه: بل يُشغّل الملف التنفيذي الرسمي في [الوضع عديم الواجهة](https://antigravity.google/docs/cli/headless/) الذي توثقه Google للسكربتات وبيئات CI. اعتبر أحد موظفي Google أنه من "المعتاد" تشغيل `agy -p` من سكربت محلي لعمله الخاص ([المنتدى الرسمي، 25 سبتمبر 2026، إجابة غير تعاقدية](https://discuss.ai.google.dev/t/is-using-the-official-agy-cli-through-a-local-mcp-server-with-third-party-ai-agents-permitted/184829))؛ ولا يوجد نص قانوني يحسم مسألة أداة موزعة كهذه.

**المستندات العامة فقط.** وفقًا للقسم 5 من الشروط نفسها، يمكن استخدام التبادلات — المحثات، والاستجابات، والبيانات الوصفية — لتحسين منتجات Google والتعلم الآلي لديها، وقد تتم مراجعتها بواسطة مراجعين بشريين، بما في ذلك الاشتراكات المدفوعة. يتم إلغاء الاشتراك عبر الإعداد `enableTelemetry`، ذي التأثير غير الموثق، والذي لا يضعه aipmt؛ ولا تنتقل إعداداتك لـ agy ضمن بيئة عزله. لا تقم بتمرير أي محتوى سري عبره.

### نحو المزود الذي تختاره: `--use_opencode`

[OpenCode](https://opencode.ai) هو وكيل برمجة مفتوح المصدر (ترخيص MIT) يوجّه الطلبات إلى المزودين المضبوطين داخله: مفتاح API، أو اشتراك، أو بوابة OpenCode Zen (نماذج مجانية، دون حساب)، أو نموذج محلي. تم قياس مسارين من البداية إلى النهاية هنا: Zen وOllama.

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` إلزامي: بدونه، سيتراجع OpenCode إلى نموذج مجاني يمكن استخدام تبادلاته في التدريب، وهذا الخيار لا يُتخذ نيابة عنك.

العزل عند كل استدعاء:

- إعدادات مضمنة، ذات أولوية على إعداداتك، تحدد الوكيل `aipmt` مع رفض جميع الأدوات (`permission: { "*": "deny" }`)، وتعطيل مشاركة الجلسة، و`--pure`، ودون `--auto` إطلاقًا؛
- دليل عمل مؤقت وفارغ، مع تعيين `OPENCODE_DISABLE_PROJECT_CONFIG` و`OPENCODE_DISABLE_CLAUDE_CODE` — فبدونهما، يقوم OpenCode بحقن `AGENTS.md` الخاص بالدليل الحالي و`~/.claude/CLAUDE.md` في المحث. ويظل `~/.config/opencode/AGENTS.md` العام محقونًا، إذ لا يتيح OpenCode استبعاده؛
- عقد المخرجات: رمز الخروج 0، وعدم وجود أي حدث `error`، وعدم وجود أي استدعاء لأداة، وتكون الخطوة الأخيرة في `stop`، والنص غير فارغ، والوكيل `aipmt` محمل فعليًا — فالوكيل `--agent` غير المعروف لا يؤدي إلى فشل OpenCode، بل يتراجع بصمت إلى وكيل البرمجة؛
- لا يتم تمرير أي مفتاح من `aipmt`، باستثناء `OPENCODE_API_KEY`، وهو مفتاح OpenCode نفسه. تُضبط إعدادات المزودين داخل OpenCode، وليس في ملف `.env` الخاص بـ `aipmt`.

معلومات مهمة:

- نماذج Zen المجانية متغيرة، وحدودها غير موثقة، ويمكن استخدام تبادلاتها في التدريب: تصلح للتوثيق العام، وليس للمحتوى الخاص.
- يجب أن يوفر النموذج المحلي سياقًا لا يقل عن 16 ألف رمز، حيث تصل المقاطع إلى 16,000 حرف. غالبًا ما يضبط Ollama السياق على 4,096: استخدم `Modelfile` مع `PARAMETER num_ctx 32768`.
- `--eco` ليس له أي تأثير؛ ويُمرر `--reasoning_effort` كما هو كـ `--variant` لـ OpenCode.
- يسجل OpenCode كل جلسة في `~/.local/share/opencode/`.
- المتغيرات: `OPENCODE_BIN` (وإلا `PATH`، ثم `~/.opencode/bin/opencode`)، و`OPENCODE_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 600). ويُمرر `OPENCODE_CONFIG` كما هو إلى OpenCode.

مثال على نموذج محلي عبر Ollama، في `~/.config/opencode/opencode.json`:

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

يوقف `reasoningEffort: "none"` التفكير الذي يفعله Ollama افتراضيًا في هذه النماذج، والذي لا يمكن لملف Modelfile تعطيله. مقاسًا على جملة من ست كلمات: 919 رمز تفكير و68 ثانية بدون هذا الخيار، مقابل 9 رموز معه.

### نحو أكثر من 400 نموذج: `--use_openrouter`

OpenRouter هو موجه يُحاسب بحسب الاستخدام عبر رصيد موحد، أمام نماذج تستضيفها جهات خارجية — بما في ذلك النماذج الصينية المفتوحة التي لا يوفرها أي مزود آخر هنا.

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` إلزامي. يقوم فحص مسبق، يُنفذ قبل أي فوترة، بضبط خاصيتين للتوجيه:

- **يتم تقديم النموذج نفسه بواسطة عشرات المضيفين بسقوف متباينة** — في `z-ai/glm-5.3-flash`، هناك 23 مضيفًا أحدهم بسقف محدد بـ 2,048 رمز إخراج. يقرأ الفحص المسبق `/api/v1/models/{modèle}/endpoints`، ويستبعد المضيفين الذين يقل سقفهم عن 8,000 رمز إخراج أو ذوي الحالة المتدهورة، ويثبت البقية باستخدام `allow_fallbacks: false`.
- **تتم فوترة الاستدلال بسعر رموز الإخراج** — 107 رموز مقابل رمزين في استجابة "OK" من `z-ai/glm-5.2`. يتم إيقافه افتراضيًا؛ وتتلقى النماذج التي تفرضه أدنى مستوى جهد تقبله، حيث يمكن للقيمة الافتراضية في الدليل أن تستنفد سعة الإخراج قبل اكتمال الترجمة. ويظل لـ `--reasoning_effort` الأولوية.

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- تُستمد نافذة السياق من الدليل. يُرفض أي نموذج يقل سياقه عن 16,400 رمز قبل أي استدعاء: 8,400 للمحث والمقطع، و8,000 للإخراج كحد أدنى.
- يؤدي وجود معرف غير موجود في الدليل، أو تعذر الوصول إلى الدليل، أو عدم توفر مضيف يستوفي السقف المطلوب، إلى إيقاف الأمر.
- يُعد `finish_reason=length` مع مخرجات فارغة ميزانية استهلكها الاستدلال، وليس اقتطاعًا: وتميز الرسالة ذلك.
- `--eco` ليس له أي تأثير.
- المتغيرات: `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>)، و`OPENROUTER_BASE_URL` (الافتراضي `https://openrouter.ai/api/v1`، ويُشترط `https://`)، و`OPENROUTER_TIMEOUT` (الافتراضي 900)، و`OPENROUTER_PREFLIGHT_TIMEOUT` (الافتراضي 30).

### ملاحظة الترجمة

يضيف `--add_translation_note` ملاحظة، إما في `bottom` (افتراضي)، أو `top` (بعد البيانات الوصفية) أو `both` (`--note_position`)، بالتنسيق `legacy` (فقرة بخط عريض، افتراضي) أو `marker` (`--note_format`). التنسيق `marker` هو تعريف مرجعي غير مرئي في Markdown،
`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`،
متبوعًا باقتباس بخط عريض: قابل للقراءة على GitHub، وقابل للاستخدام أثناء البناء بواسطة إضافة remark.

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## قياسات تفصيلية

جميع القياسات عبارة عن ترجمات نُفذت فعليًا باستخدام `aipmt`، إلى أربع عشرة لغة: en، وes، وde، وit، وpt، وnl، وpl، وsv، وro، وja، وko، وzh، وar، وhi.
يعد **المكتوبة** الملفات التي سمحت أدوات الحماية بتمريرها؛ بينما يعد **بدون تباين** تلك التي لم يرصد فيها `scripts/compare_structure.py` أي شيء — العدد نفسه من الأقسام، والعناوين الفرعية، والروابط، وعناوين URL المميزة، وكتل الأكواد، والأكواد المضمنة، وأسطر الجداول، وكتل الاقتباس، والكلمات المكتوبة بخط عريض.

"بدون تباين" تعني "لم يُرصد شيء"، ولا تعني "متطابق": إذ تقوم أداة المقارنة بعدّ العناصر دون قراءة محتواها. فهي لا تنبه إلى عنوان محذوف من المستوى الرابع، ولا إلى نص تم استبداله داخل كود مضمن، ولا إلى راية تم تبديلها، ولا إلى رابط داخلي وُضع بقوس زائد، `[texte]((#ancre))`، بحيث لم يعد يؤدي إلى أي مكان — كما أنها لا تُقيّم اللغة.

### ما لا تعنيه هذه القياسات

- **ليست تصنيفًا شاملًا**: يقدم OpenRouter وحده أكثر من أربعمائة
  نموذج، ولم يُقَس سوى قرابة خمسة عشر منها.
- **مُدد زمنية استرشادية**: من ثلاث إلى ست ترجمات بالتوازي بحسب
  الحملات، كما يختلف معدل نقل بيانات المزود خلال اليوم.
- **ملاحظات مرتبطة بتاريخها**: تتغير النماذج تحت الاسم نفسه، كما أن
  وثائقكم تختلف عن وثائقنا.

لإعادة إجراء القياس على وثائقكم، على نسخة مجمّدة من الملف:

```bash
aipmt --file reference.md --target_dir out/ --source_lang fr --target_lang ja --use_gemini --force
aipmt --file veille.mdx   --target_dir out/ --source_lang fr --target_lang ja --use_gemini --news --force
python scripts/compare_structure.py reference.md out/reference-ja.md
# « structure identique », ou la liste des écarts — sortie 0 si identique, 1 sinon
```

## المساهمة

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

كلا السطرين ضروريان: دون `pip install -e .`، يرد `python -m aipmt`
بـ `No module named aipmt`.

أدوات الجودة، اختيارية لكن يُوصى بها:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```
