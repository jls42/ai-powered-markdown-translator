يترجم ملفات Markdown من لغة إلى أخرى مع الحفاظ على البنية: كتل الأكواد البرمجية، الأكواد المضمنة، عناوين URL، المراسي، الجداول، والـ front matter. إحدى عشرة طريقة لاستدعاء النماذج — خمس واجهات برمجة تطبيقات (APIs)، وأربعة اشتراكات بدون فوترة حسب الاستخدام، وموجّهان — مع قياس منشور لما يحافظ عليه كل نموذج فعلياً.

## باختصار

- **إحدى عشرة طريقة للمزودين** : واجهات برمجة تطبيقات (APIs) لكل من OpenAI وMistral وClaude وGemini وGrok؛ واشتراكات ChatGPT (Codex) وGrok وGoogle (Antigravity) وClaude (Claude Code) بدون فوترة حسب الاستخدام؛ وموجّها OpenCode (مفتوح المصدر، مجاني أو محلي) وOpenRouter (أكثر من 400 نموذج).
- **لا أخطاء بسبب رمز مفقود** : تُستبدل كتل الأكواد البرمجية، الأكواد المضمنة، عناوين URL، المراسي والاقتباسات برموز نائبة قبل الاستدعاء وتُفحص عند العودة. وإذا فُقد أي منها، فلن يُكتب الملف.
- **المستندات الطويلة** : تقسيم حسب سياق نافذة النموذج.
- **وضع `--news`** : حماية الاقتباسات الإنجليزية وإدارة العلامات حسب اللغة، لمقالات الرصد والمتابعة.
- **وضع `--eco`** : نماذج سريعة وأقل تكلفة.
- **ملاحظة ترجمة** اختيارية، في الأعلى أو الأسفل أو كليهما.

## التثبيت

```bash
pip install ai-powered-markdown-translator     # ou : pipx install ai-powered-markdown-translator
aipmt --help                                   # ou : python -m aipmt --help
```

Python 3.11 أو أحدث. للتثبيت من المستودع، راجع [المساهمة](#المساهمة).

## الإعداد

تُقرأ المفاتيح من ثلاثة أماكن، حسب الأولوية من الأعلى إلى الأدنى؛ ولا يملأ كل مكان إلا ما تركه السابق فارغاً.

|     | أين                                           | الغرض                                 |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | متغيرات البيئة                                | CI، الحاويات، استثناء لمرة واحدة      |
| 2   | `.env` الخاص بالدليل الحالي (أو دليل أب) | مفتاح خاص بمشروع ما                   |
| 3   | `~/.config/aipmt/.env`                        | يُثبّت مرة واحدة، ويسري في كل مكان    |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

يُقبل `GEMINI_API_KEY` بدلاً من `GOOGLE_API_KEY`. ويتبع ملف المستخدم `XDG_CONFIG_HOME` (مسار مطلق فقط) و`%APPDATA%` على Windows. وفي حال عدم وجود مفتاح، يعرض الأمر المواقع الثلاثة.

**لا يمكن لملف `.env` الخاص بالمشروع إعادة توجيه الاستدعاءات ولا اختيار البرنامج المُشغَّل.** فهو يوفّر مفاتيح فقط، ولا يحدد أبداً وجهة أو ملفاً تنفيذياً: حيث يتم تجاهل أي متغير يبدأ بـ `_BASE_URL` أو `_API_BASE` أو `_ENDPOINT` أو `_BIN` (`CODEX_BIN`، `GROK_BIN`، `OPENCODE_BIN`، `AGY_BIN`)، و`GROK_HOME`، والبروكسيات (`HTTP_PROXY`، `HTTPS_PROXY`، `ALL_PROXY`)، ومخازن الشهادات (`SSL_CERT_FILE`، `SSL_CERT_DIR`، `REQUESTS_CA_BUNDLE`، `CURL_CA_BUNDLE`)، و`XDG_CONFIG_HOME` / `APPDATA` مع ظهور تحذير. فلا ينبغي لأي مستودع مستنسخ أن يتمكن من الاستيلاء على مفتاحك، ولا أن يجعلك تشغّل برنامجه الخاص عند أول ترجمة. يُقرأ هذا الملف أيضاً بدون استيفاء: حيث لا ينسخ `NOM=${OPENAI_API_KEY}` المفتاح فيه. ضع هذه المتغيرات في البيئة أو في `~/.config/aipmt/.env`.

المتغيرات الاختيارية: `XAI_BASE_URL` (القيمة الافتراضية `https://api.x.ai/v1`)، و`CLAUDE_TIMEOUT` (ثوانٍ لكل استدعاء، القيمة الافتراضية 900)، و`CODEX_BIN`، و`CODEX_TIMEOUT` (القيمة الافتراضية 600)، و`GROK_BIN`، و`GROK_HOME` (القيمة الافتراضية `~/.grok`)، و`GROK_TIMEOUT` (القيمة الافتراضية 900)، و`GROK_TRANSLATE_SANDBOX`، و`AGY_BIN`، و`AGY_TIMEOUT` (القيمة الافتراضية 900)، و`OPENCODE_BIN`، و`OPENCODE_TIMEOUT` (القيمة الافتراضية 600)، و`OPENROUTER_BASE_URL` (`https://` مطلوب)، و`OPENROUTER_TIMEOUT` (القيمة الافتراضية 900)، و`OPENROUTER_PREFLIGHT_TIMEOUT` (القيمة الافتراضية 30). كل منها مفصل في القسم الخاص بمزوده.

## الخطوات الأولى

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

ينتج عن ترجمة `document.md` إلى الإسبانية الملف `document-es.md` داخل `--target_dir`؛ ومع `--include_model`، ينتج `document-es-gpt-6.1-terra.md`. يصبح الامتداد دائماً `.md` — ينتج عن `article.mdx` الملف `article-en.md` — ما عدا مع `--keep_filename`، الذي يحتفظ بالاسم الأصلي. ويتم تخطي أي ترجمة موجودة مسبقاً بدون `--force`.

رموز الخروج: `0` إذا نجح كل شيء أو تم تخطيه، و`1` إذا تعثر أي ملف (تظهر القائمة في مخرج الأخطاء)، و`2` إذا كان السبب يعود إلى الإعدادات. لا يُكتب الملف الفاشل أبداً، حتى لو فشلت عملية الكتابة نفسها: حيث يُكتب المحتوى بجانبه أولاً ثم يُعاد تسميته. ويكفي إعادة التشغيل.

أهم النقاط المستخلصة:

- **الترجمة المرفوضة ليست ترجمة تالفة.** عندما يُفقد رمز نائب عند الاستجابة، لا يُكتب الملف وتُحسب اللغة على أنها مرفوضة. هذا ما حدث مع Grok في المقال: فُقدت أربعة أكواد مضمنة وثلاثة عناوين URL منذ المقطع الأول في أنظمة الكتابة غير اللاتينية الخمسة.
- **يمكن للنموذج أن يرفض مستنداً كاملاً بسبب جملة واحدة.** يترجم Opus 5.5 ملف README هذا دون أدنى خطأ، لكنه يرفض مقالات الرصد بالكامل: إذ توقف حواجز الحماية الخاصة به الاستجابة بسبب خبر موجز في علم الأحياء. لا يُكتب الملف، وتوضح أداة aipmt السبب.
- **شبكة الأمان هذه لا تشمل العناوين ولا الجداول ولا الـ front matter ولا النصوص.** فالنموذج الذي يحذف قسماً يعيد ملفاً تقوم الأداة بكتابته دون تردد — كما هو الحال مع Mistral. هذه العناصر لا يمكن استبدالها برمز نائب، وآليات الحراسة الحالية لا تفحصها؛ وتكتشف أداة `scripts/compare_structure.py` القسم المفقود، ولكن بعد فوات الأوان.
- **لم يحصل Grok على تقييم في ملف README هذا** : فقد انتهت صلاحية جلسة CLI الخاصة به بعد اثنتي عشرة لغة، من بينها إحدى عشرة لغة دون أي أخطاء. الحملة التي تنقطع لا يتم تقييمها.
- **كثافة المستند أهم من نوع اللغة.** ينجح Grok مع ملفات README العادية ويتعثر أمام مقال مليء بالروابط، حتى في اللغة الهولندية.

التواريخ والمستندات: عُمِل على قياس عمود «ملف README هذا» في 9 سبتمبر 2026 بناءً على مراجعة ثابتة من هذا الملف (785 سطراً، 285 كوداً مضمناً، 89 سطراً في الجداول)، عُدلت لاحقاً — باستثناء سطري Antigravity وClaude Code اللذين تم قياسهما في 26 سبتمبر على المراجعة المنشورة مع الإصدار 1.14.0، وهي أقصر (600 سطر، 257 كوداً مضمناً، 85 سطراً في الجداول)، وأسطر Claude Sonnet 5.5 وHaiku 5.5 وHaiku 4.5 عبر واجهة برمجة التطبيقات (API) التي تم قياسها في 18 أكتوبر على المراجعة نفسها. ويأتي عمود «مقال رصد مكثف» من حملة يومي 4 و5 سبتمبر على مقال مؤلف من 589 سطراً، باستثناء سطر Grok الذي أُعيد قياسه في 9 سبتمبر على إصدار آخر من ملف الرصد نفسه، وسطري Antigravity وClaude Code اللذين تم قياسهما في 26 سبتمبر على المقال نفسه، وتلك الأسطر الثلاثة لـ Claude في 18 أكتوبر. وتتوفر الجداول الكاملة والمدد الزمنية وبروتوكول الاختبار في [القياسات التفصيلية](#قياسات-مفصلة).

## مزودو الخدمة (Providers)

### عبر واجهة برمجة التطبيقات (API): OpenAI وMistral وClaude وGemini وGrok

```bash
aipmt --source_dir content/fr --target_dir content/en --target_lang en             # OpenAI, défaut
aipmt --use_mistral --source_dir content/fr --target_dir content/es --target_lang es
aipmt --use_claude  --source_dir content/fr --target_dir content/de --target_lang de
aipmt --use_gemini  --source_dir content/fr --target_dir content/ja --target_lang ja
aipmt --use_grok    --source_dir content/fr --target_dir content/pt --target_lang pt
```

`--eco` يبدّل إلى الفئة الاقتصادية لكل مزود.

| المزود      | الجودة (الافتراضية)                                                  | اقتصادي (`--eco`)         |
| ----------- | -------------------------------------------------------------------- | --------------------------------- |
| OpenAI      | `gpt-6.1-terra`                                                      | `gpt-6-luna`                   |
| Claude      | `claude-sonnet-5-5`                                                      | `claude-haiku-5-5`                   |
| Mistral     | `mistral-large-latest`                                                      | `mistral-small-latest`                   |
| Gemini      | `gemini-4-hydrogen`                                                      | `gemini-3.1-flash-lite`                   |
| Codex       | `gpt-6.1-sol` (أيضًا `gpt-5.6-sol`، و`terra` و`luna` عبر `--model`) | `gpt-6-luna`              |
| Grok API    | `grok-4.7`                                                      | `grok-4.3`                   |
| Grok CLI    | `grok-4.7`                                                      | نفسه — `--eco` بدون تأثير |
| Antigravity | `gemini-3.8-flash-medium`                                                      | `gemini-3.8-flash-low`                   |
| Claude Code | `sonnet`، جهد `low`                                 | نفسه — `--eco` بدون تأثير |
| OpenCode    | `--model provider/modèle` إلزامي                                               | نفسه — `--eco` بدون تأثير |
| OpenRouter  | `--model fournisseur/modèle` إلزامي                                               | نفسه — `--eco` بدون تأثير |

تتبع الإعدادات الافتراضية أحدث جيل من كل مزود، بعد قياسه قبل اعتماده: GPT-6 لدى OpenAI، وGemini 4 Hydrogen لدى Google، وGrok 4.7 لدى xAI منذ الإصدار 1.19.0. وتظل النماذج السابقة مقبولة عبر `--model` (`gpt-5.6-terra`، `gemini-3.8-flash`، `grok-4.6`...)، وكذلك Gemini 4 Argon وCarbon، وهي الفئة الأعلى من Google. يضبط aipmt بنفسه جهد التفكير لنماذج GPT وGrok، والذي يُعطَّل في `--eco`، ويفرضه `--reasoning_effort`؛ بينما يتلقى Gemini دائمًا أدنى مستوى يقبله.
أي عطل عابر في واجهة برمجة تطبيقات Gemini (أخطاء 503، 429، انتهاء المهلة) يؤدي إلى إعادة محاولة الاستدعاء حتى ثلاث مرات، بعد 10 ثم 20 ثم 40 ثانية. ويتم التخلي عن أي محاولة تظل بلا استجابة بعد 5 دقائق، ثم إعادة محاولتها بالطريقة نفسها: فالخادم الصامت يتسبب في إخفاق المقطع خلال عشرين دقيقة تقريبًا على الأكثر، بدلًا من التعليق بلا نهاية.

### عبر اشتراك ChatGPT: `--use_codex`

يقود واجهة سطر الأوامر (CLI) الرسمية لـ Codex: تُخصم الترجمة من حصة اشتراك ChatGPT، دون الحاجة إلى مفتاح API أو فواتير حسب الاستخدام.

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- يتم البحث عن الملف التنفيذي في `CODEX_BIN`، ثم `PATH`، ثم حزمة `openai-codex-cli-bin`. ولا تتم قراءة `~/.codex/auth.json` مطلقًا.
- تتم إزالة `OPENAI_API_KEY` و`CODEX_API_KEY` من بيئة العملية الفرعية: وجود أي مفتاح لن يؤدي إطلاقًا إلى التبديل إلى API.
- يكلف كل مقطع «رسالة» واحدة على الأقل من نافذة الـ 5 ساعات — واثنتين إذا فشل التحقق منه وأُعيدت المحاولة. تعلن OpenAI، على سبيل التقدير، عن 250-2,000 رسالة/5 ساعات لـ `gpt-5.6-luna`، النموذج الاقتصادي حتى الإصدار 1.18.0، و10-100 لـ `gpt-5.6-sol` في خطة Plus.
- يمر `--model gpt-5.6-sol`، الافتراضي حتى الإصدار 1.16.3، و`--model gpt-5.6-terra` و`--model gpt-5.6-luna` أيضًا عبر الاشتراك.
- خطأ 429 من الخادم لا يتسبب في فقدان الملف: يعيد Codex الاتصال تلقائيًا، وينتظر aipmt نهاية الجولة، وإذا استمر خطأ 429، يُستأنف المقطع بعد 30 ثم 60 ثانية. أما النموذج الذي لا يحق للحساب استخدامه فيُرجع خطأ 400 «model is not supported when using Codex with a ChatGPT account».
- أبطأ من API، وتزداد الفجوة مع زيادة حجم المستند: في ملف README هذا، بلغ الوسيط 6 دقائق و46 ثانية لكل لغة مع `gpt-5.6-sol`، مقابل 36 ثانية لـ `gemini-3.7-flash`.
- مرفوض في بيئات CI (عند تحديد `CI` أو `GITHUB_ACTIONS`): يتم توثيق الاشتراك عبر ملف جلسة شخصي، لا ينبغي وجوده على بيئة تشغيل (runner) مشتركة.
- المتغيرات: `CODEX_BIN`، `CODEX_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 600).

### عبر اشتراك Grok: `--use_grok_cli`

المبدأ نفسه ينطبق مع CLI الرسمي Grok Build، عبر اشتراك SuperGrok أو X Premium+.

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --file README.md --target_dir . --target_lang pl
```

- **عزل أضعف من Codex.** لا تعمل بيئة الرمل (sandbox) الخاصة بنظام التشغيل لـ Grok على العديد من أجهزة Linux الحديثة (AppArmor، مقابس بيئات تشغيل الحاويات)، والملف التعريفي الذي يتعذر تطبيقه يبدأ بصمت دون عزل. لذلك لا يطلب السكريبت أي ملف تعريفي افتراضيًا، ويعلن ذلك، ويعتمد على قواعد `--deny` الخاصة بـ CLI، بما في ذلك القاعدة الشاملة `*` — وهي الطبقة الوحيدة التي ترفض البدء بدلًا من إزالة الحماية دون إشعار. يتطلب `GROK_TRANSLATE_SANDBOX=read-only` بيئة الرمل لنظام التشغيل، ويفشل بدء التشغيل إذا عجز الجهاز عن الوفاء بذلك.
- الحصة أسبوعية ومشتركة مع Chat وImagine وVoice، ولا يوجد أمر لقراءتها: يمكن لدفعة معالجة أن تستهلك الاستخدام الحواري دون أي إشعار.
- المتغيرات: `GROK_BIN`، `GROK_HOME` (دليل CLI، الافتراضي `~/.grok`)، `GROK_TIMEOUT` (الافتراضي 900)، `GROK_TRANSLATE_SANDBOX`.

### عبر اشتراك Google: `--use_antigravity`

المبدأ نفسه مع `agy`، أداة CLI الرسمية لـ Antigravity: لمشتركي Google AI Pro أو Ultra، تُخصم الترجمة من حصة الاشتراك بدلًا من محاسبتها بالرمز (token). هذا هو المسار الوحيد نحو هذه الحصة: لم يعد Gemini CLI يخدم هذه الحسابات منذ 18 يونيو 2026 ([إعلان](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/))، كما أن SDK الخاص بـ Antigravity لا يقبل سوى مفتاح API أو مشروع Google Cloud.

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **لا يظل أي مسار مدفوع مفتوحًا.** لا يتلقى agy من بيئتك سوى قائمة مغلقة من المتغيرات — `PATH`، واللغة والمنطقة الزمنية، والطرفية، والهوية، والبروكسيات والشهادات، وناقل الجلسة — دون أي مفتاح: إذ تتسبب عدة متغيرات تابعة له في تحويل الاستدعاء بصمت دون عرض أي شيء (أمر تم قياسه: أحدها يرسل المستند إلى بوابة تابعة لجهة خارجية، وآخر إلى مشروع Google Cloud خاضع للفوترة)، وقائمة الحظر كانت تغفل بعضها في كل مراجعة. قبل أي مقطع، يجب أن يوضح `agy -p /config`، الذي لا يستهلك أي حصة، أن أرصدة الذكاء الاصطناعي المدفوعة معطلة، دون مفتاح API أو مشروع Google Cloud — ويُعد غياب الإعداد بمثابة رفض — وإلا فلن تتم ترجمة أي شيء؛ كما يجب أن يشهد سجل كل استدعاء بعد ذلك على وجود الاشتراك (`authMethod=consumer`)، وإلا تُرفض الاستجابة.
- **العزل.** يعمل كل استدعاء في دليل شخصي خاص ومؤقت، مع وكيل ترجمة بلا أدوات: إعداداتك وقواعدك وإضافاتك وخوادم MCP وخطافات agy لا تدخل إليه، ولا يُضاف أي شيء إلى سجلك، ويظل الاتصال في سلسلة المفاتيح (keychain) التي لا يقرؤها aipmt مطلقًا. إذا تعذر العثور على الوكيل، يتراجع agy بصمت إلى وكيل البرمجة الخاص به وأدواته: ويجب أن يؤكد سطر كامل من السجل استخدام الوكيل الصحيح — ولا يُعد المستند الذي يقتبس هذه الرسالة بديلًا عنه — وإلا فسيتم الرفض.
- **المنصات**: Linux، في جلسة تحتوي على سلسلة مفاتيح (ناقل جلسة D-Bus، خدمة Secret Service)؛ نظام macOS مدعوم، دون اختباره في القياسات. مرفوض على Windows، حيث لا يقرأ agy المتغيرات التي تعزل كل استدعاء، وعلى Linux دون ناقل جلسة — جلسات SSH، الحاويات، الخوادم: إذ يخزن agy رمزه هناك في ملف ضمن `~/.gemini` يحجبه العزل. ويأتي الرفض قبل أي تشغيل مع ذكر سببه، بدلًا من الانتظار لمدة دقيقة للحصول على رمز تسجيل الدخول.
- **النماذج**: تلك المتاحة في `agy models`. تحمل نماذج Gemini مستوى الجهد في اسمها (`gemini-3.8-flash-medium`...): يُرفض أي اسم بدون لاحقة قبل الاستدعاء، ويكون `--reasoning_effort` بلا تأثير. الافتراضي هو `gemini-3.8-flash-medium`، و`gemini-3.8-flash-low` في وضع `--eco`، منذ أن توقف agy عن تقديم Gemini 3.7 Flash؛ الحملة الاختبارية التي حددت الإعداد الافتراضي مشروحة في [قياسات مفصلة](#قياسات-مفصلة). يتشارك Gemini 4 Hydrogen (`gemini-4-hydrogen-low`...) حصة 3.8 Flash ويستهلك أكثر منها: 0.95 نقطة من نافذة الـ 5 ساعات لملف README هذا عند الجهد المتوسط، مقابل 0.32. ولـ Claude وGPT-OSS حصتهما الخاصة، وهي أصغر بكثير: حوالي 1% من نافذة الـ 5 ساعات لكل استدعاء تم قياسه، مقابل 0.05% لـ Flash. أما Gemini 4 Argon فله حصته الأسبوعية الخاصة: يستهلك ملف README هذا 1.35% منها.
- **الحصة**: لكل مجموعة، توجد نافذة لمدة 5 ساعات وأخرى أسبوعية، بالتناسب مع تكلفة الرموز (tokens). تم قياسها على حساب المؤلف: حوالي 16 نقطة من نافذة الـ 5 ساعات لكل مليون حرف مصدر في `gemini-3.8-flash-medium`، و14 في `gemini-3.7-flash-medium`، و7 إلى 8 عند الجهد المنخفض — وبالتالي فإن ملف README يحتوي على 40,000 حرف يكلف أكثر بقليل من نصف نقطة. أما الحد الأسبوعي فيعتمد على الفئة. تتبع إعادة المحاولة ما يحدده agy كقابل لإعادة المحاولة؛ وبخلاف ذلك، لا تتم أبدًا إعادة محاولة نافذة مستنفدة: بل تتسبب في فشل كل ملف حتى يحين وقت إعادة الضبط الذي يعرضه `/usage`.
- **أبطأ من API**: في مقال القياسات الكثيف، بلغ الوسيط 3 دقائق و59 ثانية لكل لغة في `gemini-3.8-flash-medium` و3 دقائق و14 ثانية في `gemini-3.7-flash-medium`، مقابل دقيقة واحدة و18 ثانية لـ Gemini 3.7 Flash عبر API.
- **المقاطعة**: يؤدي استخدام Ctrl-C، أو إغلاق الطرفية، إلى إيقاف agy مع الأمر بدلًا من تركه يُكمل دورته مستهلكًا حصتك؛ وينطبق الأمر نفسه على Codex وGrok CLI وOpenCode. وتحت `nohup`، تستمر الترجمة.
- مرفوض في بيئات CI (عند تحديد `CI` أو `GITHUB_ACTIONS`): فالاتصال يعيش داخل سلسلة مفاتيح شخصية. على بيئة التشغيل (runner)، استخدم `--use_gemini` مع `GOOGLE_API_KEY`.
- المتغيرات: `AGY_BIN` (وإلا `PATH`، ثم `~/.local/bin/agy`)، `AGY_TIMEOUT` (بالثواني لكل مقطع، متضمنًا وقت البدء، الافتراضي 900).

**شروط الاستخدام: حسابك هو المسؤول.** تحظر [شروط Antigravity](https://antigravity.google/terms) (القسم 6) و[الأسئلة الشائعة](https://antigravity.google/docs/faq/) الخاصة بها الوصول إلى الخدمة عبر برنامج تابع لجهة خارجية باستخدام مصادقة Antigravity — مذكور فيها Claude Code وOpenClaw وOpenCode — تحت طائلة تعليق الحساب. لا يقرأ aipmt الرمز المميز (token) ولا يعيد استخدامه: بل يقوم بتشغيل الملف التنفيذي الرسمي في [الوضع غير المرئي (headless mode)](https://antigravity.google/docs/cli/headless/) الذي توثقه Google للسكريبتات وبيئات CI. وقد اعتبر أحد مسؤولي Google أنه من "المعتاد" تشغيل `agy -p` من سكريبت محلي للعمل الشخصي ([المنتدى الرسمي، 25 سبتمبر 2026، إجابة غير ملزمة](https://discuss.ai.google.dev/t/is-using-the-official-agy-cli-through-a-local-mcp-server-with-third-party-ai-agents-permitted/184829))؛ ولا يوجد أي نص قانوني يحسم مسألة أداة موزعة مثل هذه.

**المستندات العامة فقط.** وفقًا للقسم 5 من الشروط نفسها، يمكن استخدام التبادلات — المطالبات، والردود، والبيانات الوصفية — لتحسين منتجات Google والتعلم الآلي ومراجعتها من قبل مراجعين بشريين، بما في ذلك الاشتراكات المدفوعة. يتم إلغاء الاشتراك عبر إعداد `enableTelemetry` غير الموثق التأثير، والذي لا يضعه aipmt؛ ولا تنتقل إعدادات agy الخاصة بك إلى بيئته المعزولة. لا تمرر أي معلومات سرية عبره.

### عبر اشتراك Claude: `--use_claude_code`

المبدأ نفسه ينطبق مع `claude`، وهي أداة CLI الرسمية لـ Claude Code، في وضع `-p`: بالنسبة لمن
يدفع مقابل Claude Pro أو Max، تُقتطع الترجمة من حصة
الاشتراك بدلاً من فوترتها بحسب الـ tokens. ويجب عدم الخلط بينها وبين
`--use_claude`، وهي واجهة برمجة التطبيقات لـ Anthropic، التي تُفوتر حسب الاستخدام.

```bash
claude                                   # une fois : /login avec le compte de l'abonnement
aipmt --use_claude_code --file README.md --target_dir . --target_lang en
```

- **لا يبقى أي مسار مدفوع مفتوحاً، وكل استدعاء يثبت ذلك.** لا
  يتلقى Claude Code من بيئتك سوى قائمة مغلقة من المتغيرات — لا
  مفتاح API، ولا رمز مميز (token)، ولا مزود سحابي، ولا علامة لجلسة Claude Code
  التي قد يُطلق منها aipmt. قبل المقطع الأول، يجب أن
  يُظهر `claude auth status` اتصال الاشتراك، دون مفتاح Console، ويجب أن يشهد بذلك
  `/usage`، الذي لا يستهلك أي حصة؛ ويشهد كل استدعاء بدوره على ذلك في
  حدث التهيئة الخاص به، وإلا يُرفض الرد.
- **عطّل «الاستخدام الإضافي» (extra usage)** (في claude.ai، الإعدادات → الاستخدام)
  ليظل الاستخدام مجانياً بصفر يورو: إذا تم تفعيله، فإنه يتولى الأمر عند نفاد النافذة
  ويقوم بالفوترة دون إظهار أي خطأ. يوقف aipmt الترجمة فور إشارة
  بيان الحصة في أحد الاستدعاءات إلى ذلك، لكن ذلك الاستدعاء يكون قد حُسب بالفعل.
- **حصة مشتركة مع جلسات Claude Code الخاصة بك.** يبلغ كل استدعاء
  عن استخدام نوافذ الـ 5 ساعات والأسبوع؛ وفي حال تجاوز 80%
  (`AIPMT_CLAUDE_MAX_UTILIZATION`)، لا يتم إطلاق أي مقطع إضافي، لتجنب
  استنزاف ما تحتاجه لعملك.
- **العزل.** يعمل كل استدعاء دون أدوات، في دليل خاص
  وقابل للحذف، في وضع بدون تخصيص: لا يتم تحميل `CLAUDE.md` الخاصة بك، ولا المكونات الإضافية،
  أو الخطافات (hooks)، أو خوادم MCP، أو الإعدادات، ولا يُحفظ أي شيء من
  الجلسة. وتُعطّل المرفقات: يظل أي `@chemin` في وثيقتك
  مجرد نص ولا يفتح أي ملف (تم التحقق بالقياس).
- **النماذج**: `sonnet` افتراضياً، مع مستوى جهد `low`، وفي `--eco` أيضاً:
  `--eco` لا يغير شيئاً في هذا المسار. وبحسب القياسات على الوثائق نفسها، فإن `haiku`
  أبطأ بمرتين — فهو يفكر دون إمكانية منعه — مقابل
  تكلفة تكاد لا تنخفض، كما أن `opus` يرفض محتويات في علم الأحياء (النقطة
  التالية). كلاهما يظل متاحاً عبر `--model`؛ وتتبع هذه الأسماء المستعارة
  أحدث نموذج في عائلتها. يُرفض `fable` ومتغيرات `[1m]`،
  لأنها تعتمد على أرصدة مدفوعة. يضبط `--reasoning_effort` الجهد،
  وهو ما لا تستفيد منه الترجمة إطلاقاً: إذ إن التفكير المقاس شبه معدوم.
- **يرفض Opus بعض محتويات علم الأحياء.** حواجز الأمان لديه
  أكثر صرامة من تلك الموجودة في Sonnet، وتحذر رسالة الخطأ من Anthropic من أنها
  «قد تصنف أحياناً الأعمال المجاورة لأبحاث الأحياء» (can sometimes flag biology-research-adjacent work). المقاس: أدى خبر
  رصد مقتضب حول 279 جزيئاً مُولداً إلى رفض المقال في اللغات
  الأربع عشرة بأكملها. لا يُكتب أي شيء: يرفض aipmt الرد المبتور، ويحدد
  حواجز الأمان وينصح بـ `--model sonnet`.
- مرفوض في بيئات CI (عند تحديد `CI` أو `GITHUB_ACTIONS`) وعلى Windows (غير مقاس).
- المتغيرات: `AIPMT_CLAUDE_BIN` (وإلا `PATH`، ثم `~/.local/bin/claude`)،
  و`AIPMT_CLAUDE_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 900)،
  و`AIPMT_CLAUDE_MAX_UTILIZATION` (الافتراضي 0.8)، و`CLAUDE_CONFIG_DIR` (حساب
  Claude Code، ولا يؤخذ أبداً من ملف `.env` للمشروع)؛ أدلة العمل ضمن
  `XDG_CACHE_HOME/aipmt/claude-code` (الافتراضي `~/.cache`).

**شروط الاستخدام: حسابك هو المسؤول.** لا تمنع
[الصفحة القانونية لـ Claude Code](https://code.claude.com/docs/en/legal-and-compliance)
«المستخدم النهائي من تسجيل الدخول إلى الملف التنفيذي غير المعدل لـ Claude Code
باستخدام اشتراك Claude الخاص به»: وهذا ما يفعله aipmt، حيث يُطلق
الملف التنفيذي الرسمي ولا يقرأ الرمز المميز أبداً. لكن Anthropic «لا تسمح
للمطورين الخارجيين [...] بتوجيه الطلبات عبر بيانات اعتماد خطط Free أو Pro أو Max
نيابة عن مستخدميهم»، وتفضل مفتاح API للأدوات
الخارجية، «بما في ذلك المشاريع مفتوحة المصدر»، وتحتفظ بالحق في احتساب
استخدامها خصماً من الأرصدة المدفوعة
([مساعدة Claude](https://support.claude.com/en/articles/13189465-logging-in-to-your-claude-account)).
ولا يوجد أي نص يفصل في حالة أداة موزعة تقوم بتشغيل الملف التنفيذي.

**البيانات**: في حسابات Free وPro وMax، ينطبق تدريب النماذج
أيضاً على Claude Code عندما يسمح إعداد الخصوصية بذلك
([صفحة البيانات](https://code.claude.com/docs/en/data-usage)). لا يحتفظ aipmt
بأي نصوص جلسات محلياً (`--no-session-persistence`). لا تُمرر
أي معلومات سرية عبره.

### نحو المزود الذي تختاره: `--use_opencode`

[OpenCode](https://opencode.ai) هو وكيل برمجة مفتوح المصدر (MIT)
يوجه الطلبات نحو المزودين المهيئين بداخله: مفتاح API، أو اشتراك، أو
بوابة OpenCode Zen (نماذج مجانية، دون حساب)، أو نموذج محلي. وقد تم
قياس مسارين بالكامل هنا: Zen وOllama.

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` إلزامي: فبدونه، سيعود OpenCode تلقائياً إلى نموذج مجاني
قد تُستخدم محادثاته في التدريب، وهذا الخيار لا يُتخذ
نيابة عنك.

العزل في كل استدعاء:

- تهيئة مضمنة (inline)، لها الأولوية على تهيئتك، تحدد وكيلاً `aipmt`
  تُرفض جميع أدواته (`permission: { "*": "deny" }`)، مع تعطيل مشاركة
  الجلسة، و`--pure`، ودون `--auto` إطلاقاً؛
- دليل عمل فارغ ومؤقت، مع وضع `OPENCODE_DISABLE_PROJECT_CONFIG` و
  `OPENCODE_DISABLE_CLAUDE_CODE` — فبدونهما، يحقن OpenCode في
  الموجه ملف `AGENTS.md` الخاص بالدليل الحالي و`~/.claude/CLAUDE.md`. ويظل ملف
  `~/.config/opencode/AGENTS.md` العام محقوناً، إذ لا يتيح OpenCode
  استبعاده؛
- عقد المخرجات: رمز الخروج 0، لا حدث `error`، لا استدعاء
  لأي أداة، الخطوة الأخيرة في `stop`، نص غير فارغ، وتحميل الوكيل `aipmt`
  بشكل فعلي — فالاسم غير المعروف لـ `--agent` لا يجعل OpenCode يفشل، بل
  يعود بصمت إلى وكيل البرمجة؛
- لا يُرسل أي مفتاح لـ `aipmt`، باستثناء `OPENCODE_API_KEY`، وهو مفتاح
  OpenCode نفسه. يتم تكوين المزودين داخل OpenCode، وليس في
  ملف `.env` الخاص بـ `aipmt`.

معلومات يجب معرفتها:

- النماذج المجانية في Zen متغيرة، وذات حدود غير موثقة،
  وقد تُستخدم محادثاتها في التدريب: وهي مناسبة للتوثيق
  العام، لا للمحتوى الخاص.
- يجب أن يوفر النموذج المحلي سياقاً لا يقل عن 16 ألف token، حيث
  تصل المقاطع إلى 16,000 حرف. وغالباً ما يحدد Ollama هذا السياق بـ 4,096: استخدم
  ملف `Modelfile` مع `PARAMETER num_ctx 32768`.
- `--eco` ليس له أي تأثير؛ يُمرر `--reasoning_effort` كما هو كـ
  `--variant` لـ OpenCode.
- يسجل OpenCode كل جلسة في `~/.local/share/opencode/`.
- المتغيرات: `OPENCODE_BIN` (وإلا `PATH`، ثم `~/.opencode/bin/opencode`)،
  و`OPENCODE_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 600). ويُمرر `OPENCODE_CONFIG`
  كما هو إلى OpenCode.

مثال على نموذج محلي عبر Ollama، في `~/.config/opencode/opencode.json`:

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

يوقف `reasoningEffort: "none"` التفكير الذي يفعله Ollama افتراضياً في هذه
النماذج، والذي لا يمكن لملف Modelfile إلغاء تفعيله. وبحسب القياس على جملة من
ست كلمات: 919 token تفكير و68 ثانية بدون الخيار، مقابل 9 tokens بوجوده.

### نحو أكثر من 400 نموذج: `--use_openrouter`

OpenRouter هو موجه يُفوتر حسب الاستخدام، برصيد موحد، أمام
نماذج يستضيفها أطراف خارجية — بما في ذلك النماذج الصينية المفتوحة التي لا
يوفرها أي مزود آخر هنا.

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` إلزامي. ويقوم فحص مسبق، يُنفذ قبل أي فوترة، بضبط
خاصيتين في التوجيه:

- **النموذج نفسه يُقدم عبر عشرات المستضيفين بحدود قصوى
  مختلفة** — في `z-ai/glm-5.3-flash`، هناك 23 مستضيفاً أحدهم بحد أقصى يبلغ
  2,048 token للمخرجات. يقرأ الفحص المسبق `/api/v1/models/{modèle}/endpoints`،
  ويستبعد المستضيفين الذين يقل حد مخرجاتهم عن 8,000 token أو ذوي الحالة المتدهورة،
  ويثبت الباقين باستخدام `allow_fallbacks: false`.
- **يُفوتر التفكير وفق تسعيرة المخرجات** — 107 tokens مقابل 2 في
  رد «OK» من `z-ai/glm-5.2`. وهو معطل افتراضياً؛ والنماذج
  التي تفرضه تتلقى أدنى مستوى جهد تقبله، لأن القيمة الافتراضية
  في الدليل قد تستنفد المخرجات قبل اكتمال الترجمة.
  تظل الأولوية لـ `--reasoning_effort`.

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- تأتي نافذة السياق من الدليل. يُرفض النموذج الذي يقل عن 16,400 token
  قبل أي استدعاء: 8,400 للموجه والمقطع، و8,000 للمخرجات
  كحد أدنى.
- يؤدي غياب المعرف (slug) من الدليل، أو تعذر الوصول إلى الدليل، أو عدم
  وجود مستضيف يفي بالحد الأدنى إلى إيقاف الأمر.
- إن ظهور `finish_reason=length` مع مخرجات فارغة يعني نفاد الميزانية بسبب
  التفكير، وليس اقتطاعاً: وتوضح الرسالة ذلك.
- `--eco` ليس له تأثير.
- المتغيرات: `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>)،
  و`OPENROUTER_BASE_URL` (الافتراضي `https://openrouter.ai/api/v1`، و`https://`
  مطلوب)، و`OPENROUTER_TIMEOUT` (الافتراضي 900)، و`OPENROUTER_PREFLIGHT_TIMEOUT`
  (الافتراضي 30).

### ملاحظة الترجمة

يضيف `--add_translation_note` ملاحظة، في `bottom` (الافتراضي)، أو `top` (بعد
الـ front matter)، أو `both` (`--note_position`)، بتنسيق `legacy` (فقرة بخط
عريض، الافتراضي) أو `marker` (`--note_format`). التنسيق `marker` هو
تعريف مرجعي غير مرئي في Markdown،
`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`،
يتبعه اقتباس بخط عريض: مقروء على GitHub، وقابل للاستخدام أثناء البناء بواسطة
إضافة remark.

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## قياسات مفصلة

جميع القياسات ناتجة عن ترجمات نُفذت فعلياً باستخدام `aipmt`، نحو
أربع عشرة لغة: en، es، de، it، pt، nl، pl، sv، ro، ja، ko، zh، ar، hi.
يشير عمود **مكتوبة** إلى عدد الملفات التي سمحت أدوات الحماية بتمريرها؛ بينما يشير **بلا فوارق**
إلى الملفات التي لم يسجل فيها `scripts/compare_structure.py` أي فارق — أي نفس عدد
الأقسام، والعناوين الفرعية، والروابط، وعناوين URL الفريدة، والكتل البرمجية،
والأكواد المضمنة، وصفوف الجداول، وكتل الاقتباس، والكلمات المكتوبة بخط عريض.

عبارة «بلا فوارق» تعني «لم يتم رصد أي شيء»، ولا تعني «متطابق تماماً»: إذ تقوم أداة
المقارنة بعدّ العناصر دون قراءة محتواها. فهي لا تبلغ عن عنوان من
المستوى 4 تم حذفه، ولا عن نص كود مضمن تم استبداله، ولا عن علم تم
تغييره، ولا عن رابط داخلي أُنشئ بقوس زائد،
`[texte]((#ancre))`، لم يعد يؤدي إلى أي مكان — كما أنها لا تقيّم جودة
اللغة.

### ما ليست عليه هذه القياسات

- **ليست تصنيفًا شاملاً**: يوفر OpenRouter بمفرده أكثر من أربعمائة
  نموذج، وقد تم قياس نحو خمسة عشر نموذجًا منها فقط.
- **مُدد زمنية استرشادية**: من ثلاث إلى ست ترجمات بالتوازي وفقًا
  للحملات، كما أن سرعة المزود تتفاوت على مدار اليوم.
- **ملاحظات محددة بتاريخ معين**: تتغير النماذج تحت الاسم نفسه،
  ومستنداتكم ليست مستنداتنا.

لإعادة إجراء القياس على مستنداتك، باستخدام نسخة مجمّدة من الملف:

```bash
aipmt --file reference.md --target_dir out/ --source_lang fr --target_lang ja --use_gemini --force
aipmt --file veille.mdx   --target_dir out/ --source_lang fr --target_lang ja --use_gemini --news --force
python scripts/compare_structure.py reference.md out/reference-ja.md
# « structure identique », ou la liste des écarts — sortie 0 si identique, 1 sinon
```

## المساهمة

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

كلا السطرين ضروريان: فبدون `pip install -e .`، يجيب `python -m aipmt`
بـ `No module named aipmt`.

أدوات الجودة، اختيارية لكن يوصى بها:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```

تتم إعادة توليد الترجمات الـ 28 للمستودع (README وCHANGELOG، بأربع عشرة لغة)
باستخدام `./regen_translations.sh --force` — مع Codex و`gpt-6.1-sol` عبر
اشتراك ChatGPT الافتراضي، بأربع ترجمات بالتوازي. ويقوم `REGEN_PROVIDER` و`REGEN_MODEL`
بتغيير المسار: يظل `antigravity` ضمن الاشتراك، اشتراك
Google، ويمر دون استثناء؛ بينما يتم رفض أي واجهة برمجة تطبيقات مدفوعة (`openai`، `gemini`،
`grok`، `openrouter`) دون `REGEN_ALLOW_PAID_API=1`؛
ويضع `REGEN_JOB_TIMEOUT` حدًا أقصى لكل مهمة (600 ثانية، و1800 ثانية مع Codex و
Antigravity). تتوفر تفاصيل الأدوات في `CLAUDE.md`.
