مترجم لملفات Markdown يستخدم **OpenAI** و**Mistral AI** و**Claude (Anthropic)** و**Google Gemini** و**Grok (xAI)** — عبر API، أو ضمن حصة اشتراك ChatGPT (Codex) أو Grok من دون فوترة حسب الاستخدام، أو عبر **OpenCode**، الوكيل مفتوح المصدر، مع المزوّد الذي تختاره: نموذج محلي (Ollama)، أو مجاني، أو اشتراك (GitHub Copilot…) أو مفتاح.

يترجم هذا البرنامج النصي المكتوب بلغة Python ملفات Markdown من لغة مصدر إلى لغة مستهدفة مع الحفاظ على التنسيق وكتل الشيفرة وبيانات front matter الوصفية.

## الميزات الرئيسية

- **تعدد المزوّدين**: ‏5 واجهات API ‏(OpenAI وMistral وClaude وGemini وGrok) + أداتا CLI تعملان بالاشتراك من دون فوترة حسب الاستخدام — Codex ‏(ChatGPT) وGrok — بالإضافة إلى OpenCode ‏(مفتوح المصدر، MIT) مع أي مزوّد مُعَدّ في OpenCode، بما في ذلك نموذج محلي
- **نماذج 2026**: ‏GPT-5.6 Terra وClaude Sonnet 5 وGemini 3.7 Flash
- **الوضع الاقتصادي**: الخيار `--eco` لاستخدام نماذج أسرع وأقل تكلفة
- **ملف واحد**: الخيار `--file` لترجمة ملف واحد فقط
- **التجزئة الذكية**: معالجة النصوص الطويلة وفق حدود الرموز الخاصة بكل نموذج
- **الحفاظ على الشيفرة**: تُحفَظ كتل الشيفرة والشيفرة المضمّنة (`` `...` ``)
- **اسم الملف**: الخيار `--keep_filename` للاحتفاظ بالاسم الأصلي
- **وضع الأخبار**: الخيار `--news` لحماية الاقتباسات الإنجليزية والتعامل مع الأعلام في المقالات الإخبارية
- **إعدادات .env**: دعم ملف `.env` لمفاتيح API
- **ملاحظة الترجمة**: إضافة اختيارية لملاحظة في نهاية المستند

## التثبيت

### لاستخدام الأداة

```bash
pip install ai-powered-markdown-translator
```

يصبح الأمر `aipmt` متاحًا بعد ذلك في كل مكان. إذا لم يكن مجلد البرامج النصية
الخاص بـPython موجودًا ضمن `PATH` لديك، فإن `python -m aipmt` يؤدي المهمة نفسها
تمامًا. يلزم Python 3.10 أو إصدار أحدث.

لإجراء تثبيت معزول عن بقية حزمك:

```bash
pipx install ai-powered-markdown-translator
```

### للمساهمة في المشروع

تظل نسخة المستودع المستنسخة ضرورية للتطوير: فهي تضم الاختبارات
والترجمات الـ28 وجميع أدوات الجودة.

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

يمثل `requirements.txt` **قفلًا مثبّت الإصدارات بالكامل** يعكس بدقة
البيئة المختبرة. أما الحدود المنشورة في `pyproject.toml` فهي
أوسع عمدًا، إذ لا تفرض شيئًا على حزمك الأخرى.

### أدوات الجودة (اختيارية لكن موصى بها)

يستخدم المشروع [`pre-commit`](https://pre-commit.com) لمنع إيداع شيفرة سيئة التنسيق أو تتضمن ثغرة أمنية أو سرًا. التثبيت:

```bash
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # hooks lourds avant chaque push
```

الخطافات النشطة: ‏ruff ‏(فحص+تنسيق)، وshellcheck ‏(bash)، وprettier ‏(markdown/yaml/json)، وLizard ‏(التعقيد)، وdetect-secrets ‏(مفاتيح API)، وmypy ‏(التحقق التدريجي من الأنواع)، وOpengrep ‏(SAST)، وpip-audit ‏(ثغرات CVE في الاعتماديات)، وunittest. راجع قسم _Quality / pre-commit_ في `CLAUDE.md` للاطلاع على التفاصيل.

## الإعداد

يُبحث عن المفاتيح في **ثلاثة مواضع**، من الأعلى إلى الأدنى أولوية.
ولا يملأ كل موضع سوى القيم التي تركها سابقه فارغة.

|     | الموضع                                            | الغرض                             |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | متغيرات البيئة                     | ‏CI والحاويات والتجاوز المؤقت |
| 2   | `.env` في المجلد الحالي (أو أحد المجلدات الأب) | مفتاح خاص بمشروع            |
| 3   | `~/.config/aipmt/.env`                        | **يُثبَّت مرة واحدة ويعمل في كل مكان**   |

أبسط خيار بعد `pip install` هو الثالث:

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

يتبع هذا الملف `XDG_CONFIG_HOME` عندما يشير المتغير إلى مسار مطلق
(وإلا فيُتجاهل، وفقًا لما تنص عليه المواصفات)، ويتبع `%APPDATA%`
على Windows.

يظل الخيار الثاني مفيدًا عندما يكون للمستودع مفتاحه الخاص: إذ يتغلب ملف `.env` في جذره
حينئذٍ على إعدادات المستخدم من دون تعديلها. كما يتغلب متغير
مُعرّف مسبقًا في البيئة على كليهما:

```bash
export OPENAI_API_KEY='une-clé-le-temps-d-une-commande'
```

إذا لم يُعثر على أي مفتاح، فلن يعرض الأمر تتبعًا للاستدعاءات، بل
يسرد المواضع الثلاثة بمساراتها الدقيقة.

يُقبل `GEMINI_API_KEY` بديلًا عن `GOOGLE_API_KEY` ‏(وفق اصطلاح AI
Studio). المتغيرات الاختيارية: `XAI_BASE_URL` ‏(نقطة نهاية xAI، والقيمة الافتراضية
`https://api.x.ai/v1`)، و`CLAUDE_TIMEOUT` ‏(عدد الثواني لكل استدعاء Anthropic، والقيمة الافتراضية
900)، و`CODEX_BIN` / `CODEX_TIMEOUT`، و`GROK_BIN` / `GROK_HOME` / `GROK_TIMEOUT`،
و`GROK_TRANSLATE_SANDBOX` ‏(راجع قسم Grok CLI)، و`OPENCODE_BIN` /
`OPENCODE_TIMEOUT` ‏(راجع قسم OpenCode)، و`OPENROUTER_BASE_URL` /
`OPENROUTER_TIMEOUT` / `OPENROUTER_PREFLIGHT_TIMEOUT` ‏(راجع قسم
OpenRouter). أما بالنسبة إلى
`regen_translations.sh`: فهناك `REGEN_PROVIDER` ‏(القيمة الافتراضية `codex`، ضمن الاشتراك)،
و`REGEN_MODEL`، و`REGEN_ALLOW_PAID_API` ‏(تجاوز إلزامي لاستخدام API
خاضعة للفوترة)، و`REGEN_JOB_TIMEOUT` ‏(الحد الأقصى لكل مهمة، والقيمة الافتراضية 600 ثانية، و1 800 ثانية على Codex).

## الاستخدام

### ترجمة ملف واحد

```bash
aipmt --file 'document.md' --target_dir 'output/' --target_lang 'en'
```

### ترجمة مجلد

```bash
# Avec OpenAI (défaut: gpt-5.6-terra)
aipmt --source_dir 'content/fr' --target_dir 'content/en' --source_lang 'fr' --target_lang 'en'

# Avec Mistral AI
aipmt --use_mistral --source_dir 'content/fr' --target_dir 'content/es' --target_lang 'es'

# Avec Claude
aipmt --use_claude --source_dir 'content/fr' --target_dir 'content/de' --target_lang 'de'

# Avec Gemini
aipmt --use_gemini --source_dir 'content/fr' --target_dir 'content/ja' --target_lang 'ja'

# Avec Codex (sur le quota de l'abonnement ChatGPT, sans facturation à l'usage)
aipmt --use_codex --eco --file 'README.md' --target_dir . --target_lang 'it'

# Avec Grok par l'API xAI (nécessite XAI_API_KEY, facturé à l'usage)
aipmt --use_grok --source_dir 'content/fr' --target_dir 'content/pt' --target_lang 'pt'

# Avec Grok sur le quota de l'abonnement Grok (nécessite `grok login`)
aipmt --use_grok_cli --eco --file 'README.md' --target_dir . --target_lang 'pl'

# Avec OpenRouter (routeur vers ~430 modèles ; --model obligatoire)
aipmt --use_openrouter --model 'z-ai/glm-5.2' --source_dir 'content/fr' --target_dir 'content/en' --source_lang 'fr' --target_lang 'en'

# Avec OpenCode (open source), vers le fournisseur de votre choix — ici un modèle local Ollama
aipmt --use_opencode --model ollama/qwen2.5:7b --file 'README.md' --target_dir . --target_lang 'nl'
```

### الترجمة ضمن اشتراك ChatGPT ‏(`--use_codex`)

لا يستهلك هذا المزوّد أي مفتاح API: فهو يتحكم في أداة Codex CLI الرسمية بالوضع
غير التفاعلي، ولذلك تُحتسب الترجمة من حصة اشتراك
ChatGPT المدفوع مسبقًا (Plus وPro وBusiness…). وهذه هي الطريقة الوحيدة التي توثقها
OpenAI لهذا الاستخدام؛ فرُموز `~/.codex/auth.json` لا تصادق على
استدعاءات API Platform، كما أن هذا البرنامج النصي لا يقرأها أصلًا.

**المتطلبات الأساسية:**

```bash
# Le binaire `codex`, au choix :
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo)
npm install -g @openai/codex       # ou l'installation npm globale

codex login                        # connexion avec le compte ChatGPT
```

يُبحث عن الملف التنفيذي بهذا الترتيب: المتغير `CODEX_BIN`، ثم `PATH`،
ثم حزمة Python ‏`openai-codex-cli-bin`. وقد استُبعدت الأخيرة عمدًا
من `requirements.txt`، إذ يبلغ حجمها نحو 250 ميغابايت، وهو ما كان سيفرضها على جميع
المستخدمين من أجل مزوّد اختياري.

**ما ينبغي معرفته:**

- **لا يُستخدم أي مفتاح API.** يُزال `OPENAI_API_KEY` و`CODEX_API_KEY`
  من بيئة العملية الفرعية، مما يضمن أن وجود مفتاح
  في `.env` لن يحوّل الترجمة أبدًا إلى فوترة حسب
  الاستخدام.
- **كل مقطع = «رسالة محلية» واحدة** ضمن نافذة الخمس ساعات للخطة.
  استخدم `--eco` ‏(النموذج `gpt-5.6-luna`، من 250 إلى 2 000 رسالة/5 ساعات ضمن Plus)
  بدلًا من نموذج الجودة (`gpt-5.6-sol`، من 10 إلى 100 رسالة/5 ساعات).
- **أبطأ** من استدعاء API: يستغرق ملف README كامل نحو 45 ثانية، مقابل
  بضع ثوانٍ عند الاستدعاء المباشر.
- **مرفوض في CI** ‏(عند تعريف `CI` أو `GITHUB_ACTIONS`): تتم مصادقة الاشتراك
  بواسطة ملف جلسة شخصي، ونقله إلى مشغّل
  مشترك يعني إيداع هوية قابلة لإعادة الاستخدام من قِبل كل ما
  يعمل عليه. استخدم مفتاح API في هذه الحالة.
- متغيرات البيئة: `CODEX_BIN` ‏(المسار الصريح للملف التنفيذي) و
  `CODEX_TIMEOUT` ‏(عدد الثواني لكل مقطع، والقيمة الافتراضية `600`).

### الترجمة ضمن اشتراك Grok ‏(`--use_grok_cli`)

المبدأ نفسه المتبع في `--use_codex`، باستخدام أداة CLI الرسمية **Grok Build**: تُحتسب
الترجمة من اشتراك Grok ‏(SuperGrok / X Premium+) بدلًا
من فوترتها حسب الرمز.

```bash
curl -fsSL https://x.ai/cli/install.sh | bash   # le binaire `grok`
grok login                                      # ou `grok login --device-code`
```

**العزل — يُرجى القراءة قبل الاستخدام.** هذا المزوّد **أضعف
بنيويًا** من `--use_codex`، وهذا مقصود:

- يعمل Codex ضمن `--sandbox read-only`، وهو حد يفرضه النظام.
- لا يمكن تطبيق sandbox الخاص بـGrok على كثير من أجهزة Linux
  الحديثة: إذ يحظر AppArmor مساحات أسماء المستخدمين غير المميّزة منذ Ubuntu
  24.04، وتفشل قائمة حظر مقابس وقت تشغيل الحاويات إذا كان
  `/run/podman` ضمن `0700`. وفي المقابل، يبدأ ملف تعريف **مدمج** تعذّر
  تطبيقه **من دون عزل وبصمت**.
- لذلك لا يطلب البرنامج النصي أي ملف تعريف افتراضيًا، و**لا يتراجع بصمت
  أبدًا**، بل يعرض تحذيرًا. ويعتمد العزل على قواعد
  `--deny` الخاصة بأداة CLI ‏(ومنها قاعدة الالتقاط الشامل `*`)، وهي الطبقة الوحيدة المقاسة
  وفق مبدأ _fail-closed_؛ إذ تتسبب قاعدة غير معروفة في رفض بدء التشغيل بدلًا من
  إزالة الحماية من دون إشعار.
- **لفرض** sandbox الخاص بنظام التشغيل: `GROK_TRANSLATE_SANDBOX=read-only`.
  سيفشل بدء التشغيل إذا تعذر على الجهاز الالتزام به، وهذا هو
  السلوك المقصود.

**الحصة**: مجموعة Grok **أسبوعية ومشتركة** مع Chat وImagine و
Voice، ولا يوجد أمر يتيح قراءتها. ولذلك قد تستهلك المعالجة الدفعية
جزءًا من استخدامك للمحادثات من دون أي تنبيه؛ ومن هنا يأتي
قصر التزامن على 2 وإظهار تحذير في `regen_translations.sh`.

متغيرات أخرى: `GROK_BIN` ‏(مسار الملف التنفيذي)، و`GROK_TIMEOUT` ‏(القيمة الافتراضية 900 ثانية).

لإعادة توليد الترجمات الـ28:

```bash
# Défaut : Codex sur l'abonnement ChatGPT, modèle qualité gpt-5.6-sol, 0 € à l'usage
./regen_translations.sh --force

# Le modèle éco de Codex, si le volume l'impose
REGEN_MODEL=gpt-5.6-luna ./regen_translations.sh --force

# Sur le quota de l'abonnement Grok
REGEN_PROVIDER=grok_cli ./regen_translations.sh --force

# Une API facturée (openai, gemini, grok, openrouter) est REFUSÉE sans cette dérogation nommée
REGEN_PROVIDER=openai REGEN_ALLOW_PAID_API=1 ./regen_translations.sh --force

# Via OpenCode, vers le modèle de son choix (REGEN_MODEL obligatoire, 2 jobs en parallèle)
REGEN_PROVIDER=opencode REGEN_MODEL=ollama/qwen2.5:7b ./regen_translations.sh --force

# Via OpenRouter : API facturée, donc dérogation ET modèle obligatoires
REGEN_PROVIDER=openrouter REGEN_ALLOW_PAID_API=1 REGEN_MODEL=z-ai/glm-5.2 ./regen_translations.sh --force
```
### الترجمة باستخدام OpenCode، عبر المزوّد الذي تختاره (`--use_opencode`)

[OpenCode](https://opencode.ai) هو وكيل برمجي **مفتوح المصدر (MIT)** يعمل في
الطرفية. وهو ليس مزوّد نماذج، بل **موجّه** إلى المزوّدين الذين
ضبطتهم داخل OpenCode نفسه: مفتاح API، أو اشتراك، أو بوابة OpenCode Zen — التي تتيح نماذج مجانية **من دون حساب** — أو
نموذج **محلي**. يشغّل هذا الـ provider ‏`opencode run` في الوضع غير التفاعلي
ويحصر الاستدعاء في جولة واحدة فقط، من دون أي أداة.

قيس اثنان من هذه المسارات هنا من البداية إلى النهاية: **بوابة Zen** و
**Ollama** محليًا. أما المسارات الأخرى التي يعلن عنها OpenCode ‏(GitHub Copilot وLM Studio و
llama.cpp)، فيفترض أن تعمل بحكم التصميم، لأن الـ provider لا يتواصل
إلا مع OpenCode — لكنها لم تُختبر، ولا يذكر ملف README هذا سوى ما
تم التحقق منه.

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles disponibles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur ou un abonnement
```

`--model` **إلزامي**، بالصيغة `provider/modèle`. إن OpenCode ليس
مزوّدًا، ولا يُختار أي خيار افتراضي نيابة عنك: فالخيار الاحتياطي الخاص به
سيكون نموذجًا مجانيًا قد تُستخدم محادثاته في التدريب.

```bash
# Gratuit, sans compte ni clé (passerelle Zen ; données utilisables pour l'entraînement)
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en

# Local, hors ligne, sans aucune clé (Ollama déclaré dans ~/.config/opencode/opencode.json)
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de

# Sur un abonnement déjà payé (après `opencode auth login`)
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

**العزل — ما يفعله السكربت عند كل استدعاء:**

- يعرّف إعداد مضمّن (`OPENCODE_CONFIG_CONTENT`)، له الأولوية على إعدادك،
  وكيلًا باسم `aipmt` تكون فيه **جميع الأدوات مرفوضة**
  (`permission: { "*": "deny" }`): فلا يستطيع النموذج القراءة أو الكتابة أو
  تشغيل أمر — ووفق القياس، لا يحاول ذلك أصلًا. تُعطّل مشاركة الجلسة،
  ويستبعد `--pure` الإضافات الخارجية، وليس `--auto` مطلقًا.
- يعمل الاستدعاء داخل **مجلد مؤقت وفارغ**، مع المفتاحين
  `OPENCODE_DISABLE_PROJECT_CONFIG` و`OPENCODE_DISABLE_CLAUDE_CODE`: فمن
  دونهما، يحقن OpenCode في كل prompt ملف `AGENTS.md` للمجلد الحالي
  وملف `~/.claude/CLAUDE.md` الخاص بك — ووفق القياس، طُبّقت على الترجمة تعليمة «اختم كل إجابة
  بكلمة BANANA» كانت موضوعة في ملف `AGENTS.md`. أما
  القواعد العامة في `~/.config/opencode/AGENTS.md` فتظل مطبّقة:
  لا يتيح OpenCode استبعادها.
- يشترط عقد الإخراج كل ما يلي معًا: رمز خروج 0، وعدم وجود أي حدث
  `error`، وعدم وجود أي استدعاء لأداة، وانتهاء الخطوة الأخيرة بالحالة `stop`، ووجود نص
  غير فارغ، وتحميل الوكيل فعليًا — فالاسم `--agent` غير المعروف لا يؤدي إلى
  فشل OpenCode، بل **يعود بصمت** إلى وكيل البرمجة مع
  تفعيل الأدوات. كما أن `exit 0` لا يثبت شيئًا هنا.
- **لا يُمرَّر أي مفتاح خاص بـ aipmt** إلى العملية الفرعية (بنفس آلية التصفية
  المستخدمة مع Codex وGrok)، باستثناء واحد محدد بالاسم: `OPENCODE_API_KEY`،
  وهو مفتاح OpenCode نفسه (Zen وGo). تُضبط إعدادات المزوّدين داخل
  OpenCode ‏(`opencode auth login` و`opencode.json`)، وليس داخل `.env` الخاص بـ aipmt.

**ما ينبغي معرفته:**

- **نماذج Zen المجانية هي نماذج «stealth» أو نماذج مساهمين**،
  وهي متغيرة وحدودها غير موثقة، وقد تُستخدم محادثاتها في
  التدريب: لذا فهي مثالية للتوثيق العام، وينبغي تجنبها للمحتوى
  الخاص. وفق القياس: يترجم `opencode/mimo-v2.5-free` ملف README هذا في
  تمريرة واحدة؛ أما `opencode/big-pickle` فأبطأ، وقد ظل طلبان متزامنان عليه
  بلا استجابة.
- **يجب أن يوفّر النموذج المحلي نافذة سياق لا تقل عن 16 k** — إذ يصل حجم المقاطع
  إلى 16 000 محرف — بينما يضبط Ollama غالبًا القيمة الافتراضية على 4 096.
  مع Ollama: ملف `Modelfile` يتضمن `PARAMETER num_ctx 32768`، ثم
  `ollama create`. وتتبع الجودةُ النموذجَ: فقد عكس نموذج 7B ترتيب قائمة
  وأفسد سياج كتلة برمجية في ملف تجريبي، بينما حافظ نموذج من
  البوابة على كل شيء.
- لا يؤثر `--eco` في شيء (فالنموذج هو المحدد في `--model`)؛
  ويُمرَّر `--reasoning_effort` كما هو بوصفه `--variant` خاصًا بـ OpenCode، ولا ينبغي
  طلبه إلا إذا كان النموذج يعرفه.
- يسجّل OpenCode الجلسات في قاعدة بياناته
  (`~/.local/share/opencode/`)، شأنها شأن أي جلسة OpenCode.
- متغيرات البيئة: `OPENCODE_BIN` (المسار الصريح للملف التنفيذي،
  وإلا يُستخدم `PATH` ثم `~/.opencode/bin/opencode`) و`OPENCODE_TIMEOUT`
  (عدد الثواني لكل مقطع، والقيمة الافتراضية `600`). ويُحترم `OPENCODE_CONFIG` إذا
  صدّرته.

**مثال مقاس: نموذج محلي عبر Ollama** ‏(RTX 3060 بسعة 12 Go، وذاكرة RAM بسعة 62 Go، وOllama 0.33.3)

```bash
curl -fsSL https://ollama.com/install.sh | sh   # conserve les modèles déjà téléchargés
ollama pull gpt-oss:20b                         # 13 Go, Apache 2.0 — le seul modèle local retenu ici

# Sous 24 Go de VRAM, Ollama plafonne le contexte à 4 096 tokens, et son API OpenAI-compatible
# ne permet pas de le régler par requête : on le fixe dans un Modelfile.
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

ثم الـ provider داخل `~/.config/opencode/opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

`reasoningEffort: "none"` ليس تفصيلًا ثانويًا: يفعّل Ollama الاستدلال
افتراضيًا في هذه النماذج، ولا يستطيع Modelfile تعطيله. وفق قياس
أُجري عبر OpenCode: من دون هذا الخيار، تستهلك عبارة «القطة نائمة على السجادة» 919 token
للاستدلال و68 s؛ ومعه، 9 tokens.

```bash
aipmt --use_opencode --model ollama/gpt-oss-20b-32k --news --keep_filename \
  --add_translation_note --file article.mdx --target_dir out/ --target_lang en
```

النتائج على تدوينة فعلية من 589 سطرًا (140 رابطًا، و21 قسمًا،
و3 اقتباسات إنجليزية محمية بواسطة الوضع `--news`)، باستخدام الأمر نفسه وثلاثة
نماذج:

| النموذج                                   | المدة       | البنية                                                  | الاختلافات                                                                                    |
| ---------------------------------------- | ----------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `opencode/mimo-v2.5-free` ‏(Zen، مجاني) | 4 min 26 s  | مطابقة للمصدر                                      | لا شيء                                                                                     |
| `ollama/gemma4-12b-32k` ‏(محلي)          | 10 min 10 s | الروابط وURL والجداول والوسوم والخط العريض والكود المضمّن مطابقة | سطر اقتباس مختلق (🇺🇸 + إعادة صياغة)، ونسبة اقتباس مكررة               |
| `ollama/qwen3.5-9b-32k` ‏(محلي)          | 8 min 18 s  | الروابط وURL والجداول والوسوم مطابقة                    | سطر اقتباس مختلق، وبعض الخط العريض والأكواد المضمّنة المضافة، ومقطع أُعيدت معالجته |

منذ ذلك الحين، **استُبعد** هذان النموذجان المحليان: فتصرف حر واحد في كل مقال
يكفي لاستبعاد نموذج من الترجمة المنشورة. كما استُبعدت خمسة نماذج أخرى
للأسباب نفسها أو بسبب تجاوز المهلة (`gemma4:26b-a4b`،
`qwen3.6:35b-a3b`، و`ministral-3:14b`، و`mistral-small3.2`، و`hy-mt2:7b`). ولم يُحتفظ إلا بـ
`gpt-oss:20b` — وحتى هذا يترك مقاطع بالفرنسية في
مقال كثيف، راجع جدول النماذج الموصى بها.

أثناء الترجمة المحلية: بلغ استخدام GPU ‏98% واستهلاكه 170 W، وشُغلت 10 Go من VRAM
(للنموذج وذاكرة cache بسعة 32 k tokens، من دون تفريغ أي شيء إلى RAM)، واستخدم
خادم Ollama ‏7.5 Go من RAM. يحافظ نموذج يضم من 9 إلى 12 مليار parameter على
البنية، لكنه يأخذ حرية واحدة في كل مقال، بينما لم يأخذ نموذج البوابة
أي حرية: لذا يجب مراجعته قبل النشر، أو تخصيصه للمسودات.

### الترجمة عبر OpenRouter ‏(`--use_openrouter`)

OpenRouter هو **موجّه** أمام أكثر من 400 نموذج تستضيفها جهات خارجية،
وتُحتسب تكلفته بحسب الاستخدام من رصيد واحد. وهو يتيح بمفتاح واحد الوصول إلى نماذج
لا يوفّرها أي provider آخر، ولا سيما النماذج الصينية المفتوحة.

```bash
# --model est OBLIGATOIRE : aucun défaut n'est choisi à votre place
aipmt --use_openrouter --model 'z-ai/glm-5.2' --file README.md \
  --target_dir . --source_lang fr --target_lang en
```

فرضت خاصيتان للتوجيه طريقة التنفيذ، ويمكن قياس كلتيهما:

- **يُقدَّم النموذج نفسه عبر عشرات المستضيفين ذوي الحدود القصوى
  المختلفة.** في `z-ai/glm-5.3-flash`، يوجد 23 مستضيفًا، من بينهم واحد حدّه الأقصى
  2 048 token للإخراج: ومن دون احتياط، كانت ترجمة طويلة واحدة من أصل 23
  تصل مبتورة، عشوائيًا بحسب التوجيه ومن دون أدنى إشارة. يقرأ فحص preflight
  ‏`/api/v1/models/{modèle}/endpoints`، ويستبعد المستضيفين الذين تقل سعة إخراجهم عن 8 000 token
  أو تكون حالتهم متدهورة، ثم يثبّت الباقين باستخدام
  `allow_fallbacks: false` — وإلا يعود الموجّه إلى مستضيف
  مستبعد.
- **يُحتسب الاستدلال بسعر الإخراج.** في الطلب نفسه على
  `z-ai/glm-5.2`، ومع الإجابة «OK»: استُهلك 107 tokens للإكمال وفق إعداد النموذج الافتراضي،
  و2 عند تعطيل الاستدلال. لذلك يُعطّل افتراضيًا في النماذج
  التي تسمح بذلك. أما النماذج التي تفرضه — `reasoning.mandatory`، وعددها 288 من أصل 431
  نموذجًا في الكتالوج — فتتلقى **أدنى مستوى جهد تعلن
  قبولَه**، وليس إعدادها الافتراضي: فإعداد `z-ai/glm-5.3-flash` هو
  `max`، وكان يستنفد 32 768 token للإخراج قبل نهاية
  الترجمة. ولم تكن زيادة السعة لتغيّر شيئًا، لأن مستوى الجهد يخصص
  نسبة مئوية منها. يظل `--reasoning_effort` صاحب الأولوية، ويُبلّغ عن استخدام `none` مع نموذج
  يفرض الاستدلال بدل التحايل عليه.

يعمل فحص preflight وفق مبدأ **الإغلاق عند الفشل** ويعرض ما احتفظ به:

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

يؤدي غياب slug من الكتالوج، أو تعذر الوصول إلى الكتالوج، أو عدم وجود مستضيف
يستوفي الحد الأقصى إلى إيقاف الأمر قبل احتساب أي تكلفة.

نقاط أخرى:

- تؤخذ نافذة السياق من الكتالوج، لا من ثابت: وتتكيّف
  التجزئة معها فعليًا، بما في ذلك النماذج ذات 4 095 token.
- لا يؤثر `--eco` في شيء (فالنموذج هو المحدد في `--model`).
- لا يعني `finish_reason=length` المصحوب بإخراج فارغ حدوث بتر، بل يعني أن
  الاستدلال استهلك الميزانية؛ وتوضح الرسالة ذلك لأن الحالتين
  تتطلبان إجراءين متعاكسين.
- متغيرات البيئة: `OPENROUTER_API_KEY` (المفتاح، على
  <https://openrouter.ai/keys>)، و`OPENROUTER_BASE_URL` (القيمة الافتراضية
  `https://openrouter.ai/api/v1`، مع اشتراط `https://`)، و`OPENROUTER_TIMEOUT`
  (عدد الثواني لكل استدعاء، والقيمة الافتراضية `900`)، و`OPENROUTER_PREFLIGHT_TIMEOUT`
  (القيمة الافتراضية `30`).

### ملاحظة الترجمة: المواضع والصيغ

باستخدام `--add_translation_note`، يستطيع الـ translator وضع الملاحظة في الأعلى أو الأسفل أو في الموضعين معًا، وتقديمها إما بصيغة نصية بسيطة (متوافقة مع الإصدارات السابقة) أو بصيغة `marker` قابلة للاستهلاك بواسطة إضافة Markdown.

**الموضع** (`--note_position`):

- `bottom` (الافتراضي): ملاحظة في نهاية الملف، كما كان الحال تاريخيًا.
- `top`: ملاحظة مُدرجة **بعد frontmatter ‏YAML** ‏(لضمان أمان Astro Content Collections وgray-matter وغيرها).
- `both`: ملاحظة مُدرجة في الأعلى والأسفل معًا (استدعاء LLM واحد فقط، ويُعاد استخدام المحتوى في الموضعين).

**الصيغة** (`--note_format`):

- `legacy` (الافتراضية): فقرة بخط عريض `**...**` — بسلوك مطابق تمامًا للإصدار v1.8، byte-for-byte. متوافقة مع Hugo وGitHub وGitLab وأي renderer لـ Markdown.
- `marker`: تعريف link reference غير مرئي في Markdown ‏(`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`)، يتبعه blockquote بخط عريض. يمكن قراءته مباشرة على GitHub وGitLab، واستثماره أثناء build بواسطة إضافة remark في Astro لإنتاج لافتة منسقة (راجع مدونة jls42.org).

```bash
# Compatibilité legacy (rien ne change vs v1.8)
aipmt --file article.mdx --target_lang en --add_translation_note

# Format marker, note en haut uniquement (Astro)
aipmt --file article.mdx --target_lang en \
    --add_translation_note --note_format marker --note_position top

# Format marker en haut ET en bas
aipmt --file article.mdx --target_lang en \
```

## ما النماذج التي تثبت جدارتها

النموذج الذي يترجم فقرةً جيدًا لا يحافظ بالضرورة على بنية
مستند كامل. تأتي هذه القياسات من **ترجمات نُفِّذت فعليًا**
باستخدام الأمر المذكور أعلاه، على ثلاث مجموعات من
المستندات وأربع عشرة لغة مستهدفة: en، es، de، it، pt، nl، pl، sv، ro، ja،
ko، zh، ar، hi.

هناك عمودان، ولا يشيران إلى الشيء نفسه. يحصي **المكتوبة** الترجمات
التي اكتملت بنجاح — أي إن وسائل الحماية في السكربت من الإخفاق الصامت
سمحت بتمرير الملف. أما **بلا اختلاف** فيحصي الترجمات التي تتطابق بنيتها
مع المصدر: الأقسام نفسها، والروابط نفسها، وعناوين URL نفسها، والكتل نفسها،
والأكواد المضمنة نفسها، والجداول نفسها، والاقتباسات نفسها، والأعلام نفسها.

### ما نستخلصه من ذلك

- **لم تفقد ثلاثة نماذج أي معلومة قط** في المستندين
  الكثيفين: `gemini-3.7-flash`، و`gpt-5.6-sol` عبر اشتراك ChatGPT،
  و`z-ai/glm-5.2` عبر OpenRouter. وكانت اختلافاتها الوحيدة في الوضع القياسي
  زوجًا من `**` لم يُنقل في لغة أو لغتين، ولم تكن قط عنوان URL أو كتلة
  أكواد أو اقتباسًا.
- **العامل الفاصل هو كثافة المستند، وليس وضع `--news`.**
  يفشل Grok عبر الاشتراك 13 مرة من أصل 14 في مقالة المدونة، وينجح في 14
  ملف README عامًا من أصل 16: سبب إخفاقه هو فقدان التماسك في مقطع طويل،
  وقد تحقق ذلك باختبار مضاد — إذ تُرجِم المقطع منفردًا ترجمة صحيحة.
- **الكتابات غير اللاتينية ليست موضع الانقسام المتوقع.** يترك `gpt-oss`
  مقاطع بالفرنسية في الترجمات العربية واليابانية والبولندية **والرومانية أيضًا**؛ ولا يفقد Mistral
  وMiMo الأكواد المضمنة إلا مع الكتابات غير اللاتينية.
- **لا يكلّف تعطيل الاستدلال شيئًا من الجودة.** ينجز `z-ai/glm-5.2`
  أربع عشرة لغة من دون أي اختلاف في الحالتين — مع الاستدلال المفعّل
  افتراضيًا بواسطة الموجّه، ثم مع تعطيله عبر `--use_openrouter` — وبعدد
  أقل بثماني عشرة مرة من رموز المخرجات المفوترة. وهذا هو القياس الذي يبرر
  الإعداد الافتراضي للمزوّد.
- **النموذج البطيء ليس نموذجًا آمنًا.** يستغرق `deepseek-v4-flash-0731` مدة 37
  دقيقة لكل لغة مقابل 4 ترجمات من أصل 14، ويستغرق `qwen3.8-flash` مدة 26 دقيقة
  لنتيجة شبه مثالية، بينما يحقق Gemini نتيجة بلا أخطاء في دقيقة و18 ثانية.

  نموذج على أي شيء بشأن جودته، بل يعني فقط أنه لم يُجرَّب.

- **تعتمد النتيجة على المستند بقدر اعتمادها على النموذج.** ينجح النموذج نفسه

  مستنداتكم إلى لغاتكم المستهدفة، ثم قارنوا البنية — عدد
