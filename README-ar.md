يترجم ملفات Markdown من لغة إلى أخرى مع الحفاظ على
البنية: كتل الكود، والكود المضمّن، وعناوين URL، وروابط الارتساء، والجداول، والترويسة
الأمامية. إحدى عشرة طريقة لاستدعاء نموذج — خمس واجهات API، وأربعة اشتراكات دون
فوترة حسب الاستخدام، وموجّهان — وقياس منشور لما يحافظ عليه كل
نموذج فعليًا.

## نظرة سريعة

- **أحد عشر مسارًا لمزوّدي الخدمة**: واجهات API من OpenAI وMistral وClaude وGemini وGrok؛
  واشتراكات ChatGPT ‏(Codex) وGrok وGoogle ‏(Antigravity) وClaude ‏(Claude
  Code) دون فوترة حسب الاستخدام؛ وموجّها OpenCode (مفتوح المصدر، مجاني أو محلي) وOpenRouter
  (أكثر من 400 نموذج).
- **لا نتائج خاطئة بسبب فقدان رمز**: تُستبدل كتل الكود والكود المضمّن
  وعناوين URL وروابط الارتساء والاقتباسات برموز قبل الاستدعاء،
  ثم يُتحقق منها عند عودة النتيجة. إذا فُقد أي منها، فلا يُكتب الملف.
- **المستندات الطويلة**: تقسيم بحسب نافذة سياق النموذج.
- **وضع `--news`**: حماية الاقتباسات الإنجليزية وإدارة الأعلام بحسب
  اللغة، لمقالات الرصد.
- **وضع `--eco`**: نماذج سريعة وأقل تكلفة.
- **ملاحظة ترجمة** اختيارية، في الأعلى أو الأسفل أو كليهما.

## التثبيت

```bash
pip install ai-powered-markdown-translator     # ou : pipx install ai-powered-markdown-translator
aipmt --help                                   # ou : python -m aipmt --help
```

Python 3.10 أو أحدث. للتثبيت من المستودع، راجع
[المساهمة](#المساهمة).

## الإعداد

تُقرأ المفاتيح من ثلاثة مواضع، من الأعلى أولوية إلى الأدنى؛ ولا يكمل كل موضع
إلا ما تركه السابق فارغًا.

|     | الموضع                                            | الغرض                             |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | متغيرات البيئة                     | CI، والحاويات، والتجاوز المؤقت |
| 2   | `.env` في المجلد الحالي (أو أحد المجلدات الأصل) | مفتاح خاص بمشروع            |
| 3   | `~/.config/aipmt/.env`                        | إعداد لمرة واحدة يسري في كل مكان       |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

يُقبل `GEMINI_API_KEY` بدلًا من `GOOGLE_API_KEY`. يتبع ملف
المستخدم `XDG_CONFIG_HOME` (مسار مطلق فقط) و`%APPDATA%`
على Windows. عند غياب المفتاح، يسرد الأمر المواضع الثلاثة.

**لا يمكن لملف `.env` الخاص بمشروع إعادة توجيه الاستدعاءات أو اختيار البرنامج
الذي يُنفَّذ.** فهو يوفّر مفاتيح، ولا يحدد وجهة أو ملفًا تنفيذيًا: تُتجاهل فيه جميع
المتغيرات من نوع `_BASE_URL` أو `_API_BASE` أو `_ENDPOINT` أو `_BIN` ‏(`CODEX_BIN`،
`GROK_BIN`، `OPENCODE_BIN`، `AGY_BIN`)، وكذلك `GROK_HOME` والوكلاء (`HTTP_PROXY`،
`HTTPS_PROXY`، `ALL_PROXY`)، ومخازن الشهادات (`SSL_CERT_FILE`،
`SSL_CERT_DIR`، `REQUESTS_CA_BUNDLE`، `CURL_CA_BUNDLE`) و`XDG_CONFIG_HOME` /
`APPDATA`، مع إصدار تحذير. يجب ألا يتمكن مستودع مستنسخ من
تحويل مفتاحك إلى وجهة أخرى أو جعلك تشغّل برنامجه الخاص عند
أول ترجمة. ويُقرأ هذا الملف أيضًا دون استيفاء المتغيرات:
لا ينسخ `NOM=${OPENAI_API_KEY}` المفتاح فيه. ضع هذه المتغيرات في
البيئة أو في `~/.config/aipmt/.env`.

المتغيرات الاختيارية: `XAI_BASE_URL` (الافتراضي `https://api.x.ai/v1`)،
`CLAUDE_TIMEOUT` (ثوانٍ لكل استدعاء، الافتراضي 900)، `CODEX_BIN`، `CODEX_TIMEOUT`
(الافتراضي 600)، `GROK_BIN`، `GROK_HOME` (الافتراضي `~/.grok`)، `GROK_TIMEOUT`
(الافتراضي 900)، `GROK_TRANSLATE_SANDBOX`، `AGY_BIN`، `AGY_TIMEOUT` (الافتراضي 900)،
`OPENCODE_BIN`، `OPENCODE_TIMEOUT` (الافتراضي 600)، `OPENROUTER_BASE_URL`
(يتطلب `https://`)، `OPENROUTER_TIMEOUT` (الافتراضي 900)،
`OPENROUTER_PREFLIGHT_TIMEOUT` (الافتراضي 30). يُشرح كل منها بالتفصيل في
قسم مزوّد الخدمة المعني.

## الخطوات الأولى

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

تنتج ترجمة `document.md` إلى الإسبانية الملف `document-es.md` في `--target_dir`؛
ومع `--include_model`، يكون الناتج `document-es-gpt-5.6-terra.md`. يصبح الامتداد
دائمًا `.md` — إذ ينتج `article.mdx` الملف `article-en.md` — إلا مع
`--keep_filename`، الذي يحتفظ بالاسم الأصلي. تُتخطى الترجمة الموجودة مسبقًا
ما لم يُستخدم `--force`.

رموز الخروج: `0` إذا نجح كل شيء أو جرى تخطيه، و`1` إذا بقي ملف
فاشل (تُعرض القائمة في مخرج الأخطاء)، و`2` إذا كان السبب هو الإعداد.
لا يُكتب الملف الفاشل أبدًا، حتى إذا فشلت عملية الكتابة نفسها:
يُكتب المحتوى في ملف مجاور ثم يُعاد تسميته. تكفي إعادة التشغيل.

ما ينبغي استخلاصه:

- **الترجمة المرفوضة ليست ترجمة تالفة.** عند فقدان رمز
  في النتيجة، لا يُكتب الملف وتُحتسب اللغة
  مرفوضة. هذا ما يحدث مع Grok في المقال: أربعة أكواد مضمّنة
  وثلاثة عناوين URL مفقودة منذ المقطع الأول، في أنظمة الكتابة الخمسة غير اللاتينية.
- **قد يرفض نموذج مستندًا كاملًا بسبب جملة واحدة.** يترجم Opus 5.5
  ملف README هذا دون أي اختلاف، لكنه لا يترجم أي مقال رصد:
  توقف آليات حمايته الإجابة عند خبر موجز في علم الأحياء. لا يُكتب
  الملف، ويوضح aipmt السبب.
- **لا تشمل شبكة الأمان هذه العناوين أو الجداول أو الترويسة الأمامية أو
  النص.** عندما يحذف نموذج قسمًا، فإنه يعيد ملفًا تكتبه الأداة
  دون اعتراض — وهذا ما يحدث مع Mistral. لا يمكن استبدال هذه العناصر
  برمز، ولا تتحقق منها آليات الحماية الحالية؛
  يكتشف `scripts/compare_structure.py` القسم المفقود، ولكن بعد وقوع ذلك.
- **لا يوجد تقييم لـ Grok على ملف README هذا**: انتهت صلاحية جلسته عبر CLI بعد اثنتي عشرة
  لغة، منها إحدى عشرة دون اختلاف. لا تُقيَّم حملة انقطعت.
- **كثافة المستند أهم من اللغة.** ينجح Grok مع ملفات
  README المعتادة، ويتعثر مع مقال مليء بالروابط، حتى
  بالهولندية.

## المزودون

### عبر API: ‏OpenAI، ‏Mistral، ‏Claude، ‏Gemini، ‏Grok

```bash
aipmt --source_dir content/fr --target_dir content/en --target_lang en             # OpenAI, défaut
aipmt --use_mistral --source_dir content/fr --target_dir content/es --target_lang es
aipmt --use_claude  --source_dir content/fr --target_dir content/de --target_lang de
aipmt --use_gemini  --source_dir content/fr --target_dir content/ja --target_lang ja
aipmt --use_grok    --source_dir content/fr --target_dir content/pt --target_lang pt
```

### ضمن اشتراك ChatGPT: ‏`--use_codex`

يشغّل CLI الرسمي لـ Codex: تُحتسب الترجمة من حصة
اشتراك ChatGPT، دون مفتاح API أو فوترة بحسب الاستخدام.

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- يُبحث عن الملف التنفيذي في `CODEX_BIN`، ثم في `PATH`، ثم في الحزمة
  `openai-codex-cli-bin`. لا يُقرأ `~/.codex/auth.json` مطلقًا.
- يُحذف `OPENAI_API_KEY` و`CODEX_API_KEY` من بيئة
  العملية الفرعية: لا يؤدي وجود مفتاح مطلقًا إلى التحويل إلى API.
- يستهلك كل مقطع «رسالة» واحدة على الأقل من نافذة الساعات الخمس — ورسالتين
  إذا فشل التحقق منه وأُعيدت المحاولة. تعلن OpenAI، على سبيل
  التقدير، عن 250-2 000 رسالة/5 ساعات لـ `gpt-5.6-luna` (`--eco`)، وعن
  10-100 لـ `gpt-5.6-sol` ضمن خطة Plus.
- تمر أيضًا عبر الاشتراك النماذج `--model gpt-5.6-sol`، الذي كان الافتراضي حتى الإصدار 1.16.3، و`--model gpt-5.6-terra`
  و`--model gpt-5.6-luna`.
- لا تؤدي استجابة 429 من الخادم إلى فقدان الملف: يعيد Codex الاتصال تلقائيًا،
  وينتظر aipmt انتهاء الدور، وإذا استمر خطأ 429 حتى النهاية، تُعاد محاولة المقطع
  بعد 30 ثم 60 ثانية. أما النموذج الذي لا يحق للحساب استخدامه فيُرجع الخطأ 400 «النموذج
  غير مدعوم عند استخدام Codex بحساب ChatGPT».
- أبطأ من API، ويزداد الفارق مع طول المستند: في ملف README هذا،
  بلغ الوسيط 6 دقائق و46 ثانية لكل لغة باستخدام `gpt-5.6-sol`، مقابل 36 ثانية باستخدام
  `gemini-3.7-flash`.
- يُرفض في CI (عند تعيين `CI` أو `GITHUB_ACTIONS`): تجري مصادقة الاشتراك
  عبر ملف جلسة شخصي، لا مكان له على مشغّل
  مشترك.
- المتغيرات: `CODEX_BIN`، و`CODEX_TIMEOUT` (الثواني لكل مقطع، الافتراضي 600).

### ضمن اشتراك Grok: ‏`--use_grok_cli`

المبدأ نفسه مع CLI الرسمي لـ Grok Build، ضمن اشتراك SuperGrok أو
X Premium+.

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --file README.md --target_dir . --target_lang pl
```

- **عزل أضعف من Codex.** لا تُطبّق بيئة العزل على مستوى نظام التشغيل في Grok
  على كثير من أجهزة Linux الحديثة (AppArmor، ومقابس بيئة تشغيل
  الحاويات)، ويؤدي تعذر تطبيق ملف تعريف إلى بدء التشغيل دون عزل
  بصمت. لذلك لا يطلب السكربت أي ملف تعريف افتراضيًا، ويعلن ذلك،
  ويعتمد على قواعد `--deny` الخاصة بـ CLI، بما فيها القاعدة الشاملة `*` — وهي
  الطبقة الوحيدة التي ترفض بدء التشغيل بدلًا من إزالة الحماية دون
  الإفصاح عن ذلك. يفرض `GROK_TRANSLATE_SANDBOX=read-only` العزل على مستوى نظام التشغيل، ويفشل بدء التشغيل
  إذا تعذر على الجهاز توفيره.
- الحصة أسبوعية، ومشتركة مع Chat وImagine وVoice، ولا يوجد
  أمر يتيح قراءتها: قد تستهلك دفعة من حصة المحادثات
  دون أي إشعار.
- المتغيرات: `GROK_BIN`، و`GROK_HOME` (مجلد CLI، الافتراضي `~/.grok`)،
  و`GROK_TIMEOUT` (الافتراضي 900)، و`GROK_TRANSLATE_SANDBOX`.

### ضمن اشتراك Google: ‏`--use_antigravity`

المبدأ نفسه مع `agy`، وهو CLI الرسمي لـ Antigravity: لمن يدفع مقابل Google
AI Pro أو Ultra، تُحتسب الترجمة من حصة الاشتراك بدلًا
من فوترتها بحسب عدد الرموز. هذا هو المسار الوحيد للوصول إلى تلك الحصة: لم يعد Gemini CLI
يخدم هذه الحسابات منذ 18 يونيو 2026
([الإعلان](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/))،
ولا يقبل SDK الخاص بـ Antigravity إلا مفتاح API أو مشروع Google Cloud.

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **لا يبقى أي مسار مدفوع مفتوحًا.** لا يتلقى agy من
  بيئتك إلا قائمة مغلقة من المتغيرات — `PATH`، واللغة والمنطقة الزمنية،
  والطرفية، والهوية، والوكلاء والشهادات، وناقل الجلسة — دون أي مفتاح:
  فبعض متغيراته يُحوّل الاستدعاء دون إظهار أي شيء (وفق القياس:
  أحدها يرسل المستند إلى بوابة تابعة لجهة خارجية، وآخر إلى مشروع
  Google Cloud مدفوع)، وكانت قائمة المنع تُغفل بعض هذه المتغيرات في كل مراجعة.
  قبل أي مقطع، يجب أن يُظهر `agy -p /config`، الذي لا يستهلك أي حصة،
  تعطيل أرصدة الذكاء الاصطناعي المدفوعة، دون مفتاح API أو مشروع Google Cloud — ويُعدّ
  غياب أي إعداد سببًا للرفض — وإلا فلن يُترجم شيء؛ ثم يجب أن يثبت سجل كل
  استدعاء استخدام الاشتراك (`authMethod=consumer`)، وإلا تُرفض
  الاستجابة.
- **العزل.** يعمل كل استدعاء في مجلد منزلي خاص
  ومؤقت، مع وكيل ترجمة بلا أدوات: لا تدخل إليه إعداداتك وقواعدك
  وإضافاتك وخوادم MCP وخطافات agy، ولا يُضاف شيء إلى
  سجلك، وتبقى بيانات تسجيل الدخول في سلسلة المفاتيح، التي لا يقرأها aipmt مطلقًا.
  إذا لم يُعثر على الوكيل، يعود agy بصمت إلى وكيل البرمجة
  وأدواته: يجب أن يؤكد سطر كامل من السجل استخدام الوكيل الصحيح — ولا
  يُغني عن ذلك مستند يقتبس هذه الرسالة — وإلا يُرفض الاستدعاء.
- **المنصات**: ‏Linux، ضمن جلسة تتوفر فيها سلسلة مفاتيح (ناقل جلسة
  D-Bus، وSecret Service)؛ ويُقبل macOS، دون إجراء قياسات عليه. يُرفض
  على Windows، حيث لا يقرأ agy المتغيرات التي تعزل كل استدعاء، وكذلك
  على Linux دون ناقل جلسة — جلسة SSH، أو حاوية، أو خادم: إذ يخزّن agy
  رمز الوصول هناك في ملف ضمن `~/.gemini`، يحجبه العزل. يحدث
  الرفض قبل أي تشغيل، مع بيان السبب، بدلًا من الانتظار دقيقة
  للحصول على رمز تسجيل دخول.
- **النماذج**: النماذج الواردة في `agy models`. تتضمن أسماء نماذج Gemini جهد الاستدلال
  (`gemini-3.8-flash-medium`…): يُرفض الاسم الذي لا يحتوي على لاحقة قبل الاستدعاء،
  ولا تأثير لـ `--reasoning_effort`. الافتراضي هو `gemini-3.8-flash-medium`،
  و`gemini-3.7-flash-low` في `--eco`؛ وتُوصف حملات القياس التي حددتها
  في [القياسات التفصيلية](#القياسات-التفصيلية). لدى Claude وGPT-OSS
  حصة خاصة بهما، أصغر بكثير: نحو 1 % من نافذة
  الساعات الخمس لكل استدعاء وفق القياسات، مقابل 0,05 % مع Flash.
- **الحصة**: لكل مجموعة نافذة من 5 ساعات وأخرى أسبوعية، بما
  يتناسب مع التكلفة بالرموز. وفق القياسات على حساب المؤلف: نحو
  16 نقطة من نافذة الساعات الخمس لكل مليون حرف مصدر باستخدام
  `gemini-3.8-flash-medium`، و14 باستخدام `gemini-3.7-flash-medium`، ومن 7 إلى 8 عند
  الجهد المنخفض — لذلك يستهلك ملف README من 40 000 حرف أكثر بقليل من
  نصف نقطة. أما الحد الأسبوعي فيعتمد على الفئة. تتبع إعادة المحاولة
  ما يصرّح agy بأنه قابل لإعادة المحاولة؛ وإلا، فلا تُعاد المحاولة مطلقًا
  عند نفاد حصة نافذة: إذ تتسبب في فشل كل ملف حتى موعد إعادة التعيين
  الذي يعرضه `/usage`.
- **أبطأ من API**: في المقال الكثيف المستخدم في القياسات، بلغ
  الوسيط 3 دقائق و59 ثانية لكل لغة باستخدام `gemini-3.8-flash-medium`، و3 دقائق و14 ثانية باستخدام
  `gemini-3.7-flash-medium`، مقابل دقيقة و18 ثانية لـ Gemini 3.7 Flash عبر API.
- **المقاطعة**: يؤدي Ctrl-C أو إغلاق الطرفية إلى إيقاف agy مع
  الأمر، بدلًا من تركه يُكمل دوره مستهلكًا حصتك؛ وينطبق الأمر
  نفسه على Codex وGrok CLI وOpenCode. ضمن `nohup`، تستمر الترجمة.
- يُرفض في CI (عند تعيين `CI` أو `GITHUB_ACTIONS`): تُحفظ بيانات تسجيل الدخول في
  سلسلة مفاتيح شخصية. على مشغّل، استخدم `--use_gemini` مع `GOOGLE_API_KEY`.
- المتغيرات: `AGY_BIN` (وإلا `PATH`، ثم `~/.local/bin/agy`)،
  و`AGY_TIMEOUT` (الثواني لكل مقطع، بما فيها بدء التشغيل، الافتراضي 900).

**شروط الاستخدام: حسابك هو الذي يتحمل المسؤولية.** تحظر
[شروط Antigravity](https://antigravity.google/terms) (القسم 6) و[الأسئلة الشائعة](https://antigravity.google/docs/faq/)
الوصول إلى الخدمة عبر برنامج تابع لجهة خارجية باستخدام تسجيل الدخول إلى Antigravity
— وتذكر Claude Code وOpenClaw وOpenCode — تحت طائلة تعليق الحساب. لا يقرأ aipmt
رمز الوصول ولا يعيد استخدامه: بل يشغّل الملف التنفيذي الرسمي في
[الوضع دون واجهة](https://antigravity.google/docs/cli/headless/) الذي توثّقه Google
للسكربتات وCI. وقد اعتبر أحد أعضاء Google أن تشغيل `agy -p`
من سكربت محلي لإنجاز العمل الشخصي أمر «اعتيادي»
([المنتدى الرسمي، 25 سبتمبر 2026، رد غير تعاقدي](https://discuss.ai.google.dev/t/is-using-the-official-agy-cli-through-a-local-mcp-server-with-third-party-ai-agents-permitted/184829))؛
ولا يوجد نص يحسم حالة أداة موزّعة مثل هذه.

**للمستندات العامة فقط.** وفق القسم 5 من الشروط نفسها، قد تُستخدم
التبادلات — الطلبات والاستجابات والبيانات الوصفية — لتحسين
منتجات Google والتعلّم الآلي لديها، وقد يراجعها
بشر، حتى مع الاشتراك المدفوع. يتم الانسحاب عبر الإعداد
`enableTelemetry`، الذي لم يُوثّق تأثيره ولا يضبطه aipmt؛ كما لا تنتقل إعداداتك
في agy إلى بيئته المعزولة. لا تمرّر عبره أي معلومات سرية.
### باستخدام اشتراك Claude: `--use_claude_code`

ينطبق المبدأ نفسه على `claude`، وهو CLI الرسمي لـ Claude Code، في وضع `-p`: لمن
يدفع مقابل Claude Pro أو Max، تُخصم الترجمة من حصة
الاشتراك بدلًا من احتساب تكلفتها لكل token. ويجب عدم الخلط بينه وبين
`--use_claude`، وهو API الخاص بـ Anthropic، الذي تُحتسب تكلفته حسب الاستخدام.

```bash
claude                                   # une fois : /login avec le compte de l'abonnement
aipmt --use_claude_code --file README.md --target_dir . --target_lang en
```

- **لا يبقى أي مسار مدفوع متاحًا، وكل استدعاء يثبت ذلك.** لا يتلقى Claude
  Code من بيئتك سوى قائمة مغلقة من المتغيرات — بلا
  مفتاح API، أو رمز وصول، أو مزود سحابي، أو علامة لجلسة Claude Code
  التي قد يُشغَّل منها aipmt. قبل المقطع الأول، يجب أن يُظهر `claude auth status`
  الاتصال عبر الاشتراك، بلا مفتاح Console، وأن يؤكد ذلك `/usage`، الذي لا يستهلك
  أي حصة؛ ويؤكده كل استدعاء بدوره في
  حدث التهيئة الخاص به، وإلا تُرفض الاستجابة.
- **عطّل «الاستخدام الإضافي»** (claude.ai، الإعدادات ← الاستخدام) لضمان
  بقاء التكلفة صفر يورو: عند تفعيله، يتولى العمل بعد نفاد حصة إحدى الفترات،
  ويحتسب رسومًا دون عرض خطأ. يوقف aipmt الترجمة بمجرد أن يشير تقرير
  حصة أحد الاستدعاءات إلى ذلك، لكن ذلك الاستدعاء يكون قد احتُسب بالفعل.
- **الحصة مشتركة مع جلسات Claude Code لديك.** يُبلغ كل استدعاء عن
  استخدام فترتَي 5 ساعات والأسبوع؛ وعند تجاوز 80 %
  (`AIPMT_CLAUDE_MAX_UTILIZATION`)، لا يُبدأ أي مقطع إضافي، لتجنب
  استنفاد ما تحتاج إليه في عملك.
- **العزل.** يعمل كل استدعاء بلا أدوات، داخل مجلد خاص
  ومؤقت، في وضع بلا تخصيص: لا تُحمَّل ملفات `CLAUDE.md` لديك، ولا إضافاتك،
  أو hooks، أو خوادم MCP، أو إعداداتك، ولا يُحتفَظ بشيء من
  الجلسة. المرفقات معطّلة: يظل `@chemin` داخل مستندك
  نصًا ولا يفتح أي ملف (تم التحقق بالقياس).
- **النماذج**: `sonnet` افتراضيًا، بمستوى الجهد `low`، وكذلك في `--eco`:
  لا يغيّر `--eco` شيئًا في هذا المسار. أظهرت القياسات على المستندات نفسها أن `haiku`
  أبطأ بمرتين — فهو يستدل دون إمكانية منعه — مقابل
  تكلفة أقل بقليل فقط، وأن `opus` يرفض محتويات في علم الأحياء (النقطة
  التالية). ويظل كلاهما متاحًا عبر `--model`؛ وتتبع هذه الأسماء البديلة
  أحدث نموذج من عائلتها. يُرفض `fable` ومتغيرات `[1m]`،
  لأنها تستخدم أرصدة مدفوعة. يضبط `--reasoning_effort` مستوى الجهد،
  الذي لا تستفيد منه الترجمة: فالاستدلال المقاس معدوم أو شبه معدوم.
- **يرفض Opus بعض محتويات علم الأحياء.** ضوابطه الوقائية أكثر
  صرامة من ضوابط Sonnet، وتحذّر رسالة الخطأ من Anthropic من أنها
  «قد تصنّف أحيانًا أعمالًا قريبة من أبحاث علم الأحياء». أظهر القياس أن خبرًا موجزًا
  عن 279 جزيئًا مولّدًا تسبب في رفض المقال باللغات الأربع عشرة.
  لا يُكتب أي شيء: يرفض aipmt الاستجابة المقطوعة، ويحدد
  الضوابط الوقائية وينصح باستخدام `--model sonnet`.
- مرفوض في CI (عند تعيين `CI` أو `GITHUB_ACTIONS`) وتحت Windows (لم يُقَس).
- المتغيرات: `AIPMT_CLAUDE_BIN` (وإلا `PATH`، ثم `~/.local/bin/claude`)،
  `AIPMT_CLAUDE_TIMEOUT` (ثوانٍ لكل مقطع، الافتراضي 900)،
  `AIPMT_CLAUDE_MAX_UTILIZATION` (الافتراضي 0.8)، `CLAUDE_CONFIG_DIR` (حساب
  Claude Code، ولا يؤخذ أبدًا من `.env` خاص بالمشروع)؛ وتوجد مجلدات العمل تحت
  `XDG_CACHE_HOME/aipmt/claude-code` (الافتراضي `~/.cache`).

**شروط الاستخدام: حسابك هو المعني.** لا تمنع
[الصفحة القانونية لـ Claude Code](https://code.claude.com/docs/en/legal-and-compliance)
«مستخدمًا نهائيًا من تسجيل الدخول إلى الملف التنفيذي غير المعدّل لـ Claude Code
باستخدام اشتراك Claude الخاص به»: وهذا ما يفعله aipmt، إذ يشغّل
الملف التنفيذي الرسمي ولا يقرأ رمز الوصول أبدًا. لكن Anthropic «لا تسمح
لمطوري الجهات الخارجية […] بتمرير الطلبات عبر بيانات اعتماد خطط Free أو Pro أو Max
نيابةً عن مستخدميهم»، وتفضّل مفتاح API لأدوات
الجهات الخارجية، «بما فيها المشاريع مفتوحة المصدر»، وتحتفظ بحق خصم
استخدامها من الأرصدة المدفوعة
([مساعدة Claude](https://support.claude.com/en/articles/13189465-logging-in-to-your-claude-account)).
لا يوجد نص يحسم حالة أداة موزّعة تشغّل الملف التنفيذي.

**البيانات**: في حسابات Free وPro وMax، ينطبق تدريب النماذج

بأي سجل محلي للمحادثة (`--no-session-persistence`). لا تمرّر عبره
أي محتوى سري.

### إلى المزوّد الذي تختاره: `--use_opencode`

[OpenCode](https://opencode.ai) هو وكيل برمجة مفتوح المصدر (MIT)
يوجّه الطلبات إلى المزوّدين المهيئين داخله: مفتاح API، أو اشتراك،
أو بوابة OpenCode Zen (نماذج مجانية، بلا حساب)، أو نموذج محلي. جرى
قياس مسارين من البداية إلى النهاية هنا، وهما Zen وOllama.

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` إلزامي: بدونه، سيلجأ OpenCode إلى نموذج مجاني
قد تُستخدم المحادثات معه في التدريب، ولا يُتخذ هذا القرار
نيابةً عنك.

العزل عند كل استدعاء:

- إعداد مضمّن، له الأولوية على إعدادك، يعرّف وكيلًا `aipmt`
  تُحظر جميع أدواته (`permission: { "*": "deny" }`)، مع تعطيل مشاركة
  الجلسة، و`--pure`، وعدم استخدام `--auto` مطلقًا؛
- مجلد عمل مؤقت وفارغ، مع تعيين `OPENCODE_DISABLE_PROJECT_CONFIG` و
  `OPENCODE_DISABLE_CLAUDE_CODE` — فبدونهما، يحقن OpenCode في
  نص التوجيه `AGENTS.md` الخاص بالمجلد الحالي و`~/.claude/CLAUDE.md`. ويظل
  `~/.config/opencode/AGENTS.md` العام محقونًا، إذ لا يتيح OpenCode
  استبعاده؛
- شروط المخرجات: رمز خروج 0، وعدم وجود أي حدث `error`، أو أي استدعاء
  لأداة، وأن تكون الخطوة الأخيرة في `stop`، وأن يكون النص غير فارغ، وأن يكون الوكيل `aipmt`
  قد حُمّل بالفعل — فقيمة `--agent` غير المعروفة لا تُفشل OpenCode،
  بل يعود بصمت إلى وكيل البرمجة؛
- لا يُمرَّر أي مفتاح من `aipmt`، باستثناء `OPENCODE_API_KEY`، وهو مفتاح
  OpenCode نفسه. يُهيَّأ المزوّدون داخل OpenCode، وليس في
  `.env` الخاص بـ `aipmt`.

معلومات ينبغي معرفتها:

- تتغير نماذج Zen المجانية، وحدودها غير موثقة،
  وقد تُستخدم المحادثات معها في التدريب: تصلح للتوثيق
  العام، ولا تصلح للمحتوى الخاص.
- يجب أن يوفّر النموذج المحلي سياقًا لا يقل عن 16 k tokens، إذ تصل المقاطع
  إلى 16 000 حرف. غالبًا ما يضبط Ollama القيمة على 4 096: استخدم
  `Modelfile` مع `PARAMETER num_ctx 32768`.
- لا تأثير لـ `--eco`؛ ويُمرَّر `--reasoning_effort` كما هو بوصفه
  `--variant` الخاص بـ OpenCode.
- يسجّل OpenCode كل جلسة في `~/.local/share/opencode/`.
- المتغيرات: `OPENCODE_BIN` (وإلا `PATH`، ثم `~/.opencode/bin/opencode`)،
  `OPENCODE_TIMEOUT` (ثوانٍ لكل مقطع، الافتراضي 600). يُمرَّر `OPENCODE_CONFIG`
  كما هو إلى OpenCode.

مثال على نموذج محلي عبر Ollama، في `~/.config/opencode/opencode.json`:

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

يعطّل `reasoningEffort: "none"` التفكير الذي يفعّله Ollama افتراضيًا في هذه
النماذج، والذي لا يستطيع Modelfile تعطيله. أظهر القياس على جملة من
ست كلمات: 919 tokens للتفكير و68 ثانية بدون الخيار، مقابل 9 tokens معه.

### إلى أكثر من 400 نموذج: `--use_openrouter`

OpenRouter هو موجّه تُحتسب تكلفته حسب الاستخدام، برصيد موحّد، يتيح الوصول إلى
نماذج تستضيفها جهات خارجية — ومنها النماذج الصينية المفتوحة التي لا يتيحها
أي مزوّد آخر هنا.

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` إلزامي. يعالج فحص مسبق، يُنفَّذ قبل احتساب أي رسوم،
خاصيتين للتوجيه:

- **تقدّم عشرات جهات الاستضافة النموذج نفسه بحدود قصوى
  مختلفة** — على `z-ai/glm-5.3-flash`، توجد 23 جهة استضافة، إحداها تحدّ المخرجات عند
  2 048 tokens. يقرأ الفحص المسبق `/api/v1/models/{modèle}/endpoints`،
  ويستبعد جهات الاستضافة التي تقل مخرجاتها عن 8 000 tokens أو التي تدهورت حالتها،
  ويثبّت البقية باستخدام `allow_fallbacks: false`.
- **تُحتسب تكلفة الاستدلال بسعر المخرجات** — 107 tokens مقابل 2 في
  استجابة «حسنًا» من `z-ai/glm-5.2`. يُعطَّل افتراضيًا؛ وتتلقى النماذج
  التي تفرضه أدنى مستوى جهد تقبله، لأن الإعداد الافتراضي في
  الكتالوج قد يستنفد سعة المخرجات قبل انتهاء الترجمة.
  تظل الأولوية لـ `--reasoning_effort`.

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- تُؤخذ نافذة السياق من الكتالوج. يُرفض أي نموذج تقل نافذته عن 16 400 tokens
  قبل أي استدعاء: 8 400 لنص التوجيه والمقطع، و8 000 للمخرجات
  على الأقل.
- يتوقف الأمر إذا كان المعرّف المختصر غائبًا عن الكتالوج، أو تعذر الوصول إلى الكتالوج،
  أو لم توجد جهة استضافة تستوفي الحد الأقصى.
- يشير `finish_reason=length` مع مخرجات فارغة إلى ميزانية استهلكها
  الاستدلال، وليس إلى اقتطاع: وتوضح الرسالة هذا الفرق.
- لا تأثير لـ `--eco`.
- المتغيرات: `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>)،
  `OPENROUTER_BASE_URL` (الافتراضي `https://openrouter.ai/api/v1`، و`https://`
  مطلوب)، `OPENROUTER_TIMEOUT` (الافتراضي 900)، `OPENROUTER_PREFLIGHT_TIMEOUT`
  (الافتراضي 30).

### ملاحظة الترجمة

يضيف `--add_translation_note` ملاحظة في `bottom` (الافتراضي)، أو `top` (بعد
البيانات الوصفية الافتتاحية)، أو `both` (`--note_position`)، بتنسيق `legacy` (فقرة
غامقة، الافتراضي) أو `marker` (`--note_format`). تنسيق `marker` هو
تعريف مرجعي غير مرئي في Markdown،
`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`،
يتبعه اقتباس غامق: يمكن قراءته على GitHub، واستخدامه أثناء البناء عبر
إضافة remark.

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## القياسات التفصيلية

جميع القياسات ناتجة عن ترجمات نُفّذت فعلًا باستخدام `aipmt`، إلى
أربع عشرة لغة: en، es، de، it، pt، nl، pl، sv، ro، ja، ko، zh، ar، hi.
يحسب **المكتوبة** الملفات التي سمحت آليات الحماية بمرورها؛ ويحسب **بلا
اختلاف** الملفات التي لم يرصد فيها `scripts/compare_structure.py` شيئًا — أي تطابق عدد
الأقسام، والعناوين الفرعية، والروابط، وعناوين URL المختلفة، وكتل الشيفرة،
والشيفرات المضمّنة، وصفوف الجداول، وكتل الاقتباس، والكلمات الغامقة.

تعني «بلا اختلاف» أنه «لم يُكتشف شيء»، ولا تعني «متطابق»: فالمقارن
يعدّ العناصر دون قراءة محتواها. ولا يكشف حذف عنوان من
المستوى 4، أو استبدال نص شيفرة مضمّنة، أو تغيير علم،
أو إخراج رابط داخلي بقوس زائد،
`[texte]((#ancre))`، بحيث لا يعود يقود إلى أي مكان — كما أنه لا يقيّم
اللغة.

ضمن فئة «علم الأحياء»؛ وترجمه `sonnet` إلى جميع اللغات. كتب `haiku`
اللغات الأربع عشرة؛ وفي ثلاث منها (en، pl، ro)، تغيّر عنوان قسم من

tokens مخرجاته —، لذا استغرق أكثر من ضعف زمن `sonnet`.

قِيست صفوف `claude-sonnet-5-5` و`claude-haiku-5-5` و`claude-haiku-4-5`
في 18 أكتوبر عبر API الخاص بـ Anthropic، على المقال نفسه، بأربع
ترجمات بالتوازي لكل نموذج. يرفض Sonnet 5.5 تعطيل
تفكيره: يرسل إليه aipmt أدنى إعداد يقبله، ولا تتضمن
استجاباته أي تفكير. يكتب اللغات الأربع عشرة بلا اختلاف ودون
إعادة أي مقطع؛ وفي الإنجليزية، حذف بنفسه أسطر
الترجمة الفرنسية، دون اختلاق علم، وظلت الاقتباسات الإنجليزية
سليمة في جميع اللغات. قِيس Haiku 5.5 مع تفكيره التكيّفي: عند تعطيل
التفكير، كان يترك فقرات كاملة بالفرنسية، فترفضها آلية الحماية —
وكُتبت 3 لغات من أصل 14. يتعثر نموذجا Haiku عند الخبر الموجز نفسه: يغيّر Haiku 5.5
مستوى عنوانه أو يكرره في اليابانية والكورية
والصينية، بينما ينقله Haiku 4.5 إلى المستوى 1 في سبع لغات، ويتركه
بالفرنسية في الترجمة اليابانية. تبلغ تكلفة Haiku 4.5 للمستندين في
اللغات الأربع عشرة 3,67 $، وتكلفة Haiku 5.5 هي 0,57 $، وتكلفة Sonnet 5.5 هي 9,21 $.

### ما لا تمثّله هذه القياسات

- **ليست تصنيفًا شاملًا**: يوفّر OpenRouter وحده أكثر من أربعمئة
  نموذج، وقد قيس نحو خمسة عشر نموذجًا.
- **مدد استرشادية**: من ثلاث إلى ست ترجمات بالتوازي بحسب
  الحملة، كما يتغيّر معدل معالجة المزوّد خلال اليوم.
- **ملاحظات مرتبطة بتاريخها**: تتغيّر النماذج مع احتفاظها بالاسم نفسه، كما أن
  مستنداتكم تختلف عن مستنداتنا.

python scripts/compare_structure.py reference.md out/reference-ja.md

## المساهمة

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

كلا السطرين ضروري: بدون `pip install -e .`، يجيب `python -m aipmt`
بـ`No module named aipmt`.

أدوات الجودة، اختيارية لكن موصى بها:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```

تُعاد توليد ترجمات المستودع الـ28 (README وCHANGELOG، بأربع عشرة لغة)
باستخدام `./regen_translations.sh --force` — مع Codex و`gpt-6.1-sol` عبر
اشتراك ChatGPT افتراضيًا، أربع ترجمات بالتوازي. يغيّر `REGEN_PROVIDER` و
`REGEN_MODEL` مسار التنفيذ: يظل `antigravity` معتمدًا على اشتراك، وهو اشتراك
Google، ويُسمح به دون استثناء؛ أما API مدفوعة (`openai` و`gemini` و
`grok` و`openrouter`) فتُرفض بدون `REGEN_ALLOW_PAID_API=1`؛
ويضع `REGEN_JOB_TIMEOUT` حدًا زمنيًا لكل مهمة (600 s، و1 800 s على Codex و
Antigravity). تفاصيل الأدوات في `CLAUDE.md`.
