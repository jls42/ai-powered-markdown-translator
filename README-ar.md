يترجم ملفات Markdown من لغة إلى أخرى مع الحفاظ على البنية: كتل الأكواد البرمجية، الأكواد المضمنة، عناوين URL، المراسي، الجداول، وfront matter. عشر طرق لاستدعاء النموذج — خمس واجهات برمجة تطبيقات (APIs)، ثلاثة اشتراكات دون فوترة حسب الاستخدام، وموجّهان — مع قياس منشور لما يحافظ عليه كل نموذج بالفعل.

## باختصار

- **عشرة مسارات لمزوّدي الخدمة**: واجهات برمجة تطبيقات OpenAI وMistral وClaude وGemini وGrok؛ اشتراكات ChatGPT (Codex) وGrok وGoogle (Antigravity) دون فوترة حسب الاستخدام؛ وموجّها OpenCode (مفتوح المصدر، مجاني أو محلي) وOpenRouter (أكثر من 400 نموذج).
- **لا أخطاء بسبب رمز مميز مفقود**: تُستبدل كتل الأكواد البرمجية، الأكواد المضمنة، عناوين URL، المراسي، والاقتباسات برموز مميزة قبل الاستدعاء ويتم التحقق منها عند الاستلام. إذا فُقد أي منها، فلن يُكتب الملف.
- **المستندات الطويلة**: تقسيم وفقًا لنافذة سياق النموذج.
- **وضع `--news`**: حماية الاقتباسات الإنجليزية وإدارة الأعلام حسب اللغة، لمقالات الرصد الإخباري.
- **وضع `--eco`**: نماذج سريعة وأقل تكلفة.
- **ملاحظة ترجمة** اختيارية، في الأعلى أو في الأسفل أو في كلا الموضعين.

## التثبيت

```bash
pip install ai-powered-markdown-translator     # ou : pipx install ai-powered-markdown-translator
aipmt --help                                   # ou : python -m aipmt --help
```

Python 3.10 أو أحدث. للتثبيت من المستودع، راجع [المساهمة](#المساهمة).

## الإعداد

تُقرأ المفاتيح من ثلاثة مواقع، من الأعلى أولوية إلى الأدنى؛ ولا يملأ كل موقع إلا ما يتركه السابق فارغًا.

|     | أين                                           | ولأي غرض                              |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | متغيرات البيئة                                | CI، الحاويات، الاستثناءات المؤقتة     |
| 2   | `.env` في الدليل الحالي (أو دليل أصل)  | مفتاح خاص بمشروع معين                 |
| 3   | `~/.config/aipmt/.env`                                 | يُثبّت مرة واحدة، ويعمل في كل مكان    |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

يُقبل `GEMINI_API_KEY` كبديل لـ `GOOGLE_API_KEY`. يتبع ملف المستخدم مسار `XDG_CONFIG_HOME` (مسار مطلق فقط) و`%APPDATA%` على Windows. في حال عدم وجود أي مفتاح، يعرض الأمر المواقع الثلاثة.

**لا يمكن لملف `.env` الخاص بالمشروع إعادة توجيه الاستدعاءات ولا اختيار البرنامج المُنفَّذ.** فهو يوفّر مفاتيح فقط، ولا يحدد وجهة أو ملفًا تنفيذيًا إطلاقًا: يتم تجاهل أي متغير ينتهي بـ `_BASE_URL` أو `_API_BASE` أو `_ENDPOINT` أو `_BIN` (`CODEX_BIN`، `GROK_BIN`، `OPENCODE_BIN`، `AGY_BIN`)، و`GROK_HOME`، والبروكسيات (`HTTP_PROXY`، `HTTPS_PROXY`، `ALL_PROXY`)، ومخازن الشهادات (`SSL_CERT_FILE`، `SSL_CERT_DIR`، `REQUESTS_CA_BUNDLE`، `CURL_CA_BUNDLE`) و`XDG_CONFIG_HOME` / `APPDATA` مع إصدار تحذير. لا ينبغي لمستودع مستنسخ أن يتمكن من اختلاس مفتاحك أو تشغيل برنامجه الخاص عند أول ترجمة. كما يُقرأ هذا الملف دون استيفاء (interpolation): لا يقوم `NOM=${OPENAI_API_KEY}` بنسخ المفتاح داخله. ضع هذه المتغيرات في البيئة أو في `~/.config/aipmt/.env`.

المتغيرات الاختيارية: `XAI_BASE_URL` (الافتراضي `https://api.x.ai/v1`)، `CLAUDE_TIMEOUT` (بالثواني لكل استدعاء، الافتراضي 900)، `CODEX_BIN`، `CODEX_TIMEOUT` (الافتراضي 600)، `GROK_BIN`، `GROK_HOME` (الافتراضي `~/.grok`)، `GROK_TIMEOUT` (الافتراضي 900)، `GROK_TRANSLATE_SANDBOX`، `AGY_BIN`، `AGY_TIMEOUT` (الافتراضي 900)، `OPENCODE_BIN`، `OPENCODE_TIMEOUT` (الافتراضي 600)، `OPENROUTER_BASE_URL` (يتطلب `https://`)، `OPENROUTER_TIMEOUT` (الافتراضي 900)، `OPENROUTER_PREFLIGHT_TIMEOUT` (الافتراضي 30). تم تفصيل كل منها في قسم مزوّد الخدمة الخاص به.

## الخطوات الأولى

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

ترجمة `document.md` إلى الإسبانية تنتج `document-es.md` في `--target_dir`؛ ومع `--include_model`، تصبح `document-es-gpt-5.6-terra.md`. يصبح الامتداد دائمًا `.md` — ينتج عن `article.mdx` الملف `article-en.md` — باستثناء استخدام `--keep_filename`، الذي يحتفظ بالاسم الأصلي. يتم تخطي أي ترجمة موجودة مسبقًا ما لم يُستخدم `--force`.

رموز الخروج: `0` إذا نجحت كل العمليات أو تم تخطيها، و`1` إذا تعذر إكمال أي ملف (تُعرض القائمة في مخرج الأخطاء القياسي)، و`2` إذا كان السبب متعلقًا بالإعدادات. لا يُكتب الملف الفاشل أبدًا، حتى وإن فشلت عملية الكتابة نفسها: حيث يُكتب المحتوى بجانبه ثم يُعاد تسميته. يكفي إعادة التشغيل.

ما يجب استخلاصه من ذلك:

- **الترجمة المرفوضة ليست ترجمة مشوهة.** عندما يُفقد رمز مميز عند الاستلام، لا يُكتب الملف وتُحسب اللغة على أنها مرفوضة. هذا ما حدث مع Grok في المقال: فُقدت أربعة أكواد مضمنة وثلاثة عناوين URL منذ المقطع الأول، عبر أنظمة الكتابة غير اللاتينية الخمسة.
- **شبكة الأمان هذه لا تغطي العناوين ولا الجداول ولا front matter ولا النصوص العادية.** النموذج الذي يحذف قسمًا كاملًا يعيد ملفًا تكتبه الأداة دون اعتراض — كما هو الحال مع Mistral. هذه العناصر لا يمكن استبدالها برمز مميز، وآليات الحماية الحالية لا تتحقق منها؛ ويكتشف `scripts/compare_structure.py` القسم المفقود ولكن بعد فوات الأوان.
- **لم يحصل Grok على تقييم في هذا الـ README**: انتهت جلسة CLI الخاصة به بعد اثنتي عشرة لغة، إحدى عشرة منها دون أي انحراف. الحملة المنقطعة لا يتم تقييمها.
- **كثافة المستند أهم من اللغة.** يصمد Grok في ملفات README العادية ويتعثر في مقال مليء بالروابط، بما في ذلك باللغة الهولندية.

## جميع الخيارات

| الخيار                   | الوصف                                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `--file`           | ملف Markdown فردي لترجمته (بديل لـ `--source_dir`)                                                            |
| `--source_dir`           | الدليل المصدر الذي يحتوي على ملفات Markdown (الافتراضي: `content/posts`)                                      |
| `--target_dir`           | دليل الإخراج للملفات المترجمة (الافتراضي: `traductions_en`)                                                     |
| `--source_lang`           | لغة المصدر (الافتراضي: `fr`)                                                                        |
| `--target_lang`           | اللغة الهدف (الافتراضي: `en`)                                                                       |
| `--model`           | نموذج محدد للاستخدام                                                                                          |
| `--eco`           | استخدام النماذج الاقتصادية                                                                                    |
| `--use_mistral`           | استخدام واجهة برمجة تطبيقات Mistral AI                                                                        |
| `--use_claude`           | استخدام واجهة برمجة تطبيقات Claude                                                                            |
| `--use_gemini`           | استخدام واجهة برمجة تطبيقات Gemini                                                                            |
| `--use_grok`           | استخدام واجهة برمجة تطبيقات xAI (Grok) — يتطلب `XAI_API_KEY`                                                 |
| `--use_codex`           | استخدام CLI الخاص بـ Codex اعتمادًا على حصة اشتراك ChatGPT                                                    |
| `--use_grok_cli`           | استخدام CLI الخاص بـ Grok اعتمادًا على حصة اشتراك Grok                                                        |
| `--use_antigravity`           | استخدام CLI الخاص بـ Antigravity (`agy`) اعتمادًا على حصة اشتراك Google AI Pro أو Ultra               |
| `--use_opencode`           | استخدام OpenCode (مفتوح المصدر) نحو المزود المكوّن في OpenCode؛ يتطلب `--model provider/modèle`                         |
| `--use_openrouter`           | استخدام OpenRouter — يتطلب `OPENROUTER_API_KEY` و`--model fournisseur/modèle`                                                     |
| `--force`           | فرض إعادة الترجمة                                                                                             |
| `--keep_filename`           | الاحتفاظ باسم الملف الأصلي                                                                                    |
| `--news`           | وضع الأخبار: حماية الاقتباسات الإنجليزية، وإدارة الأعلام حسب اللغة                                            |
| `--add_translation_note`           | إضافة ملاحظة ترجمة                                                                                            |
| `--note_position`           | موضع الملاحظة: `top`، `bottom` (الافتراضي)، أو `both`                                  |
| `--note_format`           | تنسيق الملاحظة: `legacy` (الافتراضي، فقرة بخط عريض) أو `marker`                                    |
| `--include_model`          | تضمين اسم النموذج في ملف الإخراج                                                                              |
| `--reasoning_effort`          | جهد التفكير لـ GPT-5.x: `none`/`low`/`medium`/`high`/`xhigh`       |

خيارات الراية التسعة الخاصة بـ `--use_*` حصرية بشكل متبادل: الجمع بين اثنين منها مرفوض.

### عبر اشتراك ChatGPT: `--use_codex`

يقود أداة CLI الرسمية لـ Codex: تُخصم الترجمة من حصة اشتراك ChatGPT، دون الحاجة إلى مفتاح API أو فوترة حسب الاستخدام.

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- يتم البحث عن الملف التنفيذي في `CODEX_BIN`، ثم في `PATH`، ثم في حزمة `openai-codex-cli-bin`. لا تتم قراءة `~/.codex/auth.json` مطلقًا.
- تُزال `OPENAI_API_KEY` و`CODEX_API_KEY` من بيئة العملية الفرعية: وجود مفتاح لا يؤدي أبدًا إلى التبديل إلى واجهة برمجة التطبيقات (API).
- يكلف كل مقطع «رسالة» واحدة على الأقل من نافذة الـ 5 ساعات — واثنتين إذا فشل التحقق منه وأُعيدت المحاولة. تعلن OpenAI، على سبيل التقدير، عن 250-2,000 رسالة/5 ساعات لـ `gpt-5.6-luna` (`--eco`) و10-100 لـ `gpt-5.6-sol` في خطة Plus.
- يمر `--model gpt-5.6-terra` و`--model gpt-5.6-luna` أيضًا عبر الاشتراك. النموذج الذي لا يحق للحساب استخدامه يُرجع الخطأ 400 «model is not supported when using Codex with a ChatGPT account».
- أبطأ من واجهة برمجة التطبيقات (API)، وتتسع الفجوة مع زيادة حجم المستند: في ملف README هذا، يستغرق 6 دقائق و46 ثانية لكل لغة كقيمة وسيطة مع `gpt-5.6-sol`، مقابل 36 ثانية لـ `gemini-3.7-flash`.
- مرفوض في بيئات التكامل المستمر CI (عند تعيين `CI` أو `GITHUB_ACTIONS`): تتم المصادقة على الاشتراك عبر ملف جلسة شخصي، لا مكان له على مشغّل (runner) مشترك.
- المتغيرات: `CODEX_BIN`، `CODEX_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 600).

### عبر اشتراك Grok: `--use_grok_cli`

المبدأ نفسه مع أداة CLI الرسمية Grok Build، عبر اشتراك SuperGrok أو X Premium+.

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --eco --file README.md --target_dir . --target_lang pl
```

- **عزل أضعف مقارنة بـ Codex.** لا تنطبق بيئة العزل (sandbox) الخاصة بنظام التشغيل لـ Grok على العديد من أجهزة Linux الحديثة (AppArmor، ومقابس وقت تشغيل الحاويات)، والملف التعريفي الذي يتعذر تطبيقه يبدأ دون عزل بصمت. لذلك لا يطلب السكريبت أي ملف تعريفي افتراضيًا، ويعلن عن ذلك، ويعتمد على قواعد `--deny` الخاصة بالـ CLI، بما في ذلك القاعدة الشاملة `*` — وهي الطبقة الوحيدة التي ترفض البدء بدلاً من إزالة الحماية دون إشعار. يتطلب `GROK_TRANSLATE_SANDBOX=read-only` وجود sandbox نظام التشغيل، ويفشل بدء التشغيل إذا لم تتمكن الآلة من توفيره.
- الحصة أسبوعية، ومشتركة مع Chat وImagine وVoice، ولا يوجد أمر يتيح قراءتها: يمكن لدفعة ترجمة أن تستهلك الاستخدام الحواري دون سابق إنذار.
- المتغيرات: `GROK_BIN`، `GROK_HOME` (دليل الـ CLI، الافتراضي `~/.grok`)، `GROK_TIMEOUT` (الافتراضي 900)، `GROK_TRANSLATE_SANDBOX`.

### عبر اشتراك Google: `--use_antigravity`

المبدأ نفسه مع `agy`، أداة CLI الرسمية لـ Antigravity: لمن يدفع مقابل Google AI Pro أو Ultra، تُخصم الترجمة من حصة الاشتراك بدلاً من محاسبتها لكل رمز (token). هذا هو المسار الوحيد نحو هذه الحصة: لم يعد Gemini CLI يخدم هذه الحسابات منذ 18 يونيو 2026 ([إعلان](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/))، وحزمة SDK لـ Antigravity لا تقبل سوى مفتاح API أو مشروع Google Cloud.

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **لا يبقى أي مسار مدفوع مفتوحًا.** لا يستقبل agy من بيئتك سوى قائمة مغلقة من المتغيرات — `PATH`، واللغة والمنطقة الزمنية، والطرفية، والهوية، والوكلاء والشهادات، وناقل الجلسة — وبدون أي مفاتيح: العديد من متغيراته تحول الطلب دون إظهار أي شيء (تم قياس ذلك: أحدها يرسل المستند إلى بوابة طرف ثالث، وآخر إلى مشروع Google Cloud مفوتر)، وكانت قائمة الحظر تغفل بعضها في كل مراجعة. قبل أي مقطع، يجب أن يوضح `agy -p /config`، الذي لا يستهلك أي حصة، أن أرصدة الذكاء الاصطناعي المدفوعة معطلة، دون مفتاح API أو مشروع Google Cloud — وغياب الإعداد يُعد رفضًا —، وإلا فلن يُترجم شيء؛ كما يجب أن يثبت سجل كل استدعاء بعد ذلك وجود الاشتراك (`authMethod=consumer`)، وإلا تُرفض الاستجابة.
- **العزل.** يعمل كل استدعاء في دليل شخصي خاص وقابل للحذف، مع وكيل ترجمة بدون أدوات: لا تدخل إعداداتك وقواعدك وإضافاتك وخوادم MCP وخطافات (hooks) agy إليه، ولا يُضاف أي شيء إلى سجلك، ويظل تسجيل الدخول في سلسلة المفاتيح (keyring)، والتي لا يقرؤها aipmt مطلقًا. إذا تعذر العثور على الوكيل، يتراجع agy بصمت إلى وكيل البرمجة وأدواته: يجب أن يؤكد سطر كامل من السجل استخدام الوكيل الصحيح — ولا يكفي مستند يقتبس هذه الرسالة كبديل له —، وإلا يُرفض.
- **المنصات**: Linux، في جلسة تحتوي على سلسلة مفاتيح (ناقل جلسة D-Bus، Secret Service)؛ نظام macOS مقبول، دون اختباره بالقياسات. مرفوض على Windows، حيث لا يقرأ agy المتغيرات التي تعزل كل استدعاء، وعلى Linux بدون ناقل جلسة — جلسة SSH، أو حاوية، أو خادم: يخزن agy رمزه المميز هناك في ملف داخل `~/.gemini`، وهو ما يحجبه العزل. يأتي الرفض قبل أي تشغيل مع ذكر سببه، بدلاً من الانتظار دقيقة للحصول على رمز تسجيل الدخول.
- **النماذج**: نماذج `agy models`. تحمل نماذج Gemini مستوى الجهد في اسمها (`gemini-3.7-flash-low`…): يُرفض الاسم الخالي من لاحقة قبل الاستدعاء، ولا يكون لـ `--reasoning_effort` أي تأثير. تم تحديد الإعدادين الافتراضيين عبر حملة شملت أربع عشرة لغة (راجع [قياسات مفصلة](#قياسات-مفصلة)). يتمتع Claude وGPT-OSS بحصتهما الخاصة، وهي أصغر بكثير: حوالي 1% من نافذة الـ 5 ساعات لكل استدعاء تم قياسه، مقابل 0.05% في Flash.
- **الحصة**: لكل مجموعة، نافذة 5 ساعات وأخرى أسبوعية، بالتناسب مع تكلفة الرموز (tokens). تم القياس على حساب المؤلف بناءً على حملة من 32 ترجمة: حوالي نصف نقطة من نافذة الـ 5 ساعات لملف README بحجم 40,000 حرف باستخدام `gemini-3.7-flash-medium`؛ أما الحد الأسبوعي فيعتمد على المستوى. تتبع إعادة المحاولة ما يعلنه agy كقابل لإعادة المحاولة؛ وبخلاف ذلك، لا يُعاد تشغيل نافذة مستنفدة أبدًا: فهي تجعل كل ملف يفشل حتى إعادة التعيين التي يعرضها `/usage`.
- **أبطأ من واجهة برمجة التطبيقات (API)**: في المقال الكثيف الخاص بالقياسات، يستغرق Gemini 3.7 Flash وقتًا وسيطًا قدره 3 دقائق و14 ثانية لكل لغة عبر الاشتراك، مقابل دقيقة و18 ثانية عبر واجهة برمجة التطبيقات (API).
- **المقاطعة**: يؤدي الضغط على Ctrl-C، أو إغلاق الطرفية، إلى إيقاف agy مع الأمر بدلاً من تركه يكمل جولته مستهلكًا حصتك؛ وينطبق الأمر نفسه على Codex وGrok CLI وOpenCode. في ظل وجود `nohup`، تستمر الترجمة.
- مرفوض في بيئات التكامل المستمر CI (عند تعيين `CI` أو `GITHUB_ACTIONS`): يوجد تسجيل الدخول في سلسلة مفاتيح شخصية. على المشغّل (runner)، استخدم `--use_gemini` مع `GOOGLE_API_KEY`.
- المتغيرات: `AGY_BIN` (وإلا `PATH`، ثم `~/.local/bin/agy`)، `AGY_TIMEOUT` (بالثواني لكل مقطع، شاملة وقت البدء، الافتراضي 900).

**شروط الاستخدام: أنت المسؤول عن حسابك.** تحظر [شروط Antigravity](https://antigravity.google/terms) (القسم 6) و[الأسئلة الشائعة الخاصة به](https://antigravity.google/docs/faq/) الوصول إلى الخدمة عبر برنامج تابع لجهة خارجية باستخدام تسجيل دخول Antigravity — وقد ذُكر فيها Claude Code وOpenClaw وOpenCode — تحت طائلة تعليق الحساب. لا يقرأ aipmt الرمز المميز ولا يعيد استخدامه: بل يقوم بتشغيل الملف التنفيذي الرسمي في [الوضع عديم الواجهة (headless)](https://antigravity.google/docs/cli/headless/) الذي توثقه Google للسكريبتات والتكامل المستمر CI. اعتبر أحد موظفي Google أنه من «المعتاد» تشغيل `agy -p` من سكريبت محلي للعمل الخاص ([المنتدى الرسمي، 25 سبتمبر 2026، رد غير تعاقدي](https://discuss.ai.google.dev/t/is-using-the-official-agy-cli-through-a-local-mcp-server-with-third-party-ai-agents-permitted/184829))؛ ولا يوجد نص يفصل في حالة أداة موزعة كهذه.

**المستندات العامة فقط.** وفقًا للقسم 5 من الشروط نفسها، يمكن استخدام التبادلات — المطالبات، والردود، والبيانات الوصفية — لتحسين منتجات Google والتعلم الآلي ومراجعتها من قِبل مراجعين بشريين، بما في ذلك الاشتراكات المدفوعة. يتم إلغاء الاشتراك عبر الإعداد `enableTelemetry`، ذي التأثير غير الموثق، والذي لا يعينه aipmt؛ ولا تتبع إعداداتك لـ agy داخل عزله. لا تمرر أي شيء سري عبره.

### نحو المزود الذي تختاره: `--use_opencode`

[OpenCode](https://opencode.ai) هو وكيل برمجة مفتوح المصدر (MIT) يوجّه الطلبات إلى المزودين الذين تم تكوينهم داخله: مفتاح API، أو اشتراك، أو بوابة OpenCode Zen (نماذج مجانية، بدون حساب)، أو نموذج محلي. تم قياس مسارين من البداية إلى النهاية هنا: Zen وOllama.

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` إلزامي: بدونه، سيتراجع OpenCode إلى نموذج مجاني يمكن استخدام محادثاته للتدريب، وهذا الاختيار لا يتم نيابة عنك.

العزل في كل استدعاء:

- يحدد تكوين مضمن (inline)، له الأولوية على تكوينك، وكيلاً `aipmt` تُرفض جميع أدواته (`permission: { "*": "deny" }`)، مع تعطيل مشاركة الجلسة، و`--pure`، ودون `--auto` مطلقًا؛
- دليل عمل فارغ ومؤقت، مع تعيين `OPENCODE_DISABLE_PROJECT_CONFIG` و`OPENCODE_DISABLE_CLAUDE_CODE` — بدونهما، يحقن OpenCode في المطالبة ملف `AGENTS.md` الخاص بالدليل الحالي و`~/.claude/CLAUDE.md`. يظل ملف `~/.config/opencode/AGENTS.md` العام محقونًا، إذ لا يتيح OpenCode استبعاده؛
- عقد المخرجات: رمز الإرجاع 0، ولا توجد أحداث `error`، ولا استدعاء لأي أداة، والخطوة الأخيرة هي `stop`، والنص غير فارغ، والوكيل `aipmt` تم تحميله بالفعل — لا يؤدي تحديد `--agent` غير معروف إلى فشل OpenCode، بل يتراجع بصمت إلى وكيل البرمجة؛
- لا يُمرر أي مفتاح لـ `aipmt`، باستثناء `OPENCODE_API_KEY`، وهو مفتاح OpenCode نفسه. يتم تكوين المزودين داخل OpenCode، وليس في `.env` الخاص بـ `aipmt`.

معلومات يجب معرفتها:

- النماذج المجانية في Zen متغيرة وذات حدود غير موثقة، وقد تُستخدم محادثاتها في التدريب: مناسبة للتوثيق العام، وليست للمحتوى الخاص.
- يجب أن يوفر النموذج المحلي سياقًا لا يقل عن 16 ألف رمز (tokens)، حيث تصل المقاطع إلى 16,000 حرف. غالبًا ما يضبط Ollama السياق على 4,096: استخدم `Modelfile` مع `PARAMETER num_ctx 32768`.
- `--eco` بدون تأثير؛ ويُمرر `--reasoning_effort` كما هو كـ `--variant` الخاص بـ OpenCode.
- يسجل OpenCode كل جلسة في `~/.local/share/opencode/`.
- المتغيرات: `OPENCODE_BIN` (وإلا `PATH`، ثم `~/.opencode/bin/opencode`)، `OPENCODE_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 600). يمر `OPENCODE_CONFIG` كما هو إلى OpenCode.

مثال على نموذج محلي عبر Ollama، في `~/.config/opencode/opencode.json`:

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

يعطل `reasoningEffort: "none"` التفكير (reasoning) الذي يفعله Ollama افتراضيًا في هذه النماذج، والذي لا يمكن لملف Modelfile تعطيله. تم القياس على جملة من ست كلمات: 919 رمزًا للتفكير و68 ثانية بدون الخيار، مقابل 9 رموز معه.

### نحو أكثر من 400 نموذج: `--use_openrouter`

OpenRouter هو موجه يُحاسب حسب الاستخدام، برصيد موحد، أمام نماذج تستضيفها أطراف ثالثة — بما في ذلك النماذج الصينية المفتوحة التي لا يوفرها أي مزود آخر هنا.

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` إلزامي. يقوم فحص مسبق (preflight)، يُنفذ قبل أي فوترة، بضبط خصوصيتين في التوجيه:

- **يُخدم النموذج نفسه من قِبل عشرات المضيفين بحدود قصوى مختلفة** — في `z-ai/glm-5.3-flash`، يوجد 23 مضيفًا أحدهم مقيد بـ 2,048 رمز إخراج. يقرأ الفحص المسبق `/api/v1/models/{modèle}/endpoints`، ويستبعد المضيفين الذين يقل حد الإخراج لديهم عن 8,000 رمز أو ذوي الحالة المتدهورة، ويثبت البقية باستخدام `allow_fallbacks: false`.
- **تتم فوترة الاستدلال (reasoning) بسعر رموز الإخراج** — 107 رموز مقابل رمزين في رد «OK» من `z-ai/glm-5.2`. يتم إيقافه افتراضيًا؛ وتتلقى النماذج التي تفرضه أقل قدر من الجهد تقبله، حيث يمكن للجهد الافتراضي في الدليل أن يستنفد الإخراج قبل انتهاء الترجمة. تظل الأولوية لـ `--reasoning_effort`.

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- تأتي نافذة السياق من الدليل. يُرفض أي نموذج يقل سياقه عن 16,400 رمز قبل أي استدعاء: 8,400 للمطالبة والمقطع، و8,000 للإخراج كحد أدنى.
- يؤدي غياب المعرّف (slug) عن الدليل، أو تعذر الوصول إلى الدليل، أو عدم وجود مضيف يفي بالحد الأقصى إلى إيقاف الأمر.
- يُعد `finish_reason=length` مع مخرجات فارغة ميزانية استهلكها الاستدلال، وليس اقتطاعًا: توضح الرسالة ذلك.
- `--eco` بدون تأثير.
- المتغيرات: `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>)، `OPENROUTER_BASE_URL` (الافتراضي `https://openrouter.ai/api/v1`، ويلزم `https://`)، `OPENROUTER_TIMEOUT` (الافتراضي 900)، `OPENROUTER_PREFLIGHT_TIMEOUT` (الافتراضي 30).

### ملاحظة الترجمة

يضيف `--add_translation_note` ملاحظة، في `bottom` (الافتراضي)، أو `top` (بعد الـ front matter)، أو `both` (`--note_position`)، بتنسيق `legacy` (فقرة بخط عريض، افتراضي) أو `marker` (`--note_format`). التنسيق `marker` هو تعريف مرجعي غير مرئي في Markdown، `[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`، متبوعًا باقتباس بخط عريض: مقروء على GitHub، وقابل للاستخدام أثناء البناء بواسطة إضافة remark.

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## قياسات مفصلة

جميع القياسات هي ترجمات نُفذت فعليًا باستخدام `aipmt`، إلى أربع عشرة لغة: en، es، de، it، pt، nl، pl، sv، ro، ja، ko، zh، ar، hi.
يحسب عمود **المكتوبة** الملفات التي سمحت أدوات الحماية بمرورها؛ بينما يحسب عمود **بدون اختلاف** الملفات التي لم يسجل فيها `scripts/compare_structure.py` أي فارق — نفس عدد الأقسام، والعناوين الفرعية، والروابط، وعناوين URL المميزة، وكتل الأكواد البرمجية، والأكواد المضمنة، وصفوف الجداول، واقتباسات الكتل، والكلمات المكتوبة بخط عريض.

«بدون اختلاف» تعني «لم يُكتشف شيء»، وليس «متطابق تمامًا»: تحصي أداة المقارنة العناصر دون قراءة محتواها. فهي لا تبلغ عن عنوان من المستوى 4 تم حذفه، ولا عن نص كود مضمن تم استبداله، ولا عن علم (flag) تم تبديله، ولا تقيّم جودة اللغة.

### ما ليست عليه هذه القياسات

- **ليست تصنيفًا شاملًا**: يوفّر OpenRouter وحده أكثر من أربعمائة
  نموذج، تم قياس نحو خمسة عشر منها فقط.
- **مُدد زمنية تقريبية**: من ثلاث إلى ست ترجمات بالتوازي حسب
  الحملات، كما يختلف معدل نقل بيانات المزود خلال اليوم.
- **ملاحظات مرتبطة بتاريخ معين**: تتغير النماذج تحت الاسم نفسه، ومستنداتكم
  تختلف عن مستنداتنا.

لإعادة إجراء القياس على مستنداتك، باستخدام نسخة مجمّدة من الملف:

```bash
aipmt --file reference.md --target_dir out/ --source_lang fr --target_lang ja --use_gemini --force
aipmt --file veille.mdx   --target_dir out/ --source_lang fr --target_lang ja --use_gemini --news --force
python scripts/compare_structure.py reference.md out/reference-ja.md
# « structure identique », ou la liste des écarts — sortie 0 si identique, 1 sinon
```

## المساهمة

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

كلا السطرين ضروريان: بدون `pip install -e .`، سيرد `python -m aipmt`
بـ `No module named aipmt`.

أدوات الجودة، اختيارية ولكن يُوصى بها:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```

تُعاد توليد ترجمات المستودع الـ 28 (README وCHANGELOG، بأربع عشرة لغة)
باستخدام `./regen_translations.sh --force` — Codex و`gpt-5.6-sol` على
اشتراك ChatGPT افتراضيًا، أربع بالتوازي. يغيّر كل من `REGEN_PROVIDER` و
`REGEN_MODEL` المسار: يظل `antigravity` على اشتراك، وهو اشتراك Google،
ويمر دون استثناء؛ وتُرفض واجهة برمجة تطبيقات مدفوعة (`openai`، `gemini`،
`grok`، `openrouter`) بدون `REGEN_ALLOW_PAID_API=1`؛
ويضع `REGEN_JOB_TIMEOUT` حدًا أقصى لكل مهمة (600 ثانية، 1800 ثانية على Codex
وAntigravity). تفاصيل الأدوات موجودة في `CLAUDE.md`.
