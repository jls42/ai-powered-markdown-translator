يُترجم ملفات Markdown من لغة إلى أخرى مع الحفاظ على البنية: كتل الكود، والكود المضمن، وعناوين URL، والمراسخ، والجداول، وfront matter. أحد عشر مساراً لاستدعاء النماذج — خمس واجهات برمجة تطبيقات (APIs)، وأربعة اشتراكات بدون فوترة حسب الاستخدام، وموجّعان — مع قياس منشور لما يحافظ عليه كل نموذج فعلياً.

## باختصار

- **أحد عشر مساراً للمزودين**: واجهات برمجة تطبيقات OpenAI وMistral وClaude وGemini وGrok؛ اشتراكات ChatGPT (Codex) وGrok وGoogle (Antigravity) وClaude (Claude Code) بدون فوترة حسب الاستخدام؛ وموجّها OpenCode (مفتوح المصدر، مجاني أو محلي) وOpenRouter (أكثر من 400 نموذج).
- **لا أخطاء بسبب رمز ضائع**: تُستبدل كتل الكود، والكود المضمن، وعناوين URL، والمراسخ، والاقتباسات برموز بديلة قبل الاستدعاء ويتم التحقق منها عند الاستجابة. وإذا فُقد أيٌّ منها، لا تتم كتابة الملف.
- **المستندات الطويلة**: تقسيم المستند وفقاً لنافذة سياق النموذج.
- **وضع `--news`**: اقتباسات إنجليزية محمية وأعلام مُدارة بحسب اللغة، لمقالات الرصد الإخباري.
- **وضع `--eco`**: نماذج سريعة وأقل تكلفة.
- **ملاحظة ترجمة** اختيارية، في الأعلى، أو في الأسفل، أو في كلا الموضعين.

## التثبيت

pip install ai-powered-markdown-translator     # ou : pipx install ai-powered-markdown-translator

## الإعداد

تُقرأ المفاتيح من ثلاثة أماكن، مرتبة من الأعلى أولوية إلى الأدنى؛ ولا يملأ كل موقع إلا ما يتركه الموقع السابق فارغاً.

|     | أين                                           | الغرض                                 |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | متغيرات البيئة                                | CI، والحاويات، والتجاوز المؤقت        |
| 2   | `.env` في الدليل الحالي (أو دليل أصل)  | مفتاح خاص بمشروع معين                 |
| 3   | `~/.config/aipmt/.env`                                 | يُثبت مرة واحدة، ويسري في كل مكان      |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

يُقبل `GEMINI_API_KEY` بدلاً من `GOOGLE_API_KEY`. يتبع ملف المستخدم `XDG_CONFIG_HOME` (مسار مطلق فقط) و`%APPDATA%` على نظام Windows. وفي حال غياب أي مفتاح، يسرد الأمر المواقع الثلاثة.

**لا يمكن لملف `.env` الخاص بالمشروع إعادة توجيه الاستدعاءات أو اختيار البرنامج المنفّذ.** فهو يوفّر مفاتيح فقط، ولا يحدد أبداً وجهة أو ملفاً تنفيذياً: أي متغير ينتهي بـ `_BASE_URL`، أو `_API_BASE`، أو `_ENDPOINT`، أو `_BIN` (`CODEX_BIN`، `GROK_BIN`، `OPENCODE_BIN`، `AGY_BIN`)، أو `GROK_HOME`، وكذلك البروكسيات (`HTTP_PROXY`، `HTTPS_PROXY`، `ALL_PROXY`)، ومخازن الشهادات (`SSL_CERT_FILE`، `SSL_CERT_DIR`، `REQUESTS_CA_BUNDLE`، `CURL_CA_BUNDLE`)، و`XDG_CONFIG_HOME` / `APPDATA` يتم تجاهلها فيه مع إصدار تحذير. فلا ينبغي لأي مستودع مستنسخ أن يتمكن من تحويل مفتاحك أو إجبارك على تشغيل برنامجه الخاص عند أول عملية ترجمة. كما يُقرأ هذا الملف دون استيفاء: فلا ينسخ `NOM=${OPENAI_API_KEY}` المفتاح فيه. ضع هذه المتغيرات في البيئة أو في `~/.config/aipmt/.env`.

المتغيرات الاختيارية: `XAI_BASE_URL` (الافتراضي `https://api.x.ai/v1`)، و`CLAUDE_TIMEOUT` (بالثواني لكل استدعاء، الافتراضي 900)، و`CODEX_BIN`، و`CODEX_TIMEOUT` (الافتراضي 600)، و`GROK_BIN`، و`GROK_HOME` (الافتراضي `~/.grok`)، و`GROK_TIMEOUT` (الافتراضي 900)، و`GROK_TRANSLATE_SANDBOX`، و`AGY_BIN`، و`AGY_TIMEOUT` (الافتراضي 900)، و`OPENCODE_BIN`، و`OPENCODE_TIMEOUT` (الافتراضي 600)، و`OPENROUTER_BASE_URL` (يتطلب `https://`)، و`OPENROUTER_TIMEOUT` (الافتراضي 900)، و`OPENROUTER_PREFLIGHT_TIMEOUT` (الافتراضي 30). كل منها مفصل في قسم المزود الخاص به.

## الخطوات الأولى

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

ترجمة `document.md` إلى الإسبانية تُنتج `document-es.md` في `--target_dir`؛ ومع `--include_model`، تصبح `document-es-gpt-6.1-terra.md`. يتحول الامتداد دائماً إلى `.md` — فيعطي `article.mdx` النتيجة `article-en.md` — ما عدا مع `--keep_filename`، الذي يحتفظ بالاسم الأصلي. وتُتخطى أي ترجمة موجودة بالفعل بدون `--force`.

رموز الخروج: `0` إذا نجح كل شيء أو تم تخطيه، و`1` إذا بقي ملف فاشل (تُعرض القائمة في مخرج الأخطاء القياسي stderr)، و`2` إذا كان الخلل في الإعداد. لا تتم كتابة الملف الفاشل أبداً، حتى لو فشلت عملية الكتابة نفسها: يُكتب المحتوى في ملف جانبي ثم يُعاد تسميته. وتكفي إعادة التشغيل.

أهم ما يُستفاد من ذلك:

- **الترجمة المرفوضة ليست ترجمة مشوهة.** فعندما يُفقد رمز بديل عند الاستجابة،
  لا يُكتب الملف وتُحسب اللغة على أنها مرفوضة. وهذا ما حدث مع Grok في المقال:
  فقدان أربعة أجزاء من الكود المضمن وثلاثة عناوين URL منذ المقطع الأول، في
  أنظمة الكتابة الخمسة غير اللاتينية.
- **قد يرفض النموذج مستنداً بأكمله بسبب جملة واحدة.** فنموذج Opus 5.5 يترجم
  ملف README هذا دون أي خلل، لكنه لم يترجم أي مقال رصد: إذ أوقفت ضوابط
  الحماية لديه الاستجابة عند خبر موجز عن علم الأحياء. ولم يُكتب الملف، وأوضح
  aipmt السبب.
- **شبكة الأمان هذه لا تشمل العناوين ولا الجداول ولا front matter ولا متن
  النص.** فالنموذج الذي يحذف قسماً يُرجع ملفاً تكتبه الأداة دون اعتراض — كما
  هو الحال مع Mistral. هذه العناصر لا يمكن استبدالها برمز بديل، والضوابط
  الحالية لا تتحقق منها؛ حيث يكتشف `scripts/compare_structure.py` القسم المفقود ولكن بعد فوات
  الأوان.
- **لا يحمل Grok تقييماً لملف README هذا**: انتهت صلاحية جلسة CLI الخاصة به بعد
  اثنتي عشرة لغة، منها إحدى عشرة لغة دون أي اختلاف. ولا يتم تقييم الاختبارات
  التي لم تكتمل.
- **كثافة المستند أهم من لغته.** يصمد Grok مع ملفات README العادية ويتعثر أمام
  مقال زاخر بالروابط، بما في ذلك باللغة الهولندية.

## مزودو الخدمة

### عبر واجهة برمجة التطبيقات (API): OpenAI وMistral وClaude وGemini وGrok

```bash
aipmt --source_dir content/fr --target_dir content/en --target_lang en             # OpenAI, défaut
aipmt --use_mistral --source_dir content/fr --target_dir content/es --target_lang es
aipmt --use_claude  --source_dir content/fr --target_dir content/de --target_lang de
aipmt --use_gemini  --source_dir content/fr --target_dir content/ja --target_lang ja
aipmt --use_grok    --source_dir content/fr --target_dir content/pt --target_lang pt
```

ينتقل `--eco` إلى الفئة الاقتصادية لكل مزود خدمة.

| المزود      | الجودة (الافتراضي)                                                   | اقتصادي (`--eco`) |
| ----------- | -------------------------------------------------------------------- | ------------------------- |
| OpenAI      | `gpt-6.1-terra`                                                      | `gpt-6-luna`           |
| Claude      | `claude-sonnet-5-5`                                                      | `claude-haiku-5-5`           |
| Mistral     | `mistral-large-latest`                                                      | `mistral-small-latest`           |
| Gemini      | `gemini-4-hydrogen`                                                      | `gemini-3.1-flash-lite`           |
| Codex       | `gpt-6.1-sol` (أيضًا `gpt-5.6-sol` و`terra` و`luna` عبر `--model`) | `gpt-5.6-luna`           |
| Grok API    | `grok-4.7`                                                      | `grok-4.3`           |
| Grok CLI    | `grok-4.7`                                                      | بالمثل — `--eco` بدون أي تأثير |
| Antigravity | `gemini-3.8-flash-medium`                                                      | `gemini-3.8-flash-low`           |
| Claude Code | `sonnet`، جهد `low`                                 | بالمثل — `--eco` بدون أي تأثير |
| OpenCode    | `--model provider/modèle` إلزامي                                               | بالمثل — `--eco` بدون أي تأثير |
| OpenRouter  | `--model fournisseur/modèle` إلزامي                                               | بالمثل — `--eco` بدون أي تأثير |

تتبع الإعدادات الافتراضية أحدث جيل لكل مزود، ويتم قياسها قبل اعتمادها: GPT-6 لدى OpenAI، وGemini 4 Hydrogen لدى Google، وGrok 4.7 لدى xAI منذ الإصدار 1.19.0. تظل النماذج السابقة مقبولة عبر `--model` (`gpt-5.6-terra`، `gemini-3.8-flash`، `grok-4.6`...)، وكذلك Gemini 4 Argon وCarbon، الفئة العليا من Google. يضبط aipmt بنفسه جهد الاستدلال لنماذج GPT وGrok، مع إيقافه في `--eco`، ويفرضه `--reasoning_effort`؛ ويتلقى Gemini دائمًا أدنى مستوى يقبله.
أي عطل مؤقت في واجهة برمجة تطبيقات Gemini (أخطاء 503، 429، تجاوز المهلة) يعيد تشغيل الطلب حتى ثلاث مرات، بعد 10 ثم 20 ثم 40 ثانية. وأي محاولة تظل دون رد يتم التخلي عنها بعد 5 دقائق، ثم يعاد تشغيلها بالمثل: الخادم الصامت يؤدي إلى فشل المقطع خلال عشرين دقيقة تقريبًا كحد أقصى، بدلًا من التعليق إلى ما لا نهاية.

### على اشتراك ChatGPT: `--use_codex`

يقود أداة CLI الرسمية لـ Codex: يتم خصم الترجمة من حصة اشتراك ChatGPT، دون الحاجة إلى مفتاح API أو فوترة حسب الاستخدام.

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- يتم البحث عن الملف التنفيذي في `CODEX_BIN`، ثم في `PATH`، ثم في حزمة `openai-codex-cli-bin`. ولا تتم قراءة `~/.codex/auth.json` أبدًا.
- يتم إزالة `OPENAI_API_KEY` و`CODEX_API_KEY` من بيئة العملية الفرعية: وجود مفتاح لا يؤدي أبدًا إلى التبديل نحو واجهة برمجة التطبيقات (API).
- يكلف كل مقطع "رسالة" واحدة على الأقل من نافذة الـ 5 ساعات — ورسالتين إذا فشل التحقق من صحته وتمت إعادة محاولته. تعلن OpenAI، على سبيل التقدير، عن 250-2,000 رسالة/5 ساعات لـ `gpt-5.6-luna` (`--eco`) و10-100 لـ `gpt-5.6-sol` في خطة Plus.
- يمر `--model gpt-5.6-sol`، وهو الافتراضي حتى الإصدار 1.16.3، و`--model gpt-5.6-terra` و`--model gpt-5.6-luna` عبر الاشتراك أيضًا.
- لا يؤدي خطأ 429 من الخادم إلى فقدان الملف: يعيد Codex الاتصال تلقائيًا، وينتظر aipmt نهاية الجولة، وإذا ظل خطأ 429 قائمًا، يُستأنف المقطع بعد 30 ثم 60 ثانية. أما النموذج الذي لا يملك الحساب حق الوصول إليه فيُرجع خطأ 400 "model is not supported when using Codex with a ChatGPT account".
- أبطأ من واجهة برمجة التطبيقات (API)، ويتسع الفارق مع حجم المستند: في ملف README هذا، 6 دقائق و46 ثانية لكل لغة في المتوسط مع `gpt-5.6-sol`، مقابل 36 ثانية لـ `gemini-3.7-flash`.
- مرفوض في بيئات CI (عند تحديد `CI` أو `GITHUB_ACTIONS`): تتم مصادقة الاشتراك عبر ملف جلسة شخصي لا مكان له على مشغّل (runner) مشترك.
- المتغيرات: `CODEX_BIN`، و`CODEX_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 600).

### على اشتراك Grok: `--use_grok_cli`

المبدأ نفسه مع أداة CLI الرسمية Grok Build، على اشتراك SuperGrok أو X Premium+.

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --file README.md --target_dir . --target_lang pl
```

- **عزل أضعف من Codex.** لا تعمل بيئة الحماية (sandbox) لنظام التشغيل الخاصة بـ Grok على العديد من أجهزة Linux الحديثة (AppArmor، ومقابس وقت تشغيل الحاويات)، والملف التعريفي الذي لا يمكن تطبيقه يبدأ بدون عزل في صمت. لذلك لا يطلب البرنامج النصي أي ملف تعريفي افتراضيًا، ويعلن عن ذلك، ويعتمد على قواعد `--deny` الخاصة بـ CLI، بما في ذلك القاعدة الشاملة `*` — وهي الطبقة الوحيدة التي ترفض البدء بدلًا من إزالة الحماية دون إشعار. يتطلب `GROK_TRANSLATE_SANDBOX=read-only` بيئة حماية لنظام التشغيل، ويفشل بدء التشغيل إذا كان الجهاز لا يستطيع توفيرها.
- الحصة أسبوعية ومشتركة مع Chat وImagine وVoice، ولا يوجد أي أمر لقراءتها: يمكن لدفعة ترجمة أن تستهلك الاستخدام الحواري دون سابق إنذار.
- المتغيرات: `GROK_BIN`، و`GROK_HOME` (دليل CLI، الافتراضي `~/.grok`)، و`GROK_TIMEOUT` (الافتراضي 900)، و`GROK_TRANSLATE_SANDBOX`.

### على اشتراك Google: `--use_antigravity`

المبدأ نفسه مع `agy`، أداة CLI الرسمية لـ Antigravity: لمن يدفع مقابل Google AI Pro أو Ultra، تُخصم الترجمة من حصة الاشتراك بدلًا من الفوترة حسب الرموز (tokens). هذا هو المسار الوحيد نحو هذه الحصة: لم يعد Gemini CLI يخدم هذه الحسابات منذ 18 يونيو 2026 ([إعلان](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/))، وحزمة SDK لـ Antigravity لا تقبل سوى مفتاح API أو مشروع Google Cloud.

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **لا تظل أي مسارات مدفوعة مفتوحة.** لا يتلقى agy من بيئتك سوى قائمة مغلقة من المتغيرات — `PATH`، واللغة والمنطقة الزمنية، والطرفية، والهوية، والوكلاء والشهادات، وناقل الجلسة — وبدون أي مفاتيح: تتسبب عدة متغيرات تابعة له في تحويل الطلب دون عرض أي شيء (تم قياس ذلك: يرسل أحدها المستند إلى بوابة طرف ثالث، وآخر إلى مشروع Google Cloud خاضع للرسوم)، وكانت قائمة الرفض تغفل بعضها في كل مراجعة. قبل أي مقطع، يجب أن يُظهر أمر `agy -p /config`، الذي لا يستهلك أي حصة، أن أرصدة الذكاء الاصطناعي المدفوعة معطلة، دون مفتاح API أو مشروع Google Cloud — وغياب الإعداد يُعد رفضًا — وإلا فلن يُترجم أي شيء؛ كما يجب أن يؤكد سجل كل طلب الاشتراك (`authMethod=consumer`)، وإلا تُرفض الاستجابة.
- **العزل.** يعمل كل طلب في دليل شخصي خاص ومؤقت، مع وكيل ترجمة خالٍ من الأدوات: لا تدخل فيه إعداداتك أو قواعدك أو ملحقاتك أو خوادم MCP أو خطافات agy، ولا يُضاف أي شيء إلى سجلك، ويظل الاتصال في حلقة المفاتيح التي لا يقرأها aipmt مطلقًا. يؤدي تعذر العثور على الوكيل إلى تراجع agy بصمت إلى وكيل البرمجة وأدواته: يجب أن يؤكد سطر كامل من السجل استخدام الوكيل الصحيح — ولا يُعد المستند الذي يستشهد بهذه الرسالة بديلًا عنه — وإلا يُرفض.
- **الأنظمة الأساسية**: Linux، في جلسة تحتوي على حلقة مفاتيح (ناقل جلسة D-Bus، خدمة Secret Service)؛ نظام macOS مقبول دون إجراء قياسات عليه. مرفوض على نظام Windows، حيث لا يقرأ agy المتغيرات التي تعزل كل استدعاء، وعلى Linux بدون ناقل جلسة — جلسة SSH، أو حاوية، أو خادم: يخزن agy رمزه في ملف داخل `~/.gemini` تحجبه عملية العزل. يأتي الرفض قبل أي تشغيل مع ذكر سببه، بدلًا من الانتظار لمدة دقيقة للحصول على رمز تسجيل الدخول.
- **النماذج**: نماذج `agy models`. تحمل نماذج Gemini مستوى الجهد في اسمها (`gemini-3.8-flash-medium`...): يُرفض الاسم الذي لا يحتوي على لاحقة قبل الطلب، ويكون `--reasoning_effort` بدون تأثير. الافتراضي هو `gemini-3.8-flash-medium`، و`gemini-3.8-flash-low` في `--eco`، منذ أن توقف agy عن تقديم Gemini 3.7 Flash؛ الحملة التي حددت الإعداد الافتراضي مشروحة في [قياسات مفصلة](#قياسات-تفصيلية). يشارك Gemini 4 Hydrogen (`gemini-4-hydrogen-low`...) حصة 3.8 Flash ويستهلك منها قدرًا أكبر: 0.95 نقطة من نافذة الـ 5 ساعات لهذا الـ README عند الجهد المتوسط، مقابل 0.32. لدى Claude وGPT-OSS حصتهما الخاصة، وهي أصغر بكثير: حوالي 1% من نافذة الـ 5 ساعات لكل طلب تم قياسه، مقابل 0.05% في Flash. يمتلك Gemini 4 Argon حصته الخاصة، وهي أسبوعية: يستهلك هذا الـ README منها 1.35%.
- **الحصة**: حسب المجموعة، نافذة مدتها 5 ساعات ونافذة أسبوعية، بما يتناسب مع تكلفة الرموز (tokens). تم قياسه على حساب المؤلف: حوالي 16 نقطة من نافذة الـ 5 ساعات لكل مليون حرف مصدر في `gemini-3.8-flash-medium`، و14 في `gemini-3.7-flash-medium`، و7 إلى 8 عند الجهد المنخفض — وبالتالي فإن ملف README المكون من 40,000 حرف يكلف أكثر من نصف نقطة بقليل. أما الحد الأسبوعي فيعتمد على الفئة. تتبع إعادة المحاولة ما يعلنه agy على أنه قابل لإعادة المحاولة؛ وبخلاف ذلك، لا يُعاد طلب النافذة المستنفدة أبدًا: فهي تتسبب في فشل كل ملف حتى إعادة التعيين التي يعرضها `/usage`.
- **أبطأ من واجهة برمجة التطبيقات (API)**: في المقال الكثيف الخاص بالقياسات، 3 دقائق و59 ثانية لكل لغة في المتوسط في `gemini-3.8-flash-medium` و3 دقائق و14 ثانية في `gemini-3.7-flash-medium`، مقابل دقيقة و18 ثانية لـ Gemini 3.7 Flash عبر واجهة برمجة التطبيقات.
- **المقاطعة**: يؤدي الضغط على Ctrl-C، أو إغلاق الطرفية، إلى إيقاف agy مع الأمر بدلًا من تركه يكمل جولته مستهلكًا حصتك؛ وينطبق الأمر نفسه على Codex وGrok CLI وOpenCode. تحت `nohup`، تستمر الترجمة.
- مرفوض في بيئات CI (عند تحديد `CI` أو `GITHUB_ACTIONS`): يعيش الاتصال في حلقة مفاتيح شخصية. على المشغّل (runner)، استخدم `--use_gemini` مع `GOOGLE_API_KEY`.
- المتغيرات: `AGY_BIN` (وإلا `PATH`، ثم `~/.local/bin/agy`)، و`AGY_TIMEOUT` (بالثواني لكل مقطع، شاملًا وقت البدء، الافتراضي 900).

**شروط الاستخدام: حسابك هو المسؤول.** تحظر [شروط Antigravity](https://antigravity.google/terms) (القسم 6) و[الأسئلة الشائعة](https://antigravity.google/docs/faq/) الوصول إلى الخدمة عبر برامج خارجية باستخدام اتصال Antigravity — وتم ذكر Claude Code وOpenClaw وOpenCode هناك — تحت طائلة تعليق الحساب. لا يقرأ aipmt الرمز المميز ولا يعيد استخدامه: إنه يشغّل الملف التنفيذي الرسمي في [الوضع بدون واجهة (headless)](https://antigravity.google/docs/cli/headless/) الذي توثقه Google للبرامج النصية وبيئات CI. اعتبر أحد أعضاء Google أنه من "القياسي" تشغيل `agy -p` من برنامج نصي محلي للعمل الخاص ([المنتدى الرسمي، 25 سبتمبر 2026، رد غير تعاقدي](https://discuss.ai.google.dev/t/is-using-the-official-agy-cli-through-a-local-mcp-server-with-third-party-ai-agents-permitted/184829))؛ ولا يوجد نص قانوني يحسم حالة أداة موزعة مثل هذه.

**المستندات العامة فقط.** وفقًا للقسم 5 من الشروط نفسها، يمكن استخدام التبادلات — المطالبات، والردود، والبيانات الوصفية — لتحسين منتجات Google والتعلم الآلي ومراجعتها من قبل البشر، بما في ذلك الاشتراكات المدفوعة. يتم إلغاء الاشتراك عبر الإعداد `enableTelemetry`، ذي التأثير غير الموثق، والذي لا يطبقه aipmt؛ ولا تنتقل إعداداتك لـ agy إلى داخل بيئته المعزولة. لا تمرر أي شيء سري عبره.

### بخصوص اشتراك Claude: `--use_claude_code`

المبدأ نفسه ينطبق مع `claude`، وهو CLI الرسمي لـ Claude Code، في وضع `-p`: لمن
يدفع مقابل Claude Pro أو Max، تُخصم الترجمة من حصة
الاشتراك بدلاً من فوترتها حسب التوكن. لا ينبغي الخلط بينه وبين
`--use_claude`، واجهة برمجة تطبيقات Anthropic، التي تُفوتر حسب الاستخدام.

```bash
claude                                   # une fois : /login avec le compte de l'abonnement
aipmt --use_claude_code --file README.md --target_dir . --target_lang en
```

- **لا يظل أي مسار مدفوع مفتوحاً، وتُثبت كل مكالمة ذلك.** لا
  يتلقى Claude Code من بيئتك سوى قائمة مغلقة من المتغيرات — لا
  مفتاح API، ولا رمز مميز، ولا مزود سحابي، ولا علامة من جلسة Claude Code
  التي قد يُشغَّل منها aipmt. قبل المقطع الأول، يجب أن يُظهر
  `claude auth status` اتصال الاشتراك، بدون مفتاح Console، ويجب أن يؤكد ذلك
  `/usage`، الذي لا يستهلك أي حصة؛ وتؤكد كل مكالمة ذلك بدورها في
  حدث التهيئة الخاص بها، وإلا فسيتم رفض الاستجابة.
- **عطّل « extra usage »** (في claude.ai، الإعدادات ← الاستخدام)
  لكي يظل الاستخدام مجانياً تماماً: إذا تم تفعيله، فإنه يتولى المسؤولية عند نفاد نافذة الاستخدام
  ويقوم بالفوترة دون إظهار أي خطأ. يُوقف aipmt الترجمة بمجرد أن يُشير
  تقرير الحصة لإحدى المكالمات إلى ذلك، ولكن تلك المكالمة تكون قد احتُسبت بالفعل.
- **حصة مشتركة مع جلسات Claude Code الخاصة بك.** تُبلّغ كل مكالمة
  عن استخدام نوافذ الـ 5 ساعات والأسبوع؛ إذا تجاوز 80%
  (`AIPMT_CLAUDE_MAX_UTILIZATION`)، فلن يتم إطلاق أي مقطع إضافي، لتجنب
  استنزاف ما يلزم لعملك.
- **العزل.** تعمل كل مكالمة بدون أدوات، في دليل خاص
  وقابل للتجاهل، في وضع بدون تخصيص: فلا يتم تحميل ملفات `CLAUDE.md` الخاصة بك، ولا مكوناتك الإضافية،
  أو خطافاتك (hooks)، أو خوادم MCP أو إعداداتك، ولا يُحفظ أي شيء من
  الجلسة. يتم قطع المرفقات: يظل أي `@chemin` في مستندك
  مجرد نص ولا يفتح أي ملف (تم قياس ذلك).
- **النماذج**: `sonnet` افتراضياً، بجهد `low`، وفي `--eco` أيضاً:
  لا يُغيّر `--eco` أي شيء في هذا المسار. وبحسب القياس على المستندات نفسها، فإن `haiku`
  أبطأ بمرتين — فهو يفكر دون إمكانية منعه — مقابل
  تكلفة أقل بقليل، بينما يرفض `opus` محتويات في علم الأحياء (النقطة
  التالية). كلاهما يظل متاحاً عبر `--model`؛ وتتبع هذه الأسماء المستعارة
  أحدث نموذج من عائلتها. يتم رفض `fable` والمتغيرات `[1m]`،
  لأنها تُحوَّل إلى أرصدة مدفوعة. يضبط `--reasoning_effort` الجهد،
  الذي لا تستفيد منه الترجمة إطلاقاً: فالتفكير المقاس منعدم أو شبه منعدم.
- **يرفض Opus بعض محتويات علم الأحياء.** حواجز الحماية لديه أكثر
  صرامة من حواجز Sonnet، وتُحذّر رسالة خطأ Anthropic من أنها
  « can sometimes flag biology-research-adjacent work ». وفقاً للقياس: موجز
  رصد حول 279 جزيئاً تم توليدها تسبب في رفض المقال في اللغات الأربع
  عشرة. لم يُكتب شيء: يرفض aipmt الاستجابة المبتورة، ويحدد
  حواجز الحماية وينصح باستخدام `--model sonnet`.
- مرفوض في CI (إذا كان `CI` أو `GITHUB_ACTIONS` معرّفاً) وعلى نظام Windows (لم يتم قياسه).
- المتغيرات: `AIPMT_CLAUDE_BIN` (وإلا `PATH`، ثم `~/.local/bin/claude`)،
  `AIPMT_CLAUDE_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 900)،
  `AIPMT_CLAUDE_MAX_UTILIZATION` (الافتراضي 0.8)، `CLAUDE_CONFIG_DIR` (حساب
  Claude Code، ولا يؤخذ أبداً من ملف `.env` الخاص بالمشروع)؛ أدلة العمل تحت
  `XDG_CACHE_HOME/aipmt/claude-code` (الافتراضي `~/.cache`).

**شروط الاستخدام: حسابك هو المسؤول.** لا تمنع
[صفحة شروط Claude Code](https://code.claude.com/docs/en/legal-and-compliance)
« an end user from signing in to the unmodified Claude Code binary
with their own Claude subscription »: وهذا ما يفعله aipmt، الذي يُشغّل
الملف الثنائي الرسمي ولا يقرأ الرمز المميز أبداً. لكن Anthropic « does not permit
third-party developers […] to route requests through Free, Pro, or Max plan
credentials on behalf of their users »، وتفضل مفتاح API للأدوات
الخارجية، « including open-source projects »، وتحتفظ بالحق في خصم
استخدامها من الأرصدة المدفوعة
([مساعدة Claude](https://support.claude.com/en/articles/13189465-logging-in-to-your-claude-account)).
لا يوجد نص يحسم حالة أداة موزعة تقوم بتشغيل الملف الثنائي.

**البيانات**: في حسابات Free وPro وMax، ينطبق تدريب النماذج
أيضاً على Claude Code عندما يسمح إعداد الخصوصية بذلك
([صفحة البيانات](https://code.claude.com/docs/en/data-usage)). لا يحتفظ aipmt
بأي نص منسوخ محلياً (`--no-session-persistence`). لا تُمرّر
أي شيء سري عبره.

### نحو المزود الذي تختاره: `--use_opencode`

[OpenCode](https://opencode.ai) هو وكيل برمجة مفتوح المصدر (MIT) يقوم
بالتوجيه نحو المزودين المكوّنين بداخله: مفتاح API، اشتراك،
بوابة OpenCode Zen (نماذج مجانية، بدون حساب) أو نموذج محلي. تم
قياس مسارين بالكامل هنا، وهما Zen وOllama.

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` إلزامي: بدونه، سيتراجع OpenCode إلى نموذج مجاني
قد تُستخدم محادثاته للتدريب، وهذا خيار لا ينبغي أن يُتخذ
نيابة عنك.

العزل في كل مكالمة:

- تكوين مضمن (inline)، له الأولوية على تكوينك، يحدد وكيلاً `aipmt`
  تُرفض جميع أدواته (`permission: { "*": "deny" }`)، ومشاركة
  الجلسة معطلة، `--pure`، ولا يكون أبداً `--auto`؛
- دليل عمل فارغ وقابل للتجاهل، مع وضع `OPENCODE_DISABLE_PROJECT_CONFIG` و
  `OPENCODE_DISABLE_CLAUDE_CODE` — بدونهما، يحقن OpenCode في
  المطالبة ملف `AGENTS.md` من الدليل الحالي و`~/.claude/CLAUDE.md`. ويظل
  ملف `~/.config/opencode/AGENTS.md` العام محقوناً، حيث لا يسمح OpenCode
  باستبعاده؛
- عقد الإخراج: رمز إرجاع 0، بدون أحداث `error`، بدون أي استدعاء
  أداة، والخطوة الأخيرة تكون `stop`، ونص غير فارغ، والوكيل `aipmt`
  محمل بالفعل — وجود `--agent` غير معروف لا يجعل OpenCode يفشل، بل
  يتراجع بصمت إلى وكيل البرمجة؛
- لا يُرسل أي مفتاح لـ `aipmt`، باستثناء `OPENCODE_API_KEY`، وهو مفتاح
  OpenCode نفسه. يتم تكوين المزودين داخل OpenCode، وليس في
  ملف `.env` الخاص بـ `aipmt`.

معلومات يجب معرفتها:

- النماذج المجانية في Zen متغيرة، بحدود غير موثقة،
  وقد تُستخدم محادثاتها للتدريب: مناسبة للتوثيق
  العام، وليست للمحتوى الخاص.
- يجب أن يوفر النموذج المحلي سياقاً لا يقل عن 16 ألف توكن، حيث تصل المقاطع
  إلى 16,000 حرف. وغالباً ما يضبط Ollama السياق عند 4,096: ينبغي استخدام
  `Modelfile` مع `PARAMETER num_ctx 32768`.
- `--eco` ليس له أي تأثير؛ يُمرر `--reasoning_effort` كما هو كـ
  `--variant` لـ OpenCode.
- يسجل OpenCode كل جلسة في `~/.local/share/opencode/`.
- المتغيرات: `OPENCODE_BIN` (وإلا `PATH`، ثم `~/.opencode/bin/opencode`)،
  `OPENCODE_TIMEOUT` (بالثواني لكل مقطع، الافتراضي 600). يُمرر `OPENCODE_CONFIG`
  كما هو إلى OpenCode.

مثال على نموذج محلي عبر Ollama، في `~/.config/opencode/opencode.json`:

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

يوقف `reasoningEffort: "none"` التفكير الذي يفعّله Ollama افتراضياً في هذه
النماذج، والذي لا يمكن لـ Modelfile تعطيله. بحسب القياس على جملة من
ست كلمات: 919 توكن تفكير و68 ثانية بدون الخيار، مقابل 9 توكنات معه.

### نحو أكثر من 400 نموذج: `--use_openrouter`

OpenRouter هو موجه يُفوتر حسب الاستخدام، برصيد موحد، أمام
نماذج تستضيفها أطراف ثالثة — بما في ذلك النماذج الصينية المفتوحة التي لا
يعرضها أي مزود آخر هنا.

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` إلزامي. يقوم فحص مسبق (preflight)، يُنفذ قبل أي فوترة، بضبط
خاصيتين في التوجيه:

- **يتم تقديم النموذج نفسه بواسطة عشرات المضيفين بحدود قصوى
  مختلفة** — في `z-ai/glm-5.3-flash`، يوجد 23 مضيفاً أحدهم محدد بحد أقصى
  2,048 توكن للإخراج. يقرأ الفحص المسبق `/api/v1/models/{modèle}/endpoints`،
  ويستبعد المضيفين الذين يقل حد إخراجهم عن 8,000 توكن أو ذوي الحالة المتدهورة،
  ويثبت الباقين باستخدام `allow_fallbacks: false`.
- **تتم فوترة التفكير بسعر الإخراج** — 107 توكنات مقابل توكنين في
  استجابة « OK » من `z-ai/glm-5.2`. يتم إيقافه افتراضياً؛ والنماذج
  التي تفرضه تتلقى أدنى جهد تقبله، حيث يمكن للافتراضي في
  الكتالوج أن يستنفد الإخراج قبل انتهاء الترجمة.
  يظل لـ `--reasoning_effort` الأولوية.

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- تأتي نافذة السياق من الكتالوج. يُرفض أي نموذج يقل عن 16,400 توكن
  قبل أي استدعاء: 8,400 للمطالبة والمقطع، و8,000 للإخراج
  كحد أدنى.
- وجود slug غير موجود في الكتالوج، أو تعذر الوصول إلى الكتالوج، أو غياب
  مضيف يحقق الحد الأدنى المطلوب يؤدي إلى إيقاف الأمر.
- إن ظهور `finish_reason=length` مع مخرجات فارغة يعني استهلاك الميزانية بواسطة
  التفكير، وليس اقتطاعاً: وتميّز الرسالة ذلك.
- `--eco` ليس له أي تأثير.
- المتغيرات: `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>)،
  `OPENROUTER_BASE_URL` (الافتراضي `https://openrouter.ai/api/v1`، و`https://`
  مطلوب)، `OPENROUTER_TIMEOUT` (الافتراضي 900)، `OPENROUTER_PREFLIGHT_TIMEOUT`
  (الافتراضي 30).

### ملاحظة الترجمة

يضيف `--add_translation_note` ملاحظة، في `bottom` (افتراضي)، أو `top` (بعد
البيانات الوصفية front matter) أو `both` (`--note_position`)، بتنسيق `legacy` (فقرة
بالخط العريض، افتراضي) أو `marker` (`--note_format`). التنسيق `marker` عبارة عن
تعريف مرجعي غير مرئي في Markdown،
`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`،
يليه اقتباس بالخط العريض: مقروء على GitHub، وقابل للاستخدام أثناء البناء بواسطة
مكون إضافي لـ remark.

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## قياسات تفصيلية

جميع القياسات عبارة عن ترجمات نُفذت بالفعل باستخدام `aipmt`، نحو
أربع عشرة لغة: en، es، de، it، pt، nl، pl، sv، ro، ja، ko، zh، ar، hi.
يحسب عمود **المكتوبة** الملفات التي سمحت أدوات الحماية بتمريرها؛ بينما يحسب **بدون تباين**
الملفات التي لم يرصد فيها `scripts/compare_structure.py` أي شيء — العدد نفسه من
الأقسام، والعناوين الفرعية، والروابط، وعناوين URL المميزة، والكتل البرمجية،
والأكواد المضمنة، وصفوف الجداول، وكتل الاقتباس، والكلمات المكتوبة بخط عريض.

تعني عبارة «بدون تباين» أنه «لم يتم اكتشاف شيء»، وليست «مطابقة تماماً»: فأداة المقارنة
تحسب العناصر دون قراءة محتواها. فهي لا تنبه إلى عنوان
من المستوى 4 تم حذفه، ولا إلى استبدال نص كود مضمن، ولا إلى استبدال علم،
ولا إلى رابط داخلي أُنشئ بقوس زائد،
`[texte]((#ancre))`، لم يعد يؤدي إلى أي مكان — كما أنها لا تُقيّم
اللغة.

المدونة بواسطة `gemini-3.7-flash-medium`: كُتبت 14 من أصل 14، جميعها بدون تباين، في زمن تراوح بين 87 و
128 ثانية لكل لغة.

قِيست صفوف `--use_claude_code` في 26 سبتمبر على
المقال نفسه، عبر أربع ترجمات بالتوازي، بجهد `low`. مع `sonnet`، بقيت
الاقتباسات الإنجليزية سليمة في اللغات الأربع عشرة، وفي اللغة الإنجليزية، أزال
النموذج بنفسه أسطر الترجمة الفرنسية، دون اختلاق أي
علم. لم يكتب `opus` أي لغة: ففي كل لغة، أوقفت حواجز الحماية لديه
الاستجابة عند المقطع الأخير، بسبب خبر موجز عن 279 جزيئاً تم
توليدها لموقع ربط. وعند إرسال هذا الخبر الموجز بمفرده، رُفض
تحت فئة «bio»؛ في حين ترجمه `sonnet` في كل مكان. يكتب `haiku`
اللغات الأربع عشرة؛ وفي ثلاث منها (en، pl، ro)، تحوّل عنوان قسم من
المستوى 2 إلى المستوى 1. وهو يفكر دون إمكانية منعه — 61% من
توكنات الإخراج الخاصة به —، مما أدى إلى استغراق أكثر من ضعف وقت `sonnet`.

قِيست الصفوف `claude-sonnet-5-5` و`claude-haiku-5-5` و`claude-haiku-4-5`
في 18 أكتوبر عبر واجهة برمجة تطبيقات Anthropic، على المقال نفسه، عبر أربع
ترجمات بالتوازي لكل نموذج. يرفض Sonnet 5.5 تعطيل ميزة
التفكير لديه: لذا يرسل له aipmt أدنى إعداد يقبله، ولا تحمل
ردوده أي أثر لها. يكتب اللغات الأربع عشرة بدون تباين ودون الحاجة
لإعادة أي مقطع؛ وفي اللغة الإنجليزية، أزال بنفسه أسطر
الترجمة الفرنسية، دون اختلاق أي علم، وبقيت الاقتباسات الإنجليزية
سليمة في كل مكان. تم قياس Haiku 5.5 بتفكيره التكيفي: فعند
تعطيل التفكير، ترك فقرات كاملة بالفرنسية، وهو ما ترفضه أداة الحماية —
حيث كُتبت 3 لغات فقط من أصل 14. تعثر كلا النموذجين من Haiku في الخبر الموجز نفسه: غيّر Haiku 5.5
مستوى عنوانه أو كرره باليابانية والكورية
والصينية، بينما حوّله Haiku 4.5 إلى المستوى 1 في سبع لغات، وتركه باللغة
الفرنسية في النسخة اليابانية. تبلغ تكلفة Haiku 4.5 ما مقداره 3.67 دولارات لكلا المستندين في
اللغات الأربع عشرة، وHaiku 5.5 ما مقداره 0.57 دولار، وSonnet 5.5 ما مقداره 9.21 دولارات.

### ما ليست عليه هذه القياسات

- **ليست تصنيفاً شاملاً**: توفر منصة OpenRouter وحدها أكثر من أربعمائة
  نموذج، وقد تم قياس حوالي خمسة عشر منها فقط.
- **مُدد زمنية استرشادية**: من ثلاث إلى ست ترجمات بالتوازي بحسب
  الحملات، كما أن معدل نقل المزود يختلف خلال اليوم.
- **ملاحظات محددة بتاريخ معين**: النماذج تتغير تحت الاسم نفسه،
  ومستنداتكم ليست هي مستنداتنا.

لإعادة إجراء القياس على مستنداتكم، باستخدام نسخة مجمدة من الملف:

```bash
aipmt --file reference.md --target_dir out/ --source_lang fr --target_lang ja --use_gemini --force
aipmt --file veille.mdx   --target_dir out/ --source_lang fr --target_lang ja --use_gemini --news --force
python scripts/compare_structure.py reference.md out/reference-ja.md
# « structure identique », ou la liste des écarts — sortie 0 si identique, 1 sinon
```

## المساهمة

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

السطران كلاهما ضروريان: بدون `pip install -e .`، يرد `python -m aipmt`
بـ `No module named aipmt`.

أدوات الجودة، اختيارية لكن يُوصى بها:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```

تتم إعادة توليد الترجمات الـ 28 للمستودع (README وCHANGELOG، بأربع عشرة لغة)
باستخدام `./regen_translations.sh --force` — مع استخدام Codex و`gpt-6.1-sol` عبر
اشتراك ChatGPT افتراضياً، أربع ترجمات بالتوازي. يغير `REGEN_PROVIDER` و`REGEN_MODEL`
المسار: يبقى `antigravity` ضمن اشتراك، وهو اشتراك Google،
ويعمل دون استثناء؛ وتُرفض واجهة برمجة تطبيقات مدفوعة (`openai`، `gemini`،
`grok`، `openrouter`) بدون `REGEN_ALLOW_PAID_API=1`؛
ويحدد `REGEN_JOB_TIMEOUT` حداً أقصى لكل مهمة (600 ثانية، 1,800 ثانية على Codex وAntigravity).
تفاصيل الأدوات متوفرة في `CLAUDE.md`.
