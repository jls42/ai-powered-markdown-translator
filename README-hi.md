संरचना को सुरक्षित रखते हुए Markdown फ़ाइलों का एक भाषा से दूसरी भाषा में अनुवाद करता है: कोड ब्लॉक, इनलाइन कोड, URL, एंकर, तालिकाएँ और front matter। किसी मॉडल को कॉल करने के ग्यारह तरीके — पाँच API, चार बिना उपयोग-आधारित बिलिंग वाले सब्सक्रिप्शन, दो राऊटर — और प्रत्येक मॉडल वास्तव में क्या सुरक्षित रखता है, इसका एक प्रकाशित माप।

## संक्षेप में

- **ग्यारह प्रोवाइडर विकल्प**: OpenAI, Mistral, Claude, Gemini और Grok API; बिना उपयोग-आधारित बिलिंग वाले ChatGPT (Codex), Grok, Google (Antigravity) और Claude (Claude Code) सब्सक्रिप्शन; OpenCode (ओपन सोर्स, मुफ़्त या स्थानीय) और OpenRouter (400 से अधिक मॉडल) राऊटर।
- **खोए हुए टोकन के कारण कुछ भी गलत नहीं**: कोड ब्लॉक, इनलाइन कोड, URL, एंकर और उद्धरणों को कॉल से पहले टोकन से बदल दिया जाता है और वापसी पर सत्यापित किया जाता है। यदि कोई एक भी अनुपलब्ध है, तो फ़ाइल नहीं लिखी जाती है।
- **लंबे दस्तावेज़**: मॉडल के संदर्भ विंडो के अनुसार विभाजन (segmentation)।
- **`--news` मोड**: तकनीकी निगरानी लेखों के लिए, अंग्रेजी उद्धरण सुरक्षित और भाषा के अनुसार फ़्लैग प्रबंधित।
- **`--eco` मोड**: तेज़ और अधिक किफ़ायती मॉडल।
- **वैकल्पिक अनुवाद नोट**, ऊपर, नीचे या दोनों जगह।

## कॉन्फ़िगरेशन

कुंजियाँ (keys) तीन स्थानों से पढ़ी जाती हैं, उच्चतम प्राथमिकता से निम्नतम तक; प्रत्येक केवल वही भरती है जो पिछला खाली छोड़ देता है।

|     | कहाँ                                          | किसके लिए                             |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | पर्यावरण चर (Environment variables)          | CI, कंटेनर, अस्थायी अपवाद             |
| 2   | वर्तमान (या पैरेंट) डायरेक्टरी की `.env` | किसी प्रोजेक्ट के लिए विशिष्ट कुंजी   |
| 3   | `~/.config/aipmt/.env`                                 | एक बार इंस्टॉल किया गया, हर जगह मान्य |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

`GOOGLE_API_KEY` के स्थान पर `GEMINI_API_KEY` स्वीकार किया जाता है। उपयोगकर्ता फ़ाइल Windows पर `XDG_CONFIG_HOME` (केवल निरपेक्ष पथ) और `%APPDATA%` का अनुसरण करती है। बिना कुंजी के, कमांड तीनों स्थानों की सूची प्रदर्शित करता है।

**किसी प्रोजेक्ट का `.env` न तो कॉल्स को पुनर्निर्देशित कर सकता है और न ही निष्पादित प्रोग्राम का चयन कर सकता है।** यह केवल कुंजियाँ प्रदान करता है, कभी भी कोई गंतव्य या बाइनरी नहीं: `_BASE_URL`, `_API_BASE`, `_ENDPOINT` या `_BIN` (`CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`, `AGY_BIN`), `GROK_HOME` में कोई भी चर, प्रॉक्सी (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`), प्रमाणपत्र स्टोर (`SSL_CERT_FILE`, `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`) और `XDG_CONFIG_HOME` / `APPDATA` को एक चेतावनी के साथ अनदेखा कर दिया जाता है। एक क्लोन किए गए रिपॉजिटरी को आपकी कुंजी को हाईजैक करने या पहले अनुवाद पर आपको उसका अपना प्रोग्राम चलाने के लिए मजबूर करने में सक्षम नहीं होना चाहिए। यह फ़ाइल बिना इंटरपोलेशन के भी पढ़ी जाती है: `NOM=${OPENAI_API_KEY}` वहाँ कुंजी को कॉपी नहीं करता है। इन चरों को पर्यावरण में या `~/.config/aipmt/.env` में सेट करें।

वैकल्पिक चर: `XAI_BASE_URL` (डिफ़ॉल्ट `https://api.x.ai/v1`), `CLAUDE_TIMEOUT` (प्रति कॉल सेकंड, डिफ़ॉल्ट 900), `CODEX_BIN`, `CODEX_TIMEOUT` (डिफ़ॉल्ट 600), `GROK_BIN`, `GROK_HOME` (डिफ़ॉल्ट `~/.grok`), `GROK_TIMEOUT` (डिफ़ॉल्ट 900), `GROK_TRANSLATE_SANDBOX`, `AGY_BIN`, `AGY_TIMEOUT` (डिफ़ॉल्ट 900), `OPENCODE_BIN`, `OPENCODE_TIMEOUT` (डिफ़ॉल्ट 600), `OPENROUTER_BASE_URL` (`https://` आवश्यक), `OPENROUTER_TIMEOUT` (डिफ़ॉल्ट 900), `OPENROUTER_PREFLIGHT_TIMEOUT` (डिफ़ॉल्ट 30)। प्रत्येक का विवरण उसके प्रोवाइडर अनुभाग में दिया गया है।

## शुरुआत करना

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

स्पैनिश में अनुवादित `document.md`, `--target_dir` में `document-es.md` देता है; `--include_model` के साथ, `document-es-gpt-5.6-terra.md` देता है। एक्सटेंशन हमेशा `.md` बन जाता है — `article.mdx` से `article-en.md` बनता है — सिवाय `--keep_filename` के, जो मूल नाम को बनाए रखता है। पहले से मौजूद अनुवाद को `--force` के बिना छोड़ दिया जाता है।

एग्जिट कोड: यदि सब कुछ सफल रहा या छोड़ दिया गया तो `0`, यदि कोई फ़ाइल विफल रही तो `1` (मानक त्रुटि आउटपुट पर सूची), यदि कॉन्फ़िगरेशन में कोई समस्या है तो `2`। एक विफल फ़ाइल कभी नहीं लिखी जाती है, भले ही लेखन प्रक्रिया स्वयं विफल हो जाए: सामग्री को पास में लिखा जाता है और फिर नाम बदला जाता है। बस पुनः चलाना ही पर्याप्त है।

| ⚠️  | सभी चौदह भाषाओं का अनुवाद किया गया; जो भिन्न है वह **मार्कअप** है — एक बोल्ड शब्द, एक `code`, कोष्ठक खोने वाला एक लिंक। कोई टेक्स्ट, कोई URL, कोई कोड ब्लॉक, कोई अनुभाग गायब नहीं है |
| ❌  | कम से कम एक भाषा का अनुवाद नहीं किया जा सका — फ़ाइल अस्वीकृत है, लिखी नहीं गई — **या** लिखी गई फ़ाइल में से सामग्री गायब है                                          |

मुख्य निष्कर्ष:

- **अस्वीकृत अनुवाद कोई ख़राब अनुवाद नहीं होता।** जब वापसी पर कोई टोकन गायब
  होता है, तो फ़ाइल नहीं लिखी जाती है और भाषा को अस्वीकृत माना जाता है। लेख पर
  Grok के साथ यही होता है: पाँच गैर-लैटिन लिपियों में, पहले ही सेगमेंट से चार
  इनलाइन कोड और तीन URL गायब हो गए।
- **एक मॉडल केवल एक वाक्य के कारण पूरे दस्तावेज़ को अस्वीकार कर सकता है।** Opus 5.5
  इस README का बिना किसी अंतर के अनुवाद करता है, लेकिन किसी भी निगरानी लेख का
  नहीं: इसके सुरक्षा उपाय जीव विज्ञान की एक संक्षिप्त खबर पर प्रतिक्रिया को रोक
  देते हैं। फ़ाइल नहीं लिखी जाती है, और aipmt इसका कारण बताता है।
- **यह सुरक्षा जाल शीर्षकों, तालिकाओं, front matter या टेक्स्ट को कवर नहीं करता है।**
  एक मॉडल जो किसी अनुभाग को हटा देता है, वह ऐसी फ़ाइल लौटाता है जिसे टूल बिना किसी
  झिझक के लिख देता है — Mistral का यही मामला है। ये तत्व टोकन द्वारा प्रतिस्थापन
  योग्य नहीं हैं, और वर्तमान सुरक्षा जाँचें इन्हें नियंत्रित नहीं करती हैं;
  `scripts/compare_structure.py` खोए हुए अनुभाग का पता लगाता है, लेकिन घटना के बाद।
- **इस README पर Grok के लिए कोई रेटिंग नहीं है**: बारह भाषाओं के बाद इसका CLI
  सत्र समाप्त हो गया, जिनमें से ग्यारह बिना किसी अंतर के थीं। बीच में रुके हुए
  अभियान को रेट नहीं किया जाता है।
- **दस्तावेज़ का घनत्व भाषा से अधिक मायने रखता है।** Grok साधारण README पर सही
  काम करता है और लिंक से भरे लेख पर लड़खड़ा जाता है, जिसमें डच भाषा भी शामिल है।

तिथियाँ और दस्तावेज़: "यह README" कॉलम को 9 सितंबर 2026 को इस फ़ाइल के एक स्थिर संशोधन (785 पंक्तियाँ, 285 इनलाइन कोड, 89 तालिका पंक्तियाँ) पर मापा गया था, जिसमें बाद में बदलाव किए गए — Antigravity और Claude Code पंक्तियों को छोड़कर, जिन्हें 26 सितंबर को 1.14.0 के साथ प्रकाशित छोटे संशोधन (600 पंक्तियाँ, 257 इनलाइन कोड, 85 तालिका पंक्तियाँ) पर मापा गया था। "सघन तकनीकी निगरानी लेख" कॉलम 589 पंक्तियों के एक लेख पर 4 और 5 सितंबर के अभियान से आता है, Grok पंक्ति को छोड़कर, जिसे 9 सितंबर को उसी निगरानी के दूसरे संस्करण पर फिर से मापा गया था, और Antigravity तथा Claude Code पंक्तियाँ, जिन्हें 26 सितंबर को उसी लेख पर मापा गया था। पूरी तालिकाएँ, समय और प्रोटोकॉल [विस्तृत माप](#विस्तृत-माप) में उपलब्ध हैं।

## प्रोवाइडर्स

### API द्वारा: OpenAI, Mistral, Claude, Gemini, Grok

```bash
aipmt --source_dir content/fr --target_dir content/en --target_lang en             # OpenAI, défaut
aipmt --use_mistral --source_dir content/fr --target_dir content/es --target_lang es
aipmt --use_claude  --source_dir content/fr --target_dir content/de --target_lang de
aipmt --use_gemini  --source_dir content/fr --target_dir content/ja --target_lang ja
aipmt --use_grok    --source_dir content/fr --target_dir content/pt --target_lang pt
```

`--eco` प्रत्येक प्रदाता के किफायती स्तर पर स्विच करता है।

| प्रोवाइडर   | गुणवत्ता (डिफ़ॉल्ट)                                    | किफायती (`--eco`)          |
| ----------- | ----------------------------------------------------- | ------------------------- |
| OpenAI      | `gpt-5.6-terra`                                       | `gpt-5.6-luna`            |
| Claude      | `claude-sonnet-5`                                     | `claude-haiku-4-5`        |
| Mistral     | `mistral-large-latest`                                | `mistral-small-latest`    |
| Gemini      | `gemini-3.7-flash`                                    | `gemini-3.1-flash-lite`   |
| Codex       | `gpt-5.6-sol` (`--model` द्वारा `terra` और `luna` भी) | `gpt-5.6-luna`            |
| Grok API    | `grok-4.6`                                            | `grok-4.3`                |
| Grok CLI    | `grok-4.6`                                            | `grok-4.5`                |
| Antigravity | `gemini-3.8-flash-medium`                             | `gemini-3.7-flash-low`    |
| Claude Code | `sonnet`, प्रयास `low`                                | वही — `--eco` निष्प्रभावी |
| OpenCode    | `--model provider/modèle` अनिवार्य                 | वही — `--eco` निष्प्रभावी |

### ChatGPT सब्सक्रिप्शन पर: `--use_codex`

आधिकारिक Codex CLI को संचालित करता है: अनुवाद ChatGPT सब्सक्रिप्शन कोटा से काटा जाता है, बिना किसी API कुंजी या उपयोग-आधारित बिलिंग के।

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- बाइनरी को `CODEX_BIN` में, फिर `PATH` में, फिर पैकेज `openai-codex-cli-bin` में खोजा जाता है। `~/.codex/auth.json` को कभी पढ़ा नहीं जाता है।
- `OPENAI_API_KEY` और `CODEX_API_KEY` को सबप्रोसेस के परिवेश से हटा दिया जाता है: मौजूद कोई कुंजी कभी भी API पर स्विच नहीं कराती है।
- प्रत्येक सेगमेंट की लागत 5 घंटे की विंडो के कम से कम एक "मैसेज" के बराबर होती है — यदि इसका सत्यापन विफल हो जाता है और इसे पुनः प्रयास किया जाता है, तो दो। OpenAI एक Plus प्लान पर, अनुमान के रूप में, `gpt-5.6-luna` (`--eco`) के लिए 250–2,000 मैसेज/5 घंटे और `gpt-5.6-sol` के लिए 10–100 की घोषणा करता है।
- `--model gpt-5.6-terra` और `--model gpt-5.6-luna` भी सब्सक्रिप्शन से होकर गुजरते हैं। ऐसा मॉडल जिसके लिए खाता योग्य नहीं है, वह 400 "model is not supported when using Codex with a ChatGPT account" लौटाता है।
- API की तुलना में धीमा, और दस्तावेज़ के साथ यह अंतर बढ़ता जाता है: इस README पर, `gpt-5.6-sol` के साथ प्रति भाषा 6 मिनट 46 सेकंड का मध्यमान, जबकि `gemini-3.7-flash` के लिए 36 सेकंड।
- CI में अस्वीकृत (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर): सब्सक्रिप्शन एक व्यक्तिगत सत्र फ़ाइल द्वारा प्रमाणित होता है, जिसका साझा रनर पर कोई काम नहीं है।
- चर: `CODEX_BIN`, `CODEX_TIMEOUT` (प्रति सेगमेंट सेकंड, डिफ़ॉल्ट 600)।

### Grok सब्सक्रिप्शन पर: `--use_grok_cli`

SuperGrok या X Premium+ सब्सक्रिप्शन पर, आधिकारिक Grok Build CLI के साथ समान सिद्धांत।

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --eco --file README.md --target_dir . --target_lang pl
```

- **Codex की तुलना में कमजोर नियंत्रण (confinement)।** Grok का OS सैंडबॉक्स कई आधुनिक Linux वर्कस्टेशनों (AppArmor, कंटेनर रनटाइम सॉकेट्स) पर लागू नहीं होता है, और जो प्रोफ़ाइल लागू नहीं हो सकती वह बिना किसी सूचना के अनियंत्रित रूप से शुरू हो जाती है। इसलिए स्क्रिप्ट डिफ़ॉल्ट रूप से किसी प्रोफ़ाइल का अनुरोध नहीं करती है, इसकी घोषणा करती है, और CLI के `--deny` नियमों पर निर्भर करती है, जिसमें कैच-ऑल `*` शामिल है — एकमात्र ऐसी परत जो बिना बताए सुरक्षा हटाने के बजाय शुरू होने से इनकार कर देती है। `GROK_TRANSLATE_SANDBOX=read-only` के लिए OS सैंडबॉक्स की आवश्यकता होती है, और यदि मशीन इसे पूरा नहीं कर सकती है तो शुरुआत विफल हो जाती है।
- कोटा साप्ताहिक है, जो Chat, Imagine और Voice के साथ साझा किया जाता है, और कोई भी कमांड इसे पढ़ने की अनुमति नहीं देती है: एक बैच बिना किसी संकेत के बातचीत संबंधी उपयोग को प्रभावित कर सकता है।
- चर: `GROK_BIN`, `GROK_HOME` (CLI डायरेक्टरी, डिफ़ॉल्ट `~/.grok`), `GROK_TIMEOUT` (डिफ़ॉल्ट 900), `GROK_TRANSLATE_SANDBOX`।

### Google सब्सक्रिप्शन पर: `--use_antigravity`

Antigravity के आधिकारिक CLI, `agy` के साथ समान सिद्धांत: Google AI Pro या Ultra के लिए भुगतान करने वालों के लिए, अनुवाद टोकन-आधारित बिलिंग के बजाय सब्सक्रिप्शन कोटा से काटा जाता है। इस कोटा तक पहुँचने का यह एकमात्र मार्ग है: Gemini CLI 18 जून 2026 से इन खातों की सेवा नहीं देता है ([घोषणा](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)), और Antigravity SDK केवल API कुंजी या Google Cloud प्रोजेक्ट स्वीकार करता है।

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **कोई भी सशुल्क मार्ग खुला नहीं रहता।** agy आपके परिवेश से केवल चरों की एक सीमित सूची प्राप्त करता है — `PATH`, भाषा और समय क्षेत्र, टर्मिनल, पहचान, प्रॉक्सी और प्रमाणपत्र, सत्र बस — और कोई कुंजी नहीं: इसके कई चर बिना कुछ प्रदर्शित किए कॉल को स्विच कर देते हैं (परीक्षण किया गया: एक दस्तावेज़ को तीसरे पक्ष के गेटवे पर भेजता है, दूसरा बिल किए गए Google Cloud प्रोजेक्ट पर), और एक ब्लैकलिस्ट में हर बार समीक्षा करने पर कुछ न कुछ छूट जाता था। किसी भी सेगमेंट से पहले, `agy -p /config`, जिसमें कोई कोटा खर्च नहीं होता, को सशुल्क AI क्रेडिट निष्क्रिय दिखाना चाहिए, जिसमें कोई API कुंजी या Google Cloud प्रोजेक्ट न हो — किसी सेटिंग की अनुपस्थिति का अर्थ अस्वीकृति है —, अन्यथा कुछ भी अनुवादित नहीं किया जाता है; प्रत्येक कॉल के लॉग को फिर सब्सक्रिप्शन (`authMethod=consumer`) प्रमाणित करना चाहिए, अन्यथा प्रतिक्रिया अस्वीकार कर दी जाती है।
- **कन्फ़ाइनमेंट।** प्रत्येक कॉल एक निजी और डिस्पोजेबल व्यक्तिगत डायरेक्टरी में चलती है, जिसमें बिना टूल वाला एक ट्रांसलेशन एजेंट होता है: आपकी सेटिंग्स, नियम, प्लगइन्स, MCP सर्वर और agy हुक इसमें प्रवेश नहीं करते हैं, आपके इतिहास में कुछ भी नहीं जुड़ता है, और लॉगिन कीचेन में रहता है, जिसे aipmt कभी नहीं पढ़ता है। यदि एजेंट नहीं मिलता है, तो agy चुपचाप अपने कोडिंग एजेंट और उसके टूल पर वापस लौट जाता है: लॉग की एक पूरी पंक्ति द्वारा सही एजेंट की पुष्टि की जानी चाहिए — इस संदेश को उद्धृत करने वाला दस्तावेज़ इसे प्रतिस्थापित नहीं करता है —, अन्यथा अस्वीकृति होती है।
- **प्लेटफ़ॉर्म**: Linux, ऐसे सत्र में जिसमें कीचेन हो (D-Bus सत्र बस, Secret Service); macOS स्वीकृत है, लेकिन वहाँ परीक्षण नहीं किया गया है। Windows पर अस्वीकृत, जहाँ agy उन चरों को नहीं पढ़ता है जो प्रत्येक कॉल को अलग करते हैं, और सत्र बस के बिना Linux पर — SSH सत्र, कंटेनर, सर्वर: agy वहाँ अपने टोकन को `~/.gemini` की एक फ़ाइल में संग्रहीत करता है, जिसे आइसोलेशन छिपा देता है। कनेक्शन कोड के लिए एक मिनट की प्रतीक्षा के बजाय, अस्वीकृति किसी भी लॉन्च से पहले उसके कारण के साथ आ जाती है।
- **मॉडल**: `agy models` वाले। Gemini मॉडल अपने नाम में प्रयास दर्शाते हैं (`gemini-3.8-flash-medium`…): बिना प्रत्यय वाला नाम कॉल से पहले ही अस्वीकार कर दिया जाता है, और `--reasoning_effort` निष्प्रभावी रहता है। डिफ़ॉल्ट रूप से `gemini-3.8-flash-medium`, और `--eco` में `gemini-3.7-flash-low`; इन्हें निर्धारित करने वाले अभियानों का वर्णन [विस्तृत माप](#विस्तृत-माप) में किया गया है। Claude और GPT-OSS का अपना कोटा है, जो काफी छोटा है: Flash में 0.05% की तुलना में प्रति मापी गई कॉल पर 5 घंटे की विंडो का लगभग 1%।
- **कोटा**: प्रति समूह, एक 5 घंटे की और एक साप्ताहिक विंडो, टोकन लागत के अनुपात में। लेखक के खाते पर मापा गया: `gemini-3.8-flash-medium` में प्रति दस लाख स्रोत वर्णों पर 5 घंटे की विंडो के लगभग 16 अंक, `gemini-3.7-flash-medium` में 14 और कम प्रयास पर 7 से 8 — 40,000 वर्णों वाले README की लागत इसलिए आधे अंक से थोड़ी अधिक होती है। साप्ताहिक सीमा स्तर पर निर्भर करती है। पुनः प्रयास उस पर आधारित होता है जिसे agy पुनः प्रयास योग्य घोषित करता है; अन्यथा, समाप्त हो चुकी विंडो पर कभी पुनः प्रयास नहीं किया जाता है: यह `/usage` द्वारा प्रदर्शित रीसेट होने तक प्रत्येक फ़ाइल को विफल कर देता है।
- **API से धीमा**: विस्तृत माप वाले लेख पर, API के माध्यम से Gemini 3.7 Flash के लिए 1 मिनट 18 सेकंड के मुकाबले, `gemini-3.8-flash-medium` में प्रति भाषा 3 मिनट 59 सेकंड का मध्यमान और `gemini-3.7-flash-medium` में 3 मिनट 14 सेकंड।
- **रुकावट**: Ctrl-C, या टर्मिनल बंद होने पर, आपके कोटे पर अपनी बारी समाप्त करने देने के बजाय कमांड के साथ agy को रोक दिया जाता है; यही बात Codex, Grok CLI और OpenCode पर भी लागू होती है। `nohup` के अंतर्गत, अनुवाद जारी रहता है।
- CI में अस्वीकृत (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर): लॉगिन व्यक्तिगत कीचेन में रहता है। रनर पर, `GOOGLE_API_KEY` के साथ `--use_gemini`।
- चर: `AGY_BIN` (अन्यथा `PATH`, फिर `~/.local/bin/agy`), `AGY_TIMEOUT` (स्टार्टअप सहित प्रति सेगमेंट सेकंड, डिफ़ॉल्ट 900)।

**केवल सार्वजनिक दस्तावेज़।** उन्हीं शर्तों की धारा 5 के अनुसार, बातचीत — प्रॉम्प्ट, प्रतिक्रियाएं, मेटाडेटा — Google के उत्पादों और मशीन लर्निंग को बेहतर बनाने के लिए उपयोग की जा सकती हैं और मनुष्यों द्वारा उनकी समीक्षा की जा सकती है, जिसमें सशुल्क सब्सक्रिप्शन भी शामिल हैं। ऑप्ट-आउट `enableTelemetry` सेटिंग के माध्यम से होता है, जिसके प्रभाव का दस्तावेज़ीकरण नहीं है, जिसे aipmt सेट नहीं करता है; आपकी agy सेटिंग्स इसके आइसोलेशन में स्थानांतरित नहीं होती हैं। इसके माध्यम से कुछ भी गोपनीय न भेजें।

### Claude सदस्यता पर: `--use_claude_code`

यही सिद्धांत `claude` के साथ भी लागू होता है, जो `-p` मोड में Claude Code का आधिकारिक CLI है: जो उपयोगकर्ता Claude Pro या Max का भुगतान करते हैं, उनके लिए अनुवाद टोकन के आधार पर बिल किए जाने के बजाय सदस्यता कोटा से घटाया जाता है। इसे `--use_claude` के साथ भ्रमित न करें, जो Anthropic का API है और उपयोग के आधार पर बिल किया जाता है।

```bash
claude                                   # une fois : /login avec le compte de l'abonnement
aipmt --use_claude_code --file README.md --target_dir . --target_lang en
```

- **कोई भी सशुल्क मार्ग खुला नहीं रहता है, और प्रत्येक कॉल इसे सिद्ध करती है।** Claude
  Code आपके वातावरण से केवल चरों की एक सीमित सूची प्राप्त करता है — न
  कोई API कुंजी, न टोकन, न कोई क्लाउड प्रदाता, और न ही उस Claude Code सत्र
  का कोई मार्कर जहाँ से aipmt लॉन्च किया गया हो। पहले खंड से पहले, `claude auth status` को
  बिना किसी Console कुंजी के सदस्यता कनेक्शन दिखाना चाहिए, और `/usage`, जिसकी
  कोई कोटा लागत नहीं होती, को इसे प्रमाणित करना चाहिए; प्रत्येक कॉल अपने
  इनिशियलाइज़ेशन इवेंट में इसे बारी-बारी से प्रमाणित करती है, अन्यथा प्रतिक्रिया अस्वीकार कर दी जाती है।
- **"अतिरिक्त उपयोग" (extra usage) को अक्षम करें** (claude.ai, सेटिंग्स → उपयोग)
  ताकि शून्य यूरो का नियम बना रहे: सक्षम होने पर, यह समाप्त हो चुकी विंडो का कार्यभार संभाल लेता है और
  बिना कोई त्रुटि दिखाए बिलिंग शुरू कर देता है। aipmt अनुवाद को तुरंत रोक देता है जैसे ही किसी
  कॉल की कोटा रिपोर्ट इसका संकेत देती है, लेकिन वह कॉल पहले ही गिनी जा चुकी होती है।
- **आपके Claude Code सत्रों के साथ साझा कोटा।** प्रत्येक कॉल 5-घंटे और
  साप्ताहिक विंडो के उपयोग की रिपोर्ट करती है; 80%
  (`AIPMT_CLAUDE_MAX_UTILIZATION`) से अधिक होने पर, आपके कार्य के लिए आवश्यक कोटा
  समाप्त न हो, इसलिए कोई अतिरिक्त खंड लॉन्च नहीं किया जाता है।
- **कन्फ़ाइनमेंट।** प्रत्येक कॉल बिना किसी टूल के, एक निजी और प्रयोज्य (disposable) डायरेक्टरी में,
  बिना किसी कस्टमाइज़ेशन वाले मोड में चलती है: न तो आपके `CLAUDE.md`, न आपके प्लगइन्स,
  हुक्स, MCP सर्वर या सेटिंग्स लोड होते हैं, और सत्र से कुछ भी सहेजा नहीं जाता है। अटैचमेंट
  काट दिए जाते हैं: आपके दस्तावेज़ में `@chemin` केवल टेक्स्ट बना रहता है
  और कोई फ़ाइल नहीं खोलता है (परीक्षित)।
- **मॉडल**: डिफ़ॉल्ट रूप से `sonnet`, `low` प्रयास पर, और `--eco` में भी:
  `--eco` इस पथ पर कुछ नहीं बदलता। उन्हीं दस्तावेज़ों पर मापे जाने पर, `haiku`
  दोगुना धीमा है — यह बिना रोके विचार करता है — लगभग
  नगण्य कम लागत के लिए, और `opus` जीव विज्ञान की सामग्री को अस्वीकार कर देता है (अगला
  बिंदु)। दोनों `--model` के माध्यम से सुलभ रहते हैं; ये उपनाम अपने
  परिवार के नवीनतम मॉडल का अनुसरण करते हैं। `fable` और `[1m]` वेरिएंट अस्वीकार कर दिए जाते हैं,
  क्योंकि वे सशुल्क क्रेडिट में चले जाते हैं। `--reasoning_effort` प्रयास को समायोजित करता है,
  जिससे अनुवाद को कोई लाभ नहीं होता: मापा गया तर्क शून्य या लगभग नगण्य है।
- **Opus जीव विज्ञान की कुछ सामग्रियों को अस्वीकार कर देता है।** इसके गार्डरेल्स
  Sonnet की तुलना में अधिक सख्त हैं, और Anthropic का त्रुटि संदेश चेतावनी देता है कि वे
  « can sometimes flag biology-research-adjacent work »। परीक्षित: 279 उत्पन्न
  अणुओं पर एक संक्षिप्त मॉनिटरिंग नोट के कारण चौदह भाषाओं में लेख
  अस्वीकार कर दिया गया। कुछ भी नहीं लिखा गया: aipmt कटी हुई प्रतिक्रिया को अस्वीकार करता है,
  गार्डरेल्स का उल्लेख करता है और `--model sonnet` की सलाह देता है।
- CI में (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर) और Windows के तहत (परीक्षित नहीं) अस्वीकृत।
- चर: `AIPMT_CLAUDE_BIN` (अन्यथा `PATH`, फिर `~/.local/bin/claude`),
  `AIPMT_CLAUDE_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 900),
  `AIPMT_CLAUDE_MAX_UTILIZATION` (दिफ़ॉल्ट 0.8), `CLAUDE_CONFIG_DIR` (Claude
  Code का खाता, कभी भी किसी प्रोजेक्ट के `.env` से नहीं लिया जाता); कार्यशील डायरेक्टरी
  `XDG_CACHE_HOME/aipmt/claude-code` के अंतर्गत (दिफ़ॉल्ट `~/.cache`)।

Claude Code पर भी लागू होता है जब गोपनीयता सेटिंग इसकी अनुमति देती है
([डेटा पृष्ठ](https://code.claude.com/docs/en/data-usage))। aipmt कोई
स्थानीय प्रतिलेखन नहीं रखता है (`--no-session-persistence`)। इसके माध्यम से
कुछ भी गोपनीय न भेजें।

### अपनी पसंद के प्रदाता की ओर: `--use_opencode`

[OpenCode](https://opencode.ai) एक ओपन सोर्स (MIT) कोड एजेंट है जो
अपने भीतर कॉन्फ़िगर किए गए प्रदाताओं पर रूट करता है: API कुंजी, सदस्यता,
OpenCode Zen गेटवे (निःशुल्क मॉडल, बिना खाते के) या स्थानीय मॉडल। यहाँ दो
मार्गों का शुरू से अंत तक परीक्षण किया गया: Zen और Ollama।

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` अनिवार्य है: इसके बिना, OpenCode एक ऐसे मुफ़्त मॉडल पर वापस चला जाएगा
जिसके संवादों का उपयोग प्रशिक्षण के लिए किया जा सकता है, और यह निर्णय आपकी
सहमति के बिना नहीं लिया जाता।

प्रत्येक कॉल पर कन्फ़ाइनमेंट:

- एक इनलाइन कॉन्फ़िगरेशन, जो आपके कॉन्फ़िगरेशन पर प्राथमिकता रखती है, एक `aipmt` एजेंट
  को परिभाषित करती है जिसके सभी उपकरण अस्वीकृत होते हैं (`permission: { "*": "deny" }`), सत्र
  साझाकरण अक्षम होता है, `--pure`, कभी भी `--auto` नहीं;
- प्रयोज्य और खाली कार्यशील डायरेक्टरी, `OPENCODE_DISABLE_PROJECT_CONFIG` और
  `OPENCODE_DISABLE_CLAUDE_CODE` मौजूद — इनके बिना, OpenCode प्रॉम्प्ट में
  वर्तमान डायरेक्टरी का `AGENTS.md` और `~/.claude/CLAUDE.md` इंजेक्ट कर देता है। वैश्विक
  `~/.config/opencode/AGENTS.md` अभी भी इंजेक्ट रहता है, OpenCode इसे हटाने की
  अनुमति नहीं देता है;
- आउटपुट अनुबंध: रिटर्न कोड 0, कोई `error` इवेंट नहीं, कोई टूल
  कॉल नहीं, अंतिम चरण `stop` में, गैर-रिक्त टेक्स्ट, और `aipmt` एजेंट
  वास्तव में लोड किया गया — एक अज्ञात `--agent` OpenCode को विफल नहीं करता, वह
  चुपचाप कोडिंग एजेंट पर वापस आ जाता है;
- `aipmt` की कोई भी कुंजी पास नहीं की जाती है, सिवाय `OPENCODE_API_KEY` के, जो
  स्वयं OpenCode की कुंजी है। प्रदाताओं को OpenCode में कॉन्फ़िगर किया जाता है,
  `aipmt` के `.env` में नहीं।

ध्यान देने योग्य बातें:

- Zen के मुफ़्त मॉडल परिवर्तनशील हैं, जिनकी सीमाएं अप्रलेखित हैं, और
  उनके संवादों का उपयोग प्रशिक्षण के लिए किया जा सकता है: सार्वजनिक दस्तावेज़ीकरण
  के लिए उपयुक्त हैं, निजी सामग्री के लिए नहीं।
- एक स्थानीय मॉडल को कम से कम 16k टोकन का संदर्भ प्रदान करना चाहिए, क्योंकि खंड
  16,000 वर्णों तक के होते हैं। Ollama अक्सर 4,096 को कॉन्फ़िगर करता है: `PARAMETER num_ctx 32768`
  के साथ `Modelfile` का उपयोग करें।
- `--eco` निष्प्रभावी है; `--reasoning_effort` को OpenCode के
  `--variant` के रूप में ज्यों का त्यों पास किया जाता है।
- OpenCode प्रत्येक सत्र को `~/.local/share/opencode/` में लॉग करता है।
- चर: `OPENCODE_BIN` (अन्यथा `PATH`, फिर `~/.opencode/bin/opencode`),
  `OPENCODE_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 600)। `OPENCODE_CONFIG`
  OpenCode को ज्यों का त्यों पास होता है।

`~/.config/opencode/opencode.json` में Ollama के माध्यम से एक स्थानीय मॉडल का उदाहरण:

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

`reasoningEffort: "none"` उस चिंतन को बंद कर देता है जिसे Ollama इन मॉडलों पर
डिफ़ॉल्ट रूप से सक्रिय करता है, और जिसे एक Modelfile अक्षम नहीं कर सकती। छह शब्दों के एक
वाक्य पर परीक्षण किया गया: इस विकल्प के बिना 919 चिंतन टोकन और 68 सेकंड, इसके साथ केवल 9 टोकन।

### 400 से अधिक मॉडलों की ओर: `--use_openrouter`

OpenRouter एक राउटर है जो तीसरे पक्ष द्वारा होस्ट किए गए मॉडलों के सामने एकल क्रेडिट पर
उपयोग के आधार पर बिल किया जाता है — जिसमें चीनी ओपन मॉडल भी शामिल हैं
जिन्हें कोई अन्य प्रदाता यहाँ प्रदर्शित नहीं करता है।

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` अनिवार्य है। किसी भी बिलिंग से पहले निष्पादित एक प्रीफ़्लाइट, रूटिंग की
दो विशेषताओं को प्रबंधित करता है:

- **एक ही मॉडल को अलग-अलग सीमाओं वाले दर्जनों होस्टों द्वारा परोसा जाता है** — `z-ai/glm-5.3-flash`
  पर, 23 होस्ट हैं जिनमें से एक 2,048 आउटपुट टोकन तक सीमित है। प्रीफ़्लाइट `/api/v1/models/{modèle}/endpoints`
  को पढ़ता है, 8,000 आउटपुट टोकन से कम या ख़राब स्थिति वाले होस्टों को हटा देता है,
  और दूसरों को `allow_fallbacks: false` के साथ पिन करता है।
- **तर्क के लिए आउटपुट दर पर बिल किया जाता है** — `z-ai/glm-5.2` से « OK » प्रतिक्रिया पर
  2 के मुकाबले 107 टोकन। इसे डिफ़ॉल्ट रूप से बंद कर दिया जाता है; जो मॉडल इसे अनिवार्य करते हैं
  उन्हें वह न्यूनतम प्रयास दिया जाता है जिसे वे स्वीकार करते हैं, क्योंकि कैटलॉग का डिफ़ॉल्ट मान
  अनुवाद समाप्त होने से पहले आउटपुट को समाप्त कर सकता है।
  `--reasoning_effort` प्राथमिकता पर रहता है।

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- संदर्भ विंडो कैटलॉग से आती है। किसी भी कॉल से पहले 16,400 टोकन से कम वाले मॉडल को
  अस्वीकार कर दिया जाता है: प्रॉम्प्ट और सेगमेंट के लिए 8,400, कम से कम 8,000
  आउटपुट के लिए।
- कैटलॉग से अनुपस्थित स्लग, अनुपलब्ध कैटलॉग या सीमा को बनाए रखने वाले
  किसी होस्ट का अभाव कमांड को रोक देता है।
- खाली आउटपुट के साथ `finish_reason=length` तर्क द्वारा खपत किया गया बजट है,
  न कि ट्रंकेशन: संदेश इसमें अंतर करता है।
- `--eco` निष्प्रभावी है।
- चर: `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>),
  `OPENROUTER_BASE_URL` (दिफ़ॉल्ट `https://openrouter.ai/api/v1`, `https://`
  आवश्यक), `OPENROUTER_TIMEOUT` (दिफ़ॉल्ट 900), `OPENROUTER_PREFLIGHT_TIMEOUT`
  (दिफ़ॉल्ट 30)।

### अनुवाद संबंधी टिप्पणी

`--add_translation_note` एक टिप्पणी जोड़ता है, `bottom` (दिफ़ॉल्ट), `top` (फ़्रंट
मैटर के बाद) या `both` (`--note_position`) में, `legacy` (बोल्ड पैराग्राफ, डिफ़ॉल्ट) या
`marker` (`--note_format`) प्रारूप में। प्रारूप `marker` एक अदृश्य Markdown
संदर्भ परिभाषा है,
`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`,
जिसके बाद एक बोल्ड उद्धरण होता है: GitHub पर पठनीय, एक remark प्लगइन द्वारा बिल्ड के समय उपयोग योग्य।

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## विस्तृत माप

सभी माप वास्तव में `aipmt` के साथ निष्पादित अनुवाद हैं, चौदह
भाषाओं में: en, es, de, it, pt, nl, pl, sv, ro, ja, ko, zh, ar, hi।
**लिखित** उन फ़ाइलों की गणना करता है जिन्हें गार्ड्स ने पास होने दिया; **बिना
अंतर** वे हैं जहाँ `scripts/compare_structure.py` कुछ भी विसंगति नहीं पाता है — अनुभागों, उपशीर्षकों, लिंकों,
विशिष्ट URL, कोड ब्लॉक, इनलाइन कोड, तालिका पंक्तियों, ब्लॉककोट और बोल्ड शब्दों की समान संख्या।

"बिना अंतर" का अर्थ है "कुछ भी पता नहीं चला", न कि "समान": तुलनित्र
उनकी सामग्री को पढ़े बिना तत्वों की गणना करता है। यह न तो किसी हटाए गए
स्तर 4 के शीर्षक की रिपोर्ट करता है, न ही बदले गए इनलाइन कोड टेक्स्ट की, न ही किसी बदले हुए
फ़्लैग की, और न ही एक अतिरिक्त कोष्ठक के साथ दिए गए किसी आंतरिक लिंक की,
`[texte]((#ancre))`, जो अब कहीं नहीं जाता — और यह भाषा का मूल्यांकन
नहीं करता है।

अंग्रेज़ी उद्धरण चौदह भाषाओं में बरकरार हैं और, अंग्रेज़ी में, मॉडल ने
बिना कोई नया फ़्लैग बनाए, फ़्रेंच अनुवाद की पंक्तियों को स्वयं हटा दिया।
`opus` ने किसी भी भाषा में नहीं लिखा: प्रत्येक में, इसके गार्डरेल्स ने बाइंडिंग

प्रतिक्रिया रोक दी। अकेले भेजे जाने पर, इस संक्षिप्त नोट को « bio » श्रेणी के
अंतर्गत अस्वीकार कर दिया जाता है; `sonnet` ने इसका हर जगह अनुवाद किया। `haiku` चौदह

### ये माप क्या नहीं हैं

- **कोई संपूर्ण रैंकिंग नहीं**: केवल OpenRouter ही चार सौ से अधिक मॉडल पेश करता है, जिनमें से लगभग पंद्रह को मापा गया था।
- **संकेतात्मक अवधियाँ**: अभियानों के आधार पर समानांतर में तीन से छह अनुवाद, और प्रदाता का थ्रूपुट दिन भर में बदलता रहता है।
- **दिनांकित अवलोकन**: मॉडल उसी नाम के तहत बदलते रहते हैं, और आपके दस्तावेज़ हमारे दस्तावेज़ों जैसे नहीं हैं।

फ़ाइल की एक स्थिर प्रति पर, अपने दस्तावेज़ों के लिए इस माप को दोहराने हेतु:

```bash
aipmt --file reference.md --target_dir out/ --source_lang fr --target_lang ja --use_gemini --force
aipmt --file veille.mdx   --target_dir out/ --source_lang fr --target_lang ja --use_gemini --news --force
python scripts/compare_structure.py reference.md out/reference-ja.md
# « structure identique », ou la liste des écarts — sortie 0 si identique, 1 sinon
```

## योगदान देना

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

दोनों पंक्तियाँ आवश्यक हैं: `pip install -e .` के बिना, `python -m aipmt` उत्तर देता है `No module named aipmt`।

गुणवत्ता टूलिंग, वैकल्पिक लेकिन अनुशंसित:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```

रिपॉजिटरी के 28 अनुवाद (README और CHANGELOG, चौदह भाषाएँ) `./regen_translations.sh --force` के साथ पुनरुत्पादित होते हैं — डिफ़ॉल्ट रूप से ChatGPT सदस्यता पर Codex और `gpt-5.6-sol`, समानांतर में चार। `REGEN_PROVIDER` और `REGEN_MODEL` पथ बदलते हैं: `antigravity` एक सदस्यता (Google की) पर रहता है और बिना किसी छूट के पास हो जाता है; एक बिल योग्य API (`openai`, `gemini`, `grok`, `openrouter`) को `REGEN_ALLOW_PAID_API=1` के बिना अस्वीकार कर दिया जाता है; `REGEN_JOB_TIMEOUT` प्रत्येक जॉब को सीमित करता है (Codex और Antigravity पर 600 सेकंड, 1,800 सेकंड)। टूलिंग का विवरण `CLAUDE.md` में है।
