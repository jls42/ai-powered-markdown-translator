संरचना को सुरक्षित रखते हुए Markdown फ़ाइलों का एक भाषा से दूसरी भाषा में अनुवाद करता है: कोड ब्लॉक, इनलाइन कोड, URL, एंकर, तालिकाएँ और front matter। किसी मॉडल को कॉल करने के ग्यारह तरीके — पाँच API, बिना उपयोग-आधारित बिलिंग वाले चार सब्सक्रिप्शन, दो राउटर — और प्रत्येक मॉडल वास्तव में क्या सुरक्षित रखता है, इसका एक प्रकाशित माप।

## संक्षेप में

- **ग्यारह प्रोवाइडर विकल्प**: OpenAI, Mistral, Claude, Gemini और Grok API; बिना उपयोग-आधारित बिलिंग वाले ChatGPT (Codex), Grok, Google (Antigravity) और Claude (Claude Code) सब्सक्रिप्शन; OpenCode (ओपन सोर्स, मुफ़्त या स्थानीय) और OpenRouter (400 से अधिक मॉडल) राउटर।
- **खोए हुए टोकन के कारण कोई ग़लती नहीं**: कोड ब्लॉक, इनलाइन कोड, URL, एंकर और उद्धरणों को कॉल से पहले टोकन से बदल दिया जाता है और वापसी पर सत्यापित किया जाता है। यदि कोई एक भी गायब हो, तो फ़ाइल नहीं लिखी जाती है।
- **लंबे दस्तावेज़**: मॉडल की संदर्भ विंडो के अनुसार विभाजन।
- **`--news` मोड**: क्यूरेशन और निगरानी से जुड़े लेखों के लिए सुरक्षित अंग्रेज़ी उद्धरण और भाषा-वार ध्वज प्रबंधन।
- **`--eco` मोड**: तेज़ और अधिक किफ़ायती मॉडल।
- शीर्ष पर, नीचे या दोनों जगह वैकल्पिक **अनुवाद टिप्पणी**।

## इंस्टॉलेशन

```bash
pip install ai-powered-markdown-translator     # ou : pipx install ai-powered-markdown-translator

```

Python 3.10 या नया। रिपॉजिटरी से इंस्टॉल करने के लिए, [योगदान करें](#योगदान-देना) देखें।

## कॉन्फ़िगरेशन

कुंजियाँ तीन स्थानों से पढ़ी जाती हैं, सर्वोच्च प्राथमिकता से न्यूनतम तक; प्रत्येक स्थान केवल वही भरता है जिसे पिछला स्थान खाली छोड़ देता है।

|     | कहाँ                                          | किसके लिए                             |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | एनवायरनमेंट वेरिएबल्स                         | CI, कंटेनर, अस्थायी छूट                |
| 2   | वर्तमान (या पैरेंट) डायरेक्टरी की `.env` | किसी प्रोजेक्ट-विशिष्ट कुंजी के लिए  |
| 3   | `~/.config/aipmt/.env`                        | एक बार इंस्टॉल किया गया, हर जगह मान्य |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

`GOOGLE_API_KEY` के स्थान पर `GEMINI_API_KEY` स्वीकार किया जाता है। उपयोगकर्ता फ़ाइल `XDG_CONFIG_HOME` (केवल पूर्ण पथ) और Windows पर `%APPDATA%` का पालन करती है। बिना किसी कुंजी के, कमांड तीनों स्थानों की सूची प्रदर्शित करता है।

**किसी प्रोजेक्ट की `.env` न तो कॉल को पुनर्निर्देशित कर सकती है और न ही निष्पादित होने वाले प्रोग्राम का चयन कर सकती है।** यह केवल कुंजियाँ प्रदान करती है, कभी कोई गंतव्य या बाइनरी नहीं: `_BASE_URL`, `_API_BASE`, `_ENDPOINT` या `_BIN` (`CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`, `AGY_BIN`), `GROK_HOME` वाले किसी भी वेरिएबल, प्रॉक्सी (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`), प्रमाणपत्र स्टोर (`SSL_CERT_FILE`, `SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`) और `XDG_CONFIG_HOME` / `APPDATA` को चेतावनी के साथ अनदेखा कर दिया जाता है। एक क्लोन किए गए रिपॉजिटरी को आपकी कुंजी को हाईजैक करने या पहले अनुवाद पर आपको अपना प्रोग्राम चलाने के लिए मजबूर करने में सक्षम नहीं होना चाहिए। यह फ़ाइल बिना इंटरपोलेशन के भी पढ़ी जाती है: `NOM=${OPENAI_API_KEY}` इसमें कुंजी की नकल नहीं करता है। इन वेरिएबल्स को एनवायरनमेंट में या `~/.config/aipmt/.env` में रखें।

वैकल्पिक वेरिएबल्स: `XAI_BASE_URL` (डिफ़ॉल्ट `https://api.x.ai/v1`), `CLAUDE_TIMEOUT` (प्रति कॉल सेकंड, डिफ़ॉल्ट 900), `CODEX_BIN`, `CODEX_TIMEOUT` (डिफ़ॉल्ट 600), `GROK_BIN`, `GROK_HOME` (डिफ़ॉल्ट `~/.grok`), `GROK_TIMEOUT` (डिफ़ॉल्ट 900), `GROK_TRANSLATE_SANDBOX`, `AGY_BIN`, `AGY_TIMEOUT` (डिफ़ॉल्ट 900), `OPENCODE_BIN`, `OPENCODE_TIMEOUT` (डिफ़ॉल्ट 600), `OPENROUTER_BASE_URL` (`https://` आवश्यक), `OPENROUTER_TIMEOUT` (डिफ़ॉल्ट 900), `OPENROUTER_PREFLIGHT_TIMEOUT` (डिफ़ॉल्ट 30)। प्रत्येक का विवरण उसके प्रोवाइडर अनुभाग में दिया गया है।

## शुरुआत करना

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

स्पैनिश में अनुवादित `document.md` `--target_dir` में `document-es.md` देता है; `--include_model` के साथ, `document-es-gpt-5.6-terra.md`। एक्सटेंशन हमेशा `.md` बन जाता है — `article.mdx` से `article-en.md` मिलता है — सिवाय `--keep_filename` के, जो मूल नाम बनाए रखता है। पहले से मौजूद अनुवाद को बिना `--force` के छोड़ दिया जाता है।

एग्ज़िट कोड: यदि सब कुछ सफल रहा या छोड़ दिया गया तो `0`, यदि कोई फ़ाइल विफल रही (मानक त्रुटि आउटपुट पर सूची) तो `1`, यदि कॉन्फ़िगरेशन में कोई समस्या है तो `2`। एक विफल फ़ाइल कभी भी नहीं लिखी जाती है, भले ही लेखन प्रक्रिया स्वयं विफल हो जाए: सामग्री को अलग से लिखा जाता है और फिर नाम बदला जाता है। बस दोबारा चलाना ही पर्याप्त है।

| ❌  | कम से कम एक भाषा का अनुवाद नहीं किया जा सका — फ़ाइल अस्वीकृत है, लिखी नहीं गई — **या** लिखी गई फ़ाइल में सामग्री गायब है                                                                              |

इससे क्या निष्कर्ष निकलता है:

- **अस्वीकृत अनुवाद कोई विकृत अनुवाद नहीं होता है।** जब वापसी पर कोई टोकन गायब होता है, तो फ़ाइल नहीं लिखी जाती है और भाषा को अस्वीकृत माना जाता है। लेख पर Grok के साथ यही हुआ: पाँच गैर-लैटिन लिपियों में, पहले ही खंड से चार इनलाइन कोड और तीन URL खो गए।
- **एक मॉडल केवल एक वाक्य के कारण पूरे दस्तावेज़ को अस्वीकार कर सकता है।** Opus 5.5 इस README का बिना किसी अंतर के अनुवाद करता है, लेकिन किसी भी निगरानी लेख का नहीं: इसके गार्डरेल्स जीव विज्ञान के एक संक्षिप्त समाचार पर प्रतिक्रिया रोक देते हैं। फ़ाइल नहीं लिखी जाती है, और aipmt इसका कारण बताता है।
- **यह सुरक्षा जाल शीर्षकों, तालिकाओं, front matter या पाठ को कवर नहीं करता है।** एक मॉडल जो किसी अनुभाग को हटा देता है, वह ऐसी फ़ाइल लौटाता है जिसे टूल बिना किसी आपत्ति के लिख देता है — Mistral का यही मामला है। इन तत्वों को टोकन से बदला नहीं जा सकता है, और वर्तमान गार्ड्स इन्हें नियंत्रित नहीं करते हैं; `scripts/compare_structure.py` किसी खोए हुए अनुभाग का पता लगाता है, लेकिन बाद में।
- **इस README पर Grok का कोई मूल्यांकन नहीं है**: बारह भाषाओं के बाद इसका CLI सत्र समाप्त हो गया, जिनमें से ग्यारह बिना किसी अंतर के थे। एक बाधित अभियान का मूल्यांकन नहीं किया जाता है।
- **भाषा की तुलना में दस्तावेज़ का घनत्व अधिक मायने रखता है।** Grok सामान्य README पर स्थिर रहता है और लिंक से भरे लेख पर पिछड़ जाता है, डच भाषा में भी।

तिथियाँ और दस्तावेज़: "यह README" कॉलम को 9 सितंबर 2026 को इस फ़ाइल के एक स्थिर संशोधन (785 पंक्तियाँ, 285 इनलाइन कोड, 89 तालिका पंक्तियाँ) पर मापा गया था, जिसमें बाद में संशोधन किए गए — Antigravity और Claude Code पंक्तियों को छोड़कर, जिन्हें 26 सितंबर को 1.14.0 के साथ प्रकाशित छोटे संशोधन (600 पंक्तियाँ, 257 इनलाइन कोड, 85 तालिका पंक्तियाँ) पर मापा गया था। "सघन निगरानी लेख" कॉलम 589 पंक्तियों के एक लेख पर 4 और 5 सितंबर के अभियान से आता है, Grok पंक्ति को छोड़कर, जिसे 9 सितंबर को उसी निगरानी के दूसरे संस्करण पर फिर से मापा गया था, और Antigravity तथा Claude Code पंक्तियों को छोड़कर, जिन्हें उसी लेख पर 26 सितंबर को मापा गया था। पूरी तालिकाएँ, अवधियाँ और प्रोटोकॉल [विस्तृत माप](#विस्तृत-माप) में हैं।

## प्रदाता

### API द्वारा: OpenAI, Mistral, Claude, Gemini, Grok

```bash
aipmt --source_dir content/fr --target_dir content/en --target_lang en             # OpenAI, défaut
aipmt --use_mistral --source_dir content/fr --target_dir content/es --target_lang es
aipmt --use_claude  --source_dir content/fr --target_dir content/de --target_lang de
aipmt --use_gemini  --source_dir content/fr --target_dir content/ja --target_lang ja
aipmt --use_grok    --source_dir content/fr --target_dir content/pt --target_lang pt
```

`--eco` प्रत्येक प्रदाता के किफ़ायती स्तर पर स्विच करता है।

| प्रदाता     | गुणवत्ता (डिफ़ॉल्ट)                                   | किफ़ायती (`--eco`)        |
| ----------- | ----------------------------------------------------- | --------------------------------- |
| OpenAI      | `gpt-5.6-terra`                                       | `gpt-5.6-luna`                   |
| Claude      | `claude-sonnet-5`                                       | `claude-haiku-4-5`                   |
| Mistral     | `mistral-large-latest`                                       | `mistral-small-latest`                   |
| Gemini      | `gemini-3.7-flash`                                       | `gemini-3.1-flash-lite`                   |
| Codex       | `gpt-5.6-sol` (`--model` के माध्यम से `terra` और `luna` भी) | `gpt-5.6-luna`                   |
| Grok API    | `grok-4.6`                                       | `grok-4.3`                   |
| Grok CLI    | `grok-4.6`                                       | `grok-4.5`                   |
| Antigravity | `gemini-3.8-flash-medium`                                       | `gemini-3.7-flash-low`                   |

| OpenCode    | `--model provider/modèle` अनिवार्य                              | वही — `--eco` का कोई प्रभाव नहीं |

### ChatGPT सदस्यता पर: `--use_codex`

यह आधिकारिक Codex CLI को नियंत्रित करता है: अनुवाद ChatGPT सदस्यता के कोटा से
घटाया जाता है, बिना किसी API कुंजी या उपयोग-आधारित बिलिंग के।

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- बाइनरी को `CODEX_BIN`, फिर `PATH`, और फिर `openai-codex-cli-bin`
  पैकेज में खोजा जाता है। `~/.codex/auth.json` को कभी पढ़ा नहीं जाता है।
- `OPENAI_API_KEY` और `CODEX_API_KEY` को सब-प्रोसेस के परिवेश से
  हटा दिया जाता है: मौजूद कुंजी कभी भी API पर स्विच नहीं कराती है।
- प्रत्येक खंड पर 5 घंटे की विंडो का कम से कम एक "संदेश" खर्च होता है — दो
  यदि इसका सत्यापन विफल हो जाता है और इसे पुनः प्रयास किया जाता है। OpenAI एक अनुमान
  के तौर पर, Plus प्लान पर `gpt-5.6-luna` (`--eco`) के लिए 250-2,000 संदेश/5 घंटे और
  `gpt-5.6-sol` के लिए 10-100 संदेशों की घोषणा करता है।
- `--model gpt-5.6-terra` और `--model gpt-5.6-luna` भी सदस्यता के माध्यम से ही
  चलते हैं। ऐसा मॉडल जिसके लिए खाता अधिकृत नहीं है, वह 400 « model is
  not supported when using Codex with a ChatGPT account » त्रुटि देता है।
- यह API की तुलना में धीमा है, और दस्तावेज़ के साथ यह अंतर बढ़ता जाता है: इस README पर,
  `gpt-5.6-sol` के साथ प्रति भाषा मीडियन 6 मिनट 46 सेकंड, जबकि
  `gemini-3.7-flash` के लिए 36 सेकंड लगे।
- CI में अस्वीकृत (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर): सदस्यता एक
  व्यक्तिगत सत्र फ़ाइल द्वारा प्रमाणित होती है, जिसका किसी साझा रनर पर
  कोई काम नहीं है।
- चर: `CODEX_BIN`, `CODEX_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 600)।

### Grok सदस्यता पर: `--use_grok_cli`

यही सिद्धांत SuperGrok या X Premium+ सदस्यता पर आधिकारिक Grok Build CLI के
साथ लागू होता है।

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --eco --file README.md --target_dir . --target_lang pl
```

- **Codex की तुलना में कमज़ोर सीमांकन।** Grok का OS सैंडबॉक्स
  कई आधुनिक Linux मशीनों (AppArmor, कंटेनर रनटाइम सॉकेट्स) पर लागू नहीं होता
  है, और जो प्रोफ़ाइल लागू नहीं हो सकती वह बिना बताए अप्रतिबंधित शुरू हो
  जाती है। इसलिए स्क्रिप्ट डिफ़ॉल्ट रूप से किसी प्रोफ़ाइल का अनुरोध नहीं करती है, इसकी घोषणा
  करती है, और CLI के `--deny` नियमों पर निर्भर करती है, जिसमें कैच-ऑल `*` शामिल है — एकमात्र
  ऐसी परत जो बिना बताए सुरक्षा हटाने के बजाय शुरू होने से मना कर देती
  है। `GROK_TRANSLATE_SANDBOX=read-only` के लिए OS सैंडबॉक्स आवश्यक है, और यदि मशीन इसे
  लागू नहीं कर सकती है तो स्टार्टअप विफल हो जाता है।
- कोटा साप्ताहिक है, जो Chat, Imagine और Voice के साथ साझा किया जाता है, और इसे
  पढ़ने के लिए कोई कमांड उपलब्ध नहीं है: एक बैच बिना किसी संकेत के संवादात्मक
  उपयोग के कोटे को कम कर सकता है।
- चर: `GROK_BIN`, `GROK_HOME` (CLI डायरेक्टरी, डिफ़ॉल्ट `~/.grok`),
  `GROK_TIMEOUT` (डिफ़ॉल्ट 900), `GROK_TRANSLATE_SANDBOX`।

### Google सदस्यता पर: `--use_antigravity`

यही सिद्धांत Antigravity के आधिकारिक CLI `agy` के साथ लागू होता है: जो लोग Google
AI Pro या Ultra के लिए भुगतान करते हैं, उनके लिए अनुवाद टोकन के आधार पर बिल किए जाने के बजाय
सदस्यता कोटे से काटा जाता है। इस कोटे तक पहुँचने का यही एकमात्र तरीका है: Gemini CLI
18 जून 2026 से इन खातों को सेवा नहीं देता है
([घोषणा](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)),
और Antigravity का SDK केवल API कुंजी या Google Cloud प्रोजेक्ट स्वीकार करता है।

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **कोई भी सशुल्क मार्ग खुला नहीं रहता है।** agy आपके परिवेश से केवल
  चरों की एक सीमित सूची प्राप्त करता है — `PATH`, भाषा और समय क्षेत्र,
  टर्मिनल, पहचान, प्रॉक्सी और प्रमाणपत्र, सत्र बस — और कोई कुंजी नहीं:
  इसके कई चर बिना कुछ प्रदर्शित किए कॉल को स्विच कर देते हैं (परीक्षण किया गया:
  एक दस्तावेज़ को किसी तीसरे पक्ष के गेटवे पर भेजता है, दूसरा बिल किए गए Google Cloud
  प्रोजेक्ट पर), और एक अस्वीकृति सूची हर समीक्षा में कुछ न कुछ छोड़ देती थी।
  किसी भी खंड से पहले, `agy -p /config`, जिसमें कोई कोटा खर्च नहीं होता, को सशुल्क AI
  क्रेडिट अक्षम दिखाना चाहिए, बिना किसी API कुंजी या Google Cloud प्रोजेक्ट के — किसी
  सेटिंग की अनुपस्थिति को अस्वीकृति माना जाता है —, अन्यथा कुछ भी अनुवादित नहीं होता है;
  प्रत्येक कॉल के लॉग को बाद में सदस्यता की पुष्टि करनी चाहिए (`authMethod=consumer`), अन्यथा
  प्रतिक्रिया अस्वीकार कर दी जाती है।
- **सीमांकन।** प्रत्येक कॉल बिना किसी टूल वाले अनुवाद एजेंट के साथ
  एक निजी और अस्थायी व्यक्तिगत डायरेक्टरी में चलती है: आपकी सेटिंग्स, नियम,
  प्लगइन्स, MCP सर्वर और agy हुक इसमें प्रवेश नहीं करते हैं, आपके इतिहास में कुछ भी नहीं जुड़ता
  है, और लॉगिन कीचेन में रहता है, जिसे aipmt कभी नहीं पढ़ता है।
  यदि कोई एजेंट नहीं मिलता है, तो agy चुपचाप अपने कोडिंग एजेंट और उसके टूल पर वापस
  आ जाता है: लॉग की पूरी पंक्ति को सही एजेंट की पुष्टि करनी चाहिए — इस संदेश को उद्धृत करने
  वाला दस्तावेज़ इसका स्थान नहीं लेता —, अन्यथा अस्वीकृति होगी।
- **प्लेटफ़ॉर्म**: Linux, ऐसे सत्र में जिसके पास कीचेन हो (D-Bus सत्र बस,
  Secret Service); macOS स्वीकार किया जाता है, हालांकि इसका परीक्षण नहीं किया गया है। Windows पर
  अस्वीकृत, जहाँ agy प्रत्येक कॉल को अलग करने वाले चरों को नहीं पढ़ता है, और
  बिना सत्र बस वाले Linux पर — SSH सत्र, कंटेनर, सर्वर: agy अपना टोकन
  `~/.gemini` की एक फ़ाइल में संग्रहीत करता है, जिसे अलगाव छुपा देता है। लॉगिन
  कोड के लिए एक मिनट प्रतीक्षा करने के बजाय, कारण सहित अस्वीकृति किसी भी लॉन्च से
  पहले ही आ जाती है।
- **मॉडल**: `agy models` वाले मॉडल। Gemini मॉडल के नाम में प्रयास शामिल होता है
  (`gemini-3.8-flash-medium`…): बिना प्रत्यय वाले नाम को कॉल से पहले ही अस्वीकार कर दिया जाता है,
  और `--reasoning_effort` का कोई प्रभाव नहीं होता है। डिफ़ॉल्ट रूप से `gemini-3.8-flash-medium`,
  और `--eco` में `gemini-3.7-flash-low`; इन्हें निर्धारित करने वाले अभियानों का
  वर्णन [विस्तृत माप](#विस्तृत-माप) में किया गया है। Claude और GPT-OSS
  का अपना अलग कोटा होता है, जो बहुत छोटा है: मापे गए कॉल के अनुसार 5 घंटे की
  विंडो का लगभग 1%, जबकि Flash में यह 0.05% है।
- **कोटा**: प्रति समूह, टोकन लागत के अनुपात में 5 घंटे की और एक साप्ताहिक विंडो।
  लेखक के खाते पर मापा गया: `gemini-3.8-flash-medium` में प्रति दस लाख स्रोत वर्णों पर
  5 घंटे की विंडो के लगभग 16 अंक, `gemini-3.7-flash-medium` में 14 और निम्न प्रयास पर
  7 से 8 अंक — इसलिए 40,000 वर्णों वाले README की लागत आधे से थोड़ी
  अधिक अंक होती है। साप्ताहिक सीमा स्तर पर निर्भर करती है। पुनः प्रयास
  उसका अनुसरण करता है जिसे agy पुनः प्रयास योग्य घोषित करता है; अन्यथा, समाप्त हो चुकी विंडो पर
  कभी पुनः प्रयास नहीं किया जाता: यह `/usage` द्वारा प्रदर्शित रीसेट होने तक
  प्रत्येक फ़ाइल को विफल कर देता है।
- **API से धीमा**: मापों के सघन लेख पर, प्रति भाषा मीडियन `gemini-3.8-flash-medium` में
  3 मिनट 59 सेकंड और `gemini-3.7-flash-medium` में 3 मिनट 14 सेकंड, जबकि
  API के माध्यम से Gemini 3.7 Flash के लिए 1 मिनट 18 सेकंड लगे।
- **रुकावट**: Ctrl-C, या बंद किया गया टर्मिनल, आपके कोटे पर अपना कार्य पूरा करने देने
  के बजाय कमांड के साथ agy को रोक देता है; यही बात Codex, Grok CLI और OpenCode पर
  भी लागू होती है। `nohup` के तहत अनुवाद जारी रहता है।
- CI में अस्वीकृत (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर): लॉगिन एक
  व्यक्तिगत कीचेन में रहता है। किसी रनर पर, `GOOGLE_API_KEY` के साथ `--use_gemini` का उपयोग करें।
- चर: `AGY_BIN` (अन्यथा `PATH`, फिर `~/.local/bin/agy`),
  `AGY_TIMEOUT` (स्टार्टअप सहित प्रति खंड सेकंड, डिफ़ॉल्ट 900)।

### Claude सब्सक्रिप्शन पर: `--use_claude_code`

`claude`, जो `-p` मोड में Claude Code का आधिकारिक CLI है, के साथ भी यही सिद्धांत लागू होता है: जो लोग Claude Pro या Max का भुगतान करते हैं, उनके लिए अनुवाद टोकन के आधार पर बिल किए जाने के बजाय सब्सक्रिप्शन कोटा से काटा जाता है। इसे `--use_claude`, जो उपयोग के आधार पर बिल की जाने वाली Anthropic की API है, के साथ भ्रमित न करें।

```bash
claude                                   # une fois : /login avec le compte de l'abonnement
aipmt --use_claude_code --file README.md --target_dir . --target_lang en
```

- **कोई भी सशुल्क मार्ग खुला नहीं रहता है, और प्रत्येक कॉल इसे प्रमाणित करती है।** Claude
  Code आपके परिवेश से केवल चरों की एक सीमित सूची प्राप्त करता है — न कोई
  API कुंजी, न कोई टोकन, न कोई क्लाउड प्रदाता, और न ही उस Claude Code सत्र
  का कोई मार्कर जिससे aipmt लॉन्च किया गया हो। पहले खंड से पहले, `claude auth status` को
  बिना किसी Console कुंजी के सब्सक्रिप्शन कनेक्शन दिखाना चाहिए, और `/usage`, जिसकी
  कोई कोटा लागत नहीं होती, को इसे प्रमाणित करना चाहिए; प्रत्येक कॉल अपने
  इनिशियलाइज़ेशन इवेंट में बदले में इसे प्रमाणित करती है, अन्यथा प्रतिक्रिया अस्वीकार कर दी जाती है।
- **"extra usage" को अक्षम करें** (claude.ai, सेटिंग्स → उपयोग) ताकि
  शून्य यूरो का नियम बना रहे: सक्षम होने पर, यह समाप्त हो चुकी विंडो की जगह ले लेता है और
  बिना कोई त्रुटि दिखाए बिलिंग शुरू कर देता है। aipmt अनुवाद को तुरंत रोक
  देता है जैसे ही किसी कॉल की कोटा रिपोर्ट इसका संकेत देती है, लेकिन वह कॉल पहले ही गिनी जा चुकी होती है।
- **आपके Claude Code सत्रों के साथ साझा कोटा।** प्रत्येक कॉल 5 घंटे और
  सप्ताह की विंडो के उपयोग की रिपोर्ट करती है; 80%
  (`AIPMT_CLAUDE_MAX_UTILIZATION`) से अधिक होने पर, आपके कार्य के लिए आवश्यक कोटा समाप्त न हो,
  इसके लिए कोई अतिरिक्त खंड लॉन्च नहीं किया जाता है।
- **कन्फाइनमेंट।** प्रत्येक कॉल बिना किसी टूल के, एक निजी और
  प्रयोज्य डायरेक्टरी में, बिना अनुकूलन वाले मोड में चलती है: न तो आपके `CLAUDE.md`, न ही आपके प्लगइन्स,
  हुक्स, MCP सर्वर या सेटिंग्स लोड होते हैं, और सत्र का कुछ भी सहेजा नहीं जाता है।
  अटैचमेंट काट दिए जाते हैं: आपके दस्तावेज़ में `@chemin` केवल टेक्स्ट
  बना रहता है और कोई फ़ाइल नहीं खोलता (मापा गया)।
- **मॉडल**: डिफ़ॉल्ट रूप से `sonnet`, `low` प्रयास पर, और `--eco` में भी:
  इस पथ पर `--eco` कुछ नहीं बदलता है। समान दस्तावेज़ों पर मापे जाने पर, `haiku`
  दोगुना धीमा है — यह सोचना जारी रखता है बिना इसके कि इसे रोका जा सके — जबकि
  लागत बमुश्किल कम होती है, और `opus` जीव विज्ञान से संबंधित सामग्री को अस्वीकार कर देता है (अगला
  बिंदु)। दोनों `--model` के माध्यम से सुलभ रहते हैं; ये उपनाम अपने परिवार के
  नवीनतम मॉडल का अनुसरण करते हैं। `fable` और `[1m]` वेरिएंट अस्वीकार कर दिए जाते हैं,
  क्योंकि वे सशुल्क क्रेडिट में चले जाते हैं। `--reasoning_effort` प्रयास को समायोजित करता है,
  जिससे अनुवाद को कोई लाभ नहीं होता: मापा गया तर्क शून्य या नगण्य है।
- **Opus जीव विज्ञान की कुछ सामग्रियों को अस्वीकार करता है।** इसके गार्डरेल्स
  Sonnet की तुलना में अधिक सख्त हैं, और Anthropic का त्रुटि संदेश चेतावनी देता है कि वे
  « can sometimes flag biology-research-adjacent work »। मापा गया: 279 उत्पन्न
  अणुओं पर एक मॉनिटरिंग संक्षिप्त टिप्पणी के कारण चौदह भाषाओं में लेख
  अस्वीकार कर दिया गया। कुछ भी नहीं लिखा जाता है: aipmt अधूरी प्रतिक्रिया को अस्वीकार करता है,
  गार्डरेल्स का नाम बताता है और `--model sonnet` की सलाह देता है।
- CI में (`CI` या `GITHUB_ACTIONS` निर्धारित होने पर) और Windows पर (परीक्षण नहीं किया गया) अस्वीकृत।
- चर: `AIPMT_CLAUDE_BIN` (अन्यथा `PATH`, फिर `~/.local/bin/claude`),
  `AIPMT_CLAUDE_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 900),
  `AIPMT_CLAUDE_MAX_UTILIZATION` (दिफ़ॉल्ट 0.8), `CLAUDE_CONFIG_DIR` (Claude Code खाता,
  कभी किसी प्रोजेक्ट के `.env` से नहीं लिया जाता); `XDG_CACHE_HOME/aipmt/claude-code` के अंतर्गत कार्य डायरेक्टरीज़
  (दिफ़ॉल्ट `~/.cache`)।

**उपयोग की शर्तें: यह आपका खाता है जो इसमें शामिल है।** Claude
Code का [कानूनी पृष्ठ](https://code.claude.com/docs/en/legal-and-compliance)
« an end user from signing in to the unmodified Claude Code binary
with their own Claude subscription » को नहीं रोकता है: aipmt यही करता है, जो
आधिकारिक बाइनरी लॉन्च करता है और कभी टोकन नहीं पढ़ता। लेकिन Anthropic « does not permit
third-party developers […] to route requests through Free, Pro, or Max plan
credentials on behalf of their users », तृतीय-पक्ष टूल के लिए API कुंजी को प्राथमिकता देता है,
« including open-source projects », और उनके उपयोग को सशुल्क क्रेडिट से
काटने का अधिकार सुरक्षित रखता है
([Claude सहायता](https://support.claude.com/en/articles/13189465-logging-in-to-your-claude-account))।
कोई भी दस्तावेज़ बाइनरी लॉन्च करने वाले वितरित टूल के मामले पर स्पष्ट निर्णय नहीं देता है।

**डेटा**: Free, Pro और Max खातों पर, मॉडल प्रशिक्षण Claude Code पर भी लागू
होता है जब गोपनीयता सेटिंग इसकी अनुमति देती है
([डेटा पृष्ठ](https://code.claude.com/docs/en/data-usage))। aipmt कोई
स्थानीय प्रतिलेखन नहीं रखता है (`--no-session-persistence`)। इसके माध्यम से
कुछ भी गोपनीय न भेजें।

### अपनी पसंद के प्रदाता की ओर: `--use_opencode`

[OpenCode](https://opencode.ai) एक ओपन-सोर्स (MIT) कोड एजेंट है जो
अपने भीतर कॉन्फ़िगर किए गए प्रदाताओं पर रूट करता है: API कुंजी, सब्सक्रिप्शन,
OpenCode Zen गेटवे (बिना खाते के मुफ़्त मॉडल) या स्थानीय मॉडल। यहाँ दो
मार्गों को शुरू से अंत तक मापा गया है, Zen और Ollama।

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` अनिवार्य है: इसके बिना, OpenCode एक मुफ़्त मॉडल पर वापस चला जाएगा
जिसके संवादों का उपयोग प्रशिक्षण के लिए किया जा सकता है, और यह विकल्प आपकी
सहमति के बिना नहीं चुना जाता है।

प्रत्येक कॉल पर कन्फाइनमेंट:

- एक इनलाइन कॉन्फ़िगरेशन, जो आपके कॉन्फ़िगरेशन से अधिक प्राथमिकता रखता है, एक एजेंट `aipmt`
  को परिभाषित करता है जिसके सभी टूल्स अस्वीकृत होते हैं (`permission: { "*": "deny" }`), सत्र
  साझाकरण अक्षम होता है, `--pure`, कभी `--auto` नहीं;
- प्रयोज्य और खाली कार्य डायरेक्टरी, `OPENCODE_DISABLE_PROJECT_CONFIG` और
  `OPENCODE_DISABLE_CLAUDE_CODE` सेट किए गए — इनके बिना, OpenCode वर्तमान डायरेक्टरी के
  `AGENTS.md` और `~/.claude/CLAUDE.md` को प्रॉम्प्ट में इंजेक्ट करता है। वैश्विक
  `~/.config/opencode/AGENTS.md` इंजेक्ट रहता है, OpenCode इसे हटाने की अनुमति
  नहीं देता है;
- आउटपुट अनुबंध: रिटर्न कोड 0, कोई `error` इवेंट नहीं, कोई टूल
  कॉल नहीं, अंतिम चरण `stop` में, गैर-रिक्त टेक्स्ट, और एजेंट `aipmt`
  वास्तव में लोड हुआ — एक अज्ञात `--agent` OpenCode को विफल नहीं करता है, यह
  चुपचाप कोडिंग एजेंट पर वापस आ जाता है;
- `aipmt` की कोई कुंजी प्रेषित नहीं की जाती है, सिवाय `OPENCODE_API_KEY` के, जो स्वयं OpenCode
  की कुंजी है। प्रदाताओं को OpenCode में कॉन्फ़िगर किया जाता है, `aipmt`
  के `.env` में नहीं।

ध्यान देने योग्य बातें:

- Zen के मुफ़्त मॉडल परिवर्तनशील हैं, जिनकी सीमाएं अप्रलेखित हैं, और
  उनके संवादों का उपयोग प्रशिक्षण के लिए किया जा सकता है: यह सार्वजनिक दस्तावेज़ों
  के लिए उपयुक्त है, निजी सामग्री के लिए नहीं।
- एक स्थानीय मॉडल को कम से कम 16 k टोकन का संदर्भ प्रदान करना चाहिए, क्योंकि खंड
  16,000 वर्णों तक के होते हैं। Ollama अक्सर 4,096 कॉन्फ़िगर करता है: `PARAMETER num_ctx 32768`
  के साथ `Modelfile` का उपयोग करें।
- `--eco` का कोई प्रभाव नहीं है; `--reasoning_effort` को OpenCode के
  `--variant` के रूप में ज्यों का त्यों प्रेषित किया जाता है।
- OpenCode प्रत्येक सत्र को `~/.local/share/opencode/` में लॉग करता है।
- चर: `OPENCODE_BIN` (अन्यथा `PATH`, फिर `~/.opencode/bin/opencode`),
  `OPENCODE_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 600)। `OPENCODE_CONFIG`
  OpenCode को ज्यों का त्यों पास किया जाता है।

`~/.config/opencode/opencode.json` में Ollama के माध्यम से एक स्थानीय मॉडल का उदाहरण:

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

`reasoningEffort: "none"` उस रीज़निंग को बंद कर देता है जिसे Ollama इन मॉडलों पर डिफ़ॉल्ट रूप से
सक्रिय करता है, और जिसे Modelfile अक्षम नहीं कर सकता। छह शब्दों के
एक वाक्य पर मापा गया: इस विकल्प के बिना 919 रीज़निंग टोकन और 68 सेकंड, विकल्प के साथ 9 टोकन।

### 400 से अधिक मॉडलों की ओर: `--use_openrouter`

OpenRouter तृतीय पक्षों द्वारा होस्ट किए गए मॉडलों के समक्ष, एकल क्रेडिट पर
उपयोग-आधारित बिलिंग वाला एक राउटर है — जिसमें खुले चीनी मॉडल भी शामिल हैं जिन्हें
यहाँ कोई अन्य प्रदाता प्रदर्शित नहीं करता है।

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` अनिवार्य है। किसी भी बिलिंग से पहले निष्पादित एक प्रीफ़्लाइट, रूटिंग की
दो विशेषताओं को संभालता है:

- **एक ही मॉडल को अलग-अलग सीमाओं वाले दर्जनों होस्टों द्वारा परोसा जाता है** — `z-ai/glm-5.3-flash`
  पर, 23 होस्ट जिनमें से एक 2,048 आउटपुट टोकन तक सीमित है। प्रीफ़्लाइट `/api/v1/models/{modèle}/endpoints` को
  पढ़ता है, 8,000 आउटपुट टोकन से कम या ख़राब स्थिति वाले होस्टों को बाहर करता है, और
  अन्यों को `allow_fallbacks: false` के साथ पिन करता है।
- **रीज़निंग का बिल आउटपुट दर पर लिया जाता है** — `z-ai/glm-5.2` की एक « OK »
  प्रतिक्रिया पर 2 के मुकाबले 107 टोकन। यह डिफ़ॉल्ट रूप से बंद रहता है; जो मॉडल
  इसे अनिवार्य करते हैं, उन्हें वह सबसे कम प्रयास दिया जाता है जिसे वे स्वीकार करते हैं, क्योंकि कैटलॉग
  का डिफ़ॉल्ट अनुवाद समाप्त होने से पहले ही आउटपुट को संतृप्त कर सकता है।
  `--reasoning_effort` प्राथमिकता पर रहता है।

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- संदर्भ विंडो कैटलॉग से आती है। 16,400 टोकन से कम वाले मॉडल को
  किसी भी कॉल से पहले अस्वीकार कर दिया जाता है: प्रॉम्प्ट और खंड के लिए 8,400, कम से कम
  8,000 आउटपुट।
- कैटलॉग में अनुपस्थित स्लग, अगम्य कैटलॉग या सीमा को बनाए रखने
  वाले होस्ट की अनुपस्थिति कमांड को रोक देती है।
- रिक्त आउटपुट के साथ `finish_reason=length` रीज़निंग द्वारा खपत किया गया बजट है,
  न कि कोई ट्रंकेशन: संदेश इसमें अंतर करता है।
- `--eco` का कोई प्रभाव नहीं है।
- चर: `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>),
  `OPENROUTER_BASE_URL` (दिफ़ॉल्ट `https://openrouter.ai/api/v1`, `https://`
  आवश्यक), `OPENROUTER_TIMEOUT` (दिफ़ॉल्ट 900), `OPENROUTER_PREFLIGHT_TIMEOUT`
  (दिफ़ॉल्ट 30)।

### अनुवाद टिप्पणी

`--add_translation_note` एक टिप्पणी जोड़ता है, `bottom` (दिफ़ॉल्ट), `top` (फ़्रंट
मैटर के बाद) या `both` (`--note_position`) पर, `legacy` प्रारूप (बोल्ड पैराग्राफ,
दिफ़ॉल्ट) या `marker` (`--note_format`) में। `marker` प्रारूप एक
अदृश्य Markdown संदर्भ परिभाषा है,
`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`,
जिसके बाद एक बोल्ड उद्धरण होता है: GitHub पर पठनीय, remark प्लगइन द्वारा बिल्ड के समय उपयोग योग्य।

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## विस्तृत माप

सभी माप चौदह भाषाओं में `aipmt` के साथ वास्तव में निष्पादित अनुवाद हैं:
en, es, de, it, pt, nl, pl, sv, ro, ja, ko, zh, ar, hi।
**लिखित** उन फ़ाइलों की गणना करता है जिन्हें गार्ड्स ने पास होने दिया; **बिना

लिंक्स, विशिष्ट URLs, कोड ब्लॉक्स, इनलाइन कोड्स, तालिका पंक्तियों, ब्लॉक उद्धरणों और बोल्ड शब्दों की समान संख्या।

« बिना अंतर » का अर्थ है « कुछ भी नहीं मिला », न कि « समान »: तुलनित्र
सामग्री को पढ़े बिना तत्वों की गणना करता है। यह न तो हटाए गए स्तर 4 के शीर्षक को
चिह्नित करता है, न ही बदले गए इनलाइन कोड के टेक्स्ट को, न ही बदले गए ध्वज को,
न ही एक अतिरिक्त कोष्ठक के साथ प्रस्तुत आंतरिक लिंक `[texte]((#ancre))` को,

### ये माप क्या नहीं हैं

- **कोई संपूर्ण रैंकिंग नहीं**: केवल OpenRouter ही चार सौ से अधिक मॉडल प्रदान करता है, जिनमें से लगभग पंद्रह को मापा गया था।
- **संकेतक अवधियाँ**: अभियानों के आधार पर समानांतर में तीन से छह अनुवाद, और किसी प्रदाता का थ्रूपुट दिन भर में बदलता रहता है।
- **तारीख-विशिष्ट अवलोकन**: एक ही नाम के तहत मॉडल बदलते रहते हैं, और आपके दस्तावेज़ हमारे दस्तावेज़ों जैसे नहीं हैं।

फ़ाइल की एक निश्चित प्रति पर, अपने दस्तावेज़ों पर माप को दोहराने के लिए:

```bash
aipmt --file reference.md --target_dir out/ --source_lang fr --target_lang ja --use_gemini --force
aipmt --file veille.mdx   --target_dir out/ --source_lang fr --target_lang ja --use_gemini --news --force
python scripts/compare_structure.py reference.md out/reference-ja.md
# « structure identique », ou la liste des écarts — sortie 0 si identique, 1 sinon
```

## योगदान देना

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

दोनों पंक्तियाँ आवश्यक हैं: बिना `pip install -e .` के, `python -m aipmt` उत्तर देता है `No module named aipmt`।

गुणवत्ता उपकरण, वैकल्पिक लेकिन अनुशंसित:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```

रिपॉजिटरी के 28 अनुवाद (README और CHANGELOG, चौदह भाषाएँ) `./regen_translations.sh --force` के साथ पुनर्जीवित किए जाते हैं — डिफ़ॉल्ट रूप से ChatGPT सदस्यता पर Codex और `gpt-5.6-sol`, समानांतर में चार। `REGEN_PROVIDER` और `REGEN_MODEL` पथ बदलते हैं: `antigravity` एक सदस्यता पर रहता है, Google की सदस्यता पर, और बिना किसी छूट के पास हो जाता है; एक बिल की जाने वाली API (`openai`, `gemini`, `grok`, `openrouter`) बिना `REGEN_ALLOW_PAID_API=1` के अस्वीकार कर दी जाती है; `REGEN_JOB_TIMEOUT` प्रत्येक जॉब को सीमित करता है (600 सेकंड, Codex और Antigravity पर 1,800 सेकंड)। उपकरणों का विवरण `CLAUDE.md` में है।
