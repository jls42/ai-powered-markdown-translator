यह संरचना को सुरक्षित रखते हुए Markdown फ़ाइलों का एक भाषा से दूसरी भाषा में
अनुवाद करता है: कोड ब्लॉक, इनलाइन कोड, URL, एंकर, तालिकाएँ और front
matter। किसी मॉडल को कॉल करने के ग्यारह तरीके—पाँच API, उपयोग के अनुसार
बिलिंग के बिना चार सदस्यताएँ, दो राउटर—और प्रत्येक मॉडल वास्तव में क्या
सुरक्षित रखता है, इसका प्रकाशित माप।

## संक्षेप में

- **provider के ग्यारह मार्ग**: OpenAI, Mistral, Claude, Gemini और Grok API;
  उपयोग के अनुसार बिलिंग के बिना ChatGPT (Codex), Grok, Google (Antigravity)
  और Claude (Claude Code) सदस्यताएँ; OpenCode राउटर (ओपन सोर्स, मुफ़्त या
  स्थानीय) और OpenRouter (400 से अधिक मॉडल)।
- **किसी खोए हुए टोकन के कारण कोई गलत परिणाम नहीं**: कोड ब्लॉक, इनलाइन कोड,
  URL, एंकर और उद्धरणों को कॉल से पहले टोकन से बदल दिया जाता है और लौटने पर
  सत्यापित किया जाता है। यदि कोई टोकन गायब हो, तो फ़ाइल नहीं लिखी जाती।
- **लंबे दस्तावेज़**: मॉडल की विंडो के अनुसार विभाजन।
- **`--news` मोड**: निगरानी लेखों के लिए अंग्रेज़ी उद्धरण सुरक्षित और
  भाषा के अनुसार फ़्लैग प्रबंधित।
- **`--eco` मोड**: तेज़ और कम महँगे मॉडल।
- वैकल्पिक **अनुवाद टिप्पणी**, ऊपर, नीचे या दोनों जगह।

## इंस्टॉलेशन

```bash
pip install ai-powered-markdown-translator     # ou : pipx install ai-powered-markdown-translator
aipmt --help                                   # ou : python -m aipmt --help
```

Python 3.10 या उससे नया। रिपॉज़िटरी से इंस्टॉल करने के लिए,
[योगदान करें](#योगदान-देना) देखें।

## कॉन्फ़िगरेशन

कुंजियाँ तीन स्थानों से, उच्चतम से न्यूनतम प्राथमिकता के क्रम में पढ़ी जाती
हैं; प्रत्येक केवल वही रिक्तियाँ भरता है जिन्हें पिछला स्थान खाली छोड़ता है।

|     | कहाँ                                            | किसलिए                             |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | पर्यावरण चर                     | CI, कंटेनर, अस्थायी अपवाद |
| 2   | वर्तमान डायरेक्टरी (या किसी parent) की `.env` | किसी प्रोजेक्ट की अपनी कुंजी            |
| 3   | `~/.config/aipmt/.env`                        | एक बार इंस्टॉल, हर जगह मान्य       |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

`GOOGLE_API_KEY` के स्थान पर `GEMINI_API_KEY` स्वीकार किया जाता है। उपयोगकर्ता
फ़ाइल `XDG_CONFIG_HOME` (केवल निरपेक्ष पथ) और Windows पर `%APPDATA%` का
अनुसरण करती है। कुंजी न होने पर कमांड तीनों स्थानों को सूचीबद्ध करती है।

**किसी प्रोजेक्ट का `.env` न तो कॉल को दूसरी ओर भेज सकता है, न ही
चलाए जाने वाले प्रोग्राम को चुन सकता है।** वह कुंजियाँ देता है, कभी कोई
गंतव्य या बाइनरी नहीं: `_BASE_URL`, `_API_BASE`, `_ENDPOINT` या
`_BIN` (`CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN`,
`AGY_BIN`) में मौजूद हर चर, `GROK_HOME`, प्रॉक्सी (`HTTP_PROXY`,
`HTTPS_PROXY`, `ALL_PROXY`), प्रमाणपत्र भंडार (`SSL_CERT_FILE`,
`SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`) और `XDG_CONFIG_HOME` /
`APPDATA` को चेतावनी के साथ अनदेखा किया जाता है। क्लोन किया गया
रिपॉज़िटरी आपकी कुंजी को दूसरी ओर नहीं भेज सके और न ही पहले अनुवाद पर आपसे
अपना प्रोग्राम चलवा सके। यह फ़ाइल interpolation के बिना भी पढ़ी जाती है:
`NOM=${OPENAI_API_KEY}` उसमें कुंजी की प्रतिलिपि नहीं बनाता। इन चरों को पर्यावरण या
`~/.config/aipmt/.env` में रखें।

वैकल्पिक चर: `XAI_BASE_URL` (डिफ़ॉल्ट `https://api.x.ai/v1`),
`CLAUDE_TIMEOUT` (प्रति कॉल सेकंड, डिफ़ॉल्ट 900), `CODEX_BIN`, `CODEX_TIMEOUT`
(डिफ़ॉल्ट 600), `GROK_BIN`, `GROK_HOME` (डिफ़ॉल्ट `~/.grok`), `GROK_TIMEOUT`
(डिफ़ॉल्ट 900), `GROK_TRANSLATE_SANDBOX`, `AGY_BIN`, `AGY_TIMEOUT` (डिफ़ॉल्ट 900),
`OPENCODE_BIN`, `OPENCODE_TIMEOUT` (डिफ़ॉल्ट 600), `OPENROUTER_BASE_URL`
(`https://` आवश्यक), `OPENROUTER_TIMEOUT` (डिफ़ॉल्ट 900),
`OPENROUTER_PREFLIGHT_TIMEOUT` (डिफ़ॉल्ट 30)। प्रत्येक का विवरण उसके
provider के अनुभाग में दिया गया है।

## शुरुआत करना

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

स्पेनी में अनुवाद करने पर `document.md`, `--target_dir` में
`document-es.md` देता है; `--include_model` के साथ, `document-es-gpt-5.6-terra.md`। एक्सटेंशन
हमेशा `.md` बन जाता है—`article.mdx`, `article-en.md` देता है—
सिवाय `--keep_filename` के साथ, जो मूल नाम बनाए रखता है। पहले से मौजूद अनुवाद
को `--force` के बिना छोड़ दिया जाता है।

निकास कोड: यदि सब कुछ सफल हुआ या छोड़ दिया गया तो `0`, यदि कोई
फ़ाइल विफल रह गई तो `1` (सूची त्रुटि आउटपुट पर), और यदि समस्या
कॉन्फ़िगरेशन की हो तो `2`। विफल फ़ाइल कभी नहीं लिखी जाती, भले ही
लेखन स्वयं विफल हो जाए: सामग्री को पास में लिखकर फिर उसका नाम बदला जाता है।
बस दोबारा चलाना पर्याप्त है।

इससे ध्यान रखने योग्य बातें:

- **अस्वीकृत अनुवाद क्षतिग्रस्त अनुवाद नहीं होता।** लौटने पर कोई टोकन गायब

  के साथ यही होता है: पाँच गैर-Latin लिपियों में पहले ही खंड से चार इनलाइन

  इस README का बिना किसी अंतर के अनुवाद करता है, लेकिन किसी निगरानी लेख का
  नहीं: उसकी सुरक्षा जाँचें जीवविज्ञान की एक संक्षिप्त ख़बर पर उत्तर रोक देती
  हैं। फ़ाइल नहीं लिखी जाती और aipmt इसका कारण बताता है।
- **यह सुरक्षा जाल शीर्षकों, तालिकाओं, front matter या पाठ को शामिल नहीं करता।**

  लिख देता है—Mistral के साथ यही होता है। इन तत्वों को टोकन से बदला नहीं जा
  सकता और वर्तमान जाँचें इन्हें नियंत्रित नहीं करतीं; `scripts/compare_structure.py` खोए हुए
  अनुभाग का पता लगाता है, लेकिन बाद में।
- **इस README के लिए Grok का कोई अंक नहीं है**: उसका CLI सत्र बारह भाषाओं के

## सभी विकल्प

| विकल्प                   | विवरण                                                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |

| `--eco`                  | किफ़ायती मॉडल का उपयोग करें                                                                              |
| `--use_mistral`          | Mistral AI API का उपयोग करें                                                                                     |
| `--use_claude`           | Claude API का उपयोग करें                                                                                         |
| `--use_gemini`           | Gemini API का उपयोग करें                                                                                         |
| `--use_grok`             | xAI (Grok) API का उपयोग करें — `XAI_API_KEY` आवश्यक है                                                           |
| `--use_codex`            | ChatGPT सदस्यता कोटा पर Codex CLI का उपयोग करें                                                    |

| `--force`                | पुनः अनुवाद को बाध्य करें                                                                                       |
| `--keep_filename`        | मूल फ़ाइल नाम बनाए रखें                                                                          |
| `--news`                 | समाचार मोड: अंग्रेज़ी उद्धरणों को सुरक्षित रखता है, भाषा के अनुसार फ़्लैग संभालता है                                      |

## प्रदाता

### API के माध्यम से: OpenAI, Mistral, Claude, Gemini, Grok

```bash
aipmt --source_dir content/fr --target_dir content/en --target_lang en             # OpenAI, défaut
aipmt --use_mistral --source_dir content/fr --target_dir content/es --target_lang es
aipmt --use_claude  --source_dir content/fr --target_dir content/de --target_lang de
aipmt --use_gemini  --source_dir content/fr --target_dir content/ja --target_lang ja
aipmt --use_grok    --source_dir content/fr --target_dir content/pt --target_lang pt
```

`--eco` प्रत्येक प्रदाता के किफ़ायती स्तर पर स्विच करता है।

| प्रदाता    | गुणवत्ता (डिफ़ॉल्ट)                                      | किफ़ायती (`--eco`)      |
| ----------- | ----------------------------------------------------- | ------------------------- |
| OpenAI      | `gpt-5.6-terra`                                       | `gpt-5.6-luna`            |
| Claude      | `claude-sonnet-5-5`                                   | `claude-haiku-5-5`        |
| Mistral     | `mistral-large-latest`                                | `mistral-small-latest`    |
| Gemini      | `gemini-3.7-flash`                                    | `gemini-3.1-flash-lite`   |
| Codex       | `gpt-5.6-sol` (`--model` के माध्यम से `terra` और `luna` भी) | `gpt-5.6-luna`            |
| Grok API    | `grok-4.6`                                            | `grok-4.3`                |
| Grok CLI    | `grok-4.6`                                            | `grok-4.5`                |
| Antigravity | `gemini-3.8-flash-medium`                             | `gemini-3.7-flash-low`    |
| Claude Code | `sonnet`, प्रयास `low`                                | समान — `--eco` का कोई प्रभाव नहीं |
| OpenCode    | `--model provider/modèle` अनिवार्य                 | समान — `--eco` का कोई प्रभाव नहीं |
| OpenRouter  | `--model fournisseur/modèle` अनिवार्य              | समान — `--eco` का कोई प्रभाव नहीं |

### ChatGPT सदस्यता पर: `--use_codex`

आधिकारिक Codex CLI को संचालित करता है: अनुवाद की गणना ChatGPT सदस्यता
कोटा में होती है, बिना API कुंजी या उपयोग-आधारित बिलिंग के।

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- बाइनरी को पहले `CODEX_BIN`, फिर `PATH`, और फिर
  `openai-codex-cli-bin` पैकेज में खोजा जाता है। `~/.codex/auth.json` को कभी नहीं पढ़ा जाता।
- उप-प्रक्रिया के परिवेश से `OPENAI_API_KEY` और `CODEX_API_KEY` हटा दिए जाते
  हैं: मौजूद कुंजी कभी भी API पर स्विच नहीं कराती।
- प्रत्येक खंड की लागत 5 घंटे की विंडो के कम-से-कम एक « संदेश » के बराबर होती है —
  यदि उसका सत्यापन विफल हो और उसे दोबारा आज़माया जाए, तो दो संदेश। OpenAI के
  अनुमान के अनुसार, Plus योजना पर `gpt-5.6-luna` (`--eco`) के लिए
  250-2 000 संदेश/5 घंटे और `gpt-5.6-sol` के लिए 10-100 संदेश मिलते हैं।
- `--model gpt-5.6-terra` और `--model gpt-5.6-luna` भी
  सदस्यता के माध्यम से चलते हैं। जिस मॉडल की अनुमति खाते को नहीं है, वह 400 « model is
  not supported when using Codex with a ChatGPT account » लौटाता है।
- API से धीमा है, और दस्तावेज़ के साथ अंतर बढ़ता जाता है: इस README पर,
  `gpt-5.6-sol` के साथ प्रति भाषा माध्यिका 6 मिनट 46 सेकंड, जबकि
  `gemini-3.7-flash` के साथ 36 सेकंड।
- CI में अस्वीकृत (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर): सदस्यता
  व्यक्तिगत सत्र फ़ाइल के माध्यम से प्रमाणित होती है, जिसे साझा रनर पर नहीं
  होना चाहिए।
- वेरिएबल: `CODEX_BIN`, `CODEX_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 600)।

### Grok सदस्यता पर: `--use_grok_cli`

आधिकारिक Grok Build CLI के साथ यही सिद्धांत SuperGrok या
X Premium+ सदस्यता पर लागू होता है।

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --eco --file README.md --target_dir . --target_lang pl
```

- **Codex की तुलना में कमज़ोर परिसीमन।** Grok का OS सैंडबॉक्स कई हालिया
  Linux मशीनों पर लागू नहीं होता (AppArmor, कंटेनर रनटाइम सॉकेट), और जो
  प्रोफ़ाइल लागू नहीं हो पाती, वह बिना किसी सूचना के अपरिसीमित रूप में शुरू
  हो जाती है। इसलिए स्क्रिप्ट डिफ़ॉल्ट रूप से किसी प्रोफ़ाइल का अनुरोध नहीं
  करती, इसकी सूचना देती है, और CLI के `--deny` नियमों पर निर्भर रहती है,
  जिनमें सर्वसमावेशी `*` भी है — यही एकमात्र परत है जो बिना बताए
  सुरक्षा हटाने के बजाय शुरू होने से इनकार करती है। `GROK_TRANSLATE_SANDBOX=read-only` OS सैंडबॉक्स
  को अनिवार्य बनाता है, और यदि मशीन इसका पालन न कर सके तो शुरुआत विफल हो जाती है।
- कोटा साप्ताहिक है और Chat, Imagine तथा Voice के साथ साझा होता है; इसे पढ़ने
  के लिए कोई कमांड उपलब्ध नहीं है: कोई बैच बिना संकेत दिए संवाद संबंधी उपयोग
  को कम कर सकता है।
- वेरिएबल: `GROK_BIN`, `GROK_HOME` (CLI डायरेक्टरी, डिफ़ॉल्ट `~/.grok`),
  `GROK_TIMEOUT` (डिफ़ॉल्ट 900), `GROK_TRANSLATE_SANDBOX`।

### Google सदस्यता पर: `--use_antigravity`

`agy`, आधिकारिक Antigravity CLI, के साथ भी यही सिद्धांत लागू होता है:
Google AI Pro या Ultra के भुगतानकर्ता के लिए अनुवाद की गणना टोकन के आधार पर
बिल किए जाने के बजाय सदस्यता कोटा में होती है। इस कोटा तक पहुँचने का यही
एकमात्र रास्ता है: Gemini CLI 18 जून 2026 से इन खातों को सेवा नहीं देता
([घोषणा](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)),
और Antigravity SDK केवल API कुंजी या Google Cloud प्रोजेक्ट स्वीकार करता है।

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **कोई सशुल्क मार्ग खुला नहीं रहता।** agy को आपके परिवेश से केवल वेरिएबल
  की एक बंद सूची मिलती है — `PATH`, भाषा और समय क्षेत्र, टर्मिनल,
  पहचान, प्रॉक्सी और प्रमाणपत्र, सत्र बस — और कोई कुंजी नहीं: इसके कई वेरिएबल
  बिना कुछ दिखाए कॉल को दूसरे मार्ग पर भेज देते हैं (मापन में: एक दस्तावेज़
  को तृतीय-पक्ष गेटवे पर भेजता है, दूसरा बिल किए गए Google Cloud प्रोजेक्ट
  पर), और हर पुनरीक्षण में निषेध सूची से कोई न कोई छूट जाता था। किसी भी खंड
  से पहले, `agy -p /config`, जिसमें कोई कोटा खर्च नहीं होता, को यह दिखाना
  आवश्यक है कि सशुल्क AI क्रेडिट अक्षम हैं और कोई API कुंजी या Google Cloud
  प्रोजेक्ट नहीं है — सेटिंग का अनुपस्थित होना अस्वीकृति माना जाता है —,
  अन्यथा कुछ भी अनूदित नहीं होता; इसके बाद प्रत्येक कॉल के लॉग को सदस्यता
  (`authMethod=consumer`) प्रमाणित करनी होती है, अन्यथा उत्तर अस्वीकार कर दिया जाता है।
- **परिसीमन।** प्रत्येक कॉल एक निजी और अस्थायी होम डायरेक्टरी में, बिना किसी
  टूल वाले अनुवाद एजेंट के साथ चलती है: आपकी सेटिंग, नियम, प्लगइन, MCP सर्वर
  और agy हुक उसमें प्रवेश नहीं करते, आपके इतिहास में कुछ नहीं जुड़ता, और
  कनेक्शन कीरिंग में ही रहता है, जिसे aipmt कभी नहीं पढ़ता। एजेंट न मिलने पर
  agy बिना सूचना दिए अपने कोडिंग एजेंट और उसके टूल पर लौट जाता है: लॉग की
  एक पूरी पंक्ति को सही एजेंट की पुष्टि करनी होती है — उस संदेश को उद्धृत
  करने वाला दस्तावेज़ उसका स्थान नहीं ले सकता —, अन्यथा अस्वीकृति होती है।
- **प्लेटफ़ॉर्म**: Linux, ऐसे सत्र में जिसमें कीरिंग हो (D-Bus सत्र बस,
  Secret Service); macOS स्वीकार्य है, हालाँकि उस पर मापन नहीं किया गया है।
  Windows पर अस्वीकृत, जहाँ agy प्रत्येक कॉल को अलग करने वाले वेरिएबल नहीं
  पढ़ता, और सत्र बस रहित Linux पर भी — SSH सत्र, कंटेनर, सर्वर: वहाँ agy
  अपना टोकन `~/.gemini` की फ़ाइल में रखता है, जिसे पृथक्करण छिपा देता है।
  अस्वीकृति किसी भी शुरुआत से पहले कारण सहित होती है, ताकि कनेक्शन कोड के
  लिए एक मिनट प्रतीक्षा न करनी पड़े।
- **मॉडल**: `agy models` के मॉडल। Gemini मॉडल अपने नाम में प्रयास स्तर
  रखते हैं (`gemini-3.8-flash-medium`…): प्रत्यय रहित नाम कॉल से पहले अस्वीकार कर दिया
  जाता है, और `--reasoning_effort` का कोई प्रभाव नहीं होता। डिफ़ॉल्ट रूप से
  `gemini-3.8-flash-medium`, और `--eco` में `gemini-3.7-flash-low`; जिन अभियानों ने
  इन्हें निर्धारित किया, उनका वर्णन [विस्तृत माप](#विस्तृत-माप) में है। Claude
  और GPT-OSS का अपना, बहुत छोटा कोटा है: मापी गई प्रत्येक कॉल पर 5 घंटे की
  विंडो का लगभग 1 %, जबकि Flash में 0.05 %।
- **कोटा**: प्रत्येक समूह के लिए 5 घंटे की और एक साप्ताहिक विंडो, टोकन लागत
  के अनुपात में। लेखक के खाते पर मापा गया: प्रति दस लाख स्रोत वर्णों पर
  5 घंटे की विंडो के लगभग 16 अंक `gemini-3.8-flash-medium` में, 14 `gemini-3.7-flash-medium` में,
  और कम प्रयास पर 7 से 8 — इसलिए 40 000 वर्णों वाले README की लागत आधे अंक
  से थोड़ी अधिक होती है। साप्ताहिक सीमा स्तर पर निर्भर करती है। पुनः प्रयास
  agy द्वारा पुनः प्रयास योग्य घोषित स्थितियों का अनुसरण करता है; अन्यथा
  समाप्त हुई विंडो पर कभी पुनः प्रयास नहीं होता: वह `/usage` में
  दिखाई गई रीसेट अवधि तक प्रत्येक फ़ाइल को विफल करती है।
- **API से धीमा**: मापों वाले सघन लेख पर, `gemini-3.8-flash-medium` में प्रति भाषा
  माध्यिका 3 मिनट 59 सेकंड और `gemini-3.7-flash-medium` में 3 मिनट 14 सेकंड, जबकि
  API के माध्यम से Gemini 3.7 Flash के लिए 1 मिनट 18 सेकंड।
- **व्यवधान**: Ctrl-C, या बंद किया गया टर्मिनल, agy को आपके कोटा पर अपना
  कार्य पूरा करते रहने देने के बजाय कमांड के साथ रोक देते हैं; Codex,
  Grok CLI और OpenCode के लिए भी यही लागू होता है। `nohup` के अंतर्गत,
  अनुवाद जारी रहता है।
- CI में अस्वीकृत (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर):
  कनेक्शन व्यक्तिगत कीरिंग में रहता है। रनर पर, `--use_gemini` के साथ
  `GOOGLE_API_KEY`।
- वेरिएबल: `AGY_BIN` (अन्यथा `PATH`, फिर `~/.local/bin/agy`),
  `AGY_TIMEOUT` (प्रति खंड सेकंड, शुरुआत सहित, डिफ़ॉल्ट 900)।

### Claude सदस्यता पर: `--use_claude_code`

यही सिद्धांत Claude Code के आधिकारिक CLI `claude` के साथ, `-p` मोड में भी लागू होता है: Claude Pro या Max के लिए भुगतान करने वालों हेतु अनुवाद की गणना प्रति token शुल्क के बजाय सदस्यता के quota से की जाती है। इसे उपयोग के अनुसार शुल्क लेने वाले Anthropic API `--use_claude` से भ्रमित न करें।

```bash
claude                                   # une fois : /login avec le compte de l'abonnement
aipmt --use_claude_code --file README.md --target_dir . --target_lang en
```

- **भुगतान वाला कोई मार्ग खुला नहीं रहता, और हर call इसे प्रमाणित करता है।** Claude Code को आपके environment से केवल variables की एक सीमित सूची मिलती है—न API key, न token, न cloud provider, न उस Claude Code session का कोई marker जहाँ से aipmt चलाया गया हो। पहले segment से पहले, `claude auth status` को Console key के बिना सदस्यता वाला connection दिखाना होगा और बिना quota खर्च किए `/usage` को इसकी पुष्टि करनी होगी; प्रत्येक call अपने initialization event में फिर इसकी पुष्टि करता है, अन्यथा response अस्वीकार कर दिया जाता है।
- **« extra usage » को अक्षम करें** (claude.ai, Settings → Usage), ताकि शून्य euro का दावा कायम रहे: सक्षम होने पर, quota window समाप्त होते ही यह उसकी जगह ले लेता है और कोई error दिखाए बिना शुल्क लगाता है। जैसे ही किसी call की quota report इसका संकेत देती है, aipmt अनुवाद रोक देता है, लेकिन वह call तब तक गिना जा चुका होता है।
- **आपके Claude Code sessions के साथ साझा quota।** हर call 5 घंटे और सप्ताह वाली windows का उपयोग बताता है; 80% से अधिक होने पर (`AIPMT_CLAUDE_MAX_UTILIZATION`) कोई अतिरिक्त segment शुरू नहीं किया जाता, ताकि आपके काम के लिए उपलब्ध quota समाप्त न हो।
- **अलगाव।** प्रत्येक call बिना किसी tool के, एक निजी और अस्थायी directory में, customization-रहित mode में चलता है: न आपके `CLAUDE.md`, न plugins, hooks, MCP servers या settings load होते हैं, और session से कुछ भी सहेजा नहीं जाता। Attachments बंद रहते हैं: आपके document में मौजूद `@chemin` केवल text बना रहता है और कोई file नहीं खोलता (मापा गया)।
- **Models**: default रूप से `sonnet`, `low` effort पर, और `--eco` में भी: इस मार्ग पर `--eco` से कोई अंतर नहीं पड़ता। उन्हीं documents पर मापने पर, `haiku` दोगुना धीमा है—यह ऐसा reasoning करता है जिसे रोका नहीं जा सकता—जबकि लागत केवल थोड़ी कम है, और `opus` biology की सामग्री अस्वीकार करता है (अगला बिंदु)। दोनों `--model` के माध्यम से उपलब्ध रहते हैं; ये aliases अपने परिवार के नवीनतम model का अनुसरण करते हैं। `fable` और `[1m]` variants अस्वीकार किए जाते हैं, क्योंकि वे भुगतान वाले credits का उपयोग करते हैं। `--reasoning_effort` effort निर्धारित करता है, जिससे अनुवाद को कोई लाभ नहीं मिलता: मापा गया reasoning शून्य या लगभग शून्य है।
- **Opus biology की कुछ सामग्री अस्वीकार करता है।** इसके safeguards, Sonnet की तुलना में अधिक कठोर हैं, और Anthropic का error message चेतावनी देता है कि वे « कभी-कभी biology research से जुड़े काम को चिह्नित कर सकते हैं »। मापन में: उत्पन्न किए गए 279 molecules पर एक संक्षिप्त निगरानी समाचार के कारण चौदहों भाषाओं में पूरा लेख अस्वीकार हो गया। कुछ भी नहीं लिखा जाता: aipmt अधूरा response अस्वीकार करता है, safeguards का उल्लेख करता है और `--model sonnet` की सलाह देता है।
- CI में (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर) और Windows पर अस्वीकार किया जाता है (मापा नहीं गया)।
- Variables: `AIPMT_CLAUDE_BIN` (अन्यथा `PATH`, फिर `~/.local/bin/claude`), `AIPMT_CLAUDE_TIMEOUT` (प्रति segment seconds, default 900), `AIPMT_CLAUDE_MAX_UTILIZATION` (default 0.8), `CLAUDE_CONFIG_DIR` (Claude Code account, project के `.env` से कभी नहीं लिया जाता); working directories `XDG_CACHE_HOME/aipmt/claude-code` के अंतर्गत (default `~/.cache`)।

**उपयोग की शर्तें: उत्तरदायित्व आपके account का है।** [Claude Code का कानूनी पृष्ठ](https://code.claude.com/docs/en/legal-and-compliance) « किसी अंतिम उपयोगकर्ता को अपनी Claude सदस्यता के साथ अपरिवर्तित Claude Code binary में sign in करने » से नहीं रोकता: aipmt यही करता है, जो आधिकारिक binary चलाता है और token कभी नहीं पढ़ता। लेकिन Anthropic « third-party developers को अपने users की ओर से Free, Pro या Max plan credentials के माध्यम से requests भेजने की अनुमति नहीं देता », third-party tools के लिए API key को प्राथमिकता देता है, « जिनमें open-source projects भी शामिल हैं », और उनके उपयोग को भुगतान वाले credits में गिनने का अधिकार सुरक्षित रखता है ([Claude सहायता](https://support.claude.com/en/articles/13189465-logging-in-to-your-claude-account))। वितरित किए गए ऐसे tool के मामले में, जो binary चलाता है, कोई text निर्णायक उत्तर नहीं देता।

**Data**: Free, Pro और Max accounts पर, privacy setting की अनुमति होने पर model training Claude Code पर भी लागू होती है ([data पृष्ठ](https://code.claude.com/docs/en/data-usage))। aipmt कोई local transcript नहीं रखता (`--no-session-persistence`)। इसके माध्यम से कोई गोपनीय सामग्री न भेजें।

### अपनी पसंद के provider तक: `--use_opencode`

[OpenCode](https://opencode.ai) एक open-source (MIT) coding agent है, जो अपने भीतर configure किए गए providers तक route करता है: API key, subscription, OpenCode Zen gateway (निःशुल्क models, account के बिना) या local model। यहाँ दो मार्गों, Zen और Ollama, को शुरू से अंत तक मापा गया है।

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` अनिवार्य है: इसके बिना OpenCode किसी free model पर लौट जाएगा, जिसकी बातचीत training के लिए उपयोग हो सकती है, और यह चुनाव आपकी ओर से नहीं किया जाता।

प्रत्येक call में अलगाव:

- आपकी configuration पर प्राथमिकता रखने वाली inline configuration एक `aipmt` agent परिभाषित करती है, जिसमें सभी tools अस्वीकार किए जाते हैं (`permission: { "*": "deny" }`), session sharing अक्षम रहता है, `--pure`, और कभी `--auto` नहीं;
- अस्थायी और खाली working directory, जिसमें `OPENCODE_DISABLE_PROJECT_CONFIG` और `OPENCODE_DISABLE_CLAUDE_CODE` निर्धारित हैं—इनके बिना OpenCode prompt में current directory का `AGENTS.md` और `~/.claude/CLAUDE.md` inject करता है। Global `~/.config/opencode/AGENTS.md` फिर भी inject होता है; OpenCode इसे हटाने की अनुमति नहीं देता;
- output contract: return code 0, कोई `error` event नहीं, कोई tool call नहीं, अंतिम step `stop` में, text खाली नहीं, और `aipmt` agent वास्तव में load हुआ हो—किसी अज्ञात `--agent` पर OpenCode विफल नहीं होता, बल्कि चुपचाप coding agent पर लौट जाता है;
- `aipmt` की कोई key pass नहीं की जाती, सिवाय `OPENCODE_API_KEY` के, जो स्वयं OpenCode की key है। Providers को OpenCode में configure किया जाता है, `aipmt` के `.env` में नहीं।

ध्यान देने योग्य बातें:

- Zen के free models बदलते रहते हैं, उनकी limits documented नहीं हैं, और उनकी बातचीत training के लिए उपयोग हो सकती है: public documentation के लिए उपयुक्त, private सामग्री के लिए नहीं।
- Local model को कम-से-कम 16 k tokens का context देना चाहिए, क्योंकि segments की लंबाई 16,000 characters तक होती है। Ollama अक्सर इसे 4,096 पर configure करता है: `PARAMETER num_ctx 32768` वाले `Modelfile` का उपयोग करें।
- `--eco` का कोई प्रभाव नहीं पड़ता; `--reasoning_effort` को OpenCode के `--variant` के रूप में ज्यों का त्यों pass किया जाता है।
- OpenCode प्रत्येक session को `~/.local/share/opencode/` में log करता है।
- Variables: `OPENCODE_BIN` (अन्यथा `PATH`, फिर `~/.opencode/bin/opencode`), `OPENCODE_TIMEOUT` (प्रति segment seconds, default 600)। `OPENCODE_CONFIG` को ज्यों का त्यों OpenCode को pass किया जाता है।

Ollama के माध्यम से local model का उदाहरण, `~/.config/opencode/opencode.json` में:

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

`reasoningEffort: "none"` उस reasoning को बंद करता है जिसे Ollama इन models पर default रूप से सक्रिय करता है और जिसे Modelfile अक्षम नहीं कर सकता। छह शब्दों के एक वाक्य पर मापन: option के बिना reasoning के 919 tokens और 68 seconds, इसके साथ 9 tokens।

### 400 से अधिक models तक: `--use_openrouter`

OpenRouter उपयोग के अनुसार शुल्क लेने वाला router है, जो एक ही credit से third parties द्वारा host किए गए models तक पहुँच देता है—इनमें वे खुले Chinese models भी शामिल हैं जिन्हें यहाँ कोई अन्य provider उपलब्ध नहीं कराता।

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` अनिवार्य है। किसी भी शुल्क से पहले चलाया गया preflight routing की दो विशेषताओं को संभालता है:

- **एक ही model को अलग-अलग limits वाले दर्जनों hosts उपलब्ध कराते हैं**—`z-ai/glm-5.3-flash` पर 23 hosts हैं, जिनमें एक की output limit 2,048 tokens है। Preflight `/api/v1/models/{modèle}/endpoints` पढ़ता है, 8,000 से कम output tokens या degraded status वाले hosts को हटाता है और शेष को `allow_fallbacks: false` से pin करता है।
- **Reasoning पर output rate के अनुसार शुल्क लगता है**—`z-ai/glm-5.2` के « OK » response पर 2 के मुकाबले 107 tokens। इसे default रूप से बंद रखा जाता है; जिन models में यह अनिवार्य है, उन्हें उनके द्वारा स्वीकार किया जाने वाला न्यूनतम effort मिलता है, क्योंकि catalog का default अनुवाद पूरा होने से पहले output को भर सकता है। `--reasoning_effort` की प्राथमिकता बनी रहती है।

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- Context window catalog से आती है। 16,400 tokens से कम वाला model किसी भी call से पहले अस्वीकार कर दिया जाता है: prompt और segment के लिए 8,400 तथा output के लिए न्यूनतम 8,000।
- Catalog में slug का न होना, catalog तक न पहुँच पाना या limit पूरी करने वाले host का अभाव command को रोक देता है।
- खाली output वाला `finish_reason=length` reasoning द्वारा खर्च किया गया budget है, truncation नहीं: message दोनों में अंतर स्पष्ट करता है।
- `--eco` का कोई प्रभाव नहीं पड़ता।
- Variables: `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>), `OPENROUTER_BASE_URL` (default `https://openrouter.ai/api/v1`, `https://` आवश्यक), `OPENROUTER_TIMEOUT` (default 900), `OPENROUTER_PREFLIGHT_TIMEOUT` (default 30)।

### अनुवाद संबंधी टिप्पणी

`--add_translation_note` एक टिप्पणी जोड़ता है—`bottom` (default), `top` (front matter के बाद) या `both` (`--note_position`) में—और इसका format `legacy` (bold paragraph, default) या `marker` (`--note_format`) होता है। `marker` format एक अदृश्य Markdown reference definition, `[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`, और उसके बाद एक bold quotation है: GitHub पर पढ़ने योग्य और build के समय remark plugin द्वारा उपयोग योग्य।

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## विस्तृत माप

सभी माप `aipmt` के साथ वास्तव में किए गए अनुवादों के हैं, चौदह भाषाओं में: en, es, de, it, pt, nl, pl, sv, ro, ja, ko, zh, ar, hi। **लिखी गईं** उन files की संख्या है जिन्हें guards ने pass होने दिया; **कोई अंतर नहीं** उन files की संख्या है जिनमें `scripts/compare_structure.py` ने कुछ नहीं पाया—sections, subtitles, links, अलग-अलग URLs, code blocks, inline codes, table rows, blockquotes और bold शब्दों की समान संख्या।

« कोई अंतर नहीं » का अर्थ « कुछ भी detect नहीं हुआ » है, « समान » नहीं: comparator elements की सामग्री पढ़े बिना उनकी संख्या गिनता है। यह न हटाए गए level 4 heading की सूचना देता है, न बदले गए inline code text की, न बदले गए flag की, न एक अतिरिक्त parenthesis के साथ render हुए internal link, `[texte]((#ancre))`, की, जो अब कहीं नहीं ले जाता—और यह भाषा का आकलन भी नहीं करता।

बीच में रोके गए दो अभियानों को अंक नहीं दिए गए: Grok का CLI session
बारह भाषाओं के बाद समाप्त हो गया (ग्यारह बिना अंतर के), और `qwen3.8-flash` को उसके

और 1 बिना अंतर के थे।

`--use_antigravity` और `--use_claude_code` पंक्तियों को स्थिर किए गए
संस्करण पर नहीं मापा गया, बल्कि 26 सितंबर को 1.14.0 के साथ प्रकाशित संस्करण पर मापा गया — और

अक्तूबर को उसी संस्करण पर मापा गया: 600 पंक्तियाँ, 257 inline code, 30 ब्लॉक-समापन, 85

### ये माप क्या नहीं हैं

- **संपूर्ण ranking नहीं**: केवल OpenRouter ही चार सौ से अधिक
  मॉडल उपलब्ध कराता है, जबकि लगभग पंद्रह को मापा गया है।
- **समय केवल संकेतात्मक हैं**: अभियान के अनुसार तीन से छह अनुवाद समानांतर चले,
  और किसी प्रदाता का throughput दिन भर बदलता रहता है।
- **समय-विशिष्ट अवलोकन हैं**: एक ही नाम के अंतर्गत मॉडल बदलते रहते हैं, और आपके
  दस्तावेज़ हमारे दस्तावेज़ नहीं हैं।

अपने दस्तावेज़ों पर माप दोहराने के लिए, फ़ाइल की स्थिर की गई प्रति पर:

```bash
python scripts/compare_structure.py reference.md out/reference-ja.md

```

## योगदान देना

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

दोनों पंक्तियाँ आवश्यक हैं: `pip install -e .` के बिना, `python -m aipmt`
`No module named aipmt` उत्तर देता है।

गुणवत्ता tooling वैकल्पिक है, पर अनुशंसित है:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```

repository के 28 अनुवाद (README और CHANGELOG, चौदह भाषाएँ)
`./regen_translations.sh --force` से दोबारा बनाए जाते हैं — डिफ़ॉल्ट ChatGPT सदस्यता पर Codex और `gpt-5.6-sol`,
चार समानांतर रूप से। `REGEN_PROVIDER` और
`REGEN_MODEL` मार्ग बदलते हैं: `antigravity` एक सदस्यता, यानी
Google की सदस्यता पर रहता है और बिना अपवाद के चलता है; सशुल्क API (`openai`, `gemini`,
`grok`, `openrouter`) को `REGEN_ALLOW_PAID_API=1` के बिना अस्वीकार किया जाता है;
`REGEN_JOB_TIMEOUT` प्रत्येक job को सीमित करता है (600 s, Codex और
Antigravity पर 1 800 s)। tooling का विवरण `CLAUDE.md` में है।
