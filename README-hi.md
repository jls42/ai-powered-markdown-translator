Markdown फ़ाइलों का एक भाषा से दूसरी भाषा में अनुवाद करता है और उनकी
संरचना सुरक्षित रखता है: कोड ब्लॉक, इनलाइन कोड, URL, एंकर, तालिकाएँ और फ़्रंट
मैटर। किसी मॉडल को कॉल करने के ग्यारह तरीके — पाँच API, उपयोग के आधार पर
शुल्क लिए बिना चार सदस्यताएँ, दो राउटर — और हर मॉडल वास्तव में क्या सुरक्षित
रखता है, इसका प्रकाशित मापन।

## एक नज़र में

- **प्रदाता तक पहुँचने के ग्यारह रास्ते**: OpenAI, Mistral, Claude, Gemini और Grok की API;
  उपयोग के आधार पर शुल्क लिए बिना ChatGPT (Codex), Grok, Google (Antigravity) और Claude (Claude
  Code) की सदस्यताएँ; OpenCode (ओपन सोर्स, मुफ़्त या स्थानीय) और OpenRouter
  (400 से अधिक मॉडल) राउटर।
- **कोई टोकन खोने से दस्तावेज़ नहीं बिगड़ता**: कोड ब्लॉक, इनलाइन कोड,
  URL, एंकर और उद्धरणों को कॉल से पहले टोकन से बदला जाता है और
  उत्तर मिलने पर जाँचा जाता है। एक भी टोकन गायब हो, तो फ़ाइल नहीं लिखी जाती।
- **लंबे दस्तावेज़**: मॉडल की संदर्भ विंडो के अनुसार खंडों में विभाजन।
- **`--news` मोड**: समाचार-समीक्षा लेखों के लिए अंग्रेज़ी उद्धरण सुरक्षित रखे जाते हैं और
  फ़्लैग हर भाषा के अनुसार सँभाले जाते हैं।
- **`--eco` मोड**: तेज़ और कम खर्चीले मॉडल।
- वैकल्पिक **अनुवाद टिप्पणी**, ऊपर, नीचे या दोनों जगह।

## स्थापना

```bash
pip install ai-powered-markdown-translator     # ou : pipx install ai-powered-markdown-translator
aipmt --help                                   # ou : python -m aipmt --help
```

Python 3.11 या इससे नया संस्करण। रिपॉज़िटरी से स्थापित करने के लिए,
[योगदान दें](#योगदान-दें) देखें।

## कॉन्फ़िगरेशन

कुंजियाँ तीन स्थानों से पढ़ी जाती हैं, सर्वोच्च से न्यूनतम प्राथमिकता के क्रम में; हर स्थान
केवल वही भरता है जो पिछले स्थान में खाली रह गया हो।

|     | कहाँ                                            | किसलिए                             |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | परिवेश चर                     | CI, कंटेनर, अस्थायी ओवरराइड |
| 2   | वर्तमान निर्देशिका (या किसी मूल निर्देशिका) की `.env` | किसी परियोजना की अपनी कुंजी            |
| 3   | `~/.config/aipmt/.env`                        | एक बार स्थापित करें, हर जगह लागू       |

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

`GOOGLE_API_KEY` की जगह `GEMINI_API_KEY` भी स्वीकार किया जाता है। उपयोगकर्ता
फ़ाइल `XDG_CONFIG_HOME` (केवल पूर्ण पथ) और Windows में `%APPDATA%`
का पालन करती है। कुंजी न मिलने पर, कमांड तीनों स्थानों की सूची दिखाता है।

**किसी परियोजना की `.env` न तो कॉल को दूसरी जगह भेज सकती है, न ही चलाया जाने वाला प्रोग्राम
चुन सकती है।** यह कुंजियाँ देती है, कभी गंतव्य या बाइनरी नहीं: इसमें
`_BASE_URL`, `_API_BASE`, `_ENDPOINT` या `_BIN` (`CODEX_BIN`,
`GROK_BIN`, `OPENCODE_BIN`, `AGY_BIN`), `GROK_HOME`, प्रॉक्सी (`HTTP_PROXY`,
`HTTPS_PROXY`, `ALL_PROXY`), प्रमाणपत्र भंडार (`SSL_CERT_FILE`,
`SSL_CERT_DIR`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`) और `XDG_CONFIG_HOME` /
`APPDATA` से जुड़े सभी चर चेतावनी के साथ अनदेखे किए जाते हैं। क्लोन की गई रिपॉज़िटरी को
आपकी कुंजी दूसरी जगह भेजने या पहले अनुवाद पर अपना प्रोग्राम चलवाने में
सक्षम नहीं होना चाहिए। यह फ़ाइल इंटरपोलेशन के बिना भी पढ़ी जाती है:
`NOM=${OPENAI_API_KEY}` इसमें कुंजी की नकल नहीं करता। ये चर
परिवेश में या `~/.config/aipmt/.env` में सेट करें।

वैकल्पिक चर: `XAI_BASE_URL` (डिफ़ॉल्ट `https://api.x.ai/v1`),
`CLAUDE_TIMEOUT` (प्रति कॉल सेकंड, डिफ़ॉल्ट 900), `CODEX_BIN`, `CODEX_TIMEOUT`
(डिफ़ॉल्ट 600), `GROK_BIN`, `GROK_HOME` (डिफ़ॉल्ट `~/.grok`), `GROK_TIMEOUT`
(डिफ़ॉल्ट 900), `GROK_TRANSLATE_SANDBOX`, `AGY_BIN`, `AGY_TIMEOUT` (डिफ़ॉल्ट 900),
`OPENCODE_BIN`, `OPENCODE_TIMEOUT` (डिफ़ॉल्ट 600), `OPENROUTER_BASE_URL`
(`https://` आवश्यक), `OPENROUTER_TIMEOUT` (डिफ़ॉल्ट 900),
`OPENROUTER_PREFLIGHT_TIMEOUT` (डिफ़ॉल्ट 30)। हर चर का विवरण संबंधित
प्रदाता के अनुभाग में दिया गया है।

## शुरुआत करें

```bash
# un fichier
aipmt --file document.md --target_dir out/ --source_lang fr --target_lang en

# un répertoire
aipmt --source_dir content/fr --target_dir content/en --source_lang fr --target_lang en

# un autre provider
aipmt --use_gemini --file document.md --target_dir out/ --target_lang ja
```

`document.md` का स्पेनिश में अनुवाद करने पर `--target_dir` में `document-es.md` मिलता है;
`--include_model` के साथ, `document-es-gpt-5.6-terra.md`। एक्सटेंशन हमेशा
`.md` बनता है — `article.mdx` से `article-en.md` बनता है — सिवाय
`--keep_filename` के साथ, जो मूल नाम बनाए रखता है। पहले से मौजूद अनुवाद
`--force` के बिना छोड़ दिया जाता है।

निकास कोड: सब कुछ सफल होने या छोड़ दिए जाने पर `0`, किसी फ़ाइल की
विफलता बाकी होने पर `1` (सूची त्रुटि आउटपुट पर), कॉन्फ़िगरेशन की समस्या होने पर `2`।
विफल फ़ाइल कभी नहीं लिखी जाती, भले ही लिखने की प्रक्रिया ही विफल हो:
सामग्री पहले पास की एक फ़ाइल में लिखी जाती है, फिर उसका नाम बदला जाता है। दोबारा चलाना पर्याप्त है।

  पहले ही खंड से चार इनलाइन कोड और

- **एक ही वाक्य के कारण मॉडल पूरे दस्तावेज़ को अस्वीकार कर सकता है।** Opus 5.5
  इस README का बिना किसी अंतर के अनुवाद करता है, लेकिन किसी भी समाचार-समीक्षा लेख का नहीं:
  जीवविज्ञान से जुड़ी एक छोटी ख़बर पर उसकी सुरक्षा व्यवस्थाएँ
  उत्तर रोक देती हैं। फ़ाइल नहीं लिखी जाती,

- **यह सुरक्षा जाल शीर्षकों, तालिकाओं, फ़्रंट मैटर या
  पाठ को नहीं सँभालता।** कोई मॉडल एक अनुभाग हटा दे, तो भी उपकरण
  उस फ़ाइल को बिना आपत्ति लिख देता है — Mistral के साथ ऐसा होता है। इन तत्वों को

  `scripts/compare_structure.py` खोए हुए अनुभाग का पता लगाता है, लेकिन बाद में।

  README पर ठीक काम करता है और बहुत सारे लिंक वाले लेख पर चूकता है, डच में
  भी।

## सभी विकल्प

## प्रदाता

### API के माध्यम से: OpenAI, Mistral, Claude, Gemini, Grok

```bash
aipmt --source_dir content/fr --target_dir content/en --target_lang en             # OpenAI, défaut
aipmt --use_mistral --source_dir content/fr --target_dir content/es --target_lang es
aipmt --use_claude  --source_dir content/fr --target_dir content/de --target_lang de
aipmt --use_gemini  --source_dir content/fr --target_dir content/ja --target_lang ja
aipmt --use_grok    --source_dir content/fr --target_dir content/pt --target_lang pt
```

`--eco` हर प्रदाता के किफ़ायती स्तर पर स्विच करता है।

| ----------- | -------------------------------------------------------------------- | ------------------------- |
| OpenAI      | `gpt-5.6-terra`                                                      | `gpt-5.6-luna`            |
| Claude      | `claude-sonnet-5-5`                                                  | `claude-haiku-5-5`        |
| Mistral     | `mistral-large-latest`                                               | `mistral-small-latest`    |
| Gemini      | `gemini-3.7-flash`                                                   | `gemini-3.1-flash-lite`   |
| Codex       | `gpt-6.1-sol` (`--model` के माध्यम से `gpt-5.6-sol`, `terra` और `luna` भी) | `gpt-5.6-luna`            |
| Grok API    | `grok-4.6`                                                           | `grok-4.3`                |

### ChatGPT सदस्यता पर: `--use_codex`

आधिकारिक Codex CLI को संचालित करता है: अनुवाद की खपत ChatGPT सदस्यता के
कोटे से काटी जाती है, बिना API कुंजी या उपयोग के अनुसार बिलिंग के।

```bash
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo), ou : npm install -g @openai/codex
codex login
aipmt --use_codex --eco --file README.md --target_dir . --target_lang it
```

- बाइनरी पहले `CODEX_BIN` में, फिर `PATH` में, फिर
  `openai-codex-cli-bin` पैकेज में खोजी जाती है। `~/.codex/auth.json` कभी नहीं पढ़ा जाता।
- `OPENAI_API_KEY` और `CODEX_API_KEY` को उपप्रक्रिया के परिवेश से
  हटा दिया जाता है: किसी कुंजी की मौजूदगी कभी API पर स्विच नहीं कराती।
- हर खंड में 5 घंटे की अवधि का कम से कम एक « संदेश » खर्च होता है — यदि
  उसका सत्यापन विफल हो और फिर प्रयास किया जाए तो दो। OpenAI के अनुमान के
  अनुसार, Plus योजना पर `gpt-5.6-luna` (`--eco`) के लिए 250-2 000 संदेश/5 h और
  `gpt-5.6-sol` के लिए 10-100 संदेश मिलते हैं।
- `--model gpt-5.6-sol`, जो 1.16.3 तक डिफ़ॉल्ट था, `--model gpt-5.6-terra`
  और `--model gpt-5.6-luna` भी सदस्यता के माध्यम से चलते हैं।
- सर्वर से आया 429 फ़ाइल को खोने नहीं देता: Codex अपने आप फिर जुड़ता है,
  aipmt बारी पूरी होने की प्रतीक्षा करता है, और यदि अंत में भी 429 बना रहे, तो खंड का
  दोबारा प्रयास पहले 30 और फिर 60 सेकंड बाद होता है। जिस मॉडल की खाते को अनुमति नहीं है, वह 400 त्रुटि देता है: « ChatGPT खाते के साथ Codex का उपयोग करते समय यह मॉडल
  समर्थित नहीं है »।
- API से धीमा है, और दस्तावेज़ बड़ा होने पर अंतर बढ़ता है: इस README पर,
  `gpt-5.6-sol` के साथ प्रति भाषा माध्यिका समय 6 min 46 s है, जबकि
  `gemini-3.7-flash` के लिए 36 s है।
- CI में अस्वीकार किया जाता है (`CI` या `GITHUB_ACTIONS` सेट होने पर): सदस्यता का प्रमाणीकरण
  एक व्यक्तिगत सत्र फ़ाइल से होता है, जिसका साझा रनर पर होना
  उचित नहीं है।
- चर: `CODEX_BIN`, `CODEX_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 600)।

### Grok सदस्यता पर: `--use_grok_cli`

आधिकारिक Grok Build CLI के साथ भी यही सिद्धांत लागू होता है, SuperGrok या
X Premium+ सदस्यता पर।

```bash
curl -fsSL https://x.ai/cli/install.sh | bash
grok login                                      # ou : grok login --device-code
aipmt --use_grok_cli --file README.md --target_dir . --target_lang pl
```

- **Codex की तुलना में कमज़ोर पृथक्करण।** Grok का ऑपरेटिंग सिस्टम सैंडबॉक्स
  कई हालिया Linux मशीनों पर लागू नहीं होता (AppArmor, कंटेनर रनटाइम के
  सॉकेट), और जो प्रोफ़ाइल लागू नहीं हो सकती, वह बिना सूचना दिए
  पृथक्करण के बिना शुरू हो जाती है। इसलिए स्क्रिप्ट डिफ़ॉल्ट रूप से कोई प्रोफ़ाइल नहीं माँगती, इसकी सूचना देती है, और
  CLI के `--deny` नियमों पर निर्भर करती है, जिनमें सभी मामलों पर लागू होने वाला `*` भी है — यही एकमात्र
  परत है जो चुपचाप सुरक्षा हटाने के बजाय शुरू होने से इनकार करती है।
  `GROK_TRANSLATE_SANDBOX=read-only` ऑपरेटिंग सिस्टम सैंडबॉक्स को अनिवार्य बनाता है, और यदि
  मशीन इसे लागू नहीं कर सकती तो शुरुआत विफल हो जाती है।
- कोटा साप्ताहिक है, Chat, Imagine और Voice के साथ साझा है, और उसे
  पढ़ने के लिए कोई कमांड उपलब्ध नहीं है: एक बैच बिना किसी संकेत के बातचीत
  के लिए उपलब्ध कोटे को खर्च कर सकता है।
- चर: `GROK_BIN`, `GROK_HOME` (CLI की डायरेक्टरी, डिफ़ॉल्ट `~/.grok`),
  `GROK_TIMEOUT` (डिफ़ॉल्ट 900), `GROK_TRANSLATE_SANDBOX`।

### Google सदस्यता पर: `--use_antigravity`

Antigravity के आधिकारिक CLI `agy` के साथ भी यही सिद्धांत लागू होता है: Google
AI Pro या Ultra के लिए भुगतान करने वालों के अनुवाद की खपत प्रति टोकन बिलिंग के बजाय
सदस्यता के कोटे से काटी जाती है। इस कोटे तक पहुँचने का यही एकमात्र रास्ता है: Gemini CLI
18 जून 2026 से इन खातों को सेवा नहीं देता
([घोषणा](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)),
और Antigravity का SDK केवल API कुंजी या Google Cloud परियोजना स्वीकार करता है।

```bash
# agy 1.2.11 ou plus récent : https://antigravity.google/docs/cli/install/
agy                                  # une fois : se connecter avec le compte de l'abonnement
aipmt --use_antigravity --file README.md --target_dir . --target_lang en
agy -p /usage --output-format json   # quota restant, sans en consommer
```

- **भुगतान वाला कोई रास्ता खुला नहीं रहता।** agy को आपके
  परिवेश से केवल चरों की एक निश्चित सूची मिलती है — `PATH`, भाषा और समय क्षेत्र,
  टर्मिनल, पहचान, प्रॉक्सी और प्रमाणपत्र, सत्र बस — और कोई कुंजी नहीं:
  इसके कई चर बिना सूचना दिए कॉल का रास्ता बदल देते हैं (माप में पाया गया:
  एक दस्तावेज़ को किसी तीसरे पक्ष के गेटवे पर भेजता है, दूसरा उसे बिलिंग वाली
  Google Cloud परियोजना पर भेजता है), और निषेध सूची की हर समीक्षा में कुछ चर छूट जाते थे।
  हर खंड से पहले, `agy -p /config`, जिसमें कोई कोटा खर्च नहीं होता, को दिखाना चाहिए
  कि सशुल्क एआई क्रेडिट बंद हैं और कोई API कुंजी या Google Cloud परियोजना नहीं है — कोई
  सेटिंग अनुपस्थित होने पर भी अस्वीकार किया जाता है — अन्यथा कोई अनुवाद नहीं होता; इसके बाद हर
  कॉल के लॉग को सदस्यता (`authMethod=consumer`) का प्रमाण देना चाहिए, अन्यथा
  उत्तर अस्वीकार कर दिया जाता है।
- **पृथक्करण।** हर कॉल एक निजी, अस्थायी होम डायरेक्टरी में
  बिना टूल वाले अनुवाद एजेंट के साथ चलती है: आपकी सेटिंग, नियम,
  प्लगइन, MCP सर्वर और agy हुक उसमें नहीं आते, आपके इतिहास में कुछ नहीं
  जुड़ता, और लॉगिन की जानकारी कीरिंग में रहती है, जिसे aipmt कभी नहीं पढ़ता।
  एजेंट न मिलने पर agy बिना सूचना दिए अपने कोडिंग एजेंट
  और उसके टूल पर लौट जाता है: लॉग की एक पूरी पंक्ति को सही एजेंट की पुष्टि करनी चाहिए — इस
  संदेश का उल्लेख करने वाला दस्तावेज़ उसका विकल्प नहीं है — अन्यथा अस्वीकार कर दिया जाता है।
- **प्लेटफ़ॉर्म**: Linux, ऐसे सत्र में जिसमें कीरिंग हो (D-Bus सत्र
  बस, Secret Service); macOS भी स्वीकार किया जाता है, हालाँकि उस पर माप नहीं किया गया है। Windows
  पर अस्वीकार किया जाता है, जहाँ agy हर कॉल को अलग करने वाले चर नहीं पढ़ता, और
  बिना सत्र बस वाले Linux पर भी — SSH सत्र, कंटेनर, सर्वर: वहाँ agy
  अपना टोकन `~/.gemini` की एक फ़ाइल में रखता है, जिसे पृथक्करण छिपा देता है। अस्वीकृति
  किसी भी शुरुआत से पहले, कारण के साथ आती है, जिससे लॉगिन कोड के लिए
  एक मिनट प्रतीक्षा नहीं करनी पड़ती।
- **मॉडल**: `agy models` वाले। Gemini मॉडल के नाम में ही प्रयास का स्तर होता है
  (`gemini-3.8-flash-medium`…): प्रत्यय के बिना नाम कॉल से पहले ही अस्वीकार कर दिया जाता है,
  और `--reasoning_effort` का कोई प्रभाव नहीं होता। डिफ़ॉल्ट रूप से `gemini-3.8-flash-medium`,
  और `--eco` में `gemini-3.7-flash-low`; इन्हें निर्धारित करने वाले परीक्षण अभियानों का
  विवरण [विस्तृत माप](#विस्तृत-माप) में दिया गया है। Claude और GPT-OSS
  का अपना कोटा है, जो बहुत छोटा है: मापी गई हर कॉल पर 5 घंटे की अवधि का
  लगभग 1 %, जबकि Flash में 0,05 %।
- **कोटा**: हर समूह के लिए, 5 घंटे की एक अवधि और एक साप्ताहिक अवधि,
  टोकन की लागत के अनुपात में। लेखक के खाते पर किए गए माप के अनुसार: प्रति
  दस लाख स्रोत वर्णों पर 5 घंटे की अवधि के लगभग 16 अंक
  `gemini-3.8-flash-medium` में, 14 अंक `gemini-3.7-flash-medium` में और 7 से 8 अंक
  कम प्रयास पर — इसलिए 40 000 वर्णों वाले README की खपत आधे अंक से थोड़ी
  अधिक होती है। साप्ताहिक सीमा सदस्यता के स्तर पर निर्भर करती है। दोबारा प्रयास
  agy की घोषणा के अनुसार होता है कि क्या पुनः प्रयास योग्य है; ऐसी घोषणा न होने पर, समाप्त कोटे वाली अवधि में कभी
  दोबारा प्रयास नहीं किया जाता: `/usage` में दिखाए गए रीसेट होने तक
  हर फ़ाइल विफल हो जाती है।
- **API से धीमा**: माप वाले सघन लेख पर, प्रति भाषा
  माध्यिका समय `gemini-3.8-flash-medium` में 3 min 59 s और
  `gemini-3.7-flash-medium` में 3 min 14 s है, जबकि API के माध्यम से Gemini 3.7 Flash के लिए 1 min 18 s है।
- **बीच में रोकना**: Ctrl-C या टर्मिनल बंद करने पर agy भी
  कमांड के साथ रुक जाता है, ताकि वह आपके कोटे पर अपनी बारी पूरी करता न रहे; यही
  Codex, Grok CLI और OpenCode पर भी लागू होता है। `nohup` के अंतर्गत अनुवाद जारी रहता है।
- CI में अस्वीकार किया जाता है (`CI` या `GITHUB_ACTIONS` सेट होने पर): लॉगिन की जानकारी
  व्यक्तिगत कीरिंग में रहती है। रनर पर, `GOOGLE_API_KEY` के साथ `--use_gemini` का उपयोग करें।
- चर: `AGY_BIN` (अन्यथा `PATH`, फिर `~/.local/bin/agy`),
  `AGY_TIMEOUT` (प्रति खंड सेकंड, शुरुआत का समय शामिल, डिफ़ॉल्ट 900)।

**उपयोग की शर्तें: ज़िम्मेदारी आपके खाते की है।**
[Antigravity की शर्तें](https://antigravity.google/terms) (धारा 6) और उसके
[अक्सर पूछे जाने वाले प्रश्न](https://antigravity.google/docs/faq/), Antigravity लॉगिन का उपयोग करके
किसी तीसरे पक्ष के सॉफ़्टवेयर के माध्यम से सेवा तक पहुँचने पर रोक लगाते हैं — इनमें Claude Code,
OpenClaw और OpenCode का उल्लेख है — और ऐसा करने पर खाता निलंबित हो सकता है। aipmt
टोकन को न पढ़ता है, न दोबारा इस्तेमाल करता है: यह आधिकारिक बाइनरी को
[हेडलेस मोड](https://antigravity.google/docs/cli/headless/) में चलाता है, जिसे Google
स्क्रिप्ट और CI के लिए दस्तावेज़ित करता है। Google के एक सदस्य ने अपने काम के लिए स्थानीय स्क्रिप्ट से
`agy -p` चलाने को « मानक » माना है
([आधिकारिक फ़ोरम, 25 सितंबर 2026, गैर-बाध्यकारी उत्तर](https://discuss.ai.google.dev/t/is-using-the-official-agy-cli-through-a-local-mcp-server-with-third-party-ai-agents-permitted/184829));
इस तरह वितरित किए जाने वाले टूल के मामले पर कोई पाठ स्पष्ट निर्णय नहीं देता।

**केवल सार्वजनिक दस्तावेज़।** इन्हीं शर्तों की धारा 5 के अनुसार,
आदान-प्रदान — प्रॉम्प्ट, उत्तर, मेटाडेटा — का उपयोग Google के
उत्पादों और मशीन लर्निंग को बेहतर बनाने के लिए हो सकता है, और उन्हें
मनुष्य पढ़ सकते हैं; यह सशुल्क सदस्यता पर भी लागू होता है। इससे बाहर होने के लिए
`enableTelemetry` सेटिंग का उपयोग करना पड़ता है, जिसके प्रभाव का दस्तावेज़ीकरण नहीं है और जिसे aipmt सेट नहीं करता; आपकी
agy सेटिंग उसके पृथक्करण में साथ नहीं आतीं। इसमें कोई गोपनीय सामग्री न भेजें।
### Claude सदस्यता पर : `--use_claude_code`

यही सिद्धांत Claude Code के आधिकारिक CLI, `claude`, पर `-p` मोड में भी लागू होता है : जो
Claude Pro या Max के लिए भुगतान करते हैं, उनके लिए अनुवाद का उपयोग
सदस्यता के कोटे से काटा जाता है, टोकन के हिसाब से शुल्क नहीं लिया जाता। इसे
Anthropic के उपयोग के आधार पर शुल्क लेने वाले API, `--use_claude`, से न मिलाएँ।

```bash
claude                                   # une fois : /login avec le compte de l'abonnement
aipmt --use_claude_code --file README.md --target_dir . --target_lang en
```

- **सशुल्क उपयोग का कोई रास्ता खुला नहीं रहता, और हर कॉल इसकी पुष्टि करती है।** Claude
  Code को आपके परिवेश से केवल चर की एक निश्चित सूची मिलती है — न
  API कुंजी, न टोकन, न क्लाउड प्रदाता, न ही उस Claude Code सत्र का कोई संकेत
  जिससे aipmt चलाया गया हो। पहले खंड से पूर्व, `claude auth status` को
  Console कुंजी के बिना सदस्यता से जुड़ा प्रमाणीकरण दिखाना चाहिए, और `/usage`, जो
  कोई कोटा खर्च नहीं करता, को इसकी पुष्टि करनी चाहिए ; प्रत्येक कॉल भी अपनी
  आरंभीकरण घटना में इसकी पुष्टि करती है, अन्यथा उत्तर अस्वीकार कर दिया जाता है।
- **« अतिरिक्त उपयोग » बंद करें** (claude.ai, सेटिंग्स → उपयोग), ताकि
  खर्च शून्य यूरो रहे : चालू होने पर यह समाप्त हो चुकी उपयोग अवधि के बाद काम संभाल लेता है और
  बिना कोई त्रुटि दिखाए शुल्क लेता है। जैसे ही किसी कॉल की कोटा रिपोर्ट इसका
  संकेत देती है, aipmt अनुवाद रोक देता है, लेकिन उस कॉल का शुल्क पहले ही गिना जा चुका होता है।
- **कोटा आपके Claude Code सत्रों के साथ साझा होता है।** प्रत्येक कॉल
  5 घंटे और साप्ताहिक उपयोग अवधि की खपत बताती है ; 80 % से अधिक होने पर
  (`AIPMT_CLAUDE_MAX_UTILIZATION`), कोई और खंड शुरू नहीं किया जाता, ताकि
  आपके काम के लिए आवश्यक कोटा समाप्त न हो।
- **पृथक्करण।** प्रत्येक कॉल बिना किसी उपकरण के, एक निजी और
  अस्थायी निर्देशिका में, बिना वैयक्तिकरण वाले मोड में चलती है : न आपके `CLAUDE.md`, न आपके प्लगइन,
  हुक, MCP सर्वर या सेटिंग्स लोड होते हैं, और सत्र से कुछ भी
  सुरक्षित नहीं रखा जाता। संलग्नक निष्क्रिय हैं : आपके दस्तावेज़ में कोई `@chemin`
  केवल पाठ रहता है और कोई फ़ाइल नहीं खोलता (परीक्षण में सत्यापित)।
- **मॉडल** : डिफ़ॉल्ट रूप से `sonnet`, प्रयास स्तर `low` पर, और `--eco` में भी :
  इस रास्ते पर `--eco` कुछ नहीं बदलता। समान दस्तावेज़ों पर किए गए परीक्षणों में, `haiku`
  दोगुना धीमा है — यह तर्क करता है और इसे रोकना संभव नहीं है — जबकि
  लागत केवल थोड़ी कम है, और `opus` जीवविज्ञान संबंधी सामग्री अस्वीकार करता है (अगला
  बिंदु)। दोनों `--model` के माध्यम से उपलब्ध रहते हैं ; ये उपनाम अपने
  परिवार के नवीनतम मॉडल का अनुसरण करते हैं। `fable` और `[1m]` संस्करण अस्वीकार किए जाते हैं,
  क्योंकि वे सशुल्क क्रेडिट का उपयोग करते हैं। `--reasoning_effort` प्रयास स्तर तय करता है,
  जिससे अनुवाद को कोई लाभ नहीं मिलता : मापी गई तर्क प्रक्रिया शून्य या लगभग शून्य है।
- **Opus जीवविज्ञान संबंधी कुछ सामग्री अस्वीकार करता है।** इसके सुरक्षा उपाय
  Sonnet से अधिक सख्त हैं, और Anthropic का त्रुटि संदेश चेतावनी देता है कि वे
  « कभी-कभी जीवविज्ञान अनुसंधान से जुड़े कार्यों को चिह्नित कर सकते हैं »। परीक्षण में :
  उत्पन्न किए गए 279 अणुओं पर एक संक्षिप्त समाचार के कारण लेख सभी चौदह
  भाषाओं में अस्वीकार हो गया। कुछ भी नहीं लिखा जाता : aipmt अधूरे उत्तर को अस्वीकार करता है,
  सुरक्षा उपायों का उल्लेख करता है और `--model sonnet` का सुझाव देता है।
- CI में (`CI` या `GITHUB_ACTIONS` निर्धारित होने पर) और Windows पर अस्वीकार किया जाता है (परीक्षण नहीं किया गया)।
- चर : `AIPMT_CLAUDE_BIN` (अन्यथा `PATH`, फिर `~/.local/bin/claude`),
  `AIPMT_CLAUDE_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 900),
  `AIPMT_CLAUDE_MAX_UTILIZATION` (डिफ़ॉल्ट 0.8), `CLAUDE_CONFIG_DIR` (Claude Code का
  खाता, कभी भी परियोजना के `.env` से नहीं लिया जाता) ; कार्य निर्देशिकाएँ
  `XDG_CACHE_HOME/aipmt/claude-code` के अंतर्गत (डिफ़ॉल्ट `~/.cache`)।

**उपयोग की शर्तें : ज़िम्मेदारी आपके खाते की है।** 
[Claude Code का कानूनी पृष्ठ](https://code.claude.com/docs/en/legal-and-compliance)
« किसी अंतिम उपयोगकर्ता को अपनी Claude सदस्यता से अपरिवर्तित Claude Code बाइनरी
में साइन इन करने » से नहीं रोकता : aipmt यही करता है, वह
आधिकारिक बाइनरी चलाता है और कभी टोकन नहीं पढ़ता। लेकिन Anthropic « तीसरे पक्ष के
डेवलपर को […] अपने उपयोगकर्ताओं की ओर से Free, Pro या Max योजना के
प्रमाण-पत्रों के माध्यम से अनुरोध भेजने की अनुमति नहीं देता », तीसरे पक्ष के उपकरणों के लिए
API कुंजी को प्राथमिकता देता है, « जिनमें मुक्त स्रोत परियोजनाएँ भी शामिल हैं », और उनके
उपयोग को सशुल्क क्रेडिट से काटने का अधिकार सुरक्षित रखता है
([Claude सहायता](https://support.claude.com/en/articles/13189465-logging-in-to-your-claude-account))।
बाइनरी चलाने वाले वितरित उपकरण के मामले को कोई भी पाठ स्पष्ट रूप से तय नहीं करता।

**डेटा** : Free, Pro और Max खातों पर, जब गोपनीयता सेटिंग इसकी अनुमति देती है,
तो मॉडल प्रशिक्षण Claude Code पर भी लागू होता है
([डेटा पृष्ठ](https://code.claude.com/docs/en/data-usage))। aipmt कोई
स्थानीय प्रतिलेख नहीं रखता (`--no-session-persistence`)। इसके माध्यम से
कोई गोपनीय सामग्री न भेजें।

### अपनी पसंद के प्रदाता की ओर : `--use_opencode`

[OpenCode](https://opencode.ai) एक मुक्त स्रोत कोड एजेंट (MIT) है, जो
अपने भीतर कॉन्फ़िगर किए गए प्रदाताओं तक अनुरोध भेजता है : API कुंजी, सदस्यता,
OpenCode Zen गेटवे (मुफ़्त मॉडल, बिना खाते के) या स्थानीय मॉडल। यहाँ दो
रास्तों का शुरू से अंत तक परीक्षण किया गया है, Zen और Ollama।

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur

# gratuit, sans compte ni clé — données utilisables pour l'entraînement
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en
# local, hors ligne
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de
# sur un abonnement déjà payé
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

`--model` अनिवार्य है : इसके बिना, OpenCode किसी ऐसे मुफ़्त मॉडल पर लौट सकता है
जिसके संवाद प्रशिक्षण के लिए इस्तेमाल हो सकते हैं, और यह चुनाव आपकी ओर से
नहीं किया जाता।

हर कॉल पर पृथक्करण :

- आपकी सेटिंग्स पर प्राथमिकता रखने वाला एक इनलाइन विन्यास `aipmt` एजेंट निर्धारित करता है,
  जिसके सभी उपकरण निषिद्ध हैं (`permission: { "*": "deny" }`), सत्र साझा करना
  बंद है, `--pure`, कभी `--auto` नहीं ;
- अस्थायी और खाली कार्य निर्देशिका, `OPENCODE_DISABLE_PROJECT_CONFIG` और
  `OPENCODE_DISABLE_CLAUDE_CODE` निर्धारित — इनके बिना, OpenCode
  प्रॉम्प्ट में मौजूदा निर्देशिका का `AGENTS.md` और `~/.claude/CLAUDE.md` जोड़ देता है। वैश्विक
  `~/.config/opencode/AGENTS.md` फिर भी जोड़ा जाता है, OpenCode इसे
  हटाने की अनुमति नहीं देता ;
- आउटपुट अनुबंध : वापसी कोड 0, कोई `error` घटना नहीं, किसी उपकरण की
  कॉल नहीं, अंतिम चरण `stop` में, पाठ खाली नहीं, और `aipmt` एजेंट
  वास्तव में लोड हुआ हो — अज्ञात `--agent` से OpenCode विफल नहीं होता, वह
  चुपचाप कोडिंग एजेंट पर लौट जाता है ;
- `aipmt` की कोई कुंजी नहीं भेजी जाती, सिवाय `OPENCODE_API_KEY` के, जो
  स्वयं OpenCode की कुंजी है। प्रदाताओं का विन्यास OpenCode में किया जाता है, न कि
  `aipmt` के `.env` में।

जानने योग्य बातें :

- Zen के मुफ़्त मॉडल बदलते रहते हैं, उनकी सीमाएँ दस्तावेज़ित नहीं हैं, और
  उनके संवाद प्रशिक्षण के लिए इस्तेमाल हो सकते हैं : सार्वजनिक दस्तावेज़ों के लिए,
  निजी सामग्री के लिए नहीं।
- स्थानीय मॉडल में कम से कम 16 k टोकन का संदर्भ होना चाहिए, क्योंकि खंड
  16 000 अक्षरों तक लंबे होते हैं। Ollama अक्सर 4 096 कॉन्फ़िगर करता है :
  `PARAMETER num_ctx 32768` के साथ `Modelfile` का उपयोग करें।
- `--eco` का कोई प्रभाव नहीं पड़ता ; `--reasoning_effort` को OpenCode के
  `--variant` के रूप में ज्यों का त्यों भेजा जाता है।
- OpenCode प्रत्येक सत्र को `~/.local/share/opencode/` में दर्ज करता है।
- चर : `OPENCODE_BIN` (अन्यथा `PATH`, फिर `~/.opencode/bin/opencode`),
  `OPENCODE_TIMEOUT` (प्रति खंड सेकंड, डिफ़ॉल्ट 600)। `OPENCODE_CONFIG`
  ज्यों का त्यों OpenCode को भेजा जाता है।

Ollama के माध्यम से स्थानीय मॉडल का उदाहरण, `~/.config/opencode/opencode.json` में :

```bash
ollama pull gpt-oss:20b
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

`reasoningEffort: "none"` उस चिंतन को बंद करता है जिसे Ollama इन
मॉडल पर डिफ़ॉल्ट रूप से चालू करता है और जिसे Modelfile निष्क्रिय नहीं कर सकता। छह शब्दों के
एक वाक्य पर परीक्षण : विकल्प के बिना चिंतन के 919 टोकन और 68 सेकंड, इसके साथ 9 टोकन।

### 400 से अधिक मॉडल की ओर : `--use_openrouter`

OpenRouter उपयोग के आधार पर शुल्क लेने वाला राउटर है, जो एक ही क्रेडिट शेष के माध्यम से
तीसरे पक्ष द्वारा होस्ट किए गए मॉडल उपलब्ध कराता है — इनमें वे खुले चीनी मॉडल भी हैं जिन्हें यहाँ कोई
अन्य प्रदाता उपलब्ध नहीं कराता।

```bash
aipmt --use_openrouter --model z-ai/glm-5.2 --file README.md --target_dir . --target_lang en
```

`--model` अनिवार्य है। कोई भी शुल्क लगने से पहले चलने वाली प्रारंभिक जाँच
रूटिंग की दो विशेषताओं को संभालती है :

- **एक ही मॉडल दर्जनों होस्टिंग प्रदाताओं से मिलता है, जिनकी अधिकतम सीमाएँ
  अलग-अलग होती हैं** — `z-ai/glm-5.3-flash` पर 23 होस्टिंग प्रदाता हैं, जिनमें से एक की सीमा
  2 048 आउटपुट टोकन है। प्रारंभिक जाँच `/api/v1/models/{modèle}/endpoints` पढ़ती है,
  8 000 से कम आउटपुट टोकन वाले या खराब स्थिति वाले होस्टिंग प्रदाताओं को हटाती है, और
  शेष को `allow_fallbacks: false` से तय करती है।
- **तर्क प्रक्रिया का शुल्क आउटपुट की दर पर लिया जाता है** — `z-ai/glm-5.2` के
  « OK » उत्तर पर 2 के मुकाबले 107 टोकन। यह डिफ़ॉल्ट रूप से बंद रहती है ; जिन मॉडल में
  यह अनिवार्य है, उन्हें उनके द्वारा स्वीकार किया जाने वाला सबसे कम प्रयास स्तर दिया जाता है, क्योंकि
  सूची का डिफ़ॉल्ट स्तर अनुवाद पूरा होने से पहले आउटपुट सीमा भर सकता है।
  `--reasoning_effort` को प्राथमिकता मिलती है।

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

- संदर्भ सीमा सूची से ली जाती है। 16 400 से कम टोकन वाला मॉडल
  किसी भी कॉल से पहले अस्वीकार कर दिया जाता है : प्रॉम्प्ट और खंड के लिए 8 400, और आउटपुट के
  लिए कम से कम 8 000।
- सूची में स्लग का न होना, सूची तक पहुँच न होना या अधिकतम सीमा पूरी करने वाले
  होस्टिंग प्रदाता का न मिलना कमांड को रोक देता है।
- खाली आउटपुट के साथ `finish_reason=length` का अर्थ तर्क प्रक्रिया द्वारा बजट खर्च हो जाना है,
  न कि पाठ कट जाना : संदेश यह अंतर स्पष्ट करता है।
- `--eco` का कोई प्रभाव नहीं पड़ता।
- चर : `OPENROUTER_API_KEY` (<https://openrouter.ai/keys>),
  `OPENROUTER_BASE_URL` (डिफ़ॉल्ट `https://openrouter.ai/api/v1`, `https://`
  आवश्यक), `OPENROUTER_TIMEOUT` (डिफ़ॉल्ट 900), `OPENROUTER_PREFLIGHT_TIMEOUT`
  (डिफ़ॉल्ट 30)।

### अनुवाद टिप्पणी

`--add_translation_note` एक टिप्पणी जोड़ता है, `bottom` में (डिफ़ॉल्ट), `top` में (फ़्रंट मैटर के
बाद) या `both` में (`--note_position`), `legacy` प्रारूप में (मोटे अक्षरों वाला
अनुच्छेद, डिफ़ॉल्ट) या `marker` में (`--note_format`)। `marker` प्रारूप एक
अदृश्य Markdown संदर्भ परिभाषा है,
`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`,
जिसके बाद मोटे अक्षरों में एक उद्धरण आता है : GitHub पर पठनीय, और निर्माण के दौरान
remark प्लगइन द्वारा उपयोग योग्य।

```bash
aipmt --file article.mdx --target_lang en --add_translation_note --note_format marker --note_position top
```

## विस्तृत माप

सभी माप `aipmt` के साथ वास्तव में किए गए अनुवादों के हैं,
चौदह भाषाओं में : en, es, de, it, pt, nl, pl, sv, ro, ja, ko, zh, ar, hi।
**लिखी गई** उन फ़ाइलों को गिनता है जिन्हें सुरक्षा जाँचों ने स्वीकार किया ; **बिना
अंतर** उन फ़ाइलों को जहाँ `scripts/compare_structure.py` को कुछ नहीं मिलता — अनुभागों,
उपशीर्षकों, लिंक, अलग-अलग URL, कोड ब्लॉक, इनलाइन कोड,
तालिका पंक्तियों, उद्धरण ब्लॉक और मोटे अक्षरों वाले शब्दों की समान संख्या।

« बिना अंतर » का अर्थ « कुछ पता नहीं चला » है, « बिल्कुल समान » नहीं : तुलना उपकरण
सामग्री पढ़े बिना तत्वों को गिनता है। यह न तो स्तर 4 के हटाए गए शीर्षक की सूचना देता है,
न बदले गए इनलाइन कोड के पाठ की, न बदले गए ध्वज की,
न ऐसे आंतरिक लिंक की जिसमें एक अतिरिक्त कोष्ठक आ गया हो,
`[texte]((#ancre))`, जो अब कहीं नहीं पहुँचता — और यह
भाषा का मूल्यांकन भी नहीं करता।

जिसे प्रदाता ने तब से सुधार दिया है। OpenRouter की पंक्तियों का परीक्षण
`--use_openrouter` से पहले, राउटर की डिफ़ॉल्ट सेटिंग्स पर किया गया था ; उपलब्ध कराए गए प्रदाता के साथ
दोबारा परीक्षण करने पर `z-ai/glm-5.2` वही 14/14 देता है। आँकड़ों की
10 सितंबर को मौजूदा तुलना उपकरण से फिर गणना की गई : `qwen3.8-flash` और
`qwen3.7-flash` दोनों को पहली प्रकाशन तिथि की तुलना में एक-एक अतिरिक्त भाषा
मिली, बाकी अपरिवर्तित हैं।

`--use_antigravity` की पंक्तियों का परीक्षण 26 सितंबर को उसी
लेख पर, एक साथ चार अनुवाद चलाकर किया गया : `gemini-3.7-flash-medium` सुबह,
`gemini-3.8-flash-medium` दोपहर में। अंग्रेज़ी में, दोनों ने स्वयं
उद्धरणों के नीचे की फ़्रेंच अनुवाद वाली तीन पंक्तियाँ हटा दीं, बिना कोई ध्वज गढ़े,
और अंग्रेज़ी उद्धरण ज्यों के त्यों रहे : वैकल्पिक सफ़ाई को
कुछ नहीं करना पड़ा। `--eco` में (`gemini-3.7-flash-low`), केवल चार भाषाओं
(en, ja, ar, hi) पर : 4 में से 4 लिखी गईं, सभी बिना अंतर के, माध्यिका
1 min 52 s। उसी दिन समाचार संकलन के अधिक हाल के संस्करण,
25 सितंबर वाले (438 पंक्तियाँ, 2 अंग्रेज़ी उद्धरण), पर पुनः सत्यापन किया गया,
जिसका अनुवाद ब्लॉग के बाहर `gemini-3.7-flash-medium` से हुआ : 14 में से 14 लिखी गईं,
सभी बिना अंतर के, प्रति भाषा 87 से 128 s।

`--use_claude_code` की पंक्तियों का परीक्षण 26 सितंबर को उसी
लेख पर, एक साथ चार अनुवाद चलाकर, प्रयास स्तर `low` पर किया गया। `sonnet` के साथ,
अंग्रेज़ी उद्धरण सभी चौदह भाषाओं में ज्यों के त्यों रहे और अंग्रेज़ी में
मॉडल ने स्वयं फ़्रेंच अनुवाद वाली पंक्तियाँ हटा दीं, बिना कोई
ध्वज गढ़े। `opus` ने किसी भी भाषा में नहीं लिखा : प्रत्येक में उसके सुरक्षा उपायों ने
अंतिम खंड पर उत्तर रोक दिया, क्योंकि एक संक्षिप्त समाचार बंधन स्थल के लिए
उत्पन्न किए गए 279 अणुओं के बारे में था। अकेले भेजे जाने पर यह समाचार
« जैव » श्रेणी के अंतर्गत अस्वीकार होता है ; `sonnet` ने हर भाषा में उसका अनुवाद किया। `haiku`
चौदह भाषाओं में लिखता है ; तीन में (en, pl, ro), एक अनुभाग का शीर्षक
स्तर 2 से स्तर 1 पर चला जाता है। यह तर्क करता है और इसे रोकना संभव नहीं है — इसके
आउटपुट टोकन का 61 % —, इसलिए इसे `sonnet` के मुकाबले दोगुने से भी अधिक समय लगता है।

`claude-sonnet-5-5`, `claude-haiku-5-5` और `claude-haiku-4-5` की पंक्तियों का

एक साथ चार अनुवाद चलाए गए। Sonnet 5.5 अपना
चिंतन बंद करने की अनुमति नहीं देता : aipmt उसे उसके द्वारा स्वीकार की जाने वाली सबसे कम सेटिंग भेजता है, और उसके
उत्तर में चिंतन का कोई अंश नहीं होता। यह चौदह भाषाओं में बिना अंतर के और किसी
खंड को दोबारा किए बिना लिखता है ; अंग्रेज़ी में इसने स्वयं
फ़्रेंच अनुवाद वाली पंक्तियाँ हटा दीं, बिना कोई ध्वज गढ़े, और अंग्रेज़ी उद्धरण
हर जगह ज्यों के त्यों रहे। Haiku 5.5 का परीक्षण उसके अनुकूली चिंतन के साथ किया गया : चिंतन
बंद करने पर यह पूरे अनुच्छेद फ़्रेंच में छोड़ देता था, जिन्हें सुरक्षा जाँच अस्वीकार करती है —
14 में से 3 भाषाएँ लिखी गईं। दोनों Haiku उसी संक्षिप्त समाचार पर अटकते हैं : Haiku 5.5
जापानी, कोरियाई और चीनी में उसके शीर्षक का स्तर बदल देता है या उसे दो बार लिखता है,

जापानी में उसे फ़्रेंच में ही छोड़ देता है। चौदह भाषाओं में दोनों दस्तावेज़ों के लिए Haiku 4.5 की लागत

### ये मापन क्या नहीं हैं

- **संपूर्ण रैंकिंग नहीं**: अकेला OpenRouter चार सौ से अधिक
  मॉडल उपलब्ध कराता है, जबकि लगभग पंद्रह का मापन किया गया है।
- **समय केवल सांकेतिक हैं**: अभियान के अनुसार तीन से छह अनुवाद समानांतर में
  चलते हैं, और प्रदाता की प्रसंस्करण दर दिन भर बदलती रहती है।
- **निश्चित तारीखों के अवलोकन हैं**: एक ही नाम के अंतर्गत मॉडल बदलते रहते हैं, और आपके
  दस्तावेज़ हमारे दस्तावेज़ों से अलग हैं।

अपने दस्तावेज़ों पर मापन दोहराने के लिए, फ़ाइल की एक स्थिर प्रति पर:

```bash
aipmt --file reference.md --target_dir out/ --source_lang fr --target_lang ja --use_gemini --force
aipmt --file veille.mdx   --target_dir out/ --source_lang fr --target_lang ja --use_gemini --news --force
python scripts/compare_structure.py reference.md out/reference-ja.md
# « structure identique », ou la liste des écarts — sortie 0 si identique, 1 sinon
```

## योगदान दें

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt   # les dépendances, lock entièrement épinglé
pip install -e .                  # le paquet lui-même, en mode éditable
```

दोनों पंक्तियाँ आवश्यक हैं: `pip install -e .` के बिना, `python -m aipmt`
`No module named aipmt` उत्तर देता है।

गुणवत्ता जाँच के उपकरण, वैकल्पिक लेकिन अनुशंसित:

```bash
pipx install pre-commit               # hors venv — absent des requirements
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # mypy, SAST, pip-audit, tests avant chaque push
```

रिपॉज़िटरी के 28 अनुवाद (README और CHANGELOG, चौदह भाषाएँ)
`./regen_translations.sh --force` से दोबारा तैयार किए जाते हैं — डिफ़ॉल्ट रूप से ChatGPT सदस्यता पर Codex और `gpt-6.1-sol`,
चार समानांतर में। `REGEN_PROVIDER` और
`REGEN_MODEL` तरीका बदलते हैं: `antigravity` सदस्यता पर ही रहता है, जो
Google की है, और बिना किसी अपवाद की अनुमति के चल जाता है; शुल्क वाली API (`openai`, `gemini`,
`grok`, `openrouter`) को `REGEN_ALLOW_PAID_API=1` के बिना अस्वीकार कर दिया जाता है;
`REGEN_JOB_TIMEOUT` हर जॉब की समय सीमा तय करता है (600 s, Codex और
Antigravity पर 1 800 s)। उपकरणों का विवरण `CLAUDE.md` में है।

- **प्रकाशित करने से पहले दोबारा पढ़ें।** सुरक्षा उपाय कोड ब्लॉक,
  इनलाइन कोड, URL, एंकर और `--news` मोड के उद्धरणों को सुरक्षित रखते हैं — शीर्षकों,
  तालिकाओं, फ्रंट मैटर या आपके वाक्यों के अर्थ को नहीं।
- **आपके दस्तावेज़ चुने गए प्रदाता के पास भेजे जाते हैं**, उसकी उपयोग की
  शर्तों और डेटा नीति के अधीन। कुछ मुफ़्त मॉडल
  आपके संवादों का प्रशिक्षण के लिए पुनः उपयोग कर सकते हैं, और Antigravity की शर्तें
  Google को उनका पुनः उपयोग करने और मनुष्यों से उनकी समीक्षा करवाने की अनुमति देती हैं,
  सशुल्क सदस्यता में भी; स्थानीय मॉडल ही एकमात्र तरीका है जिसमें
  आपकी मशीन से कोई डेटा बाहर नहीं जाता।
- **API कॉल का शुल्क आपसे लिया जाता है।** यह प्रोग्राम खर्च की
  सीमा तय नहीं करता: लंबा दस्तावेज़, विफलता के बाद दोबारा प्रयास या अधिक तर्क करने वाला मॉडल
  ज़्यादा खर्च कराता है।
- **प्रकाशित मापन निश्चित तारीखों के अवलोकन हैं**, गारंटी नहीं।

उल्लिखित उत्पादों और कंपनियों के नाम उनके संबंधित स्वामियों के हैं।
यह परियोजना उनमें से किसी से संबद्ध नहीं है।
