**OpenAI**, **Mistral AI**, **Claude (Anthropic)**, **Google Gemini** और **Grok (xAI)** का उपयोग करने वाला Markdown फ़ाइल अनुवादक — API के माध्यम से, बिना उपयोग-आधारित बिलिंग के ChatGPT (Codex) या Grok सदस्यता के कोटे पर, अथवा ओपन-सोर्स एजेंट **OpenCode** के माध्यम से आपकी पसंद के प्रदाता के साथ: स्थानीय मॉडल (Ollama), निःशुल्क सेवा, सदस्यता (GitHub Copilot…) या कुंजी।

यह Python स्क्रिप्ट स्वरूपण, कोड ब्लॉक और front matter मेटाडेटा को सुरक्षित रखते हुए Markdown फ़ाइलों का स्रोत भाषा से लक्ष्य भाषा में अनुवाद करती है।

## मुख्य विशेषताएँ

- **Multi-Provider**: 5 API (OpenAI, Mistral, Claude, Gemini, Grok) + बिना उपयोग-आधारित बिलिंग वाले 2 सदस्यता CLI — Codex (ChatGPT) और Grok — + OpenCode (ओपन सोर्स, MIT), जो OpenCode में कॉन्फ़िगर किए गए किसी भी प्रदाता के साथ काम करता है, जिसमें स्थानीय मॉडल भी शामिल है
- **2026 के मॉडल**: GPT-5.6 Terra, Claude Sonnet 5, Gemini 3.7 Flash
- **किफ़ायती मोड**: अधिक तेज़ और कम लागत वाले मॉडल उपयोग करने के लिए `--eco` विकल्प
- **एकल फ़ाइल**: केवल एक फ़ाइल का अनुवाद करने के लिए `--file` विकल्प
- **बुद्धिमान विभाजन**: प्रत्येक मॉडल की token सीमाओं के अनुसार लंबे पाठों का प्रबंधन
- **कोड संरक्षण**: कोड ब्लॉक और inline code (`` `...` ``), दोनों सुरक्षित रखे जाते हैं
- **फ़ाइल का नाम**: मूल नाम बनाए रखने के लिए `--keep_filename` विकल्प
- **समाचार मोड**: समाचार लेखों में अंग्रेज़ी उद्धरणों को सुरक्षित रखने और झंडों को संभालने के लिए `--news` विकल्प
- **.env कॉन्फ़िगरेशन**: API कुंजियों के लिए `.env` फ़ाइल का समर्थन
- **अनुवाद टिप्पणी**: दस्तावेज़ के अंत में वैकल्पिक टिप्पणी जोड़ना

## स्थापना

### उपकरण का उपयोग करने के लिए

```bash
pip install ai-powered-markdown-translator
```

इसके बाद `aipmt` कमांड हर जगह उपलब्ध होती है। यदि Python scripts की
डायरेक्टरी आपके `PATH` में नहीं है, तो `python -m aipmt` ठीक वही
कार्य करता है। Python 3.10 या उससे नया संस्करण आवश्यक है।

अपने अन्य पैकेजों से अलग स्थापना के लिए:

```bash
pipx install ai-powered-markdown-translator
```

### परियोजना में योगदान करने के लिए

विकास के लिए clone किया गया repository आवश्यक रहता है: tests,
28 अनुवाद और गुणवत्ता संबंधी सभी उपकरण यहीं मौजूद हैं।

```bash
git clone https://github.com/jls42/ai-powered-markdown-translator.git
cd ai-powered-markdown-translator
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

`requirements.txt` एक **पूरी तरह pin किया गया lock** है, जो परीक्षित
वातावरण का सटीक प्रतिबिंब है। `pyproject.toml` में प्रकाशित सीमाएँ
जानबूझकर अधिक व्यापक हैं: वे आपके अन्य पैकेजों पर कोई बाध्यता नहीं लगातीं।

### गुणवत्ता उपकरण (वैकल्पिक, लेकिन अनुशंसित)

परियोजना गलत स्वरूपित, असुरक्षित या secret युक्त कोड को commit होने से रोकने के लिए [`pre-commit`](https://pre-commit.com) का उपयोग करती है। स्थापना:

```bash
pip install -r requirements-dev.txt   # detect-secrets, pip-audit, mypy, lizard
pre-commit install                    # hooks rapides à chaque commit
pre-commit install --hook-type pre-push  # hooks lourds avant chaque push
```

सक्रिय hooks: ruff (lint+format), shellcheck (bash), prettier (markdown/yaml/json), Lizard (जटिलता), detect-secrets (API कुंजियाँ), mypy (क्रमिक typing), Opengrep (SAST), pip-audit (dependencies के CVE), unittest। विवरण के लिए `CLAUDE.md` का _Quality / pre-commit_ अनुभाग देखें।

## कॉन्फ़िगरेशन

कुंजियाँ प्राथमिकता के उच्चतम से निम्नतम क्रम में **तीन स्थानों** पर खोजी जाती हैं।
प्रत्येक स्थान केवल उन मानों को भरता है जिन्हें पिछला स्थान खाली छोड़ देता है।

|     | कहाँ                                            | किसके लिए                             |
| --- | --------------------------------------------- | ------------------------------------- |
| 1   | Environment variables                     | CI, containers, अस्थायी override |
| 2   | वर्तमान डायरेक्टरी (या उसकी किसी parent डायरेक्टरी) की `.env` | किसी परियोजना-विशिष्ट कुंजी के लिए            |
| 3   | `~/.config/aipmt/.env`                        | **एक बार स्थापित करें, हर जगह उपयोग करें**   |

`pip install` के बाद सबसे सरल विकल्प तीसरा है:

```bash
mkdir -p ~/.config/aipmt
cat > ~/.config/aipmt/.env <<'EOF'
OPENAI_API_KEY=votre-clé-api-openai
XAI_API_KEY=votre-clé-api-xai
MISTRAL_API_KEY=votre-clé-api-mistral
ANTHROPIC_API_KEY=votre-clé-api-anthropic
GOOGLE_API_KEY=votre-clé-api-google
OPENROUTER_API_KEY=votre-clé-api-openrouter
EOF
chmod 600 ~/.config/aipmt/.env
```

जब variable किसी absolute path को निर्दिष्ट करता है, तो यह फ़ाइल `XDG_CONFIG_HOME` का अनुसरण करती है
(अन्यथा specification के निर्देशानुसार उसे अनदेखा किया जाता है), और Windows पर `%APPDATA%`
का उपयोग करती है।

दूसरा विकल्प तब उपयोगी रहता है जब किसी repository की अपनी कुंजी हो: उसके root में मौजूद `.env`
user configuration को बदले बिना उस पर प्राथमिकता लेता है। और environment में पहले से
परिभाषित variable इन दोनों पर प्राथमिकता लेता है:

```bash
export OPENAI_API_KEY='une-clé-le-temps-d-une-commande'
```

यदि कोई कुंजी नहीं मिलती, तो कमांड call trace प्रदर्शित नहीं करती: वह
तीनों स्थानों को उनके सटीक path सहित सूचीबद्ध करती है।

`GEMINI_API_KEY` को `GOOGLE_API_KEY` के विकल्प के रूप में स्वीकार किया जाता है (AI
Studio convention)। वैकल्पिक variables: `XAI_BASE_URL` (xAI endpoint, default
`https://api.x.ai/v1`), `CLAUDE_TIMEOUT` (प्रत्येक Anthropic call के लिए seconds, default
900), `CODEX_BIN` / `CODEX_TIMEOUT`, `GROK_BIN` / `GROK_HOME` / `GROK_TIMEOUT`,
`GROK_TRANSLATE_SANDBOX` (Grok CLI अनुभाग देखें), `OPENCODE_BIN` /
`OPENCODE_TIMEOUT` (OpenCode अनुभाग देखें) और `OPENROUTER_BASE_URL` /
`OPENROUTER_TIMEOUT` / `OPENROUTER_PREFLIGHT_TIMEOUT` (OpenRouter अनुभाग देखें)।
`regen_translations.sh` के लिए: `REGEN_PROVIDER` (default `codex`, सदस्यता पर),
`REGEN_MODEL`, `REGEN_ALLOW_PAID_API` (बिल योग्य API के लिए अनिवार्य override)
और `REGEN_JOB_TIMEOUT` (प्रत्येक job की सीमा, default 600 s, Codex पर 1 800 s)।

## उपयोग

### एक फ़ाइल का अनुवाद करना

```bash
aipmt --file 'document.md' --target_dir 'output/' --target_lang 'en'
```

### एक डायरेक्टरी का अनुवाद करना

```bash
# Avec OpenAI (défaut: gpt-5.6-terra)
aipmt --source_dir 'content/fr' --target_dir 'content/en' --source_lang 'fr' --target_lang 'en'

# Avec Mistral AI
aipmt --use_mistral --source_dir 'content/fr' --target_dir 'content/es' --target_lang 'es'

# Avec Claude
aipmt --use_claude --source_dir 'content/fr' --target_dir 'content/de' --target_lang 'de'

# Avec Gemini
aipmt --use_gemini --source_dir 'content/fr' --target_dir 'content/ja' --target_lang 'ja'

# Avec Codex (sur le quota de l'abonnement ChatGPT, sans facturation à l'usage)
aipmt --use_codex --eco --file 'README.md' --target_dir . --target_lang 'it'

# Avec Grok par l'API xAI (nécessite XAI_API_KEY, facturé à l'usage)
aipmt --use_grok --source_dir 'content/fr' --target_dir 'content/pt' --target_lang 'pt'

# Avec Grok sur le quota de l'abonnement Grok (nécessite `grok login`)
aipmt --use_grok_cli --eco --file 'README.md' --target_dir . --target_lang 'pl'

# Avec OpenRouter (routeur vers ~430 modèles ; --model obligatoire)
aipmt --use_openrouter --model 'z-ai/glm-5.2' --source_dir 'content/fr' --target_dir 'content/en' --source_lang 'fr' --target_lang 'en'

# Avec OpenCode (open source), vers le fournisseur de votre choix — ici un modèle local Ollama
aipmt --use_opencode --model ollama/qwen2.5:7b --file 'README.md' --target_dir . --target_lang 'nl'
```

### अपनी ChatGPT सदस्यता पर अनुवाद करना (`--use_codex`)

यह provider किसी API कुंजी का उपयोग नहीं करता: यह आधिकारिक Codex CLI को
non-interactive mode में संचालित करता है, इसलिए अनुवाद पहले से भुगतान की गई
ChatGPT सदस्यता (Plus, Pro, Business…) के कोटे से घटाया जाता है। इस उपयोग के लिए
OpenAI द्वारा प्रलेखित यह एकमात्र तरीका है — `~/.codex/auth.json` के tokens,
API Platform calls को authenticate नहीं करते और यह script उन्हें कभी पढ़ती भी नहीं है।

**पूर्वापेक्षाएँ:**

```bash
# Le binaire `codex`, au choix :
pip install openai-codex-cli-bin   # package officiel OpenAI (~250 Mo)
npm install -g @openai/codex       # ou l'installation npm globale

codex login                        # connexion avec le compte ChatGPT
```

Binary इस क्रम में खोजी जाती है: `CODEX_BIN` variable, `PATH`,
फिर Python package `openai-codex-cli-bin`। अंतिम विकल्प को जानबूझकर
`requirements.txt` में शामिल नहीं किया गया है: इसका आकार लगभग 250 MB है, जिसे एक
वैकल्पिक provider के लिए सभी users पर थोपना पड़ता।

**ध्यान देने योग्य बातें:**

- **किसी API कुंजी का उपयोग नहीं होता।** `OPENAI_API_KEY` और `CODEX_API_KEY` को
  subprocess के environment से हटा दिया जाता है, जिससे यह सुनिश्चित होता है कि
  `.env` में मौजूद कोई कुंजी अनुवाद को कभी उपयोग-आधारित billing पर नहीं ले जाएगी।
- **एक segment = 5 घंटे की plan window का एक « local message »**।
  quality model (`gpt-5.6-sol`, 10-100 messages/5 h) के बजाय
  `--eco` (model `gpt-5.6-luna`, Plus पर 250-2 000 messages/5 h) का उपयोग करें।
- **API call से धीमा**: एक पूरे README के लिए लगभग 45 s लगते हैं, जबकि
  सीधे उपयोग में केवल कुछ seconds लगते हैं।
- **CI में अस्वीकृत** (`CI` या `GITHUB_ACTIONS` परिभाषित होने पर): सदस्यता
  व्यक्तिगत session file से authenticate होती है, और उसे साझा runner पर रखने का अर्थ
  वहाँ ऐसी पुनः उपयोग योग्य identity रखना है जिसे उस runner पर चलने वाली हर चीज़
  उपयोग कर सकती है। इस स्थिति में API कुंजी का उपयोग करें।
- Environment variables: `CODEX_BIN` (binary का स्पष्ट path) और
  `CODEX_TIMEOUT` (प्रति segment seconds, default `600`)।

### अपनी Grok सदस्यता पर अनुवाद करना (`--use_grok_cli`)

`--use_codex` के समान सिद्धांत, आधिकारिक **Grok Build** CLI के साथ: अनुवाद का उपयोग
प्रति token bill किए जाने के बजाय Grok सदस्यता (SuperGrok / X Premium+) से घटाया जाता है।

```bash
curl -fsSL https://x.ai/cli/install.sh | bash   # le binaire `grok`
grok login                                      # ou `grok login --device-code`
```

**Confinement — उपयोग से पहले पढ़ें।** यह provider संरचनात्मक रूप से `--use_codex`
से **कमज़ोर** है, और यह एक सुविचारित निर्णय है:

- Codex `--sandbox read-only` में चलता है, जो system द्वारा लागू की गई boundary है।
- Grok sandbox कई नए Linux systems पर **लागू नहीं हो सकता**: Ubuntu
  24.04 से AppArmor unprivileged user namespaces को block करता है, और यदि
  `/run/podman`, `0700` में हो तो container runtime sockets की deny-list
  विफल हो जाती है। जबकि ऐसा **अंतर्निहित** profile जो लागू नहीं हो सकता,
  **बिना confinement के और चुपचाप** शुरू हो जाता है।
- इसलिए script default रूप से किसी profile का अनुरोध नहीं करती और **कभी चुपचाप
  fallback नहीं करती**: वह चेतावनी प्रदर्शित करती है। Confinement CLI के
  `--deny` नियमों (जिसमें catch-all `*` शामिल है) पर निर्भर करता है,
  जो मापी गई एकमात्र _fail-closed_ layer है — कोई अज्ञात नियम सुरक्षा को बिना बताए
  हटाने के बजाय startup को अस्वीकार कर देता है।
- OS sandbox को **अनिवार्य करने** के लिए: `GROK_TRANSLATE_SANDBOX=read-only`। यदि machine इसे लागू
  नहीं कर सकती, तो startup विफल हो जाएगा, और यही अपेक्षित व्यवहार है।

**कोटा**: Grok pool **साप्ताहिक है और Chat, Imagine तथा Voice के साथ साझा किया जाता है**,
और कोई command इसे पढ़ने की सुविधा नहीं देती। इसलिए batch processing आपके
संवादात्मक उपयोग को बिना किसी सूचना के कम कर सकती है — इसी कारण concurrency को 2 तक
सीमित रखा गया है और `regen_translations.sh` में चेतावनी दी जाती है।

अन्य variables: `GROK_BIN` (binary का path), `GROK_TIMEOUT` (default 900 s)।

28 अनुवादों को दोबारा generate करने के लिए:

```bash
# Défaut : Codex sur l'abonnement ChatGPT, modèle qualité gpt-5.6-sol, 0 € à l'usage
./regen_translations.sh --force

# Le modèle éco de Codex, si le volume l'impose
REGEN_MODEL=gpt-5.6-luna ./regen_translations.sh --force

# Sur le quota de l'abonnement Grok
REGEN_PROVIDER=grok_cli ./regen_translations.sh --force

# Une API facturée (openai, gemini, grok, openrouter) est REFUSÉE sans cette dérogation nommée
REGEN_PROVIDER=openai REGEN_ALLOW_PAID_API=1 ./regen_translations.sh --force

# Via OpenCode, vers le modèle de son choix (REGEN_MODEL obligatoire, 2 jobs en parallèle)
REGEN_PROVIDER=opencode REGEN_MODEL=ollama/qwen2.5:7b ./regen_translations.sh --force

# Via OpenRouter : API facturée, donc dérogation ET modèle obligatoires
REGEN_PROVIDER=openrouter REGEN_ALLOW_PAID_API=1 REGEN_MODEL=z-ai/glm-5.2 ./regen_translations.sh --force
```
### OpenCode के साथ, अपनी पसंद के प्रदाता के माध्यम से अनुवाद करें (`--use_opencode`)

[OpenCode](https://opencode.ai) terminal में चलने वाला एक **open source (MIT)** code agent है। यह model प्रदाता नहीं, बल्कि OpenCode में आपके द्वारा configure किए गए प्रदाताओं तक पहुँचने वाला एक **router** है: API key, subscription, OpenCode Zen gateway — जो **बिना account** के निःशुल्क models उपलब्ध कराता है — या कोई **local** model। यह provider `opencode run` को non-interactive mode में चलाता है और बिना किसी tool के call को केवल एक round-trip तक सीमित रखता है।

इनमें से दो तरीकों को यहाँ शुरू से अंत तक मापा गया है: **Zen gateway** और local **Ollama**। OpenCode द्वारा घोषित अन्य विकल्पों (GitHub Copilot, LM Studio, llama.cpp) को संरचनागत रूप से काम करना चाहिए, क्योंकि provider केवल OpenCode से संवाद करता है — लेकिन उनका परीक्षण नहीं किया गया है, और यह README केवल सत्यापित बातों का उल्लेख करता है।

```bash
curl -fsSL https://opencode.ai/install | bash   # ou : npm install -g opencode-ai
opencode models                                 # les modèles disponibles, au format provider/modèle
opencode auth login                             # facultatif : brancher un fournisseur ou un abonnement
```

`--model`, `provider/modèle` प्रारूप में, **अनिवार्य** है। OpenCode कोई प्रदाता नहीं है और आपकी ओर से कोई default नहीं चुना जाता: इसका अपना fallback एक निःशुल्क model होगा, जिसके exchanges का उपयोग training के लिए किया जा सकता है।

```bash
# Gratuit, sans compte ni clé (passerelle Zen ; données utilisables pour l'entraînement)
aipmt --use_opencode --model opencode/mimo-v2.5-free --file README.md --target_dir . --target_lang en

# Local, hors ligne, sans aucune clé (Ollama déclaré dans ~/.config/opencode/opencode.json)
aipmt --use_opencode --model ollama/qwen2.5:7b --file README.md --target_dir . --target_lang de

# Sur un abonnement déjà payé (après `opencode auth login`)
aipmt --use_opencode --model github-copilot/gpt-5 --file README.md --target_dir . --target_lang ja
```

**सीमाबद्धता — प्रत्येक call पर script क्या करती है:**

- आपकी configuration पर प्राथमिकता रखने वाली inline configuration (`OPENCODE_CONFIG_CONTENT`), एक `aipmt` agent निर्धारित करती है, जिसमें **सभी tools अस्वीकृत होते हैं** (`permission: { "*": "deny" }`): model न तो पढ़ सकता है, न लिख सकता है और न ही command चला सकता है — मापने पर पाया गया कि वह इसका प्रयास भी नहीं करता। Session sharing अक्षम रहती है, `--pure` बाहरी plugins को हटाता है, `--auto` को कभी नहीं।
- Call एक **खाली अस्थायी directory** में `OPENCODE_DISABLE_PROJECT_CONFIG` और `OPENCODE_DISABLE_CLAUDE_CODE` switches के साथ चलती है: इनके बिना OpenCode प्रत्येक prompt में वर्तमान directory की `AGENTS.md` और आपकी `~/.claude/CLAUDE.md` inject करता है — मापने पर, `AGENTS.md` में दी गई “हर उत्तर को BANANA पर समाप्त करें” instruction अनुवाद पर लागू हुई। हालाँकि `~/.config/opencode/AGENTS.md` के global rules लागू रहते हैं: OpenCode उन्हें हटाने की अनुमति नहीं देता।
- Output contract एक साथ ये सभी शर्तें माँगता है: return code 0, कोई `error` event नहीं, कोई tool call नहीं, `stop` में समाप्त हुआ अंतिम step, non-empty text और वास्तव में load किया गया agent — कोई अज्ञात `--agent` OpenCode को विफल नहीं करता, बल्कि वह **चुपचाप fallback** करके सक्रिय tools वाले coding agent पर लौट जाता है। यहाँ `exit 0` भी कुछ सिद्ध नहीं करता।
- Subprocess को **aipmt की कोई key नहीं भेजी जाती** (Codex और Grok जैसा ही filtering), केवल नामित अपवाद `OPENCODE_API_KEY`, अर्थात OpenCode की अपनी key (Zen, Go), को छोड़कर। प्रदाताओं को OpenCode (`opencode auth login`, `opencode.json`) में configure किया जाता है, aipmt के `.env` में नहीं।

**जानने योग्य बातें:**

- **Zen के निःशुल्क models “stealth” या contributor models हैं**, जो बदलते रहते हैं, जिनकी limits documented नहीं हैं और जिनके exchanges का उपयोग training के लिए हो सकता है: सार्वजनिक documentation के लिए उपयुक्त, निजी content के लिए अनुपयुक्त। मापा गया: `opencode/mimo-v2.5-free` इस README का एक pass में अनुवाद करता है; `opencode/big-pickle` धीमा है और उस पर दो simultaneous requests अनुत्तरित रहीं।
- **Local model में कम-से-कम 16 k context होना चाहिए** — segments अधिकतम 16 000 characters के होते हैं — जबकि Ollama अक्सर default रूप से 4 096 configure करता है। Ollama के साथ: `PARAMETER num_ctx 32768` वाला `Modelfile`, फिर `ollama create`। गुणवत्ता model पर निर्भर करती है: जहाँ gateway model ने सब कुछ सुरक्षित रखा, वहीं एक 7B model ने test file में एक list उलट दी और code block की closing fence बिगाड़ दी।
- `--eco` का कोई प्रभाव नहीं है (model `--model` वाला होता है); `--reasoning_effort` को OpenCode के `--variant` के रूप में ज्यों का त्यों भेजा जाता है, इसलिए इसे केवल तभी माँगें जब model इसे पहचानता हो।
- Sessions को OpenCode अपनी database (`~/.local/share/opencode/`) में, हर OpenCode session की तरह, log करता है।
- Environment variables: `OPENCODE_BIN` (binary का explicit path; अन्यथा `PATH`, फिर `~/.opencode/bin/opencode`) और `OPENCODE_TIMEOUT` (प्रति segment seconds, default `600`)। यदि आप `OPENCODE_CONFIG` export करते हैं, तो उसका पालन किया जाता है।

**मापा गया उदाहरण: Ollama के माध्यम से local model** (RTX 3060 12 GB, 62 GB RAM, Ollama 0.33.3)

```bash
curl -fsSL https://ollama.com/install.sh | sh   # conserve les modèles déjà téléchargés
ollama pull gpt-oss:20b                         # 13 Go, Apache 2.0 — le seul modèle local retenu ici

# Sous 24 Go de VRAM, Ollama plafonne le contexte à 4 096 tokens, et son API OpenAI-compatible
# ne permet pas de le régler par requête : on le fixe dans un Modelfile.
printf 'FROM gpt-oss:20b\nPARAMETER num_ctx 32768\n' > gpt-oss-20b-32k.Modelfile
ollama create gpt-oss-20b-32k -f gpt-oss-20b-32k.Modelfile
```

फिर `~/.config/opencode/opencode.json` में प्रदाता:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama (local)",
      "options": { "baseURL": "http://127.0.0.1:11434/v1" },
      "models": {
        "gpt-oss-20b-32k": {
          "name": "gpt-oss 20B (32k, sans réflexion)",
          "limit": { "context": 32768, "output": 8192 },
          "options": { "reasoningEffort": "none" }
        }
      }
    }
  }
}
```

`reasoningEffort: "none"` कोई मामूली विवरण नहीं है: Ollama इन models पर default रूप से reasoning सक्रिय करता है और Modelfile इसे बंद नहीं कर सकता। OpenCode के माध्यम से मापा गया: option के बिना “बिल्ली चटाई पर सो रही है” में 919 reasoning tokens और 68 s लगते हैं; इसके साथ 9 tokens।

```bash
aipmt --use_opencode --model ollama/gpt-oss-20b-32k --news --keep_filename \
  --add_translation_note --file article.mdx --target_dir out/ --target_lang en
```

589 lines वाले एक वास्तविक blog article (140 links, 21 sections, `--news` mode द्वारा सुरक्षित 3 English quotations) पर, एक ही command और तीन models के परिणाम:

| Model                                    | अवधि        | संरचना                                                     | अंतर                                                                                         |
| ---------------------------------------- | ----------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `opencode/mimo-v2.5-free` (Zen, निःशुल्क) | 4 min 26 s  | source के समान                                             | कोई नहीं                                                                                     |
| `ollama/gemma4-12b-32k` (local)          | 10 min 10 s | links, URL, tables, tags, bold और inline code समान         | quotation की एक गढ़ी हुई line (🇺🇸 + paraphrase), एक duplicated attribution                  |
| `ollama/qwen3.5-9b-32k` (local)          | 8 min 18 s  | links, URL, tables और tags समान                            | quotation की एक गढ़ी हुई line, कुछ अतिरिक्त bold और inline code, एक segment दोबारा process हुआ |

इन दोनों local models को बाद में **हटा दिया गया**: प्रत्येक article में एक मनमानी published translation के लिए किसी model को अयोग्य ठहराने हेतु पर्याप्त है। पाँच अन्य models भी इन्हीं कारणों या timeout (`gemma4:26b-a4b`, `qwen3.6:35b-a3b`, `ministral-3:14b`, `mistral-small3.2`, `hy-mt2:7b`) के कारण हटाए गए। केवल `gpt-oss:20b` को रखा गया — और वह भी किसी सघन article में कुछ अंश French में छोड़ देता है; सुझाए गए models की table देखें।

Local translation के दौरान: GPU 98% और 170 W पर, 10 GB VRAM उपयोग में (model और 32 k tokens का cache, RAM में कुछ भी offload नहीं), Ollama server के लिए 7.5 GB RAM। 9 से 12 billion parameters वाला model संरचना का पालन करता है, लेकिन प्रत्येक article में एक मनमानी कर देता है, जबकि gateway model ने एक भी नहीं की: publication से पहले proofreading करें या इसे drafts तक सीमित रखें।

### OpenRouter के माध्यम से अनुवाद करें (`--use_openrouter`)

OpenRouter, तीसरे पक्षों द्वारा host किए गए 400 से अधिक models के आगे स्थित एक **router** है, जिसका usage एकल credit से bill किया जाता है। यह एक key के माध्यम से उन models तक access देता है जिन्हें अन्य कोई provider उपलब्ध नहीं कराता, विशेष रूप से खुले Chinese models।

```bash
# --model est OBLIGATOIRE : aucun défaut n'est choisi à votre place
aipmt --use_openrouter --model 'z-ai/glm-5.2' --file README.md \
  --target_dir . --source_lang fr --target_lang en
```

Routing की दो विशेषताओं ने implementation निर्धारित किया, और दोनों को मापा जा सकता है:

- **एक ही model को अलग-अलग limits वाले दर्जनों hosts serve करते हैं।** `z-ai/glm-5.3-flash` पर 23 hosts हैं, जिनमें से एक की output limit 2 048 tokens है: सावधानी के बिना 23 में से एक long translation routing के अनुसार randomly truncate हो जाती थी, और इसका कोई संकेत नहीं मिलता था। एक preflight `/api/v1/models/{modèle}/endpoints` पढ़ता है, 8 000 output tokens से कम limit या degraded status वाले hosts को हटाता है, फिर अन्य को `allow_fallbacks: false` के साथ pin करता है — इसके बिना router फिर हटाए गए host पर चला जाता है।
- **Reasoning का billing output rate पर होता है।** `z-ai/glm-5.2` पर वही request, response “OK”: model के default पर 107 completion tokens, reasoning बंद करने पर 2। इसलिए जिन models में संभव है, उनमें यह default रूप से बंद रहता है। जो इसे अनिवार्य करते हैं — `reasoning.mandatory`, catalogue के 431 में से 288 models — उन्हें उनके द्वारा स्वीकार घोषित **सबसे कम effort** मिलता है, उनका default setting नहीं: `z-ai/glm-5.3-flash` का setting `max` है और translation समाप्त होने से पहले ही उसने 32 768 output tokens पूरे खर्च कर दिए। Envelope बढ़ाने से कुछ नहीं बदलता, क्योंकि effort उसका एक percentage allocate करता है। `--reasoning_effort` की प्राथमिकता बनी रहती है और reasoning अनिवार्य करने वाले model पर `none` को bypass करने के बजाय report किया जाता है।

Preflight **fail-closed** है और बताता है कि उसने क्या चुना:

```
→ OpenRouter : 30 hébergeur(s) épinglé(s) sur 33, contexte 1048576 tokens,
  sortie plafonnée à 32768, raisonnement coupé
```

Catalogue में अनुपस्थित slug, inaccessible catalogue या limit पूरी करने वाले host की अनुपस्थिति, किसी billing से पहले command रोक देती है।

अन्य बिंदु:

- Context window किसी constant से नहीं, catalogue से आती है: segmentation वास्तव में उसके अनुसार adapt होती है, 4 095 tokens वाले models के लिए भी।
- `--eco` का कोई प्रभाव नहीं है (model `--model` वाला होता है)।
- Empty output वाला `finish_reason=length` truncation नहीं, बल्कि reasoning द्वारा खर्च किया गया budget है; message यह स्पष्ट करता है, क्योंकि दोनों स्थितियों में विपरीत कार्रवाई आवश्यक होती है।
- Environment variables: `OPENROUTER_API_KEY` (key, <https://openrouter.ai/keys> पर), `OPENROUTER_BASE_URL` (default `https://openrouter.ai/api/v1`, `https://` आवश्यक), `OPENROUTER_TIMEOUT` (प्रति call seconds, default `900`) और `OPENROUTER_PREFLIGHT_TIMEOUT` (default `30`)।

### किफ़ायती mode

अधिक तेज़ और कम लागत वाले models (gpt-5.6-luna, claude-haiku-4-5, gemini-3.1-flash-lite) का उपयोग करता है:

aipmt --eco --source_dir 'content/fr' --target_dir 'content/en'

| `--use_opencode`         | OpenCode में configured प्रदाता के माध्यम से OpenCode (open source) का उपयोग करें; `--model provider/modèle` आवश्यक |
| `--force`                | पुनः अनुवाद बाध्य करें                                                                                        |
| `--keep_filename`        | मूल filename बनाए रखें                                                                                        |
| `--news`                 | News mode: English quotations सुरक्षित रखता है, language के अनुसार flags संभालता है                          |
| `--add_translation_note` | Translation note जोड़ें                                                                                       |
| `--note_position`        | Note की position: `top`, `bottom` (default), या `both`                             |
| `--note_format`          | Note का format: `legacy` (default, bold paragraph) या `marker`                                  |
| `--include_model`        | Output file में model का नाम शामिल करें                                                                       |
| `--reasoning_effort`     | GPT-5.x reasoning effort: `none`/`low`/`medium`/`high`/`xhigh`    |

> **सातों provider flags परस्पर असंगत हैं।** पहले दो को combine करना चुपचाप स्वीकार कर लिया जाता था और resolution जाँचे गए पहले provider पर होता था: subscription quota (`--use_codex`, `--use_grok_cli`) पर माँगा गया translation बिना किसी warning के usage-based billing पर जा सकता था।
> अब `argparse` इस combination को अस्वीकार करता है।

### Translation note: positions और formats

`--add_translation_note` के साथ translator note को ऊपर, नीचे या दोनों स्थानों पर रख सकता है और इसे backward-compatible plain text format या Markdown plugin द्वारा उपयोग किए जा सकने वाले `marker` format में render कर सकता है।

**Position** (`--note_position`):

- `bottom` (default): पहले की तरह file के अंत में note।
- `top`: note **YAML frontmatter के बाद** insert किया जाता है (Astro Content Collections, gray-matter आदि के लिए सुरक्षित)।
- `both`: note ऊपर और नीचे दोनों स्थानों पर insert किया जाता है (एक ही LLM call, दोनों placements के लिए content reuse होता है)।

**Format** (`--note_format`):

- `legacy` (default): bold paragraph `**...**` — v1.8 के बिल्कुल समान व्यवहार, byte-for-byte। Hugo, GitHub, GitLab और किसी भी Markdown renderer के साथ compatible।
- `marker`: invisible Markdown link reference definition (`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`), जिसके बाद bold blockquote होता है। GitHub/GitLab पर natively readable और Astro में remark plugin द्वारा build के समय styled banner बनाने के लिए usable (blog jls42.org देखें)।

```bash
# Compatibilité legacy (rien ne change vs v1.8)
aipmt --file article.mdx --target_lang en --add_translation_note

# Format marker, note en haut uniquement (Astro)
aipmt --file article.mdx --target_lang en \
    --add_translation_note --note_format marker --note_position top

# Format marker en haut ET en bas
aipmt --file article.mdx --target_lang en \
    --add_translation_note --note_format marker --note_position both
```

## कौन-से मॉडल कसौटी पर खरे उतरते हैं

किसी अनुच्छेद का अच्छा अनुवाद करने वाला मॉडल आवश्यक नहीं कि पूरे दस्तावेज़ की संरचना भी सुरक्षित रखे। ये माप **वास्तव में किए गए अनुवादों** से प्राप्त हुए हैं, ऊपर दी गई कमांड का उपयोग करते हुए, दस्तावेज़ों के तीन समूहों और चौदह लक्षित भाषाओं पर: en, es, de, it, pt, nl, pl, sv, ro, ja, ko, zh, ar, hi।

दो कॉलम हैं, और दोनों का अर्थ एक नहीं है। **लिखे गए** उन सफल अनुवादों की संख्या है जिनकी फ़ाइल को स्क्रिप्ट के मौन-विफलता-रोधी सुरक्षा-जाँच स्वीकार कर लेती हैं। **बिना अंतर** उन अनुवादों की संख्या है जिनकी संरचना स्रोत के समान है: वही अनुभाग, वही लिंक, वही URL, वही ब्लॉक और इनलाइन कोड, वही तालिकाएँ, वही उद्धरण, वही फ़्लैग।

- **तीन मॉडलों ने दोनों सघन दस्तावेज़ों में कभी कोई जानकारी नहीं खोई**: `gemini-3.7-flash`, ChatGPT सदस्यता के माध्यम से `gpt-5.6-sol`, और OpenRouter के माध्यम से `z-ai/glm-5.2`। मानक मोड में उनके एकमात्र अंतर एक या दो भाषाओं में `**` की एक जोड़ी का न दोहराया जाना है; कोई URL, कोड ब्लॉक या उद्धरण कभी नहीं छूटा।

### यह तालिका क्या नहीं है

- **यह कोई व्यापक रैंकिंग नहीं है।** केवल OpenRouter ही चार सौ से अधिक मॉडल उपलब्ध कराता है; यहाँ लगभग पंद्रह को मापा गया है। किसी मॉडल की अनुपस्थिति उसकी गुणवत्ता के बारे में कुछ नहीं बताती, केवल यह कि उसे आज़माया नहीं गया।
- **इन मापों की एक तारीख है**: 4 और 5 सितंबर 2026। एक ही नाम के अंतर्गत मॉडल बदलते रहते हैं, होस्टिंग प्रदाता quantization और सीमाएँ समायोजित करते हैं, और हर सप्ताह नए मॉडल जारी होते हैं।
- **अवधियाँ किसी को क्रमबद्ध नहीं करतीं।** अलग-अलग परीक्षण अभियानों में एक साथ 3 से 6 अनुवाद चल रहे थे, और किसी प्रदाता की प्रवाह-दर दिन भर बदलती रहती है। ये केवल परिमाण का अनुमान देती हैं, तुलना नहीं।
- **परिणाम मॉडल पर जितना निर्भर करता है, उतना ही दस्तावेज़ पर भी।** वही मॉडल एक लेख में चौदह भाषाओं पर सफल होता है और इस README में नौ पर। आपकी फ़ाइलें हमारी फ़ाइलें नहीं हैं।
- **सही तरीका अपने परिवेश में मापना ही है**: अपने किसी दस्तावेज़ का अपनी लक्षित भाषाओं में अनुवाद करें, फिर संरचना की तुलना करें—अनुभागों, लिंक, अलग-अलग URL, कोड ब्लॉक, इनलाइन कोड और तालिका की पंक्तियों की संख्या। ऊपर दिया गया प्रोटोकॉल ठीक यही करता है, और यह `aipmt` पर एक ही लूप में समा जाता है।
