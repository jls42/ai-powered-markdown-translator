- **1.16.3** Fim de arquivo: uma tradução por API preserva a quebra de linha final da fonte, e o SDK 3.0 da Mistral foi validado (2026-10-04):

  - **Uma tradução por API preserva a quebra de linha final da fonte.** Os providers de API — OpenAI, Anthropic, Gemini, Mistral — removem os espaços em branco ao redor da resposta do modelo. No último segmento, essa limpeza removia a quebra de linha final da fonte: um arquivo traduzido sem nota de tradução terminava sem quebra de linha, algo que o git sinaliza e que os formatadores corrigem a cada execução. Isso foi observado durante a validação do SDK 3.0 da Mistral, em um guia que terminava com uma quebra de linha, mas cuja tradução já não a tinha. A nota de tradução voltava a adicioná-la, e os providers de linha de comando — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — reproduzem o fim do segmento: apenas uma tradução por API sem nota era afetada. Agora, a tradução reproduz a quebra de linha final da fonte, qualquer que seja o provider, e não adiciona nenhuma a uma fonte que não a tenha.

  - **Mistral: o SDK 3.0 validado por uma chamada real.** `mistralai` 3.0.0 substitui a biblioteca HTTP `httpx` por `httpx2`; os imports e a chamada de tradução não mudam. Uma instalação nova do aipmt já o recebia, pois as dependências não têm limite máximo de versão, mas nenhuma chamada real ainda o havia testado: um guia Markdown traduzido pela API Mistral com o SDK 3.0 mantém uma estrutura idêntica à fonte. As versões fixadas para desenvolvimento passam para esse SDK, e os testes de nova tentativa fornecem-lhe um cliente `httpx2`, aquele que ele utiliza em produção.

- **1.16.2** Proteção do código: um código citado em uma citação `--news` e um bloco indentado em uma lista já não fazem com que a tradução de todos os idiomas seja recusada (2026-10-03):

  - **Um código citado em uma citação já não bloqueia a tradução.** No modo `--news`, o aipmt protege o código inline antes de separar as citações em inglês, restauradas sem alterações. Portanto, um código colocado em uma citação era levado junto com ela: o modelo nunca via seu token, e a validação o declarava perdido, em todos os idiomas. O acompanhamento diário de notícias do autor parou aí em 2 de outubro: um comando `/plugin enable …` citado em um tweet, o idioma de teste recusado duas vezes, os outros treze nunca iniciados. Agora, os tokens levados por uma citação são resolvidos no texto separado. Quando o idioma de destino é o inglês, a linha de tradução francesa de uma citação já não é enviada ao modelo: a instrução pedia que ele a removesse, e o código que ela continha era então considerado perdido, embora o modelo tivesse obedecido. O resultado publicado não muda. Por fim, a restauração de uma citação já não reinterpreta suas barras invertidas: um `\n` citado continua sendo um `\n`. Verificado de ponta a ponta no artigo que havia falhado: inglês e alemão traduzidos na primeira tentativa por `gpt-6.1-sol`, com estrutura idêntica às versões publicadas.

  - **Um bloco de código indentado em uma lista é protegido.** O CommonMark permite um fechamento de bloco deslocado, e esse é o caso normal de um bloco que documenta uma etapa de uma lista numerada: ele pertence ao item da lista e, portanto, é indentado. Ancorado na coluna 0, o padrão de proteção não detectava nenhum deles: medido em um README real, 8 blocos detectados de um total de 14. Os outros seis eram enviados ao modelo como prosa, voltavam idênticos, pois eram comandos, e a proteção que recusa uma tradução copiada sem alterações rejeitava o arquivo em todos os idiomas, com uma mensagem que indicava o sintoma, mas nunca a causa. Agora, o padrão aceita um fechamento indentado, e a ida e volta entre proteção e restauração devolve o documento sem alterações, incluindo a indentação.

- **1.16.1** Links internos: o token de âncora deixa os parênteses no link, e um link traduzido já não é duplicado silenciosamente (2026-09-27):

  - **Um link interno já não se quebra sem que ninguém perceba.** Para proteger um link para uma seção, `[texte](#ancre)`, o aipmt substituía sua parte entre parênteses, incluindo os próprios parênteses, por um token: o modelo recebia colchetes seguidos de um token isolado, um link aparentemente quebrado, e às vezes tentava «corrigi-lo». A restauração produzia então `[texte]((#ancre))`, um link que não leva a lugar algum, sem que nenhuma proteção o sinalizasse. O defeito reaparecia a cada regeneração das traduções deste repositório — em espanhol, coreano e depois italiano para a 1.15.0, em alemão para a 1.16.0 — com cada Gemini Flash testado, e até mesmo com Claude Sonnet e Haiku. Agora, o token de um link Markdown mantém os parênteses: o modelo recebe um link válido, que já não tem motivo para corrigir, e a restauração também aceita um token do qual ele tenha removido os parênteses. As âncoras HTML mantêm um token isolado. Verificado de ponta a ponta com o modelo mais frágil, `gemini-3.8-flash-low`, em um README no qual um link estava entre parênteses: sem a correção, README recusado, três links duplicados e um segmento processado novamente; com ela, três links intactos de três, sem nenhuma nova tentativa. Depois, nesse README, em alemão, japonês e hindi por `gemini-3.8-flash-medium`, e em alemão pelo Claude Code com `sonnet`: estrutura idêntica à fonte, com os três links internos intactos em todos os casos.

  - **Os testes já não podem modificar o repositório que os executa.** Quando se faz push a partir de um worktree vinculado, o git transmite aos hooks a variável que designa o repositório, e o hook pre-push executa os testes: o `git init` de um teste, destinado a um diretório temporário, reinicializou o repositório real, que subitamente foi declarado sem árvore de trabalho. Agora, os testes que executam git removem do ambiente todas as variáveis `GIT_*`, e um teste de não regressão, que utiliza essa variável para designar um repositório-isca, verifica isso.

- **1.16.0** Provider `--use_claude_code`: traduzir usando a quota da assinatura Claude Pro ou Max, por meio do CLI oficial `claude -p` — sem nenhuma via paga, e cada chamada comprova isso (2026-09-26):

  - **Décimo primeiro caminho: a assinatura Claude, sem cobrança por uso.** `--use_claude_code` controla o binário oficial do Claude Code no modo `-p`, sobre a mesma base que Codex, Grok CLI e Antigravity — grupo de processos próprio, interrupção segura em caso de timeout, Ctrl-C ou fechamento do terminal. Não confundir com `--use_claude`, a API da Anthropic cobrada por uso. O aipmt nunca lê o token.

  - **Nenhuma via paga, verificada em três níveis.** O ambiente do subprocesso é uma lista de permissões: nenhuma chave de API, token, provider de cloud ou marcador da sessão do Claude Code a partir da qual o aipmt teria sido iniciado — aquela que escreveu este provider exportava quinze. O preflight, sem turno do modelo, exige de `claude auth status` a conexão da assinatura sem chave do Console e de `/usage` a frase que comprova a assinatura. Em seguida, cada chamada deve comprová-la em seu evento de inicialização — `apiKeySource: none`, ambiente forçado recebido corretamente, modelo da família solicitada, sem modo rápido — e em seu relatório de quota: o «extra usage» pago interrompe imediatamente a tradução.

  - **A quota é compartilhada com as sessões do Claude Code, e o provider a poupa.** Cada chamada informa o uso das janelas de 5 horas e da semana; acima de 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), nenhum segmento adicional é iniciado. No dia em que isto foi escrito, a semana da conta do autor já estava em 98%.

  - **Nada da configuração do usuário entra, nada da sessão permanece.** Sem ferramentas, no modo sem personalização, configurações do usuário ignoradas, servidores MCP e hooks desativados, diretório de trabalho privado e descartável, nenhuma transcrição preservada. Medido por canários: sem `CLAUDE_CODE_DISABLE_ATTACHMENTS`, um `@chemin` do documento transformava-se em um anexo, e o modelo retornava uma chamada de leitura em vez da tradução; com ele, nada passa. Os canários `AGENTS.md`, `CLAUDE.md` e de hook não carregaram nem executaram nada.

  - **Um segmento que começa com `/` não chegava ao modelo.** Sob `--disable-slash-commands`, o próprio Claude Code responde «… isn't available in this environment.», com o status `success`, sem nenhum turno. Uma quebra de linha antes do segmento o envia ao modelo; de qualquer forma, o contrato de saída recusa uma resposta devolvida sem turno, em mais de um turno, truncada ou por um modelo diferente daquele anunciado.

  - **Modelos: aliases, nunca um identificador fixo.** `sonnet` por padrão, com o esforço `low`, inclusive em `--eco` — portanto, `--eco` não altera nada nesse caminho —, `opus` e `haiku` por `--model`; `fable` e as variantes `[1m]` são recusados porque, em `-p`, passam a usar créditos pagos sem perguntar.

  - **Os padrões são medidos, não presumidos.** Pelo próprio `aipmt --use_claude_code`, quatro traduções em paralelo, nos dois documentos das medições do README — o artigo denso de acompanhamento de notícias, em `--news`, e este README em sua revisão 1.14.0 —, cada um em quatorze idiomas. `sonnet`, com o esforço `low`, escreve as 28 traduções, 26 sem diferenças: uma palavra adicional em negrito em chinês no artigo e, em árabe, no README, uma linha de tabela colada à anterior, algo que a renderização oculta. Links internos intactos, citações em inglês copiadas sem alterações e, em inglês, as linhas de tradução francesa removidas pelo modelo, sem flag inventada; mediana de 6 min 49 s por idioma no artigo, 2 min 20 s no README. `opus` traduz o README sem nenhuma diferença, um quarto mais rápido, mas nenhum artigo: suas proteções interromperam a resposta nos quatorze idiomas, em uma nota curta de biologia. `haiku`, por sua vez, escreve tudo — três títulos de seção promovidos ao nível 1 no artigo, os links internos do README em inglês duplicados —, mas duas vezes mais lentamente que `sonnet`: ele raciocina sem que seja possível impedi-lo, usando nisso 61% de seus tokens de saída, e seu preço mais baixo gera apenas 14% de economia em equivalente de API. Daí `sonnet` também em `--eco`. O esforço não serve para traduzir: em um lote anterior — este README e este CHANGELOG em inglês, japonês e hindi —, `sonnet` não produziu nenhum token de raciocínio, `opus` com esforço médio usou nisso 1% de seus tokens de saída, e o esforço médio não trouxe nenhum ganho em relação ao baixo, nem em estrutura nem em duração. A campanha `sonnet`, com 1,8 milhão de caracteres-fonte, consumiu 9 pontos da janela de 5 horas e 2 da semana na assinatura Max do autor — um limite superior: a sessão que controlava as medições utilizava a mesma quota.

  - **Uma recusa das proteções da Anthropic é identificada como tal.** O Opus 5.5 tem proteções mais rigorosas que o Sonnet, e a mensagem de erro da Anthropic alerta que elas às vezes sinalizam trabalhos próximos da pesquisa biológica. Uma nota curta de acompanhamento sobre 279 moléculas geradas para um sítio de ligação foi suficiente. O Claude Code então interrompe a resposta, tenta novamente uma vez, e o modelo retorna «I can't continue this translation» com um status de sucesso, sem erro, em dois turnos: somente o contrato de turno único interrompia essa resposta, com uma mensagem que nada dizia sobre sua causa. Enviada isoladamente, a nota é recusada pela API na categoria «bio». Agora, o aipmt reconhece esses sinais, identifica as proteções e sua categoria, não tenta novamente — o mesmo texto provocaria a mesma recusa — e recomenda `--model sonnet`, que traduziu a nota para os quatorze idiomas.

  - **As traduções deste repositório podem passar por esse caminho, sem exceção.** `REGEN_PROVIDER=claude_code` é uma assinatura, não uma API cobrada: ele funciona sem `REGEN_ALLOW_PAID_API`, com quatro jobs — as campanhas foram executadas com quatro traduções simultâneas sem nenhum erro de limite de requisições ou de bloqueio de conexão —, após um único preflight que não consome nenhuma quota. O padrão continua sendo Codex com `gpt-5.6-sol`.

  - **Os termos de uso, apresentados sem rodeios.** A página jurídica do Claude Code não impede que um usuário se conecte ao binário não modificado com sua própria assinatura; ela proíbe desenvolvedores terceiros de encaminhar requisições por meio das credenciais Pro ou Max de seus usuários, e a Anthropic prefere a chave de API para ferramentas de terceiros, incluindo projetos open source, reservando-se o direito de descontar seu uso dos créditos pagos. Nenhum texto decide o caso de uma ferramenta distribuída que inicia o binário oficial: o usuário compromete sua conta.

  - **Testes**: novo arquivo `tests/test_claude_code_provider.py` (58 testes), 100% das instruções e ramificações do módulo, sem nunca iniciar o verdadeiro `claude` — ambiente esvaziado, binário inexistente, `PATH` sem `claude`, doubles que lançam uma exceção se forem chamados.

- **1.15.0** Provider `--use_antigravity`: traduzir usando a quota da assinatura Google AI Pro ou Ultra, por meio do CLI oficial `agy`; e, para todos os providers, Ctrl-C já não abandona um agente em execução, um segmento em branco já não faz o arquivo falhar, um `.env` do projeto já não escolhe o binário executado (2026-09-26):

  - **Décimo caminho de provider: a assinatura Google, sem cobrança por uso.** Quem paga pelo Google AI Pro ou Ultra agora pode descontar dela suas traduções, em vez de pagá-las por token na API Gemini. `agy`, o CLI oficial do Antigravity, é o único caminho para essa quota: o Gemini CLI deixou de atender contas Pro, Ultra ou gratuitas desde 18 de junho de 2026, e o SDK Antigravity só se autentica por uma chave de API ou pelo Google Cloud. `--use_antigravity` o controla no modo headless, como Codex e Grok CLI, sobre a mesma base — grupo de processos próprio, `SIGTERM` e depois `SIGKILL` ao atingir o timeout, ambiente depurado. Verificado de ponta a ponta no agy 1.2.11: um guia Markdown — front matter, negrito, link com parênteses, código inline, bloco de código indentado em uma lista, tabela, citação — traduzido para o inglês em 14 segundos, incluindo o preflight, com estrutura idêntica à fonte e nota de tradução adicionada; depois, após as correções da revisão, para o alemão em 19 segundos, com estrutura idêntica e nada escrito em `~/.gemini`.
  - **Nenhuma via paga permanece aberta, e cada execução verifica isso.** O agy conhece outras vias além da assinatura — chave de API, projeto Google Cloud, gateway, créditos de IA pagos — e várias variáveis de ambiente fazem com que ele mude para elas sem exibir nada. Medido: `AGY_GATEWAY_URL` envia o documento para um gateway de terceiros, `AGY_ADC_AUTH` muda para um projeto Google Cloud faturado, `CLOUD_CODE_URL` redireciona o endpoint autenticado para qualquer endereço. Portanto, o ambiente do subprocesso é uma lista de permissões, e não de bloqueios: `PATH`, o idioma e o fuso horário, o terminal, a identidade, os proxies e certificados da máquina e o barramento da sessão — dos quais um `env -i` comprovou que o agy precisa —, sem nenhuma chave. Uma lista de bloqueios por famílias de prefixos (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), testada primeiro, deixava alguns escapar: uma revisão encontrou, nas strings do binário, substituições de endpoint que nenhum prefixo abrangia, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Duas configurações escapam ao ambiente e só podem ser lidas por `agy -p /config`: os créditos de IA pagos que assumem quando uma cota se esgota e a conexão por meio de um projeto Google Cloud. Um preflight que não consome cota alguma — uso zero, medido — recusa-se a traduzir se qualquer um deles estiver ativo ou se uma chave de API estiver configurada, e uma configuração ausente de `/config` equivale a uma recusa para cada um dos três: uma versão do agy que renomeasse uma delas não deve passar por uma verificação que não confirmou nada. Por fim, o log de cada chamada deve comprovar a autenticação pela assinatura (`authMethod=consumer`), e qualquer outro método de autenticação que apareça nele, sob qualquer uma das duas grafias usadas pelo binário, faz com que a resposta seja recusada: é a própria chamada que serve de prova, não a configuração preparada.

  - **O agente de tradução não tem ferramenta alguma, e seu carregamento é comprovado a cada chamada.** Cada chamada grava, em um diretório descartável, um agente no formato dos agentes de projeto do agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Cerca de 800 tokens de entrada em vez de 12.400 com o agente padrão, e a terceira configuração não é redundante: apenas `excludeDefaultComponents` ainda permitia que um hook do workspace executasse seus comandos e injetasse seu texto. A verdadeira armadilha está em outro lugar: um agente não encontrado não faz o agy falhar. Código de retorno 0, status `SUCCESS`, e é o agente de programação, com 57 ferramentas ativas, que responde — a «O gato dorme.», ele respondeu «Psiu, não vamos acordá-lo! 🐱💤 O que posso fazer por você hoje?». Nada no stdout nem no stderr: somente o log da chamada informa isso. Portanto, a resposta é recusada se o log anunciar esse fallback e também se não contiver o marcador positivo de carregamento do agente — uma alteração no formato do log faz com que a tradução seja recusada, em vez de remover silenciosamente a proteção. Cada marcador deve ocupar uma linha inteira do log, no formato medido — severidade, data, hora, thread, arquivo e linha: o binário também contém uma linha que copia a mensagem do usuário para o log — nunca observada no nível de log padrão, em 78 logs reais —, e um documento que cite essas mensagens não deve poder satisfazer a proteção no lugar do agy.

  - **As configurações e o histórico do agy do usuário não são alterados.** Cada chamada é executada com HOME, diretório temporário e diretório de trabalho privados, depois eliminados. Ainda assim, o agy se autentica pelo chaveiro do sistema, que o aipmt nunca lê. Nada é herdado: nem as permissões do usuário — que permitiam ao agente padrão executar `ls` e `git` sem perguntar nada —, nem suas regras globais, plugins, servidores MCP, hooks e skills. E nada é acrescentado ao histórico, no qual cada chamada deixava uma conversa de cerca de 200 KB, incluindo o texto traduzido: a campanha de testes havia deixado ali cerca de 95 conversas e removido 17 entradas de um cache limitado a 100. Verificado: nenhum arquivo gravado em `~/.gemini/antigravity-cli`.

  - **Recusa por padrão onde o isolamento não se sustentaria.** No Linux sem barramento de sessão D-Bus — sessão SSH, contêiner, servidor —, o agy armazena seu token em um arquivo de `~/.gemini` em vez do chaveiro, como anuncia seu próprio changelog (1.1.3), e o isolamento de cada chamada oculta esse arquivo. Agora, a recusa ocorre antes de qualquer execução, com sua causa real, em vez de um minuto de espera por um código de conexão seguido de uma recomendação para reconectar que não resolveria nada. No Windows, o agy lê `USERPROFILE`, `APPDATA` e `TEMP`, não `HOME` nem `TMPDIR` — segundo a documentação do Go e as strings do binário —: nada ali isolaria a chamada das configurações ou do histórico do usuário, e `--use_antigravity` é recusado nessa plataforma enquanto isso não for medido. O macOS passa, sem ter sido medido; a proteção contra faturamento, que lê a configuração efetiva, funciona nele.

  - **`exit 0` não prova nada, quarta CLI.** Uma resposta só é aceita com código de retorno zero, um objeto JSON com status `SUCCESS`, um log em conformidade, nenhuma ação recusada, nenhum comando, nenhum erro no JSON, nenhum aviso de truncamento no stderr e texto não vazio. `--print-timeout` nunca é usado: quando expira, o agy devolve a saída parcial em `SUCCESS`, código 0; o limite de tempo é externo e encerra o grupo de processos. Um segmento que começa com `/commande`, `!commande` ou `@fichier` é traduzido, nunca executado nem resolvido — sem `--disable-slash-commands`, «/help» era executado em vez de traduzido. Um segmento em branco já não chega ao agy, pois o pipeline o devolve sem alterações (veja abaixo), e continua sendo recusado antes da chamada como última proteção: diante de uma entrada vazia, o agy abre sua interface interativa com código 0. A nova tentativa segue o campo `retryable` da linha `AGY_ERROR` que o agy grava no stderr desde a versão 1.2.6: ele próprio já tenta novamente os erros transitórios — 502, 503, 504, limite por minuto —, e é ele quem sabe se a falha restante ainda é transitória. Na ausência desse campo, não há nova tentativa quando a mensagem fala em esgotamento — no Google, `RESOURCE_EXHAUSTED` apresenta o mesmo código 429 que um limite por minuto, mas uma janela de 5 horas esgotada não se recupera em 90 segundos —, e, nos demais casos, apenas diante de limitação de taxa. A resposta preserva a terminação de linha do segmento: o agy sempre termina a sua com uma quebra de linha que, na junção, dividia em dois um parágrafo segmentado no meio de uma frase. Uma sessão desconectada produz uma mensagem que pede a execução de `agy` para reconectar. Por fim, `AGY_CLI_DISABLE_AUTO_UPDATE=true` impede que um HOME novo execute, a cada chamada, um verificador de atualizações em sua própria sessão, fora do alcance do limite de tempo — já o valor `1` não tem efeito.

  - **Modelos: o esforço de raciocínio faz parte do nome.** Os identificadores são os de `agy models` — `gemini-3.8-flash-medium`, `gemini-3.7-flash-low`, `gemini-3.1-pro-high`, `claude-sonnet-4-6`… Um nome-base isolado, que o agy recusaria, é recusado antes da chamada, com os sufixos existentes: `-medium` ou `-low` para um Flash, `-high` ou `-low` para um Pro. Por padrão, `gemini-3.8-flash-medium`, e `gemini-3.7-flash-low` em `--eco`, definidos pelas campanhas descritas abaixo. `--reasoning_effort` não tem efeito e informa isso. Claude e GPT-OSS usam uma cota distinta e muito menor — cerca de 1% da janela de 5 horas por chamada medida, contra 0,05% no Flash —, e um aviso relembra isso. A cota restante pode ser consultada gratuitamente por `agy -p /usage`. Recusado em CI, assim como Codex e Grok CLI: a conexão reside em um chaveiro pessoal, e a mensagem sugere `--use_gemini` com uma chave do Google.

  - **Duas campanhas em 26 de setembro: os padrões são medidos, não presumidos.** Por meio do próprio `aipmt --use_antigravity`, quatro traduções em paralelo, cada uma comparada à sua fonte por `scripts/compare_structure.py`, com a cota lida por `agy -p /usage` antes e depois. Pela manhã, na revisão deste README publicada com a versão 1.14.0 e no artigo de monitoramento denso das medições do README, em `--news`, `gemini-3.7-flash-medium` produz os quatorze idiomas dos dois documentos: o artigo sem qualquer divergência, com mediana de 3 min 14 s por idioma, e o README com apenas uma palavra em negrito divergente, em coreano, em 1 min 22 s. Depois, a campanha da manhã, repetida em `gemini-3.8-flash-medium`: quatorze idiomas em quatorze sem divergência no artigo, mediana de 3 min 59 s, e, no README, 1 min 43 s; os links internos intactos nos quatorze README, enquanto o 3.7 os quebrava em italiano; e, em inglês, as linhas de tradução francesa removidas pelo modelo, sem bandeira inventada, citações em inglês intactas.   - **Ctrl-C e o fechamento do terminal agora interrompem o agente, nas quatro CLI.** Codex, Grok CLI, OpenCode e Antigravity são executados em sua própria sessão, fora do grupo em primeiro plano: o `SIGINT` de um Ctrl-C não os alcança e, ao pressionar Ctrl-C, `Popen` espera por eles por apenas um quarto de segundo antes de devolver o controle. Verificado pela revisão com um binário falso: o agente sobrevivia ao aipmt e concluía sua execução consumindo a cota, para um resultado descartado — quatro de cada vez durante o regen. Um `KeyboardInterrupt` ou um `SystemExit` durante a chamada agora encerra o grupo do agente antes de propagar o sinal. Fechar o terminal ou interromper uma sessão SSH (`SIGHUP`) encerrava o Python sem qualquer limpeza: o agente continuava, e o diretório privado do Antigravity permanecia no disco com seu log, que contém o endereço da conta. Agora, `SIGHUP` segue o caminho de `SIGTERM`: o grupo do agente é encerrado e, em seguida, o processo sai com 129. Um `SIGHUP` ignorado, por uma execução sob `nohup`, continua sendo ignorado: essa é a escolha do usuário. O preflight do Antigravity — `agy --version`, depois `agy -p /config` — passa pelo mesmo gerenciador: um sinal recebido durante essa verificação interrompe o agy e também elimina o diretório privado, em vez de deixá-lo no disco com seu log.

  - **O controlador de subprocessos já não pode atingir toda a sessão.** No Linux, `killpg(1, sig)` equivale a `kill(-1, sig)`: o sinal é enviado a todos os processos do usuário. Isso ocorreu durante o desenvolvimento desta versão, em uma campanha de mutações: um mutante chamava um `Popen` substituído por um `MagicMock` isolado, o erro resultante passava pelo novo caminho de interrupção, e o pid do processo falso, que o Python converte em 1, fez com que toda a sessão gráfica fosse encerrada. `_codex_kill_group`, comum às quatro CLI, agora só visa um grupo se o pid for um inteiro real maior que 1, se `getpgid` retornar esse mesmo pid — um agente iniciado em sua própria sessão é líder de seu grupo — e se não for o grupo do processo atual; caso contrário, apenas o processo filho direto é atingido. Em produção, essa proteção não muda nada: ela cobre o caso em que um bug retornasse outra coisa. Os doubles de `Popen` que não devem ser usados agora falham imediatamente, os processos falsos têm um pid impossível e as campanhas de mutações são executadas em um namespace PID.

  - **Um segmento em branco já não faz o arquivo falhar, independentemente do provider.** `segment_text` pode isolar o final em branco de um documento: 16.001 caracteres terminados por três quebras de linha produzem um segundo segmento composto por duas quebras de linha. O Antigravity o recusava antes da chamada — reproduzido pela revisão — e, em um provider de API, uma resposta vazia era rejeitada pela proteção contra conteúdo vazio: nos dois casos, o arquivo inteiro falhava depois de a cota dos segmentos anteriores já ter sido consumida. Agora, um segmento em branco é devolvido sem alterações, sem nenhuma chamada.
  - **Segurança: um `.env` de projeto já não pode escolher o binário executado.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN` e `AGY_BIN` designam o programa que a tradução inicia, com as permissões do utilizador: definidas pelo `.env` de um repositório acabado de clonar, faziam executar um ficheiro desse repositório logo na primeira tradução. O sufixo `_BIN` junta-se, portanto, a `_BASE_URL`, `_API_BASE` e `_ENDPOINT` no filtro da camada de projeto, juntamente com `GROK_HOME`, sob o qual o binário Grok é procurado (`$GROK_HOME/bin/grok`). Estas variáveis continuam a ser aceites a partir do ambiente e de `~/.config/aipmt/.env`, e cada rejeição é indicada em stderr, juntamente com o local onde devem ser definidas.

A instalação para contribuir não produzia uma ferramenta utilizável: `pip install -r requirements.txt` instala apenas as dependências, `python -m aipmt` respondia `No module named aipmt`, e `pip install -e .` estava em falta — tal como a linha de instalação de `pre-commit`, ausente dos dois ficheiros de dependências. A promessa do OpenRouter sobre contextos pequenos afirmava o contrário do código: um modelo com uma janela inferior a **16 400 tokens** é rejeitado antes de qualquer chamada, conforme medido com 4 095, 8 192 e 16 384. O filtro que impede um `.env` de projeto de redirecionar as chamadas de API não estava documentado em lado nenhum; está agora, juntamente com a lista das variáveis abrangidas. Por fim, dois números: uma célula do Grok na tabela inicial provinha de uma campanha de 9 de setembro, embora a sua coluna indicasse a campanha de dia 4, e «um link desfeito» atribuído ao Gemini era o inverso da medição — transforma três URL simples em links, sem perder nenhuma.

  - **Uma falha de escrita já não deixa uma tradução truncada no disco.** `open(cible, "w")` trunca o ficheiro antes de o preencher: um erro durante a escrita — disco cheio — deixava nele um destino parcial. Reproduzido: oito bytes escritos, estado `failure` devolvido; depois, a execução seguinte encontrava esse ficheiro, respondia `skipped` e conservava-o. Uma falha tornava-se uma tradução truncada que já nada assinalava, e o código de saída era 0. O conteúdo é agora escrito num ficheiro temporário do mesmo diretório — `os.replace` só é atómico no mesmo sistema de ficheiros — e depois renomeado, sendo o temporário eliminado se a escrita falhar, inclusive em caso de interrupção. Esse temporário é criado por `mkstemp`, e uma revisão demonstrou que um nome previsível apenas teria deslocado o problema: um link simbólico colocado em `cible.md.aipmt-tmp` fazia a tradução ser escrita no ficheiro apontado, fora do diretório de saída, devolvendo `success`; e duas execuções simultâneas no mesmo destino partilhavam esse nome, com a segunda a renomeá-lo enquanto a primeira ainda escrevia no mesmo inode — destino anunciado como bem-sucedido, conteúdo misturado (`BBBAAAAA` em vez de `BBBBBBBB`, segundo as medições). `mkstemp` cria-o em `O_CREAT | O_EXCL` com um nome único, resolvendo ambos os casos. As permissões do destino existente são explicitamente retomadas antes da substituição: `mkstemp` cria com 0600, e, caso contrário, um destino deliberadamente definido como 0600 passava a 0664, enquanto um destino com 0644 servido por um servidor web se tornaria ilegível. Oito testes fixam todo o conjunto, e duas mutações do código fazem-nos falhar.

Porém, deslocar uma escrita para um ficheiro temporário muda o nome da variável aberta: a supressão Sonar é a mesma, mas a sua linha muda. A categoria `markers` do manifesto declara este par `old` → `new` juntamente com o respetivo motivo. Duas condições, sendo a segunda proveniente de uma revisão: o substituto deve existir **e conter as mesmas supressões que a linha original**. Sem ela, declarar `value = 1  # NOSONAR` → `value = 1` passava a verificação, pelo que bastava uma declaração para remover um marcador — exatamente aquilo que esta verificação existe para impedir. Um desaparecimento não declarado continua a ser rejeitado.

Nenhuma proporção média seria adequada — um ideograma do plano suplementar chega a 1,33 byte por token, um caractere combinante a 1,00 —, e agora entrada mais saída cabem na janela por construção. - **1.12.0** Provider `--use_opencode`: OpenCode, o agente open source, para o fornecedor de sua escolha — modelo local, gratuito sem conta, assinatura ou chave (2026-09-04):

  - **Oitavo caminho de provider, de natureza diferente dos sete primeiros.** [OpenCode](https://opencode.ai) (MIT) não é um fornecedor de modelos, mas um _roteador_ para aqueles que o usuário configurou no próprio OpenCode: uma chave de API, uma assinatura (GitHub Copilot, ChatGPT, SuperGrok), o gateway OpenCode Zen — que oferece modelos gratuitos **sem conta** — ou um modelo **local** (Ollama, LM Studio, llama.cpp). O script controla `opencode run` em modo não interativo, assim como controla Codex e Grok, e reutiliza a mesma base de subprocessos (grupo de processos próprio, `SIGTERM` e depois `SIGKILL` em caso de timeout, stdin sempre fechado, ambiente expurgado). Verificado por **duas traduções reais**: este README inteiro para o inglês por meio de `opencode/mimo-v2.5-free` — 49 s, uma única passagem, estrutura idêntica à do arquivo de origem (32 títulos, 26 fechamentos de código, 18 links, 37 URLs, 37 linhas de tabela, 135 códigos inline) — e um arquivo de teste por meio de `ollama/qwen2.5:7b`, localmente, sem nenhuma chave.

  - **`--model provider/modèle` é obrigatório, e isso é uma escolha.** Sem `--model`, o OpenCode recorre ao próprio padrão, que em uma instalação nova é `opencode/big-pickle`, modelo gratuito “stealth” cujas interações podem ser usadas para treinamento — conforme medido, foi esse modelo que respondeu. Escolher isso silenciosamente no lugar do usuário seria exatamente o tipo de mudança invisível que este repositório procura detectar; portanto, a mensagem de erro informa o comando que lista os modelos (`opencode models`) e três exemplos (local, gratuito, assinatura). `--eco` não tem efeito e informa isso. `--reasoning_effort` é transmitido sem alterações como `--variant` do OpenCode, somente mediante solicitação explícita.

  - **Confinamento medido, não presumido.** Uma configuração inline (`OPENCODE_CONFIG_CONTENT`, a última na ordem de mesclagem do OpenCode e, portanto, prioritária em relação à do usuário sem substituí-la) define um agente `aipmt` no qual todas as ferramentas são recusadas (`permission: {"*": "deny"}`): o registro deixa até mesmo de oferecê-las ao modelo, que, ao receber a ordem de “listar os arquivos e executar `id`”, responde que não possui ferramentas. Compartilhamento de sessão desativado, plugins externos excluídos (`--pure`), nunca `--auto`, diretório de trabalho descartável e vazio. Duas injeções silenciosas foram medidas e desativadas: sem `OPENCODE_DISABLE_CLAUDE_CODE`, o `~/.claude/CLAUDE.md` do usuário entra em **cada** prompt (515 tokens de entrada em vez de 186 para um simples “Olá”); sem `OPENCODE_DISABLE_PROJECT_CONFIG`, o `AGENTS.md` do diretório atual também — uma instrução para “terminar cada resposta com BANANA” foi aplicada à tradução. O `~/.config/opencode/AGENTS.md` global, por sua vez, continua sendo injetado: nenhum interruptor o exclui, e contorná-lo por meio de um `XDG_CONFIG_HOME` desviado também ocultaria os fornecedores do usuário. Documentado em vez de remendado.

  - **`exit 0` não prova nada, terceira CLI, mesmos reflexos — com duas armadilhas específicas.** Um `--agent` desconhecido não faz `opencode run` falhar: aviso em stderr e fallback **silencioso** para o agente de codificação, com ferramentas ativas. Se a configuração inline não fosse aplicada, a tradução seria, portanto, executada por um agente capaz de escrever; o contrato de saída verifica a ausência dessa mensagem, além de: código de retorno 0, nenhum evento `error`, nenhum `tool_use`, último `step_finish` em `stop` (um `length` é uma resposta truncada), texto não vazio. Segunda armadilha: o evento JSON de erro é **opaco** — “Erro inesperado do servidor. Consulte os logs do servidor para obter detalhes.”, com uma simples referência — e a causa real (`ProviderModelNotFoundError: Model not found: foo/bar. Did you mean…`, `ProviderAuthError`…) só existe nos logs. Daí `--print-logs --log-level ERROR` e a leitura do campo `error="…"` de stderr, sem o stack trace do Bun que vem em seguida. Assim, um modelo desconhecido falha em um segundo, com a causa identificada. De quebra, `--title` evita uma chamada LLM parasita: sem ele, o OpenCode gera um título de sessão por meio de uma interação adicional com `small_model`.

Os fornecedores são configurados no OpenCode (`opencode auth login`, `opencode.json`), nunca no `.env` do aipmt, do qual nenhuma chave chega ao subprocesso. Não há recusa em CI, ao contrário das CLIs de assinatura: uma chave de API ou um modelo auto-hospedado em um runner são usos legítimos.

A proteção de perímetro `_ensure_within_directory` permanece como a segunda camada, sem alterações.
