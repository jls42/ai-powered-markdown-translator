- **1.17.0** Claude 5.5 via API: Sonnet 5.5, que recusava o pensamento desativado, torna-se traduzível e passa a ser o modelo padrão, Haiku 5.5 adota o modo `--eco`; Dependabot passa a rodar também nos fins de semana (19-10-2026):

  - **`--use_claude` traduz com Claude Sonnet 5.5, Opus 5.5 e Fable 5.1.** O aipmt desativava o pensamento do Claude com `thinking: {"type": "disabled"}`, o que estes três modelos recusam: HTTP 400 logo no primeiro segmento, medido por uma chamada real. O aipmt agora envia a configuração mais baixa aceita por cada modelo, obtida a partir das capacidades publicadas pela API da Anthropic: `between_tools` para o Sonnet 5.5, que desativa o seu pensamento prévio, e nenhuma configuração para o Opus 5.5 e Fable 5.x, que pensam livremente. Um modelo ainda desconhecido tenta, na primeira recusa, as configurações da mais econômica à mais permissiva, mantendo depois a que funcionar para os segmentos seguintes — a mesma lógica já utilizada para o Gemini. Qualquer outro erro é propagado como está. Os quatro modelos 5.x entram na tabela de janelas de contexto, com um milhão de tokens.

  - **Claude Sonnet 5.5 torna-se o modelo padrão de `--use_claude`.** Medido pelo próprio aipmt nos dois documentos de referência do README — o artigo denso de monitoramento, em `--news`, e este README na sua revisão 1.14.0 —, catorze idiomas cada: 28 traduções em 28 geradas e sem discrepâncias de estrutura, nenhum segmento reprocessado, links internos intactos, citações em inglês mantidas exatamente como estavam e, em inglês, as linhas de tradução francesa removidas pelo próprio modelo. O Claude Sonnet 5 alcançava 11 e 12 em 14 via API, numa revisão mais longa deste README, e 13 e 13 via Claude Code. O preço permanece inalterado: US$ 2 e US$ 10 por milhão de tokens de entrada e saída, totalizando US$ 9,21 para as 28 traduções.

  - **`--eco` passa para o Claude Haiku 5.5, com pensamento ativado.** Medido nos mesmos documentos: com o pensamento desativado, o Haiku 5.5 deixa parágrafos inteiros em francês, recusados pela verificação de trechos não traduzidos — 9 traduções geradas em 28. Com o seu pensamento adaptativo, gera 26, sendo 23 sem discrepâncias; dois READMEs são recusados, em árabe e em híndi, com códigos inline perdidos no retorno. O Claude Haiku 4.5, o padrão anterior, medido pela primeira vez via API, gera as 28, mas apenas 21 sem discrepâncias: no artigo, eleva um título para o nível 1 em sete idiomas e deixa-o em francês no japonês, algo que nenhuma verificação detecta. O Haiku 5.5 custa US$ 0,57 para as 28 traduções, contra US$ 3,67, e é duas vezes mais rápido; o aipmt, portanto, deixa-o pensar.

  - **Dependabot executa todos os dias, incluindo fins de semana.** Configurado com `daily`, ele só executava de segunda a sexta: uma versão cujo prazo de três dias expirava numa sexta-feira, após a execução matinal, aguardava até segunda-feira, e a verificação diária de atualização, ajustada para uma execução diária, iria considerá-la atrasada no domingo. Em 18 de outubro, o google-genai 2.30.1 escapou disso por 1h35. O Dependabot agora segue um cron diário, e o teste que alinha o prazo da verificação ao seu cronograma conta três dias para `daily`: retornar a ele sem estender o prazo causa falha no teste.

  - **O verificador de pureza da divisão foi removido**, conforme previsto desde a 1.13.0. Ele comparava o pacote ao snapshot tirado na divisão, e cada alteração no código precisava declarar suas discrepâncias nele. A sua verificação mais útil permanece: `check-release-ready.sh` recusa um módulo Python não rastreado pelo git, invisível tanto para os hooks quanto para a CI.

  - **Dois problemas apontados pelo SonarCloud foram corrigidos**: a função que organiza os tokens de código de uma citação `--news`, excessivamente complexa, foi dividida em duas, e um teste de exceção agora chama apenas uma função em seu bloco.

  - **Dependências atualizadas desde a 1.16.3.** Nas versões fixadas, `anthropic` 1.13.0, `openai` 3.29.0, `google-genai` 2.30.0, `mistralai` 3.2.0 e `python-dotenv` 1.2.4, integradas automaticamente pelo Dependabot; as actions de publicação e análise do SonarCloud foram atualizadas manualmente. As duas questões deixadas em aberto pelo merge automático foram resolvidas: ele funciona sem permissões adicionais e não dispara workflows de push — a verificação diária de `main` cumpre esse papel.

- **1.16.3** Fim de arquivo: uma tradução via API mantém a quebra de linha final da sua fonte, e o SDK 3.0 do Mistral foi validado (04-10-2026):

  - **Uma tradução via API mantém a quebra de linha final da sua fonte.** Os provedores de API — OpenAI, Anthropic, Gemini, Mistral — removem os espaços em branco ao redor da resposta do modelo. No último segmento, essa limpeza eliminava a quebra de linha final do arquivo original: um arquivo traduzido sem nota de tradução terminava sem quebra de linha, o que o git sinaliza e os formatadores corrigem a cada execução. Observado ao validar o SDK 3.0 do Mistral, num guia terminado com uma quebra de linha cuja tradução não a continha mais. A nota de tradução adicionava uma, e os provedores de linha de comando — Codex, Grok CLI, Antigravity, Claude Code, OpenCode — preservam o final do segmento: apenas traduções via API sem nota eram afetadas. A tradução agora preserva a quebra de linha final da fonte, independentemente do provedor, e não adiciona nenhuma a uma fonte que não a possua.

  - **Mistral: SDK 3.0 validado com uma chamada real.** O `mistralai` 3.0.0 substitui a biblioteca HTTP `httpx` por `httpx2`; as importações e a chamada de tradução não mudam. Uma nova instalação do aipmt já a recebia, visto que as dependências não possuem versão máxima estrita, mas nenhuma chamada real havia testado isso: um guia Markdown traduzido pela API do Mistral com o SDK 3.0 mantém a estrutura idêntica à fonte. As versões fixadas para desenvolvimento foram atualizadas para este SDK, e os testes de repetição fornecem a ele um cliente `httpx2`, o mesmo utilizado em produção.

- **1.16.2** Proteção de código: código citado em uma citação `--news` e bloco indentado em uma lista não fazem mais a tradução ser recusada em todos os idiomas (03-10-2026):

  - **Código citado em uma citação não bloqueia mais a tradução.** No modo `--news`, o aipmt protege o código inline antes de isolar as citações em inglês, restauradas exatamente como estão. Um código contido em uma citação era, portanto, isolado junto com ela: o modelo nunca via o seu token, e a validação o considerava perdido em todos os idiomas. O monitoramento diário de notícias do autor foi interrompido por isso em 2 de outubro: um comando `/plugin enable …` citado em um tweet fez o idioma de teste ser recusado duas vezes, e os outros treze nunca foram iniciados. Os tokens isolados junto com uma citação agora são resolvidos no texto que foi separado. Para o inglês como destino, a linha de tradução em francês de uma citação não é mais enviada ao modelo: a instrução solicitava sua remoção, e o código contido nela era considerado perdido, apesar de o modelo ter cumprido a ordem. O resultado publicado não muda. Por fim, a restauração de uma citação não reinterpreta mais suas barras invertidas: um `\n` citado continua sendo um `\n`. Verificado de ponta a ponta no artigo que havia falhado: inglês e alemão traduzidos na primeira tentativa por `gpt-6.1-sol`, com estrutura idêntica às versões publicadas.

  - **Bloco de código indentado em uma lista é protegido.** O CommonMark permite o fechamento deslocado de um bloco, e este é o caso normal de um bloco que documenta uma etapa de lista numerada: ele pertence ao item da lista, logo é indentado. Fixado na coluna 0, o padrão de proteção não capturava nenhum deles: medido em um README real, 8 blocos detectados em 14. Os outros seis eram enviados ao modelo como prosa, retornavam idênticos por serem comandos, e a regra que recusa traduções copiadas integralmente rejeitava o arquivo para todos os idiomas, com uma mensagem que indicava o sintoma, mas nunca a causa. O padrão agora aceita fechamento indentado, e o ciclo de proteção e restauração retorna o documento idêntico, inclusive na indentação.

- **1.16.1** Links internos: o token de âncora preserva os parênteses do link, e um link traduzido não é mais duplicado silenciosamente (27-09-2026):

  - **Um link interno não quebra mais sem ser detectado.** Para proteger um link para uma seção, `[texte](#ancre)`, o aipmt substituía a parte entre parênteses, incluindo os próprios parênteses, por um token: o modelo recebia colchetes seguidos por um token isolado, parecendo um link quebrado, e às vezes tentava "consertá-lo". A restauração resultava em `[texte]((#ancre))`, um link que não leva a lugar nenhum, sem que nenhuma verificação alertasse sobre isso. A falha ocorria a cada regeneração das traduções deste repositório — em espanhol, coreano e depois em italiano na 1.15.0, em alemão na 1.16.0 — com todos os modelos Gemini Flash testados, e até mesmo com Claude Sonnet e Haiku. O token de um link Markdown agora preserva os seus parênteses: o modelo recebe um link válido, sem motivo para tentar corrigi-lo, e a restauração também aceita tokens dos quais os parênteses tenham sido removidos. Âncoras HTML continuam com tokens simples. Verificado de ponta a ponta com o modelo mais frágil, `gemini-3.8-flash-low`, em um README cujo link estava entre parênteses: sem a correção, o README foi recusado, com três links duplicados e um segmento reprocessado; com ela, três links intactos em três, nenhuma repetição. Em seguida, neste README, em alemão, japonês e híndi com `gemini-3.8-flash-medium`, e em alemão pelo Claude Code com `sonnet`: estrutura idêntica à fonte, com os três links internos preservados em todos os casos.

  - **Os testes não podem mais modificar o repositório que os executa.** Ao realizar push a partir de um worktree vinculado, o git repassa aos hooks a variável que aponta para o repositório, e o hook pre-push executa os testes: o `git init` de um teste, projetado para um diretório temporário, reinicializou o repositório real, que subitamente ficou sem árvore de trabalho. Os testes que chamam o git agora removem qualquer variável `GIT_*` do seu ambiente, e um teste de regressão, que usa essa variável para apontar para um repositório simulado, valida isso.

- **1.16.0** Provedor `--use_claude_code`: tradução na cota da assinatura Claude Pro ou Max, através do CLI oficial `claude -p` — sem vias pagas avulsas, comprovado a cada chamada (26-09-2026):

  - **Décimo primeiro caminho: a assinatura do Claude, sem cobrança por uso.** `--use_claude_code` executa o binário oficial do Claude Code no modo `-p`, sobre a mesma base de Codex, Grok CLI e Antigravity — grupo de processos próprio, encerramento seguro por timeout, Ctrl-C ou fechamento do terminal. Não deve ser confundido com `--use_claude`, a API da Anthropic com cobrança por uso. O aipmt nunca lê o token.

  - **Nenhuma via paga, validada em três níveis.** O ambiente do subprocesso é uma lista de permissões: sem chaves de API, sem tokens, sem provedores de nuvem e sem marcadores da sessão do Claude Code de onde o aipmt teria sido iniciado — a mesma que implementou este provedor exportava quinze deles. O preflight, sem chamadas ao modelo, exige do `claude auth status` o login por assinatura sem chave de Console, e do `/usage` a mensagem que atesta a assinatura. Cada chamada subsequente deve comprovar isso em seu evento de inicialização — `apiKeySource: none`, ambiente forçado recebido corretamente, modelo da família solicitada, sem modo rápido — e no seu relatório de cota: qualquer "extra usage" pago interrompe a tradução imediatamente.

  - **A cota é compartilhada com as sessões do Claude Code, e o provedor a gerencia.** Cada chamada relata o consumo das janelas de 5 horas e semanais; acima de 80% (`AIPMT_CLAUDE_MAX_UTILIZATION`), nenhum segmento adicional é iniciado. No dia da implementação, o consumo semanal da conta do autor já estava em 98%.

  - **Nenhuma configuração do usuário entra, nenhum resquício da sessão permanece.** Sem ferramentas, em modo sem personalização, configurações do usuário ignoradas, servidores MCP e hooks desativados, diretório de trabalho privado e temporário, nenhum histórico de transcrição mantido. Validado por testes com canários: sem `CLAUDE_CODE_DISABLE_ATTACHMENTS`, um `@chemin` do documento tornava-se um anexo, e o modelo retornava uma chamada de leitura em vez da tradução; com a proteção, nada passa. Os canários de `AGENTS.md`, `CLAUDE.md` e hooks não carregaram nem executaram nada.

  - **Segmentos iniciados por `/` não chegavam ao modelo.** Sob `--disable-slash-commands`, o próprio Claude Code respondia com "… isn't available in this environment.", com status `success`, sem turnos de execução. Uma quebra de linha antes do segmento permite o envio ao modelo; o contrato de saída, de qualquer forma, recusa qualquer resposta gerada sem turnos, em múltiplos turnos, truncada ou retornada por um modelo diferente do anunciado.

  - **Modelos: aliases, nunca identificadores fixos.** `sonnet` por padrão, com esforço `low`, e também em `--eco` — `--eco` não altera nada nesse caminho —, `opus` e `haiku` através de `--model`; `fable` e as variantes de `[1m]` são recusados, pois em `-p` consomem créditos pagos sem confirmação.

  - **Os comportamentos padrão foram medidos, não presumidos.** Pelo próprio `aipmt --use_claude_code`, quatro traduções em paralelo, nos dois documentos de teste do README — o artigo denso de monitoramento, em `--news`, e este README na sua revisão 1.14.0 —, catorze idiomas cada. O `sonnet`, com esforço `low`, produz as 28 traduções, 26 sem discrepâncias: uma palavra a mais em negrito em chinês no artigo e, no README em árabe, uma linha de tabela unida à anterior, mascarada pela renderização visual. Links internos intactos, citações em inglês mantidas exatamente como estavam e, em inglês, as linhas de tradução francesa removidas pelo modelo, sem bandeiras inventadas; mediana de 6 min 49 s por idioma no artigo, 2 min 20 s no README. O `opus` traduz o README sem nenhuma divergência, 25% mais rápido, mas nenhum artigo: as suas proteções interromperam a resposta em todos os catorze idiomas, em uma nota sobre biologia. O `haiku` traduz tudo — três títulos de seção elevados para o nível 1 no artigo, os links internos do README em inglês duplicados —, porém duas vezes mais lento que o `sonnet`: ele raciocina sem possibilidade de desativação, gerando 61% de seus tokens em saída de raciocínio, e seu custo menor resulta em apenas 14% de economia no equivalente via API. Daí a escolha de `sonnet` também em `--eco`. O nível de esforço não traz vantagens para a tradução: em um lote preliminar — este README e este CHANGELOG em inglês, japonês e híndi —, o `sonnet` não gerou nenhum token de raciocínio, o `opus` com esforço médio gerou 1% dos seus tokens de saída em raciocínio, e o esforço médio não trouxe ganhos sobre o baixo, nem em termos de estrutura nem de tempo. O lote com `sonnet`, totalizando 1,8 milhão de caracteres fonte, consumiu 9 pontos percentuais da janela de 5 horas e 2 da semanal na assinatura Max do autor — um teto máximo, visto que a sessão que coordenava as medições consumia da mesma cota.

  - **Uma recusa das salvaguardas da Anthropic é identificada como tal.** O Opus 5.5 possui salvaguardas mais rigorosas do que o Sonnet, e a mensagem de erro da Anthropic alerta que elas às vezes sinalizam trabalhos próximos da pesquisa biológica. Uma nota informativa de monitoramento sobre 279 moléculas geradas para um sítio de ligação foi suficiente. O Claude Code interrompe então a resposta, tenta novamente uma vez, e o modelo retorna "I can't continue this translation" com status de sucesso, sem erro, ao longo de dois turnos: apenas o contrato de turno único interrompia essa resposta, com uma mensagem omissa quanto à sua causa. Enviada isoladamente, a nota é recusada pela API sob a categoria "bio". O aipmt agora reconhece esses sinais, nomeia as salvaguardas e sua categoria, não faz novas tentativas — o mesmo texto dispararia a mesma recusa — e recomenda `--model sonnet`, que traduziu a nota nos quatorze idiomas.

  - **As traduções deste repositório podem passar por este caminho, sem exceção.** `REGEN_PROVIDER=claude_code` é uma assinatura, não uma API faturada: passa sem `REGEN_ALLOW_PAID_API`, com quatro jobs — as campanhas rodaram com quatro traduções simultâneas sem nenhum erro de taxa nem de trava de conexão —, após um preflight único que não consome cota alguma. O padrão continua sendo o Codex com `gpt-5.6-sol`.

  - **Os termos de uso, expostos com franqueza.** A página de termos legais do Claude Code não impede que um usuário se conecte ao binário não modificado com sua própria assinatura; ela proíbe desenvolvedores terceiros de rotear requisições pelas credenciais Pro ou Max de seus usuários, e a Anthropic prefere a chave de API para ferramentas de terceiros, incluindo projetos de código aberto, reservando-se o direito de deduzir seu uso dos créditos pagos. Nenhum texto define claramente o caso de uma ferramenta distribuída que executa o binário oficial: o usuário assume o risco de sua própria conta.

  - **Testes**: novo arquivo `tests/test_claude_code_provider.py` (58 testes), 100% das instruções e ramificações do módulo, sem nunca executar o `claude` real — ambiente limpo, binário inexistente, `PATH` sem `claude`, dublês que geram exceções se forem chamados.

- **1.15.0** Provedor `--use_antigravity`: traduzir usando a cota da assinatura Google AI Pro ou Ultra, por meio da CLI oficial `agy`; e, para todos os provedores, o Ctrl-C não deixa mais nenhum agente abandonado em execução, um segmento em branco não faz mais o arquivo falhar, e um `.env` de projeto não escolhe mais o binário executado (2026-09-26):

  - **Décimo caminho de provedor: a assinatura do Google, sem cobrança por uso.** Quem assina o Google AI Pro ou Ultra agora pode debitar suas traduções dessa cota em vez de pagar por token na API do Gemini. O `agy`, a CLI oficial do Antigravity, é o único caminho para essa cota: a Gemini CLI não atende mais contas Pro, Ultra nem gratuitas desde 18 de junho de 2026, e o SDK do Antigravity só se autentica por chave de API ou pelo Google Cloud. O `--use_antigravity` o controla em modo headless, como o Codex e a Grok CLI, sobre a mesma base — grupo de processos próprio, `SIGTERM` e depois `SIGKILL` no tempo limite, ambiente expurgado. Verificado de ponta a ponta no agy 1.2.11: um guia em Markdown — front matter, negrito, link com parênteses, código em linha, bloco de código indentado em uma lista, tabela, citação — traduzido para o inglês em 14 segundos, incluindo o preflight, estrutura idêntica à de origem, nota de tradução adicionada; depois, após as correções da revisão, para o alemão em 19 segundos, estrutura idêntica, nada gravado em `~/.gemini`.

  - **Nenhuma via paga permanece aberta, e cada inicialização verifica isso.** O agy conhece outros caminhos além da assinatura — chave de API, projeto do Google Cloud, gateway, créditos de IA pagos — e várias variáveis de ambiente o fazem alternar para eles sem exibir nada. Medido: `AGY_GATEWAY_URL` envia o documento para um gateway de terceiros, `AGY_ADC_AUTH` alterna para um projeto faturado do Google Cloud, `CLOUD_CODE_URL` redireciona o endpoint autenticado para qualquer endereço. O ambiente do subprocesso é, portanto, uma lista de permissões e não de bloqueio: `PATH`, o idioma e o fuso horário, o terminal, a identidade, os proxies e certificados da máquina e o barramento de sessão — o que um `env -i` provou que o agy precisa —, sem nenhuma chave. Uma lista de bloqueio por famílias de prefixos (`AGY_`, `GOOGLE_`, `GEMINI_`, `CLOUD_CODE_`…), testada inicialmente, deixava passar itens: uma revisão encontrou nas strings do binário sobreposições de endpoint que nenhum prefixo cobria, `AICODE_ENDPOINT_URL`, `UNLEASH_URL`, `GCE_METADATA_HOST`. Duas configurações escapam ao ambiente e só podem ser lidas por meio de `agy -p /config`: os créditos de IA pagos que assumem o controle quando a cota se esgota, e a conexão por meio de um projeto do Google Cloud. Um preflight que não consome cota alguma — uso medido em zero — recusa-se a traduzir se um deles estiver ativo ou se uma chave de API estiver configurada, e uma configuração ausente de `/config` equivale a uma recusa para cada um dos três: uma versão do agy que renomeasse um deles não deve burlar uma verificação que não validou nada. Por fim, o log de cada chamada deve atestar a autenticação pela assinatura (`authMethod=consumer`), e qualquer outro método de autenticação que conste ali, sob qualquer uma das duas grafias que o binário emprega, faz com que a resposta seja recusada: é a própria chamada que serve como prova, e não a configuração que foi preparada.

  - **O agente de tradução não possui ferramentas, e seu carregamento é comprovado a cada chamada.** Cada chamada grava, em um diretório descartável, um agente no formato dos agentes de projeto do agy: `tools: []`, `excludeDefaultComponents: true`, `inheritCustomizations: false`. Cerca de 800 tokens de entrada em vez de 12.400 com o agente padrão, e a terceira configuração não é redundante: `excludeDefaultComponents` sozinho permitia que um hook do workspace executasse seus comandos e injetasse seu texto. A verdadeira armadilha está em outro lugar: um agente não encontrado não faz o agy falhar. Código de retorno 0, status `SUCCESS`, e é o agente de codificação, com 57 ferramentas ativas, que responde — para "O gato está dormindo.", ele respondeu "Psiu, não vamos acordá-lo! 🐱💤 O que posso fazer por você hoje?". Nada na stdout nem na stderr: apenas o log da chamada informa isso. A resposta é, portanto, recusada se o log anunciar esse fallback, e também se não contiver o marcador positivo de carregamento do agente — uma alteração no formato do log faz com que a tradução seja recusada em vez de remover a proteção silenciosamente. Cada marcador deve ocupar uma linha inteira do log, no formato medido — severidade, data, hora, thread, arquivo e linha: o binário também contém uma linha que reproduz a mensagem do usuário no log — nunca vista no nível de log padrão, ao longo de 78 logs reais —, e um documento que mencione essas mensagens não deve conseguir satisfazer a proteção no lugar do agy.

  - **As configurações e o histórico do agy do usuário não são afetados.** Cada chamada roda com um HOME, um diretório temporário e um diretório de trabalho privados, excluídos posteriormente. O agy ainda assim se autentica, por meio das chaves do sistema, que o aipmt nunca lê. Nada é herdado: nem as permissões do usuário — que permitiam ao agente padrão executar `ls` e `git` sem pedir confirmação —, nem suas regras globais, plugins, servidores MCP, hooks e skills. E nada é adicionado ao seu histórico, onde cada chamada deixava uma conversa de cerca de 200 KB, incluindo o texto traduzido: a campanha de sondagens havia deixado ali cerca de 95 conversas e descartado 17 entradas de um cache limitado a 100. Verificado: nenhum arquivo gravado em `~/.gemini/antigravity-cli`.

  - **Recusa preventiva onde o isolamento não se sustentaria.** No Linux sem barramento de sessão D-Bus — sessão SSH, contêiner, servidor —, o agy armazena seu token em um arquivo em `~/.gemini` em vez do chaveiro, como anuncia seu próprio changelog (1.1.3), e o isolamento de cada chamada oculta esse arquivo. A recusa agora ocorre antes de qualquer inicialização, com sua causa real, em vez de um minuto de espera por um código de conexão seguido de uma sugestão de reconexão que não resolveria nada. No Windows, o agy lê `USERPROFILE`, `APPDATA` e `TEMP`, não `HOME` nem `TMPDIR` — de acordo com a documentação do Go e as strings do binário —: nada ali isolaria a chamada das configurações nem do histórico do usuário, e `--use_antigravity` é recusado lá até que isso seja mensurado. O macOS é aceito, sem ter sido medido; a proteção de faturamento, que lê a configuração efetiva, se mantém nele.

  - **`exit 0` não prova nada, quarta CLI.** Uma resposta só é aceita com um código de retorno zero, um objeto JSON com status `SUCCESS`, um log em conformidade, nenhuma ação recusada, nenhum comando, nenhum erro no JSON, nenhum aviso de truncamento na stderr e um texto não vazio. `--print-timeout` nunca é usado: ao expirar, o agy retorna a saída parcial em `SUCCESS`, código 0; o tempo limite é externo e encerra o grupo de processos. Um segmento que começa com `/commande`, `!commande` ou `@fichier` é traduzido, nunca executado nem resolvido — sem `--disable-slash-commands`, "/help" era executado em vez da tradução. Um segmento em branco não chega mais ao agy, pois o pipeline o retorna tal como está (veja abaixo), e permanece rejeitado antes da chamada como última salvaguarda: em uma entrada vazia, o agy abre sua interface interativa com código 0. A repetição segue o campo `retryable` da linha `AGY_ERROR` que o agy grava na stderr desde a versão 1.2.6: ele próprio já tenta novamente erros transitórios — 502, 503, 504, limite por minuto —, e é ele quem sabe se a falha restante ainda o é. Na ausência desse campo, nenhuma nova tentativa ocorre quando a mensagem menciona esgotamento — no Google, `RESOURCE_EXHAUSTED` traz o mesmo código 429 de um limite por minuto, mas uma janela de 5 horas esgotada não retorna em 90 segundos —, e, caso contrário, apenas em limitações de taxa. A resposta mantém a terminação de linha do segmento: o agy sempre termina a sua com uma quebra de linha que, na junção, dividia ao meio um parágrafo quebrado no meio de uma frase. Uma sessão desconectada gera uma mensagem instruindo a executar `agy` para reconectar. Por fim, `AGY_CLI_DISABLE_AUTO_UPDATE=true` impede que um HOME novo execute a cada chamada um verificador de atualização em sua própria sessão, fora do alcance do tempo limite — o valor `1`, por sua vez, não tem efeito.

Por padrão `gemini-3.8-flash-medium`, e `gemini-3.7-flash-low` em `--eco`, definidos pelas campanhas descritas abaixo. `--reasoning_effort` não tem efeito e informa isso. Recusado em CI, assim como o Codex e a Grok CLI: a conexão reside em um chaveiro pessoal, e a mensagem sugere `--use_gemini` com uma chave do Google.

- **Ctrl-C e o fechamento do terminal agora encerram o agente, para as quatro CLIs.** O Codex, Grok CLI, OpenCode e Antigravity rodam em sua própria sessão, fora do grupo de primeiro plano: o `SIGINT` de um Ctrl-C não os alcança e, no Ctrl-C, o `Popen` só os aguarda por um quarto de segundo antes de devolver o controle. Verificado pela revisão em um binário falso: o agente sobrevivia ao aipmt e terminava sua rodada consumindo a cota, gerando um resultado descartado — quatro de uma vez sob o regen. Um `KeyboardInterrupt` ou um `SystemExit` durante a chamada agora encerra o grupo do agente antes de retornar. O fechamento do terminal ou a queda de uma sessão SSH (`SIGHUP`) encerrava o Python sem nenhuma limpeza: o agente continuava, e o diretório privado do Antigravity permanecia no disco com seu log, que contém o endereço da conta. O `SIGHUP` agora segue o caminho do `SIGTERM`: grupo do agente encerrado, seguido por saída em 129. Um `SIGHUP` ignorado, por uma inicialização sob o `nohup`, permanece assim: é a escolha do usuário.   - **O driver de subprocessos não pode mais atingir a sessão inteira.** No Linux, `killpg(1, sig)` equivale a `kill(-1, sig)`: o sinal é enviado para todos os processos do usuário. Isso aconteceu durante a escrita desta versão, devido a uma bateria de mutações: um mutante chamou um `Popen` duplicado por um `MagicMock` simples, o erro resultante passou pelo novo caminho de interrupção, e o pid do processo falso, que o Python converte para 1, causou o encerramento de toda a sessão gráfica. O `_codex_kill_group`, comum às quatro CLIs, agora só tem como alvo um grupo se o pid for um inteiro real maior que 1, se o `getpgid` retornar esse mesmo pid — um agente iniciado em sua própria sessão é o líder de seu grupo — e se esse não for o grupo do processo atual; caso contrário, apenas o filho direto é visado. Em produção, essa proteção não muda nada: ela fecha o caso em que um bug faria retornar algo diferente. Os dublês de `Popen` que não devem ser utilizados agora falham diretamente, os processos falsos carregam um pid impossível, e as baterias de mutações rodam em um namespace PID.

Um segmento em branco agora é retornado como está, sem chamada.

  - **Segurança: um `.env` de projeto não pode mais escolher o binário executado.** `CODEX_BIN`, `GROK_BIN`, `OPENCODE_BIN` e `AGY_BIN` especificam o programa que a tradução executa, com os privilégios do usuário: definidos pelo `.env` de um repositório recém-clonado, eles faziam com que um arquivo desse repositório fosse executado logo na primeira tradução. O sufixo `_BIN` junta-se, portanto, a `_BASE_URL`, `_API_BASE` e `_ENDPOINT` no filtro da camada de projeto, juntamente com `GROK_HOME`, sob o qual o binário do Grok é procurado (`$GROK_HOME/bin/grok`). Essas variáveis continuam sendo aceitas a partir do ambiente e do `~/.config/aipmt/.env`, e cada recusa é exibida no stderr informando o local onde devem ser configuradas.

O provedor lê, portanto, `supported_efforts` no preflight e solicita o menor, recorrendo a « nada » quando o catálogo não indica nenhum utilizável. Contraprova no idioma problemático: antes falhava por esgotamento de orçamento, agora é concluído em 9 minutos com estrutura idêntica à de origem.

  - **Uma falha no hospedeiro upstream agora traz seu nome.** O roteador normaliza esse caso em `finish_reason=error` com um `native_finish_reason` nulo — medido duas vezes, em dois idiomas, em exatos 750 segundos. - **1.12.0** Provedor `--use_opencode`: OpenCode, o agente de código aberto, para o provedor de sua escolha — modelo local, gratuito sem conta, assinatura ou chave (2026-09-04):

  - **Oitavo caminho de provedor, de natureza diferente dos sete primeiros.** [OpenCode](https://opencode.ai) (MIT) não é um provedor de modelos, mas um _roteador_ para aqueles que o usuário configurou no próprio OpenCode: uma chave de API, uma assinatura (GitHub Copilot, ChatGPT, SuperGrok), o gateway OpenCode Zen — que disponibiliza modelos gratuitos **sem conta** —, ou um modelo **local** (Ollama, LM Studio, llama.cpp). O script controla `opencode run` em modo não interativo, da mesma forma que controla o Codex e o Grok, e reutiliza a mesma base de subprocessos (grupo de processos próprio, `SIGTERM` e depois `SIGKILL` em caso de timeout, stdin sempre fechado, ambiente sanitizado). Verificado por **duas traduções reais**: todo este README em inglês via `opencode/mimo-v2.5-free` — 49 s, uma única passada, estrutura idêntica à do arquivo de origem (32 títulos, 26 fechamentos de código, 18 links, 37 URLs, 37 linhas de tabela, 135 códigos inline) — e um arquivo de teste via `ollama/qwen2.5:7b`, localmente, sem nenhuma chave.

  - **`--model provider/modèle` é obrigatório, e isso é uma escolha deliberada.** Sem `--model`, o OpenCode recorre ao seu próprio padrão, que em uma instalação limpa é `opencode/big-pickle`, modelo gratuito "stealth" cujas interações podem ser usadas para treinamento — medido, foi esse modelo que respondeu. Escolher isso silenciosamente no lugar do usuário seria exatamente o tipo de alternância invisível que este repositório combate; a mensagem de erro, portanto, indica o comando que lista os modelos (`opencode models`) e três exemplos (local, gratuito, assinatura). `--eco` não tem efeito e informa isso. `--reasoning_effort` é transmitido exatamente como `--variant` do OpenCode, apenas mediante solicitação explícita.

  - **Isolamento medido, não presumido.** Uma configuração inline (`OPENCODE_CONFIG_CONTENT`, a última na ordem de mesclagem do OpenCode, portanto com prioridade sobre a do usuário sem substituí-la) define um agente `aipmt` cujas ferramentas são todas recusadas (`permission: {"*": "deny"}`): o registro sequer as oferece ao modelo, que, ao ser instruído a "listar os arquivos e executar `id`", responde que não tem ferramentas. Compartilhamento de sessão desativado, plugins externos descartados (`--pure`), nunca `--auto`, diretório de trabalho descartável e vazio. Duas injeções silenciosas foram medidas e eliminadas: sem `OPENCODE_DISABLE_CLAUDE_CODE`, o `~/.claude/CLAUDE.md` do usuário entra em **cada** prompt (515 tokens de entrada em vez de 186 para um simples "Olá"); sem `OPENCODE_DISABLE_PROJECT_CONFIG`, o `AGENTS.md` do diretório atual também — uma instrução para "terminar cada resposta com BANANA" foi aplicada à tradução. O `~/.config/opencode/AGENTS.md` global, por sua vez, continua sendo injetado: nenhuma chave o descarta, e contorná-lo por meio de um `XDG_CONFIG_HOME` redirecionado também ocultaria os provedores do usuário.   - **Bug corrigido** : a extração das URLs de atribuição em `_protect_news_quotes` utilizava a regex `re.search(r"\((.+?)\)", attribution)` (lazy capture entre parênteses). Em uma atribuição do tipo `(relayé par [@user sur X](https://x.com/.../123))` (parênteses aninhados : `(` delimitador + `]()` do markdown link), a captura parava no primeiro `)` encontrado → string truncada + incluindo o prefixo FR : `relayé par [@user sur X](https://x.com/.../123` (sem o `)` final). Robusta para os dois padrões problemáticos :

    - `via [@source](url)` ou `selon [@author](url)` — prefixo FR sem parênteses delimitadores

- **1.9** Correção de silent-failure + ferramentas de qualidade completas + nota de tradução multi-posição (2026-05-07) :
  - **Nota de tradução multi-posição + formato marker "embed card"** :
    - Novas opções de CLI (aditivas, padrões inalterados → **non breaking**) :
      - `--note_position {top,bottom,both}` (padrão : `bottom`) : coloca a nota no topo, no rodapé ou em ambos os locais do arquivo traduzido.
      - `--note_format {legacy,marker}` (padrão : `legacy`) :
        - `legacy` reproduz estritamente o comportamento da v1.8 (parágrafo em negrito `**…**`) **byte-for-byte**.
        - `marker` emite uma link reference definition Markdown invisível (`[ai-translation-note-<placement>]: <> "v=1 source=… target=… model=… date=…"`) seguida de um **blockquote de 3 parágrafos** estruturado para uma renderização do tipo "GitHub repo embed card" : título do projeto em código inline (`**\`ai-powered-markdown-translator\`\*\*`), descrição traduzida pelo LLM e link CTA (`[Voir le projet sur GitHub ↗](URL)`) com seta visível. Utilizável durante o build por um plugin remark (cf. blog jls42.org → plugin `remark-translation-banner`).
    - **Invariantes nunca enviados ao LLM** : o título do repositório e a URL do GitHub são montados no lado do Python após a tradução da frase descritiva. O LLM nunca vê o slug `ai-powered-markdown-translator` nem `https://github.com/jls42/...`, garantindo que nenhum renderer/case/scheme seja alterado.
    - **Frontmatter-aware insertion** : no modo `top` ou `both`, a nota é inserida **após o bloco `---` de fechamento** do frontmatter YAML (segurança do Astro Content Collections / gray-matter). O helper `_split_frontmatter` detecta `---\n…\n---\n` no início do arquivo e preserva sua integridade ; **lança `RuntimeError`** em frontmatter aberto sem fence de fechamento (o arquivo vai para `failed_files` em vez de ser gravado com uma nota mal posicionada).
    - **Sanitizer de modelo whitelist** : `_sanitize_model` substitui qualquer caractere fora de `[A-Za-z0-9._:/-]` por `_`, fallback `unknown` se estiver vazio. Alinha-se com o validador no lado do plugin remark do Astro e neutraliza caracteres que quebrariam a formatação do marker (espaço, aspas, parênteses, vírgula, etc.).
    - **Refatoração interna** : `_append_translation_note` (1 função monolítica) → 7 helpers puros (`_translation_note_invariants`, `_build_translation_note_phrase`, `_assemble_translation_note_paragraphs`, `_build_translation_note_source`, `_sanitize_model`, `_quote_lines`, `_split_frontmatter`, `_build_translation_note_block`, `_compose_with_notes`). Builder/composer separados (o builder retorna um bloco puro sem separador, o composer aplica os `\n\n` conforme a posição) ; produção e helper de origem compartilham o mesmo montador de 3 parágrafos.
    - **`_quote_lines` blank-preserving** : prefixa cada linha com `> `, transformando as linhas vazias em `>` isolado. Permite que o mdast veja 3 parágrafos distintos no blockquote (título / descrição / link) em vez de um único parágrafo com quebras de linha.
    - **`_build_translation_note_block` adaptativo** : conforme o número de parágrafos que o LLM preservou (3 = formato card completo, 2 = frase + link, 1 = fallback). O fallback de 1 parágrafo **não envolve mais em `**...**`** quando um link Markdown `](` é detectado (renderização frágil de `<strong>` ao redor de um link).
    - **Compatibilidade retroativa** : `getattr(args, "note_position", "bottom")` e `getattr(args, "note_format", "legacy")` no lado de `_compose_with_notes` — Namespaces sem esses atributos (testes existentes, chamadas programáticas externas) continuam a funcionar sem modificação.
  - **Correção de silent-failure em traduções longas** :
    - Validação de idioma pós-tradução em todos os provedores (OpenAI, Mistral, Claude, Gemini) : camada determinística (trecho original encontrado verbatim) + camada probabilística (`langdetect`)
    - Whitelist `finish_reason` / `stop_reason` : lançar `RuntimeError` para qualquer estado fora da whitelist (truncation, content_filter, etc.)
    - `max_tokens` Claude : `4096` → `32768` (evita truncamento latente em segmentos de 16k, margem cross-script FR→JA/ZH/KO/AR/HI)
    - Segmentação heading-aware : prioridade H2/H3 na 2ª metade do segmento (cada segmento começa com uma seção semântica completa)
    - Propagação de erros até exit code diferente de zero : `translate_markdown_file` retorna um status tipado `success` / `failure` / `skipped`, `main()` `sys.exit(1)` se pelo menos um arquivo falhar (arquivo único e lote)
    - Empty-content guard em todos os provedores, sanity ratio origem/saída (≥ 500 caracteres, < 5% = recusa), validação de placeholders de código (`#CODEBLOCK`/`#INLINECODE`), normalização pós-LLM (separadores/links colados a um heading), `BadRequestError` retry sem `reasoning_effort`
